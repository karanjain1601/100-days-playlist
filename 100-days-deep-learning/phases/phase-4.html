Why MLPs Fail on Images

47

  2. Loss of spatial structure when flattening
  3. No translation invariance

Three separate failures, not one

Take a modest 224×224 RGB image and feed it to a fully connected layer with 1000 hidden units. Flattening gives \(224\times224\times3=150{,}528\) inputs, so that single layer holds \(150{,}528\times1000\approx1.5\times10^8\) weights — more parameters than all of ResNet-50, for one layer that has learned nothing yet. That is the failure everyone quotes, and it is the least interesting of the three.

The second failure is that flattening destroys the information you needed. In the flattened vector, pixel \((i,j)\) and pixel \((i+1,j)\) — vertical neighbours, almost certainly part of the same object — end up 224 positions apart, exactly as far as two random pixels. The MLP has to rediscover that images are 2D from data alone. It can, given enough examples, but you have thrown away a fact you already knew for free.

The third is the deepest: an MLP has no translation invariance. Train it on cats in the top-left and it learns weights for cats-in-the-top-left. Move the cat 40 pixels right and every one of those weights is now looking at the wrong place; the network must independently learn a second set of cat detectors for the new location, and a third, and so on. Nothing shares.

Convolution is two constraints, and both are priors

Local connectivity — a unit sees only a small neighbourhood, because pixels far apart are rarely directly related. Weight sharing — the same small filter is applied at every position, because an edge is an edge wherever it appears.

Both are restrictions. A CNN is strictly less expressive than an MLP of the same size — it cannot represent every function the MLP can. That restriction is the entire point: it encodes true facts about images, so the network spends its capacity on things it does not already know. This is the clearest example in the course of an inductive bias, and it is exactly the trade Vision Transformers reopen in Lesson 62.

Four orders of magnitude fewer parameters, and the smaller one generalises better. That is not a trade-off — it is a free win, paid for by knowing something about your data.

Exercise

Train an MLP and a small CNN with roughly equal parameter counts on MNIST. Then evaluate both on a test set where every image has been shifted 4 pixels in a random direction. The MLP will collapse; the CNN will barely notice. That gap is weight sharing, measured.

The operation

Slide a small weight matrix over the input and take a dot product at every position:

\[ y[i,j]=\sum_{u=0}^{k-1}\sum_{v=0}^{k-1} w[u,v]\;x[i+u,\;j+v] \;+\; b \]
It is not actually convolution

True mathematical convolution flips the kernel: \(\sum w[u,v]\,x[i-u,j-v]\). What every deep learning framework calls Conv2d is cross-correlation — no flip. It does not matter, because the kernel is learned: if the flipped version were better, gradient descent would simply learn the flipped weights. It matters only when you port hand-designed kernels from a signal-processing textbook, or read a paper that is careful about the distinction. Do not let it confuse you; it confuses everyone once.

Output size, derived

Start with a 1D input of length \(n\), kernel \(k\), padding \(p\) on each side, stride \(s\), dilation \(d\). Dilation inflates the kernel's footprint: a \(k\)-tap kernel with dilation \(d\) spans \(k_{\text{eff}}=d(k-1)+1\) positions. The first window starts at 0 and the last must fit, so the number of valid start positions is:

\[ n_{\text{out}}=\left\lfloor\frac{n+2p-\big(d(k-1)+1\big)}{s}\right\rfloor+1 \]

Every shape bug in a CNN is this formula, applied wrong. The two special cases worth memorising:

SettingResultName
\(k=3,\ p=1,\ s=1,\ d=1\)\(n_{\text{out}}=n\)"same" — the workhorse. Size preserved.
\(k=3,\ p=1,\ s=2\)\(n_{\text{out}}=\lceil n/2\rceil\)Downsample by 2 without pooling
\(k=1,\ p=0,\ s=1\)\(n_{\text{out}}=n\)1×1 conv — mixes channels only
\(p=0\)\(n_{\text{out}}=n-k+1\)"valid" — shrinks every layer

In general, \(p=\lfloor k/2\rfloor\) with odd \(k\) preserves size. Odd kernels are near-universal precisely because they have a well-defined centre and an integer "same" padding.

Multi-channel: the shape bookkeeping that actually matters

A colour image has 3 channels, and a hidden layer has however many the previous layer produced. A single filter is therefore not \(k\times k\) but \(C_{\text{in}}\times k\times k\) — it spans all input channels and collapses them to one output number per position. Stack \(C_{\text{out}}\) such filters and you get \(C_{\text{out}}\) output channels.

x (N, Cin, H, W)*W (Cout, Cin, k, k)→y (N, Cout, H′, W′)
\[ \#\text{params}=C_{\text{out}}\cdot C_{\text{in}}\cdot k^2+C_{\text{out}} \qquad\qquad \#\text{FLOPs}\approx 2\cdot C_{\text{out}}\cdot C_{\text{in}}\cdot k^2\cdot H'\cdot W' \]

Note what is not in the parameter count: \(H\) and \(W\). A conv layer's parameter count is independent of input resolution — which is why the same backbone accepts 224×224 and 512×512 images, and why only the classifier head cares about resolution.

Pitfall · assuming filters are 2D

People draw a 3×3 filter as a little square and then cannot explain where the channels went. A "3×3 conv from 64 to 128 channels" holds \(128\times64\times3\times3=73{,}728\) weights, not 9. Each of the 128 output channels owns a \(64\times3\times3\) volume. If you internalise nothing else from this lesson, internalise the shape \((C_{\text{out}},C_{\text{in}},k,k)\) — it is the source of most RuntimeError: expected input to have N channels messages.

Receptive field

The receptive field is the region of the original input that influences one output unit. Stack layers and it grows:

\[ r_{l}=r_{l-1}+\big(k_l-1\big)\prod_{i=1}^{l-1}s_i \]

Three stacked 3×3 convs with stride 1 give \(r=3\to5\to7\): the same receptive field as a single 7×7 conv, but with \(3\times(3^2C^2)=27C^2\) parameters instead of \(49C^2\), and two extra non-linearities. That single observation is the entire design principle behind VGG, and it is why almost nobody uses large kernels in the classic era.

What a channel means

After the first layer, channel \(c\) of the feature map is a spatial map answering one question: "how strongly does filter \(c\)'s pattern appear here?" Early channels answer things like "is there a vertical edge here"; deep channels answer "is there a dog's face here". The spatial dimensions shrink while the channel dimension grows — the network trades where for what, progressively.

Pooling

Why global average pooling was such a big deal

AlexNet and VGG ended with flatten → dense layers, and those layers held 90% of the network's parameters — VGG-16's first dense layer alone is \(25088\times4096\approx10^8\) weights, more than the entire convolutional stack. Global average pooling replaces all of it with a parameter-free mean and a single small classifier. The result is fewer parameters, less overfitting, and a backbone that accepts any input resolution, since averaging does not care how many positions it averages over. Everything modern does this.

The 1×1 convolution

It looks like it does nothing — a 1×1 window sees one pixel. But remember the shape: a 1×1 conv has weights \((C_{\text{out}},C_{\text{in}},1,1)\), so at each spatial position it applies a full \(C_{\text{in}}\to C_{\text{out}}\) linear map across channels. It is a per-position dense layer. Three uses, all essential:

  • Cheap dimensionality change. 256→64 channels costs \(64\times256=16{,}384\) weights; doing it with a 3×3 would cost nine times that. This is how Inception and ResNet bottlenecks afford to be deep.
  • Channel mixing. Depthwise convolution (Lesson 53) deliberately does not mix channels, so a 1×1 is paired with it to do exactly that.
  • Adding non-linearity without touching spatial extent.

Upsampling, and the checkerboard problem

Segmentation and generative models need to go back up in resolution. Transposed convolution (ConvTranspose2d) learns the upsampling, but when the kernel size is not divisible by the stride, output positions receive unequal numbers of contributions, producing a visible checkerboard artifact. Two fixes: use \(k\) divisible by \(s\) (4×4 with stride 2), or — more reliably — Upsample(scale_factor=2, mode='bilinear') followed by an ordinary 3×3 conv. The second option is what most modern segmentation and diffusion decoders actually use.

import torch.nn as nn

class ConvBlock(nn.Module):
    """The unit you will type a thousand times: conv -> norm -> activation."""
    def __init__(self, cin, cout, k=3, s=1):
        super().__init__()
        self.block = nn.Sequential(
            nn.Conv2d(cin, cout, k, stride=s, padding=k // 2, bias=False),  # bias=False: BN follows
            nn.BatchNorm2d(cout),
            nn.ReLU(inplace=True))
    def forward(self, x):
        return self.block(x)

class SmallCNN(nn.Module):
    def __init__(self, num_classes=10, w=64):
        super().__init__()
        self.features = nn.Sequential(
            ConvBlock(3, w), ConvBlock(w, w), nn.MaxPool2d(2),          # 32 -> 16
            ConvBlock(w, 2 * w), ConvBlock(2 * w, 2 * w), nn.MaxPool2d(2),   # 16 -> 8
            ConvBlock(2 * w, 4 * w), ConvBlock(4 * w, 4 * w))
        self.head = nn.Sequential(
            nn.AdaptiveAvgPool2d(1),      # (N, 4w, 8, 8) -> (N, 4w, 1, 1); ANY input size works
            nn.Flatten(),
            nn.Dropout(0.2),
            nn.Linear(4 * w, num_classes))
    def forward(self, x):
        return self.head(self.features(x))   # raw logits (Lesson 40)
The pattern behind almost every CNN

Resolution halves and channels double at each stage, keeping the compute per stage roughly constant: \(H\!\times\!W\) drops 4×, \(C_{\text{in}}C_{\text{out}}\) rises 4×. Look for that balance in every architecture in the next two lessons — 224→112→56→28→14→7 with 64→128→256→512 channels is the skeleton of the entire field.

The naive version, so the fast one makes sense

import numpy as np

def conv2d_naive(x, W, b, stride=1, pad=1):
    """x (N,Cin,H,Wd) · W (Cout,Cin,k,k) -> (N,Cout,H',W'). Correct, and painfully slow."""
    N, Cin, H, Wd = x.shape
    Cout, _, k, _ = W.shape
    xp = np.pad(x, ((0, 0), (0, 0), (pad, pad), (pad, pad)))
    Ho = (H + 2 * pad - k) // stride + 1
    Wo = (Wd + 2 * pad - k) // stride + 1
    out = np.zeros((N, Cout, Ho, Wo))
    for n in range(N):
        for co in range(Cout):
            for i in range(Ho):
                for j in range(Wo):
                    patch = xp[n, :, i*stride:i*stride+k, j*stride:j*stride+k]
                    out[n, co, i, j] = np.sum(patch * W[co]) + b[co]
    return out

Six nested loops in Python. For a single 224×224×64→64 layer that is roughly \(10^9\) iterations — minutes per image. The fix is not to optimise the loops but to change the problem.

im2col — turning convolution into one matrix multiply

Every output position consumes a \(C_{\text{in}}\times k\times k\) patch and dot-products it with a filter. So: extract every patch, flatten each into a column, and stack them into a matrix \(X_{\text{col}}\) of shape \((C_{\text{in}}k^2,\ N\!\cdot\!H'W')\). Flatten the filters into \(W_{\text{row}}\) of shape \((C_{\text{out}},\ C_{\text{in}}k^2)\). Then:

\[ Y = W_{\text{row}}\,X_{\text{col}} + \mathbf b \]

One GEMM. This is why convolution is fast — not because anyone wrote a clever convolution kernel, but because it is reduced to the single operation that decades of BLAS and every tensor core on your GPU are built to do. The cost is memory: \(X_{\text{col}}\) duplicates each pixel \(k^2\) times. (Modern cuDNN also has implicit-GEMM, Winograd and FFT paths, but im2col is the one to understand.)

def im2col(x, k, stride, pad):
    N, C, H, Wd = x.shape
    xp = np.pad(x, ((0,0), (0,0), (pad,pad), (pad,pad)))
    Ho = (H + 2*pad - k)//stride + 1
    Wo = (Wd + 2*pad - k)//stride + 1
    # stride tricks give a VIEW of every patch with no copying
    s = xp.strides
    patches = np.lib.stride_tricks.as_strided(
        xp, shape=(N, C, Ho, Wo, k, k),
        strides=(s[0], s[1], s[2]*stride, s[3]*stride, s[2], s[3]))
    return patches.transpose(1,4,5,0,2,3).reshape(C*k*k, -1), Ho, Wo

def conv2d_fast(x, W, b, stride=1, pad=1):
    Cout = W.shape[0]
    cols, Ho, Wo = im2col(x, W.shape[2], stride, pad)
    out = W.reshape(Cout, -1) @ cols + b.reshape(-1, 1)
    return out.reshape(Cout, x.shape[0], Ho, Wo).transpose(1, 0, 2, 3)

The backward pass

Once convolution is a matmul, its gradients are the matmul gradients from Lesson 22 — the outer-product rule and the \(W\T\) rule, unchanged:

\[ \bar W_{\text{row}}=\bar Y\,X_{\text{col}}\T,\qquad \bar X_{\text{col}}=W_{\text{row}}\T\,\bar Y,\qquad \bar b=\textstyle\sum_{\text{positions}}\bar Y \]

The only new work is col2im: scattering \(\bar X_{\text{col}}\) back into image shape. Because im2col duplicated each pixel across overlapping patches, and duplication is fan-out, col2im must accumulate — \(\mathrel{+}=\), not \(=\). That is the "copy is a summer" rule from Lesson 22, and getting it wrong is the single most common bug when people write this by hand.

Pitfall · = instead of += in col2im

With overlapping windows, one input pixel contributes to up to \(k^2\) outputs. Assigning instead of accumulating keeps only the last contribution, so your gradient is silently wrong by a factor that varies across the image — largest in the interior, correct at the corners. The network still trains, badly, and the loss curve looks merely disappointing rather than broken. Always gradient-check against finite differences (Lesson 23) before you trust a hand-written conv backward.

Max pooling backward: a router

Max pooling forwards only the maximum in each window, so on the backward pass the entire incoming gradient goes to that one position and zero goes everywhere else. Cache the argmax indices on the forward pass; the backward is a scatter. Average pooling instead divides the gradient equally among all \(k^2\) positions.

Verify against PyTorch — always 
x = np.random.randn(2, 3, 9, 9)
W = np.random.randn(4, 3, 3, 3); b = np.random.randn(4)
mine  = conv2d_fast(x, W, b, stride=1, pad=1)
theirs = torch.nn.functional.conv2d(
    torch.tensor(x), torch.tensor(W), torch.tensor(b), stride=1, padding=1).numpy()
print(np.abs(mine - theirs).max())     # expect < 1e-10 in float64

LeNet-5 (1998)

Yann LeCun's digit reader, deployed to read cheques. \(32\times32\) grayscale → conv 6@5×5 → pool → conv 16@5×5 → pool → dense 120 → dense 84 → 10. About 60,000 parameters and tanh activations. Every structural idea in a modern CNN is here already: alternating convolution and subsampling, growing channels, a dense classifier at the end. It then sat mostly unused for fourteen years because the data and the GPUs did not exist.

AlexNet (2012)

60M parameters, 8 layers, top-5 error 15.3% against 26.2% for the runner-up. That margin — not the architecture — is what changed the field overnight. What was actually new:

  • ReLU instead of tanh, roughly 6× faster to train (Lesson 20).
  • Two GPUs, with the network split across them out of necessity: 3GB of memory each.
  • Dropout in the dense layers, which held 90% of the parameters.
  • Heavy augmentation: random crops, flips, PCA colour jitter.
  • Large early kernels — 11×11 stride 4 — which the very next paper showed was a mistake.

ZFNet (2013): look at what the filters learned

Zeiler and Fergus built a deconvolutional visualisation to see what AlexNet's filters responded to, found that the 11×11 stride-4 first layer produced aliased, dead and mixed-frequency filters, and simply shrank it to 7×7 stride 2. Error dropped to 11.7%. The lesson is methodological and still applies: visualising the model told them more than another architecture search would have. You will do this yourself in Lesson 64.

VGG (2014): one idea, applied relentlessly

Use only 3×3 convolutions with stride 1 and padding 1, only 2×2 max pooling, and double the channels after each pool. Nothing else. The justification is the receptive-field arithmetic from Lesson 48:

ConfigurationReceptive fieldParameters (\(C\to C\))Non-linearities
One 7×7 conv7×7\(49C^2\)1
Three stacked 3×3 convs7×7\(27C^2\) — 45% fewer3

Same field of view, fewer weights, more non-linearity. It is a clean argument and it settled the kernel-size question for a decade.

Pitfall · VGG's real cost is not where you think

VGG-16 has 138M parameters, of which 124M sit in the three dense layers and only 14M in all thirteen convolutions. Yet the convolutions consume the overwhelming majority of the compute — 15.5 GFLOPs per image, about 30× a ResNet-18. Parameters and FLOPs are different resources, and confusing them leads to wrong decisions: a model can be huge and fast, or tiny and slow. Always quote both.

Network-in-Network, the quiet paper

NiN (2013) introduced both the 1×1 convolution and global average pooling — the two ideas that make Inception, ResNet and every efficient architecture since possible. It is barely cited compared to the papers built on top of it. Worth remembering when you read the field's history: the loudest paper is rarely the one carrying the idea.

Inception: stop choosing a kernel size

Objects appear at many scales, so instead of picking 3×3 or 5×5, run 1×1, 3×3, 5×5 and a pooling path in parallel and concatenate the outputs along the channel axis. The naive version is unaffordable — a 5×5 over 256 channels is enormous — so each expensive branch is preceded by a 1×1 that squeezes the channel count first:

in (N, 256, H, W)→1×1 → 64 cheap→5×5 → 32⊕concat (N, C, H, W)

Without the squeeze: \(256\times32\times25=204{,}800\) weights. With it: \(256\times64+64\times32\times25=67{,}584\). A 3× saving on one branch, and it is what lets GoogLeNet be 22 layers deep with 5M parameters — twelve times fewer than AlexNet at better accuracy. Later versions add factorisation (a 5×5 becomes two 3×3s; a 3×3 becomes 1×3 then 3×1), BatchNorm (v2), and label smoothing (v3, where it was introduced).

The degradation problem

By 2015 the obvious move was to keep stacking. It stopped working — and not because of overfitting. A 56-layer plain network had higher training error than a 20-layer one. That is the key observation: it was not failing to generalise, it was failing to fit.

Why that is strange, and what it implies

A 56-layer network can represent everything a 20-layer network can: set the extra 36 layers to the identity. So the deeper model's optimum is at least as good. It reached a worse solution anyway, which means the problem is optimisation, not capacity.

And the specific difficulty is that learning the identity is hard for a stack of convolutions and ReLUs. Nothing in \(\text{ReLU}(Wx+b)\) makes \(W=I\) a natural resting point. So He et al. restructured the block so that identity is what you get for free, and the layers only have to learn the deviation from it.

Why the gradient survives

For \(\mathbf y=\mathbf x+F(\mathbf x)\), differentiate:

\[ \frac{\partial\mathbf y}{\partial\mathbf x}=I+\frac{\partial F}{\partial\mathbf x} \qquad\Longrightarrow\qquad \frac{\partial L}{\partial\mathbf x_l}=\frac{\partial L}{\partial\mathbf x_L}\prod_{i=l}^{L-1}\left(I+\frac{\partial F_i}{\partial\mathbf x_i}\right) \]

Expand that product and one term is the bare identity: the gradient at layer \(L\) reaches layer \(l\) undiminished, no matter how many layers sit between them. Compare with Lesson 28, where the plain-network product \(\prod\gamma_i\) decayed to \(10^{-18}\) over 30 layers. The skip connection does not reduce the vanishing gradient — it adds a path that cannot vanish at all.

        super().__init__()
        self.c1 = nn.Conv2d(cin, cout, 3, stride, 1, bias=False)
        self.b1 = nn.BatchNorm2d(cout)
        self.c2 = nn.Conv2d(cout, cout, 3, 1, 1, bias=False)
        self.b2 = nn.BatchNorm2d(cout)
        # the skip must match shape; a 1x1 stride-s conv is the standard projection
        self.skip = nn.Identity() if (stride == 1 and cin == cout) else nn.Sequential(
            nn.Conv2d(cin, cout, 1, stride, bias=False), nn.BatchNorm2d(cout))

    def forward(self, x):
        out = F.relu(self.b1(self.c1(x)))
        out = self.b2(self.c2(out))
        return F.relu(out + self.skip(x))      # add BEFORE the final ReLU
Pitfall · putting the ReLU on the skip path

Writing return self.skip(x) + F.relu(out) or applying a ReLU to the shortcut breaks the identity and you lose most of the benefit — a ReLU zeroes half the gradient every time it is crossed. The order is: transform, add, then activate. And initialise the final BN's \(\gamma\) to zero (zero_init_residual=True): the block then starts as an exact identity, which measurably improves both stability and final accuracy.

EfficientNet's compound scaling

Given \(\phi\times\) more compute, how should you spend it? EfficientNet grid-searched the answer once on a small model and found that depth, width and resolution should scale together:

\[ \text{depth}=\alpha^\phi,\quad \text{width}=\beta^\phi,\quad \text{resolution}=\gamma^\phi \qquad\text{with } \alpha\beta^2\gamma^2\approx2 \]

The constraint holds because FLOPs scale linearly in depth but quadratically in width and in resolution. Their values were \(\alpha=1.2,\beta=1.1,\gamma=1.15\). The practical takeaway survives even if you never use EfficientNet: scaling one axis alone saturates fast. A network twice as deep at the same width and resolution wastes most of the extra compute.

Pitfall · FLOPs are not latency

Depthwise convolutions cut FLOPs by 9× and frequently deliver nothing like a 9× speedup — often under 2×. The reason is arithmetic intensity: a depthwise conv does very little maths per byte of memory it touches, so it is memory-bandwidth-bound and leaves the GPU's compute units idle. Dense 3×3 convolutions map beautifully onto tensor cores; depthwise ones do not. Always measure wall-clock latency on your actual target hardware. A model that is theoretically 5× cheaper and practically the same speed is a very common and very expensive surprise.

What to actually use in 2026

Default backbone: ResNet-50 — universally supported and a fair baseline. Best accuracy per FLOP on a GPU: ConvNeXt or EfficientNetV2. Mobile or edge: MobileNetV3 or MobileViT, chosen by measured latency. Small dataset: whatever has the best pretrained weights, which usually beats whatever has the best architecture. Reach for timm (Lesson 55) and compare three candidates on your data rather than reasoning about it from a table.

Pitfall · using an ImageNet stem on 32×32 images

A stock torchvision.models.resnet18 begins with a 7×7 stride-2 conv followed by a stride-2 max pool. On a 224×224 image that reduces to 56×56, which is fine. On a 32×32 image it reduces to 8×8 before the first residual block has run — you have thrown away 94% of the spatial information in two operations, and the network never recovers. Every "CIFAR ResNet" replaces the stem with a single 3×3 stride-1 conv and deletes the max pool. This one change is worth roughly 5 percentage points, and it is the most common reason people report that "ResNet doesn't work on CIFAR".

EMA — free accuracy, almost

Keep a shadow copy of the weights updated as \(\theta_{\text{ema}}\leftarrow\rho\,\theta_{\text{ema}}+(1-\rho)\,\theta\) with \(\rho\approx0.999\), and evaluate that. Box formats and IoU

Three conventions, and mixing them is a rite of passage: xyxy (corners), xywh (top-left plus size), and cxcywh (centre plus size, usually normalised to \([0,1]\)). COCO's JSON uses xywh in pixels; YOLO's text files use normalised cxcywh; torchvision expects xyxy.

\[ \text{IoU}(A,B)=\frac{|A\cap B|}{|A\cup B|}=\frac{|A\cap B|}{|A|+|B|-|A\cap B|} \] 
def iou_xyxy(a, b):
    """a (N,4), b (M,4) -> (N,M). The single most-used function in detection."""
    x1 = torch.max(a[:, None, 0], b[None, :, 0])
    y1 = torch.max(a[:, None, 1], b[None, :, 1])
    x2 = torch.min(a[:, None, 2], b[None, :, 2])
    y2 = torch.min(a[:, None, 3], b[None, :, 3])
    inter = (x2 - x1).clamp(min=0) * (y2 - y1).clamp(min=0)   # clamp: no negative overlap
    area_a = (a[:, 2] - a[:, 0]) * (a[:, 3] - a[:, 1])
    area_b = (b[:, 2] - b[:, 0]) * (b[:, 3] - b[:, 1])
    return inter / (area_a[:, None] + area_b[None, :] - inter + 1e-9)
IoU and non-max suppression · what survives, and what a threshold change costs you

Non-max suppression

Detectors produce many overlapping boxes for the same object. NMS keeps the highest-scoring one and deletes its near-duplicates:

def nms(boxes, scores, iou_thresh=0.5):
    keep, order = [], scores.argsort(descending=True)
    while order.numel() > 0:
        i = order[0]
        keep.append(i.item())
        if order.numel() == 1:
            break
        ious = iou_xyxy(boxes[i][None], boxes[order[1:]])[0]
        order = order[1:][ious <= iou_thresh]      # drop everything that overlaps too much
    return keep
Pitfall · NMS deletes real objects in crowds

Two people standing shoulder to shoulder can have genuinely overlapping boxes with IoU above 0.5. Hard NMS deletes one of them, and no amount of training fixes it because the error happens after the model. Soft-NMS decays the neighbour's score by \(s_j\leftarrow s_j\,e^{-\text{IoU}^2/\sigma}\) instead of deleting it, so a strong-but-overlapping detection survives. Also remember to run NMS per class — a "person" box and a "backpack" box are supposed to overlap. Class-agnostic NMS is a classic silent bug.

mAP, computed honestly

Average Precision for one class is the area under its precision–recall curve. The procedure:

  1. Sort all predictions for that class across the whole dataset by confidence, descending.
  2. Walk down the list. A prediction is a true positive if it has IoU ≥ threshold with an unmatched ground-truth box; otherwise it is a false positive. Each ground truth can be matched once — a second box on the same object is a duplicate, not a second hit.
  3. Accumulate precision and recall at each step, then integrate.

mAP is the mean of AP over classes. mAP@0.5 (Pascal VOC's metric) uses a single IoU threshold of 0.5 and is forgiving about box tightness. mAP@[.5:.95] (COCO's primary metric) averages AP over ten thresholds from 0.50 to 0.95 in steps of 0.05, so it heavily rewards precise localisation. A model can score 0.65 on the first and 0.42 on the second; quoting the wrong one makes numbers incomparable across papers.

Anchors and assignment, in one paragraph

Most detectors pre-place a grid of reference boxes (anchors) of several scales and aspect ratios, then predict an offset from each anchor rather than absolute coordinates — regressing a small correction is far easier than regressing a coordinate from scratch. Training then needs an assignment rule: an anchor with IoU ≥ 0.7 against some ground truth is positive, IoU < 0.3 is negative, and anything in between is ignored so it contributes no gradient. Assignment is where most of a detector's behaviour is decided, and it is why anchor-free methods (Lesson 58) are attractive — they delete a whole layer of hyperparameters.

The Region Proposal Network

A small conv head slides over the shared feature map. At every position it looks at \(k\) anchors (Faster R-CNN uses 9: three scales × three aspect ratios) and outputs, for each, an objectness score and four box offsets. Top proposals go to the second stage for classification and refinement. The RPN is trained with the same assignment rule from Lesson 56 and shares all its convolutional features with the detection head — which is exactly where the speedup comes from.

RoI Pool vs RoI Align — why half a pixel mattered

A proposal in image coordinates must be mapped onto a feature map that has been downsampled by 16 or 32. RoI Pooling rounds those coordinates to integers twice: once mapping the box onto the grid, once dividing it into bins. On a stride-16 feature map, a rounding error of 0.5 cells is 8 pixels in the original image.

For a bounding box, 8 pixels of slop is survivable. For a per-pixel mask it is fatal — the mask ends up systematically offset from the object. RoI Align removes both roundings and samples at exact fractional positions with bilinear interpolation. That single change improved Mask R-CNN's mask AP by around 10 points on COCO, and it is the reason Mask R-CNN works at all.

Feature Pyramid Networks

Deep feature maps are semantically strong but coarse (stride 32); shallow maps are fine-grained but semantically weak. A small object is invisible at stride 32 and unrecognisable at stride 4. FPN fixes this with a top-down path: upsample the deep map, add it laterally to the shallower one, and repeat — producing a pyramid where every level is both high-resolution and semantically strong. Objects are then assigned to a pyramid level by size.

FPN is not a detector; it is a neck that plugs into almost anything, and it is present in Faster R-CNN, RetinaNet, Mask R-CNN, and most YOLO variants. If you see a detector reporting a big jump on small objects, FPN or a descendant is usually why.

Two-stage vs one-stage, honestly

Two-stage detectors filter to a few hundred proposals before classifying, so their classifier sees a roughly balanced set. One-stage detectors score every one of ~100,000 anchor positions, of which perhaps ten are objects — a 10,000:1 imbalance that plain cross-entropy cannot handle. That single fact is why one-stage detection needed focal loss to become competitive, which is where Lesson 58 begins.

YOLO: detection as one regression

Divide the image into an \(S\times S\) grid. Each cell predicts \(B\) boxes with confidences plus one class distribution. The whole thing is a single forward pass with no proposal stage — hence "You Only Look Once", and hence 45 FPS in 2016 when Faster R-CNN managed 5. v1 was noticeably less accurate, especially on small and clustered objects, because one cell could only claim so many boxes. The lineage since then has mostly been engineering: anchors and multi-scale prediction (v2/v3), CSP backbones and mosaic augmentation (v4/v5), anchor-free heads and decoupled classification/regression branches (v8 onward).

Focal loss — the fix for 100,000 background anchors

With extreme foreground–background imbalance, the summed loss is dominated by a vast number of easy negatives that are each already classified correctly with \(p_t\approx0.99\). Individually negligible, collectively overwhelming. Focal loss multiplies cross-entropy by a factor that vanishes for confident predictions:

\[ \text{FL}(p_t)=-\alpha_t\,(1-p_t)^{\gamma}\log(p_t) \]

At \(\gamma=2\), an easy negative with \(p_t=0.99\) is down-weighted by \((0.01)^2=10^{-4}\), while a hard example at \(p_t=0.5\) is down-weighted only 4×. The gradient is therefore reallocated to the examples that are still wrong. RetinaNet applied this and became the first one-stage detector to beat two-stage accuracy while staying faster — one loss function closing a gap that architecture had not.

Anchor-free detection

Anchors bring scales, aspect ratios, IoU thresholds and assignment rules — a large hyperparameter surface that must be re-tuned per dataset. FCOS discards them: every feature-map location directly regresses four distances to the object's edges (left, top, right, bottom), with a "centerness" score suppressing predictions from near the boundary. CenterNet goes further and predicts object centres as peaks in a heatmap, plus a size regression — and because a peak is unique, it needs no NMS at all, just a 3×3 max-pool to find local maxima.

DETR: detection as set prediction

DETR removes both anchors and NMS by reframing the problem. A transformer decoder takes \(N=100\) learned "object queries" and outputs exactly \(N\) predictions, each a class (including a special "no object") and a box. Training uses the Hungarian algorithm to compute the optimal one-to-one matching between predictions and ground truths, then applies the loss only along that matching.

Why bipartite matching removes the need for NMS

Duplicate boxes exist because conventional detectors reward every anchor near an object. Under one-to-one matching, exactly one prediction is assigned to each ground truth and all others are pushed towards "no object". Producing a duplicate is therefore actively penalised by the loss rather than cleaned up afterwards. The architecture stops needing a hand-written post-processing step because the training objective already forbids the behaviour that step existed to fix. That is an elegant idea and worth carrying forward.

The original DETR converged notoriously slowly — 500 epochs on COCO, roughly 10× a Faster R-CNN — because global attention over all feature positions takes a long time to focus. Deformable DETR attends to a small learned set of sampling points per query instead, cutting training to 50 epochs and greatly improving small-object performance.

Which detector to actually reach for

Real-time on a modest GPU or edge device → a current YOLO. Mature tooling, excellent speed/accuracy, easy export. Highest accuracy, latency is negotiable → DINO-DETR or Cascade R-CNN with a strong backbone. You also need instance masks → Mask R-CNN, or Mask2Former. Crowded scenes → anything anchor-free or DETR-family, precisely to avoid NMS. Few-shot or open-vocabulary → Grounding DINO or OWL-ViT, which take a text prompt (Lesson 109). Start from a maintained implementation; detection has a very large amount of fiddly, easy-to-get-wrong detail, and re-implementing assignment from scratch is rarely the best use of a week.

Atrous convolution and ASPP

Segmentation faces a direct conflict: you need a large receptive field for context, but downsampling destroys the spatial precision the output needs. U-Net resolves it with skips. Heatmaps: the trick that unifies half of these

Pose estimation could regress \((x,y)\) coordinates directly. It works badly — regressing a coordinate from a global feature vector is exactly the spatially-destructive step Lesson 47 warned about. Instead, predict a heatmap per keypoint: a full-resolution map whose target is a small Gaussian centred on the true location, trained with MSE. The prediction is the argmax.

Why heatmaps beat coordinate regression

The heatmap preserves spatial structure end to end — every output pixel corresponds to an input location, so the network never has to encode "position" into a vector. It also represents uncertainty naturally: a diffuse blob means "somewhere around here", which a coordinate pair cannot express. And the loss is dense, giving gradient signal at every pixel rather than from two numbers. The same idea powers CenterNet (Lesson 58), landmark detection, and keypoint-based tracking.

CTC: reading text without knowing where the characters are

OCR has an alignment problem. A CRNN turns an image strip into \(T\) timesteps, but the word "cat" has 3 characters, not \(T\) — and nobody labelled which timestep contains which letter. Connectionist Temporal Classification solves it by introducing a blank symbol and summing the probability over every alignment that collapses to the target:

\[ p(\mathbf y\mid\mathbf x)=\sum_{\pi\in\mathcal B^{-1}(\mathbf y)}\prod_{t=1}^{T}p(\pi_t\mid\mathbf x) \]

where \(\mathcal B\) removes blanks and merges repeats, so c-aa-t, cc-a-t and -c-a-t all collapse to cat. The sum has exponentially many terms and is computed in \(O(T\cdot L)\) by dynamic programming, in the same family as the forward algorithm for HMMs. You will meet CTC again for speech in Lesson 110 — the alignment problem is identical.

Multi-object tracking

The dominant paradigm is tracking by detection: run a detector every frame, then associate detections across frames. SORT uses a Kalman filter for motion prediction plus Hungarian matching on IoU — fast, and remarkably strong. It beat far more complex trackers.

Video is expensive, and 2D often wins

3D convolutions multiply cost by the temporal kernel size. SlowFast splits the work: a slow pathway at low frame rate with many channels for appearance, a fast pathway at high frame rate with few channels for motion. But the honest baseline is worth knowing — a 2D CNN on individual frames with averaged predictions is a strong baseline on many video benchmarks, because a great many "action recognition" labels are inferable from a single frame. When classification is the wrong shape

A face recognition system cannot have a softmax output per person: the set of people changes daily, most have one enrolled photo, and retraining for each new employee is absurd. The same holds for product search, duplicate detection and re-identification. What you want instead is an embedding function \(f\) such that distance means similarity:

\[ \|f(\mathbf x_a)-f(\mathbf x_p)\|\ \ll\ \|f(\mathbf x_a)-f(\mathbf x_n)\| \]

Then adding a new class is just storing one more vector. Recognition becomes nearest-neighbour search.

Triplet loss and the mining problem

\[ \mathcal L=\max\!\Big(0,\ \|f(a)-f(p)\|^2-\|f(a)-f(n)\|^2+\alpha\Big) \]

Push the positive closer than the negative by at least a margin \(\alpha\). The subtlety is that after a few epochs, a randomly chosen triplet almost always already satisfies the margin — the loss is exactly zero and the gradient with it. Mining is therefore not an optimisation; it is the difference between training and not training.

Pitfall · hardest-negative mining collapses the model

The obvious move is to always pick the hardest negative in the batch. It fails: the hardest negatives are frequently mislabelled examples or near-duplicates, and chasing them drives \(f\) to a constant function where every distance is zero — a degenerate solution with zero loss. Use semi-hard mining instead: negatives that are farther than the positive but still inside the margin. FaceNet's result depended on this detail, and it is the standard first explanation for "my embedding model collapsed".

Margin losses: the modern answer

Triplet loss needs careful batch construction and mining. ArcFace sidesteps all of it by staying with a softmax classifier over training identities, but adding an angular margin to the correct class before the softmax:

\[ \mathcal L=-\log\frac{e^{s\cos(\theta_y+m)}}{e^{s\cos(\theta_y+m)}+\sum_{j\ne y}e^{s\cos\theta_j}} \]

Both weights and features are L2-normalised, so the logit is purely the cosine of the angle between a feature and its class centre. Adding \(m\) before the cosine forces the correct class to be right by a geometric margin on the hypersphere. Typical values \(s=64,\ m=0.5\). It trains as easily as ordinary classification, needs no mining, and outperforms triplet loss — which is why essentially all face recognition uses it now. At inference you discard the classifier and keep the embedding.

Patch arithmetic · why patch size is the most consequential ViT hyperparameter

The data hunger, and what it revealed

ViT trained on ImageNet-1k alone loses to a ResNet of similar size. Trained on JFT-300M it wins decisively. That crossover is the most instructive result in the paper: a CNN's locality and translation-equivariance priors are worth roughly 100 million images. Below that, the priors help; above it, they are a constraint the model would rather learn its way around.

DeiT then showed the gap was not really about data but about recipe: with heavy augmentation, strong regularisation and a distillation token that learns to match a CNN teacher, ViT reaches competitive ImageNet accuracy using ImageNet alone. The distillation token is a neat idea — a second special token, alongside CLS, whose loss target is the teacher's prediction, letting the model absorb the CNN's inductive bias through supervision rather than architecture.

Swin: put the hierarchy back

Plain ViT keeps one resolution throughout, which is wasteful and useless for detection or segmentation, where a feature pyramid is required. Swin restores the CNN's structure: compute attention only within local windows (7×7 patches), merge patches between stages to halve resolution and double channels, and shift the window grid by half a window on alternate layers so information crosses window boundaries. Cost drops from \(O(n^2)\) to \(O(n)\) in the number of patches, and the output is a proper multi-scale pyramid that plugs straight into FPN. Swin became the default transformer backbone for dense prediction.

CNN vs ViT — the honest summary

ViTs have weaker inductive biases, so they need more data or better recipes, but scale further and transfer better. They also see globally from layer one, where a CNN needs depth to accumulate receptive field. Their attention maps are somewhat more interpretable, and they are more robust to texture bias and some corruptions.

But ConvNeXt is the crucial control experiment. Take a ResNet-50 and apply, one at a time, the things that changed alongside the architecture — AdamW, 300 epochs, heavy augmentation, larger kernels, fewer activations and norms, LayerNorm, inverted bottlenecks — and you match Swin on ImageNet, detection and segmentation, with no attention anywhere. A large share of "transformers beat CNNs" was the training recipe, not the attention. Hold onto that scepticism when reading architecture papers; it generalises.

Pitfall · changing input resolution on a ViT

A CNN accepts any input size (Lesson 49). A ViT does not — its learned position embeddings have one entry per patch position, so a 224-trained model fed 384 pixels has 576 patches and only 196 embeddings. You must interpolate the position embeddings onto the new grid, which every good implementation provides (timm does it automatically). Skip it and you get a shape error at best, or silently scrambled positions at worst.

The premise

Labels are expensive; images are free. Self-supervised learning invents a task whose supervision comes from the data itself, learns representations by solving it, and then transfers those representations to real tasks with very few labels. Early attempts used pretext tasks — predict the rotation applied to an image, solve a jigsaw of shuffled patches, colourise a greyscale photo. They worked somewhat, but the model tends to learn shortcuts specific to the pretext rather than general features.

Contrastive learning

SimCLR's formulation: take an image, apply two random augmentations to get a positive pair, treat all other images in the batch as negatives, and pull positives together while pushing negatives apart with the NT-Xent loss:

\[ \mathcal L_{i,j}=-\log\frac{\exp\big(\text{sim}(\mathbf z_i,\mathbf z_j)/\tau\big)}{\sum_{k\ne i}\exp\big(\text{sim}(\mathbf z_i,\mathbf z_k)/\tau\big)} \]

Three details carry most of the performance, and all three are counterintuitive:

  • The augmentation is the task. Random crop plus colour distortion is essential — without colour jitter the network solves the problem by matching colour histograms, which is a shortcut, not a representation. The augmentations define what invariances you are asking for.
  • A projection head helps, and you throw it away. The contrastive loss is applied to \(g(f(\mathbf x))\), but the representation you keep is \(f(\mathbf x)\). The head absorbs the information destroyed by the invariance objective, leaving \(f\) richer than the loss alone would allow.
  • Batch size matters enormously. Negatives come from the batch, so SimCLR needs 4096+ — which is why MoCo's momentum-updated queue of past embeddings was such a practical contribution: it decouples the negative count from the batch size.
BYOL — no negatives at all, which should not work

BYOL removes negatives entirely: an online network predicts the output of a momentum-updated target network on a different augmentation of the same image. With no repulsive term, the obvious solution is to output a constant for everything. It does not collapse, and explaining why took the field several papers.

The ingredients that prevent collapse are the predictor head on the online branch only (breaking the symmetry) and the stop-gradient on the target branch. SimSiam then showed the momentum encoder is not even necessary — stop-gradient plus predictor suffices. The lesson is that architectural asymmetry can substitute for an explicit repulsive loss, which was genuinely surprising.

Masked image modeling

The BERT idea (Lesson 87) transplanted to images: mask most of the patches and reconstruct them. MAE makes it efficient and effective with two choices: mask a very high fraction — 75%, far higher than BERT's 15%, because images are much more redundant than text — and pass only the visible patches through the encoder, with a lightweight decoder reconstructing the rest. The encoder therefore processes 25% of the tokens, making pretraining roughly 3× faster despite the harder task.

DINOv2 and what to actually use

DINO is self-distillation with no labels: a student matches a teacher's output distribution over different crops, with centring and sharpening preventing collapse. Its striking property is emergent segmentation — attention maps from a DINO ViT delineate object boundaries without ever having seen a mask. DINOv2 scaled this with a heavily curated dataset, producing general-purpose features that are excellent under a frozen linear probe across classification, depth and segmentation.

The practical recommendation

Unless you are researching SSL, do not train it yourself — it requires large batches, long schedules and careful tuning. Download DINOv2 or a CLIP backbone (Lesson 109) and probe it. Train your own only when your domain is genuinely unlike natural images — satellite, histopathology, industrial inspection — and you have a large pool of unlabelled in-domain data and few labels. That is the situation SSL is actually for, and there it is transformative.

Pitfall · the linear probe can mislead

Linear probe accuracy is the standard SSL benchmark, but it measures whether information is linearly accessible, not whether it is present. A representation can encode something perfectly while a linear classifier cannot reach it, and methods can be tuned to score well on probes specifically. Always also report fine-tuned accuracy and, ideally, low-shot performance at 1% and 10% of labels — the regime you adopted SSL for in the first place.

Grad-CAM, which is the one you will use

Take the feature maps \(A^k\) of the last convolutional layer. Weight each channel by how much the target class score responds to it, then combine and keep the positive part:

\[ \alpha_k^c=\frac{1}{HW}\sum_{i,j}\frac{\partial y^c}{\partial A^k_{ij}},\qquad L^c_{\text{Grad-CAM}}=\relu\!\Big(\sum_k \alpha_k^c A^k\Big) \]

The ReLU matters: you want evidence for the class, not against it. The result is a coarse heatmap (the resolution of the last conv layer, typically 7×7) upsampled over the image. It works on any CNN with no retraining and no architectural change, which is why it displaced CAM — CAM required a global-average-pooled architecture.

class GradCAM:
    def __init__(self, model, layer):
        self.model, self.acts, self.grads = model.eval(), None, None
        layer.register_forward_hook(lambda m, i, o: setattr(self, "acts", o))
        layer.register_full_backward_hook(lambda m, gi, go: setattr(self, "grads", go[0]))

    def __call__(self, x, cls=None):
        logits = self.model(x)
        cls = logits.argmax(1) if cls is None else cls
        self.model.zero_grad()
        logits[range(len(cls)), cls].sum().backward()
        w = self.grads.mean(dim=(2, 3), keepdim=True)          # alpha_k
        cam = torch.relu((w * self.acts).sum(1, keepdim=True))
        cam = torch.nn.functional.interpolate(cam, x.shape[-2:], mode="bilinear")
        return (cam / (cam.amax(dim=(2,3), keepdim=True) + 1e-8)).squeeze(1)

What this is actually for

Not for reassuring stakeholders — for finding the bugs your metrics hide. The canonical cases are real: a pneumonia classifier attending to the hospital's scanner watermark rather than the lung; a husky-vs-wolf model attending to snow; a skin-lesion model keying on the ruler that dermatologists place beside malignancies. Every one of these had excellent validation accuracy, because the shortcut was present in validation too. Grad-CAM on your worst and your best predictions is the cheapest shortcut detector there is, and it belongs in every project's error analysis.

Adversarial examples

Take a correctly classified image and add a perturbation invisible to a human but chosen to maximise the loss:

\[ \text{FGSM:}\quad \mathbf x'=\mathbf x+\epsilon\,\mathrm{sign}\!\big(\nabla_{\mathbf x}L(\mathbf x,y)\big) \]

One gradient step with \(\epsilon=8/255\) is typically enough to flip a confident prediction. PGD iterates FGSM with small steps and projects back into the \(\epsilon\)-ball each time, and is the standard strong attack. What makes this more than a curiosity is transferability: an example crafted against one model often fools a completely different model trained on different data, which means an attacker needs no access to your weights.

Why they exist

The original "excessive non-linearity" explanation turned out to be backwards. Goodfellow's argument is that models are too locally linear: for a linear model, a perturbation \(\boldsymbol\eta\) with \(\|\boldsymbol\eta\|_\infty\le\epsilon\) changes the logit by \(\mathbf w\T\boldsymbol\eta\), which for \(\boldsymbol\eta=\epsilon\,\mathrm{sign}(\mathbf w)\) equals \(\epsilon\|\mathbf w\|_1\) — and that grows with dimension. In high-dimensional space, many tiny coordinated changes sum to a large logit shift. A later view is that adversarial examples exploit real but non-robust features: patterns that genuinely predict the label on natural data but are imperceptible and brittle. On that account the model is not malfunctioning; it is using signal we did not intend it to use.

Pitfall · defences that only look like defences

A long list of published defences worked by gradient masking — making gradients uninformative rather than making the model robust. They reported high accuracy under gradient-based attack and then fell to attacks that estimated gradients differently or attacked a substitute model. Adversarial training (train on PGD examples) remains the only broadly reliable defence, and it costs 3–10× the training time and several points of clean accuracy. If you evaluate robustness, use AutoAttack or an established benchmark, never your own attack against your own model.

Pitfall · the leak that will get you

You photograph 40 objects from 15 angles each and randomly split 600 images. Near-identical frames of the same physical object land in both train and test, and your reported mAP is fiction — you have measured memorisation.
