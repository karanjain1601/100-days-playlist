The KV cache — the most important optimisation in inference

Generating token \(t\) recomputes attention over all previous tokens. But the keys and values of tokens \(1..t-1\) do not change — only the new query does. Cache them and each new token costs \(O(n)\) instead of \(O(n^2)\), turning generation from quadratic to linear.

The cost is memory, and it is substantial:

\[ \text{KV bytes}=2\cdot B\cdot n\cdot L\cdot h_{kv}\cdot d_{\text{head}}\cdot\text{sizeof(dtype)} \]

For Llama-2-70B (\(L=80\), \(h=64\), \(d_{\text{head}}=128\)) at 4096 tokens with batch 1 in fp16, full multi-head attention would need 10.7 GB of cache for a single sequence — more than the weights of a 7B model, for one user. Serve 32 concurrent users and the cache dwarfs everything else. That number is why the next idea exists.

FlashAttention — the same maths, a different memory schedule

FlashAttention computes exactly standard attention. It is not an approximation. The insight is that GPUs are bottlenecked by memory bandwidth, not arithmetic: a naive implementation writes the \(n\times n\) score matrix to high-bandwidth memory, reads it back for the softmax, writes it again, and reads it for the value multiply. That traffic dominates the runtime.

Instead, tile the computation and keep each tile in on-chip SRAM, using the online softmax trick — a running maximum and running normaliser (Lesson 10's log-sum-exp, made incremental) that lets you finish a tile before seeing the rest of the row. The \(n\times n\) matrix is never materialised. Memory drops from \(O(n^2)\) to \(O(n)\) and wall-clock improves 2–4×, with bit-identical outputs. FlashAttention-2 improved the work partitioning; FlashAttention-3 exploits Hopper's asynchrony and FP8.

Why exact beat approximate

Between 2020 and 2022 there were dozens of sub-quadratic attention papers, and almost none are in production. FlashAttention is the reason: by removing the memory bottleneck from exact attention, it moved the practical crossover point so far out that the approximations no longer paid for their quality loss and implementation complexity. The lesson generalises — a constant-factor improvement to the exact method can defeat an asymptotic improvement to an approximate one, for any problem size people actually run.

PagedAttention (vLLM) applies operating-system virtual memory to the KV cache. Naive serving pre-allocates a contiguous block per request sized to the maximum possible length, wasting 60–80% of it. PagedAttention stores the cache in fixed-size blocks with a page table, allowing non-contiguous allocation, near-zero waste, and copy-on-write sharing of a common prompt prefix across requests. It raised serving throughput by 2–4× with no model change at all.
