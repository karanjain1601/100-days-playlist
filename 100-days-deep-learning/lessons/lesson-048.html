The operation

Slide a small weight matrix over the input and take a dot product at every position:

\[ y[i,j]=\sum_{u=0}^{k-1}\sum_{v=0}^{k-1} w[u,v]\;x[i+u,\;j+v] \;+\; b \]
It is not actually convolution

True mathematical convolution flips the kernel: \(\sum w[u,v]\,x[i-u,j-v]\). What every deep learning framework calls Conv2d is cross-correlation — no flip. It does not matter, because the kernel is learned: if the flipped version were better, gradient descent would simply learn the flipped weights. It matters only when you port hand-designed kernels from a signal-processing textbook, or read a paper that is careful about the distinction. Do not let it confuse you; it confuses everyone once.

Output size, derived

Start with a 1D input of length \(n\), kernel \(k\), padding \(p\) on each side, stride \(s\), dilation \(d\). Dilation inflates the kernel's footprint: a \(k\)-tap kernel with dilation \(d\) spans \(k_{\text{eff}}=d(k-1)+1\) positions. The first window starts at 0 and the last must fit, so the number of valid start positions is:

\[ n_{\text{out}}=\left\lfloor\frac{n+2p-\big(d(k-1)+1\big)}{s}\right\rfloor+1 \]

Every shape bug in a CNN is this formula, applied wrong. The two special cases worth memorising:

SettingResultName
\(k=3,\ p=1,\ s=1,\ d=1\)\(n_{\text{out}}=n\)"same" — the workhorse. Size preserved.
\(k=3,\ p=1,\ s=2\)\(n_{\text{out}}=\lceil n/2\rceil\)Downsample by 2 without pooling
\(k=1,\ p=0,\ s=1\)\(n_{\text{out}}=n\)1×1 conv — mixes channels only
\(p=0\)\(n_{\text{out}}=n-k+1\)"valid" — shrinks every layer

In general, \(p=\lfloor k/2\rfloor\) with odd \(k\) preserves size. Odd kernels are near-universal precisely because they have a well-defined centre and an integer "same" padding.

Multi-channel: the shape bookkeeping that actually matters

A colour image has 3 channels, and a hidden layer has however many the previous layer produced. A single filter is therefore not \(k\times k\) but \(C_{\text{in}}\times k\times k\) — it spans all input channels and collapses them to one output number per position. Stack \(C_{\text{out}}\) such filters and you get \(C_{\text{out}}\) output channels.

x (N, Cin, H, W)*W (Cout, Cin, k, k)→y (N, Cout, H′, W′)
\[ \#\text{params}=C_{\text{out}}\cdot C_{\text{in}}\cdot k^2+C_{\text{out}} \qquad\qquad \#\text{FLOPs}\approx 2\cdot C_{\text{out}}\cdot C_{\text{in}}\cdot k^2\cdot H'\cdot W' \]

Note what is not in the parameter count: \(H\) and \(W\). A conv layer's parameter count is independent of input resolution — which is why the same backbone accepts 224×224 and 512×512 images, and why only the classifier head cares about resolution.

Pitfall · assuming filters are 2D

People draw a 3×3 filter as a little square and then cannot explain where the channels went. A "3×3 conv from 64 to 128 channels" holds \(128\times64\times3\times3=73{,}728\) weights, not 9. Each of the 128 output channels owns a \(64\times3\times3\) volume. If you internalise nothing else from this lesson, internalise the shape \((C_{\text{out}},C_{\text{in}},k,k)\) — it is the source of most RuntimeError: expected input to have N channels messages.

Receptive field

The receptive field is the region of the original input that influences one output unit. Stack layers and it grows:

\[ r_{l}=r_{l-1}+\big(k_l-1\big)\prod_{i=1}^{l-1}s_i \]

Three stacked 3×3 convs with stride 1 give \(r=3\to5\to7\): the same receptive field as a single 7×7 conv, but with \(3\times(3^2C^2)=27C^2\) parameters instead of \(49C^2\), and two extra non-linearities. That single observation is the entire design principle behind VGG, and it is why almost nobody uses large kernels in the classic era.
