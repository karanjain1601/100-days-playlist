One equation

\[ \mathbf h_t=\tanh\big(W_{hh}\mathbf h_{t-1}+W_{xh}\mathbf x_t+\mathbf b\big),\qquad \mathbf y_t=W_{hy}\mathbf h_t \]

The hidden state \(\mathbf h_t\) is a fixed-size summary of everything seen so far. The same \(W_{hh}\) and \(W_{xh}\) are applied at every timestep — weight sharing across time, exactly as a CNN shares across space (Lesson 47). That is what lets one model handle any sequence length, and what lets a pattern learned at position 3 be recognised at position 300.

Backpropagation through time

Unrolling turns the RNN into a deep feedforward network, so BPTT is ordinary backprop applied to it — with one twist. Because \(W_{hh}\) is used at every step, its gradient accumulates across all of them (the fan-out rule from Lesson 22):

\[ \frac{\partial L}{\partial W_{hh}}=\sum_{t=1}^{T}\frac{\partial L_t}{\partial W_{hh}},\qquad \frac{\partial L_t}{\partial \mathbf h_k}=\frac{\partial L_t}{\partial \mathbf h_t}\prod_{i=k+1}^{t}\frac{\partial \mathbf h_i}{\partial \mathbf h_{i-1}} \] \[ \frac{\partial \mathbf h_i}{\partial \mathbf h_{i-1}}=W_{hh}\T\,\diag\!\big(1-\tanh^2(\cdot)\big) \]
Why it vanishes — and why it is worse than in a plain deep net

That product contains \(W_{hh}\T\) raised to the power \(t-k\). If the largest singular value of \(W_{hh}\) is \(\lambda\), the gradient magnitude scales roughly as \(\lambda^{t-k}\), further damped by \(\tanh'\le1\). Over 50 steps with \(\lambda=0.9\): \(0.9^{50}\approx0.005\). With \(\lambda=1.1\): \(1.1^{50}\approx117\).

There is no safe setting. \(\lambda<1\) vanishes, \(\lambda>1\) explodes, and \(\lambda=1\) is a measure-zero knife edge that training will not stay on. In a plain deep network each layer has its own matrix, so the products are of different matrices and errors partly cancel. Here it is one matrix compounded, so its spectral radius decides the fate of the whole sequence. This is the single reason the vanilla RNN was abandoned.

The cell, written out

class RNNCell(nn.Module):
    def __init__(self, d_in, d_hid):
        super().__init__()
        self.Wxh = nn.Linear(d_in,  d_hid, bias=False)
        self.Whh = nn.Linear(d_hid, d_hid, bias=True)
        # orthogonal init keeps every singular value at exactly 1 (Lesson 27)
        nn.init.orthogonal_(self.Whh.weight)

    def forward(self, x, h):
        return torch.tanh(self.Wxh(x) + self.Whh(h))

def run_sequence(cell, xs, h0):
    h, outs = h0, []
    for t in range(xs.size(1)):          # this Python loop is why RNNs are slow:
        h = cell(xs[:, t], h)            # no parallelism across time, ever
        outs.append(h)
    return torch.stack(outs, dim=1), h
Pitfall · not detaching the hidden state between batches

When training on long text you carry the hidden state from one batch to the next so the model retains context. If you pass it forward without h.detach(), autograd keeps the entire graph from the start of the epoch alive — memory grows without bound and the backward pass gets slower every step until it dies. This is truncated BPTT: keep the state as a value, discard its history. One .detach(), and it is one of the most common bugs in RNN code.

What actually helps a vanilla RNN

Gradient clipping by norm (Lesson 28) fixes explosion completely and costs one line — it is non-negotiable for any recurrent model. Orthogonal initialisation of \(W_{hh}\) starts you on the knife edge. ReLU with identity initialisation (the IRNN) helps somewhat. None of it fixes vanishing, because the problem is structural rather than numerical: information has to survive repeated multiplication. The actual fix is to build a path where it does not have to, which is Lesson 71.
