Day 71

The Transformer: Motivation & Bird's-Eye View

22 min

Diagram-driven lesson. Print the poster; you will refer to it for the next 50 days.

What recurrence costs

Sequential opsPath length between positions \(i,j\)Complexity per layer
RNN\(O(n)\)\(O(|i-j|)\)\(O(n\,d^2)\)
CNN (kernel \(k\))\(O(1)\)\(O(\log_k n)\) dilated\(O(k\,n\,d^2)\)
Self-attention\(O(1)\)\(O(1)\)\(O(n^2 d)\)

Two wins. Parallelism: an RNN must finish step \(t\) before starting \(t+1\), so a 500-token sequence takes 500 sequential GPU launches; self-attention does all positions in one matmul. Path length: for an RNN, the gradient between token 1 and token 500 traverses 500 multiplications; in self-attention it is a single edge. The cost is the \(n^2\) term, which is what Day 92 attacks.

Day 72

Self-Attention, Mathematically

28 min

Fifteen lines of code you must be able to write from memory.

Queries, keys, values

A soft dictionary lookup. Each token emits a query ("what am I looking for?"), every token offers a key ("what do I have?") and a value ("what do I contribute if selected?"). The match between query and key decides how much of each value you take.

$$Q=XW^Q,\quad K=XW^K,\quad V=XW^V,\qquad W^Q,W^K,W^V\in\mathbb{R}^{d_{\text{model}}\times d_k}$$
$$\mathrm{Attention}(Q,K,V)=\softmax\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

Why \(\sqrt{d_k}\)

Assume the components of \(\mathbf{q}\) and \(\mathbf{k}\) are independent with mean 0 and variance 1. Then

$$\mathbf{q}\cdot\mathbf{k}=\sum_{i=1}^{d_k}q_ik_i,\qquad \E[\mathbf{q}\cdot\mathbf{k}]=0,\qquad \mathrm{Var}(\mathbf{q}\cdot\mathbf{k})=d_k$$

So the standard deviation of the logits grows as \(\sqrt{d_k}\). At \(d_k=64\) the logits have sd 8; a softmax over logits with sd 8 is nearly one-hot, and \(\partial\softmax/\partial z\to0\) in the saturated regime — the gradient dies before training starts. Dividing by \(\sqrt{d_k}\) restores unit variance. This is not a normalization convention; it is a fix for a specific vanishing-gradient failure.

Scaled dot-product attention — a full worked example on 4 tokens

Masks

Padding mask — never attend to <pad>. Shape \((B,1,1,n)\), broadcast over heads and query positions. Causal mask — position \(i\) may attend only to \(j\le i\). An upper-triangular matrix of \(-\infty\), shape \((1,1,n,n)\). Both are applied to the logits before the softmax.

def scaled_dot_product_attention(q, k, v, mask=None, dropout=None):
    # q,k,v: (B, h, n, d_k)   mask: broadcastable to (B, h, n, n), True = keep
    d_k = q.size(-1)
    scores = q @ k.transpose(-2, -1) / math.sqrt(d_k)      # (B,h,n,n)
    if mask is not None:
        scores = scores.masked_fill(~mask, torch.finfo(scores.dtype).min)
    attn = scores.softmax(dim=-1)
    if dropout is not None: attn = dropout(attn)
    return attn @ v, attn                                  # (B,h,n,d_k), (B,h,n,n)
Use torch.finfo(dtype).min, not -inf In fp16, \(-\infty\) minus anything is NaN, and a fully-masked row produces NaN after softmax. The dtype minimum is finite and behaves. If a whole row is masked (an empty sequence in the batch), you still get a uniform distribution rather than NaN — handle that case explicitly.

Day 73

Multi-Head Attention

22 min

One attention distribution is one relation. Language needs many at once.

The problem with one head

Softmax produces a single probability distribution per query, so a token can only strongly attend to one place at a time. But "sat" needs its subject and its object and its adverbial, simultaneously. Splitting into \(h\) heads gives \(h\) independent distributions.

$$\mathrm{MHA}(X)=\mathrm{Concat}(\mathrm{head}_1,\dots,\mathrm{head}_h)W^O,\qquad \mathrm{head}_i=\mathrm{Attention}(XW_i^Q,XW_i^K,XW_i^V)$$
$$d_k=d_v=\frac{d_{\text{model}}}{h}\quad\Longrightarrow\quad \text{total cost} \approx \text{single-head cost with } d_k=d_{\text{model}}$$

Multi-head attention is therefore free relative to a single wide head. \(d_{\text{model}}=512, h=8 \Rightarrow d_k=64\).

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model, h, dropout=0.1):
        super().__init__()
        assert d_model % h == 0
        self.h, self.d_k = h, d_model // h
        self.qkv = nn.Linear(d_model, 3 * d_model, bias=False)   # fused: one matmul
        self.out = nn.Linear(d_model, d_model)
        self.drop = nn.Dropout(dropout)

    def forward(self, x, mask=None):
        B, n, _ = x.shape
        q, k, v = self.qkv(x).chunk(3, dim=-1)
        # (B,n,d) -> (B,n,h,d_k) -> (B,h,n,d_k)
        shape = lambda t: t.view(B, n, self.h, self.d_k).transpose(1, 2)
        q, k, v = shape(q), shape(k), shape(v)
        y, attn = scaled_dot_product_attention(q, k, v, mask, self.drop)
        y = y.transpose(1, 2).contiguous().view(B, n, self.h * self.d_k)
        return self.out(y), attn
Two implementation notes Fuse Q, K and V into one Linear(d, 3d) — one large matmul beats three small ones on a GPU. And .contiguous() after the transpose is required before .view(), because transpose only changes strides; forgetting it raises an error, and using .reshape() instead silently copies.

What heads specialize in

Probing studies (Clark et al., Voita et al.) consistently find recognisable roles: positional heads attending to the previous or next token; syntactic heads tracking specific dependency relations — direct objects to their verbs, determiners to their nouns, prepositions to their objects; coreference heads linking pronouns to antecedents; and a large number of heads attending overwhelmingly to [SEP] or the first token, which appears to function as a no-op — a place to dump attention when the head has nothing to contribute.

Most heads can be removed Michel et al. found that at test time a majority of heads can be pruned with negligible loss, and many layers work fine with a single head. Voita et al. found ~10% of heads do most of the syntactic work and the rest are redundant. So multi-head attention is over-parameterized — but the redundancy appears to matter during training, giving optimization more paths to a good solution. Prune after training, not before.

Day 74

Positional Encoding

24 min

Attention is a set operation. Position has to be injected, and how you inject it decides your context length.

The permutation-invariance problem

Permute the rows of \(X\) and \(\softmax(QK^\top/\sqrt{d_k})V\) permutes identically — the output for a token depends on the multiset of other tokens, not their order. Without positional information, dog bites man and man bites dog are the same input.

Sinusoidal

$$PE_{(pos,2i)}=\sin\!\left(\frac{pos}{10000^{2i/d}}\right),\qquad PE_{(pos,2i+1)}=\cos\!\left(\frac{pos}{10000^{2i/d}}\right)$$

Each dimension is a sinusoid with a different wavelength, from \(2\pi\) up to \(10000\cdot2\pi\) — a binary-like positional code in continuous form. The key property:

$$PE_{pos+k}=M_k\cdot PE_{pos}\quad\text{for a fixed rotation matrix } M_k \text{ depending only on } k$$

So a relative offset is a linear function of the encoding, which the attention's linear projections can in principle learn to extract. And because it is a closed-form function, it is defined for positions beyond any seen in training — though in practice extrapolation quality degrades quickly.

Sinusoidal encoding heatmap · and RoPE's rotation property

Learned absolute

Just an \(\texttt{nn.Embedding}(n_{\max}, d)\) added to the token embeddings. What BERT and GPT-2 use. Simple, marginally better in-distribution, and hard-capped: position 513 in a 512-trained model has no embedding at all.

Relative positions

Shaw et al. add a learned vector per relative offset into the key and value computations. T5 simplifies this to a learned scalar bias per bucket of relative distance, added to the attention logits, with logarithmically-spaced buckets so far-apart positions share a bucket. Cheap, and it extrapolates better than absolute.

RoPE — what modern LLMs use

Instead of adding position, rotate the query and key vectors by an angle proportional to position. Treat consecutive dimension pairs as complex numbers and multiply by \(e^{i m\theta}\):

$$\tilde{\mathbf{q}}_m=R_{\Theta,m}\mathbf{q},\qquad R_{\Theta,m}^{(i)}=\begin{pmatrix}\cos m\theta_i & -\sin m\theta_i\\ \sin m\theta_i & \cos m\theta_i\end{pmatrix},\qquad \theta_i=10000^{-2i/d}$$
$$\langle R_{\Theta,m}\mathbf{q},\ R_{\Theta,n}\mathbf{k}\rangle=\langle \mathbf{q},\ R_{\Theta,n-m}\mathbf{k}\rangle \;=\; f(\mathbf{q},\mathbf{k},\,n-m)$$

The inner product depends only on the relative offset \(n-m\) — exactly, not approximately, and with no extra parameters and no change to the attention kernel. That identity is why RoPE won. It also composes cleanly with KV caching, since a cached key keeps its rotation.

ALiBi

$$\text{logits}_{ij}\;\leftarrow\;\mathbf{q}_i^\top\mathbf{k}_j - m_h\cdot|i-j|$$

No positional embeddings at all — just a linear penalty on distance, with a different slope \(m_h\) per head (a geometric sequence). Trivially cheap, and it extrapolates to sequences several times longer than trained. Its cost is an inductive bias toward recency that some tasks do not want.

Day 75

Inside the Transformer Block

24 min

Where the parameters actually live, and the one-line change that decides whether training diverges.

Residuals

$$\mathbf{x}_{\ell+1}=\mathbf{x}_\ell+F(\mathbf{x}_\ell)\quad\Longrightarrow\quad \frac{\partial\mathbf{x}_{\ell+1}}{\partial\mathbf{x}_\ell}=I+\frac{\partial F}{\partial\mathbf{x}_\ell}$$

The identity term guarantees a gradient path with multiplier 1 straight to the input, no matter how deep the stack. A 96-layer network without residuals does not train; with them it does. Read the residual stream as a shared memory that each block reads from and writes to.

LayerNorm vs BatchNorm

$$\mathrm{LN}(\mathbf{x})=\gamma\odot\frac{\mathbf{x}-\mu}{\sqrt{\sigma^2+\varepsilon}}+\beta,\qquad \mu=\frac{1}{d}\sum_{i=1}^{d}x_i,\ \ \sigma^2=\frac{1}{d}\sum_{i=1}^{d}(x_i-\mu)^2$$

LayerNorm normalizes across features within one token. BatchNorm normalizes across the batch per feature — which for text means the statistics depend on how many padded positions happen to be in the batch, differ between training and inference, and break at batch size 1. LayerNorm has none of those problems, which is why NLP uses it everywhere.

$$\mathrm{RMSNorm}(\mathbf{x})=\gamma\odot\frac{\mathbf{x}}{\sqrt{\frac{1}{d}\sum_i x_i^2+\varepsilon}}$$

RMSNorm drops the mean subtraction and the bias. ~10–15% faster, no measurable quality loss, and it is what LLaMA and most modern LLMs use.

The feed-forward network

$$\mathrm{FFN}(\mathbf{x})=W_2\,f(W_1\mathbf{x}+\mathbf{b}_1)+\mathbf{b}_2,\qquad W_1\in\mathbb{R}^{4d\times d},\ W_2\in\mathbb{R}^{d\times 4d}$$

Applied identically and independently at every position — it is a 1×1 convolution over time. The 4× expansion is empirical. SwiGLU replaces the single projection with a gated pair:

$$\mathrm{SwiGLU}(\mathbf{x})=\bigl(\mathrm{Swish}(W_1\mathbf{x})\odot W_3\mathbf{x}\bigr)W_2,\qquad \mathrm{Swish}(z)=z\,\sigma(z)$$

Three matrices instead of two, so the hidden width is reduced to \(\tfrac{8}{3}d\) to keep the parameter count matched. Consistently a small win, and standard in modern LLMs.

Day 76

Build a Transformer From Scratch I: The Encoder

30 min

Assemble the pieces. Assert the shapes at every layer or you will spend the evening hunting a silent broadcast.

import math, torch, torch.nn as nn

class PositionalEncoding(nn.Module):
    def __init__(self, d, max_len=5000, dropout=0.1):
        super().__init__()
        self.drop = nn.Dropout(dropout)
        pe  = torch.zeros(max_len, d)
        pos = torch.arange(max_len).unsqueeze(1).float()
        div = torch.exp(torch.arange(0, d, 2).float() * (-math.log(10000.0) / d))
        pe[:, 0::2] = torch.sin(pos * div)
        pe[:, 1::2] = torch.cos(pos * div)
        self.register_buffer("pe", pe.unsqueeze(0))    # buffer: saved, not trained
    def forward(self, x):                              # (B,n,d)
        return self.drop(x + self.pe[:, :x.size(1)])

class EncoderLayer(nn.Module):
    def __init__(self, d, h, d_ff, dropout=0.1):
        super().__init__()
        self.attn = MultiHeadAttention(d, h, dropout)
        self.ff   = nn.Sequential(nn.Linear(d, d_ff), nn.GELU(),
                                  nn.Dropout(dropout), nn.Linear(d_ff, d))
        self.ln1, self.ln2 = nn.LayerNorm(d), nn.LayerNorm(d)
        self.drop = nn.Dropout(dropout)

    def forward(self, x, mask=None):                   # PRE-LN
        a, attn = self.attn(self.ln1(x), mask)
        x = x + self.drop(a)
        x = x + self.drop(self.ff(self.ln2(x)))
        return x, attn

class Encoder(nn.Module):
    def __init__(self, V, d=512, h=8, d_ff=2048, N=6, dropout=0.1, pad=0):
        super().__init__()
        self.d   = d
        self.emb = nn.Embedding(V, d, padding_idx=pad)
        self.pos = PositionalEncoding(d, dropout=dropout)
        self.layers = nn.ModuleList(EncoderLayer(d, h, d_ff, dropout) for _ in range(N))
        self.ln = nn.LayerNorm(d)                      # final norm: required with pre-LN
        self.apply(self._init)

    @staticmethod
    def _init(m):
        if isinstance(m, nn.Linear):
            nn.init.xavier_uniform_(m.weight)
            if m.bias is not None: nn.init.zeros_(m.bias)
        elif isinstance(m, nn.Embedding):
            nn.init.normal_(m.weight, std=0.02)

    def forward(self, src, src_mask):                  # src (B,n)  src_mask (B,n) bool
        x = self.pos(self.emb(src) * math.sqrt(self.d))
        mask = src_mask[:, None, None, :]              # (B,1,1,n) broadcast over h and queries
        maps = []
        for layer in self.layers:
            x, a = layer(x, mask); maps.append(a)
        return self.ln(x), maps
Why * math.sqrt(d) on the embeddings Embeddings are initialized with std ≈ 0.02, so their entries are far smaller than the positional encoding's, which lives in \([-1,1]\). Without the scale-up, position swamps content in the first layer. It is one character of code and a real bug if you omit it.

The shape-assertion harness

def test_encoder():
    B, n, V, d, h, N = 4, 17, 1000, 64, 4, 3
    enc = Encoder(V, d=d, h=h, d_ff=4*d, N=N)
    src = torch.randint(1, V, (B, n)); src[0, 12:] = 0          # pad doc 0
    mask = src != 0
    out, maps = enc(src, mask)
    assert out.shape == (B, n, d),          out.shape
    assert len(maps) == N
    assert maps[0].shape == (B, h, n, n),   maps[0].shape
    # attention to padded positions must be exactly zero
    assert maps[-1][0, :, :, 12:].abs().max() < 1e-6
    # rows of the attention matrix must sum to 1
    assert torch.allclose(maps[0].sum(-1), torch.ones(B, h, n), atol=1e-5)
    # permutation equivariance WITHOUT positions (sanity check of the mechanism)
    print("ok", sum(p.numel() for p in enc.parameters()), "params")

(2) Forgetting register_buffer for the positional encoding, so it is not moved to the GPU by .to(device) and you get a device mismatch — or worse, it becomes a trained parameter. (3) Applying dropout to the residual input rather than the sublayer output, which slowly degrades the residual stream.

Day 77

Build a Transformer From Scratch II: Decoder & Training

30 min

Two attention blocks, one mask you must get exactly right, and a convergence checklist.

The causal mask

def causal_mask(n, device):
    return torch.tril(torch.ones(n, n, dtype=torch.bool, device=device))[None, None]

def make_tgt_mask(tgt, pad=0):
    B, n = tgt.shape
    pad_m = (tgt != pad)[:, None, None, :]           # (B,1,1,n)
    return pad_m & causal_mask(n, tgt.device)        # (B,1,n,n)

class DecoderLayer(nn.Module):
    def __init__(self, d, h, d_ff, dropout=0.1):
        super().__init__()
        self.self_attn  = MultiHeadAttention(d, h, dropout)
        self.cross_attn = MultiHeadAttention(d, h, dropout)   # needs separate q / kv inputs
        self.ff = nn.Sequential(nn.Linear(d, d_ff), nn.GELU(),
                                nn.Dropout(dropout), nn.Linear(d_ff, d))
        self.ln1, self.ln2, self.ln3 = (nn.LayerNorm(d) for _ in range(3))
        self.drop = nn.Dropout(dropout)

    def forward(self, x, mem, tgt_mask, src_mask):
        a, _  = self.self_attn(self.ln1(x), tgt_mask)
        x = x + self.drop(a)
        c, ca = self.cross_attn(self.ln2(x), src_mask, kv=mem)   # Q=x, K=V=mem
        x = x + self.drop(c)
        x = x + self.drop(self.ff(self.ln3(x)))
        return x, ca

Weight tying

$$W_{\text{out}} = E^\top \quad\text{where } E\in\mathbb{R}^{|V|\times d}\text{ is the embedding matrix}$$

Sharing the input embedding with the output projection saves \(|V|\cdot d\) parameters (about 23M for BERT-base) and usually improves perplexity — the intuition is that a token's input and output representations should live in the same space. Standard in GPT-2, T5 and most LLMs. In an encoder–decoder you can additionally tie source and target embeddings if the vocabulary is shared.

Training

crit = nn.CrossEntropyLoss(ignore_index=PAD, label_smoothing=0.1)

def loss_fn(logits, tgt_out):
    return crit(logits.reshape(-1, logits.size(-1)), tgt_out.reshape(-1))

# the original inverse-sqrt schedule, if you don't know the total step count
def noam(step, d_model, warmup=4000):
    step = max(step, 1)
    return d_model ** -0.5 * min(step ** -0.5, step * warmup ** -1.5)

opt   = torch.optim.AdamW(model.parameters(), lr=1.0, betas=(0.9, 0.98),
                          eps=1e-9, weight_decay=0.01)
sched = torch.optim.lr_scheduler.LambdaLR(opt, lambda s: noam(s, D_MODEL, 4000))

Note \(\beta_2=0.98\) rather than 0.999: transformer gradients are noisier early, and the shorter second-moment window adapts faster. This is in the original paper and is still a reasonable default for from-scratch training.

Day 78

Subword Tokenization: Byte-Pair Encoding

24 min

The compression algorithm that quietly decides your model's arithmetic ability and your API bill.

The closed-vocabulary problem

Word-level vocabularies leak OOV forever (Heaps' law, Day 12). Character-level has no OOV but makes sequences 5× longer, and attention is \(O(n^2)\). Subword sits between: frequent words stay whole, rare words decompose into meaningful pieces.

The merge algorithm

  1. Start with a vocabulary of individual characters (or bytes).
  2. Count all adjacent symbol pairs across the corpus.
  3. Merge the most frequent pair into a new symbol; record the merge.
  4. Repeat until the vocabulary reaches the target size.

The merge table is ordered, and encoding applies merges in exactly that order. That ordering is the model — lose it and the tokenizer is useless.

Train BPE and watch the merges — then encode a word it has never seen

Byte-level BPE

GPT-2's variant starts from the 256 possible bytes rather than Unicode characters. Consequences: no <unk> is possible, ever, for any input in any language or encoding; the base vocabulary is a fixed 256; and emoji, code, and unseen scripts all work. The cost is that non-Latin scripts fragment heavily — a Devanagari character is 3 UTF-8 bytes, so Hindi costs several times more tokens per word than English.

The tradeoff

Vocab sizeSequence lengthEmbedding paramsEffect
~1kvery longtinynear character-level; attention cost explodes
~32kbalanced\(32k\times d\)the usual monolingual choice
~128k–256kshortlargemultilingual models; better fertility for non-English
What tokenization silently breaks Arithmetic — if 1234 is one token but 1235 splits as 123+5, digit-wise algorithms cannot be learned consistently. Models that tokenize digits individually do notably better at maths. Code — indentation matters, and a tokenizer that merges runs of spaces inconsistently makes Python harder. Non-English cost — the same sentence can cost 2–5× more tokens in Hindi, Thai or Burmese than in English, which is simultaneously a context-length penalty, a latency penalty and a literal billing penalty. Trailing whitespace — "hello" and "hello " tokenize differently and can produce very different completions.

Day 79

WordPiece, Unigram LM & SentencePiece

22 min

Three more ways to split a word, and the one that lets you train on raw bytes with no pre-tokenizer.

WordPiece

Same greedy merging as BPE, different criterion. BPE merges the most frequent pair; WordPiece merges the pair that most increases the likelihood of the corpus under a unigram language model:

$$\text{score}(a,b)=\frac{\mathrm{count}(ab)}{\mathrm{count}(a)\cdot\mathrm{count}(b)}$$

This is PMI in disguise (Day 18), so it prefers pairs that co-occur more than chance rather than pairs that are merely common. It is why WordPiece avoids merging th + e just because both are frequent. BERT uses WordPiece with the ## continuation prefix: tokenization → token ##ization. Encoding is longest-match-first from the left, not a merge replay.

Unigram LM

Works backwards. Start with a large candidate vocabulary (all substrings up to some length), then iteratively prune:

  1. Fit unigram probabilities \(p(x_i)\) over the current vocabulary with EM, where a word's probability marginalizes over all its segmentations.
  2. For each token, compute the loss increase if it were removed.
  3. Drop the bottom ~20% by that criterion. Repeat until the target size.
$$P(\mathbf{x})=\prod_{i=1}^{M}p(x_i),\qquad \mathbf{x}^{*}=\argmax_{\mathbf{x}\in S(X)}P(\mathbf{x})$$

Because it is a proper probabilistic model, it can sample segmentations instead of always taking the best one. That is subword regularization: during training, randomly segment the same word differently across epochs, which acts as data augmentation and gains ~1 BLEU in low-resource MT. BPE-dropout achieves the same effect for BPE by randomly skipping merges.

SentencePiece

Not an algorithm but a framework (implementing both BPE and Unigram) whose key design choice is treating the input as a raw character stream, including spaces, which it encodes as ▁ (U+2581). Consequences:

  • No language-specific pre-tokenizer needed — works identically for English, Chinese, Thai, Japanese.
  • Detokenization is lossless and trivial: replace ▁ with a space and concatenate. No detokenizer heuristics, no "don't" reassembly bugs.
  • The same model file handles training and inference, so there is no drift between them.

Fertility: the number to measure

$$\text{fertility}=\frac{\#\text{subword tokens}}{\#\text{words}}$$

English on a 32k English-trained vocabulary: ~1.2–1.4. The same text on a multilingual vocabulary: ~1.6. Finnish or Turkish on an English vocabulary: 2.5–4. Fertility is directly proportional to compute cost, context consumption and price, so it is worth training a domain tokenizer when your text is unusual — medical, legal, code, or a non-Latin script.

The lineage

word2vec / GloVe (2013–14)
Transfer the embedding layer only. One vector per word type, no context.
ELMo (2018)
A deep bidirectional LSTM language model; the transferred representation is a learned weighted sum of all layers, \(\mathbf{h}_k=\gamma\sum_j s_j\mathbf{h}_{k,j}\), with the task learning \(s_j\). First widely-used contextual embeddings. Still feature-based.
ULMFiT (2018)
Fine-tuning done properly for text: (1) pretrain an LM on general text, (2) fine-tune the LM on the target domain's unlabelled text, (3) fine-tune a classifier head. Every one of those tricks is still used.
BERT / GPT (2018)
Transformer + massive scale + fine-tuning. The paradigm.

Self-supervision as free labels

The objective is generated from the data itself, so the supply of training signal equals the supply of text. Next-token prediction, masked-token prediction, span corruption, replaced-token detection, next-sentence prediction, contrastive sentence pairs — all of them turn unlabelled text into a supervised problem with billions of examples.

Catastrophic forgetting

Fine-tuning on a small target task can destroy the pretrained knowledge, especially with a high learning rate or many epochs. Mitigations: small LR (\(2\times10^{-5}\), not \(10^{-3}\)), few epochs (2–4), gradual unfreezing, layer-wise LR decay, mixing in some pretraining data, or freezing lower layers entirely. Parameter-efficient methods (Day 96) sidestep it by not touching the base weights at all.

"Foundation model" — when the term became load-bearing Coined in the 2021 Stanford report to name a real shift: a single pretrained artifact serving as the shared basis for many downstream systems. The term is useful because it points at the homogenization risk — when a thousand applications inherit one model, they inherit its biases, its blind spots and its failure modes simultaneously. It is a claim about supply-chain structure, not about capability.

Day 81

BERT: Architecture & Pretraining

28 min

Bidirectional encoding needs a different objective. That single constraint explains the whole design.

Why not next-token prediction?

An encoder attends in both directions, so a next-token objective would let position \(t\) simply read \(t+1\) — the task becomes trivial and nothing is learned (the same leak as the BiRNN on Day 62). BERT's answer: corrupt the input and reconstruct it.

Masked language modelling

Select 15% of token positions. For each selected position:

ShareReplace withWhy
80%[MASK]the actual reconstruction task
10%a random tokenforces the model to build a representation of every token, not just masked ones — it can never fully trust the input
10%the original tokenbiases the representation toward the observed word, and closes part of the pretrain/fine-tune gap
The pretrain–finetune mismatch [MASK] appears in pretraining and never at fine-tuning time. The 80/10/10 recipe reduces but does not remove that mismatch. ELECTRA (Day 84) removes it entirely by never using a mask token. Also note the sample efficiency cost: only 15% of positions produce a loss signal, so BERT extracts far less learning per token than a causal LM does.

Next sentence prediction, and its retraction

Given sentence A and B, predict whether B actually follows A (50% real, 50% random). Intended to teach discourse relations for QA and NLI. RoBERTa showed it was unnecessary and mildly harmful — the "random" negatives came from different documents, so the task collapsed to topic detection, which the model gets for free. Modern encoders drop it or replace it with sentence-order prediction (ALBERT), which uses the same two sentences in swapped order and is genuinely about coherence.

The three embedding sums

$$\mathbf{h}^0_i = \underbrace{E_{\text{token}}(x_i)}_{30522\times768} + \underbrace{E_{\text{segment}}(s_i)}_{2\times768} + \underbrace{E_{\text{position}}(i)}_{512\times768}$$

followed by LayerNorm and dropout. [CLS] at position 0 is a learned aggregate used for sentence-level tasks; [SEP] separates the two segments; segment embeddings mark which sentence each token belongs to.

ConfigLHAParamsNotes
BERT-base1276812110Mthe workhorse; fine-tunes on one consumer GPU
BERT-large24102416340M+2–3 points, notoriously unstable on small data

Pretraining data: BooksCorpus (800M words) + English Wikipedia (2500M words), max sequence 512, 1M steps, batch 256. Roughly 16 TPU-days for base.

What each layer learns

Probing (Tenney et al., "BERT rediscovers the classical NLP pipeline") finds an ordering that mirrors a hand-built pipeline: layers 1–4 surface features and POS; 4–8 syntax, constituents, dependencies; 8–12 semantic roles, coreference, and task-specific abstraction. The practical consequence: for a syntactic task, the middle layers may transfer better than the last one — do not assume the top layer is always the right feature.

The head

$$\mathbf{h}_{\texttt{[CLS]}}\in\mathbb{R}^{768}\ \longrightarrow\ \tanh(W_p\mathbf{h}+\mathbf{b}_p)\ \longrightarrow\ \text{dropout}\ \longrightarrow\ W_c\cdot(\cdot)+\mathbf{b}_c \in\mathbb{R}^{C}$$

That is fewer than 600k new parameters on top of 110M pretrained ones. Almost everything you need is already in the encoder; you are learning a readout.

Instability on small datasets

With fewer than ~5,000 examples, BERT-large fine-tuning fails outright on a noticeable fraction of random seeds — the loss stays at chance. Documented causes and fixes:

  • Optimizer bug in the original BERT code — it omitted Adam's bias correction. Modern AdamW includes it; this alone removed much of the instability.
  • Train longer with more warmup — Mosbach et al. showed most "failed runs" are simply under-trained; 20 epochs with early stopping beats 3.
  • Re-initialize the top \(k\) layers — the last few pretrained layers are the most task-specific and often the least useful; resetting 2–6 of them helps.
  • Layer-wise LR decay — \(\eta_\ell=\eta\cdot\xi^{L-\ell}\) with \(\xi\approx0.9\text{–}0.95\), so lower layers move less.
  • Report mean ± std over ≥5 seeds. A single-seed number on a small dataset is not a result.
def layerwise_lr_groups(model, base_lr=2e-5, xi=0.95, wd=0.01):
    no_decay = ("bias", "LayerNorm.weight")
    layers = [model.bert.embeddings] + list(model.bert.encoder.layer)
    groups, n = [], len(layers)
    for i, layer in enumerate(layers):
        lr = base_lr * (xi ** (n - i))            # top layers get the full LR
        groups += [
          {"params": [p for k,p in layer.named_parameters() if not any(x in k for x in no_decay)],
           "lr": lr, "weight_decay": wd},
          {"params": [p for k,p in layer.named_parameters() if any(x in k for x in no_decay)],
           "lr": lr, "weight_decay": 0.0},
        ]
    groups.append({"params": model.classifier.parameters(), "lr": base_lr*10, "weight_decay": wd})
    return groups

BERT for Token Classification & Question Answering

26 min

The subword alignment trap, and span prediction. Two tasks, one shared bookkeeping problem.

The alignment problem

Your labels are per word. The model consumes subwords. Washington might become Wash ##ing ##ton — one label, three tokens. Get this wrong and your F1 quietly drops several points.

def align_labels(examples, tok, label2id, label_all_subwords=False):
    enc = tok(examples["tokens"], is_split_into_words=True,
              truncation=True, max_length=256)
    all_labels = []
    for i, labels in enumerate(examples["ner_tags"]):
        word_ids, prev, out = enc.word_ids(batch_index=i), None, []
        for wid in word_ids:
            if wid is None:                      # [CLS], [SEP], [PAD]
                out.append(-100)
            elif wid != prev:                    # first subword of a word
                out.append(labels[wid])
            else:                                # continuation subwords
                if not label_all_subwords:
                    out.append(-100)             # ignored by the loss
                else:
                    lab = labels[wid]
                    name = id2label[lab]
                    out.append(label2id[name.replace("B-", "I-")] if name.startswith("B-") else lab)
            prev = wid
        all_labels.append(out)
    enc["labels"] = all_labels
    return enc
Three traps in nine lines (1) -100 is CrossEntropyLoss's default ignore_index — any other value trains the model on garbage. (2) If you do label continuation subwords, a B-PER must become I-PER on the continuations, or you create spurious entity starts. (3) At prediction time you must map subword predictions back to words — take the first subword's prediction, and use offset_mapping to recover the original character span. Never assume detokenization by whitespace joins correctly.

Extractive QA as span prediction

Two linear heads over the token representations produce start and end logits:

$$P_{\text{start}}(i)=\frac{e^{\mathbf{s}^\top\mathbf{h}_i}}{\sum_j e^{\mathbf{s}^\top\mathbf{h}_j}},\qquad P_{\text{end}}(i)=\frac{e^{\mathbf{e}^\top\mathbf{h}_i}}{\sum_j e^{\mathbf{e}^\top\mathbf{h}_j}},\qquad \mathcal{L}=-\tfrac12\bigl(\log P_{\text{start}}(i^*)+\log P_{\text{end}}(j^*)\bigr)$$

At inference, score each candidate span by \(\log P_{\text{start}}(i)+\log P_{\text{end}}(j)\) subject to \(i\le j\) and \(j-i+1\le L_{\max}\). Take the top-\(n\) starts and ends, form the pairs, filter, and pick the best.

SQuAD v1 vs v2

v1 guarantees the answer is in the passage. v2 adds 50k unanswerable questions, written adversarially to look answerable — and that changes the task fundamentally, because the model must now decide whether to answer. The standard trick: treat position 0 ([CLS]) as the "no answer" span, then compare

$$s_{\text{null}}=\text{start}_0+\text{end}_0 \quad\text{vs.}\quad s_{\text{best}}=\max_{i\le j}\bigl(\text{start}_i+\text{end}_j\bigr)$$

and abstain if \(s_{\text{null}} - s_{\text{best}} > \tau\), with \(\tau\) tuned on the dev set. That threshold is worth several F1 points on its own — tune it, and report it.

Long contexts: stride windows

enc = tok(questions, contexts,
          truncation="only_second", max_length=384, stride=128,
          return_overflowing_tokens=True, return_offsets_mapping=True,
          padding="max_length")
# one example can become several features; keep sample_mapping to regroup them,
# and at post-processing take the best span across ALL features of one example.

truncation="only_second" is essential — truncating the question instead of the context would destroy the query. The stride overlap ensures an answer straddling a window boundary is fully contained in at least one window.

Metrics

Exact Match — normalized string equality (lowercase, strip articles and punctuation). F1 — token-level overlap between predicted and gold answer, which gives partial credit for "the Eiffel Tower" vs "Eiffel Tower". Report both; the gap between them tells you whether your errors are boundary errors or wrong-answer errors.

Distillation, properly

$$\mathcal{L}=\alpha\underbrace{\mathcal{L}_{\text{CE}}(y,\ \sigma(z_s))}_{\text{hard labels}}+\beta\underbrace{T^2\,\KL\!\bigl(\sigma(z_t/T)\,\|\,\sigma(z_s/T)\bigr)}_{\text{soft teacher targets}}+\gamma\underbrace{\bigl(1-\cos(\mathbf{h}_t,\mathbf{h}_s)\bigr)}_{\text{hidden-state alignment}}$$

The \(T^2\) factor keeps the soft-target gradient magnitude comparable to the hard-target one as \(T\) varies. The soft targets carry dark knowledge: the teacher's relative probabilities over wrong classes encode similarity structure that a one-hot label throws away.

Gururangan et al. showed continued pretraining on domain text (DAPT) and on the task's own unlabelled text (TAPT) each help, and they stack.

In-context learning

GPT-3's headline: put \(k\) input-output examples in the prompt and the model performs the task without any weight update. Zero-shot (instruction only), one-shot, few-shot (10–100 examples). What is actually going on is contested — the leading explanations are that the demonstrations mainly specify the format and label space rather than teaching the mapping (Min et al. found that randomizing the labels in the demonstrations barely hurts performance on many tasks), and that attention can implement something functionally similar to gradient descent on the demonstrations. Either way, in-context learning is real, sensitive to example order, and not a substitute for fine-tuning when you have data.

The KV cache

Generating token \(t+1\) recomputes \(K\) and \(V\) for all \(t\) previous tokens — pure waste, since those tokens have not changed. Cache them:

$$\text{cache size}=2\cdot L\cdot n\cdot h\cdot d_k\cdot b\ \text{bytes}\quad(\text{K and V, per sequence})$$

For LLaMA-7B (\(L=32\), \(h=32\), \(d_k=128\)) at 4,096 tokens in fp16: \(2\times32\times4096\times32\times128\times2 \approx 2.1\) GB per sequence. Batch 16 and the cache alone exceeds the model weights. This is why generation is memory-bandwidth-bound, not compute-bound, and why grouped-query attention (Day 91) and PagedAttention (Day 115) exist.

import time, torch
from transformers import AutoTokenizer, AutoModelForCausalLM

tok = AutoTokenizer.from_pretrained("gpt2")

ids = tok("The history of natural language processing", return_tensors="pt").input_ids

def gen(use_cache, n=60):
    t0 = time.time()
    with torch.no_grad():
        out = m.generate(ids, max_new_tokens=n, do_sample=False, use_cache=use_cache)
    return time.time() - t0, tok.decode(out[0])

t_on,  _ = gen(True)
t_off, _ = gen(False)
print(f"cache on {t_on:.2f}s   off {t_off:.2f}s   speedup {t_off/t_on:.1f}x")

The complexity changes from \(O(n^2)\) total work re-done every step to \(O(n)\) per step — typically a 5–20× wall-clock speedup at a few hundred tokens, growing with length.

T5, BART & Encoder-Decoder Transformers

24 min

Every task is text-to-text. A framing decision with surprisingly large consequences.

T5's text-to-text framing

translate English to German: That is good.   →  Das ist gut.
cola sentence: The course is jumping well.   →  not acceptable
stsb sentence1: ... sentence2: ...           →  3.8
summarize: state authorities dispatched ...  →  six people hospitalized after ...

Classification becomes generating a label string; regression becomes generating a number rounded to 0.2. One model, one loss, one decoding procedure for everything — which is what makes multi-task training trivial.

Span corruption

Instead of masking single tokens, mask contiguous spans (mean length 3, 15% of tokens) and replace each with a unique sentinel. The target is the sentinels followed by their contents:

input:  Thank you <X> me to your party <Y> week .
target: <X> for inviting <Y> last <Z>

The target is much shorter than the input, so training is cheaper than reconstructing the full sequence, and predicting multi-token spans is a harder, more useful task than single-token MLM. Trained on C4 — Common Crawl filtered by heuristics (English only, ends with terminal punctuation, at least 5 sentences, no "lorem ipsum", no bad-words list, deduplicated three-sentence spans), ~750 GB.

BART's denoising menu

CorruptionEffect
Token maskingBERT-style, single tokens
Token deletionModel must infer where something was missing, not just what
Text infillingSpans (Poisson λ=3) → one mask each, including zero-length. Best single objective.
Sentence permutationShuffle sentences; the decoder restores order
Document rotationStart the document at a random token; find the true start

BART is a standard encoder–decoder, so it is directly usable for generation while its encoder is BERT-like for understanding. It is still one of the strongest summarization backbones.

When encoder–decoder beats decoder-only

The asymmetry argument When the source is fully available and the target is generated, an encoder–decoder gives the source bidirectional attention while keeping the target causal. A decoder-only model sees the source causally too, which wastes the fact that the whole input is present. Empirically this matters most for translation, summarization and grammatical correction — tasks with a long, information-dense source. Decoder-only wins on open-ended generation, in-context learning, and anything where you want one model for everything. The industry moved to decoder-only mostly for the second reason, not the first.

Variants

mT5 — 101 languages, 250k SentencePiece vocabulary, trained on mC4; needs its own fine-tuning care because it was pretrained without any supervised task. FLAN-T5 — T5 instruction-tuned on 1,800+ tasks; substantially better zero-shot and usually the better starting checkpoint. ByT5 — token-free, operates on raw bytes; slower but immune to tokenization pathologies and much better on noisy text.

Day 87

Sentence Embeddings & Sentence-BERT

24 min

Raw BERT vectors are bad at similarity. The fix is a training objective, not a pooling trick.

Why [CLS] fails

[CLS] was trained for next-sentence prediction, not similarity — nothing in pretraining ever asked for "similar sentences get similar vectors". Measured: raw BERT [CLS] cosine on STS-B scores below averaged GloVe vectors. Mean-pooling BERT is better but still weak. The representation space is also anisotropic: embeddings occupy a narrow cone, so every pair of random sentences has cosine ~0.6–0.9 and the metric has almost no dynamic range.

The cost argument for bi-encoders

Finding the most similar pair among 10,000 sentences with a cross-encoder means \(\binom{10000}{2}\approx5\times10^7\) forward passes — about 65 hours on a V100. With a bi-encoder: 10,000 forward passes (~5 seconds) plus a cosine matrix. That is the entire motivation.

Training objectives

$$\text{MultipleNegativesRanking: }\ \mathcal{L}=-\frac{1}{B}\sum_{i=1}^{B}\log\frac{e^{\cos(\mathbf{u}_i,\mathbf{v}_i)/\tau}}{\sum_{j=1}^{B}e^{\cos(\mathbf{u}_i,\mathbf{v}_j)/\tau}}$$

You only need positive pairs; the other items in the batch serve as negatives. So batch size is the number of negatives — bigger batches train better encoders, which is why this objective is run at batch 512+ with gradient checkpointing.

$$\text{SimCSE (unsupervised): }\ \mathbf{u}_i, \mathbf{u}_i^{+} = \text{same sentence, two different dropout masks}$$

That is the entire method: dropout is the augmentation. It beats every hand-designed text augmentation for this purpose and needs no labelled data at all. Supervised SimCSE uses NLI entailment pairs as positives and contradiction pairs as hard negatives, which is the strongest cheap recipe.

Hard negative mining

Random negatives are too easy — the model learns to separate "about cats" from "about quantum physics" and stops. Mine negatives that are lexically similar but semantically wrong using BM25 or the current model itself, then filter out false negatives with a cross-encoder (a mined "negative" that is actually a paraphrase will actively harm training).

def rerank(query, candidates, k=10):
    scores = ce.predict([(query, c) for c in candidates])
    return [c for _, c in sorted(zip(scores, candidates), reverse=True)[:k]]
Reading MTEB critically Leaderboard rank is not your rank. Check: is your domain represented in the 50+ tasks, or is the average dominated by tasks you do not care about? Was the model trained on the eval data (contamination is widespread)? What is the embedding dimension and the max sequence length — a 4096-dim model costs 5× the index memory of a 768-dim one for maybe a point of average score. Always evaluate on your own golden set.

transformers

Auto classes read config.json and instantiate the right architecture, so your code is checkpoint-agnostic. The heads matter: AutoModel (bare encoder, no head — use for feature extraction), AutoModelForSequenceClassification, ...ForTokenClassification, ...ForQuestionAnswering, ...ForCausalLM, ...ForSeq2SeqLM. Loading a checkpoint into a different head randomly initializes the head and warns you — read that warning; it is the difference between fine-tuning and evaluating noise.

Memory-mapping means a 100 GB dataset uses almost no RAM. map results are cached by a hash of the function and arguments, so re-running a notebook is instant — and if you change the function's closure without changing its code, the cache can go stale. Pass load_from_cache_file=False when in doubt.
