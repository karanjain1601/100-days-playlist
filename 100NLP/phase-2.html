Days 17–36

Day 17

One-Hot, Bag of Words & the Vector Space Model

20 min

Turning documents into arithmetic. Everything after this is a refinement of one idea.

The document-term matrix

Fix a vocabulary \(V=\{w_1,\dots,w_{|V|}\}\) with an index map. Document \(d\) becomes \(\mathbf{x}_d \in \mathbb{R}^{|V|}\) where \(x_{d,j}\) counts \(w_j\) in \(d\). Stack all documents and you have the DTM \(X \in \mathbb{R}^{|D|\times|V|}\).

Why cosine, not Euclidean

A 5,000-word article and a 200-word abstract on the same topic have wildly different vector magnitudes but nearly the same direction. Euclidean distance is dominated by length; cosine removes it:

$$\cos(\mathbf{a},\mathbf{b})=\frac{\mathbf{a}\cdot\mathbf{b}}{\|\mathbf{a}\|_2\|\mathbf{b}\|_2}\;,\qquad \text{and if } \|\mathbf{a}\|_2=\|\mathbf{b}\|_2=1 \text{ then } \|\mathbf{a}-\mathbf{b}\|_2^2 = 2-2\cos(\mathbf{a},\mathbf{b})$$

So on L2-normalized vectors, ranking by cosine and ranking by Euclidean distance are identical. This is why TfidfVectorizer normalizes by default and why FAISS's inner-product index works for cosine search (Day 101).

What bag-of-words throws away

Order (dog bites man = man bites dog), syntax, negation scope, coreference, and any long-range dependency. It keeps topical content, which is enough for a surprising number of tasks — and that surprise is the reason it survived for thirty years.

Curse of dimensionality In \(|V|=50{,}000\) dimensions, random vectors are near-orthogonal and distances concentrate. Sparsity saves you: two documents only "interact" through shared words, so effective dimensionality is the size of the intersection, not \(|V|\).

Day 18

N-grams and Collocations

18 min

The cheapest way to put a little word order back into a bag of words.

The vocabulary explosion

If unigrams give \(|V|\) features, bigrams give up to \(|V|^2\) — but observed bigrams grow roughly linearly in corpus size, so in practice bigrams multiply your feature count by 5–20×, not 50,000×. Set ngram_range=(1,2) with min_df=2 and you usually gain 1–3 F1 points on sentiment.

Character n-grams

They beat word n-grams when: text is misspelled (recieve shares 4-grams with receive), the language is morphologically rich, you are doing language ID or authorship attribution, or the text is code-switched. analyzer='char_wb' restricts n-grams to inside word boundaries and is almost always better than raw 'char'.

Collocations: which bigrams are real?

of the is frequent but meaningless. New York is a unit. Frequency alone cannot tell them apart. Pointwise mutual information can:

$$\mathrm{PMI}(x,y)=\log_2\frac{P(x,y)}{P(x)P(y)} \qquad \mathrm{PPMI}(x,y)=\max\bigl(0,\ \mathrm{PMI}(x,y)\bigr)$$

PMI is zero when the words are independent, positive when they attract. Its flaw: it is biased towards rare pairs — a bigram seen once whose parts are each seen once gets a huge PMI. Fixes: a frequency floor (\(\ge 5\)), or use the log-likelihood ratio test, which is better behaved on sparse counts:

$$-2\log\lambda = 2\sum_{i,j} O_{ij}\log\frac{O_{ij}}{E_{ij}} \;\sim\; \chi^2_1$$

where \(O\) is the 2×2 contingency table of (word1 present/absent) × (word2 present/absent) and \(E\) the independence expectation. Dunning's log-likelihood ratio is the one to reach for on real corpora.

Day 19

TF-IDF from Scratch

22 min

Thirty years old, four lines of code, still the baseline that embarrasses half of all neural papers.

The two halves

Term frequency — how much this document is about the term. Variants:

$$\tf_{t,d}\in\Bigl\{\;f_{t,d},\quad \mathbb{1}[f_{t,d}>0],\quad 1+\log f_{t,d},\quad 0.5+0.5\frac{f_{t,d}}{\max_{t'}f_{t',d}}\;\Bigr\}$$

Sublinear (log) tf is the usual best choice: seeing a word ten times does not make a document ten times more about it. sublinear_tf=True.

Inverse document frequency — how surprising the term is corpus-wide. Derived: if a term appears in \(\mathrm{df}_t\) of \(N\) documents, the probability a random document contains it is \(\mathrm{df}_t/N\), so its self-information is \(-\log(\mathrm{df}_t/N)=\log(N/\mathrm{df}_t)\). IDF is the information content of "this document contains \(t\)".

$$\idf_t=\log\frac{N}{\mathrm{df}_t}\quad\text{(textbook)}\qquad\qquad \idf_t^{\,\text{sklearn}}=\log\frac{1+N}{1+\mathrm{df}_t}+1$$

sklearn's version adds 1 inside (a fictitious document containing every term, so \(\mathrm{df}_t=0\) never divides by zero) and adds 1 outside, so a term appearing in every document gets \(\idf=1\) rather than 0 and is therefore not annihilated. That "+1 outside" is the difference that surprises people.

$$\text{tf-idf}_{t,d}=\tf_{t,d}\cdot\idf_t,\qquad \mathbf{x}_d \leftarrow \frac{\mathbf{x}_d}{\|\mathbf{x}_d\|_2}$$

Day 20

Vectorizer Engineering & Feature Design

18 min

The gap between a textbook TF-IDF baseline and a strong one is entirely in this lesson.

The hashing trick

Instead of learning a vocabulary map, hash each feature string to a fixed range: \(j = h(t) \bmod m\). No vocabulary to store, no fit step, constant memory, and it works on streams — you can vectorize a corpus larger than RAM in one pass.

$$\phi(t) = \bigl(h(t)\bmod m,\ \ \sigma(t)\bigr),\qquad \sigma(t)\in\{-1,+1\}$$

The signed variant makes collisions cancel in expectation rather than accumulate, so the inner product is an unbiased estimator of the true one. Cost: features are no longer inspectable (you cannot recover which word index 4,182 was) and you lose IDF unless you compute it separately. Use HashingVectorizer for out-of-core; use TfidfVectorizer when you need interpretability.

Combining feature families

from sklearn.pipeline import Pipeline, FeatureUnion
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.preprocessing import FunctionTransformer, StandardScaler
import numpy as np, scipy.sparse as sp

def handcrafted(texts):
    out = []
    for t in texts:
        n = max(len(t), 1)
        out.append([
            len(t),                                   # length
            sum(c.isupper() for c in t) / n,          # shouting
            sum(c in "!?" for c in t) / n,            # emphasis
            sum(c.isdigit() for c in t) / n,          # numeric density
            t.count("http"),                          # links
            len(t.split()) / max(t.count(".") + 1, 1) # words per sentence
        ])
    return np.asarray(out, dtype=float)

feats = FeatureUnion([
    ("word", TfidfVectorizer(ngram_range=(1,2), min_df=2, sublinear_tf=True)),
    ("char", TfidfVectorizer(analyzer="char_wb", ngram_range=(3,5), min_df=3)),
    ("hand", Pipeline([("f", FunctionTransformer(handcrafted)),
                       ("s", StandardScaler())])),
])

Word + char n-grams together is the single most reliable free win on noisy text: the char features cover misspellings and morphology the word features miss.

Day 21

Probability & Information Theory for NLP

24 min

The 24 minutes that make Days 22–108 make sense. Do not skip it.

The chain rule — the whole of language modelling

$$P(w_1,\dots,w_n)=\prod_{i=1}^{n}P(w_i \mid w_1,\dots,w_{i-1})$$

This is exact, not an approximation. Every autoregressive model in this series — n-gram, RNN, GPT — is a different way of parameterizing that conditional. The Markov assumption (Day 22) truncates the history; a transformer keeps all of it.

Bayes, on spam

$$P(\text{spam}\mid w)=\frac{P(w\mid \text{spam})\,P(\text{spam})}{P(w\mid\text{spam})P(\text{spam})+P(w\mid\text{ham})P(\text{ham})}$$

Concretely: 20% of mail is spam; "viagra" appears in 5% of spam and 0.01% of ham. Then \(P(\text{spam}\mid\text{viagra}) = \frac{0.05\cdot0.2}{0.05\cdot0.2+0.0001\cdot0.8}=\frac{0.010}{0.010080}\approx 0.992\). Note how much work the prior does — halve the spam rate and the posterior barely moves, because the likelihood ratio is 500:1.

Entropy and friends

$$H(P)=-\sum_x P(x)\log_2 P(x) \qquad\text{(expected surprisal, in bits)}$$
$$H(P,Q)=-\sum_x P(x)\log_2 Q(x) \qquad \KL(P\,\|\,Q)=\sum_x P(x)\log_2\frac{P(x)}{Q(x)}$$
$$H(P,Q)=H(P)+\KL(P\,\|\,Q)\;\ge\;H(P)$$

Read that last line carefully: cross-entropy is what you minimize, and it can never go below the true entropy \(H(P)\). The gap you are actually closing is the KL divergence. \(\KL\) is not symmetric and is not a metric. Mutual information \(I(X;Y)=H(X)-H(X\mid Y)=\KL\bigl(P(x,y)\,\|\,P(x)P(y)\bigr)\) is the expected PMI from Day 18.

Perplexity

$$\mathrm{PPL}(W)=2^{\,H(P,Q)}=P(w_1\dots w_N)^{-1/N}=\exp\!\left(-\frac{1}{N}\sum_{i=1}^{N}\log P(w_i\mid w_{<i})\right)$$

Interpret it as the effective branching factor: a perplexity of 100 means the model is as uncertain as if it were choosing uniformly among 100 words at each step. Rough anchors: uniform over a 50k vocabulary → 50,000; a good trigram model on news → 100–200; GPT-2 on WikiText-103 → ~30; a modern LLM → single digits on its own distribution.

Perplexity is not comparable across tokenizers A model with a 32k BPE vocabulary and one with a 256-token byte vocabulary produce different \(N\), so their per-token perplexities are on different scales. Compare bits-per-byte or bits-per-character instead: \(\mathrm{BPB} = \frac{N_{\text{tok}}}{N_{\text{bytes}}}\cdot\log_2 \mathrm{PPL}\).
Entropy, cross-entropy, KL — move the sliders

Day 22

N-gram Language Models

24 min

Your first generative model. It will produce nonsense, and the specific way it fails is instructive.

The Markov assumption

$$P(w_i\mid w_1^{i-1})\;\approx\;P(w_i\mid w_{i-n+1}^{\,i-1})$$

Estimate by counting (this is the MLE for a multinomial):

$$\hat{P}(w_i\mid w_{i-2},w_{i-1})=\frac{C(w_{i-2},w_{i-1},w_i)}{C(w_{i-2},w_{i-1})}$$

Pad with \(n-1\) start tokens <s> so the first real word has a context, and append </s> so the model can decide to stop — without an end token, probabilities do not sum to 1 over the set of all strings and generation never terminates.

Train a character/word n-gram on your own text and sample from it

Raise \(n\) in the demo and the output gets more fluent and more plagiarised — at \(n=4\) on a small corpus it simply reproduces the training text, because almost every 3-word context was seen exactly once. That is the bias–variance tradeoff of n-gram order, visible in ten seconds.

The zero-probability catastrophe If any test n-gram has count 0, its probability is 0, the sentence probability is 0, and perplexity is \(\infty\). On a 40M-word corpus with a trigram model, roughly 30% of trigrams in held-out text are unseen. Unsmoothed n-gram models are not merely inaccurate on new data — they are undefined. That is Day 23.
Exercise Build a trigram model, generate 20 samples, and hand-classify each as: copied verbatim / locally fluent but globally incoherent / nonsense. The proportions tell you your corpus size relative to your \(n\).
Day 23

Smoothing & Backoff

22 min

Moving probability mass from what you saw to what you didn't. The whole subject in one sentence.

Add-one (Laplace), and why it is too blunt

$$P_{\text{add-1}}(w_i\mid w_{i-1})=\frac{C(w_{i-1},w_i)+1}{C(w_{i-1})+|V|}$$

With \(|V|=50{,}000\) and a context seen 10 times, the denominator becomes 50,010 — you have given 99.98% of the mass to unseen events. Add-\(k\) with \(k\in(0,1]\) softens it but the shape of the fix is wrong: it moves the same mass to every unseen word regardless of how plausible that word is.

Good–Turing: estimate the unseen mass from the once-seen

Let \(N_r\) be the number of n-grams occurring exactly \(r\) times. Then

$$r^{*}=(r+1)\frac{N_{r+1}}{N_r},\qquad P_0 \;=\; \frac{N_1}{N}$$

The intuition is beautiful: the probability that the next token is something you have never seen is estimated by the fraction of your corpus made of things you saw exactly once. \(N_r\) is noisy for large \(r\), so in practice you smooth \(N_r\) (Simple Good–Turing fits a log-log line) and apply the discount only for small \(r\).

Backoff vs interpolation

$$\underbrace{P_{\text{Katz}}(w_i\mid w_{i-1})=\begin{cases}P^{*}(w_i\mid w_{i-1}) & C(w_{i-1},w_i)>0\\[2pt] \alpha(w_{i-1})P_{\text{Katz}}(w_i) & \text{otherwise}\end{cases}}_{\textbf{backoff: use the lower order only when you must}}$$
$$\underbrace{P_{\text{JM}}(w_i\mid w_{i-1})=\lambda P_{\mathrm{ML}}(w_i\mid w_{i-1})+(1-\lambda)P_{\mathrm{ML}}(w_i)}_{\textbf{interpolation: always mix every order}}$$

\(\lambda\) is tuned on held-out data (EM, or just a grid search). Better: make \(\lambda\) depend on the context count — trust a context seen 5,000 times more than one seen twice.

Kneser–Ney, and the idea worth remembering

Absolute discounting subtracts a fixed \(d\approx0.75\) from every nonzero count and redistributes it:

$$P_{\text{abs}}(w_i\mid w_{i-1})=\frac{\max\bigl(C(w_{i-1},w_i)-d,\,0\bigr)}{C(w_{i-1})}+\lambda(w_{i-1})P(w_i)$$

Kneser–Ney's contribution is replacing that lower-order \(P(w_i)\) with a continuation probability:

$$P_{\text{cont}}(w_i)=\frac{\bigl|\{\,w' : C(w',w_i)>0\,\}\bigr|}{\bigl|\{\,(w',w'') : C(w',w'')>0\,\}\bigr|}$$
The Francisco example Francisco is a frequent word, but it appears almost exclusively after San. A unigram backoff would happily predict Francisco after the glasses of. Continuation probability asks instead: in how many distinct contexts does this word appear? Francisco scores near zero; glasses scores high. That single change made KN the best n-gram smoothing method for two decades.

Unknown words

Fix a vocabulary from the training set (by frequency threshold or top-\(k\)), map everything else to <UNK> in training too, so <UNK> has real counts. If you only map at test time, the model has never seen the token and assigns it zero.

Day 24

Naive Bayes for Text Classification

22 min

Wrong assumptions, right answers, and it trains in one pass over the data.

The generative story

To make a document: pick a class \(c\) from the prior, then draw each word independently from that class's word distribution. That story is obviously false — words are not independent — but we only need the argmax to be right, not the probabilities.

$$\hat{c}=\argmax_{c}\;P(c)\prod_{i=1}^{n}P(w_i\mid c) \;=\;\argmax_{c}\;\Bigl[\log P(c)+\sum_{i=1}^{n}\log P(w_i\mid c)\Bigr]$$

Always compute in log space: 300 probabilities each ≈0.001 multiply to \(10^{-900}\), which underflows float64 to exactly zero.

$$\hat{P}(w\mid c)=\frac{C(w,c)+\alpha}{\sum_{w'\in V}C(w',c)+\alpha|V|}$$

Three variants

VariantModelsUse for
Multinomialword counts; repeated words count repeatedlyTopic / long-document classification. The default.
Bernoullibinary presence, and explicitly models absenceShort texts, small vocabularies. Absence is informative.
Complementestimates each class from all other classes' dataImbalanced data. Usually beats multinomial there.

Why the wrong assumption still works

Dependence between words inflates the magnitude of the log-posterior (the same evidence gets counted several times through correlated words) but rarely flips its sign. So classification accuracy holds up while the probabilities themselves become wildly overconfident — a typical NB posterior is 0.9999 when the true confidence is 0.7. Never use raw NB probabilities for thresholding or calibration (see Day 36).

multinomial NB from scratch, log-space, 25 lines 
import numpy as np
from scipy.sparse import csr_matrix

class MultinomialNB:
    def __init__(self, alpha=1.0): self.alpha = alpha

    def fit(self, X: csr_matrix, y):
        self.classes_ = np.unique(y)
        n_c, n_f = len(self.classes_), X.shape[1]
        self.log_prior_ = np.zeros(n_c)
        self.log_lik_   = np.zeros((n_c, n_f))
        for i, c in enumerate(self.classes_):
            Xc = X[y == c]
            self.log_prior_[i] = np.log(Xc.shape[0] / X.shape[0])
            counts = np.asarray(Xc.sum(axis=0)).ravel() + self.alpha
            self.log_lik_[i] = np.log(counts) - np.log(counts.sum())
        return self

    def predict_log_proba(self, X):
        return X @ self.log_lik_.T + self.log_prior_   # sparse matmul

    def predict(self, X):
        return self.classes_[np.argmax(self.predict_log_proba(X), axis=1)]

    def top_features(self, vocab, c=1, k=15):
        """Log-odds of class c vs the rest — the honest 'most informative' view."""
        others = np.delete(np.arange(len(self.classes_)), c)
        odds = self.log_lik_[c] - self.log_lik_[others].mean(axis=0)
        idx = np.argsort(odds)[-k:][::-1]
        return [(vocab[i], round(float(odds[i]), 3)) for i in idx]
Inspect the log-odds, not the likelihood The most frequent words in a class are always the, and, of. The most informative are the ones with the largest likelihood ratio against the other classes. That one-line change turns a useless feature list into a debugging tool.

Day 25

Logistic Regression & Maximum Entropy Models

24 min

The workhorse. Learn its gradient by hand today and Day 54's backprop is a formality.

Discriminative vs generative

Naive Bayes models \(P(x,y)\) and derives \(P(y\mid x)\). Logistic regression models \(P(y\mid x)\) directly and never explains where \(x\) came from. That means it can use overlapping, correlated features without penalty — which is exactly what text features are.

$$P(y=1\mid \mathbf{x})=\sigma(\mathbf{w}^\top\mathbf{x}+b)=\frac{1}{1+e^{-(\mathbf{w}^\top\mathbf{x}+b)}},\qquad P(y=k\mid\mathbf{x})=\frac{e^{\mathbf{w}_k^\top\mathbf{x}}}{\sum_{j}e^{\mathbf{w}_j^\top\mathbf{x}}}$$

The loss and its gradient — derive this once

$$\mathcal{L}=-\frac{1}{N}\sum_{i=1}^{N}\Bigl[y_i\log \hat{y}_i+(1-y_i)\log(1-\hat{y}_i)\Bigr],\qquad \hat{y}_i=\sigma(z_i),\ z_i=\mathbf{w}^\top\mathbf{x}_i+b$$

Using \(\dfrac{\partial\sigma}{\partial z}=\sigma(1-\sigma)\), the \(\sigma(1-\sigma)\) terms cancel against the log derivatives and everything collapses to:

$$\frac{\partial\mathcal{L}}{\partial \mathbf{w}}=\frac{1}{N}\sum_{i=1}^{N}(\hat{y}_i-y_i)\,\mathbf{x}_i \;=\; \frac{1}{N}X^\top(\hat{\mathbf{y}}-\mathbf{y})$$

Gradient = feature × error. The same form appears for softmax regression, for the output layer of every neural classifier, and for the LM head of a transformer. Memorize the shape, not the algebra.

Gradient descent, live — watch the loss curve

Regularization on text features

$$\mathcal{L}_{\text{L2}}=\mathcal{L}+\frac{\lambda}{2}\|\mathbf{w}\|_2^2 \qquad\qquad \mathcal{L}_{\text{L1}}=\mathcal{L}+\lambda\|\mathbf{w}\|_1$$

L2 shrinks all weights smoothly and keeps correlated features (it splits the weight between them). L1 drives weights to exactly zero and picks one from each correlated group — useful when you want a small readable model, but unstable: rerun with a different seed and it picks a different member of the group. In sklearn, C = 1/λ, so smaller C means more regularization. This trips up everyone once.

Why "MaxEnt" is the same model Choose the distribution with maximum entropy subject to matching the empirical feature expectations, \(\E_P[f_j]=\E_{\tilde{P}}[f_j]\). Solve with Lagrange multipliers and the solution is exactly the softmax with the multipliers as weights. "Be as uninformative as possible while fitting the data" and "maximize the conditional log-likelihood of a log-linear model" are dual problems. Different literature, same equations.

Day 26

SVMs & Other Linear Classifiers for Text

20 min

The strongest pre-neural text classifier, and it is still linear.

Maximum margin

Many hyperplanes separate the data. SVM picks the one furthest from the nearest point of either class — the margin is \(2/\|\mathbf{w}\|\), so maximizing it means minimizing \(\|\mathbf{w}\|^2\).

$$\min_{\mathbf{w},b}\;\frac{1}{2}\|\mathbf{w}\|^2+C\sum_{i=1}^{N}\max\bigl(0,\;1-y_i(\mathbf{w}^\top\mathbf{x}_i+b)\bigr),\qquad y_i\in\{-1,+1\}$$

That second term is hinge loss. Compare it to logistic loss: hinge is exactly zero once a point is correctly classified with margin ≥1, so well-classified points contribute nothing to the gradient. Logistic loss never reaches zero, so every point keeps nudging the boundary. This is why SVMs are decided by the support vectors alone.

Why linear kernels win on text

With \(|V|=50{,}000\) features and 20,000 documents, the data is almost certainly already linearly separable in the original space — you have more dimensions than points. An RBF kernel adds capacity you do not need, costs \(O(N^2)\) training, and typically loses a point of accuracy. Use LinearSVC (liblinear, dual coordinate descent) or SGDClassifier(loss='hinge') for streaming.

Calibration

decision_function returns a signed distance, not a probability. To get probabilities, wrap in CalibratedClassifierCV: Platt scaling fits \(P(y=1\mid s)=\sigma(as+b)\) on held-out scores, or isotonic regression fits a free monotone function (more flexible, needs ≥1000 calibration points or it overfits).

Tree ensembles on text

Random forests and gradient boosting underperform on raw sparse text. A tree splits on one feature at a time; with 50k mostly-zero features, each split isolates a handful of documents and the ensemble needs enormous depth to express what a linear model expresses in one dot product. They become competitive only after dimensionality reduction (SVD to ~300 dims) or when combined with dense metadata features.

Day 27

Evaluation Metrics I

22 min

If you learn one thing this phase, learn this. Most published NLP mistakes are metric mistakes.

Accuracy lies

A dataset with 1% positives: predicting "negative" always gives 99% accuracy and is worthless. Report accuracy only when classes are balanced and errors are symmetric.

Confusion matrix → every metric, computed live

Averaging, and why the choice is a claim about values

$$\text{micro-F1}=\frac{2\sum_c TP_c}{2\sum_c TP_c+\sum_c FP_c+\sum_c FN_c} \qquad \text{macro-F1}=\frac{1}{|C|}\sum_c F1_c$$
Micro
Pools all decisions. Dominated by frequent classes. In single-label multi-class it equals accuracy.
Macro
Averages per-class F1 with equal weight. A class with 6 examples counts as much as one with 60,000. Use this when rare classes matter.
Weighted
Per-class F1 weighted by support. Looks like a compromise, is mostly micro in disguise, and can exceed both precision and recall — avoid it.

ROC-AUC vs PR-AUC

ROC plots TPR against FPR. Because FPR has \(TN\) in its denominator and \(TN\) is huge under imbalance, the FPR barely moves and ROC-AUC stays flatteringly high. PR curves use precision, which has no \(TN\) term, so they expose the problem. Under class imbalance, report PR-AUC (average precision). Note the PR baseline is the positive rate, not 0.5.

Threshold ≠ 0.5 The default 0.5 is an arbitrary inheritance. Pick the threshold on a validation set against your actual cost function — maximize F\(_\beta\), or fix precision at the level operations can tolerate and maximize recall subject to it. Then report the threshold.

Confidence intervals by bootstrap

No closed form needed. Resample the test set with replacement \(B=1000\) times, recompute the metric each time, take the 2.5th and 97.5th percentiles.

import numpy as np
def boot_ci(y_true, y_pred, metric, B=1000, seed=0):
    rng = np.random.default_rng(seed); n = len(y_true)
    stats = np.array([metric(y_true[i], y_pred[i])
                      for i in (rng.integers(0, n, n) for _ in range(B))])
    return stats.mean(), np.percentile(stats, [2.5, 97.5])

On a 1,000-item test set an F1 of 0.85 typically has a ±0.02 interval. So a "0.5 point improvement" on such a set is noise. Say so.

Comparing two systems

McNemar's test — the correct test for two classifiers on the same test set. Build the 2×2 table of disagreements: \(b\) = A right / B wrong, \(c\) = A wrong / B right. Items both get right or both get wrong carry no information about which is better.

$$\chi^2=\frac{(|b-c|-1)^2}{b+c}\;\sim\;\chi^2_1$$

Paired bootstrap — more general, works for any metric including F1 and BLEU: resample the test set, compute \(\Delta = m_A - m_B\) on each resample, and the p-value is the fraction of resamples where \(\Delta \le 0\).

Tuning on test Every time you look at the test score and change something, you spend a little of its validity. Fifty such peeks and your test set is a validation set with extra steps. Touch it once, at the end, and report how many times you touched it.

Error analysis that changes what you build next

Take 100–200 errors and bucket them. Then bucket the metric by slice, not just the errors:

import pandas as pd
df = pd.DataFrame({"y": y_true, "p": y_pred, "text": texts})

for col in ["len_bucket", "has_negation", "source", "y"]:
    print(df.groupby(col).apply(lambda g: (g.y == g.p).mean()).round(3))

Then write a failure taxonomy: name each category, give its share of total errors, give one example, and state whether it is fixable by data, features, model, or not at all. That document is worth more than the accuracy number.

Day 29

Hidden Markov Models

26 min

Hidden states you want, observations you get. Viterbi is the algorithm you will reimplement three more times.

The pieces

States \(S=\{s_1..s_K\}\) (tags), observations \(O\) (words). Three parameter sets: initial \(\pi_k=P(q_1=s_k)\), transition \(A_{jk}=P(q_t=s_k\mid q_{t-1}=s_j)\), emission \(B_k(o)=P(o_t=o\mid q_t=s_k)\).

$$P(O,Q)=\pi_{q_1}B_{q_1}(o_1)\prod_{t=2}^{T}A_{q_{t-1}q_t}B_{q_t}(o_t)$$

Two independence assumptions, both false and both useful: the state depends only on the previous state (first-order Markov), and the observation depends only on its own state (output independence — so a word's identity tells you nothing beyond its tag, which is why HMM taggers cannot use suffix features).

The three problems

ProblemQuestionAlgorithmCost
Likelihood\(P(O\mid\lambda)\)?Forward\(O(K^2T)\)
Decodingbest \(Q\)?Viterbi\(O(K^2T)\)
Learningbest \(\lambda\)?Baum–Welch (EM)\(O(K^2T)\) per iteration

Forward sums over paths, Viterbi maximizes over them — the only difference in the code is sum vs max plus a backpointer.

$$\alpha_t(k)=B_k(o_t)\sum_{j}\alpha_{t-1}(j)A_{jk} \qquad\qquad \delta_t(k)=B_k(o_t)\max_{j}\ \delta_{t-1}(j)A_{jk}$$
$$\psi_t(k)=\argmax_{j}\ \delta_{t-1}(j)A_{jk}\qquad \hat{q}_T=\argmax_k \delta_T(k),\qquad \hat{q}_t=\psi_{t+1}(\hat{q}_{t+1})$$
Viterbi on a lattice — every cell, every backpointer

Classic toy HMM: hidden weather (Sunny/Rainy) emits an observed activity. π = [S .6, R .4] · A = [[S→S .7, S→R .3],[R→S .4, R→R .6]] · B(S) = [walk .6, shop .3, clean .1], B(R) = [walk .1, shop .4, clean .5]

Underflow Multiplying \(T\) probabilities underflows for \(T>300\). Work in log space (products become sums, max is unchanged) or rescale \(\alpha\) at each step and track the log of the scaling factors.

Baum–Welch, intuitively

You need counts to estimate \(A\) and \(B\), but the states are hidden so you cannot count. EM: (E) use current parameters to compute the expected number of times you were in state \(k\) at time \(t\) — that is \(\gamma_t(k)\propto\alpha_t(k)\beta_t(k)\), where \(\beta\) is the backward variable; (M) re-estimate \(A,B\) from those soft counts as if they were real. Repeat. Guaranteed to increase likelihood, guaranteed only to find a local optimum, and very sensitive to initialization. In practice, if you have labels, use them (supervised MLE) — Baum–Welch is for when you genuinely have none.

Day 30

Part-of-Speech Tagging

22 min

A solved problem in English, an excellent teacher, and still a feature source for parsing and IE.

Two tagsets

Penn Treebank: 45 tags, fine-grained — NN NNS NNP NNPS for nouns, VB VBD VBG VBN VBP VBZ for verbs. Universal POS: 17 coarse tags — NOUN PROPN VERB AUX ADJ ADV PRON DET ADP NUM CONJ SCONJ PART INTJ PUNCT SYM X. UD is cross-linguistically comparable; PTB carries English morphology explicitly. spaCy gives you both (token.pos_ and token.tag_).

How hard is it, really?

About 85–86% of English word types are unambiguous, but ambiguous types are the frequent ones, so only ~55–60% of tokens are unambiguous. The baseline "assign each word its most frequent tag, and NN to unknowns" already reaches ~90–92%. State of the art is ~97.5%. So the entire research history of POS tagging is the last 6 points — and human inter-annotator agreement is itself only about 97%.

Report unknown-word accuracy separately Overall 97% typically decomposes into 98%+ on known words and 85–90% on unknown ones. Unknowns are where all the real difficulty is, and they are what changes when you move domain.

Three taggers

HMM tagger
\(\hat{Q}=\argmax_Q \prod P(t_i\mid t_{i-1})P(w_i\mid t_i)\), decoded with Viterbi. Unknown words handled by a suffix-based emission model. ~96%.
Averaged perceptron
Greedy left-to-right. Predict with the current weights; on error, add the gold features and subtract the predicted ones. Average the weight vectors over all updates to reduce variance. Fast to train, ~97%, and this is what NLTK's default tagger is.
Neural (BiLSTM / transformer)
Day 63 and Day 83. ~97.5–98%, and the gain is almost entirely on unknown words because subword/character features generalize.

Feature templates that do the work

def features(words, i, prev_tag, prev2_tag):
    w = words[i]
    return {
        "bias": 1,
        "w": w.lower(),
        "suf3": w[-3:].lower(), "suf2": w[-2:].lower(),   # -ing -ed -ly -tion
        "pre3": w[:3].lower(),
        "shape": "".join("X" if c.isupper() else "x" if c.islower()
                         else "d" if c.isdigit() else c for c in w),
        "is_title": w.istitle(), "is_upper": w.isupper(),
        "has_digit": any(c.isdigit() for c in w),
        "has_hyphen": "-" in w,
        "prev": words[i-1].lower() if i else "<s>",
        "next": words[i+1].lower() if i+1 < len(words) else "</s>",
        "t-1": prev_tag, "t-2": prev2_tag, "t-1|t-2": prev2_tag + "|" + prev_tag,
    }

The suffix features are why perceptron and CRF taggers crush HMMs on unknown words: -ing is overwhelming evidence for VBG regardless of whether you have ever seen the word. An HMM's output independence assumption forbids exactly this.

Day 31

Conditional Random Fields

24 min

Discriminative sequence labelling. The right answer for a decade, and still the right output layer today.

Why HMMs hurt

An HMM must model \(P(w\mid t)\) — a distribution over the whole vocabulary — which forces the output-independence assumption and forbids overlapping features. A CRF models \(P(\text{tags}\mid \text{words})\) directly, so it can condition on anything about the input: the word, its suffix, its shape, the word two positions away, whether it is in a gazetteer, the output of another model.

$$P(\mathbf{y}\mid\mathbf{x})=\frac{1}{Z(\mathbf{x})}\exp\left(\sum_{t=1}^{T}\sum_{k}\lambda_k f_k(y_{t-1},y_t,\mathbf{x},t)\right)$$
$$Z(\mathbf{x})=\sum_{\mathbf{y}'\in\mathcal{Y}^T}\exp\left(\sum_t\sum_k \lambda_k f_k(y'_{t-1},y'_t,\mathbf{x},t)\right)$$

\(Z(\mathbf{x})\) sums over \(K^T\) sequences — computed in \(O(K^2T)\) by the forward algorithm, the same recursion as Day 29 in log space.

The label bias problem

What global normalization buys you In an MEMM (per-token softmax), each step's probabilities must sum to 1 given that state. A state with only one outgoing transition passes all its mass through regardless of the observation — the observation is effectively ignored. Low-entropy states therefore "win" paths they should lose. A CRF normalizes over whole sequences, so an unlikely observation can veto a path even at a deterministic state. This is the single reason CRFs beat MEMMs.

Training

The negative log-likelihood is convex, so there is one global optimum. Its gradient is the familiar observed minus expected form:

$$\frac{\partial \mathcal{L}}{\partial\lambda_k}=\underbrace{\sum_t f_k(y_{t-1},y_t,\mathbf{x},t)}_{\text{empirical count}}-\underbrace{\sum_t\sum_{y',y''}P(y',y''\mid\mathbf{x})f_k(y',y'',\mathbf{x},t)}_{\text{model expectation, from forward-backward}}-\;\lambda_k/\sigma^2$$

Optimized with L-BFGS (quasi-Newton, uses curvature, converges in ~100 iterations on text) or SGD for very large data.

import sklearn_crfsuite
from sklearn_crfsuite import metrics

crf = sklearn_crfsuite.CRF(
    algorithm="lbfgs",
    c1=0.1,          # L1 -> feature selection, sparse model
    c2=0.1,          # L2 -> smooth weights
    max_iterations=200,
    all_possible_transitions=True,   # learn that I-PER can't follow B-LOC
)
crf.fit(X_train, y_train)            # X = list of list of feature dicts
print(metrics.flat_classification_report(y_test, crf.predict(X_test), digits=3))

# the most useful debugging output in the whole library:
from collections import Counter
for (a, b), w in Counter(crf.transition_features_).most_common(8):
    print(f"{a:8s} -> {b:8s} {w:+.3f}")

all_possible_transitions=True matters: without it, transitions never seen in training get no weight at all rather than a learned negative weight, so the model cannot actively forbid O → I-PER.

Day 32

Named Entity Recognition, Classical Approach

22 min

The task where token-level metrics quietly lie to you.

Entity-level evaluation, and why token-level is wrong

Predict B-PER I-PER O where gold is B-PER I-PER I-PER: token accuracy is 2/3 = 67%, but you produced zero correct entities — the span is wrong, so it is one FP and one FN, and entity F1 is 0. Use seqeval, which scores exact span+type matches.

from seqeval.metrics import classification_report, f1_score
print(classification_report(y_true, y_pred, mode="strict", scheme="IOB2", digits=3))

mode="strict" matters: the default lenient mode accepts an I-PER that starts an entity, which inflates scores by ~1 point.

Features and gazetteers

Beyond the Day 30 template, add: word shape (Xxxxx, XX-999), whether the token is in a gazetteer of known names/places/companies (as a feature, not a rule), the token's most-frequent-tag from a big unlabelled corpus (Brown clusters were the classic semi-supervised trick), and a window of ±2 words.

Gazetteers as features, not rules Dictionary matching alone gets high precision and terrible recall, and it cannot resolve Washington the person vs the state vs the university. Feed the match as a binary feature and let the model weigh it against context.

Schema drift

CoNLL-2003 has PER/LOC/ORG/MISC. OntoNotes has 18 types including DATE, MONEY, NORP, WORK_OF_ART. WNUT-17 targets emerging entities on social media and reports a separate "unseen entity" F1 — on which scores drop from ~90 to ~40. When someone quotes an NER F1, always ask which dataset, which scheme, and whether entities were seen in training.

Nested and overlapping entities "the University of Washington" is an ORG containing a LOC. BIO cannot express this — it assigns one tag per token. Options: multiple independent BIO layers (one per type), span-based classification (enumerate all spans up to length \(L\), classify each — \(O(nL)\) candidates), or a hypergraph decoder. Span-based is the modern default.

Chunking & Shallow Parsing

16 min

Non-recursive phrases, flat and fast. Often all you need.

Chunking as sequence labelling

Same BIO machinery as NER, different labels: B-NP I-NP B-VP I-VP B-PP O. Chunks do not nest and do not overlap, which is exactly what makes the task tractable and what limits it.

import nltk
grammar = r"""
  NP: {<DT|PRP\$>?<JJ.*>*<NN.*>+}     # optional det, adjectives, noun(s)
      {<NNP>+}                          # proper noun sequence
      {<PRP>}                           # bare pronoun
  PP: {<IN><NP>}
  VP: {<MD>?<VB.*>+<RB.*>?}
"""
cp = nltk.RegexpParser(grammar)
tree = cp.parse(nltk.pos_tag(nltk.word_tokenize(
        "The quick brown fox will jump over the lazy dog")))

A regex chunk grammar over POS tags gets ~85–90 F1 on newswire in about ten lines. A learned CRF chunker gets ~94–96. Choose based on whether you have training data and whether you need to explain the rules to a domain expert.

When shallow beats full parsing

Full parsing costs \(O(n^3)\) and is fragile on noisy text. Shallow parsing is linear and degrades gracefully. Use chunking when you need: noun phrases as candidate terms for keyword extraction, phrase-level retrieval units, aspect candidates for ABSA (Day 50), or arguments for a template-based IE system. Use full parsing when you need long-range relations — who did what across a clause boundary.

spaCy shortcut: doc.noun_chunks derives flat NPs from the dependency parse — you get parser-quality chunks without writing a grammar.

Day 34

Constituency Parsing

24 min

CKY is the clearest dynamic program in NLP. Trace it once by hand and chart parsing is yours forever.

CFGs and the explosion

A grammar \(G=(N,\Sigma,R,S)\) with rules like S → NP VP, NP → Det N, VP → V NP PP. The number of binary trees over \(n\) leaves is the Catalan number \(C_{n-1}=\frac{1}{n}\binom{2n-2}{n-1}\): 5 words → 14 trees, 10 words → 4,862, 20 words → over 1.7 billion. Enumeration is hopeless; you need a chart.

Chomsky Normal Form

Every rule must be \(A\to BC\) or \(A\to w\). Conversion is mechanical: binarize long right-hand sides with fresh symbols (VP → V NP PP becomes VP → V @VP, @VP → NP PP), eliminate unit rules by collapsing chains, remove ε-rules. CNF is what makes CKY's two-way split possible.

CKY chart parser — every cell shows the constituents spanning it

Type the fox saw a dog with a telescope and look at cell (2,8): both a VP reading (saw-with-telescope) and, via NP → NP PP, a dog-with-telescope reading exist in the chart simultaneously. The chart stores the ambiguity compactly in \(O(n^3)\) space even though there are exponentially many trees. That is the whole trick.

PCFGs

$$P(T)=\prod_{r\in T}P(r),\qquad \hat{P}(A\to\beta)=\frac{C(A\to\beta)}{\sum_{\beta'}C(A\to\beta')}=\frac{C(A\to\beta)}{C(A)}$$

Plain PCFGs are weak because rule probabilities ignore words: VP → V NP PP has the same probability whether the verb is eat or see. Lexicalization annotates each non-terminal with its head word (VP(saw)), which fixes PP-attachment but multiplies the grammar size enormously and needs heavy smoothing. Parent annotation and latent-variable splitting (Berkeley parser) are cheaper fixes.

PARSEVAL

Score labelled brackets: a predicted \((\text{label}, i, j)\) is correct if the gold tree contains it. Report labelled precision, recall, F1, and crossing brackets. Around 95 F1 on WSJ for neural parsers. PARSEVAL is criticized for being insensitive to the attachment errors that matter most — a single misattached PP costs very little.

Day 35

Dependency Parsing

24 min

Two families: build the tree with a sequence of actions, or score all arcs and find the best tree.

Projectivity

A tree is projective if no two arcs cross when drawn above the sentence. English is ~99% projective; Czech, Dutch and German are not (~15–25% non-projective sentences), because they allow discontinuous constituents. Transition-based arc-standard/arc-eager can only produce projective trees; graph-based MST parsers handle non-projectivity for free.

Transition-based: arc-eager traced

Configuration = (stack \(\sigma\), buffer \(\beta\), arc set \(A\)). Four actions:

ActionPreconditionEffect
SHIFTbuffer non-emptymove \(b_1\) to the stack
LEFT-ARC(l)\(s_1\) has no head, \(s_1\ne\)ROOTadd \(b_1\xrightarrow{l}s_1\), pop \(s_1\)
RIGHT-ARC(l)—add \(s_1\xrightarrow{l}b_1\), push \(b_1\)
REDUCE\(s_1\) already has a headpop \(s_1\)

Arc-standard vs arc-eager: arc-standard only attaches a right dependent once all of that dependent's own dependents are found, so right arcs are added late; arc-eager attaches as soon as possible and needs the extra REDUCE action to clean up. Arc-eager is more incremental and usually a little more accurate.

Graph-based: score every arc, find the best tree

Score all \(n^2\) possible arcs with a model, then find the maximum spanning tree of the resulting directed graph rooted at ROOT. Chu–Liu/Edmonds does this in \(O(n^2)\): each node greedily selects its highest-scoring incoming arc; if the result is a tree, done; if there is a cycle, contract it into a single node, recompute arc scores into the contracted node, and recurse.

$$\hat{T}=\argmax_{T\in\mathcal{T}(x)}\sum_{(h,d,l)\in T}s(h,d,l)$$
Transition-basedGraph-based
Complexity\(O(n)\)\(O(n^2)\) MST, \(O(n^3)\) with Eisner for projective

Metrics

UAS = % of tokens with the correct head. LAS = % with the correct head and label. LAS is always lower, typically by 2–3 points; always report LAS. Modern parsers reach ~96 UAS / ~94 LAS on English UD.

SVO triples from a dependency parse 
import spacy
nlp = spacy.load("en_core_web_sm")

SUBJ = {"nsubj", "nsubjpass", "csubj"}
OBJ  = {"dobj", "obj", "attr", "oprd", "dative"}

def triples(text):
    for sent in nlp(text).sents:
        for tok in sent:
            if tok.pos_ not in ("VERB", "AUX"):
                continue
            subs = [c for c in tok.children if c.dep_ in SUBJ]
            objs = [c for c in tok.children if c.dep_ in OBJ]
            # also follow prepositional objects: "acquired BY x", "invested IN y"
            for prep in (c for c in tok.children if c.dep_ == "prep"):
                objs += [g for g in prep.children if g.dep_ == "pobj"]
            neg = any(c.dep_ == "neg" for c in tok.children)
            for s in subs:
                for o in objs:
                    yield (span(s), ("NOT " if neg else "") + tok.lemma_, span(o))

def span(tok):                      # expand a head to its full noun phrase
    return "".join(t.text_with_ws for t in tok.subtree).strip()
Negation A naive triple extractor turns "Acme did not acquire Beta" into (Acme, acquire, Beta) — the exact opposite of the truth. Always check for a neg child. This single bug has shipped in production IE systems more than once.

The reproducible pipeline

from sklearn.pipeline import Pipeline
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import GridSearchCV, StratifiedKFold
from sklearn.calibration import CalibratedClassifierCV

pipe = Pipeline([
    ("tfidf", TfidfVectorizer(sublinear_tf=True)),
    ("clf",   LogisticRegression(max_iter=2000, class_weight="balanced")),
])

grid = {
    "tfidf__ngram_range": [(1,1), (1,2)],
    "tfidf__min_df":      [1, 2, 5],
    "tfidf__max_df":      [0.9, 1.0],
    "clf__C":             [0.1, 1, 10],
}

search.fit(X_train, y_train)          # everything inside a fold: no leakage

Putting the vectorizer inside the Pipeline is the whole point: GridSearchCV refits it on each training fold, so document frequencies never leak across the split.

Class imbalance, three honest options

class_weight="balanced"
Weights each class by \(n/(K\cdot n_c)\) in the loss. Free, no data change, first thing to try.
Resampling
Random undersampling of the majority loses information; SMOTE interpolates in feature space, which is meaningless for sparse text — the interpolated point is a document that contains half a word. Avoid SMOTE on TF-IDF.
Threshold moving
Train normally, then pick the decision threshold on validation. Usually as good as reweighting and it keeps the probabilities interpretable.

Calibration

If your downstream system routes anything above 0.8 to auto-action, the number must mean something. Plot a reliability diagram (predicted probability vs observed frequency, binned) and report Expected Calibration Error:

$$\mathrm{ECE}=\sum_{m=1}^{M}\frac{|B_m|}{N}\Bigl|\,\mathrm{acc}(B_m)-\mathrm{conf}(B_m)\,\Bigr|$$

LR is usually well calibrated out of the box; NB and SVM are not.

Interpretation

Global — sort clf.coef_ and print the top ±25 features per class. Anything obviously spurious (a document ID, a boilerplate footer, the name of the annotator) is leakage. Local — LIME perturbs one document by deleting words and fits a local linear surrogate to explain that prediction. Useful for showing a stakeholder why one case was flagged; not a global truth claim.
