Day 53

Neural Network Foundations

26 min

One hidden layer, and why the nonlinearity is the entire point.

The perceptron and XOR

A single linear unit computes \(\hat{y}=\mathbb{1}[\mathbf{w}^\top\mathbf{x}+b>0]\) — a hyperplane. XOR is not linearly separable, so no setting of \(\mathbf{w},b\) works. Minsky and Papert's 1969 proof of this stalled the field for a decade. The fix is a hidden layer: two units can carve the plane into regions whose intersection solves XOR.

$$\mathbf{h}=f(W_1\mathbf{x}+\mathbf{b}_1),\qquad \hat{\mathbf{y}}=\softmax(W_2\mathbf{h}+\mathbf{b}_2)$$
Stack two linear layers with no nonlinearity and you get \(W_2W_1\mathbf{x}=W'\mathbf{x}\) — still one linear map, no matter how many layers. Depth without a nonlinearity buys nothing. \(f\) is not a detail.
FunctionFormulaRangeUse
sigmoid\(1/(1+e^{-x})\)(0,1)binary output, gates — never a hidden layer
tanh\((e^{x}-e^{-x})/(e^{x}+e^{-x})\)(−1,1)RNN cell state; zero-centred
ReLU\(\max(0,x)\)[0,∞)default for CNNs/MLPs. Cheap, no saturation for \(x>0\)
LeakyReLU\(\max(\alpha x, x)\)ℝwhen units die (gradient exactly 0 forever)

Initialization

If weights are too large, activations explode layer by layer; too small and they vanish. Keep the variance of activations (forward) and gradients (backward) roughly constant:

$$\text{Xavier/Glorot: }\ \mathrm{Var}(W)=\frac{2}{n_{\text{in}}+n_{\text{out}}}\qquad \text{He: }\ \mathrm{Var}(W)=\frac{2}{n_{\text{in}}}$$

Xavier for tanh/sigmoid; He for ReLU (the factor 2 compensates for ReLU zeroing half the units). Initialize biases to zero, except forget-gate biases (Day 61). PyTorch's defaults are Kaiming-uniform, which is usually fine — but if a model will not train, this is worth checking early.

What the universal approximation theorem does not say It says a one-hidden-layer network with enough units can approximate any continuous function on a compact set arbitrarily well. It says nothing about how many units (possibly exponentially many), nothing about whether gradient descent will find those weights, and nothing about generalization to new data. It is an existence proof, not an engineering guarantee — and it is not the reason deep networks work.

Day 54

Backpropagation & Automatic Differentiation

26 min

The chain rule, applied bookkeepingly. Build the engine once and PyTorch stops being magic.

The computational graph

Why reverse mode

Forward mode computes \(\partial(\text{everything})/\partial(\text{one input})\) — cost \(O(n_{\text{inputs}})\) passes. Reverse mode computes \(\partial(\text{one output})/\partial(\text{everything})\) — cost \(O(n_{\text{outputs}})\) passes. Neural networks have millions of parameters and one scalar loss, so reverse mode wins by a factor of millions. The price is memory: you must store every intermediate activation for the backward pass, which is why batch size × sequence length × hidden size is what fills your GPU.

a ~90-line autodiff engine that actually works 
import math

class Value:
    def __init__(self, data, _children=(), _op=""):
        self.data, self.grad = data, 0.0
        self._backward = lambda: None
        self._prev, self._op = set(_children), _op

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other), "+")
        def _backward():
            self.grad  += out.grad          # += , not = : nodes can be reused
            other.grad += out.grad
        out._backward = _backward
        return out

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other), "*")
        def _backward():
            self.grad  += other.data * out.grad
            other.grad += self.data  * out.grad
        out._backward = _backward
        return out

    def __pow__(self, k):
        out = Value(self.data ** k, (self,), f"**{k}")
        def _backward(): self.grad += k * self.data ** (k - 1) * out.grad
        out._backward = _backward
        return out

    def sigmoid(self):
        s = 1 / (1 + math.exp(-self.data))
        out = Value(s, (self,), "sigmoid")
        def _backward(): self.grad += s * (1 - s) * out.grad
        out._backward = _backward
        return out

    def relu(self):
        out = Value(max(0.0, self.data), (self,), "relu")
        def _backward(): self.grad += (out.data > 0) * out.grad
        out._backward = _backward
        return out

    def backward(self):
        topo, seen = [], set()
        def build(v):
            if v in seen: return
            seen.add(v)
            for c in v._prev: build(c)
            topo.append(v)                  # children before parents
        build(self)
        self.grad = 1.0
        for v in reversed(topo): v._backward()

    __radd__ = __add__; __rmul__ = __mul__
    def __neg__(self):  return self * -1
    def __sub__(self, o): return self + (-o)
    def __truediv__(self, o): return self * o ** -1

# check it
w, x, b, y = Value(2.0), Value(3.0), Value(-5.0), Value(1.0)
L = (( w*x + b ).sigmoid() - y) ** 2
L.backward()
print(L.data, w.grad, b.grad)     # 0.0724  -0.3174  -0.1058

Gradient checking

$$\frac{\partial L}{\partial\theta_i}\approx\frac{L(\theta+\varepsilon e_i)-L(\theta-\varepsilon e_i)}{2\varepsilon},\qquad \varepsilon\approx10^{-5}$$

Use the central difference (error \(O(\varepsilon^2)\)), not the forward one (\(O(\varepsilon)\)). Compare with relative error \(\frac{|a-b|}{\max(|a|,|b|)}\): below \(10^{-7}\) is correct, above \(10^{-4}\) is a bug. Check in float64, and beware of kinks — ReLU at exactly 0 will always fail the check.

PyTorch essentials this maps onto requires_grad=True marks a leaf to accumulate into · .backward() is the topological pass above · .grad accumulates, hence optimizer.zero_grad() · with torch.no_grad(): stops graph construction for inference · .detach() cuts a tensor out of the graph (this is how you truncate BPTT on Day 60).

Day 55

PyTorch for NLP

26 min

The variable-length problem, and the training loop you will paste for the next 65 days.

The one thing that is different about text

Images are rectangles. Sentences are not. Every batch has different lengths, so you pad to the longest in the batch — and then must stop the model from learning anything from the padding. Three mechanisms: padding_idx in the embedding, an attention/loss mask, and pack_padded_sequence for RNNs.

import torch, torch.nn as nn
from torch.utils.data import Dataset, DataLoader
from torch.nn.utils.rnn import pad_sequence

PAD, UNK, BOS, EOS = 0, 1, 2, 3

class TextDS(Dataset):
    def __init__(self, texts, labels, vocab):
        self.texts, self.labels, self.vocab = texts, labels, vocab
    def __len__(self): return len(self.texts)
    def __getitem__(self, i):
        ids = [self.vocab.get(t, UNK) for t in self.texts[i].split()]
        return torch.tensor(ids), torch.tensor(self.labels[i])

def collate(batch):
    seqs, ys = zip(*batch)
    lens = torch.tensor([len(s) for s in seqs])
    X    = pad_sequence(seqs, batch_first=True, padding_value=PAD)
    mask = (X != PAD)                       # (B, T) bool
    return X, lens, mask, torch.stack(ys)

loader = DataLoader(ds, batch_size=32, shuffle=True, collate_fn=collate,
                    num_workers=4, pin_memory=True, drop_last=True)
Sort by length, or waste half your compute Random batching mixes a 5-token tweet with a 400-token review, so the batch is padded to 400 and 98% of the tensor is <pad>. Use a bucketing sampler: sort by length within a shuffled pool of ~100 batches, then batch. Typical speedup on real corpora: 2–4×, for about fifteen lines of code.

The canonical loop

def run_epoch(model, loader, loss_fn, opt=None, sched=None, device="cuda",
              clip=1.0, scaler=None):
    train = opt is not None
    model.train() if train else model.eval()
    total, n = 0.0, 0
    with torch.set_grad_enabled(train):
        for X, lens, mask, y in loader:
            X, mask, y = X.to(device), mask.to(device), y.to(device)
            with torch.autocast("cuda", dtype=torch.bfloat16, enabled=scaler is not None):
                logits = model(X, lens, mask)
                loss   = loss_fn(logits, y)
            if train:
                opt.zero_grad(set_to_none=True)     # cheaper than zeroing
                if scaler:
                    scaler.scale(loss).backward()
                    scaler.unscale_(opt)            # unscale BEFORE clipping
                    torch.nn.utils.clip_grad_norm_(model.parameters(), clip)
                    scaler.step(opt); scaler.update()
                else:
                    loss.backward()
                    torch.nn.utils.clip_grad_norm_(model.parameters(), clip)
                    opt.step()
                if sched: sched.step()              # per-step for warmup schedules
            total += loss.item() * y.size(0); n += y.size(0)
    return total / n

Things that bite

model.eval()
Switches dropout off and BatchNorm to running statistics. Forgetting it makes validation loss noisy and pessimistic. It does not disable gradients — that is torch.no_grad(), and you need both.
loss.item()
Accumulating total += loss keeps the whole graph alive and leaks memory until you OOM. Always .item() or .detach().
Checkpoints
Save model.state_dict(), not the model object (pickling a class breaks on any refactor). Save the optimizer and scheduler state too, or resuming restarts your LR schedule from zero.
Broadcasting
(B,T,1) * (B,1,H) silently gives (B,T,H). Assert shapes in the forward pass while developing; the bug that produces a plausible-looking wrong tensor is the expensive one.

Day 56

Optimization & Training Dynamics

24 min

Learning rate is the most important hyperparameter. Everything else is a distant second.

The optimizer lineage

$$\text{SGD: }\ \theta_{t+1}=\theta_t-\eta g_t \qquad \text{Momentum: }\ v_t=\beta v_{t-1}+g_t,\ \ \theta_{t+1}=\theta_t-\eta v_t$$
$$\text{Adam: }\ m_t=\beta_1m_{t-1}+(1-\beta_1)g_t,\quad v_t=\beta_2v_{t-1}+(1-\beta_2)g_t^2$$
$$\hat{m}_t=\frac{m_t}{1-\beta_1^t},\quad \hat{v}_t=\frac{v_t}{1-\beta_2^t},\qquad \theta_{t+1}=\theta_t-\eta\frac{\hat{m}_t}{\sqrt{\hat{v}_t}+\varepsilon}$$

The bias correction matters: at \(t=1\), \(m_1=(1-\beta_1)g_1=0.1g_1\), which would be a 10× too-small first step without dividing by \(1-\beta_1^t\). Adam adapts a per-parameter step size, which suits text: rare-word embeddings get few gradients and need bigger steps than the frequent ones.

Why AdamW, always, for NLP In Adam, adding \(\lambda\theta\) to the gradient means the decay term gets divided by \(\sqrt{\hat v}\) too — so parameters with large gradient history get less weight decay, which is backwards. AdamW decouples it: \(\theta_{t+1}=\theta_t-\eta\bigl(\hat m_t/(\sqrt{\hat v_t}+\varepsilon)+\lambda\theta_t\bigr)\). Every transformer recipe you will meet from Day 82 onward uses AdamW. Exclude biases and LayerNorm parameters from the decay.

Warmup, and the reason it exists

At step 1 Adam's variance estimate \(\hat v\) is computed from a single noisy gradient, so the adaptive step size is wildly unreliable and can throw the model somewhere it never recovers from. Warmup raises the LR linearly from 0 over the first few hundred to few thousand steps, giving \(\hat v\) time to become a real estimate. This matters most for transformers with post-LN (Day 75), where without warmup training diverges outright.

Learning-rate schedules — the shapes you will actually use

Finding the learning rate in 90 seconds

The LR range test: start at \(10^{-8}\), multiply by ~1.1 every batch, plot loss against log-LR. The loss falls, reaches a minimum, then explodes. Pick roughly one order of magnitude below the minimum — i.e. the steepest part of the descent, not the bottom.

Gradient clipping and batch size

$$\text{if }\|\mathbf{g}\|_2>c:\quad \mathbf{g}\leftarrow c\,\frac{\mathbf{g}}{\|\mathbf{g}\|_2}$$

Clip by global norm (\(c=1.0\) is standard), not per-parameter value, so the gradient direction is preserved. Essential for RNNs, still helpful for transformers. On batch size: larger batches give less gradient noise, so you can raise the LR — the linear scaling rule (\(\eta\propto B\)) works up to a point, \(\sqrt{B}\) scaling is safer for Adam. Very large batches generalize slightly worse without a compensating LR increase and warmup.

Mixed precision: bf16 has the same exponent range as fp32 so it rarely overflows and needs no loss scaling — use it on Ampere or newer. fp16 has a narrow range and needs a GradScaler. Both give roughly 2× speed and half the activation memory.

Reading loss curves, and honest numbers on how much text augmentation actually helps.

The single best sanity check Before any real run, overfit a batch of 16 examples to near-zero loss. If you cannot, you have a bug — a masking error, a detached graph, a label misalignment — and no amount of regularization will help.

Dropout, placed correctly

Zero each unit with probability \(p\) at training time and scale the survivors by \(1/(1-p)\) (inverted dropout), so no rescaling is needed at inference. In NLP: apply after embeddings (0.1–0.3), between RNN/transformer layers (0.1–0.5), and before the classifier head. Do not apply it inside recurrent connections naively — that resamples the mask at every timestep and destroys the memory. Use variational dropout: one mask, reused across all timesteps.

Other useful variants: word dropout (replace whole tokens with <unk> at ~10%, which forces context use and improves rare-word handling) and DropConnect on the recurrent weight matrix (the AWD-LSTM recipe).

Label smoothing

$$y_i^{\mathrm{LS}}=(1-\alpha)y_i+\frac{\alpha}{K},\qquad \alpha\approx0.1$$

Stops the model from driving logits to infinity to reach a probability of exactly 1. Improves calibration and usually BLEU by ~0.5, while slightly worsening perplexity — because perplexity rewards exactly the overconfidence you just removed. Report both and say which you optimized.

Day 58

Embedding Layers & Neural Text Classification

22 min

Your first real PyTorch model — and a genuine chance that it loses to Day 36.

What nn.Embedding actually is

A \(|V|\times d\) matrix plus a row lookup. Mathematically it is \(\mathbf{e}=\mathbf{x}_{\text{one-hot}}^\top E\), but computing that as a matmul would be \(O(|V|d)\) per token of pure waste, so it is implemented as indexing. The gradient is sparse — only the rows for tokens in the batch receive updates.

emb = nn.Embedding(vocab_size, 300, padding_idx=PAD)
# padding_idx: that row is initialised to zeros AND its gradient is forced to zero,
# so  never drifts into meaning anything.

# initialise from pretrained vectors
import numpy as np
W = np.random.normal(0, 0.1, (vocab_size, 300)).astype("float32")
hit = 0
for tok, i in vocab.items():
    if tok in glove: W[i] = glove[tok]; hit += 1
print(f"coverage {hit/len(vocab):.1%}")        # report this number; below 60% is a tokenizer mismatch
emb.weight.data.copy_(torch.from_numpy(W))
emb.weight.data[PAD].zero_()
emb.weight.requires_grad = False               # freeze; unfreeze later
Freeze then unfreeze With under ~10k training examples, fine-tuning 300×50k = 15M embedding parameters overfits instantly and destroys the pretrained geometry for words that appear rarely in your data. Train the head with embeddings frozen for 2–3 epochs, then unfreeze with a 10× smaller LR. This is ULMFiT's gradual unfreezing, and it is still good advice.

Pooling

$$\text{mean: } \mathbf{s}=\frac{\sum_t m_t\mathbf{h}_t}{\sum_t m_t}\qquad \text{max: } s_j=\max_{t:\,m_t=1}h_{t,j}\qquad \text{attn: } \mathbf{s}=\sum_t\alpha_t\mathbf{h}_t,\ \ \alpha=\softmax(\mathbf{v}^\top\tanh(W\mathbf{h}))$$

Masking is not optional: an unmasked mean divides by the padded length, and an unmasked max can select a padding position. For max-pooling, set padded positions to \(-\infty\) before the max, not to 0.

The deep averaging network

class DAN(nn.Module):
    def __init__(self, V, d=300, h=256, C=2, p=0.3, pad=0):
        super().__init__()
        self.emb  = nn.Embedding(V, d, padding_idx=pad)
        self.drop = nn.Dropout(p)
        self.mlp  = nn.Sequential(nn.Linear(d, h), nn.ReLU(), nn.Dropout(p),
                                  nn.Linear(h, h), nn.ReLU(), nn.Dropout(p))
        self.out  = nn.Linear(h, C)

    def forward(self, x, lens=None, mask=None):
        e = self.drop(self.emb(x))                       # (B,T,d)
        m = mask.unsqueeze(-1).float()                   # (B,T,1)
        s = (e * m).sum(1) / m.sum(1).clamp(min=1)       # masked mean
        return self.out(self.mlp(s))

Iyyer et al. showed this order-free model matches syntactic models on sentiment. The depth — not the order — does the work: each layer amplifies small differences in the averaged vector.

Expect to lose to TF-IDF On a few thousand labelled examples with a small vocabulary, TF-IDF + LinearSVC frequently beats a from-scratch neural classifier. Neural models need either much more data or pretrained representations. If your neural model loses, that is a finding, not a failure — write it up, and note that Day 82 is where the ordering flips.

Day 59

CNNs for Text

22 min

Filters as learned n-gram detectors. Fast, parallel, and still the right tool sometimes.

$$c_i=f\bigl(\mathbf{w}^\top \mathbf{x}_{i:i+h-1}+b\bigr),\qquad \hat{c}=\max_i c_i$$
class KimCNN(nn.Module):
    def __init__(self, V, d=300, nf=100, widths=(2,3,4,5), C=2, p=0.5, pad=0):
        super().__init__()
        self.emb  = nn.Embedding(V, d, padding_idx=pad)
        self.conv = nn.ModuleList(nn.Conv1d(d, nf, w, padding=w-1) for w in widths)
        self.drop = nn.Dropout(p)
        self.fc   = nn.Linear(nf * len(widths), C)

    def forward(self, x, lens=None, mask=None):
        e = self.emb(x).transpose(1, 2)              # (B,d,T) — Conv1d wants channels first
        feats = []
        for conv in self.conv:
            h = torch.relu(conv(e))                  # (B,nf,T')
            feats.append(h.max(dim=2).values)        # max over time
        return self.fc(self.drop(torch.cat(feats, dim=1)))

Variants worth knowing

Multi-channel
Two embedding copies, one frozen and one fine-tuned, stacked as channels. Kim's best-performing setup; small gain, easy to add.
Character-level CNN
Convolve over characters instead of words. No vocabulary, robust to typos and morphology, but needs much more data and deeper stacks.
Dilated convolution
Insert gaps in the filter so the receptive field grows exponentially with depth: \(1,2,4,8,\dots\). \(k\) layers of dilation-2 see \(2^k\) tokens. This is how WaveNet and ByteNet get long context without recurrence.
Why CNNs still matter They parallelize completely over time (unlike RNNs), they are 5–20× faster than a transformer at inference for the same accuracy on short-text classification, they are robust to word order noise, and their filters are directly inspectable — take the top-activating n-gram per filter and you have an interpretability story a stakeholder can read.

Day 60

RNN Fundamentals

24 min

Memory as a loop — and the reason the loop breaks.

$$\mathbf{h}_t=\tanh\bigl(W_{hh}\mathbf{h}_{t-1}+W_{xh}\mathbf{x}_t+\mathbf{b}\bigr),\qquad \mathbf{y}_t=W_{hy}\mathbf{h}_t$$

The same \(W\) matrices at every timestep — parameter sharing across time, exactly analogous to a CNN's sharing across space. It gives you variable-length input for free and a strong prior that the same pattern means the same thing wherever it appears.

Where the gradient goes

$$\frac{\partial \mathcal{L}_T}{\partial \mathbf{h}_k}=\frac{\partial \mathcal{L}_T}{\partial \mathbf{h}_T}\prod_{t=k+1}^{T}\frac{\partial \mathbf{h}_t}{\partial \mathbf{h}_{t-1}}=\frac{\partial \mathcal{L}_T}{\partial \mathbf{h}_T}\prod_{t=k+1}^{T}W_{hh}^\top\,\mathrm{diag}\bigl(\tanh'(\cdot)\bigr)$$

That product of \(T-k\) matrices behaves like \(\lambda^{T-k}\) where \(\lambda\) is the largest singular value of the per-step Jacobian. Since \(\tanh'\le1\) and is typically much less, the product shrinks geometrically. With an effective \(\lambda=0.8\), the gradient at 50 steps back is \(0.8^{50}\approx1.4\times10^{-5}\) — it is not that long dependencies are hard to learn; it is that no learning signal reaches them at all.

Exploding is the mirror case and is easy to fix (clip). Vanishing is the hard one and needs an architectural fix — that is Day 61.

Truncated BPTT

Full BPTT over a 10,000-token document needs all 10,000 activations in memory. Truncated BPTT processes \(k_1\) steps forward, backpropagates \(k_2\) steps, then detaches the hidden state and continues:

h = None
for chunk in chunks(doc, size=128):
    out, h = model(chunk, h)
    loss = criterion(out, targets(chunk))
    loss.backward()
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    opt.step(); opt.zero_grad()
    h = tuple(x.detach() for x in h)     # forward state kept, gradient path cut

The hidden state still carries information forward past the boundary; only the gradient stops. Forget the detach and the graph grows until you OOM — one of the most common RNN bugs.

Day 61

LSTM

26 min

1997's answer, and the reason it works is one addition sign.

$$\begin{aligned} \mathbf{f}_t&=\sigma\bigl(W_f[\mathbf{h}_{t-1},\mathbf{x}_t]+\mathbf{b}_f\bigr) &&\text{forget: what to erase from memory}\\ \mathbf{i}_t&=\sigma\bigl(W_i[\mathbf{h}_{t-1},\mathbf{x}_t]+\mathbf{b}_i\bigr) &&\text{input: how much of the candidate to write}\\ \tilde{\mathbf{c}}_t&=\tanh\bigl(W_c[\mathbf{h}_{t-1},\mathbf{x}_t]+\mathbf{b}_c\bigr) &&\text{candidate: what could be written}\\ \mathbf{c}_t&=\mathbf{f}_t\odot\mathbf{c}_{t-1}+\mathbf{i}_t\odot\tilde{\mathbf{c}}_t &&\textbf{the state update}\\ \mathbf{o}_t&=\sigma\bigl(W_o[\mathbf{h}_{t-1},\mathbf{x}_t]+\mathbf{b}_o\bigr) &&\text{output: what to expose}\\ \mathbf{h}_t&=\mathbf{o}_t\odot\tanh(\mathbf{c}_t) \end{aligned}$$

Why the gradient survives

$$\frac{\partial \mathbf{c}_t}{\partial \mathbf{c}_{t-1}}=\mathbf{f}_t\ (+\ \text{small terms through the gates})$$

Compare with the vanilla RNN's \(W_{hh}^\top\mathrm{diag}(\tanh')\). Here the dominant term is elementwise multiplication by a learned gate, not a matrix product. If the model learns \(f_t\approx1\) for some dimension, the gradient flows through that dimension essentially unchanged for hundreds of steps. That is the constant error carousel — the actual mechanism, and the reason the additive update matters more than the gates themselves.

Initialize the forget-gate bias to 1 At initialization \(\sigma(0)=0.5\), so the cell state halves every step and information decays with a half-life of one timestep — the model starts in the worst possible regime and must climb out. Setting \(\mathbf{b}_f=1\) gives \(\sigma(1)\approx0.73\) and a much longer default memory. Jozefowicz et al. found this single line worth several points. PyTorch does not do it for you.

Parameters and variants

An LSTM has \(4(dh+h^2+h)\) parameters against a vanilla RNN's \(dh+h^2+h\) — exactly 4× (three gates plus the candidate). Peephole connections let the gates see \(\mathbf{c}_{t-1}\) directly; coupled gates set \(\mathbf{i}_t=1-\mathbf{f}_t\) (what you forget, you replace), which is what the GRU does. Greff et al.'s large-scale comparison found no variant reliably beats the vanilla LSTM, and that the forget gate and the output activation are the two components you cannot remove.

Day 62

GRU, Bidirectional & Stacked RNNs

20 min

Fewer gates, two directions, more layers. Three cheap upgrades and one thing you must not do.

GRU: the LSTM with two gates

$$\begin{aligned} \mathbf{z}_t&=\sigma(W_z[\mathbf{h}_{t-1},\mathbf{x}_t]) &&\text{update gate (merges forget + input)}\\ \mathbf{r}_t&=\sigma(W_r[\mathbf{h}_{t-1},\mathbf{x}_t]) &&\text{reset gate}\\ \tilde{\mathbf{h}}_t&=\tanh\bigl(W[\mathbf{r}_t\odot\mathbf{h}_{t-1},\mathbf{x}_t]\bigr)\\ \mathbf{h}_t&=(1-\mathbf{z}_t)\odot\mathbf{h}_{t-1}+\mathbf{z}_t\odot\tilde{\mathbf{h}}_t \end{aligned}$$

No separate cell state — \(\mathbf{h}\) does both jobs, and the update is a convex interpolation between old and new. 3 gate-sized matrices instead of 4, so ~25% fewer parameters and ~20–30% faster. The reset gate is the genuinely different piece: it can make the candidate ignore the previous state entirely, which is useful at phrase boundaries.

Empirically LSTM and GRU are within noise of each other on most tasks. GRU tends to win on smaller datasets (fewer parameters to fit); LSTM tends to win on long sequences and language modelling. Try both; the difference is usually smaller than your seed variance, so report both with multiple seeds.

Bidirectional

$$\overrightarrow{\mathbf{h}}_t=\mathrm{RNN}(\mathbf{x}_{1:t}),\qquad \overleftarrow{\mathbf{h}}_t=\mathrm{RNN}(\mathbf{x}_{T:t}),\qquad \mathbf{h}_t=[\overrightarrow{\mathbf{h}}_t;\overleftarrow{\mathbf{h}}_t]$$

Two independent RNNs, concatenated. Output dimension doubles. This typically buys 1–3 points on tagging and classification, because "which tag is this" often depends on what comes after.

Never use a BiRNN for autoregressive generation The backward pass reads \(\mathbf{x}_{t+1..T}\) — the tokens you are trying to predict. Train a bidirectional language model naively and it will reach near-zero loss by copying the answer from the backward state, then produce nothing at inference. The same leak is why BERT needs masked LM instead of next-token prediction (Day 81), and why decoder-only models use causal masks (Day 72).

Stacking

Two to four layers is the useful range; beyond that RNNs stop improving. Feed layer \(\ell\)'s outputs as layer \(\ell+1\)'s inputs, and add residual connections between layers (\(\mathbf{h}^{\ell+1}=\mathrm{RNN}(\mathbf{h}^\ell)+\mathbf{h}^\ell\)) once you go past two — without them, depth hurts. Lower layers empirically capture morphology and POS, upper layers capture semantics and long-range structure, which is the finding that later gets reproduced in transformer probing studies.

Dropout in recurrent nets

PyTorch's nn.LSTM(dropout=p) applies dropout between layers only, not on the recurrent connection — and it silently does nothing if num_layers=1. For recurrent regularization you need variational dropout: sample one mask per sequence and reuse it at every timestep, so the same units are dropped throughout and the memory is not scrambled.

class VariationalDropout(nn.Module):
    """One mask per sequence, shared across all timesteps."""
    def __init__(self, p): super().__init__(); self.p = p
    def forward(self, x):                        # x: (B, T, H)
        if not self.training or self.p == 0: return x
        mask = x.new_empty(x.size(0), 1, x.size(2)).bernoulli_(1 - self.p)
        return x * mask / (1 - self.p)

Day 63

Sequence Labelling with BiLSTM-CRF

24 min

The pre-BERT state of the art, and still the right output layer on top of BERT today.

Why a softmax per token is not enough

Independent per-token softmax can emit O I-PER B-LOC I-PER — a sequence that is structurally illegal under BIO. It has no mechanism to know that I-PER cannot follow O. A CRF layer adds a learned transition matrix \(A\in\mathbb{R}^{K\times K}\) and scores whole sequences:

$$s(\mathbf{x},\mathbf{y})=\sum_{t=1}^{T}\underbrace{P_{t,y_t}}_{\text{BiLSTM emission}}+\sum_{t=0}^{T}\underbrace{A_{y_t,y_{t+1}}}_{\text{learned transition}}$$
$$\log P(\mathbf{y}\mid\mathbf{x})=s(\mathbf{x},\mathbf{y})-\underbrace{\log\sum_{\mathbf{y}'}e^{s(\mathbf{x},\mathbf{y}')}}_{\text{partition function, forward algorithm}}$$

The partition function is the same \(O(K^2T)\) forward recursion from Day 29, in log-space with logsumexp. Inference is Viterbi. Typical gain over plain softmax: +1 to +3 entity F1, and 100% structurally valid output.

the CRF layer — forward score and Viterbi in ~40 lines 
class CRF(nn.Module):
    def __init__(self, K):
        super().__init__()
        self.K = K
        self.trans = nn.Parameter(torch.randn(K, K) * 0.01)   # trans[i,j] = i -> j
        self.start = nn.Parameter(torch.randn(K) * 0.01)
        self.end   = nn.Parameter(torch.randn(K) * 0.01)

    def _logZ(self, em, mask):                    # em (B,T,K)  mask (B,T)
        a = self.start + em[:, 0]                                    # (B,K)
        for t in range(1, em.size(1)):
            nxt = torch.logsumexp(a.unsqueeze(2) + self.trans        # (B,K,K)
                                  + em[:, t].unsqueeze(1), dim=1)    # (B,K)
            a = torch.where(mask[:, t].unsqueeze(1), nxt, a)         # respect padding
        return torch.logsumexp(a + self.end, dim=1)                  # (B,)

    def _score(self, em, tags, mask):
        B, T = tags.shape
        s = self.start[tags[:, 0]] + em[:, 0].gather(1, tags[:, :1]).squeeze(1)
        for t in range(1, T):
            step = self.trans[tags[:, t-1], tags[:, t]] \
                 + em[:, t].gather(1, tags[:, t:t+1]).squeeze(1)
            s = s + step * mask[:, t]
        last = mask.sum(1).long() - 1
        return s + self.end[tags.gather(1, last.unsqueeze(1)).squeeze(1)]

    def nll(self, em, tags, mask):
        return (self._logZ(em, mask) - self._score(em, tags, mask)).mean()

    @torch.no_grad()
    def viterbi(self, em, mask):
        B, T, K = em.shape
        a  = self.start + em[:, 0]
        bp = []
        for t in range(1, T):
            sc = a.unsqueeze(2) + self.trans                # (B,K,K)
            best, idx = sc.max(dim=1)
            nxt = best + em[:, t]
            a = torch.where(mask[:, t].unsqueeze(1), nxt, a)
            bp.append(idx)
        best_last = (a + self.end).argmax(1)
        paths = []
        for b in range(B):
            L = int(mask[b].sum().item())
            y = [int(best_last[b])]
            for t in range(L - 2, -1, -1):
                y.append(int(bp[t][b, y[-1]]))
            paths.append(y[::-1])
        return paths

Character features for unknown words

The classic architecture composes three representations per token: a pretrained word embedding, a character-level BiLSTM or CNN output, and optionally hand-crafted shape features. The character encoder is what handles words never seen in training — it learns that a token ending in -ovic or starting with a capital and containing a digit has a characteristic tag distribution.

$$\mathbf{x}_t=\bigl[\underbrace{\mathbf{e}_{w_t}}_{\text{word, pretrained}}\ ;\ \underbrace{\mathrm{CharBiLSTM}(c_1..c_m)}_{\text{morphology, OOV}}\ ;\ \underbrace{\mathbf{s}_t}_{\text{shape flags}}\bigr]$$
This layer never went away Replace the BiLSTM emissions with BERT's token outputs and you have the standard 2019–2024 NER architecture. The CRF still contributes when: labels have hard structural constraints, the tagset is large, or entities are long. On short entities with a strong encoder the gain shrinks to ~0.3 F1, so measure before you pay the \(O(K^2T)\) decoding cost.

Sequence-to-Sequence Models

26 min

One network reads, another writes. The framing that unlocked translation, summarization and dialogue.

Encoder–decoder

The encoder consumes the source and produces a context vector \(\mathbf{c}\) (classically its final hidden state). The decoder is a conditional language model initialized from \(\mathbf{c}\):

$$P(\mathbf{y}\mid\mathbf{x})=\prod_{t=1}^{T_y}P(y_t\mid y_{
The bottleneck Every word of a 60-token source sentence must be squeezed into one fixed 512-dimensional vector. Measured consequence: BLEU on the original seq2seq falls off a cliff for sentences beyond ~30 tokens. Sutskever's workaround was reversing the source sentence, which brought the first source words closer to the first target words and gained several BLEU — a hack that tells you exactly where the problem was. Attention (Day 65) removes the bottleneck properly.

Teacher forcing and exposure bias

At training time you feed the gold previous token; at inference you feed the model's own previous token. So the model is never trained on its own mistakes, and once it makes one, it is in a state it has never seen — errors compound. That mismatch is exposure bias.

Scheduled sampling mixes gold and predicted tokens with probability annealed from 1 to ~0.5 over training. It reduces the mismatch but breaks the likelihood objective (the model is no longer maximizing \(P(\mathbf{y}\mid\mathbf{x})\)), and Huszár showed it is an inconsistent estimator. In practice modern systems mostly accept exposure bias and fix the symptom at decoding time or with sequence-level fine-tuning.

class Seq2Seq(nn.Module):
    def __init__(self, V_src, V_tgt, d=256, h=512, layers=2, pad=0):
        super().__init__()
        self.enc_emb = nn.Embedding(V_src, d, padding_idx=pad)
        self.dec_emb = nn.Embedding(V_tgt, d, padding_idx=pad)
        self.enc = nn.LSTM(d, h, layers, batch_first=True, bidirectional=True)
        self.bridge = nn.Linear(2*h, h)
        self.dec = nn.LSTM(d, h, layers, batch_first=True)
        self.out = nn.Linear(h, V_tgt)
        self.layers = layers

    def encode(self, src, lens):
        packed = nn.utils.rnn.pack_padded_sequence(
            self.enc_emb(src), lens.cpu(), batch_first=True, enforce_sorted=False)
        outs, (h, c) = self.enc(packed)
        outs, _ = nn.utils.rnn.pad_packed_sequence(outs, batch_first=True)
        # merge the two directions per layer, then map 2h -> h
        def merge(s):
            s = s.view(self.layers, 2, s.size(1), -1)
            return torch.tanh(self.bridge(torch.cat([s[:,0], s[:,1]], dim=-1)))
        return outs, (merge(h), merge(c))

    def forward(self, src, lens, tgt_in):            # teacher forcing
        _, state = self.encode(src, lens)
        dec_out, _ = self.dec(self.dec_emb(tgt_in), state)
        return self.out(dec_out)

The Attention Mechanism

26 min

The most important 26 minutes in the series. Everything in Phase 5 is this idea, scaled.

The fix

Instead of one context vector for the whole sentence, compute a different context vector at every decoding step, as a weighted average of all encoder states — with the weights decided by the decoder's current state.

$$e_{t,i}=\mathrm{score}\bigl(\mathbf{s}_{t-1},\mathbf{h}_i\bigr),\qquad \alpha_{t,i}=\frac{\exp(e_{t,i})}{\sum_{j=1}^{T_x}\exp(e_{t,j})},\qquad \mathbf{c}_t=\sum_{i=1}^{T_x}\alpha_{t,i}\mathbf{h}_i$$

The \(\alpha\) row sums to 1 and is a soft alignment: how much of each source word to look at right now. Nothing forces it to be interpretable — but it usually is, and that was a large part of why the paper landed.

class BahdanauAttention(nn.Module):
    def __init__(self, enc_dim, dec_dim, attn_dim=256):
        super().__init__()
        self.W1 = nn.Linear(dec_dim, attn_dim, bias=False)
        self.W2 = nn.Linear(enc_dim, attn_dim, bias=False)
        self.v  = nn.Linear(attn_dim, 1, bias=False)

    def forward(self, s, H, mask):            # s (B,dec)  H (B,Tx,enc)  mask (B,Tx)
        e = self.v(torch.tanh(self.W1(s).unsqueeze(1) + self.W2(H))).squeeze(-1)
        e = e.masked_fill(~mask, float("-inf"))          # never attend to 
        a = torch.softmax(e, dim=1)                      # (B,Tx)
        c = torch.bmm(a.unsqueeze(1), H).squeeze(1)      # (B,enc)
        return c, a
Mask before the softmax, not after Zeroing the weights afterwards leaves them unnormalized (they no longer sum to 1). Use -inf (or -1e9 in fp16) on the scores. This exact bug reappears in every attention implementation, including the ones on Day 76.

Global vs local

Global attention scores all \(T_x\) positions — \(O(T_xT_y)\). Local attention predicts an alignment position \(p_t\) and attends only within \([p_t-D,p_t+D]\), optionally weighted by a Gaussian centred on \(p_t\). Cheaper for long sequences and the direct ancestor of the sliding-window attention on Day 92.

Attention is not explanation Alignment heatmaps are attractive and often plausible, but Jain & Wallace showed you can frequently find very different attention distributions that produce the same prediction. Use them as a debugging signal, not as a causal account of the model's reasoning.

Decoding Strategies

24 min

Same model, six decoders, six completely different personalities.

Greedy and its myopia

$$\hat{y}_t=\argmax_{y}P(y\mid y_{

Locally optimal, globally not: a high-probability first token can lead into a low-probability continuation while a slightly worse first token opens a much better path. Greedy cannot back up.

Beam search

Keep the \(k\) highest-scoring partial hypotheses at each step, expand all of them, keep the best \(k\) again. Cost \(O(kV T)\).

$$\mathrm{score}(\mathbf{y})=\frac{1}{\mathrm{lp}(|\mathbf{y}|)}\sum_{t=1}^{|\mathbf{y}|}\log P(y_t\mid y_{

Without length normalization, every extra token adds a negative log-probability, so beam search systematically prefers short outputs and truncates translations. \(\alpha\approx0.6\text{–}1.0\) is the usual range.

The curse of large beams Raising \(k\) from 5 to 100 makes BLEU worse. Larger beams find genuinely higher-probability sequences — and those turn out to be short, generic, repetitive text. The model's most probable output is not its best output. This is evidence that maximum likelihood training and human quality judgements are misaligned, not that the search is broken. Practical beam sizes: 4–10 for translation, 1–4 for summarization, and beam search is usually the wrong choice for open-ended generation entirely.
Sampling: temperature, top-k, and nucleus — over one real next-token distribution
$$P_T(y)=\frac{\exp(z_y/T)}{\sum_{y'}\exp(z_{y'}/T)}\qquad \text{nucleus: smallest } V^{(p)} \text{ with } \sum_{y\in V^{(p)}}P(y)\ge p$$

Top-\(k\) uses a fixed cutoff, which is wrong in both directions: too permissive when the model is certain, too restrictive when it is not. Nucleus (top-\(p\)) adapts the cutoff to the shape of the distribution — that is the whole argument of the paper, and why \(p=0.9\text{–}0.95\) became the default.

Repetition control

Repetition penalty divides the logit of already-generated tokens by \(\theta\approx1.1\text{–}1.2\). No-repeat n-gram blocking sets the probability of any token that would complete a previously seen \(n\)-gram to zero (\(n=3\) is common) — effective but dangerous, since legitimate repeats like names get blocked. Contrastive search penalizes candidates whose hidden state is too similar to previous ones, trading a little likelihood for measurably less degeneration.

Day 67

Machine Translation

24 min

The task that drove the field for sixty years, and the metric everyone complains about and still uses.

The SMT era, briefly

The noisy-channel framing: \(\hat{e}=\argmax_e P(f\mid e)P(e)\) — a translation model times a target language model. The IBM models 1–5 built up alignment machinery incrementally (lexical translation, then absolute position, then fertility and distortion), trained by EM on parallel text. Phrase-based SMT replaced word alignment with a phrase table extracted from the alignments, plus a distortion model and a log-linear combination of features tuned by MERT. Moses was the standard toolkit. It worked, it was interpretable, and it needed a large hand-built pipeline that NMT replaced with one network.

Parallel corpora

Sources: institutional proceedings (Europarl, UN, Hansard), subtitle collections (OpenSubtitles — huge, noisy, informal), crawled and aligned web text (ParaCrawl, CCMatrix, mined with LASER/LaBSE sentence embeddings), and religious texts (the widest language coverage, unusual register). Cleaning matters enormously: length-ratio filters, language ID on both sides, and dual conditional cross-entropy filtering typically remove 20–50% of a crawled corpus and improve BLEU.

BLEU, precisely

$$\mathrm{BLEU}=\mathrm{BP}\cdot\exp\left(\sum_{n=1}^{N}w_n\log p_n\right),\qquad w_n=\tfrac{1}{N},\ N=4$$
$$p_n=\frac{\sum_{\text{ngrams}}\min\bigl(\mathrm{count}_{\text{cand}},\ \mathrm{count}_{\text{ref}}\bigr)}{\sum_{\text{ngrams}}\mathrm{count}_{\text{cand}}},\qquad \mathrm{BP}=\begin{cases}1 & c>r\\ e^{1-r/c} & c\le r\end{cases}$$

The clipping in \(p_n\) stops "the the the the" from scoring 1.0. The brevity penalty stops the system from emitting one high-confidence word — precision alone would reward that. It is a corpus-level metric: sum the numerators and denominators over the whole test set before dividing. Sentence-level BLEU is unreliable and needs smoothing.

Back-translation is the workhorse: translate target-language monolingual text into the source with a reverse model, and add the synthetic pairs to training. Pivoting through English is the pragmatic fallback and compounds errors.

Text Summarization

24 min

The task where the model can be fluent, on-topic, and confidently wrong.

Extractive vs abstractive

Extractive selects existing sentences: guaranteed faithful to the source, never ungrammatical within a sentence, but choppy across them and unable to compress or fuse. Abstractive generates new text: fluent and concise, and free to hallucinate. Extractive is the safe default for legal, medical and financial text.

TextRank

Build a graph with sentences as nodes and similarity as edge weights, then run PageRank:

$$\mathrm{WS}(V_i)=(1-d)+d\sum_{V_j\in\mathrm{In}(V_i)}\frac{w_{ji}}{\sum_{V_k\in\mathrm{Out}(V_j)}w_{jk}}\mathrm{WS}(V_j),\qquad d=0.85$$
$$\mathrm{sim}(S_i,S_j)=\frac{|\{w : w\in S_i\wedge w\in S_j\}|}{\log|S_i|+\log|S_j|}$$

The log normalization stops long sentences from dominating purely by overlap. LexRank is the same idea with TF-IDF cosine similarity and a threshold on the edges. Both are unsupervised, need no training data, and are respectable baselines.

import networkx as nx, numpy as np
from sklearn.feature_extraction.text import TfidfVectorizer

def textrank(sentences, k=3):
    X = TfidfVectorizer(stop_words="english").fit_transform(sentences)
    S = (X @ X.T).toarray()
    np.fill_diagonal(S, 0)
    scores = nx.pagerank(nx.from_numpy_array(S), alpha=0.85)
    idx = sorted(sorted(scores, key=scores.get, reverse=True)[:k])   # keep source order
    return [sentences[i] for i in idx]

ROUGE, and what it misses

$$\mathrm{ROUGE\text{-}N}=\frac{\sum_{S\in\mathrm{ref}}\sum_{g_n\in S}\mathrm{count}_{\text{match}}(g_n)}{\sum_{S\in\mathrm{ref}}\sum_{g_n\in S}\mathrm{count}(g_n)}$$

Factual consistency is the open problem Studies find 25–30% of abstractive summaries from strong models contain a factual error relative to the source. def chunk_predict(text, tok, model, max_len=512, stride=128, agg="mean"):
    enc = tok(text, return_overflowing_tokens=True, truncation=True,
              max_length=max_len, stride=stride, return_tensors="pt", padding=True)
    with torch.no_grad():
        logits = model(input_ids=enc["input_ids"],
                       attention_mask=enc["attention_mask"]).logits   # (n_chunks, C)
    if agg == "mean":  return logits.mean(0)          # smooth, dilutes a single strong signal
    if agg == "max":   return logits.max(0).values    # any chunk can trigger — good for detection
    if agg == "first": return logits[0]
    # learned: feed chunk CLS vectors into a small transformer or attention pooler

Overlap (stride) matters so a decisive sentence is not split. Mean is right when evidence is distributed; max is right when one passage decides the label (toxicity, compliance flags, PII detection).

3 · Hierarchical encoding

Encode each sentence or chunk independently, then run a second-level encoder over those vectors: sentence → document. Cost drops from \(O(n^2)\) to \(O(k\cdot m^2 + k^2)\) for \(k\) chunks of \(m\) tokens. Downside: no token-level interaction across chunk boundaries, so cross-chunk coreference is invisible to the model.

4 · Recurrence and memory

Transformer-XL caches the previous segment's hidden states and attends to them with a stop-gradient, giving an effective context far longer than the segment while keeping training cost per segment fixed. This is the ancestor of the KV-cache reuse and streaming attention patterns on Day 92.

What this is setting up Every option here is a workaround for the \(O(n^2)\) attention cost. Day 92 attacks the cost directly — FlashAttention makes exact attention IO-efficient, sparse patterns reduce the number of pairs, and position interpolation extends the trained context. Understand the workarounds first so you can tell when the fancy method is actually earning its complexity.

🛠 Project 4: Neural Seq2Seq with Attention

32 min

Portfolio piece four. The first project where the training loop itself is the hard part.

The full pipeline

  1. Data — Multi30k (30k image captions, en↔de, small enough to train on a laptop GPU) or a synthetic transduction task. Clean, lowercase or not (decide and record), build separate source and target vocabularies with min_freq=2.
  2. Batching by length — bucket so padding stays under ~15% of tokens. Log the padding ratio; it is the cheapest speedup you will find.
  3. Model — BiLSTM encoder, LSTM decoder, Bahdanau attention, dropout 0.3, embeddings 256, hidden 512.
  4. Training — teacher forcing, cross-entropy with ignore_index=PAD and label smoothing 0.1, AdamW, warmup + cosine, grad clip 1.0.
  5. Inference — beam search 5 with length penalty 0.6, plus greedy for comparison.
  6. Evaluation — sacreBLEU + chrF on the test set, with the signature recorded.
  7. Analysis — attention heatmaps, BLEU bucketed by source length, and a manual error taxonomy on 50 outputs.

Debugging a seq2seq that will not converge

SymptomLikely cause
Loss flat at \(\log|V_{\text{tgt}}|\)Nothing is learning — check the LR, and check that labels are shifted correctly
Loss drops then output is one repeated tokenDecoder input/target off-by-one, or you fed the target as its own input
Perfect train loss, garbage generationTeacher forcing at eval — you are still feeding gold tokens
Attention is uniformMask applied after softmax, or encoder outputs collapsed
Output always shortNo length penalty in beam search
NaN lossExploding gradients (clip), or -inf row in a fully-masked softmax
The order to check things (1) Can the model overfit 16 examples to near-zero loss? If not, stop and fix the plumbing. (2) Does greedy decoding of a training example reproduce it? If not, your inference path differs from your training path. (3) Only then look at the validation metric.
