Goal: by Day 52 you understand how meaning gets encoded as vectors, you can train and evaluate embeddings, and you have built a working semantic search engine.

Days 37–52

Day 37

Lexical Semantics & WordNet

20 min

Meaning as a hand-built graph. Thirty years of human labour, and it still tells you things embeddings cannot.

The structure

The unit is not the word but the synset: a set of synonyms sharing one sense, with a gloss and examples. bank.n.01 ("sloping land beside water") and bank.n.02 ("a financial institution") are different nodes. English WordNet has ~117k synsets over ~155k words.

RelationMeaningExample
hypernymis-a (up)dog → canine → carnivore → mammal → animal
hyponymis-a (down)dog → poodle, beagle
meronympart-ofwheel is a meronym of car
holonymhas-partcar is a holonym of wheel
antonymopposite (word-level, not synset)hot / cold
entailmentverb implicationsnore entails sleep

Similarity measures over the hierarchy

$$\mathrm{path}(c_1,c_2)=\frac{1}{1+\mathrm{len}(c_1,c_2)} \qquad \mathrm{lch}=-\log\frac{\mathrm{len}(c_1,c_2)}{2D} \qquad \mathrm{wup}=\frac{2\,\mathrm{depth}(\mathrm{LCS})}{\mathrm{depth}(c_1)+\mathrm{depth}(c_2)}$$

All three treat every edge as equally long, which is wrong — the step from entity to physical entity spans far more meaning than poodle to miniature poodle. Information-content measures fix this by weighting nodes by corpus frequency:

$$\mathrm{IC}(c)=-\log P(c),\qquad P(c)=\frac{\sum_{w\in\mathrm{words}(c)}\mathrm{count}(w)}{N}$$
$$\mathrm{res}=\mathrm{IC}(\mathrm{LCS})\qquad \mathrm{lin}=\frac{2\,\mathrm{IC}(\mathrm{LCS})}{\mathrm{IC}(c_1)+\mathrm{IC}(c_2)}\qquad \mathrm{jcn}=\frac{1}{\mathrm{IC}(c_1)+\mathrm{IC}(c_2)-2\,\mathrm{IC}(\mathrm{LCS})}$$

LCS = least common subsumer, the deepest shared ancestor. Resnik uses only the LCS so any two dogs score identically; Lin and Jiang–Conrath normalize by how specific the inputs are, and generally correlate better with human judgements.

What WordNet is still good for

Explicit is-a chains for ontology construction; guaranteed antonym pairs (embeddings famously place hot and cold close together, because they occur in identical contexts); sense inventories for annotation; and query expansion where you need to justify each added term. What it is bad at: coverage (no doomscrolling, no transformer in the ML sense), fine sense granularity that annotators cannot agree on, verbs and adjectives generally, and languages other than English — though Open Multilingual WordNet links ~40 languages of varying quality.

Day 38

Word Sense Disambiguation

20 min

A task with a baseline so strong it embarrassed the field for twenty years.

The most-frequent-sense baseline

Always pick the first sense listed in WordNet (which is frequency-ordered from SemCor). This gets 65–78% on standard benchmarks, and until roughly 2015 most supervised systems beat it by only a few points. Any WSD paper that does not report the MFS baseline is uninterpretable. The reason it is so strong is Zipfian again: sense distributions are themselves highly skewed.

Lesk

Original Lesk: pick the sense whose dictionary gloss shares the most words with the glosses of surrounding words. Simplified Lesk: overlap the gloss with the context sentence directly — far more practical.

$$\hat{s}=\argmax_{s\in\mathrm{senses}(w)}\bigl|\,\mathrm{signature}(s)\;\cap\;\mathrm{context}(w)\,\bigr|$$

The signature is the gloss plus examples, and optionally the glosses of hypernyms and hyponyms — extending it is the single biggest accuracy lever. Even so, plain Lesk lands around 50–60%, i.e. below the MFS baseline. Its value is that it needs no training data at all.

from nltk.corpus import wordnet as wn
from nltk.corpus import stopwords
SW = set(stopwords.words("english"))

def signature(sense, expand=True):
    words = set(sense.definition().lower().split())
    for ex in sense.examples(): words |= set(ex.lower().split())
    if expand:
        for rel in list(sense.hypernyms()) + list(sense.hyponyms()):
            words |= set(rel.definition().lower().split())
    return {w.strip(".,;:'\"") for w in words} - SW

def lesk(word, sentence, pos=None):
    ctx = {w.lower() for w in sentence.split()} - SW
    senses = wn.synsets(word, pos=pos)
    if not senses: return None
    return max(senses, key=lambda s: len(signature(s) & ctx))

lesk("bank", "he sat on the bank and watched the river flow")
# Synset('bank.n.01')  -> sloping land beside a body of water

One sense per discourse

Yarowsky's observation: within a single document, a word almost always keeps one sense (~95%+ for coarse senses). This gives you a powerful bootstrapping constraint — disambiguate the easy occurrences confidently, then propagate that sense to the whole document.

Why this lesson mostly became history Contextual embeddings (Day 81) give each occurrence its own vector, so sense distinctions fall out of the representation without an explicit sense inventory. Nearest-neighbour classification over BERT vectors, with a handful of labelled examples per sense, now beats every method above by a wide margin. The task did not get solved so much as dissolved. Keep the vocabulary though: polysemy is still the reason static embeddings fail and why retrieval confuses Apple the company with the fruit.

Day 39

Distributional Semantics & Co-occurrence

22 min

Build meaning by counting neighbours. Word2vec is a compression of what you build today.

The word-context matrix

Slide a window of \(\pm L\) over the corpus; \(M_{ij}\) counts how often context word \(c_j\) appeared near target \(w_i\). The row is the word's vector.

Window size changes what "similar" means Small windows (±1–2) capture syntagmatic/functional similarity: nearest neighbours of Hogwarts become Sunnydale, Evernight — other fictional schools, same syntactic slots. Large windows (±5–10) capture topical similarity: neighbours become Dumbledore, Malfoy, half-blood. Neither is wrong; pick to match your task, and say which you used.

From counts to PPMI

Raw counts are dominated by frequency: the co-occurs with everything. PMI divides out the marginals:

$$\mathrm{PMI}(w,c)=\log_2\frac{P(w,c)}{P(w)P(c)}=\log_2\frac{\#(w,c)\cdot N}{\#(w)\cdot\#(c)}$$

Negative PMI values say "these co-occur less than chance", which is unreliably estimated from finite data (you would need enormous corpora to confirm a genuine repulsion), so clip them:

$$\mathrm{PPMI}(w,c)=\max\bigl(0,\ \mathrm{PMI}(w,c)\bigr)$$

Two well-known refinements: context distribution smoothing, raising the context marginal to \(\alpha=0.75\), which reduces PMI's bias toward rare contexts; and shifted PPMI, \(\max(0,\mathrm{PMI}-\log k)\) — which Levy & Goldberg showed is exactly what skip-gram with negative sampling implicitly factorizes.

Co-occurrence → PPMI → cosine neighbours, on your own text

Swap the target between dog, cat and car in the demo. Notice the neighbours are driven by shared contexts, never by any shared letters — that is the distributional hypothesis doing its work.

First- vs second-order similarity

First-order (syntagmatic): drink and beer co-occur, so they are associated. Second-order (paradigmatic): beer and wine rarely co-occur with each other but co-occur with the same words, so their vectors are similar. Cosine over co-occurrence rows measures second-order similarity — which is why it finds synonyms rather than collocates.

These vectors are unusable at scale \(|V|=50{,}000\) means 50,000-dimensional sparse rows: 2.5 billion cells, painful to store, and noisy in every low-count cell. The next three lessons are all different answers to "compress this matrix to 300 dense dimensions".
Exercise Build a PPMI matrix on a real corpus at window ±2 and ±10. Print the top-10 neighbours of the same five words under each. Write one sentence describing how the character of the lists differs.
Day 40

SVD, LSA & Matrix Factorization

22 min

The 1990 answer to "compress the matrix", and the mathematical backbone of half of this phase.

SVD, geometrically

$$M \;=\; U\Sigma V^\top,\qquad U\in\mathbb{R}^{m\times m},\ \Sigma\in\mathbb{R}^{m\times n},\ V\in\mathbb{R}^{n\times n}$$

Any linear map is a rotation (\(V^\top\)), then an axis-aligned scaling (\(\Sigma\)), then another rotation (\(U\)). The singular values \(\sigma_1\ge\sigma_2\ge\dots\) on \(\Sigma\)'s diagonal say how much the map stretches each direction. Keeping the top \(k\) gives the best rank-\(k\) approximation in both Frobenius and spectral norm — that is the Eckart–Young theorem, and it is why truncated SVD is the canonical dimensionality reduction.

$$M_k=U_k\Sigma_k V_k^\top \;=\; \argmin_{\mathrm{rank}(B)\le k}\|M-B\|_F,\qquad \|M-M_k\|_F^2=\sum_{i>k}\sigma_i^2$$

LSA in practice

Build a TF-IDF term-document matrix, run truncated SVD to \(k\approx100\text{–}300\), and compare documents (or queries) by cosine in the reduced space. Because related terms end up in the same latent directions, LSA partly solves the vocabulary mismatch problem: a query for car now retrieves documents about automobile even with zero literal overlap.

from sklearn.decomposition import TruncatedSVD
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import Normalizer

# TruncatedSVD works directly on sparse matrices (unlike PCA, which centres
# and would destroy sparsity). Re-normalize afterwards so cosine still works.
lsa = make_pipeline(TruncatedSVD(n_components=200, random_state=0),
                    Normalizer(copy=False))
X_lsa = lsa.fit_transform(X_tfidf)

svd = lsa[0]
print(svd.explained_variance_ratio_.sum())       # how much you kept
terms = vectorizer.get_feature_names_out()
for i, comp in enumerate(svd.components_[:5]):
    top = terms[comp.argsort()[-8:][::-1]]
    print(f"component {i}: {', '.join(top)}")

Choosing \(k\)

Plot the singular-value spectrum and look for the elbow; or plot cumulative explained variance and take 80–90%; or — best — plot downstream task performance against \(k\), which is the only criterion that actually matters. Too small and you merge unrelated topics; too large and you keep the noise you were trying to remove.

LSA's interpretability problem Components can be negative, and a negative loading has no natural reading ("this document is minus 0.4 about sport"?). Components are also orthogonal by construction, which real topics are not. NMF (Day 42) fixes both by forcing non-negativity.
Exercise Run LSA on a document collection. Print the top terms of the first 10 components. Component 0 is nearly always "general frequency" rather than a topic — check whether yours is, and explain why.
Day 41

Topic Modeling I: Latent Dirichlet Allocation

26 min

A generative story you can tell at a dinner party, and a posterior you cannot compute exactly.

The generative story

To write a corpus with \(K\) topics:

  1. For each topic \(k\): draw a distribution over words \(\varphi_k\sim\mathrm{Dir}(\beta)\).
  2. For each document \(d\): draw a distribution over topics \(\theta_d\sim\mathrm{Dir}(\alpha)\).
  3. For each word position \(i\) in \(d\): draw a topic \(z_{d,i}\sim\mathrm{Mult}(\theta_d)\), then draw the word \(w_{d,i}\sim\mathrm{Mult}(\varphi_{z_{d,i}})\).
$$P(\mathbf{w},\mathbf{z},\theta,\varphi\mid\alpha,\beta)=\prod_{k=1}^{K}P(\varphi_k\mid\beta)\prod_{d=1}^{D}P(\theta_d\mid\alpha)\prod_{i=1}^{N_d}P(z_{d,i}\mid\theta_d)\,P(w_{d,i}\mid\varphi_{z_{d,i}})$$

Inference reverses the story: given the words, recover \(z\), \(\theta\) and \(\varphi\). The denominator \(P(\mathbf{w})\) requires summing over \(K^{N}\) topic assignments, so it is intractable and you approximate.

What the Dirichlet priors control

Collapsed Gibbs sampling, intuitively

Integrate out \(\theta\) and \(\varphi\) analytically (they are Dirichlet conjugate to the multinomial), leaving only the discrete assignments \(z\) to sample. Then repeatedly: pick a word, remove its current topic from all counts, and resample

$$P(z_i=k\mid \mathbf{z}_{-i},\mathbf{w})\;\propto\;\underbrace{\frac{n^{(d)}_{k,-i}+\alpha}{n^{(d)}_{\cdot,-i}+K\alpha}}_{\text{how much doc }d\text{ likes topic }k}\;\cdot\;\underbrace{\frac{n^{(w_i)}_{k,-i}+\beta}{n^{(\cdot)}_{k,-i}+|V|\beta}}_{\text{how much topic }k\text{ likes word }w_i}$$

Two counters and a multiply. Run for a few hundred sweeps and the assignments settle. Variational inference is the alternative: posit a factorized approximate posterior and optimize its parameters — deterministic, faster, and what gensim's online LDA uses so it can stream a corpus larger than memory.

Preprocessing decides whether LDA works

The checklist that makes or breaks it Remove stop words (LDA will give you a "the of and" topic otherwise) · lemmatize · keep only nouns and adjectives if topics look mushy · add bigrams via Phrases so "machine learning" is one token · no_below=5, no_above=0.5 in Dictionary.filter_extremes · and remove documents under ~50 tokens, since LDA cannot estimate a mixture from 12 words.
from gensim.corpora import Dictionary
from gensim.models import LdaMulticore

dic = Dictionary(docs); dic.filter_extremes(no_below=5, no_above=0.5)
bow = [dic.doc2bow(d) for d in docs]

lda = LdaMulticore(bow, id2word=dic, num_topics=20,
                   passes=10, iterations=200, chunksize=2000,
                   alpha="asymmetric",   # learn per-topic priors
                   eta="auto", random_state=0)

for k, words in lda.print_topics(num_words=10):
    print(k, words)

Day 42

Topic Modeling II: NMF, Coherence & Modern Alternatives

22 min

How many topics? The two standard answers disagree with each other, and one of them is wrong.

NMF

$$X \approx WH,\qquad W\in\mathbb{R}_{\ge0}^{D\times K},\ H\in\mathbb{R}_{\ge0}^{K\times V},\qquad \min_{W,H\ge0}\|X-WH\|_F^2$$

Non-negativity forces a parts-based decomposition: because nothing can cancel, each topic must be an additive component. Practically: NMF is deterministic given a seed, much faster, works well on short texts and small corpora where LDA's estimates are unstable, and pairs naturally with TF-IDF input. LDA is a proper generative model, so it gives you a principled way to infer topics for unseen documents and to extend hierarchically.

Coherence, and why perplexity fails

Chang et al.'s 2009 result: models with better held-out perplexity produced topics humans found less interpretable. Perplexity measures how well you predict held-out words; interpretability is a different quantity. So use coherence.

$$C_{\mathrm{UMass}}=\frac{2}{N(N-1)}\sum_{i<j}\log\frac{D(w_i,w_j)+1}{D(w_j)}$$

UMass uses document co-occurrence within the training corpus (intrinsic, fast, range roughly \(-14\) to \(0\), higher is better). \(C_v\) is the one to report: it uses sliding-window NPMI over an external reference corpus, builds context vectors for the top words, and averages their cosine similarity. Range 0–1; below ~0.4 is junk, above ~0.65 is usually good.

from gensim.models import CoherenceModel
scores = {}
for k in [5, 10, 15, 20, 30, 40, 60]:
    m = LdaMulticore(bow, id2word=dic, num_topics=k, passes=8, random_state=0)
    scores[k] = CoherenceModel(model=m, texts=docs, dictionary=dic,
                               coherence="c_v").get_coherence()
    print(k, round(scores[k], 4))
Do not just take the argmax The \(C_v\) curve is usually noisy with several local peaks. Take the smallest \(K\) near the top of the curve (parsimony), then read the topics. A defensible topic count is one you can justify to a domain expert, not one an argmax produced.

Visualization

pyLDAvis gives an intertopic distance map (topics projected by Jensen-Shannon divergence into 2D via MDS) plus a relevance slider:

$$r(w,k\mid\lambda)=\lambda\log P(w\mid k)+(1-\lambda)\log\frac{P(w\mid k)}{P(w)}$$

At \(\lambda=1\) you see the most probable words (generic); at \(\lambda=0\) the most distinctive words (specific, sometimes rare). \(\lambda\approx0.6\) is the usual sweet spot for labelling.

The embedding-era successors

BERTopic
Embed documents with a sentence transformer → reduce with UMAP → cluster with HDBSCAN → describe each cluster with class-based TF-IDF (c-TF-IDF). Handles short text well, needs no \(K\) up front (HDBSCAN finds it), and produces an explicit outlier cluster. Downside: it is a clustering method, so each document gets one topic, not a mixture.
Top2Vec
Jointly embeds documents and words, finds dense regions, and takes the nearest word vectors as topic labels.
Dynamic / hierarchical
DTM chains topic-word distributions across time slices so you can watch a topic drift; hLDA infers a topic tree rather than a flat set.

Day 43

Word2Vec: CBOW and Skip-gram

26 min

2013. Stop counting, start predicting — and the field changed direction.

The objectives

$$\mathcal{L}_{\text{SG}}=-\frac{1}{T}\sum_{t=1}^{T}\sum_{\substack{-c\le j\le c\\ j\ne0}}\log P(w_{t+j}\mid w_t),\qquad P(o\mid c)=\frac{\exp(\mathbf{u}_o^\top\mathbf{v}_c)}{\sum_{w\in V}\exp(\mathbf{u}_w^\top\mathbf{v}_c)}$$

\(\mathbf{v}\) is the input (row of \(W\)) and \(\mathbf{u}\) the output (column of \(W'\)) embedding. The gradient with respect to \(\mathbf{v}_c\) is again observed minus expected:

$$\frac{\partial\mathcal{L}}{\partial\mathbf{v}_c}=-\mathbf{u}_o+\sum_{w\in V}P(w\mid c)\,\mathbf{u}_w$$

Which is exactly why the plain softmax is unusable: that sum runs over the whole vocabulary at every single training step.

Dynamic window Word2vec samples the actual window uniformly from \(\{1..c\}\) per token, which weights nearer words more heavily without any explicit weighting term. It is a one-line trick most reimplementations forget.

The analogy arithmetic, and the honest caveats

$$\mathbf{v}_{\text{king}}-\mathbf{v}_{\text{man}}+\mathbf{v}_{\text{woman}}\;\approx\;\mathbf{v}_{\text{queen}}$$

Real, but oversold. Three things the headline hides: (1) the standard evaluation excludes the three input words from the candidate set — without that exclusion the top answer is usually king itself; (2) 3CosAdd is often beaten by 3CosMul, \(\argmax_b \frac{\cos(b,b^*)\cos(b,a)}{\cos(b,a^*)+\varepsilon}\); (3) accuracy is highly uneven — capital-of and currency relations score above 80%, while morphological and "is-a" relations score far lower. Report the breakdown, not the average.

Day 44

Word2Vec Training Tricks

24 min

The paper's real contribution is not the architecture. It is four engineering decisions that made it tractable.

Negative sampling

Replace "predict the right word out of 100,000" with "distinguish the right word from \(k\) random ones" — a set of \(k+1\) binary logistic regressions instead of one giant softmax.

$$\mathcal{L}_{\text{NEG}}=-\log\sigma(\mathbf{u}_o^\top\mathbf{v}_c)-\sum_{i=1}^{k}\E_{w_i\sim P_n}\bigl[\log\sigma(-\mathbf{u}_{w_i}^\top\mathbf{v}_c)\bigr]$$

Cost per step drops from \(O(|V|d)\) to \(O((k+1)d)\) — for \(|V|=10^5\), \(k=5\), that is a ~16,000× reduction. This comes from noise-contrastive estimation, which shows that a classifier separating data from a known noise distribution recovers the data density; word2vec's version drops the normalizing terms NCE keeps, so it is an approximation rather than a consistent estimator — but it works.

The 0.75 exponent

$$P_n(w)=\frac{U(w)^{3/4}}{\sum_{w'}U(w')^{3/4}}$$

Sampling negatives from the raw unigram distribution picks the almost every time — uninformative, because the co-occurs with everything so it is a trivially easy negative. Sampling uniformly picks garbage hapax words that are trivially easy in the other direction. The \(3/4\) power flattens the distribution: it raises rare-word probability and lowers frequent-word probability, giving negatives that are hard enough to be informative. Concretely, a word with \(U=0.9\) drops to ~0.92 of its share while one with \(U=0.01\) rises to ~3× its share. The exponent was found empirically and has stuck for a decade.

Frequent-word subsampling

$$P_{\text{discard}}(w)=1-\sqrt{\frac{t}{f(w)}},\qquad t\approx10^{-5}$$

Words with frequency below \(t\) are always kept; the at \(f=0.05\) is discarded with probability \(1-\sqrt{10^{-5}/0.05}\approx98.6\%\). This gives two wins at once: training gets ~2–10× faster, and quality improves, because deleting tokens effectively widens the window across the deleted positions so real content words become neighbours.

Hierarchical softmax

The alternative to negative sampling. Build a Huffman tree over the vocabulary (frequent words get short codes); represent \(P(w\mid c)\) as the product of binary decisions along the root-to-leaf path:

$$P(w\mid c)=\prod_{j=1}^{L(w)-1}\sigma\Bigl(\llbracket n_{j+1}=\mathrm{child}(n_j)\rrbracket\cdot \mathbf{u}_{n_j}^\top\mathbf{v}_c\Bigr)$$

Cost \(O(d\log|V|)\), and it is a proper normalized distribution (negative sampling is not). Rule of thumb: hierarchical softmax is better for rare words and when you need real probabilities; negative sampling is better for frequent words and is faster in practice. Almost everyone uses negative sampling.

from gensim.models import Word2Vec
from gensim.models.callbacks import CallbackAny2Vec

class LossLogger(CallbackAny2Vec):
    def __init__(self): self.epoch, self.prev = 0, 0
    def on_epoch_end(self, model):
        loss = model.get_latest_training_loss()      # cumulative, not per-epoch
        print(f"epoch {self.epoch:3d}  loss {loss - self.prev:12.1f}")
        self.prev, self.epoch = loss, self.epoch + 1

w2v = Word2Vec(
    sentences, vector_size=300, window=5, min_count=5,
    sg=1,            # 1 = skip-gram, 0 = CBOW
    negative=10,     # k
    ns_exponent=0.75,
    sample=1e-5,     # subsampling threshold t
    epochs=15, workers=8, seed=42,
    compute_loss=True, callbacks=[LossLogger()],
)
w2v.wv.most_similar("embedding", topn=10)
gensim's loss counter is cumulative and overflows get_latest_training_loss() returns a running total in a float32 that saturates on large corpora, so the curve flattens artificially. Diff it per epoch as above, and treat it as a rough signal only — the real check is nearest-neighbour quality on words you know.

Day 45

GloVe

20 min

Stanford's answer: go back to the co-occurrence matrix, but fit it with a proper objective.

The motivating observation

Absolute co-occurrence probabilities are noisy; ratios are informative. Take probe words against ice and steam:

\(P(k\mid\cdot)\)k = solidk = gask = waterk = fashion
ice1.9e-46.6e-53.0e-31.7e-5
steam2.2e-57.8e-42.2e-31.8e-5
ratio8.90.0851.360.96

The ratio is large for words related to ice only, small for steam only, and ≈1 for words related to both or to neither. So the ratio, not the probability, is what encodes meaning — and it is the quantity the model should reproduce.

The objective

Requiring \(\mathbf{w}_i^\top\tilde{\mathbf{w}}_k - \mathbf{w}_j^\top\tilde{\mathbf{w}}_k = \log\frac{P_{ik}}{P_{jk}}\) for all \(i,j,k\) reduces to \(\mathbf{w}_i^\top\tilde{\mathbf{w}}_k + b_i + \tilde{b}_k = \log X_{ik}\), giving a weighted least-squares problem:

$$J=\sum_{i,j=1}^{|V|}f(X_{ij})\Bigl(\mathbf{w}_i^\top\tilde{\mathbf{w}}_j+b_i+\tilde{b}_j-\log X_{ij}\Bigr)^2$$
$$f(x)=\begin{cases}(x/x_{\max})^{\alpha} & x

The weighting function does three jobs: \(f(0)=0\) so zero cells are skipped entirely (the sum is over nonzeros only — this is what makes it tractable), rare co-occurrences are down-weighted because their \(\log X\) estimates are noisy, and the cap stops the-like pairs from dominating. Note \(\alpha=0.75\) again, empirically, for the same flattening reason as Day 44.

Count-based vs prediction-based: the distinction dissolved

Levy & Goldberg, 2014 Skip-gram with negative sampling is implicitly factorizing a shifted PPMI matrix: its optimum satisfies \(\mathbf{u}_w^\top\mathbf{v}_c = \mathrm{PMI}(w,c)-\log k\). So "predict-based" word2vec and "count-based" GloVe/PPMI-SVD are solving closely related problems with different losses and different weightings. The follow-up finding — that most of the reported quality gap came from hyperparameters (dynamic windows, subsampling, context distribution smoothing, negative sampling count) rather than from the algorithms — is one of the more useful results in the field. Transfer the tricks and the methods converge.

Using pretrained GloVe

import gensim.downloader as api
glove = api.load("glove-wiki-gigaword-300")     # 400k vocab, 300d, ~1 GB

glove.most_similar(positive=["king", "woman"], negative=["man"], topn=5)
glove.most_similar_cosmul(positive=["king", "woman"], negative=["man"])  # 3CosMul
glove.doesnt_match("breakfast cereal lunch dinner".split())
glove.evaluate_word_pairs(api.load("wordsim353"))    # (pearson, spearman, oov%)

Match the pretraining domain to your data — Twitter vectors beat Wikipedia vectors on social media by a wide margin even at a quarter of the dimensionality.

Day 46

FastText & Subword Embeddings

20 min

Words are made of pieces. Once you model the pieces, out-of-vocabulary stops being a category.

Character n-gram decomposition

Wrap the word in boundary markers and take all character n-grams for \(n\in[3,6]\). For <where>: <wh, whe, her, ere, re> and longer, plus the whole word <where> as its own unit.

$$\mathbf{v}_w=\sum_{g\in\mathcal{G}_w}\mathbf{z}_g,\qquad s(w,c)=\mathbf{v}_w^\top\mathbf{u}_c=\sum_{g\in\mathcal{G}_w}\mathbf{z}_g^\top\mathbf{u}_c$$

Everything else — skip-gram objective, negative sampling, subsampling — is unchanged. Only the input representation differs. Note that the boundary markers matter: <her> (the word) and her (inside where) are different n-grams, so the model does not confuse them.

What this buys

  • OOV disappears. A never-seen word still has n-grams, so it still gets a vector. Misspellings land near their correct forms; new product names land near similar names.
  • Morphology is free. walk / walked / walking / walker share most of their n-grams, so their vectors are related without any stemming step. This is why fastText's advantage over word2vec is largest in Turkish, Finnish, Czech and Arabic and smallest in English.
  • Rare words improve. A word seen 3 times borrows statistical strength from every other word sharing its n-grams.

The bucket tradeoff

You cannot store a vector for every possible n-gram, so fastText hashes them into bucket slots (default 2,000,000). Collisions mean unrelated n-grams share a vector. More buckets = less collision = more memory. A 300-dim model with 2M buckets is ~2.4 GB in float32; model.quantize() with product quantization gets it under 100 MB at a small accuracy cost.

Supervised mode: the fast baseline that keeps winning

import fasttext
# training file format: __label__positive this movie was wonderful
model = fasttext.train_supervised(
    "train.txt", lr=0.5, epoch=25, wordNgrams=2,
    dim=100, loss="softmax",       # or "ova" for multi-label, "hs" for many classes
    bucket=200_000, minCount=2, thread=8)

print(model.test("valid.txt"))          # (n, precision@1, recall@1)
model.predict("a stunning achievement", k=3)
model.quantize(input="train.txt", retrain=True, qnorm=True)   # ~10x smaller

Architecture: average the embeddings of all words and word n-grams in the document, then a single linear layer + softmax. It is a linear bag-of-embeddings classifier — essentially the Day 58 deep averaging network with no hidden layer. It trains on a million documents in seconds on a laptop CPU and lands within a point or two of far heavier models on topic classification.

Use it as your speed floor Before reaching for a transformer, run fastText supervised. If it gets 0.91 F1 in 8 seconds and your fine-tuned BERT gets 0.93 in 40 GPU-minutes, you now have a real cost/benefit conversation instead of an assumption.

Pretrained vectors exist for 157 languages (trained on Common Crawl + Wikipedia), plus the aligned MUSE vectors that put many languages in a shared space for zero-shot cross-lingual transfer.

Evaluating Word Embeddings

20 min

The benchmark that ranks your embeddings first is usually not the one that predicts your task.

Intrinsic: word similarity

Humans rate word pairs 0–10; you score Spearman rank correlation between their ratings and your cosines.

DatasetPairsMeasures
WordSim-353353Relatedness — mixes similarity and association. coffee/cup scores high.
SimLex-999999Similarity only, explicitly instructed. coffee/cup scores low; coffee/tea high.
MEN3,000Relatedness, crowdsourced, larger.
SimVerb-35003,500Verbs only — the hardest, and the most neglected.

Distributional models score well on WordSim and poorly on SimLex, because context-sharing captures relatedness far more naturally than strict similarity. Antonyms are the extreme case: hot and cold have near-identical contexts and near-identical vectors, which SimLex correctly punishes.

Intrinsic: analogies, and their flaws

Google's set has 19,544 questions in 14 relation types. Known problems: the three input words are excluded from the answer set, which does a lot of hidden work; performance is dominated by a few relation types; many questions are solvable from word frequency alone; and the whole framing assumes relations are single consistent offset vectors, which they are not (the capital-of offset differs systematically between large and small countries).

Extrinsic

Freeze the embeddings, feed them to a fixed simple classifier (logistic regression on averaged vectors, or a small BiLSTM), and measure the downstream metric on NER, sentiment, chunking. This is the number that matters, and it is the number that most often disagrees with the intrinsic ranking. Report both, and if they conflict, trust extrinsic.

Day 48

Bias, Fairness & What Embeddings Encode

20 min

The vectors learned what the corpus contained. That includes the parts nobody wanted.

How bias gets in

The distributional hypothesis is neutral machinery: it faithfully encodes whatever co-occurrence structure exists. If historical text places nurse near she and engineer near he, the geometry records that. Nothing malfunctioned — the model did exactly what it was asked to.

WEAT

Adapted from the Implicit Association Test. Two target sets \(X,Y\) (e.g. maths terms, arts terms) and two attribute sets \(A,B\) (male names, female names):

$$s(w,A,B)=\mathrm{mean}_{a\in A}\cos(\mathbf{w},\mathbf{a})-\mathrm{mean}_{b\in B}\cos(\mathbf{w},\mathbf{b})$$
$$d=\frac{\mathrm{mean}_{x\in X}s(x,A,B)-\mathrm{mean}_{y\in Y}s(y,A,B)}{\mathrm{sd}_{w\in X\cup Y}\,s(w,A,B)}$$

\(d\) is a Cohen's-\(d\) effect size: 0.2 small, 0.5 medium, 0.8 large. Caliskan et al. (2017) reproduced every documented human IAT bias in off-the-shelf embeddings, including effect sizes above 1.0 for gender–career and race–pleasantness associations. Significance comes from a permutation test over the partition of \(X\cup Y\).

Debiasing, and why it mostly does not work

Hard debiasing (Bolukbasi et al.): find a gender direction \(\mathbf{g}\) from the PCA of difference vectors of definitional pairs (he–she, man–woman, …), then project it out of every word that should be gender-neutral, and equalize the definitional pairs about the remaining subspace.

$$\mathbf{w}' = \frac{\mathbf{w}-(\mathbf{w}\cdot\hat{\mathbf{g}})\hat{\mathbf{g}}}{\|\mathbf{w}-(\mathbf{w}\cdot\hat{\mathbf{g}})\hat{\mathbf{g}}\|}$$
Gonen & Goldberg, 2019: "Lipstick on a Pig" After hard debiasing, WEAT scores drop and the projection onto \(\mathbf{g}\) is zero — yet the biased words still cluster together. Train a classifier on the debiased vectors to predict a word's original gender bias and it succeeds at over 90%. The information was redistributed, not removed. The lesson generalizes: a metric going to zero is evidence about the metric, not necessarily about the system.

What does help: fixing the training data (reweighting, counterfactual data augmentation that swaps gendered terms), constraining the objective during training rather than patching afterwards, and — most reliably — measuring bias at the task level where the harm actually occurs.

Where the harm lands

Hiring
Résumé ranking with embedding similarity to a job description imports the association directly into who gets an interview.
Search
Query expansion via nearest neighbours can inject stereotyped terms into results the user never asked for.
Moderation
Toxicity classifiers over-flag African-American English and reclaimed identity terms — a documented, repeatedly reproduced result.
Translation
Gender-neutral pronouns in Turkish or Finnish resolve to stereotyped genders in English output.
Exercise Run WEAT on pretrained vectors with the original word sets and report effect sizes with permutation p-values. Apply hard debiasing. Re-run WEAT (it drops). Then train a logistic classifier on the debiased vectors to predict original bias — and report that it still works. Both numbers belong in your write-up.
Day 49

Sentence & Document Embeddings (Pre-Transformer)

20 min

Word vectors are solved. Sentence vectors are where the simple baseline refuses to die.

Averaging, and why it is embarrassingly strong

$$\mathbf{s}=\frac{1}{|s|}\sum_{w\in s}\mathbf{v}_w \qquad\qquad \mathbf{s}_{\text{tfidf}}=\frac{\sum_{w\in s}\idf_w\,\mathbf{v}_w}{\sum_{w\in s}\idf_w}$$

Order is destroyed, so the dog bit the man and the man bit the dog are identical. Yet plain averaging beat several purpose-built neural sentence encoders on the standard STS benchmarks for years. IDF weighting typically adds 2–4 Spearman points for free.

SIF: the two-line upgrade

Arora et al.'s "simple but tough-to-beat baseline":

$$\mathbf{s}=\frac{1}{|s|}\sum_{w\in s}\frac{a}{a+p(w)}\mathbf{v}_w,\qquad a\approx10^{-3}$$

then compute the first principal component \(\mathbf{u}\) across all sentence vectors and remove it: \(\mathbf{s}\leftarrow\mathbf{s}-\mathbf{u}\mathbf{u}^\top\mathbf{s}\). The weighting is a smooth-inverse-frequency version of IDF derived from a generative model; the common-component removal deletes the "syntax and general frequency" direction that every sentence shares and that swamps cosine similarity. Both steps matter; the second matters more. uSIF removes the need to tune \(a\) and subtracts several components with decaying weights.

Doc2Vec

PV-DM
Add a paragraph vector to the context in CBOW; it acts as a memory of what the document is about. Order-aware within the window.
PV-DBOW
Use the paragraph vector alone to predict randomly sampled words from the document. Simpler, faster, no word vectors needed, and usually the better performer.
Inference is stochastic A vector for an unseen document is obtained by gradient descent with the model weights frozen, so calling infer_vector twice on the same text gives different answers. Fix the seed, raise epochs to 50+, and average multiple runs if you need stability. Reproducibility problems with Doc2Vec are almost always this.

Skip-Thought

An encoder–decoder trained to reconstruct the previous and next sentence from the current one — the sentence-level analogue of skip-gram. Conceptually elegant, extremely slow to train, and superseded by InferSent (supervised on NLI data) and then by Sentence-BERT (Day 87). Its lasting contribution is the idea that the surrounding sentences are free supervision for sentence meaning, which reappears in every modern contrastive objective.

The order-free ceiling Any bag-of-embeddings method cannot distinguish sentences that differ only in structure: negation scope, argument order, quantifier scope, conditionals. On STS this costs a few points because most benchmark pairs differ lexically. On NLI it is fatal, which is precisely why NLI became the training signal for good sentence encoders.
Exercise Benchmark mean, IDF-weighted mean, SIF and Doc2Vec on STS-B with Spearman correlation. Rank them. Then hand-pick five pairs where the winner fails and check whether order is the cause.
Day 50

Sentiment Analysis Deep Dive

24 min

The task everyone thinks is easy, with a human agreement ceiling around 80% on hard data.

Three different tasks wearing one name

Polarity
positive / negative / neutral, or a 1–5 star rating. Neutral is the hard class — it absorbs both "genuinely balanced" and "not about the target at all".
Emotion
Multi-label over a taxonomy: Ekman's six, Plutchik's eight, or GoEmotions' 27. Anger and disgust are chronically confused; annotator agreement is much lower than for polarity.
Subjectivity
Opinion vs fact. A useful filter stage: run it first and only send subjective sentences to the polarity model.

Lexicons

VADER is rule-based and tuned for social media: it has valence scores, plus explicit handling of intensity boosters (very ×1.29), all-caps emphasis, exclamation marks (up to +0.292 for three), degree modifiers, contrastive but (weights the clause after it ~1.5× more), emoji and common slang. It needs no training data and it is a serious baseline on tweets. SentiWordNet assigns positivity/negativity/objectivity to WordNet synsets, so it needs WSD to use properly. NRC Emotion Lexicon maps ~14k words to eight emotions plus two polarities, in 100+ languages via translation.

$$\text{compound}=\frac{\sum_i v_i}{\sqrt{\left(\sum_i v_i\right)^2+\alpha}},\qquad \alpha=15$$

That normalization is what squashes the raw valence sum into \([-1,1]\), with longer texts saturating rather than growing without bound.

Negation and intensifiers

The default fix is a negation window: flip or dampen the polarity of the next \(n\) tokens (VADER uses ~3) after a negator. Crude but effective. The correct fix is syntactic scope from a dependency parse — not attaches to a head, and the scope is that head's subtree. Compare: "not only good but great" (no flip), "I don't think it's good" (flip, across a clause boundary), "nothing about this is good" (flip, negator is the subject).

Aspect-based sentiment (ABSA)

"The food was incredible but the service was slow and the prices are fair." One sentence, three aspects, three polarities. Sub-tasks: aspect-term extraction, aspect-category detection, aspect-polarity classification, and opinion-term extraction. A serviceable pipeline without any labelled data:

import spacy
from vaderSentiment.vaderSentiment import SentimentIntensityAnalyzer
nlp, sia = spacy.load("en_core_web_sm"), SentimentIntensityAnalyzer()

def aspects(text):
    for sent in nlp(text).sents:
        for chunk in sent.noun_chunks:              # candidate aspects
            head = chunk.root
            opinions = []
            # adjectival modifiers:  "slow service"
            opinions += [c for c in head.children if c.dep_ == "amod"]
            # predicate adjectives:  "the service was slow"
            if head.dep_ in ("nsubj", "nsubjpass"):
                opinions += [c for c in head.head.children if c.dep_ == "acomp"]
                if head.head.pos_ == "ADJ": opinions.append(head.head)
            if not opinions: continue
            neg  = any(c.dep_ == "neg" for o in opinions for c in o.head.children)
            span = " ".join(o.text for o in opinions)
            score = sia.polarity_scores(span)["compound"] * (-1 if neg else 1)
            yield chunk.text, span, round(score, 3)

The hard parts

Domain transfer collapses A model trained on movie reviews and tested on electronics reviews loses 10–20 points. Unpredictable is negative for a laptop, positive for a thriller. Small is positive for a phone, negative for a hotel room. Sentiment is not a property of words; it is a property of words applied to a domain.

Sarcasm and irony ("Great, another meeting that could have been an email") need context the sentence does not contain — author history, conversation thread, community norms. Reported sarcasm-detection scores above ~75 F1 are usually benefiting from a self-labelled #sarcasm hashtag that is itself the signal. Human agreement on fine-grained sentiment is roughly 79–86%, so a model reporting 95% on a hard dataset is measuring an annotation artifact, not the task.

Exercise Build the ABSA extractor above on real product reviews. Hand-check 50 outputs. Bucket the errors: wrong aspect, wrong opinion attachment, missed negation, wrong polarity. The proportions tell you where to spend your next hour.
Day 51

Information Retrieval Foundations

24 min

BM25 is 30 years old, has two tunable constants, and still beats most neural retrievers out of the box.

The inverted index

Map each term to a postings list of the documents containing it, with positions and frequencies. Intersecting two sorted postings lists is linear in their combined length, so a two-term AND query costs \(O(|p_1|+|p_2|)\), not \(O(|D|)\). Compression (delta-encode the doc IDs, then variable-byte or PForDelta) gets a web-scale index down to ~10–20% of the raw text size.

From TF-IDF ranking to BM25

Two problems with plain TF-IDF ranking: term frequency grows without bound (a document repeating jaguar 50 times is not 50× more relevant), and long documents win by having more of everything. BM25 fixes both explicitly.

$$\mathrm{BM25}(q,d)=\sum_{t\in q}\idf(t)\cdot\frac{f_{t,d}\,(k_1+1)}{f_{t,d}+k_1\left(1-b+b\dfrac{|d|}{\mathrm{avgdl}}\right)}$$
$$\idf(t)=\ln\left(\frac{N-\mathrm{df}_t+0.5}{\mathrm{df}_t+0.5}+1\right)$$
\(k_1\) — term-frequency saturation (typ. 1.2–2.0)
As \(f\to\infty\) the tf component tends to \(k_1+1\), a hard ceiling. Small \(k_1\) saturates almost immediately (near-binary); large \(k_1\) approaches raw tf.
\(b\) — length normalization (typ. 0.75)
\(b=0\) ignores document length entirely; \(b=1\) fully normalizes by \(|d|/\mathrm{avgdl}\). Use lower \(b\) when long documents are genuinely more informative (e.g. legal), higher when length is just verbosity.
Inverted index + BM25 — tune k₁ and b and watch the ranking move

Set b to 0 and the long document 4 climbs; set it to 1 and it falls. Set k₁ to 0 and document 2 — which repeats fox and quick — stops benefiting from the repetition at all. Those two sliders are the whole model.

Query expansion

Rocchio relevance feedback moves the query vector toward relevant documents and away from non-relevant ones:

$$\mathbf{q}_m=\alpha\mathbf{q}_0+\frac{\beta}{|D_r|}\sum_{d\in D_r}\mathbf{d}-\frac{\gamma}{|D_{nr}|}\sum_{d\in D_{nr}}\mathbf{d}$$

Pseudo-relevance feedback assumes the top-\(k\) results are relevant and expands from them with no user input — typically +2–5% on recall, and it fails badly when the initial results are off-topic (query drift). RM3 is the standard language-model formulation.

Ranking metrics

$$\mathrm{AP}=\frac{1}{R}\sum_{k=1}^{n}P@k\cdot \mathrm{rel}(k),\qquad \mathrm{MRR}=\frac{1}{|Q|}\sum_{i}\frac{1}{\mathrm{rank}_i}$$
$$\mathrm{DCG}@k=\sum_{i=1}^{k}\frac{2^{\mathrm{rel}_i}-1}{\log_2(i+1)},\qquad \mathrm{NDCG}@k=\frac{\mathrm{DCG}@k}{\mathrm{IDCG}@k}$$

Use MRR when there is one right answer (QA, known-item search); MAP for binary relevance with many relevant docs; NDCG when relevance is graded — it is the only one of the three that distinguishes "perfect" from "merely relevant".

Test collections TREC (classic, small, deeply judged) · MS MARCO (530k real Bing queries, sparse judgements — usually one relevant passage per query, which inflates MRR) · BEIR (18 datasets, zero-shot) — BEIR is the one that exposed how badly dense retrievers generalize out of domain, with BM25 beating many of them on unseen corpora.
Exercise Build an inverted index from scratch, implement BM25, and evaluate NDCG@10 on a labelled query set. Then grid-search \(k_1\) and \(b\) — you will typically gain 3–6% over the defaults, for free.

🛠 Project 3: Semantic Search Engine

30 min

Portfolio piece three. Hybrid retrieval — and a keyword baseline you are honest about.

Reciprocal rank fusion

$$\mathrm{RRF}(d)=\sum_{r\in R}\frac{1}{k+\mathrm{rank}_r(d)},\qquad k=60$$

It uses only ranks, so incomparable score scales stop being a problem. The constant \(k=60\) damps the influence of the very top positions so one retriever cannot dominate. It is nearly parameter-free and reliably within a point or two of a carefully tuned weighted sum.

Chunking, which decides more than the model does

StrategyGoodBad
Fixed 512 charstrivial, uniformsplits mid-sentence, mid-table
Sentence groups (3–5)coherent unitsvariable length, may lack context
Recursive (¶ → sentence → word)respects structure — the defaultstill needs a size target
Parent-documentembed small, return largetwo stores to keep in sync

Overlap of 10–20% keeps a sentence straddling a boundary retrievable from both sides. Prepend the document title and section heading to every chunk before embedding — a two-line change that reliably buys several points of recall, because it restores the context the chunk lost.

import numpy as np, faiss
from rank_bm25 import BM25Okapi
from sentence_transformers import SentenceTransformer

class Hybrid:
    def __init__(self, chunks):
        self.chunks = chunks
        self.bm25   = BM25Okapi([c.lower().split() for c in chunks])
        self.enc    = SentenceTransformer("all-MiniLM-L6-v2")
        E = self.enc.encode(chunks, normalize_embeddings=True,
                            batch_size=64, show_progress_bar=True)
        self.index = faiss.IndexFlatIP(E.shape[1])   # inner product == cosine
        self.index.add(E.astype("float32"))

    def search(self, q, k=10, pool=50, rrf_k=60):
        lex = np.argsort(self.bm25.get_scores(q.lower().split()))[::-1][:pool]
        qv  = self.enc.encode([q], normalize_embeddings=True).astype("float32")
        _, den = self.index.search(qv, pool)
        fused = {}
        for rank, i in enumerate(lex):     fused[i] = fused.get(i, 0) + 1/(rrf_k+rank+1)
        for rank, i in enumerate(den[0]):  fused[i] = fused.get(i, 0) + 1/(rrf_k+rank+1)
        top = sorted(fused, key=fused.get, reverse=True)[:k]
        return [(self.chunks[i], round(fused[i], 5)) for i in top]

Evaluate, or you have built a demo

If the hybrid does not beat BM25 alone, say so in the README — that result is common on small technical corpora and reporting it is worth more than hiding it.
