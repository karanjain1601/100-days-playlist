Days 1–16

Day 01

What NLP Actually Is, and Why It's Hard

14 min

The roadmap video. No code — set the map, name the enemy.

NLP vs NLU vs NLG

NLP
The umbrella: any computational handling of human language, including tasks with no "understanding" at all (tokenizing, spell-check, search).
NLU
Mapping surface text to structure or meaning: intent, entities, roles, logical form, entailment.
NLG
Producing text from an internal state: templates, seq2seq, or an autoregressive LM.

Modern LLMs collapse the distinction — one decoder does all three — but the split still tells you where a failure lives. If the model answers a question about a document it retrieved wrongly, that is retrieval + NLU. If it answers fluently but falsely, that is NLG outrunning NLU.

The four levels of ambiguity

LevelExampleThe two readings
LexicalI went to the bank.financial institution / river edge
SyntacticI saw the man with the telescope.PP attaches to saw (instrument) or to man (modifier)
SemanticEvery student read a book.one shared book / one book each (quantifier scope)
PragmaticCan you pass the salt?question about ability / indirect request

Ambiguity is not an edge case; it is the default state of language, resolved by listeners so cheaply that it feels absent. The whole field is machinery for choosing among readings.

The task map (~25 core tasks)

Sequence in → label out: classification, sentiment, NLI, topic. Sequence in → sequence of labels out: POS, NER, chunking, SRL. Sequence in → structure out: constituency parsing, dependency parsing, coreference, knowledge-graph extraction. Sequence in → sequence out: translation, summarization, QA, dialogue, style transfer. Query + corpus → ranked list: retrieval, RAG. Text → vector: embeddings, clustering, semantic search.

Why "understanding" is contested Searle's Chinese Room and Bender & Koller's "octopus" argument both claim form alone cannot yield meaning without grounding. The counter-position: meaning is use, and a system that reliably behaves as if it understands has whatever understanding the word usefully picks out. You do not need to settle this to build systems — but you do need it to write honest evaluation.

Day 03

Linguistics Crash Course I: Words & Morphology

20 min

What is a "word"? The question has four answers and your code needs all four.

Type, token, lemma, wordform

In the cat sat on the mat: 6 tokens, 5 types (the occurs twice). Wordform is the surface string (running); lemma is the dictionary head (run). Type/token ratio (TTR) is a crude lexical-diversity measure, and it is length-dependent — always compare TTR at matched token counts, or use a normalized variant like MTLD.

Open vs closed classes

Open (nouns, verbs, adjectives, adverbs) accept new members constantly — this is where OOV words come from. Closed (determiners, prepositions, pronouns, conjunctions, auxiliaries) are a fixed few hundred items and carry most of the syntax. Stop-word lists are essentially "delete the closed classes", which is why they destroy negation and phrase queries.

Why English flatters your tokenizer

TypeLanguageOne "word"
AnalyticEnglishI will not be able to come — 7 tokens
AgglutinativeTurkishgelemeyeceğim — one token, same meaning
AgglutinativeFinnish~2,000 inflected forms per noun
TemplaticArabicroot k-t-b + vowel template → kataba, kitāb, maktab…

Whitespace tokenization plus a word-level vocabulary is catastrophic for the bottom three rows: your OOV rate explodes and your embedding table cannot generalize. This is the direct motivation for subword tokenization on Day 78 and for fastText on Day 46.

Day 04

Linguistics Crash Course II: Syntax

20 min

Two competing pictures of sentence structure. Modern NLP mostly picked one.

Constituency vs dependency

Constituency groups words into nested phrases (NP, VP, PP) with non-terminal nodes; it comes from CFGs and the Penn Treebank. Dependency draws labelled directed arcs from a head word to its dependents; every node is a real token, no invented non-terminals. Dependency won practically because arcs map straight onto relation extraction, it handles free word order better, and Universal Dependencies gave one annotation scheme across 100+ languages.

PP-attachment: the canonical ambiguity

I saw the man with the telescope. The PP with the telescope can attach to the verb (I used a telescope) or to the object NP (the man had one). The number of parses for n stacked PPs follows the Catalan numbers — 2 PPs give 2 parses, 5 give 42, 8 give 1430. Structural ambiguity is combinatorial, which is why exhaustive parsing needs dynamic programming (Day 34).

Garden paths

The horse raced past the barn fell. Readers commit to raced as the main verb, then must reanalyse it as a reduced relative clause. Incremental parsers fail the same way; a transformer, which sees the whole sentence at once, does not have this particular failure mode — it has others.

Treebanks Penn Treebank (1993, WSJ text) — constituency, 45-tag POS set, licence-restricted, the benchmark for two decades. Universal Dependencies — dependency, 17 coarse POS tags, ~37 relations, 250+ treebanks over 150 languages, permissively licensed. Use UD unless you have a specific reason not to.

Day 05

Linguistics Crash Course III: Semantics & Pragmatics

18 min

Where meaning stops being a function of the parts — and where prompting secretly lives.

Compositionality and its failures

The principle: the meaning of a whole is a function of the meanings of its parts and how they combine. It underwrites every vector-composition scheme you will build. It fails for idioms (kick the bucket), light verbs (take a walk), metaphor, and non-intersective adjectives — a fake gun is not a gun, and a former senator is not a senator, so the naive "adjective ∧ noun" intersection is wrong.

Word senses

Polysemy: related senses of one word (bank = institution / building / the company). Homonymy: unrelated senses that happen to share a form (bank = river edge). Static embeddings (Day 43) collapse all senses into one vector; contextual embeddings (Day 81) do not — that is the single largest practical gain of the BERT era.

Semantic roles

Syntax changes; roles do not. In John broke the window, The window was broken by John, and The hammer broke the window, the subject position holds an agent, a patient and an instrument in turn. Core roles: agent, patient/theme, experiencer, instrument, source, goal, beneficiary.

Beyond the sentence

Entailment
She sold the car ⊨ Someone owns the car. Survives negation? No. This is the NLI task.
Presupposition
She stopped smoking presupposes she smoked — and the presupposition survives negation, which is the diagnostic test.
Implicature
Some students passed conversationally implies not all, though it is logically compatible with all. Cancellable: "some, in fact all".
Deixis
here, now, I, you, tomorrow — resolvable only against a context. A stateless API call has none of that context unless you put it in the prompt.
Speech acts
Locution (what was said) / illocution (what was meant) / perlocution (the effect). "It's cold in here" as a request to shut the window.
Grice's maxims, and why prompting depends on them Cooperative conversation follows four maxims: quantity (as informative as needed, no more), quality (say what you believe true and can support), relation (be relevant), manner (be clear and orderly). An instruction-tuned model has absorbed these from human preference data. So "be concise" works because the model already models quantity; and hallucination is a quality-maxim violation that the training signal only weakly penalises. Every prompt-engineering trick on Day 98 is a maxim being made explicit.

Text as Data: Files, Encodings & Unicode

20 min

Before you can tokenize a string you have to be sure you have the right string.

The encoding lineage

ASCII (7-bit, 128 chars) → Latin-1 / cp1252 (8-bit, one byte per char, Western Europe only) → UTF-8 (variable width 1–4 bytes, ASCII-compatible, now ~98% of the web). Mojibake is what you get when UTF-8 bytes are decoded as cp1252: café becomes cafÃ©. Double-encoding gives cafÃƒÂ©. The ftfy library reverses most of these by pattern.

NFKC is lossy It rewrites superscripts (x² → x2), mathematical alphanumerics, and CJK width variants. Great for a search index, wrong for a corpus you will later train on. Normalize the index key with NFKC; keep the document in NFC.

Corpus formats you will actually meet

JSONL — one JSON object per line; streamable, the de-facto standard for LLM data. CoNLL — one token per line, tab-separated columns, blank line between sentences; used by every sequence-labelling dataset. CSV — fine until a field contains a newline. XML/TEI — older linguistic corpora.

streaming loader with encoding detection 
import unicodedata, io
from charset_normalizer import from_path   # or `chardet`

def read_lines(path, target="NFC"):
    best = from_path(path).best()
    enc = best.encoding if best else "utf-8"
    with io.open(path, encoding=enc, errors="replace", newline="") as fh:
        for i, line in enumerate(fh):
            line = unicodedata.normalize(target, line.rstrip("\n"))
            if line:
                yield i, line

def strip_accents(s):
    d = unicodedata.normalize("NFD", s)
    return "".join(c for c in d if unicodedata.category(c) != "Mn")

Regular Expressions for NLP, Part 1

22 min

Still the fastest path from raw text to a usable feature — and still in production everywhere.

The building blocks

PieceMeaningGotcha
[abc] [^abc] [a-z]character class / negated / rangeInside a class, most metacharacters lose their power
\w \d \sword char, digit, whitespaceIn Python 3 these are Unicode-aware: \w matches é, ж, 漢. Add re.ASCII to restrict
* + ? {m,n}quantifiersAll greedy by default
^ $ \b \Banchors$ also matches before a trailing newline; use \Z for true end
(…) (?:…)capturing / non-capturing groupfindall returns groups, not matches, if any group exists

The Python API, chosen correctly

re.search
First match anywhere. Returns a Match or None.
re.match
Anchored at position 0 only. Almost never what you want — use search with ^.
re.fullmatch
Whole string must match. The right tool for validation.
re.finditer
Lazy iterator of Match objects with offsets. This is the one to use in NLP, because .span() gives you the character offsets you need to keep alignment (Day 16).
re.sub
Replace. The repl can be a function taking a Match.

Flags that matter: re.IGNORECASE, re.MULTILINE (makes ^ $ match at line breaks), re.DOTALL (makes . match newlines), and re.VERBOSE — which lets you write a pattern across multiple lines with comments. Every regex over ~40 characters should be VERBOSE.

Day 08

Regular Expressions for NLP, Part 2

20 min

Greed, lookaround, and the failure mode that takes down web servers.

Greedy vs lazy

Against <a>one</a><a>two</a>: the greedy <.+> matches the entire string; the lazy <.+?> matches just <a>. Quantifiers first consume as much as possible, then backtrack until the rest of the pattern fits. Adding ? reverses the order — consume as little as possible, then grow.

Lookaround: match without consuming

SyntaxNameExample
(?=…)positive lookahead\d+(?= USD) → the number before "USD"
(?!…)negative lookahead\b(?!the\b)\w+ → any word that is not "the"
(?<=…)positive lookbehind(?<=\$)\d+ → the number after a dollar sign
(?<!…)negative lookbehind(?<!Mr)\.\s → a period that is not an abbreviation

Python's re requires fixed-width lookbehind. The third-party regex module lifts that, and adds Unicode property classes: \p{Lu} (uppercase letter), \p{Han}, \p{Emoji}, plus proper grapheme matching with \X. For multilingual work, install regex.

Catastrophic backtracking (ReDoS)

The killer shape is nested quantifiers over an overlapping alternation: (a+)+$ or (\w+\s?)*$. On a non-matching input of length \(n\) the engine explores \(O(2^n)\) partitions. Twenty as and no match takes seconds; thirty takes hours.

$$\text{(a+)+ against } a^n b \;\Longrightarrow\; \text{backtracking paths} \;=\; 2^{\,n-1}$$

Fixes, in order of preference: (1) make the inner and outer parts non-overlapping; (2) use possessive quantifiers or atomic groups (?>…) via the regex module; (3) impose a timeout; (4) use a linear-time engine (RE2, Rust regex).

When a regex is the wrong tool Anything with recursive nesting. HTML, JSON, balanced parentheses, nested quotes. Regular languages cannot count arbitrary nesting depth — that is the pumping lemma, not a limitation of your cleverness. Reach for a real parser.
a VERBOSE, documented money/date extractor 
import regex as re

MONEY = re.compile(r"""
    (?P<cur>[$£€¥]|USD|EUR|GBP|INR|Rs\.?)\s?     # symbol or code
    (?P<amt>\d{1,3}(?:[,\u00a0]\d{3})*(?:\.\d+)? # 1,234,567.89
           |\d+(?:\.\d+)?)                       # or plain 1234.89
    \s?(?P<mult>k|m|bn?|thousand|million|billion|lakh|crore)?
""", re.VERBOSE | re.IGNORECASE)

MULT = {"k":1e3,"thousand":1e3,"m":1e6,"million":1e6,
        "b":1e9,"bn":1e9,"billion":1e9,"lakh":1e5,"crore":1e7}

def money(text):
    for m in MONEY.finditer(text):          # finditer → we keep offsets
        amt = float(m.group("amt").replace(",","").replace("\u00a0",""))
        amt *= MULT.get((m.group("mult") or "").lower(), 1)
        yield m.span(), m.group("cur"), amt

Day 09

Tokenization Fundamentals

22 min

The most consequential preprocessing decision in the whole pipeline, and the one people think about least.

Why text.split() fails

It glues punctuation to words (dog. ≠ dog), splits nothing in don't, destroys U.S.A., mangles state-of-the-art, breaks URLs and emails apart at slashes and dots, and produces zero tokens for Chinese, Japanese and Thai, which have no spaces at all.

Penn Treebank conventions

Separate clitics (don't → do + n't, they're → they + 're), keep hyphenated compounds together, split off most punctuation, and convert brackets to codes (( → -LRB-). NLTK's word_tokenize implements this. If you evaluate on a treebank, you must match its conventions or your scores are meaningless.

Languages without spaces

Chinese and Japanese need word segmentation as a separate learned step (jieba, MeCab, or a CRF/BiLSTM segmenter). Thai has no spaces and no clear word boundary consensus. This is a major reason byte-level subword tokenization (Day 78) took over: it sidesteps the question entirely at the cost of longer sequences.

Tokenizer bake-off — three strategies, same input
Tokenization is an accuracy variable Swap NLTK for spaCy under a fixed classifier and F1 moves by 1–3 points on noisy text. Always log which tokenizer produced a result. Two "identical" experiments that disagree usually differ here.
Exercise Run all three tokenizers over 20 deliberately nasty sentences and tabulate every disagreement. That table is your regression test for the rest of the series.
Day 10

Sentence Segmentation

15 min

Splitting on . works on 95% of sentences, and 95% is a disaster at scale.

The failure inventory

Abbreviations (Dr., Inc., e.g., Fig.) · decimals and versions (3.14, v2.1.0) · ellipses · initials (J. R. R. Tolkien) · quotes where the period sits inside (She said "go.") · numbered lists · URLs · domain-specific dosages (2.5 mg p.o. q.d.).

Three approaches

Rule-based
A period ends a sentence unless it follows a known abbreviation or precedes a lowercase letter. Fast, needs an abbreviation list per domain. spaCy's sentencizer.
Unsupervised statistical (Punkt)
Learns abbreviations from the corpus itself using a collocation test between a word and the following period, plus frequency of the type appearing sentence-internally. Ships in NLTK, needs no labels, and adapts to a new domain if you train it on that domain's text.
Parser-derived
spaCy's default: the dependency parser predicts sentence starts, so it can use syntax. Most accurate on clean prose, slowest, and it degrades on text unlike its training data.
Transcripts and OCR ASR output and scanned text may have no punctuation at all. Neither rules nor Punkt help. You need a punctuation-restoration model (a token classifier predicting none/./,/? per token — see Day 110) run before segmentation.
Why it matters downstream Sentence boundaries define: the unit for extractive summarization (Day 68), the chunk for retrieval (Day 101), the window for coreference (Day 112), and the input length for any sentence-level model. A boundary error propagates into every one of them.
Exercise Run one segmenter on a contract and on a chat log. Count boundary errors by hand on 100 sentences each. Report the two numbers separately — the average would hide the story.
Day 11

Normalization: Case, Stemming & Lemmatization

20 min

Every normalization step trades vocabulary size against signal. Know which you are buying.

Case folding

Lowercasing shrinks the vocabulary ~20–30% and helps bag-of-words models. It also destroys: US/us, Apple/apple, IT/it, March/march, and every capitalization cue an NER model relies on. Rule of thumb: lowercase for sparse count-based models, never for NER, never for anything neural with a cased checkpoint.

Note str.lower() ≠ str.casefold(): German ß lowercases to itself but casefolds to ss. For matching keys, use casefold.

Lemmatization: dictionary-backed, needs POS

WordNet's lemmatizer defaults to noun. lemmatize("better") returns better; lemmatize("better", pos="a") returns good. Without a POS tagger in front of it, a lemmatizer is a partly-broken stemmer.

$$\text{cost of normalization} \;=\; \underbrace{-\Delta|V|}_{\text{fewer parameters, denser counts}} \;-\; \underbrace{\Delta\,\text{signal}}_{\text{merged distinctions you needed}}$$
When to skip normalization entirely Anything with a subword tokenizer already handles morphology (studying → study+##ing), so stemming before BERT actively hurts: it produces non-words that fragment badly. Skip it for NER (case is a feature), sentiment (intensity lives in morphology), authorship attribution, and every transformer model.

Day 12

Stop Words, Frequency Filtering & Zipf's Law

18 min

Word frequency is not roughly uniform, not roughly normal — it is brutally, usefully power-law.

Zipf's law

Rank words by frequency. Then frequency is inversely proportional to rank:

$$f(r) \;\propto\; \frac{1}{r^{\,s}}, \qquad s \approx 1 \quad\Longrightarrow\quad \log f = \log C - s\log r$$

So a log–log plot of frequency against rank is a straight line with slope \(-s\). The practical consequences: the top ~150 types cover roughly half of all tokens; about half of all types occur exactly once (hapax legomena); and no matter how much data you add, you keep meeting new words.

Heaps' law

$$|V| \;=\; K\,N^{\beta}, \qquad K\in[10,100],\;\; \beta\in[0.4,0.6]$$

Vocabulary grows sublinearly but without bound. Quadruple your corpus and vocabulary roughly doubles. This is exactly why a fixed word-level vocabulary always leaks OOV, and why subword models exist.

Zipf & Heaps on your own text

Stop words: where the lists come from, and when they hurt

Standard lists are historical artifacts. NLTK's English list has 179 entries and includes not, no, nor, against. sklearn's has 318 and is documented by its own authors as having known problems. spaCy's has 326. They disagree substantially.

Removing stop words breaks these Negation — "not good" → "good". Sentiment — intensifiers and negators are function words. Phrase search — "to be or not to be" becomes empty. Authorship — function-word frequencies are the strongest authorship signal there is. Any neural model — it has attention; let it decide.

The better tool is a document-frequency threshold: drop types with \(\mathrm{df} > 0.9|D|\) (corpus-specific stop words) and \(\mathrm{df} < 3\) (noise and typos). This adapts to the corpus instead of importing someone else's 1990s assumptions.

Day 13

Real-World Text Cleaning Pipelines

22 min

Scraped text is 60–90% not-text. This is the day you learn to measure the loss instead of guessing at it.

Near-duplicate detection

Exact dedup is a hash set. Near-dup needs MinHash + LSH. Represent each doc as the set of its \(k\)-shingles (overlapping \(k\)-word or \(k\)-char sequences). Jaccard similarity is

$$J(A,B)=\frac{|A\cap B|}{|A\cup B|}$$

The MinHash trick: for a random permutation \(\pi\) of the universe, \(\Pr[\min \pi(A) = \min \pi(B)] = J(A,B)\) exactly. So take \(m\) hash functions, keep the \(m\) minima as a signature, and the fraction of agreeing positions estimates \(J\) with variance \(J(1-J)/m\). Then band the signature into \(b\) bands of \(r\) rows (\(m=br\)) and hash each band — two docs become candidates if any band collides, giving an S-curve threshold at roughly \((1/b)^{1/r}\).

SimHash is the alternative: a single 64-bit fingerprint where Hamming distance approximates cosine similarity. Cheaper, better for very large corpora, slightly less accurate.

Language ID and code-switching

fasttext's lid.176 model classifies 176 languages from character n-grams in microseconds; langdetect is slower and unstable on short strings. Both fail on code-switched text ("mera phone kharab ho gaya, can you help?") because they return a single label. If your corpus is code-switched, classify at the span level or accept the noise deliberately.

PII

Regex catches emails, phones, card numbers (validate with Luhn), IPs, and national ID formats. Names and addresses need NER (Day 32) or a dedicated tool like Presidio. Decide your policy up front: redact ([EMAIL]), hash (reversible with a key), or surrogate (replace with a fake but realistic value — best for keeping downstream models working).

a composable, measurable pipeline 
from dataclasses import dataclass, field

@dataclass
class Stage:
    name: str
    fn:   callable
    kept: int = 0
    dropped: int = 0
    chars_in: int = 0
    chars_out: int = 0

class Pipeline:
    def __init__(self, *stages): self.stages = list(stages)

    def __call__(self, doc):
        for s in self.stages:
            s.chars_in += len(doc)
            doc = s.fn(doc)
            if doc is None or not doc.strip():
                s.dropped += 1
                return None                       # short-circuit
            s.kept += 1
            s.chars_out += len(doc)
        return doc

    def report(self):
        for s in self.stages:
            pct = 100 * s.chars_out / max(s.chars_in, 1)
            print(f"{s.name:22s} docs kept {s.kept:6d} dropped {s.dropped:5d} "
                  f"chars retained {pct:5.1f}%")
Exercise Clean a scraped corpus and print the funnel. If any single stage removes more than 50% of characters, go and look at 20 examples it removed. Every time.
Day 14

Edit Distance & Spelling Correction

22 min

The first real dynamic program in the series. You will meet this recurrence again on Days 29, 34 and 63.

The Levenshtein recurrence

\(D[i][j]\) = the cheapest edit script turning the first \(i\) characters of \(a\) into the first \(j\) of \(b\).

$$D[i][j]=\min\begin{cases} D[i-1][j] + 1 & \text{deletion}\\ D[i][j-1] + 1 & \text{insertion}\\ D[i-1][j-1] + \mathbb{1}[a_i \ne b_j] & \text{substitution / match} \end{cases}$$

with \(D[i][0]=i\) and \(D[0][j]=j\). Time \(O(mn)\), space \(O(\min(m,n))\) if you keep only two rows — but you need the full table to backtrace the alignment. Damerau–Levenshtein adds a fourth case for adjacent transpositions (teh→the costs 1, not 2), which matters because transposition is one of the four most common human typing errors.

Levenshtein DP table — edit it and watch the table rebuild

Norvig's noisy channel, derived

Observed a misspelling \(x\); want the intended word \(w\).

$$\hat{w}=\argmax_{w\in V} P(w\mid x)=\argmax_{w\in V}\frac{P(x\mid w)\,P(w)}{P(x)}=\argmax_{w\in V}\underbrace{P(x\mid w)}_{\text{error model}}\;\underbrace{P(w)}_{\text{language model}}$$

\(P(x)\) drops because it is constant across candidates. Norvig's shortcut: approximate the error model as a hard preference for edit distance 1 over edit distance 2, and take \(P(w)\) as unigram frequency. Candidates are generated by applying all single edits to \(x\) — for a length-\(L\) word over a 26-letter alphabet that is \(54L+25\) strings, which is small enough to enumerate.

SymSpell: the same idea, 1000× faster

Instead of generating all edits of the query, precompute all deletions of every dictionary word up to distance \(k\) and store them in a hash map. At query time, generate only the deletions of the query and look them up. Deletion-only is symmetric enough to cover insertions, substitutions and transpositions, and it reduces candidate generation from \(O(54L)\) to \(O(L^k)\) map lookups.

Phonetic matching

Soundex (1918): keep the first letter, map consonants to 6 digit classes, drop vowels, truncate to 4. Robert and Rupert both give R163. Crude and English-only. Metaphone / Double Metaphone use real English phonotactic rules and return two codes for ambiguous pronunciations — the right choice for name matching.

Exercise Implement Levenshtein with backtrace, then Norvig's corrector over a frequency dictionary. Measure accuracy on a real typo list. Then check how often the correct word was in the candidate set but ranked second — that gap is your language model's fault, not your error model's.
Day 15

String Similarity & Fuzzy Matching at Scale

20 min

Edit distance is \(O(mn)\) per pair. With a million records that is \(5\times10^{11}\) comparisons. You need blocking.

The similarity zoo

$$J(A,B)=\frac{|A\cap B|}{|A\cup B|}\qquad \mathrm{Dice}(A,B)=\frac{2|A\cap B|}{|A|+|B|}\qquad \cos(\mathbf{a},\mathbf{b})=\frac{\mathbf{a}\cdot\mathbf{b}}{\|\mathbf{a}\|\,\|\mathbf{b}\|}$$

Applied to sets of character \(n\)-grams, Jaccard and Dice are monotonically related (same ranking, different scale). Cosine over character-\(n\)-gram counts handles repetition, which set measures ignore.

Which score fits which mistake?

Blocking: the only way this scales

Never compare all pairs. Generate a cheap blocking key, compare only within blocks:

  • Exact key — postcode, birth year, first letter of surname. Fast, brittle (a typo in the key loses the pair).
  • Sorted-neighbourhood — sort by key, slide a window of size \(w\). \(O(n\log n + nw)\).
  • Q-gram / LSH blocking — index by character n-grams or MinHash bands. Typo-tolerant, the practical default.
  • Canopy clustering — a cheap metric forms loose overlapping clusters; the expensive metric runs inside.

Then report pair completeness (recall of true matches surviving blocking) and reduction ratio (fraction of pairs eliminated). You are trading one against the other; state the trade explicitly.

In practice rapidfuzz is a drop-in for fuzzywuzzy, 10–100× faster, MIT-licensed, and its process.cdist does blocked batch scoring with a score cutoff that prunes early. Start there.
Exercise Deduplicate a messy customer list. Report precision, recall and the reduction ratio of your blocking. Then hand-inspect 20 false positives — they will teach you the right threshold faster than a grid search.
Day 16

🛠 Project 1: Ship Your Own Text Preprocessing Library

28 min

Portfolio piece one. The single most reusable thing you will build in this series.

The offset-preservation problem

If StripHTML turns <b>Ada</b> Lovelace (position 3–6 for "Ada") into Ada Lovelace (position 0–3), any entity span found later points at the wrong original characters. Keep an offset map: an array where omap[i] is the index in the original string of character i in the current string. Every step composes its map with the previous one.

the core of the library 
from dataclasses import dataclass, field
from typing import Callable, List, Tuple
import unicodedata, re, yaml

@dataclass
class Doc:
    raw: str
    text: str
    omap: List[int]                       # omap[i] -> index into raw
    meta: dict = field(default_factory=dict)
    log:  list = field(default_factory=list)

    @classmethod
    def of(cls, raw):  return cls(raw, raw, list(range(len(raw))))

    def to_raw(self, start, end):         # span in .text -> span in .raw
        return self.omap[start], self.omap[end - 1] + 1

class Step:
    name = "step"
    def apply(self, doc: Doc) -> Doc: raise NotImplementedError
    def keep_mask(self, doc: Doc) -> List[bool]:
        """Return a per-character keep mask; base class handles the offsets."""
        raise NotImplementedError
    def __call__(self, doc):
        mask = self.keep_mask(doc)
        text = "".join(c for c, k in zip(doc.text, mask) if k)
        omap = [o for o, k in zip(doc.omap, mask) if k]
        doc.log.append((self.name, len(doc.text) - len(text)))
        doc.text, doc.omap = text, omap
        return doc

class DropControlChars(Step):
    name = "drop_control"
    def keep_mask(self, doc):
        return [unicodedata.category(c) not in ("Cc", "Cf") or c in "\n\t"
                for c in doc.text]

class Pipeline:
    def __init__(self, steps: List[Step]): self.steps = steps
    @classmethod
    def from_config(cls, path):
        cfg = yaml.safe_load(open(path))
        return cls([REGISTRY[s["kind"]](**s.get("args", {})) for s in cfg["steps"]])
    def __call__(self, raw):
        doc = Doc.of(raw)
        for s in self.steps: doc = s(doc)
        return doc

REGISTRY = {"drop_control": DropControlChars}

Ship it properly

  • Tests — one test per step, plus a property test: doc.to_raw(...) must always recover a substring that exists in doc.raw.
  • pyproject.toml — [project] with name, version, deps; [project.optional-dependencies] for dev; hatchling or setuptools as the backend.
  • README — one install command, one five-line usage example, a table of available steps, and the honest limitations section.
  • CI — GitHub Actions running pytest + ruff on push. Two files, permanent credibility.
