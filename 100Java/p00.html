Setup & Orientation

Phase 0 sets up the workbench a Java backend engineer uses every day: a JDK you can switch between versions, an IDE and debugger, Git and GitHub, a terminal, Docker and an HTTP client. It also draws the map of the course, the path of a request from client to server to database, so that the Java language core in Phase 1 and everything after it has an obvious place to fit.

By the end of this phase you can

  • Explain how a request travels from a browser through a load balancer, a Spring Boot application's layers and a database, and back.
  • Install two JDK versions side by side, switch between them, set JAVA_HOME and PATH, and diagnose an UnsupportedClassVersionError.
  • Create and configure an IntelliJ IDEA project and find a bug using conditional breakpoints, stepping, watches and the Frames panel instead of print statements.
  • Work with Git branches, merge and rebase, resolve a conflict, and use stash, bisect and reflog; push over SSH and open a pull request with a Conventional Commit title.
  • Use pipes, redirection, grep, find, ps and kill, and pass configuration to a Java program through environment variables.
  • Run a container with Docker, read a raw HTTP exchange from curl -v, and write valid JSON.

L1 · DAY 1

Course Roadmap: What a Java Backend Engineer Actually Does

35m video20m practice

A backend engineer owns everything between the network socket and the database: receiving a request, enforcing the rules of the business, storing and fetching data, and answering correctly under load and failure. Every lesson in this course is one piece of that path, so learn the path first and you will always know where a topic fits.

Backend, frontend, full-stack

Definition

The frontend is code that runs on the user's device: HTML, CSS and JavaScript in a browser, or a mobile app. It renders data and collects input, and it cannot be trusted, because the user controls it. The backend is code that runs on servers you control: it authenticates callers, validates input again, applies business rules, talks to databases, queues and other services, and returns data, usually as JSON over HTTP. A full-stack engineer works on both, typically with less depth in each. Java's centre of gravity is the backend: banks, insurers, retailers, telecoms and governments run large Java estates, mostly on Spring Boot, and those systems are maintained for decades.

Anatomy of a request

  1. DNS and connection. The browser resolves api.example.com to an IP address, opens a TCP connection and performs a TLS handshake.
  2. Edge. A load balancer or API gateway receives the HTTP request (method, path, headers, body), often terminates TLS, and forwards it to one of several identical application instances.
  3. Application server. Inside the JVM, an embedded server (Tomcat by default in Spring Boot) parses the HTTP bytes and hands the request to a thread. Filters run first: authentication, CORS, logging, tracing.
  4. Controller. Deserializes the JSON body into Java objects, validates it, and calls the service layer.
  5. Service. Applies business rules inside a database transaction; may read a cache or publish an event to a broker such as Kafka.
  6. Repository. Borrows a connection from a pool, sends SQL to the database, maps rows back to objects.
  7. Response. The controller returns an object; it is serialized to JSON with a status code (200, 201, 400, 404, 500…) and travels back the way it came.

The smallest possible version of this, with no framework, fits in the JDK alone. Run it with java TinyApi.java and visit http://localhost:8080/hello:

import com.sun.net.httpserver.HttpServer;
import java.io.IOException;
import java.net.InetSocketAddress;
import java.nio.charset.StandardCharsets;

public class TinyApi {
    public static void main(String[] args) throws IOException {
        HttpServer server = HttpServer.create(new InetSocketAddress(8080), 0);
        server.createContext("/hello", exchange -> {
            byte[] body = """
                {"message": "hello from the backend"}
                """.getBytes(StandardCharsets.UTF_8);
            exchange.getResponseHeaders().add("Content-Type", "application/json");
            exchange.sendResponseHeaders(200, body.length);
            try (var out = exchange.getResponseBody()) {
                out.write(body);
            }
        });
        server.start();
        System.out.println("Listening on http://localhost:8080/hello");
    }
}

Spring Boot exists because real services also need routing, JSON mapping, validation, security, transactions, connection pooling, metrics and configuration, and nobody should hand-write those for every project.

What you build day to day

  • APIs. REST (sometimes gRPC or GraphQL) endpoints that web and mobile clients and other services call. The bulk of the work.
  • Batch jobs. Scheduled processes: nightly settlement, report generation, data imports of millions of rows (Spring Batch, scheduled tasks).
  • Event consumers. Services that read from Kafka or RabbitMQ and react: update a read model, send an email, call a partner.
  • Integrations. Adapters to payment providers, legacy SOAP services, files on SFTP, third-party APIs with their own rate limits and failure modes.
  • The unglamorous rest. Database migrations, tests, dashboards and alerts, on-call debugging, code review, and reading far more code than you write.

The job market in 2026, honestly

Java remains one of the most-used languages in professional server-side work; developer surveys such as Stack Overflow's annual survey and JetBrains' State of the Developer Ecosystem consistently place it near the top. Job postings for Java backend roles typically ask for Java 17 or 21, Spring Boot, SQL and JPA, REST design, testing (JUnit 5, Mockito, Testcontainers), Docker, some Kubernetes and one cloud provider, and often Kafka. With AI coding assistants now common, interviews put more weight on fundamentals: can you read, review and debug code you did not write?

Salary bands vary by country, city, company type and level by a factor of several, and any number quoted here would be stale within months. Compare by level (junior, mid, senior, staff) rather than by title, and check current sources for your market: levels.fyi for large tech companies, Glassdoor and national salary surveys elsewhere. The ordering is stable even where numbers are not: product companies and finance usually pay more than services firms, and senior engineers who can own a system end to end are the scarce resource.

Interview trap

"What happens when I type a URL and press Enter?" is a standard opening question. Weak answers jump straight to "the server returns the page". A strong backend answer names the layers in order: DNS lookup, TCP and TLS handshakes, the HTTP request line and headers, load balancer, application server thread, filters, controller, service and transaction, connection pool and SQL, serialization, status code, and where caching can short-circuit the trip. Interviewers then pick one layer and dig, so each layer should eventually be something you can explain for five minutes.

L2 · DAY 2

JDK, JRE, JVM & Installing Java 21/25

40m video40m practice

"Java" on your machine is three nested things: a virtual machine that runs bytecode, a runtime that adds the standard library, and a development kit that adds the compiler and tools. Install a JDK from a vendor whose licence you understand, point JAVA_HOME at it, and make sure the java on your PATH is the one you think it is.

JVM, JRE, JDK: three nested layers

Definition

JVM (Java Virtual Machine): an abstract machine defined by the JVM Specification that loads .class files, verifies their bytecode, and executes it with an interpreter plus a just-in-time (JIT) compiler, while managing memory with a garbage collector. HotSpot is the JVM inside almost every OpenJDK build.

JRE (Java Runtime Environment): a JVM plus the Java SE class libraries (java.lang, java.util, java.net.http…). Enough to run programs, not to compile them.

JDK (Java Development Kit): a JRE plus development tools: javac, jar, javadoc, jshell, the debugger and the diagnostic tools.

Since JDK 11, OpenJDK no longer ships a separate JRE download; the expectation is that you either ship a full JDK or build a trimmed runtime with jlink containing only the modules your application uses. Some vendors (Temurin, Corretto, Zulu) still publish JRE packages, and container base images such as eclipse-temurin:21-jre exist because a runtime image is smaller than a JDK image. On a developer machine, always install the full JDK.

Distributions and licensing

OpenJDK is the open-source project where Java SE is developed, licensed GPLv2 with the Classpath Exception (which lets you ship proprietary applications on it). Vendors take that source, build it, test it against the Java SE compatibility kit (TCK), and publish binaries. The code is nearly identical across them; what differs is licence terms and how long each vendor keeps shipping security updates for an old version.

LTS versions and which to pick

Since Java 10 (2018) a new feature release ships every six months, in March and September. Most releases get updates only until the next one appears; some are designated long-term support (LTS) by vendors: 8 (2014), 11 (2018), 17 (2021), 21 (2023) and 25 (2025). Since 17 the LTS cadence is every two years.

  • New projects: 21 or 25. Java 21 brought virtual threads, record patterns and pattern matching for switch; this course's code targets 21+ and calls out 25-only features.
  • Spring Boot 3.x requires Java 17 or later, so 8 and 11 are legacy-maintenance territory.
  • Existing systems often run 11 or 17. You will read that code at work, so it helps to know which features arrived when.

Installing, JAVA_HOME and PATH

# Windows (PowerShell, winget)
winget install EclipseAdoptium.Temurin.21.JDK

# macOS (Homebrew)
brew install --cask temurin@21

# Ubuntu / Debian            # Fedora / RHEL
sudo apt install openjdk-21-jdk   # sudo dnf install java-21-openjdk-devel

Two environment variables matter. JAVA_HOME points at the JDK's root folder (the one containing bin/, not bin/ itself); Maven, Gradle, IDEs and many scripts read it to find a JDK. PATH must contain $JAVA_HOME/bin (%JAVA_HOME%\bin on Windows) so that typing java in a shell finds the same JDK. The two are independent, and they can drift apart.

# macOS / Linux: ~/.zshrc or ~/.bashrc
export JAVA_HOME=$(/usr/libexec/java_home -v 21)   # macOS helper; on Linux use the real path
export PATH="$JAVA_HOME/bin:$PATH"

# Windows: System Properties → Environment Variables, or
setx JAVA_HOME "C:\Program Files\Eclipse Adoptium\jdk-21..."   # then add %JAVA_HOME%\bin to Path

Several JDKs side by side: SDKMAN and jEnv

You will need more than one JDK: 21 for this course, 17 for a work project, 25 to try new features. SDKMAN (macOS, Linux, WSL) downloads and switches JDKs and rewires JAVA_HOME and PATH for you. jEnv does not download anything; it switches between JDKs you have already installed, per shell, per directory or globally.

sdk list java                    # identifiers look like 21.0.x-tem, 25.0.x-tem
sdk install java <identifier>   # downloads into ~/.sdkman/candidates/java
sdk use java <identifier>       # this shell only
sdk default java <identifier>   # new shells
sdk env init                     # writes .sdkmanrc in a project; "sdk env" applies it

jenv add /path/to/jdk-21         # register an installed JDK
jenv local 17                    # writes .java-version in the current directory
jenv enable-plugin export        # make jEnv also set JAVA_HOME

Verifying, and a tour of bin/

$ java -version          # note: prints to stderr; "java --version" prints to stdout
openjdk version "21.0.x" ...
OpenJDK Runtime Environment Temurin-21.0.x ...
$ javac -version
javac 21.0.x
$ which -a java          # Windows: where java   (lists every java on PATH, in order)

The versions of java and javac must match, and the vendor line tells you whose build you are running. Inside the JDK root you will find bin/ (tools), lib/ (including lib/modules, the packed class library), conf/ (security and logging settings), and a plain-text release file stating the exact version. The tools you will use this year: java (launcher), javac (compiler), jar, javap (disassembler, L7), jshell (REPL), javadoc, jdb, jlink/jpackage (custom runtimes and installers), jcmd, jfr, jstack, jmap, jps (diagnostics on a running JVM), keytool (TLS certificates) and jwebserver (a static file server, JDK 18+).

A program can report which runtime it is on. Save this as WhichJava.java and run java WhichJava.java:

public class WhichJava {
    public static void main(String[] args) {
        Runtime.Version v = Runtime.version();
        System.out.println("feature = " + v.feature());          // 21
        System.out.println("full    = " + v);                    // 21.0.x+y-LTS
        System.out.println("vendor  = " + System.getProperty("java.vendor"));
        System.out.println("home    = " + System.getProperty("java.home"));
        System.out.println("vm      = " + System.getProperty("java.vm.name"));
    }
}
What breaks in production
  • Build and runtime JDKs differ. Code compiled by JDK 25 and run on a Java 21 server fails at startup with UnsupportedClassVersionError ... class file version 69.0. The class-file major version is the Java version plus 44 (52 = Java 8, 61 = 17, 65 = 21, 69 = 25). Compile with javac --release 21 (or the build tool's equivalent) to target the oldest runtime you deploy to.
  • A stale java wins on PATH. Old Oracle installers on Windows put C:\Program Files\Common Files\Oracle\Java\javapath early in PATH, so java -version shows a JDK you thought you had removed. where java reveals it.
  • JAVA_HOME points at bin/ or at a removed JDK. Maven then fails with a vague "JAVA_HOME is not defined correctly".
  • The container image is not your laptop. If CI builds on 21 and the Dockerfile says FROM eclipse-temurin:17-jre, you get the class-version error only after deploy.

Practice · 40 min

  1. Install Temurin 21 with your OS's package manager (or SDKMAN). Set JAVA_HOME and PATH, open a fresh terminal, and confirm java -version and javac -version agree.
  2. Install a second JDK (25, or 17). Switch between them with SDKMAN or jEnv and run WhichJava.java under each; note how java.home changes.
  3. Compile WhichJava.java with JDK 25 using plain javac, then run the class on 21 and read the error. Recompile with javac --release 21 and run it again.
  4. List your JDK's bin/ directory and open the release file. Run jps while IntelliJ is open and note what it lists.

Read JVM Specification (Java SE 21), ch. 1–2 · JEP 322, "Time-Based Release Versioning" · JEP 223, "New Version-String Scheme" · Adoptium and SDKMAN installation docs · Javadoc: java.lang.Runtime.Version

L3 · DAY 3

IntelliJ IDEA Setup & The Debugger Tour

45m video45m practice

An IDE is a compiler, an indexer and a debugger with an editor attached. The engineers who move fastest are not the ones who type fastest; they navigate by symbol, let the IDE refactor for them, and replace println debugging with breakpoints that show the real state of the program.

Which IDE, and which edition

IntelliJ IDEA is the default for professional Java work. Historically it came in two editions: Community (free, open source) with everything needed for plain Java, Maven, Gradle, Git, JUnit and the debugger; and Ultimate (paid) adding Spring and Spring Boot support (bean navigation, run dashboard, configuration-property completion), database tools, the built-in HTTP client, Jakarta EE and JPA tooling, and profiler integration. JetBrains announced in 2025 a move to a single IntelliJ IDEA download where the former Community features stay free and Ultimate features unlock with a subscription; the feature split is what matters. For Phases 0–10, the free features are enough. Students can get Ultimate through JetBrains' educational licence.

Alternatives work: VS Code with Microsoft's Extension Pack for Java (language server from Eclipse JDT, Maven/Gradle, test runner, debugger) is lighter and good if you live in VS Code already; Eclipse IDE (with Spring Tools) is still common in enterprises. Every concept below exists in all three under slightly different names.

First project, structure, modules and SDK

New Project → Java, pick a build system (IntelliJ for today; Maven and Gradle from Phase 7), choose the JDK you installed in L2, tick Add sample code. IntelliJ creates:

hello-java/
  .idea/            # IDE settings: run configurations, code style (commit the shareable parts)
  hello-java.iml    # module definition (IntelliJ build system only)
  src/Main.java     # "src" is marked as a Sources Root (blue folder icon)
  out/              # compiled .class files: never commit
Definition · project, module, SDK

A project is the top-level workspace. A module is a unit with its own source roots, dependencies and output folder; with Maven or Gradle, modules are generated from the build file and the build file is the source of truth. The SDK is the JDK used to compile and run; the language level limits which syntax the editor accepts. All of these live in File → Project Structure (Ctrl+Alt+Shift+S, macOS Cmd+;). A "cannot find symbol" for String almost always means no SDK is configured.

The refactoring menu

Refactorings rewrite every reference in the project, including other files, which a find-and-replace cannot do safely. Refactor This (Ctrl+Alt+Shift+T, macOS Ctrl+T) lists what applies at the caret. The ones you will use weekly: Rename (Shift+F6), Extract Variable (Ctrl+Alt+V), Extract Method (Ctrl+Alt+M), Extract Constant / Field / Parameter (Ctrl+Alt+C / F / P), Inline (Ctrl+Alt+N), Change Signature (Ctrl+F6), Move (F6) and Safe Delete (Alt+Delete), which refuses if the element is still used. On macOS replace Ctrl+Alt with Cmd+Opt.

The debugger

Run with Debug and the JVM starts with a debugging agent (JDWP) attached; the IDE can then suspend threads, read memory and evaluate code. Use this program, which has a bug (customers spending exactly 100 should get a discount):

import java.util.List;

public class Discounts {
    record Order(String id, int amount, boolean member) {}

    static int discountPercent(Order o) {
        if (o.amount() > 100 && o.member()) return 10;   // bug: should be >=
        if (o.amount() > 100) return 5;
        return 0;
    }

    public static void main(String[] args) {
        List<Order> orders = List.of(
                new Order("A1", 80, true),
                new Order("A2", 150, false),
                new Order("A3", 100, true));
        long total = 0;
        for (Order o : orders) {
            total += o.amount() * (100 - discountPercent(o)) / 100;
        }
        System.out.println("Total = " + total);   // prints 322, expected 312
    }
}
  • Line breakpoint (click the gutter or Ctrl+F8): suspends before that line runs.
  • Conditional breakpoint: right-click it and enter a boolean Java expression, here o.id().equals("A3"). Untick Suspend and tick Evaluate and log to get a log line with no code change.
  • Exception breakpoint: Run → View Breakpoints (Ctrl+Shift+F8) → + → Java Exception Breakpoints; stops wherever, say, NullPointerException is thrown, before any catch block hides it.
  • Stepping: Step Over (F8) runs the line; Step Into (F7) enters the called method; Step Out (Shift+F8) finishes the current method; Run to Cursor (Alt+F9); Resume (F9). Reset Frame pops the current frame and re-runs the method.
  • Watches and Evaluate Expression (Alt+F8): type any expression, such as o.amount() >= 100, and see its value in the current frame.

The Variables panel shows this, parameters and locals of the selected frame; F2 sets a value at runtime, which is how you test a hypothesis without recompiling. The thread drop-down switches between suspended threads, which matters once you reach concurrency in Phase 5.

Plugins worth installing

  • SonarLint (renamed SonarQube for IDE): flags bugs and code smells as you type, such as unclosed resources and equals without hashCode.
  • Key Promoter X: teaches shortcuts by showing the one you just missed.
  • GitToolBox: inline blame, ahead/behind status and auto-fetch on top of the built-in Git support.
What breaks in production
  • Evaluate Expression has side effects. Evaluating iterator.next() or a getter that lazily loads a JPA association changes program state; the bug you are chasing can vanish or move.
  • The Variables panel calls toString(). On a Hibernate entity that can fire SQL queries or throw LazyInitializationException while you are merely looking.
  • Method breakpoints are slow. They can slow the JVM by orders of magnitude; prefer a line breakpoint on the method's first line.
  • Remote debugging a live server. A JDWP port left open on a network is remote code execution for anyone who can reach it, and a breakpoint that suspends all threads stops every user's request. Debug locally or in an isolated environment; use logs, metrics and JFR in production.

Practice · 45 min

  1. Create the Discounts project with the IntelliJ build system. Open Project Structure and find the SDK, language level and output folder.
  2. Find the bug with the debugger only: a conditional breakpoint on the loop, Step Into discountPercent, and a watch comparing > with >=. Fix it, then confirm the total is 312.
  3. Use Extract Method to pull the loop body into priceAfterDiscount(Order), then Rename it. Check that every call site changed.
  4. Add an exception breakpoint for ArithmeticException, insert int x = 1 / 0;, and see where it stops.
  5. Pick ten shortcuts from the table and use only those for the rest of the session. Install the three plugins.

L4 · DAY 4

Git & GitHub for Backend Engineers

50m video60m practice

Git stores your project as a graph of immutable snapshots, and every command either creates snapshots, moves a named pointer around that graph, or copies snapshots between repositories. Once you see branches as pointers and commits as snapshots, merge, rebase, stash and reflog stop being incantations.

The model: snapshots, pointers and four places

Definition

A commit is a snapshot of every tracked file, plus author, message and a link to its parent commit(s), identified by a hash of all of that. A branch is a movable name pointing at one commit. HEAD names the branch (or commit) you are on. Commits are never edited; "rewriting history" creates new commits and moves pointers.

git init                      # or: git clone git@github.com:you/repo.git
git status                    # what changed, what is staged
git add src/Main.java         # stage (git add -p to stage hunks interactively)
git commit -m "feat: add main entry point"
git push -u origin main       # first push sets the upstream; later just "git push"
git pull                      # fetch + integrate the remote's new commits

Branching, merging and rebasing

git switch -c feature/discount creates a pointer and moves HEAD to it; commits now advance only that pointer. To bring the work back, either merge or rebase:

before:      A---B---C        main
                  \
                   D---E      feature

merge:       A---B---C-------M  main      (git switch main; git merge feature)
                  \         /
                   D-------E

rebase:      A---B---C---D'--E'  feature  (git switch feature; git rebase main)
                                          then main fast-forwards to E'

A merge keeps history exactly as it happened and adds a merge commit M with two parents; if main has not moved since you branched, Git simply moves the pointer forward (a fast-forward). A rebase replays your commits on top of the new base, creating new commits D' and E' with new hashes, which gives a linear history. The rule: rebase only commits nobody else has. Rebase your own feature branch to tidy it before review; never rebase main or a branch colleagues have pulled. If you rebased a branch you had already pushed, push with git push --force-with-lease, which refuses if someone else pushed in the meantime.

Resolving conflicts

A conflict happens when both sides changed the same lines. Git stops and writes both versions into the file:

<<<<<<< HEAD
        return amount * 90 / 100;
=======
        return amount.multiply(MEMBER_RATE);
>>>>>>> feature/bigdecimal

Edit the file to the correct final code (often neither side as-is), delete the markers, compile and run the tests, then git add the file and git commit (during a rebase: git rebase --continue). git merge --abort or git rebase --abort returns you to where you started. IntelliJ's three-way merge tool (Git → Resolve Conflicts) shows yours, theirs and the result side by side.

Conventional Commits give messages a parseable shape, type(scope): description: feat(loans): add renewal endpoint, fix: handle null ISBN, plus docs, refactor, test, build, ci, chore. A ! after the type or a BREAKING CHANGE: footer marks an incompatible change. Tools use the types to generate changelogs and pick the next Semantic Versioning number: fix → patch, feat → minor, breaking → major. Write the subject in the imperative, under about 70 characters, and use the body to explain why.

A pull request asks to merge a branch and is where code review happens. As an author: keep it small and about one thing, review your own diff first, explain why and how to test it, and make sure CI is green. As a reviewer: comment on the code, not the person; separate blocking issues from optional ones (prefix with nit:); ask questions instead of issuing orders; approve when it is better than what exists, not when it matches what you would have written.

Tags, stash, bisect, reflog

git tag -a v0.1.0 -m "Phase 0 complete"   # annotated tag (has author, date, message)
git push origin v0.1.0                     # tags are not pushed by default
git stash push -u -m "wip: half-done refactor"   # shelve changes, including untracked files
git stash list; git stash pop              # reapply the newest and drop it
git bisect start; git bisect bad; git bisect good v0.1.0
git bisect run ./check.sh                  # exit 0 = good, 1-127 = bad, 125 = skip
git bisect reset
git reflog                                 # every position HEAD has had
git branch rescue HEAD@{3}                 # recover commits "lost" by a reset or rebase

A tag is a pointer that never moves; GitHub Releases attach notes and build artifacts to a tag. Stash saves uncommitted work on a stack so you can switch branches. Bisect binary-searches history for the commit that introduced a bug: with 1,000 commits between good and bad, about 10 tests find it. Reflog is your local undo log; commits are effectively unrecoverable only once they have been unreachable for a while and garbage collection has run (by default, unreachable reflog entries expire after 30 days).

SSH keys and the repository for this course

ssh-keygen -t ed25519 -C "you@example.com"     # accept the default path; set a passphrase

# paste ~/.ssh/id_ed25519.pub into GitHub → Settings → SSH and GPG keys
ssh -T git@github.com                            # "Hi you! You've successfully authenticated"

git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main
git remote add origin git@github.com:you/java-backend-journey.git

The private key never leaves your machine; GitHub stores only the .pub half. Work on a branch per lesson or project, open a PR to yourself, and merge it: practising the workflow daily is the point.

What breaks in production
  • A committed secret stays in history. Deleting the file in the next commit does not remove it; anyone with a clone has it. Rotate the credential immediately, then purge history with git filter-repo if you must.
  • Plain force-push on a shared branch silently discards colleagues' commits. Use --force-with-lease, and protect main in GitHub settings.
  • Line endings on Windows. Mixed CRLF/LF makes every line look changed. Add a .gitattributes with * text=auto.
  • Committing target/ or IDE files causes endless conflicts and huge repos. Set up .gitignore before the first commit.

  2. Create two branches that edit the same line of a file. Merge one, then merge the other and resolve the conflict by hand. Repeat with rebase and compare git log --oneline --graph.
  3. Make ten small commits, one of which breaks a main method. Find it with git bisect, first manually, then with git bisect run.
  4. Run git reset --hard HEAD~3, then recover the three commits with git reflog.
  5. Open a pull request on your own repo with a Conventional Commit title, review it, merge it, and tag the result v0.0.1.

L5 · DAY 5

Terminal, HTTP Preview & Your Dev Environment

40m video40m practice

Backend work happens in terminals, in containers and over HTTP, and almost all of it is text: commands piped into commands, configuration in environment variables, requests and responses as headers plus a JSON body. Read those texts fluently and every later phase is easier to debug.

Shell essentials

Use bash or zsh (macOS, Linux, WSL or Git Bash on Windows). Every program has three streams: standard input (0), standard output (1) and standard error (2). A pipe | connects one program's stdout to the next one's stdin; redirection sends a stream to a file.

pwd; cd ~/code/java-backend-journey; cd -     # where am I, go there, go back
ls -la                                         # long listing including hidden files
grep -rn "TODO" src/                           # recursive search with line numbers
grep ERROR app.log | grep -v HealthCheck       # filter, then exclude
find . -name "*.java" -mtime -1                # Java files changed in the last day
curl -s localhost:8080/actuator/health         # quick HTTP call (-s hides the progress bar)
ps aux | grep java                             # running JVMs (or: jps -l)
kill 12345                                     # SIGTERM: ask the process to stop cleanly
kill -9 12345                                  # SIGKILL: immediate, no cleanup; last resort
lsof -i :8080                                  # who holds port 8080 (Windows: netstat -ano | findstr :8080)
java -jar app.jar > out.log 2> err.log         # stdout and stderr to separate files
java -jar app.jar >> all.log 2>&1               # append both to one file
cut -d' ' -f9 access.log | sort | uniq -c | sort -rn   # count HTTP status codes in a log

The difference between the two kills matters for Java: SIGTERM lets the JVM run its shutdown hooks, which is how Spring Boot finishes in-flight requests and closes database connections. SIGKILL gives it no chance.

Environment variables

Definition

An environment variable is a name/value string pair held by a process. A child process gets a copy of its parent's environment at start-up; changes in the child never flow back to the parent. That is why export in one terminal does nothing to another terminal, or to an IDE that was already running.

export APP_PORT=9090              # this shell and every process it starts from now on
echo "$APP_PORT"; env | grep APP_
APP_PROFILE=dev java EnvDemo.java # set for this one process only
# PowerShell: $env:APP_PORT = "9090"     persistent on Windows: setx APP_PORT 9090
public class EnvDemo {
    public static void main(String[] args) {
        String port = System.getenv().getOrDefault("APP_PORT", "8080");
        String profile = System.getenv("APP_PROFILE");          // null when unset
        System.out.println("port=" + port
                + " profile=" + (profile == null ? "(none)" : profile));
    }
}

Production services take their configuration from the environment (the "config" factor of the Twelve-Factor App), so the same artifact runs in dev, test and prod. Spring Boot maps SPRING_DATASOURCE_URL to the property spring.datasource.url automatically; you will rely on that in Phase 13.

Docker and HTTP clients

Install Docker Desktop (on Windows it runs on the WSL 2 backend). Check its licence before using it at work: at the time of writing it is free for personal use, education and small companies, and larger companies need a paid plan. Rancher Desktop, Podman Desktop, Colima (macOS) or plain Docker Engine (Linux) are free alternatives. From Phase 9 on, every database, broker and cache in this course runs in a container.

docker version                       # both Client and Server sections must appear
docker run --rm hello-world          # pulls an image, runs it, removes the container
docker run -d --name pg -e POSTGRES_PASSWORD=secret -p 5432:5432 postgres:17
docker ps; docker logs pg; docker rm -f pg

For HTTP you want both a command-line and a GUI client. curl is installed everywhere, including servers you SSH into. HTTPie (http POST :8080/api/books title=Dune) is curl with readable output and JSON by default. Postman is the most common GUI, built around cloud-synced collections. Bruno is an open-source, offline GUI that stores collections as plain-text files, so they live in your Git repository next to the code.

HTTP on the wire

An HTTP/1.1 message is text: a start line, headers, a blank line, and an optional body. (HTTP/2 and HTTP/3 encode the same fields in binary frames, but tools show them the same way.)

POST /api/books HTTP/1.1                    ← method, path, version
Host: localhost:8080                        ← headers: name: value, case-insensitive names
Content-Type: application/json
Content-Length: 50
                                            ← blank line ends the headers
{"isbn":"978-0134685991","title":"Effective Java"}

HTTP/1.1 201 Created                        ← version, status code, reason
Location: /api/books/978-0134685991
Content-Type: application/json

curl -v prints exactly this: lines starting * are curl's notes (DNS, connect, TLS), > lines were sent, < lines were received, and the body follows. Status classes: 2xx success, 3xx redirect, 4xx the client's fault (400 bad input, 401 not authenticated, 403 forbidden, 404 not found), 5xx the server's fault. Methods: GET reads, POST creates, PUT replaces, PATCH modifies, DELETE removes. Phase 11 covers all of it in depth.

JSON in ten minutes

{
  "id": "b-1029",
  "title": "Effective Java",
  "edition": 3,
  "price": "45.99",
  "available": true,
  "tags": ["java", "best-practices"],
  "author": { "name": "Joshua Bloch" },
  "subtitle": null
}
  • Six types: object {}, array [], string, number, true/false, null. Object keys are always strings.
  • Strict syntax: double quotes only, no comments, no trailing commas, no NaN or Infinity, no leading zeros.
  • One number type: JSON does not distinguish integers from decimals. JavaScript clients parse numbers as 64-bit doubles, so integers above 253 lose precision there; large IDs are often sent as strings, and money as a string or an integer count of cents (see L10).
  • No date type: dates travel as ISO-8601 strings such as "2026-10-10T09:30:00Z".

In Phase 14, Jackson converts between JSON like this and Java records automatically; knowing what JSON cannot express tells you where that conversion can go wrong.

The mental model for the next 475 lessons

Keep one rule from this picture: the server should hold no state between requests that it cannot afford to lose. Durable state lives in the database, which is what lets you run ten identical server instances behind a load balancer.

What breaks in production
  • Missing environment variable. System.getenv returns null, and the service dies later with a NullPointerException far from the cause. Validate configuration at start-up and fail with a message naming the variable.
  • Secrets in environment variables leak through docker inspect, crash dumps and debug endpoints that print the environment. Never log the environment wholesale.
  • Port already in use. A previous run still holds 8080, and start-up fails with BindException: Address already in use. Find it with lsof or netstat.
  • kill -9 as a habit skips shutdown hooks: requests are cut off mid-flight and messages may be processed twice.
