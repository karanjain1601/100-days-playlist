Temporal-Difference Learning

Twelve lessons on the idea Sutton & Barto call central and novel to reinforcement learning: update a guess towards a better-informed guess one step later. TD methods keep Monte Carlo's freedom from a model (Module 4) and borrow dynamic programming's bootstrapping (Module 3), which gives online, incremental prediction and control. SARSA, Q-learning and their n-step and eligibility-trace generalisations are the tabular core that Dyna and planning (Module 6) and every deep value-based agent (Modules 7–8) are built on.

DAY 42

TD(0) Prediction

40m video90m practice

Temporal-difference learning updates a guess from a guess. One step after visiting \(S_t\) it moves \(V(S_t)\) towards \(R_{t+1} + \gamma V(S_{t+1})\) instead of waiting for the return, and that single change makes learning online, incremental and possible in tasks that never end.

Learning from incomplete episodes

Constant-α Monte Carlo (Day 35) updates \(V(S_t) \leftarrow V(S_t) + \alpha\,[G_t - V(S_t)]\). The target \(G_t\) is only known when the episode ends, so nothing is learned until then, and in a continuing task nothing is learned at all. Dynamic programming (Day 28) updates \(V(s) \leftarrow \E_\pi[R_{t+1} + \gamma V(S_{t+1}) \mid S_t = s]\) without waiting for anything, but it needs the model \(p(s', r \mid s, a)\) to compute the expectation. TD learning takes one piece from each: it samples, like MC, and it bootstraps, like DP.

The three targets come from three ways of writing the same quantity:

$$v_\pi(s) = \E_\pi[G_t \mid S_t = s] = \E_\pi[R_{t+1} + \gamma G_{t+1} \mid S_t = s] = \E_\pi[R_{t+1} + \gamma\, v_\pi(S_{t+1}) \mid S_t = s].$$

MC uses a sample of the first expression. DP computes the last expression exactly, with the current estimate \(V\) standing in for \(v_\pi\). TD uses a sample of the last expression and substitutes \(V\) for \(v_\pi\), so its target is approximate twice over: it is noisy because it is one sample, and it is biased because \(V(S_{t+1})\) is only an estimate.

Intuition · driving home

Leaving work you predict 30 minutes to get home. Rain makes the walk to the car slow, and you revise to 40. The highway turns out clear, so you revise to 35, then a truck slows the last stretch and it takes 43 in total. Monte Carlo waits until you are in your driveway and shifts every earlier prediction towards 43. TD shifts each prediction towards the next prediction as soon as it is made: the 30 becomes more like 40 the moment you see the rain. You learn from the change in the prediction, the temporal difference, without waiting for the outcome (Sutton & Barto, Example 6.1).

The TD target, the TD error and bootstrapping

Definition
  • TD target: \(R_{t+1} + \gamma V(S_{t+1})\), with the convention \(V(\text{terminal}) = 0\).
  • TD error: \(\delta_t = R_{t+1} + \gamma V(S_{t+1}) - V(S_t)\), the difference between the better-informed estimate available at \(t+1\) and the estimate made at \(t\). It is only available at time \(t+1\).
  • Bootstrapping: updating an estimate partly on the basis of other estimates. DP and TD bootstrap; MC does not.

The TD error is the sample version of the Bellman residual. If \(V = v_\pi\), then \(\E_\pi[\delta_t \mid S_t = s] = 0\) for every state, by the Bellman expectation equation (Day 23). A learning rule that drives the expected TD error to zero is therefore driving \(V\) towards a solution of the Bellman equation, without ever writing the equation down.

The update rule

TD(0), also called one-step TD, is the familiar incremental rule \(\text{new} \leftarrow \text{old} + \alpha\,(\text{target} - \text{old})\) of Day 12 with the TD target:

$$V(S_t) \leftarrow V(S_t) + \alpha\,\big[R_{t+1} + \gamma V(S_{t+1}) - V(S_t)\big] = V(S_t) + \alpha\,\delta_t.$$
Algorithm · Tabular TD(0) for estimating \(v_\pi\)
  1. Input: the policy \(\pi\) to evaluate, step size \(\alpha \in (0, 1]\). Initialise \(V(s)\) arbitrarily, with \(V(\text{terminal}) = 0\).
  2. For each episode:
    1. Initialise \(S\).
    2. Repeat until \(S\) is terminal: choose \(A \sim \pi(\cdot \mid S)\); take it, observe \(R, S'\); \(V(S) \leftarrow V(S) + \alpha\,[R + \gamma V(S') - V(S)]\); \(S \leftarrow S'\).

The Monte Carlo error is a sum of TD errors

The two targets are tightly related. If the array \(V\) does not change during the episode, the MC error telescopes into TD errors.

Derivation

Add and subtract \(\gamma V(S_{t+1})\), then recurse, using \(G_T = 0\) and \(V(S_T) = 0\) at termination:

$$\begin{aligned} G_t - V(S_t) &= R_{t+1} + \gamma G_{t+1} - V(S_t) + \gamma V(S_{t+1}) - \gamma V(S_{t+1}) \\ &= \delta_t + \gamma\,\big(G_{t+1} - V(S_{t+1})\big) \\ &= \delta_t + \gamma\delta_{t+1} + \gamma^2\,\big(G_{t+2} - V(S_{t+2})\big) \\ &= \sum_{k=t}^{T-1} \gamma^{\,k-t}\, \delta_k . \end{aligned}$$

So an MC update is the discounted sum of the TD updates that would have been made along the way, applied all at once at the end. TD applies each piece as soon as it is known. When \(V\) is updated during the episode, as TD(0) does, the identity picks up correction terms of order \(\alpha\); for tabular TD(0) they appear only at steps where \(S_{k+1} = S_k\) (practice 2). This identity is the seed of eligibility traces: Day 51 runs it backwards to make an online algorithm whose updates add up to MC's.

Online, fully incremental learning

  • No waiting. Learning starts on the first transition. Long episodes no longer delay everything, and continuing tasks, which have no episodes at all, become learnable.
  • Constant cost per step. One addition and one multiplication; no stored trajectory.
  • Robust to what happens next. Off-policy MC must discard or reweight the tail of an episode after a non-target action (Day 40). TD learns from each transition regardless of what follows it.
  • Convergence. For a fixed policy and a finite MDP, tabular TD(0) converges to \(v_\pi\) in the mean for a sufficiently small constant \(\alpha\), and with probability 1 if every state is visited infinitely often and the step sizes satisfy the Robbins–Monro conditions of Day 5 (Sutton 1988; Dayan 1992; Jaakkola, Jordan & Singh 1994; Tsitsiklis 1994).

The random walk: TD and MC side by side

Sutton & Barto's Example 6.2 is the standard test bed. Five non-terminal states A–E lie in a row; every episode starts in C and moves left or right with probability ½ until it leaves either end. Leaving on the right gives +1, every other reward is 0, and \(\gamma = 1\). So \(v(s)\) is the probability of leaving on the right, which satisfies \(v(k) = \tfrac12 v(k-1) + \tfrac12 v(k+1)\) with \(v = 0\) and \(v = 1\) at the two ends. The solution is linear: \(v(\text{A}), \dots, v(\text{E}) = \tfrac16, \tfrac26, \tfrac36, \tfrac46, \tfrac56\).

import numpy as np

TRUE = np.arange(1, 6) / 6                     # v(A..E) = 1/6 ... 5/6

def episode(rng):
    """One walk from C (index 2). Returns the visited states and the final reward."""
    s, states = 2, []
    while 0 <= s <= 4:
        states.append(s)
        s += 1 if rng.random() < 0.5 else -1
    return states, (1.0 if s == 5 else 0.0)

def td0(states, r, V, alpha):
    for i, s in enumerate(states):              # online: one update per transition
        target = V[states[i + 1]] if i + 1 < len(states) else r   # gamma = 1, V(terminal) = 0
        V[s] += alpha * (target - V[s])

def mc(states, r, V, alpha):
    for s in states:                            # every-visit: each return equals the final reward
        V[s] += alpha * (r - V[s])

def rms_curve(update, alpha, runs=100, episodes=100, seed=0):
    rng, err = np.random.default_rng(seed), np.zeros(episodes)
    for _ in range(runs):
        V = np.full(5, 0.5)
        for k in range(episodes):
            update(*episode(rng), V, alpha)
            err[k] += np.sqrt(np.mean((V - TRUE) ** 2))
    return err / runs

for a in (0.05, 0.1, 0.15):
    print("TD", a, rms_curve(td0, a)[[0, 9, 99]].round(3))
for a in (0.01, 0.02, 0.03, 0.04):
    print("MC", a, rms_curve(mc, a)[[0, 9, 99]].round(3))

Both learners see the same kind of episodes; only the target differs. Rewards inside the walk are 0, so TD's target is just the next state's estimate, and MC's return is the final reward.

On this task TD is faster than constant-α MC at every step size Sutton & Barto tried. The Day 43 demo runs exactly this comparison live, with sliders for both step sizes, and Day 43 explains why the gap appears.

What breaks
  • Slow propagation from a bad start. TD bootstraps on whatever \(V\) currently holds. Information about a reward moves back only one state per update, so a long chain of states needs many episodes before the start state hears about the goal. n-step returns (Day 48) and traces (Day 51) speed this up.
  • A constant step size never settles. With fixed \(\alpha\) the estimates fluctuate around \(v_\pi\) with a spread that grows with \(\alpha\). Large \(\alpha\) learns fast and ends noisy; this is the dip-then-rise you will see in the demo.
  • Bootstrapping through the wrong boundary. Bootstrap from \(V(S_{t+1})\) unless \(S_{t+1}\) is truly terminal. A time-limit truncation is not terminal (Day 8), and a terminal state must have value exactly 0, not a learned entry in the table.
  • Non-Markov states. The TD target assumes \(V(S_{t+1})\) summarises the future. If the state representation hides information, that assumption is false and TD can converge to the wrong values while MC stays consistent (Day 43).

DAY 43

TD vs MC vs DP

45m video75m practice

Prediction methods differ along two axes: whether an update averages over all successors or samples one, and whether it bootstraps or runs to the end. TD sits at “sample, bootstrap”. It trades MC's unbiasedness for much lower variance, and on a fixed batch of data it converges to the certainty-equivalence estimate, which is the right answer whenever the process really is Markov.

Two axes: sample vs expected, shallow vs deep

An expected update averages over every possible successor using the model:

$$V(s) \leftarrow \sum_a \pi(a \mid s) \sum_{s', r} p(s', r \mid s, a)\,\big[r + \gamma V(s')\big].$$

It has no sampling noise and needs no step size, but its cost grows with the branching factor and it needs \(p\). A sample update uses one successor drawn from the real environment (or a sample model), costs \(O(1)\), needs no model, and needs a step size to average out its noise. The other axis is depth: one-step updates bootstrap on \(V(S_{t+1})\); full-depth updates use the actual return.

Bias and variance, precisely

The MC target is unbiased by definition: \(\E_\pi[G_t \mid S_t = s] = v_\pi(s)\). The TD target with the current estimate has bias

$$\E_\pi[R_{t+1} + \gamma V(S_{t+1}) \mid S_t = s] - v_\pi(s) = \gamma\, \E_\pi\big[V(S_{t+1}) - v_\pi(S_{t+1}) \mid S_t = s\big],$$

which is \(\gamma\) times the average error of the successor estimates. It vanishes as \(V \to v_\pi\), so it is a transient bias, but while it lasts the method chases its own errors. The variance comparison is just as exact.

Derivation · law of total variance

Condition the return on the first transition \(X = (A_t, R_{t+1}, S_{t+1})\). Given \(X\), \(G_t = R_{t+1} + \gamma G_{t+1}\) with \(R_{t+1}\) known, and by the Markov property \(\E[G_{t+1} \mid X, S_t] = v_\pi(S_{t+1})\) and \(\Var[G_{t+1} \mid X, S_t] = \Var[G_{t+1} \mid S_{t+1}]\). So

$$\Var[G_t \mid S_t = s] = \underbrace{\Var\big[R_{t+1} + \gamma v_\pi(S_{t+1}) \,\big|\, S_t = s\big]}_{\text{variance of the ideal TD target}} + \underbrace{\gamma^2\, \E\big[\Var[G_{t+1} \mid S_{t+1}] \,\big|\, S_t = s\big]}_{\text{everything after the first step}} .$$

The second term is non-negative, so the MC target is never less variable than the ideal TD target, and unrolling the recursion shows MC's variance is the discounted sum of the one-step variances along the whole trajectory.

A concrete number: in the random walk, the MC target from C is 0 or 1 with equal probability, variance \(1/4\). The ideal TD target from C is \(v(\text{B}) = 2/6\) or \(v(\text{D}) = 4/6\), variance \(1/36\), nine times smaller. TD pays for that with bias while its estimates are wrong. Kearns & Singh (2000) turn this trade-off into finite-sample error bounds.

Batch updating

Suppose experience is limited, say 10 episodes, and we present it over and over. In batch updating, every step's increment is computed with \(V\) held fixed, the increments are summed over the whole batch, \(V\) is changed once by the sum, and the process repeats until \(V\) stops moving. With \(\alpha\) small enough, batch TD(0) and batch constant-α MC each converge deterministically to an answer that does not depend on \(\alpha\). They converge to different answers.

The A–B example (Sutton & Barto, Example 6.4)

You observe eight episodes with no discounting: A, 0, B, 0 once; B, 1 six times; B, 0 once. Both methods agree that \(V(\text{B}) = 6/8 = 3/4\). They disagree about A. Batch MC averages the returns observed after A: there is one, and it is 0, so \(V(\text{A}) = 0\). Batch TD notes that A always went to B with reward 0, so \(V(\text{A}) = 0 + V(\text{B}) = 3/4\).

Which is right? Batch MC's answer has zero error on the training data. But if the process is Markov, the one episode through A is just one sample of what happens after B, and pooling it with the seven other B-episodes is more accurate. Batch TD's answer will have lower error on future data. The reason is a clean fixed-point argument.

Theorem · batch TD(0) finds the certainty-equivalence estimate

Let \(N(s)\) be the number of times \(s\) occurs in the batch, \(\hat p(s' \mid s)\) the fraction of those times it was followed by \(s'\), and \(\hat r(s)\) the mean reward received on leaving \(s\). This is the maximum-likelihood model of the Markov process. Batch TD(0) converges to the value function of that model.

Proof

Batch TD stops moving exactly when the summed increment for every state is zero:

$$\sum_{t:\, S_t = s} \big[R_{t+1} + \gamma V(S_{t+1}) - V(s)\big] = 0 \quad\Longleftrightarrow\quad V(s) = \frac{1}{N(s)} \sum_{t:\, S_t = s} \big[R_{t+1} + \gamma V(S_{t+1})\big] = \hat r(s) + \gamma \sum_{s'} \hat p(s' \mid s)\, V(s').$$

The right-hand form is the Bellman equation of the fitted model, whose solution is unique (Day 25). Batch MC's fixed point is instead \(\sum_{t:\, S_t = s} [G_t - V(s)] = 0\), the sample mean of the returns, which minimises squared error on the training set.

The name comes from control theory: estimate the model, then act as if the estimate were certainly correct. Computing it directly needs \(O(n^2)\) memory for the transition counts and \(O(n^3)\) time to solve for \(n\) states. TD(0) approximates it with \(O(n)\) memory and \(O(1)\) work per step, and even non-batch TD moves roughly towards it. That is why TD tends to beat MC on Markov problems, though no one has proved that it always does; the question of which converges faster in general is open.

When MC is right instead

Suppose the state is not Markov: visiting A secretly flips a switch that makes the following B worth 0. Then MC's \(V(\text{A}) = 0\) is correct and TD's pooled answer is wrong. TD's speed comes from trusting the Markov property. Partial observability (Day 121) and state aggregation (Module 7) both break it, which is one reason Monte Carlo and long n-step returns stay useful.

import numpy as np

# Sutton & Barto Example 6.4. States: A = 0, B = 1; next state None means terminal.
episodes = [[(0, 0.0, 1), (1, 0.0, None)]] + [[(1, 1.0, None)]] * 6 + [[(1, 0.0, None)]]

def batch(method, alpha=0.01, tol=1e-10):
    V = np.zeros(2)
    while True:
        inc = np.zeros(2)
        for ep in episodes:
            G = 0.0
            for s, r, s2 in reversed(ep):         # gamma = 1
                G = r + G
                target = r + (V[s2] if s2 is not None else 0.0) if method == "td" else G
                inc[s] += target - V[s]
        V += alpha * inc                          # one change per sweep, from V held fixed
        if np.abs(alpha * inc).max() < tol:
            return V

# certainty equivalence: fit the maximum-likelihood model, then solve its Bellman equation
N, P, R = np.zeros(2), np.zeros((2, 2)), np.zeros(2)
for ep in episodes:
    for s, r, s2 in ep:
        N[s] += 1
        R[s] += r
        if s2 is not None:
            P[s, s2] += 1
V_ce = np.linalg.solve(np.eye(2) - P / N[:, None], R / N)

print(batch("mc"), batch("td"), V_ce)        # [0, 0.75]  [0.75, 0.75]  [0.75, 0.75]

What breaks
  • “TD is always faster” is not a theorem. It is an empirical regularity on Markov tasks, explained by the batch result. On non-Markov or aliased states, TD's bias can be permanent.
  • Bias compounds through bootstrapping. Errors in \(V(S')\) become errors in \(V(S)\). With function approximation the TD fixed point is only within a bounded factor of the best approximation (Day 63), and with off-policy data it can diverge (Day 69).
  • Batch updates with too large a step diverge. The increment is a sum over the whole batch, so \(\alpha\) must shrink as the batch grows; \(\alpha\) times the largest visit count should stay well below 1.
  • Comparing at one step size is unfair. Compare methods at their best \(\alpha\), or show a sweep, which is what Days 46 and 48 do.

DAY 44

SARSA — On-Policy TD Control

40m video90m practice

For control, learn action values and improve the policy as you go. SARSA runs generalised policy iteration at the finest possible grain: every transition \((S, A, R, S', A')\) nudges \(Q(S, A)\) towards \(R + \gamma Q(S', A')\), and the ε-greedy policy read off \(Q\) changes at once.

From state values to action values

Without a model, \(v_\pi\) cannot choose an action: picking \(\argmax_a \sum_{s', r} p(s', r \mid s, a)[r + \gamma v(s')]\) needs \(p\) (Day 36). So control methods learn \(q_\pi(s, a)\) directly. Under a fixed policy, the sequence of state–action pairs is itself a Markov chain, so everything Days 42–43 proved about TD(0) on states carries over unchanged to pairs.

The update needs five quantities from consecutive steps: \(S_t, A_t, R_{t+1}, S_{t+1}, A_{t+1}\). The quintuple gives the algorithm its name.

$$Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha\,\big[R_{t+1} + \gamma\, Q(S_{t+1}, A_{t+1}) - Q(S_t, A_t)\big], \qquad Q(\text{terminal}, \cdot) = 0.$$

The target uses the action the agent will actually take next, chosen by the same ε-greedy policy that is being evaluated. That is what makes SARSA on-policy: it learns the value of the policy it follows, exploration included.

GPI with TD

Policy iteration alternates full evaluation and greedy improvement (Day 30). Monte Carlo control shortened evaluation to one episode (Day 37). SARSA shortens it to one step: each update is a sliver of evaluation, and improvement happens implicitly, because the behaviour policy is defined as ε-greedy with respect to the current \(Q\). There is no separate policy table to update.

Algorithm · SARSA (on-policy TD control)
  1. Parameters: \(\alpha \in (0, 1]\), small \(\varepsilon > 0\). Initialise \(Q(s, a)\) arbitrarily, with \(Q(\text{terminal}, \cdot) = 0\).
  2. For each episode:
    1. Initialise \(S\); choose \(A\) from \(S\) ε-greedily with respect to \(Q\).
    2. Repeat until \(S\) is terminal:
      1. Take \(A\), observe \(R, S'\).
      2. Choose \(A'\) from \(S'\) ε-greedily with respect to \(Q\). (before the update: the target needs it)
      3. \(Q(S, A) \leftarrow Q(S, A) + \alpha\,[R + \gamma Q(S', A') - Q(S, A)]\).
      4. \(S \leftarrow S'\), \(A \leftarrow A'\). (the action used in the target is the one executed)

Convergence conditions

Theorem · Singh, Jaakkola, Littman & Szepesvári 2000

In a finite MDP with \(\gamma < 1\) and rewards of bounded variance, tabular SARSA converges with probability 1 to \(q_*\), and its greedy policy to an optimal policy, provided

  1. the step sizes satisfy \(\sum_t \alpha_t(s, a) = \infty\) and \(\sum_t \alpha_t^2(s, a) < \infty\) for every pair, with \(\alpha_t(s, a) = 0\) except for the pair being updated; and
  2. the behaviour policy is GLIE (Day 38): every action is tried infinitely often in every state visited infinitely often, and the policy becomes greedy with respect to \(Q\) in the limit. ε-greedy with \(\varepsilon_t(s) = c / n_t(s)\), \(0 < c < 1\), where \(n_t(s)\) counts visits to \(s\), is one example.

The proof idea is worth knowing, because it reuses Day 45's argument. Write SARSA's target as Q-learning's target plus a perturbation, \(R + \gamma \max_a Q(S', a) + \gamma\,[Q(S', A') - \max_a Q(S', a)]\). Under GLIE the expected perturbation goes to zero, so SARSA is asymptotically a noisy version of the Q-learning iteration, which converges. Without GLIE the theorem says nothing. With \(\varepsilon\) held fixed, SARSA's natural fixed point is the action-value function of the best ε-greedy policy, which is the ε-soft optimum of Day 38 rather than \(q_*\). That is the policy you actually get in practice, and it explains the “safe path” behaviour below.

Windy Gridworld walkthrough

Sutton & Barto's Example 6.5 is a 7 × 10 grid with a start and a goal three columns apart that are hard to connect. A crosswind blows upward through the middle columns: after every move, the agent is shifted up by the wind strength of the column it started in (0, 0, 0, 1, 1, 1, 2, 2, 1, 0 from left to right), never past the top edge. Every step costs −1 until the goal, with no discounting, so the return is minus the episode length.

Run SARSA with \(\varepsilon = 0.1\), \(\alpha = 0.5\) and \(Q = 0\). The first episode is long, typically several hundred steps (a median of about 700 in our runs, occasionally over 1,000), as the agent wanders until it stumbles into G. Each step costs −1, so the values of whatever it keeps doing sink, and other actions start to look better. Episodes then shorten rapidly. In our runs of the snippet below, SARSA completes about 150–160 episodes in its first 8,000 steps, close to the roughly 170 in Sutton & Barto's figure, and ε-greedy episodes settle a few steps above the 15-step optimum (about 19 on average) because exploration keeps knocking the agent off the path. With king's moves (the eight compass directions, Exercise 6.9) the optimum drops to 7 steps; adding a ninth “stay” action doesn't shorten it further.

Why Monte Carlo struggles here

Some policies never reach the goal: one that pushes into the top wall forever never ends its episode, and an MC learner waiting for the return waits forever. SARSA learns during the episode: each −1 lowers the value of the looping action until another action wins the argmax, so a bad policy is abandoned after a few steps instead of after an episode that never comes.

import numpy as np

WIND = np.array([0, 0, 0, 1, 1, 1, 2, 2, 1, 0])
ROWS, COLS, START, GOAL = 7, 10, (3, 0), (3, 7)
MOVES4 = [(-1, 0), (0, 1), (1, 0), (0, -1)]                  # up, right, down, left
KING = MOVES4 + [(-1, 1), (1, 1), (1, -1), (-1, -1)]

def step(s, a, moves):
    r, c = s
    dr, dc = moves[a]
    r2 = int(np.clip(r + dr - WIND[c], 0, ROWS - 1))       # wind of the column you start in
    c2 = int(np.clip(c + dc, 0, COLS - 1))
    return (r2, c2), -1.0, (r2, c2) == GOAL

def sarsa(moves, steps=8000, alpha=0.5, eps=0.1, seed=0):
    rng = np.random.default_rng(seed)
    Q = np.zeros((ROWS, COLS, len(moves)))
    def policy(s):                                          # epsilon-greedy, random tie-breaking
        if rng.random() < eps:
            return int(rng.integers(len(moves)))
        return int(rng.choice(np.flatnonzero(Q[s] == Q[s].max())))
    s, a, finished = START, policy(START), []
    for t in range(steps):
        s2, r, done = step(s, a, moves)
        if done:
            Q[s][a] += alpha * (r - Q[s][a])                # Q(terminal, .) = 0
            finished.append(t)
            s = START
            a = policy(s)
            continue
        a2 = policy(s2)                                     # commit to A' first: the target uses it
        Q[s][a] += alpha * (r + Q[s2][a2] - Q[s][a])       # gamma = 1
        s, a = s2, a2
    return Q, finished

for moves in (MOVES4, KING):
    print(len(moves), "actions:", len(sarsa(moves)[1]), "episodes in 8000 steps")

The x-axis of Sutton & Barto's windy figure is time steps, not episodes; finished holds the step at which each episode ended, which is exactly what that plot needs.

Why SARSA learns “safe” paths

Because SARSA evaluates the ε-greedy policy, its values include the cost of its own future mistakes. In expectation the target bootstraps on

$$\E_{A' \sim \pi}\big[Q(S', A')\big] = (1 - \varepsilon) \max_{a} Q(S', a) + \frac{\varepsilon}{|\mathcal A|} \sum_{a} Q(S', a).$$

If one action from \(S'\) is catastrophic, the second term drags down the value of being in \(S'\), and the states next to the hazard look worse than they would to an agent that never slipped. The greedy part of SARSA's policy therefore steers away from hazards by a margin that grows with \(\varepsilon\). Whether that is a bug or a feature depends on whether you will keep exploring when it matters. Day 45 shows this on Cliff Walking with a live demo.

What breaks
  • Using a different \(A'\) in the target from the one executed. If you draw a fresh action for the target and another to act, the update is no longer SARSA. It becomes a noisy, partly off-policy hybrid.
  • Bootstrapping from a terminal state. \(Q(\text{terminal}, \cdot)\) must be 0. A table entry that happens to be indexed there and learns a value silently corrupts every predecessor.
  • Trusting the frozen greedy policy. With a large constant \(\alpha\), SARSA's table is noisy, because its target includes the randomly chosen next action. A self-loop action, such as walking into a wall, can end up with the highest estimate in its state. The ε-greedy agent soon escapes and corrects it; a frozen greedy policy loops forever. In our runs on Cliff Walking with \(\alpha = 0.5\), the greedy policy read off SARSA's table looped in 3 of 10 seeds, while Q-learning's and Expected SARSA's never did. Evaluate with a step cap and report time-outs.
  • Constant ε, constant α. The theorem needs both to decay. With them fixed you converge, at best, near the best ε-greedy policy.

DAY 45

Q-Learning — Off-Policy TD Control

45m video105m practice

Q-learning bootstraps on the best next action rather than the one actually taken. Its target then estimates \(q_*\) whatever the agent does next, so the behaviour policy can explore freely without importance sampling, and under the Watkins–Dayan conditions the table converges to \(q_*\) with probability 1.

The max in the target

$$Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha\,\big[R_{t+1} + \gamma \max_a Q(S_{t+1}, a) - Q(S_t, A_t)\big].$$

This is a sampled version of value iteration on action values. The Bellman optimality equation (Day 24) says \(q_*(s, a) = \E[R_{t+1} + \gamma \max_{a'} q_*(S_{t+1}, a') \mid S_t = s, A_t = a]\). Q-learning replaces the expectation by one sample and \(q_*\) by the current table. The learned \(Q\) approximates \(q_*\) directly, independent of the policy being followed (Watkins 1989).

Off-policy without importance sampling, and why that works here

Off-policy Monte Carlo (Day 39) needed the ratio \(\prod_k \pi(A_k \mid S_k)/b(A_k \mid S_k)\) because the return depends on every action the behaviour policy chose. Q-learning's target depends on none of them. Condition on the pair being updated:

$$\E_b\big[R_{t+1} + \gamma \max_{a'} Q(S_{t+1}, a') \,\big|\, S_t = s, A_t = a\big] = \sum_{s', r} p(s', r \mid s, a)\,\big[r + \gamma \max_{a'} Q(s', a')\big] = (\mathcal T Q)(s, a).$$

Two facts make this independent of \(b\). First, the action \(A_t = a\) is given, not sampled, because we are estimating a value conditioned on it. Second, the target policy's next action is never sampled at all: the max computes its value exactly. The only randomness left is the environment's \((R_{t+1}, S_{t+1})\), whose distribution is the same whoever is acting. The behaviour policy only decides which pairs get updated and how often, so all it must do is keep visiting every pair. Importance sampling returns as soon as the target uses more than one step of sampled actions: n-step off-policy methods (Day 49) need ratios for the actions after \(A_t\).

Algorithm · Q-learning (off-policy TD control)
  1. Parameters: \(\alpha \in (0, 1]\), small \(\varepsilon > 0\). Initialise \(Q(s, a)\) arbitrarily, with \(Q(\text{terminal}, \cdot) = 0\).
  2. For each episode: initialise \(S\), then repeat until \(S\) is terminal:
    1. Choose \(A\) from \(S\) with a behaviour policy derived from \(Q\) (e.g. ε-greedy).
    2. Take \(A\), observe \(R, S'\).
    3. \(Q(S, A) \leftarrow Q(S, A) + \alpha\,[R + \gamma \max_a Q(S', a) - Q(S, A)]\).
    4. \(S \leftarrow S'\). (the next action is chosen from the updated table)

Convergence (Watkins & Dayan 1992)

Theorem · Watkins & Dayan 1992

Consider a finite MDP with bounded rewards \(|R_t| \le R_{\max}\) and discount \(0 \le \gamma < 1\). Let \(n^i(s, a)\) be the index of the \(i\)-th time that action \(a\) is tried in state \(s\), and let the step sizes satisfy \(0 \le \alpha_n < 1\) and, for every pair \((s, a)\),

$$\sum_{i=1}^{\infty} \alpha_{n^i(s, a)} = \infty, \qquad \sum_{i=1}^{\infty} \alpha_{n^i(s, a)}^2 < \infty .$$

Then \(Q_n(s, a) \to q_*(s, a)\) with probability 1 as \(n \to \infty\), for all \(s, a\).

Read the conditions carefully. The first sum ranges over the visits to \((s, a)\), so it can only diverge if every pair is tried infinitely often; that is the whole exploration requirement, and no other property of the behaviour policy is needed. The step sizes are per pair: \(\alpha = 1/n(s, a)\) qualifies, a constant \(\alpha\) does not. Watkins and Dayan proved it with an “action-replay process”, an artificial MDP built from the stored sequence of experiences whose optimal values are exactly the current \(Q_n\), and which converges to the real MDP. Undiscounted episodic tasks are covered by later stochastic-shortest-path results (Tsitsiklis 1994; Bertsekas & Tsitsiklis 1996), which need assumptions about termination: for example, that some policy terminates and every policy that doesn't accumulates unbounded cost, as on the cliff.

Proof sketch · stochastic approximation of a contraction

This is the modern route (Jaakkola, Jordan & Singh 1994; Tsitsiklis 1994). Let \(\Delta_n = Q_n - q_*\). When the pair \((s, a)\) is updated with sample \((r, s')\),

$$\Delta_{n+1}(s, a) = (1 - \alpha_n)\,\Delta_n(s, a) + \alpha_n F_n(s, a), \qquad F_n(s, a) = r + \gamma \max_{a'} Q_n(s', a') - q_*(s, a).$$
  1. The mean contracts. Since \(q_* = \mathcal T q_*\), \(\E[F_n \mid \text{past}] = (\mathcal T Q_n)(s, a) - (\mathcal T q_*)(s, a)\). The max is non-expansive, \(|\max_{a'} f(a') - \max_{a'} g(a')| \le \max_{a'} |f(a') - g(a')|\), so \(\big|\E[F_n \mid \text{past}]\big| \le \gamma \|Q_n - q_*\|_\infty = \gamma \|\Delta_n\|_\infty\). This is the contraction of Day 32.
  2. The noise is controlled. With bounded rewards, \(\Var[F_n \mid \text{past}] \le C\,(1 + \|\Delta_n\|_\infty^2)\) for some constant \(C\).
  3. Apply the lemma. Jaakkola et al. (1994, Theorem 1): a process of this form with per-component Robbins–Monro step sizes, a mean that contracts in the sup norm and noise variance bounded as above converges to 0 with probability 1, even when components are updated asynchronously, one at a time, in any order.

The picture: each update is a noisy, partial step of value iteration on one entry. The contraction pulls every entry towards \(q_*\); the step sizes shrink fast enough that the noise averages out, but not so fast that the pull stops.

Convergence says nothing about speed. With \(\alpha = 1/n(s, a)\) the conditions hold, but Even-Dar & Mansour (2003) show convergence can then be exponentially slow in \(1/(1 - \gamma)\); polynomial rates \(\alpha = 1/n(s, a)^\omega\) with \(\omega \in (\tfrac12, 1)\) are much faster. In practice a constant \(\alpha\) is common: it gives up exact convergence to track a policy that is still changing.

Cliff Walking: optimal but risky vs safe

Sutton & Barto's Example 6.6: a 4 × 12 grid, start at bottom-left, goal at bottom-right, and the cells between them along the bottom are a cliff. Every step costs −1; stepping into the cliff costs −100 and sends the agent back to the start. Both agents act ε-greedily with \(\varepsilon = 0.1\).

  • Q-learning learns \(q_*\), whose greedy policy walks the edge: 13 steps, return −13. But it acts ε-greedily, and on each step along the edge there is a \(\varepsilon/4 = 2.5\%\) chance of a random step down into the cliff. Its online reward per episode settles around −50.
  • SARSA learns the values of the ε-greedy policy, so the edge cells carry the expected cost of slipping. Its greedy path detours one or two rows up, costs a few extra steps, rarely falls, and its online reward settles around −25.

So the off-policy method finds the better policy and performs worse while learning. If \(\varepsilon\) decays to zero, both converge to the optimal path. Which one you want depends on whether exploration continues when performance counts.

The demo runs both on the same task. With the defaults (\(\varepsilon = 0.1\), \(\alpha = 0.5\)) watch the two greedy paths separate on the grid, and in the plot underneath, Q-learning's reward curve settle well below SARSA's after the first few dozen episodes. Then set \(\varepsilon = 0\): both agents become greedy, explore only through the optimistic \(Q_0 = 0\), and end on the same optimal path. Raise \(\varepsilon\) to 0.2–0.3: SARSA's path climbs further from the edge, and Q-learning's online reward gets worse.

import numpy as np

class Cliff:
    """4 x 12 Cliff Walking with the Gymnasium interface. State = row * 12 + col."""
    moves = [(-1, 0), (0, 1), (1, 0), (0, -1)]           # up, right, down, left (Gymnasium's order)
    def reset(self, seed=None):
        self.s = 36
        return self.s, {}
    def step(self, a):
        r, c = divmod(self.s, 12)
        r, c = min(max(r + self.moves[a][0], 0), 3), min(max(c + self.moves[a][1], 0), 11)
        if r == 3 and 1 <= c <= 10:                      # fell: -100, back to start, not terminal
            self.s = 36
            return self.s, -100.0, False, False, {}
        self.s = r * 12 + c
        return self.s, -1.0, self.s == 47, False, {}

def run(env, method, episodes=500, alpha=0.5, eps=0.1, gamma=1.0, seed=0):
    rng, Q, returns = np.random.default_rng(seed), np.zeros((48, 4)), []
    def act(s):
        if rng.random() < eps:
            return int(rng.integers(4))
        return int(rng.choice(np.flatnonzero(Q[s] == Q[s].max())))
    for _ in range(episodes):
        (s, _), G, done = env.reset(), 0.0, False
        a = act(s)
        while not done:
            s2, r, terminated, truncated, _ = env.step(a)
            if method == "sarsa":
                a2 = act(s2)                               # commit to A', then back it up
                nxt = Q[s2, a2]
            else:
                nxt = Q[s2].max()                          # back up the greedy action instead
            Q[s, a] += alpha * (r + gamma * (0.0 if terminated else nxt) - Q[s, a])
            if method == "q":
                a2 = act(s2)                               # behave from the updated table
            s, a, G, done = s2, a2, G + r, terminated or truncated
        returns.append(G)
    return Q, np.array(returns)

for m in ("sarsa", "q"):
    print(m, run(Cliff(), m)[1][-100:].mean())            # roughly -25 vs -50 at eps = 0.1

The two methods differ in one line, the bootstrap value, plus when the next action is chosen. The difference matters at self-transitions such as bumping into a wall, where the update can change the greedy action in the very state you are about to act in.

What breaks
  • Online performance. Optimal values do not mean good behaviour while exploring, as the cliff shows.
  • Maximization bias. \(\max_a Q(S', a)\) over noisy estimates is biased upward, so Q-learning systematically overestimates, sometimes badly enough to prefer a bad action for hundreds of episodes. Day 47 fixes this.
  • Function approximation. The tabular guarantee does not survive. Off-policy updates, bootstrapping and function approximation together, the deadly triad, can diverge (Baird's counterexample, Day 69). DQN needs replay and target networks to tame it (Days 72–73).
  • Insufficient exploration. The theorem requires every pair to be tried infinitely often. A behaviour policy that stops visiting a region freezes its values, and greedy decay schedules can do this long before convergence.
  • Truncation. Bootstrap through a time-limit cut (truncated), never through a real termination (Day 8).

Expected SARSA

30m video75m practice

Expected SARSA replaces the sampled \(Q(S', A')\) in SARSA's target with its expectation under the target policy. The mean is unchanged and a whole source of variance disappears. With a greedy target policy it is exactly Q-learning, so it is the general form of one-step TD control.

Replacing the sample of \(A'\) with its expectation

$$Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha\,\Big[R_{t+1} + \gamma \sum_a \pi(a \mid S_{t+1})\, Q(S_{t+1}, a) - Q(S_t, A_t)\Big].$$

SARSA's target \(R + \gamma Q(S', A')\) with \(A' \sim \pi(\cdot \mid S')\) is an unbiased sample of this target given \((R, S')\). Expected SARSA computes the inner expectation instead of sampling it. Write \(\bar V(s') = \sum_a \pi(a \mid s') Q(s', a)\) for the expected next value; for an ε-greedy \(\pi\),

$$\bar V(s') = (1 - \varepsilon) \max_a Q(s', a) + \frac{\varepsilon}{|\mathcal A|} \sum_a Q(s', a),$$

where tied maximisers share the greedy mass, which leaves the formula unchanged because they have the same value. The expected update of SARSA and Expected SARSA is the same when \(\pi\) is the behaviour policy, so they have the same fixed point. The difference is entirely in the noise.

Variance elimination

Derivation · what the expectation removes

Hold the table \(Q\) fixed and condition SARSA's target on \((R, S')\). Its conditional mean is \(R + \gamma \bar V(S')\), which is Expected SARSA's target, and its conditional variance is \(\gamma^2 \Var_{A' \sim \pi(\cdot \mid S')}[Q(S', A')]\). By the law of total variance,

$$\Var\big[R + \gamma Q(S', A') \mid s, a\big] = \Var\big[R + \gamma \bar V(S') \mid s, a\big] + \gamma^2\, \E\Big[\Var_{A' \sim \pi(\cdot \mid S')}\big[Q(S', A')\big] \,\Big|\, s, a\Big].$$

Both targets have the same mean. Expected SARSA's variance is smaller by exactly the second term: the spread of action values in the next state, weighted by how randomly the policy picks among them.

The second term is large precisely where it hurts. Next to the cliff, one action is worth about −100 more than the others, so with \(\varepsilon = 0.1\) SARSA's target swings by tens of reward units depending on whether the next action happened to be the exploratory step down. In Cliff Walking the environment is deterministic, so once \(Q\) is fixed, Expected SARSA's target has zero variance given \((s, a)\). That is why it can use \(\alpha = 1\) there without losing asymptotic performance.

A generalisation that covers Q-learning

Target policy \(\pi\) in the expectationBehaviour \(b\)Result
the behaviour policy (ε-greedy in \(Q\))ε-greedyon-policy Expected SARSA: SARSA's fixed point, less variance
greedy in \(Q\)anything exploratory\(\bar V(s') = \max_a Q(s', a)\): exactly Q-learning
any other \(\pi\) (e.g. ε = 0.01)any \(b\) covering \(\pi\)off-policy Expected SARSA, no importance sampling

The off-policy case works for the same reason as Q-learning (Day 45): given \((S_t, A_t)\), the target's only randomness is the environment's, and the next action is integrated out rather than sampled from \(b\). Expected SARSA is therefore a family that runs continuously from SARSA's values to Q-learning's as the target policy is made greedier. On Cliff Walking with an ε-greedy target it learns a safe path like SARSA's, and in our runs at \(\alpha = 0.5\) its greedy path ran one row above the edge (15 steps), while SARSA's usually took the top row (17 steps) and Q-learning's walked the edge (13).

Larger stable step sizes

A step size has two jobs: averaging out noise in the target, and moving quickly towards a target that is itself moving. SARSA's target noise forces a small \(\alpha\) for good asymptotic performance, which slows the second job. Removing the policy noise lets Expected SARSA use a large \(\alpha\) for both. In the figure, its early performance improves all the way to \(\alpha = 1\), while SARSA's peaks around \(\alpha \approx 0.7\)–\(0.9\) and its late performance falls steadily with \(\alpha\). Van Seijen et al. (2009) analyse the variance reduction formally and report Expected SARSA matching or beating SARSA across several tasks. On environments with stochastic transitions or rewards, \(\alpha\) still has to average the environment's noise, so the advantage is smaller.

The price is computation: the expectation costs \(O(|\mathcal A|)\) per update instead of \(O(1)\). That is irrelevant for tabular problems, matters for very large discrete action spaces, and becomes an integral for continuous actions, where methods such as SAC approximate it with samples (Day 95).

import numpy as np

def eps_greedy_probs(q, eps):
    """pi(a | s) for an epsilon-greedy policy; tied maximisers share the greedy mass."""
    p = np.full(len(q), eps / len(q))
    best = np.flatnonzero(q == q.max())
    p[best] += (1.0 - eps) / len(best)
    return p

def expected_sarsa_target(Q, r, s2, terminated, gamma, eps_target):
    if terminated:
        return r
    return r + gamma * eps_greedy_probs(Q[s2], eps_target) @ Q[s2]

Q = np.array([[0.0, -1.0, -2.0, -3.0]])

      expected_sarsa_target(Q, -1.0, 0, False, 1.0, 0.1))   # -1.15 = -1 + 0.9*0 + 0.1*mean(Q)

What breaks
  • The wrong \(\pi\) in the expectation. If the target's ε differs from the behaviour's, you are running off-policy Expected SARSA and learning a different policy's values, possibly without meaning to.
  • Ties. Giving all the greedy mass to the first maximiser changes \(\bar V\) whenever tied actions are later updated differently. Split it, as in the snippet.
  • Environment noise remains. The expectation removes only the policy's noise. With stochastic rewards or transitions, a large \(\alpha\) is still noisy.
  • Off-policy with function approximation. Expected SARSA with a greedy target is Q-learning, and it inherits the deadly triad (Day 69).

DAY 47

Maximization Bias & Double Q-Learning

40m video90m practice

The maximum of noisy, unbiased estimates is biased upward, so every Q-learning target overestimates, and bootstrapping carries the error backwards. Double Q-learning keeps two independent tables, selects the action with one and evaluates it with the other, and the upward bias goes away.

Why max over noisy estimates is systematically optimistic

Let \(\hat Q(a) = q(a) + \text{noise}\) with \(\E[\hat Q(a)] = q(a)\) for each action, and let \(a^\star = \argmax_a q(a)\) be the truly best one. Because the max is at least as large as any single term,

$$\E\Big[\max_a \hat Q(a)\Big] \;\ge\; \E\big[\hat Q(a^\star)\big] = q(a^\star) = \max_a q(a),$$

with strict inequality whenever the noise can make another action's estimate exceed \(a^\star\)'s. (Equivalently: max is convex, so Jensen's inequality applies, as on Day 3.) The size is not small. If ten actions all have true value 0 and estimates with independent \(\mathcal N(0, \sigma^2)\) noise, the expected maximum is about \(1.54\,\sigma\); with 100 actions it is about \(2.51\,\sigma\). The worse the estimates and the more actions, the larger the bias. Decision analysts call the same effect the optimizer's curse (Smith & Winkler 2006).

Q-learning computes \(\max_a Q(S', a)\) from estimates that are noisy, especially early on, at every update. The overestimate enters \(Q(S, A)\), which is then maxed over in the update of its own predecessors, so the bias propagates backward through the state space. SARSA and Expected SARSA with ε-greedy policies suffer too, in milder form, because their policies are also built by maximising over noisy estimates. With function approximation, approximation error plays the role of noise (Thrun & Schwartz 1993).

The maximization-bias MDP (Sutton & Barto, Example 6.7)

Episodes start in A. “Right” terminates with reward 0. “Left” moves to B with reward 0, and from B every one of many actions terminates with a reward drawn from \(\mathcal N(-0.1, 1)\). Going left is worth −0.1 in expectation, so right is optimal. But after a few visits to B, some of its action estimates are positive by chance, \(\max_b Q(\text{B}, b) > 0\), and Q-learning concludes that left is worth more than right.

Double Q-learning with two independent tables

The bias arises because one set of estimates does two jobs: it chooses the action (argmax) and it evaluates that choice (the value at the argmax). Noise that makes an action look best is exactly the noise that makes its value look high. Use two estimates with independent noise, and let one choose while the other evaluates.

Lemma · the double estimator does not overestimate

Let \(Q_1, Q_2\) be independent, with \(\E[Q_2(a)] = q(a)\) for every \(a\). Let \(\hat a = \argmax_a Q_1(a)\). Then

$$\E\big[Q_2(\hat a)\big] = \E\Big[\E\big[Q_2(\hat a) \mid Q_1\big]\Big] = \E\big[q(\hat a)\big] \le \max_a q(a).$$

The middle step uses independence: once \(Q_1\) fixes \(\hat a\), \(Q_2(\hat a)\) is an unbiased estimate of \(q(\hat a)\). The estimate is unbiased for the value of the action actually selected, which can be below the best value but never above it in expectation (van Hasselt 2010).

Algorithm · Double Q-learning
  1. Initialise \(Q_1(s, a)\) and \(Q_2(s, a)\) arbitrarily, with both 0 at terminal states.
  2. For each episode: initialise \(S\), then repeat until \(S\) is terminal:
    1. Choose \(A\) from \(S\) ε-greedily with respect to \(Q_1 + Q_2\). (act on all the data)
    2. Take \(A\), observe \(R, S'\).
    3. With probability ½: \(Q_1(S, A) \leftarrow Q_1(S, A) + \alpha\,\big[R + \gamma\, Q_2\big(S', \argmax_a Q_1(S', a)\big) - Q_1(S, A)\big]\).
    4. Otherwise swap the roles: \(Q_2(S, A) \leftarrow Q_2(S, A) + \alpha\,\big[R + \gamma\, Q_1\big(S', \argmax_a Q_2(S', a)\big) - Q_2(S, A)\big]\).
    5. \(S \leftarrow S'\).

Memory doubles; the computation per step is unchanged, since only one table is updated. Each table sees about half the transitions, so Double Q can learn more slowly when there is little bias to remove: on deterministic gridworlds it is often visibly slower early on (you will measure this on Day 53). The same trick applies to SARSA and Expected SARSA (Exercise 6.13), and its deep version, with the online network selecting and the target network evaluating, is Double DQN (Day 75). TD3's clipped double-Q takes the minimum of two critics instead (Day 94).

Decoupling selection from evaluation

The update for \(Q_1\) uses \(Q_1\) only to pick \(\argmax_a Q_1(S', a)\), and the value comes from \(Q_2\). Selection noise and evaluation noise are now independent, so a lucky overestimate in \(Q_1\) no longer inflates the target. The cost is the opposite bias in some cases: if \(Q_1\) picks a truly worse action because of its own noise, \(Q_2\) honestly reports that worse action's value, and the target falls below \(\max_a q(a)\). Double Q-learning is pessimistic rather than unbiased.

import numpy as np

N_B, ALPHA, EPS, RUNS, EPISODES = 10, 0.1, 0.1, 1000, 300
LEFT, RIGHT = 0, 1

def greedy(q, rng):
    return int(rng.choice(np.flatnonzero(q == q.max())))

def eps_greedy(q, rng):
    return int(rng.integers(len(q))) if rng.random() < EPS else greedy(q, rng)

def run(double, rng):
    # tables[k] = (Q_k at A, Q_k at B); plain Q-learning has a single table
    tables = [(np.zeros(2), np.zeros(N_B)) for _ in range(2 if double else 1)]
    went_left = np.zeros(EPISODES)
    for ep in range(EPISODES):
        a = eps_greedy(sum(t[0] for t in tables), rng)      # behave on Q1 + Q2
        k = int(rng.integers(len(tables)))                  # which table this update changes
        QA, QB = tables[k]
        if a == RIGHT:
            QA[RIGHT] += ALPHA * (0.0 - QA[RIGHT])          # terminal, reward 0
            continue
        went_left[ep] = 1
        if double:   # select with the table being updated, evaluate with the other
            target = tables[1 - k][1][greedy(QB, rng)]
        else:
            target = QB.max()
        QA[LEFT] += ALPHA * (0.0 + target - QA[LEFT])
        b = eps_greedy(sum(t[1] for t in tables), rng)      # one step in B, then terminal
        k = int(rng.integers(len(tables)))
        tables[k][1][b] += ALPHA * (rng.normal(-0.1, 1.0) - tables[k][1][b])
    return went_left

rng = np.random.default_rng(0)
for double in (False, True):
    left = np.mean([run(double, rng) for _ in range(RUNS)], axis=0)
    print("double" if double else "single", (100 * left[[9, 49, 299]]).round(1))   # % left at episodes 10, 50, 300

A complete reproduction of the figure. The only difference between the two learners is where the target's value comes from.

What breaks
  • Underestimation. When the good action is the noisy one, Double Q's pessimism slows its discovery. Practice 4 builds such a case.
  • Acting on one table. Behaving ε-greedily on \(Q_1\) alone wastes half the information; act on \(Q_1 + Q_2\) (or their average).
  • Correlated tables. Updating both tables on the same transition, or selecting and evaluating with the same table, brings the bias back.
  • Bias is not the only error. Removing the upward bias does not remove variance. Double Q still needs exploration and step-size tuning, and on tasks with little noise it can simply be slower.

DAY 48

n-Step TD Prediction

40m video90m practice

One-step TD and Monte Carlo are the two ends of a dial. The n-step return uses n real rewards and then bootstraps, the bootstrap's error is shrunk by a factor \(\gamma^n\), and on most problems an intermediate n learns faster than either end.

The n-step return

Definition · n-step return

For \(n \ge 1\) and \(0 \le t < T - n\),

$$G_{t:t+n} = R_{t+1} + \gamma R_{t+2} + \cdots + \gamma^{n-1} R_{t+n} + \gamma^n\, V_{t+n-1}(S_{t+n}),$$

and \(G_{t:t+n} = G_t\) if \(t + n \ge T\): an episode that ends within \(n\) steps leaves nothing to bootstrap on. \(V_{t+n-1}\) is the estimate available at time \(t + n\), when the return can first be computed.

With \(n = 1\) this is the TD(0) target \(R_{t+1} + \gamma V(S_{t+1})\); with \(n \ge T - t\) (informally \(n = \infty\)) it is the Monte Carlo return. The backup diagrams make the family visible.

The n-step update

$$V_{t+n}(S_t) = V_{t+n-1}(S_t) + \alpha\,\big[G_{t:t+n} - V_{t+n-1}(S_t)\big], \qquad 0 \le t < T,$$

with all other states unchanged. Nothing is updated during the first \(n - 1\) steps of an episode, because no n-step return is complete yet; after termination the remaining \(n - 1\) updates are made with returns that run to the end. The bookkeeping is easiest with \(\tau = t - n + 1\), the time whose state is being updated at time \(t\).

Algorithm · n-step TD for estimating \(v_\pi\)
  1. Initialise \(V(s)\) arbitrarily, \(V(\text{terminal}) = 0\). Store \(S_t, R_t\) indexed by time (only the last \(n + 1\) are needed).
  2. For each episode: store \(S_0\); set \(T \leftarrow \infty\). For \(t = 0, 1, 2, \dots\):
    1. If \(t < T\): act with \(\pi\), store \(R_{t+1}, S_{t+1}\); if \(S_{t+1}\) is terminal, \(T \leftarrow t + 1\).
    2. \(\tau \leftarrow t - n + 1\). If \(\tau \ge 0\):
      1. \(G \leftarrow \sum_{i=\tau+1}^{\min(\tau+n,\, T)} \gamma^{\,i-\tau-1} R_i\).
      2. If \(\tau + n < T\): \(G \leftarrow G + \gamma^n V(S_{\tau+n})\).
      3. \(V(S_\tau) \leftarrow V(S_\tau) + \alpha\,[G - V(S_\tau)]\).
    3. Stop when \(\tau = T - 1\).

The error-reduction property

Theorem · error reduction

For any \(V\) used to bootstrap,

$$\max_s \Big|\, \E_\pi\big[G_{t:t+n} \mid S_t = s\big] - v_\pi(s) \Big| \;\le\; \gamma^n \max_s \big| V(s) - v_\pi(s) \big| .$$
Proof

Treat termination as entering an absorbing state with zero reward and \(V = v_\pi = 0\), so the formulas need no special cases. Unrolling the Bellman equation \(n\) times gives the n-step Bellman equation

$$v_\pi(s) = \E_\pi\big[R_{t+1} + \gamma R_{t+2} + \cdots + \gamma^{n-1} R_{t+n} + \gamma^n v_\pi(S_{t+n}) \,\big|\, S_t = s\big].$$

Subtract it from the expected n-step return. The rewards cancel term by term, leaving

$$\E_\pi\big[G_{t:t+n} \mid S_t = s\big] - v_\pi(s) = \gamma^n\, \E_\pi\big[V(S_{t+n}) - v_\pi(S_{t+n}) \,\big|\, S_t = s\big],$$

whose absolute value is at most \(\gamma^n \max_{s'} |V(s') - v_\pi(s')|\). ∎

So the expected n-step update is a \(\gamma^n\)-contraction towards \(v_\pi\): in the language of Day 32, it applies the Bellman operator \(n\) times, \(T_\pi^n\). Even when \(\gamma = 1\), most of the error usually disappears, because episodes that end within \(n\) steps contribute no bootstrap error at all. This is why all n-step methods converge to correct predictions under the usual conditions. One more identity, the n-step version of Day 42's: with \(V\) held fixed, \(G_{t:t+n} - V(S_t) = \sum_{k=t}^{t+n-1} \gamma^{k-t} \delta_k\).

The delay/bootstrapping trade-off

  • Bias falls with n. The bootstrap's error is multiplied by \(\gamma^n\), and more of the target is real reward.
  • Variance rises with n. The target now contains n random rewards and n random transitions.
  • Information moves n states per update. One-step TD needs one pass per state to push a reward back along a chain. An n-step update reaches n states back in a single episode, which is what makes the gridworld example of Day 49 so much faster.
  • Delay and memory. \(S_t\)'s update waits n steps, and the last \(n + 1\) states and rewards must be stored. In control (Day 49) the policy acts for those n steps on values that do not yet reflect them.

Sweeping n on the 19-state random walk

A five-state walk is too short to tell n = 4 from n = ∞, so Sutton & Barto (Example 7.1) use 19 states, start in the middle, and give −1 for leaving on the left and +1 on the right with \(\gamma = 1\). The true values run from −0.9 to +0.9 in steps of 0.1, and estimates start at 0. The −1 on the left matters: with a left reward of 0 and initial values of 0, many left exits would produce no error signal at all. The measure is RMS error over the 19 states, averaged over the first 10 episodes and 100 runs, plotted against \(\alpha\) for each n.

import numpy as np

N = 19
TRUE = np.arange(1, N + 1) / 10 - 1.0         # states 1..19 have values -0.9 ... 0.9; 0 and 20 are terminal

def nstep_td(n, alpha, rng, episodes=10, gamma=1.0):
    V, errs = np.zeros(N + 2), []                # V[0] = V[20] = 0 are never updated
    for _ in range(episodes):
        S, R, T, t = [10], [0.0], np.inf, 0      # R[0] is a placeholder so that R[i] is R_i
        while True:
            if t < T:
                s = S[t] + (1 if rng.random() < 0.5 else -1)
                S.append(s)
                R.append(1.0 if s == N + 1 else -1.0 if s == 0 else 0.0)
                if s in (0, N + 1):
                    T = t + 1
            tau = t - n + 1                      # the time whose estimate is updated now
            if tau >= 0:
                h = int(min(tau + n, T))
                G = sum(gamma ** (i - tau - 1) * R[i] for i in range(tau + 1, h + 1))
                if tau + n < T:
                    G += gamma ** n * V[S[tau + n]]
                V[S[tau]] += alpha * (G - V[S[tau]])
            if tau == T - 1:
                break
            t += 1
        errs.append(np.sqrt(np.mean((V[1:N + 1] - TRUE) ** 2)))
    return np.mean(errs)

rng = np.random.default_rng(0)
for n in (1, 2, 4, 8, 16, 32):
    row = [np.mean([nstep_td(n, a, rng) for _ in range(100)]) for a in (0.1, 0.2, 0.4, 0.6, 0.8)]
    print(f"n={n:<3}", np.round(row, 3))

A direct transcription of the algorithm box. The if tau + n < T test is the bootstrap rule: near the end of an episode the return runs to termination instead.

Choosing n in practice

  • Start around 3–10 and tune it with α. Larger n wants smaller α, as the figure shows; sweep the two together.
  • Long delays between action and reward favour larger n; noisy rewards and transitions favour smaller n.
  • Non-Markov states favour larger n, since the bootstrap is the part that relies on the Markov property (Day 43).
  • Deep RL uses small n. Rainbow uses \(n = 3\) (Hessel et al. 2018), and A2C/A3C commonly use rollouts of about 5 steps (Mnih et al. 2016). Day 78 discusses why off-policy replay keeps n small.
  • If you don't want to commit to one n, average them. That is the λ-return of Day 50.
What breaks
  • Off-by-one errors. \(\tau\), the upper limit \(\min(\tau + n, T)\), and the discount exponent \(i - \tau - 1\) are where n-step code goes wrong. Test against a hand-computed episode, and check that n = 1 reproduces TD(0) and a huge n reproduces constant-α MC exactly.
  • Forgetting the tail. The loop must continue past termination until \(\tau = T - 1\), or the last \(n - 1\) states of every episode are never updated.
  • Bootstrapping past the end. Add \(\gamma^n V(S_{\tau+n})\) only if \(\tau + n < T\); and with time limits, bootstrap at a truncation but not at a termination.
  • Large n with large α. The variance of the target grows with n; the right side of the figure is what happens when α is not reduced to match.

DAY 49

n-Step Control & Tree Backup

45m video90m practice

The n-step idea carries straight over to control. n-step SARSA and n-step Expected SARSA are on-policy; off-policy n-step methods need importance-sampling ratios for every sampled action after the first, unless they use the tree-backup target, which weights each untaken branch by its target-policy probability instead. Q(σ) puts all of them on one dial.

n-step SARSA

Switch states for state–action pairs and bootstrap on the action actually taken \(n\) steps later:

$$G_{t:t+n} = R_{t+1} + \gamma R_{t+2} + \cdots + \gamma^{n-1} R_{t+n} + \gamma^n Q_{t+n-1}(S_{t+n}, A_{t+n}), \qquad n \ge 1,\ 0 \le t < T - n,$$ $$Q_{t+n}(S_t, A_t) = Q_{t+n-1}(S_t, A_t) + \alpha\,\big[G_{t:t+n} - Q_{t+n-1}(S_t, A_t)\big],$$

with \(G_{t:t+n} = G_t\) if \(t + n \ge T\). The policy is ε-greedy with respect to the current \(Q\), so control and evaluation interleave as in one-step SARSA. The algorithm is Day 48's box with \(Q\) in place of \(V\) and \(A_{t+1}\) chosen and stored at each step.

n-step Expected SARSA

Take the n sampled steps, then use the expected value under \(\pi\) at the horizon:

$$G_{t:t+n} = R_{t+1} + \cdots + \gamma^{n-1} R_{t+n} + \gamma^n\, \bar V_{t+n-1}(S_{t+n}), \qquad \bar V(s) = \sum_a \pi(a \mid s)\, Q(s, a),$$

with \(\bar V(\text{terminal}) = 0\). Only the last action is integrated out; the earlier ones are still samples, so this removes the final step's policy noise but not the rest.

Gridworld speedup

Picture a gridworld whose only non-zero reward is at the goal, with all values starting at 0 (Sutton & Barto, Figure 7.4). In the first episode the agent wanders and eventually reaches G. One-step SARSA learns from that episode only about the very last action: every earlier TD error was zero. 10-step SARSA strengthens the last ten actions, so a single episode lays down a ten-cell trail of useful values leading into the goal.

Off-policy n-step learning with importance sampling

To learn about a target policy \(\pi\) from data generated by \(b\), weight each update by the relative probability of the sampled actions under the two policies (Day 39):

$$\rho_{t:h} = \prod_{k=t}^{\min(h,\, T-1)} \frac{\pi(A_k \mid S_k)}{b(A_k \mid S_k)} .$$

For state values, \(V(S_t) \leftarrow V(S_t) + \alpha\, \rho_{t:t+n-1}\,[G_{t:t+n} - V(S_t)]\): the return depends on the actions \(A_t, \dots, A_{t+n-1}\). For action values,

$$Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha\, \rho_{t+1:t+n}\,\big[G_{t:t+n} - Q(S_t, A_t)\big].$$
Why the ratio starts at t + 1 and ends at t + n

We are estimating \(\E_\pi[G \mid S_t = s, A_t = a]\). The first action is conditioned on, so its probability appears in neither policy's expectation and needs no correction: the ratio starts at \(t + 1\). The n-step SARSA return then depends on the sampled actions \(A_{t+1}, \dots, A_{t+n}\), the last because the bootstrap is \(Q(S_{t+n}, A_{t+n})\), so the ratio ends at \(t + n\). The trajectory's probability under either policy is \(\prod_k \text{policy}(A_k \mid S_k)\, p(S_{k+1}, R_{k+1} \mid S_k, A_k)\); the dynamics terms cancel in the ratio, which is why it can be computed without a model. For the n-step Expected SARSA return, the last action is integrated out under \(\pi\), so the ratio stops at \(t + n - 1\).

The variance problem of Day 40 returns with a vengeance. If \(\pi\) is greedy and \(b\) is ε-greedy, each factor is either 0 (an exploratory action, which the greedy policy would never take) or \(1/(1 - \varepsilon + \varepsilon/|\mathcal A|)\), slightly above 1. Every update whose window contains an exploratory action is thrown away, and the rest are scaled up. For large n almost every window contains one.

Per-decision importance sampling with control variates

Sutton & Barto §7.4 reduce the variance by applying each ratio only to the part of the return that depends on that action, and adding a zero-mean control variate. For state values, define recursively

$$G_{t:h} = \rho_t\,\big(R_{t+1} + \gamma\, G_{t+1:h}\big) + (1 - \rho_t)\, V_{h-1}(S_t), \qquad G_{h:h} = V_{h-1}(S_h).$$

When \(\rho_t = 0\) the target collapses to the current estimate instead of to 0, so the update does nothing rather than shrinking \(V\). The second term has expectation zero under \(b\), because \(\E_b[\rho_t] = 1\), so the estimate stays unbiased in the same sense as before. The action-value version is the σ = 1 case of Q(σ) below.

The tree-backup algorithm: off-policy without importance sampling

Precup, Sutton & Singh (2000) found an n-step target that needs no ratios at all. At each state along the trajectory, the actions not taken contribute their current estimates, weighted by their probabilities under \(\pi\); the action that was taken contributes the rest of the tree, weighted by its probability under \(\pi\):

$$G_{t:t+n} = R_{t+1} + \gamma \sum_{a \ne A_{t+1}} \pi(a \mid S_{t+1})\, Q(S_{t+1}, a) + \gamma\, \pi(A_{t+1} \mid S_{t+1})\, G_{t+1:t+n},$$

for \(t < T - 1\) and \(n \ge 2\), with base cases \(G_{t:t+1} = R_{t+1} + \gamma \sum_a \pi(a \mid S_{t+1}) Q(S_{t+1}, a)\) (the Expected SARSA target) and \(G_{T-1:t+n} = R_T\). The update is \(Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha\,[G_{t:t+n} - Q(S_t, A_t)]\). Unrolled, a leaf action at depth \(k\) is weighted by \(\gamma^k\) times the product of \(\pi\)-probabilities of the taken actions above it times its own \(\pi\)-probability. The behaviour probabilities \(b(A_k \mid S_k)\) never appear.

Why no ratios are needed

Suppose \(Q = q_\pi\) and show by induction on n that \(\E_b[G_{t:t+n} \mid S_t = s, A_t = a] = q_\pi(s, a)\) for any behaviour policy. For \(n = 1\) it is the Bellman equation for \(q_\pi\). For larger n, condition on \(S_{t+1} = s'\) and average over \(A_{t+1} = a' \sim b\), using the induction hypothesis \(\E_b[G_{t+1:t+n} \mid s', a'] = q_\pi(s', a')\):

$$\sum_{a'} b(a' \mid s') \Big[\sum_{a \ne a'} \pi(a \mid s')\, q_\pi(s', a) + \pi(a' \mid s')\, q_\pi(s', a')\Big] = \sum_{a'} b(a' \mid s') \sum_a \pi(a \mid s')\, q_\pi(s', a) = \sum_a \pi(a \mid s')\, q_\pi(s', a).$$

The behaviour policy averages over a quantity that no longer depends on which action it chose, so \(b\) drops out and the target's mean is \(\E[R_{t+1} + \gamma \sum_a \pi(a \mid S_{t+1}) q_\pi(S_{t+1}, a)] = q_\pi(s, a)\). So \(q_\pi\) is a fixed point of the expected update, whatever \(b\) is.

The catch is the mirror image of the IS problem. When \(\pi\) is greedy and \(b\) explores, \(\pi(A_{t+1} \mid S_{t+1}) = 0\) after an exploratory action, so the rest of the tree gets weight zero and the backup is cut short. Tree backup is never high-variance, but when the policies differ a lot it is effectively a short-n method.

Q(σ): one dial for all of them

De Asis et al. (2018) let each step choose between sampling and expectation with a degree of sampling \(\sigma_t \in [0, 1]\). With \(\bar V(s) = \sum_a \pi(a \mid s) Q(s, a)\) and \(\rho_t = \pi(A_t \mid S_t)/b(A_t \mid S_t)\),

$$G_{t:h} = R_{t+1} + \gamma\,\big(\sigma_{t+1}\rho_{t+1} + (1 - \sigma_{t+1})\,\pi(A_{t+1} \mid S_{t+1})\big)\big(G_{t+1:h} - Q(S_{t+1}, A_{t+1})\big) + \gamma\, \bar V(S_{t+1}),$$

for \(t < h \le T\), with \(G_{h:h} = Q(S_h, A_h)\) if \(h < T\) and \(G_{T-1:T} = R_T\). Check the two ends. With \(\sigma = 0\), the bracket's weight is \(\pi(A_{t+1} \mid S_{t+1})\) and the target rearranges into exactly the tree-backup recursion. With \(\sigma = 1\), the weight is \(\rho_{t+1}\) and it is n-step SARSA with per-decision importance sampling and a control variate; on-policy (\(\rho = 1\)) it is the n-step SARSA return plus the zero-mean term \(\gamma(\bar V(S_{t+1}) - Q(S_{t+1}, A_{t+1}))\) at each step. Intermediate σ blends the two at every step. In De Asis et al.'s experiments, an intermediate σ, or one that starts at 1 and decays towards 0 during training, did better than either extreme.

import numpy as np

def n_step_sarsa(env, n=4, episodes=200, alpha=0.1, gamma=1.0, eps=0.1, seed=0):
    """On-policy n-step SARSA for any env with Discrete observation and action spaces."""
    rng = np.random.default_rng(seed)
    Q = np.zeros((env.observation_space.n, env.action_space.n))
    def act(s):
        if rng.random() < eps:
            return int(rng.integers(Q.shape[1]))
        return int(rng.choice(np.flatnonzero(Q[s] == Q[s].max())))
    for ep in range(episodes):
        s, _ = env.reset(seed=seed * 100_000 + ep)
        S, A, R = [s], [act(s)], [0.0]           # R[0] is a placeholder so that R[i] is R_i
        T, t, cut = np.inf, 0, False
        while True:
            if t < T:
                s2, r, terminated, truncated, _ = env.step(A[t])
                S.append(s2)
                R.append(r)
                if not terminated:
                    A.append(act(s2))            # A_{t+1}: executed next, or bootstrapped at a time limit
                if terminated or truncated:
                    T, cut = t + 1, not terminated
            tau = t - n + 1
            if tau >= 0:
                h = int(min(tau + n, T))
                G = sum(gamma ** (i - tau - 1) * R[i] for i in range(tau + 1, h + 1))
                boot = tau + n if tau + n < T else (T if cut else None)
                if boot is not None:             # bootstrap on the action actually chosen there
                    G += gamma ** (boot - tau) * Q[S[boot], A[boot]]
                Q[S[tau], A[tau]] += alpha * (G - Q[S[tau], A[tau]])
            if tau == T - 1:
                break
            t += 1
    return Q

n-step SARSA with the terminated/truncated rule: after a real termination the return runs to the end; after a time-limit cut it bootstraps on \(Q(S_T, A_T)\) with the appropriate power of γ.

import numpy as np

def tree_backup_return(S, A, R, Q, pi, tau, n, T, gamma=1.0):
    """n-step tree-backup target for (S[tau], A[tau]); pi(s) returns target-policy probabilities.
    S, A, R are indexed by time (R[0] unused). Behaviour probabilities never appear."""
    h = min(tau + n, T)
    if h == T:
        G = R[T]                                          # the last reward before termination
    else:
        G = R[h] + gamma * pi(S[h]) @ Q[S[h]]             # expected value at the horizon
    for k in range(h - 1, tau, -1):                       # back up through k = h-1, ..., tau+1
        p = pi(S[k])
        untaken = p @ Q[S[k]] - p[A[k]] * Q[S[k], A[k]]   # leaves, weighted by pi
        G = R[k] + gamma * (untaken + p[A[k]] * G)        # the taken branch carries the subtree
    return G

Q = np.array([[1.0, 3.0], [2.0, 0.0], [0.0, 0.0]])        # state 2 is terminal
greedy = lambda s: np.eye(2)[int(np.argmax(Q[s]))]
S, A, R = [0, 1, 2], [0, 1], [0.0, 1.0, 5.0]
print(tree_backup_return(S, A, R, Q, greedy, tau=0, n=2, T=2))   # 1 + 2 = 3: cut at the non-greedy A_1

The tree-backup target, written exactly as Sutton & Barto's backward loop. In the example the second action is non-greedy, so the greedy target policy gives it weight 0 and the backup stops at \(\max_a Q(S_1, a)\), ignoring the reward of 5 that followed.

What breaks
  • Exploding or vanishing ratios. Products of n ratios have variance that grows exponentially in n; with a greedy target they are mostly 0. Clip, truncate (Retrace- and V-trace-style, Day 121) or use tree backup.
  • Tree backup that never looks far. With a greedy target and ε-greedy behaviour, the effective backup length is the time to the next exploratory action, so off-policy multi-step gains shrink as ε grows.
  • Using n-step returns from replay without correction. The return then mixes the behaviour policy's actions into the target, biasing it towards the behaviour policy's values. Deep RL does exactly this with small n and gets away with it (Day 78).
  • Index bookkeeping. Store \(A_{t+1}\) before the update, and make sure the stored lists cover \(S_{\tau+n}\) and \(A_{\tau+n}\) when you bootstrap.

DAY 50

Eligibility Traces I — The Forward View

40m video75m practice

Instead of committing to one n, average all the n-step returns with geometrically decaying weights. The λ-return slides smoothly from TD(0) at λ = 0 to Monte Carlo at λ = 1, and updating towards it, the forward view, is clean to analyse but needs the future. Truncating it at a horizon is the practical compromise.

Averaging n-step returns

Any convex combination of n-step returns is a valid update target. \(\tfrac12 G_{t:t+2} + \tfrac12 G_{t:t+4}\) is one; its expected error is at most the same mix of \(\gamma^2\) and \(\gamma^4\) times the worst value error, by Day 48's error-reduction property applied term by term. Updates towards such averages are called compound updates. The λ-return is the compound update that weights every n, geometrically.

The λ-return

Definition · λ-return

For \(\lambda \in [0, 1]\),

$$G_t^\lambda = (1 - \lambda) \sum_{n=1}^{\infty} \lambda^{n-1}\, G_{t:t+n} .$$

In an episode that ends at \(T\), every \(G_{t:t+n}\) with \(n \ge T - t\) equals the full return \(G_t\), so their weights collect into one term:

$$G_t^\lambda = (1 - \lambda) \sum_{n=1}^{T-t-1} \lambda^{n-1}\, G_{t:t+n} \;+\; \lambda^{T-t-1}\, G_t .$$

The weights sum to 1, since \((1 - \lambda)\sum_{n \ge 1} \lambda^{n-1} = 1\), and the residual weight is \((1 - \lambda)\sum_{n \ge T-t} \lambda^{n-1} = \lambda^{T-t-1}\). The two ends are the familiar methods:

  • \(\lambda = 0\): all weight on \(G_{t:t+1}\), the TD(0) target.
  • \(\lambda = 1\): the sum vanishes and the residual weight is 1, so \(G_t^1 = G_t\), the Monte Carlo return.

Two numbers make λ concrete. Under the weights \((1 - \lambda)\lambda^{n-1}\), the mean n is \(1/(1 - \lambda)\): λ = 0.9 averages, in effect, around a 10-step return. And the weights halve every \(\ln 2 / \ln(1/\lambda)\) steps, which is about 6.6 steps for λ = 0.9 and about 69 for λ = 0.99. With discounting, the weight on reward \(R_{t+k}\) carries a factor \((\gamma\lambda)^{k-1}\), so \(\gamma\lambda\) sets the effective horizon.

A recursion, and the TD errors inside it

Derivation · recursive form

Use \(G_{t:t+1} = R_{t+1} + \gamma V(S_{t+1})\) and, for \(n \ge 2\), \(G_{t:t+n} = R_{t+1} + \gamma G_{t+1:t+n}\), with \(V\) held fixed:

$$\begin{aligned} G_t^\lambda &= (1 - \lambda)\big[R_{t+1} + \gamma V(S_{t+1})\big] + (1 - \lambda)\sum_{n \ge 2} \lambda^{n-1}\big[R_{t+1} + \gamma G_{t+1:t+n}\big] \\ &= R_{t+1} + \gamma (1 - \lambda) V(S_{t+1}) + \gamma\lambda\, (1 - \lambda) \sum_{m \ge 1} \lambda^{m-1} G_{t+1:t+1+m} \\ &= R_{t+1} + \gamma\big[(1 - \lambda)\, V(S_{t+1}) + \lambda\, G_{t+1}^\lambda\big]. \end{aligned}$$

The first line's reward weights sum to 1; the second line substitutes \(m = n - 1\). In words: take one real step, then bootstrap partly on the estimate (weight \(1 - \lambda\)) and partly on the λ-return from the next state (weight \(\lambda\)). Subtracting \(V(S_t)\) and adding and subtracting \(\gamma\lambda V(S_{t+1})\) gives

$$G_t^\lambda - V(S_t) = \delta_t + \gamma\lambda\,\big(G_{t+1}^\lambda - V(S_{t+1})\big) = \sum_{k=t}^{T-1} (\gamma\lambda)^{k-t}\, \delta_k .$$

This is Day 42's identity with \(\gamma\) replaced by \(\gamma\lambda\): the λ-return error is a sum of future TD errors, discounted by \(\gamma\lambda\). Day 51 turns this sum around to get eligibility traces, and GAE (Day 88) applies the same sum to advantages.

The offline λ-return algorithm

Algorithm · offline λ-return (forward view)
  1. Run an episode with \(\pi\), storing \(S_0, R_1, S_1, \dots, R_T\). Make no updates during the episode.
  2. With \(V\) as it was during the episode, compute \(G_t^\lambda\) for \(t = T-1, \dots, 0\) by the backward recursion.
  3. For every state \(s\): \(V(s) \leftarrow V(s) + \alpha \sum_{t:\, S_t = s} \big[G_t^\lambda - V(S_t)\big]\).

Applying the summed increments at the end, with \(V\) held fixed for all of them, is the version for which Day 51's equivalence is exact. On the 19-state random walk the offline λ-return algorithm performs about as well as the best n-step method of Day 48, with its best results at intermediate λ (Sutton & Barto Figure 12.3); practice 1 checks this.

This is called the forward view: from each state you look forward in time to all the rewards that follow and decide how to weight them.

Why the forward view is not implementable online

\(G_t^\lambda\) depends on \(R_{t+1}, \dots, R_T\), and with \(\lambda > 0\) the last of them carries weight \(\lambda^{T-t-1}\). At time \(t\) none of them has happened. So the update for \(S_t\) cannot be made until the episode ends, which brings back Monte Carlo's two problems: no learning during the episode, and no learning at all in continuing tasks. It also needs the whole episode in memory. There are three ways out:

  1. Truncate the λ-return at a horizon, accepting a delay of n steps (below).
  2. Redo the updates as the horizon advances, the online λ-return algorithm (below), which is exact but expensive.
  3. Reverse the computation with eligibility traces (Day 51), which distribute each TD error backwards as soon as it is known and reproduce the offline algorithm exactly, at the cost of one extra vector.

Truncated λ-returns

Definition · truncated λ-return

For a horizon \(h\) with \(0 \le t < h \le T\),

$$G_{t:h}^\lambda = (1 - \lambda) \sum_{n=1}^{h-t-1} \lambda^{n-1}\, G_{t:t+n} \;+\; \lambda^{h-t-1}\, G_{t:h} .$$

The horizon plays the role of the episode's end: the residual weight goes to the longest return available, \(G_{t:h}\), which bootstraps on \(V(S_h)\) if \(h < T\).

TTD(λ) updates \(S_t\) at time \(t + n\) towards \(G_{t:t+n}^\lambda\), with the delay and memory of n-step TD (Cichosz 1995). The same derivation as above, with the recursion stopped at \(h\), gives an efficient form for fixed \(V\): \(G_{t:h}^\lambda = V(S_t) + \sum_{i=t}^{h-1} (\gamma\lambda)^{i-t}\, \delta_i\). Each new TD error extends every pending return by one term.

The online λ-return algorithm (Sutton & Barto §12.4) goes further: at every time step \(h\) it redoes all of the episode's updates from the start, using truncated returns with horizon \(h\) and the most recent values. It is the best-performing of these methods, since every target uses the freshest information, but its cost per step grows with \(t\). Day 52's true online TD(λ) computes exactly the same sequence of values at a constant cost per step.

import numpy as np

def lambda_returns(rewards, values, lam, gamma=1.0):
    """rewards[t] = R_{t+1}, values[t] = V(S_t) for t = 0..T-1, V fixed during the episode.
    Backward recursion G_t = R_{t+1} + gamma * ((1 - lam) * V(S_{t+1}) + lam * G_{t+1})."""
    G, next_v, next_G = np.zeros(len(rewards)), 0.0, 0.0    # V(terminal) = 0, G_T = 0
    for t in reversed(range(len(rewards))):
        G[t] = rewards[t] + gamma * ((1 - lam) * next_v + lam * next_G)
        next_v, next_G = values[t], G[t]
    return G

def n_step(rewards, values, t, n, gamma=1.0):
    T = len(rewards)
    G = sum(gamma ** (k - t) * rewards[k] for k in range(t, min(t + n, T)))
    return G + (gamma ** n * values[t + n] if t + n < T else 0.0)

def lambda_return_direct(rewards, values, t, lam, gamma=1.0):
    """The definition: geometric weights on n-step returns, the rest on the full return."""
    T = len(rewards)
    G = sum((1 - lam) * lam ** (n - 1) * n_step(rewards, values, t, n, gamma) for n in range(1, T - t))
    return G + lam ** (T - t - 1) * n_step(rewards, values, t, T - t, gamma)

rng = np.random.default_rng(0)
r, v = rng.normal(size=8), rng.normal(size=8)
for lam in (0.0, 0.5, 0.9, 1.0):
    fast = lambda_returns(r, v, lam, gamma=0.9)
    assert np.allclose(fast, [lambda_return_direct(r, v, t, lam, gamma=0.9) for t in range(8)])
print(np.allclose(lambda_returns(r, v, 0.0, 0.9)[:-1], r[:-1] + 0.9 * v[1:]),   # lambda = 0: TD(0) targets
      np.allclose(lambda_returns(r, v, 1.0, 0.9)[0], sum(0.9 ** k * r[k] for k in range(8))))   # lambda = 1: MC

The O(T) backward recursion agrees with the O(T²) definition for every λ, and reproduces the TD(0) targets at λ = 0 and the Monte Carlo return at λ = 1. This is the computation behind the offline λ-return algorithm.

What breaks
  • Waiting for the end. The forward view inherits MC's delay and memory, and does not work in continuing tasks without truncation.
  • Stale bootstraps. The offline algorithm computes every \(G_t^\lambda\) with the values from the start of the episode. In long episodes that information is old by the time it is used, which is why the online variants of Days 51–52 learn faster.
  • λ near 1 is Monte Carlo. It brings MC's variance with it, and with \(\gamma = 1\) and long episodes the targets can be very noisy.
  • Off-policy data. The λ-return as defined assumes the actions came from the policy being evaluated. Off-policy versions need corrections: cutting (Watkins, Day 52), tree-backup weights, or truncated importance ratios as in Retrace and V-trace (Day 121).
  • Too short a horizon. A truncated λ-return with a small horizon is just a short n-step return with an odd weighting; the horizon should be several times \(1/(1 - \gamma\lambda)\).

DAY 51

Eligibility Traces II — The Backward View

45m video90m practice

An eligibility trace is a short-term memory of how recently, and how often, each state was visited. Each TD error is broadcast to every state in proportion to its trace. Offline this reproduces the λ-return algorithm exactly; online it is a cheap, close approximation that learns during the episode and works for continuing tasks.

The eligibility trace vector

Day 50 ended with \(G_t^\lambda - V(S_t) = \sum_{k \ge t} (\gamma\lambda)^{k-t} \delta_k\): state \(S_t\) wants every future TD error, discounted by \(\gamma\lambda\) per step. Turn that around. When \(\delta_k\) arrives, every earlier state \(S_t\) is owed \((\gamma\lambda)^{k-t}\delta_k\). Keep, for every state, a running sum of how much it is owed per unit of TD error:

Definition · accumulating eligibility trace

\(\mathbf z_t \in \R^{|\mathcal S|}\) (written \(e_t\) in the first edition of Sutton & Barto and much of the literature), with \(\mathbf z_{-1} = \mathbf 0\) at the start of each episode and

$$z_t(s) = \gamma\lambda\, z_{t-1}(s) + \mathbb 1\{S_t = s\} \quad\text{for all } s, \qquad\text{so}\qquad z_t(s) = \sum_{j \le t} (\gamma\lambda)^{t-j}\, \mathbb 1\{S_j = s\}.$$

The TD(λ) update applies the current TD error to every state in proportion to its trace:

$$V(s) \leftarrow V(s) + \alpha\, \delta_t\, z_t(s) \quad \text{for all } s .$$

The trace combines two heuristics for credit: recency (it decays by \(\gamma\lambda\) every step) and frequency (each visit adds 1). With \(\lambda = 0\) the trace is the indicator of \(S_t\) and TD(λ) is TD(0). With \(\lambda = 1\) and \(\gamma = 1\) the trace never decays, every visited state receives every later TD error, and by Day 42's identity the total offline update is Monte Carlo's. For linear function approximation (Module 7) the same rule reads \(\mathbf z_t = \gamma\lambda \mathbf z_{t-1} + \mathbf x(S_t)\), \(\mathbf w \leftarrow \mathbf w + \alpha \delta_t \mathbf z_t\); the tabular case is one-hot features.

Accumulating, replacing and dutch traces

  • Accumulating: \(z(S_t) \leftarrow \gamma\lambda\, z(S_t) + 1\). Repeated visits pile up, so a state revisited in a tight loop can have a trace well above 1.
  • Replacing: \(z(S_t) \leftarrow 1\) (Singh & Sutton 1996). A revisit resets the trace to 1 instead of adding to it. In tasks with loops, this is often more stable, and Singh & Sutton relate replacing-trace TD(1) to first-visit MC, as accumulating-trace TD(1) relates to every-visit MC.
  • Dutch: \(z(S_t) \leftarrow (1 - \alpha)\gamma\lambda\, z(S_t) + 1\), the tabular case of \(\mathbf z_t = \gamma\lambda \mathbf z_{t-1} + (1 - \alpha\gamma\lambda\, \mathbf z_{t-1}^\top \mathbf x_t)\, \mathbf x_t\) (van Seijen & Sutton 2014). It sits between the other two: \(\alpha \to 0\) gives accumulating, \(\alpha = 1\) gives replacing. Dutch traces belong with the true online update of Day 52, which is what makes them exact.

In every case the traces of all other states decay by \(\gamma\lambda\).

The online TD(λ) algorithm

Algorithm · tabular TD(λ) for estimating \(v_\pi\)
  1. Initialise \(V(s)\) arbitrarily, \(V(\text{terminal}) = 0\).
  2. For each episode: \(\mathbf z \leftarrow \mathbf 0\); initialise \(S\). Repeat until \(S\) is terminal:
    1. Act with \(\pi\); observe \(R, S'\).
    2. \(\delta \leftarrow R + \gamma V(S') - V(S)\).
    3. \(\mathbf z \leftarrow \gamma\lambda\, \mathbf z\), then \(z(S) \leftarrow z(S) + 1\) (accumulating) or \(z(S) \leftarrow 1\) (replacing). (decay first, then mark the current state)
    4. \(V(s) \leftarrow V(s) + \alpha\, \delta\, z(s)\) for all \(s\).
    5. \(S \leftarrow S'\).

Updating every state every step costs \(O(|\mathcal S|)\), but traces below a small threshold (say \(10^{-4}\)) can be dropped, so in practice you keep a short list of recently visited states and the cost is about \(\log(10^{-4}) / \log(\gamma\lambda)\) updates per step: 87 for \(\gamma\lambda = 0.9\).

The forward/backward equivalence

Theorem · offline equivalence of the forward and backward views

Hold \(V\) fixed during an episode and accumulate TD(λ)'s increments with accumulating traces, applying their sum at the end. Then for every state \(s\),

$$\sum_{t=0}^{T-1} \alpha\, \delta_t\, z_t(s) = \sum_{t=0}^{T-1} \alpha\,\big[G_t^\lambda - V(S_t)\big]\,\mathbb 1\{S_t = s\}.$$

The left side is offline TD(λ), the right side is the offline λ-return algorithm of Day 50.

Proof sketch

Start from the right side and use the TD-error form of the λ-return error, then swap the order of summation over the triangle \(0 \le t \le k \le T - 1\):

$$\sum_{t} \mathbb 1\{S_t = s\} \sum_{k=t}^{T-1} (\gamma\lambda)^{k-t}\delta_k = \sum_{k=0}^{T-1} \delta_k \underbrace{\sum_{t=0}^{k} (\gamma\lambda)^{k-t}\,\mathbb 1\{S_t = s\}}_{=\, z_k(s)} = \sum_{k=0}^{T-1} \delta_k\, z_k(s).$$

The inner sum is exactly the accumulating trace. The forward view collects future TD errors at each state; the backward view sends each TD error to past states. They are the same double sum, read in two orders. ∎

Two caveats. First, the proof uses accumulating traces; with replacing traces the inner sum is different and the equivalence does not hold exactly. Second, online TD(λ) changes \(V\) during the episode, so later TD errors are computed with updated values and the two sides differ by terms of order \(\alpha\). With small \(\alpha\) online TD(λ) closely tracks the λ-return algorithm; with large \(\alpha\) and λ near 1 it can do clearly worse, which is visible on the random walk (Sutton & Barto §12.2, and practice 1). Day 52's true online TD(λ) removes the gap entirely.

Trace decay on a corridor

The corridor is the clearest picture of why traces speed up learning. Walk it once with all values 0: every TD error is 0 until the last transition gives \(\delta = 1\). TD(0) updates only state 9. TD(λ) updates all ten at once, by \(\alpha \lambda^{9-s}\) for state \(s\) (with \(\gamma = 1\)): the same backward sweep that n-step methods buy with an n-step buffer, but obtained online and graded smoothly over all n.

import numpy as np

def td_lambda(episode, V, alpha, lam, gamma=1.0, trace="accumulating"):
    """One episode of online tabular TD(lambda). episode: list of (s, r, s_next, terminal)."""
    z = np.zeros_like(V)
    for s, r, s2, terminal in episode:
        delta = r + (0.0 if terminal else gamma * V[s2]) - V[s]
        z *= gamma * lam                       # every trace decays ...
        if trace == "accumulating":
            z[s] += 1.0                        # ... then the current state is marked
        else:
            z[s] = 1.0                         # replacing
        V += alpha * delta * z                 # every state moves in proportion to its trace
    return V, z

# A 10-state corridor walked left to right, reward +1 on leaving state 9.
corridor = [(s, 0.0, s + 1, False) for s in range(9)] + [(9, 1.0, None, True)]
for lam in (0.0, 0.5, 0.9):
    V, _ = td_lambda(corridor, np.zeros(10), alpha=0.5, lam=lam)
    print(lam, V.round(3))      # lambda = 0: only V[9] moves; lambda = 0.9: V[s] = 0.5 * 0.9**(9 - s)

# A loop that visits state 0 four times: accumulating traces exceed 1, replacing traces do not.
loop = [(0, 0.0, 1, False), (1, 0.0, 0, False)] * 3 + [(0, 1.0, None, True)]
for kind in ("accumulating", "replacing"):
    print(kind, td_lambda(loop, np.zeros(2), alpha=0.1, lam=0.9, trace=kind)[1].round(3))

The corridor reproduces the right panel of the figure, and the loop shows accumulating traces reaching about 3 for a state visited four times in quick succession.

What breaks
  • Order of operations. Decay, then mark the current state, then update. Marking before decaying gives the current state a trace of \(\gamma\lambda\) instead of 1, which is a different, worse algorithm.
  • Not resetting traces between episodes. Leftover traces send the first TD errors of a new episode to states from the old one.
  • Accumulating traces plus large α. In a loop a trace can approach \(1/(1 - \gamma\lambda)\), so the effective step on that state is \(\alpha/(1 - \gamma\lambda)\). With λ near 1 that exceeds 1 and the values oscillate or diverge. Use smaller α, replacing traces, or true online TD(λ).
  • Expecting exact equivalence online. The equivalence theorem is about offline updates; online TD(λ) is an approximation whose quality degrades with α.
  • Traces across a terminal boundary. The terminal value is 0 and must not get a trace; with time limits, bootstrap through a truncation and reset the traces afterwards.

SARSA(λ), Q(λ) & True Online TD(λ)

40m video90m practice

Traces carry over to control. SARSA(λ) is the on-policy case and needs nothing new. Off-policy Q-learning with traces has to decide what to do after an exploratory action: cut the trace (Watkins) or keep it and accept a hybrid target (Peng). True online TD(λ) adds dutch traces and one correction term, and reproduces the ideal online λ-return algorithm exactly at the cost of ordinary TD(λ).

SARSA(λ)

Give every state–action pair a trace and use SARSA's TD error:

$$\delta_t = R_{t+1} + \gamma Q(S_{t+1}, A_{t+1}) - Q(S_t, A_t), \qquad z_t(s, a) = \gamma\lambda\, z_{t-1}(s, a) + \mathbb 1\{S_t = s, A_t = a\}, \qquad Q \leftarrow Q + \alpha\,\delta_t\, \mathbf z_t .$$

Its forward view is the λ-return built from n-step SARSA returns (Day 49), and the offline equivalence of Day 51 holds unchanged with pairs in place of states. In the gridworld of Day 49, one episode of SARSA(λ) strengthens every action on the path, by an amount that fades by \(\gamma\lambda\) per step back from the goal: the n-step trail, with every n at once.

Algorithm · tabular SARSA(λ)
  1. Initialise \(Q(s, a)\) arbitrarily, \(Q(\text{terminal}, \cdot) = 0\).
  2. For each episode: \(\mathbf z \leftarrow \mathbf 0\); initialise \(S\); choose \(A\) ε-greedily from \(Q\). Repeat until \(S\) is terminal:
    1. Take \(A\), observe \(R, S'\); choose \(A'\) ε-greedily from \(Q(S', \cdot)\).
    2. \(\delta \leftarrow R + \gamma Q(S', A') - Q(S, A)\) (with \(Q(S', A') = 0\) if \(S'\) is terminal)
    3. \(z(S, A) \leftarrow z(S, A) + 1\) (accumulating) or \(z(S, A) \leftarrow 1\) (replacing).
    4. For all \(s, a\): \(Q(s, a) \leftarrow Q(s, a) + \alpha\,\delta\, z(s, a)\), then \(z(s, a) \leftarrow \gamma\lambda\, z(s, a)\).
    5. \(S \leftarrow S'\), \(A \leftarrow A'\).

This box decays the traces after the update, so the current pair is marked with exactly 1 when its own TD error is applied; that is the same algorithm as Day 51's “decay, then mark, then update” ordering. A common variant for replacing traces also zeroes the traces of the other actions in \(S\), on the grounds that revisiting a state with a different action should erase credit for the old one (Singh & Sutton 1996). The true online version, true online SARSA(λ) (Sutton & Barto §12.7), is usually the best performer of the family with linear features.

Watkins's Q(λ): cut the trace after exploration

For off-policy control, the target policy is greedy. A λ-return consistent with it may follow the actual trajectory only as long as the actions taken are greedy; at the first exploratory action, the greedy policy would have done something else, so the return must stop there and bootstrap with the max. As a recursion, writing \(M_{t+1} = \max_a Q(S_{t+1}, a)\),

$$G_t = R_{t+1} + \gamma\Big[M_{t+1} + \lambda\,\mathbb 1\{A_{t+1} \text{ greedy}\}\,\big(G_{t+1} - M_{t+1}\big)\Big].$$

At greedy steps this is \(R_{t+1} + \gamma[(1 - \lambda) M_{t+1} + \lambda G_{t+1}]\); at an exploratory step it is the one-step Q-learning target. It is tree backup with traces (Day 49), specialised to a greedy target policy: Watkins's Q(λ) is TB(λ) when π is greedy.

Algorithm · Watkins's Q(λ) (Watkins 1989)
  1. As SARSA(λ), but each step: take \(A\), observe \(R, S'\); choose \(A'\) ε-greedily; let \(A^* = \argmax_a Q(S', a)\), with \(A^* \leftarrow A'\) if \(A'\) ties for the max.
  2. \(\delta \leftarrow R + \gamma Q(S', A^*) - Q(S, A)\); \(z(S, A) \leftarrow z(S, A) + 1\).
  3. For all \(s, a\): \(Q(s, a) \leftarrow Q(s, a) + \alpha\,\delta\, z(s, a)\); then \(z(s, a) \leftarrow \gamma\lambda\, z(s, a)\) if \(A' = A^*\), else \(z(s, a) \leftarrow 0\).

The weakness is obvious in the formula: traces only survive runs of greedy actions. With ε-greedy behaviour a non-greedy action comes along roughly every \(1/\varepsilon\) steps, and early in learning, when the greedy action keeps changing, much more often. Much of the advantage over one-step Q-learning disappears exactly when exploration is high. On the other hand the target is consistent with the greedy policy, and after decades as an open problem, Munos et al. (2016) proved convergence of Watkins's Q(λ) as a corollary of their analysis of Retrace(λ).

Peng's Q(λ): never cut, always bootstrap with the max

Peng & Williams (1996) keep the traces and instead make every component of the λ-return bootstrap with the max: the n-step component follows the actual actions for \(n - 1\) steps and then takes \(\max_a Q(S_{t+n}, a)\). The recursion is

$$G_t = R_{t+1} + \gamma\big[(1 - \lambda)\, \max_a Q(S_{t+1}, a) + \lambda\, G_{t+1}\big].$$

Compare it with Watkins's: identical at greedy steps, but Peng's does not stop at an exploratory step. The actions inside each n-step component are the behaviour policy's, so the target is a hybrid: for a fixed exploratory behaviour policy and \(\lambda > 0\) it converges to neither \(q_\pi\) nor \(q_*\) but to something between them. If the behaviour policy is made greedier over time, the hybrid is expected to approach \(q_*\), though for a long time this was not proved. In practice it often learns faster than Watkins's version because no data are thrown away, and Kozuno et al. (2021) revisited it for deep RL, giving conditions on the behaviour policy under which it still reaches an optimal policy and finding it competitive with more conservative corrections. A backward-view implementation needs two TD errors per step (Peng & Williams); with a stored trajectory, as in modern deep RL, the recursion above can simply be computed backwards like the λ-returns of Day 50.

import numpy as np

def watkins_q_lambda_episode(env, Q, rng, alpha=0.1, gamma=1.0, lam=0.9, eps=0.1):
    """One episode of tabular Watkins's Q(lambda) with accumulating traces. Updates Q in place."""
    def act(s):
        if rng.random() < eps:
            return int(rng.integers(Q.shape[1]))
        return int(rng.choice(np.flatnonzero(Q[s] == Q[s].max())))
    z = np.zeros_like(Q)
    (s, _), done, G = env.reset(), False, 0.0
    a = act(s)
    while not done:
        s2, r, terminated, truncated, _ = env.step(a)
        a2 = act(s2)
        greedy = Q[s2, a2] == Q[s2].max()                    # ties for the max count as greedy
        delta = r + (0.0 if terminated else gamma * Q[s2].max()) - Q[s, a]
        z[s, a] += 1.0
        Q += alpha * delta * z
        z = gamma * lam * z if greedy else np.zeros_like(Q)  # cut every trace after exploration
        s, a, G, done = s2, a2, G + r, terminated or truncated
    return G

True online TD(λ)

The online λ-return algorithm of Day 50 is the ideal: at every step it redoes all of the episode's updates with the latest truncated λ-returns. It costs \(O(t)\) per step. Van Seijen & Sutton (2014) found that, for linear \(\hat v(s) = \mathbf w^\top \mathbf x(s)\), the weight vectors it produces can be computed exactly with an \(O(d)\) update:

$$\begin{aligned} \delta_t &= R_{t+1} + \gamma\, \mathbf w_t^\top \mathbf x_{t+1} - \mathbf w_t^\top \mathbf x_t, \\ \mathbf z_t &= \gamma\lambda\, \mathbf z_{t-1} + \big(1 - \alpha\gamma\lambda\, \mathbf z_{t-1}^\top \mathbf x_t\big)\, \mathbf x_t, \\ \mathbf w_{t+1} &= \mathbf w_t + \alpha\,\delta_t\, \mathbf z_t + \alpha\,\big(\mathbf w_t^\top \mathbf x_t - \mathbf w_{t-1}^\top \mathbf x_t\big)\big(\mathbf z_t - \mathbf x_t\big). \end{aligned}$$
Theorem · exact equivalence (van Seijen & Sutton 2014; van Seijen et al. 2016)

With linear function approximation, true online TD(λ) produces exactly the same sequence of weight vectors \(\mathbf w_0, \mathbf w_1, \dots\) as the online λ-return algorithm, for every \(\alpha\), \(\gamma\) and \(\lambda\). In the tabular case \(\mathbf x\) is one-hot.

Compared with TD(λ), there are two changes. The trace is the dutch trace of Day 51. And the last term corrects for the fact that \(\mathbf w\) changed between the time \(\mathbf x_t\)'s value was last used as a bootstrap (\(\mathbf w_{t-1}^\top \mathbf x_t\)) and now (\(\mathbf w_t^\top \mathbf x_t\)); if the weights stop changing, it vanishes. With \(V = \mathbf w^\top \mathbf x\), the update is usually written with a stored scalar \(V_{\text{old}}\):

Algorithm · true online TD(λ) (Sutton & Barto §12.5)
  1. For each episode: observe \(\mathbf x\) for the initial state; \(\mathbf z \leftarrow \mathbf 0\); \(V_{\text{old}} \leftarrow 0\). Repeat until terminal:
    1. Act with \(\pi\); observe \(R\) and the next feature vector \(\mathbf x'\) (\(\mathbf x' = \mathbf 0\) at a terminal state).
    2. \(V \leftarrow \mathbf w^\top \mathbf x\); \(V' \leftarrow \mathbf w^\top \mathbf x'\); \(\delta \leftarrow R + \gamma V' - V\).
    3. \(\mathbf z \leftarrow \gamma\lambda\, \mathbf z + (1 - \alpha\gamma\lambda\, \mathbf z^\top \mathbf x)\, \mathbf x\).
    4. \(\mathbf w \leftarrow \mathbf w + \alpha\,(\delta + V - V_{\text{old}})\, \mathbf z - \alpha\,(V - V_{\text{old}})\, \mathbf x\).
    5. \(V_{\text{old}} \leftarrow V'\); \(\mathbf x \leftarrow \mathbf x'\).
import numpy as np

def true_online_td_lambda(episodes, n_states, alpha, lam, gamma=1.0):
    """Tabular true online TD(lambda): one-hot features, dutch traces, one correction term.
    episodes: lists of (s, r, s_next, terminal)."""
    w = np.zeros(n_states)
    for episode in episodes:
        z, v_old = np.zeros(n_states), 0.0
        for s, r, s2, terminal in episode:
            v = w[s]
            v_next = 0.0 if terminal else w[s2]
            delta = r + gamma * v_next - v
            zs = z[s]                                     # z_{t-1} . x_t for a one-hot x_t
            z *= gamma * lam
            z[s] += 1.0 - alpha * gamma * lam * zs        # dutch trace
            w += alpha * (delta + v - v_old) * z
            w[s] -= alpha * (v - v_old)                   # the "- alpha (V - V_old) x" term
            v_old = v_next
    return w

def random_walk_episodes(n_episodes, rng, n=19):
    out = []
    for _ in range(n_episodes):
        s, ep = n // 2, []
        while True:
            s2 = s + (1 if rng.random() < 0.5 else -1)
            if s2 < 0 or s2 >= n:                         # leave on the left (-1) or right (+1)
                ep.append((s, 1.0 if s2 >= n else -1.0, None, True))
                break
            ep.append((s, 0.0, s2, False))
            s = s2
        out.append(ep)
    return out

The equivalence is a statement about linear function approximation. With neural networks there is no cheap exact version, which is one reason deep RL computes λ-returns forward over stored trajectories (GAE, Day 88) instead of using traces.

Practical guidance on λ

  • Intermediate λ is usually best. Across the tasks Sutton & Barto summarise at the end of Chapter 12, performance is U-shaped in λ, with good values commonly around 0.8–0.95 and λ = 1 often clearly worse. Start at 0.9.
  • Tune α and λ together. The effective step size grows with the trace, roughly as \(\alpha/(1 - \gamma\lambda)\) under frequent revisits with accumulating traces, so larger λ wants smaller α.
  • Prefer replacing or dutch traces in control, and true online TD(λ) or true online SARSA(λ) with linear features, which are both more accurate and less sensitive to α.
  • Raise λ when the state is not quite Markov or rewards are long delayed; lower it when rewards and transitions are very noisy.
  • Off-policy: Watkins's cut is safe but wasteful at high ε; Peng's is fast but biased towards the behaviour policy; tree-backup-style and truncated-ratio corrections (Retrace, V-trace, Day 121) are the principled middle ground.
  • In deep RL λ appears as GAE's λ, typically 0.95 (Day 88), and in λ-returns computed over replayed or rolled-out sequences.
What breaks
  • Watkins's Q(λ) at high ε. Traces are cut every few steps, and the method quietly degrades to one-step Q-learning.
  • Peng's Q(λ) with a fixed exploratory policy. It does not converge to \(q_*\); the bias grows with λ and with how different the behaviour policy is from greedy.
  • Accumulating traces in control with loops. Revisiting pairs inflates traces and can destabilise SARSA(λ) at large α; use replacing or dutch traces.
  • True online bookkeeping. \(V_{\text{old}}\) must be reset at the start of each episode and set to \(V'\), not \(V\), at the end of each step. Getting either wrong produces an algorithm that still learns, just not the exact one, so test against the brute-force version.
  • Assuming exactness beyond linear FA. The equivalence proof uses linearity; with nonlinear approximators the update is only a heuristic.

The framework

The one-step methods share a class and differ only in the bootstrap value. Note the two rules from earlier lessons built into the interface: SARSA-style agents commit to \(A'\) before the update, while the others choose the next action from the updated table; and the bootstrap is dropped only on terminated, never on truncated.

import numpy as np

class TabularAgent:
    """SARSA, Expected SARSA, Q-learning and Double Q-learning: everything is shared except the target."""
    def __init__(self, n_states, n_actions, method, alpha=0.5, gamma=1.0, eps=0.1, seed=0):
        self.Q = np.zeros((n_states, n_actions))
        self.Q2 = np.zeros((n_states, n_actions)) if method == "double_q" else None
        self.method, self.alpha, self.gamma, self.eps = method, alpha, gamma, eps
        self.rng = np.random.default_rng(seed)
        self.needs_next_action = method == "sarsa"          # SARSA's target uses A'

    def probs(self, q):                                     # epsilon-greedy pi(. | s), ties split
        p = np.full(len(q), self.eps / len(q))
        best = np.flatnonzero(q == q.max())
        p[best] += (1.0 - self.eps) / len(best)
        return p

    def table(self):                                        # what the policy acts on
        return self.Q if self.Q2 is None else self.Q + self.Q2

    def act(self, s):
        return int(self.rng.choice(self.Q.shape[1], p=self.probs(self.table()[s])))

    def start_episode(self):
        pass                                                # n-step / lambda agents reset buffers here

    def update(self, s, a, r, s2, a2, terminated, truncated):
        Q = Qe = self.Q                                     # table to update, table to evaluate with
        if self.method == "double_q":
            Q, Qe = (self.Q, self.Q2) if self.rng.random() < 0.5 else (self.Q2, self.Q)
        if terminated:
            nxt = 0.0                                       # never bootstrap through a termination
        elif self.method == "sarsa":
            nxt = Q[s2, a2]
        elif self.method == "expected_sarsa":
            nxt = self.probs(Q[s2]) @ Q[s2]
        elif self.method == "q_learning":
            nxt = Q[s2].max()
        else:                                               # double Q: select with Q, evaluate with Qe
            nxt = Qe[s2, self.rng.choice(np.flatnonzero(Q[s2] == Q[s2].max()))]
        Q[s, a] += self.alpha * (r + self.gamma * nxt - Q[s, a])

import numpy as np
import gymnasium as gym

def train(env_id, agent, episodes, seed, env_kwargs=None):
    """One run of one agent: the online return of the behaviour policy in every episode."""
    env = gym.make(env_id, **(env_kwargs or {}))
    returns = np.zeros(episodes)
    for ep in range(episodes):
        s, _ = env.reset(seed=seed * 100_000 + ep)          # reproducible, distinct per episode
        agent.start_episode()
        a, done = agent.act(s), False
        while not done:
            s2, r, terminated, truncated, _ = env.step(a)
            a2 = agent.act(s2) if agent.needs_next_action else None   # on-policy: commit to A' first
            agent.update(s, a, r, s2, a2, terminated, truncated)
            if a2 is None:
                a2 = agent.act(s2)                          # off-policy: act on the updated table
            s, a, done = s2, a2, terminated or truncated
            returns[ep] += r
    env.close()
    return returns

def evaluate(env_id, Q, episodes, seed, max_steps=1_000, env_kwargs=None):
    """Greedy policy on a frozen table with random tie-breaking. Returns (mean return, time-out rate)."""
    env, rng = gym.make(env_id, **(env_kwargs or {})), np.random.default_rng(seed)
    total, timeouts = 0.0, 0
    for ep in range(episodes):
        s, _ = env.reset(seed=seed + ep)
        for _ in range(max_steps):
            s, r, terminated, truncated, _ = env.step(int(rng.choice(np.flatnonzero(Q[s] == Q[s].max()))))
            total += r
            if terminated or truncated:
                break
        else:
            timeouts += 1                                   # a looping greedy policy: report it
    env.close()
    return total / episodes, timeouts / episodes

Sanity checks before you trust a curve
  • Q-learning on the cliff with ε = 0.1 and α = 0.5 must reach a greedy return of −13 and an online return near −50. If not, look at the terminal handling and at when the next action is chosen.
  • n-step SARSA with n = 1 must reproduce SARSA exactly with the same seed, and SARSA(λ) with λ = 0 likewise.
  • Expected SARSA with a greedy target must reproduce Q-learning's table exactly.
  • On Taxi and FrozenLake, a run truncated by the time limit must still bootstrap; check by counting how many updates had truncated set and terminated unset.
  • Every curve in the figure must come from results/ files written by benchmark.py with a recorded config hash, not from a notebook cell.
What breaks in benchmarks like this
  • Comparing at one shared α. Each method has its own best step size; a shared α mostly measures which method that α happens to suit.
  • Averaging time-outs into the greedy mean. One looping seed at −1,000 dominates 49 good ones. Report time-out rates separately, or use the IQM.
  • Tuning and reporting on the same seeds. This inflates every tuned method, by more for the methods with more hyperparameters.
  • Smoothing away the story. A 100-episode moving average hides Double Q's slow start and Q-learning's cliff falls. Keep the window short and show the band.
