Function Approximation

Every method so far stored one number per state or state–action pair. This module replaces the table with a parameterized function, which is the only way reinforcement learning reaches problems with continuous or astronomically many states. It is also where the theory gets hard: the TD target stops being a proper gradient, only linear methods keep clean guarantees, and off-policy bootstrapping with function approximation can diverge. Modules 3–6 supply the algorithms being approximated; Module 8 puts a neural network where the linear features were and inherits every problem met here.

DAY 61

Why Function Approximation

35m video60m practice

A table learns about one state at a time, so it has to visit every state, many times. Function approximation replaces the table with a function \(\hat v(s, \mathbf w)\) that has far fewer parameters than there are states, so every update generalizes. The price is that no setting of \(\mathbf w\) gets every state right, and we have to say which states matter, through a weighting \(\mu\).

Where tables die

Memory is rarely the binding constraint: a table of \(10^6\) states × 4 actions in float64 is 32 MB. Experience is. A table learns nothing about a state until it visits it, and each entry needs many visits to average out noise, so the data required grows at least linearly with the number of states. Past roughly a million states, or as soon as states are continuous, tabular methods stop being practical long before they stop fitting in memory.

Generalization across states

The fix is to let experience with one state inform the estimates of others. View each update \(s \mapsto u\) as a training example for a supervised learner: input \(S_t\), target \(U_t\) (a return, or a bootstrapped estimate of one). Any regression method could be used in principle, but RL makes two demands most supervised methods don't expect. Data arrive one example at a time, from a distribution the learner's own policy shapes, so the method must learn online. And the targets are nonstationary: bootstrapped targets change as the estimates change, and in control the policy, and hence the true values, change too.

The parameter vector

We approximate \(v_\pi\) with a parameterized function \(\hat v(s, \mathbf w) \approx v_\pi(s)\), where \(\mathbf w \in \R^d\) and typically \(d \ll |\mathcal S|\). The function might be linear in features of the state (Days 63–65), a neural network (Module 8), or a decision tree. Because there are fewer weights than states, changing one weight changes the estimated value of many states, and making one state's estimate more accurate generally makes others' less accurate. That is the whole difference from the tabular case, where every state has its own parameter and all of them can be right at once.

The value-error objective and μ

Definition · mean squared value error

Given a state weighting \(\mu(s) \ge 0\) with \(\sum_s \mu(s) = 1\),

$$\overline{\text{VE}}(\mathbf w) \doteq \sum_{s \in \mathcal S} \mu(s)\,\big[v_\pi(s) - \hat v(s, \mathbf w)\big]^2 .$$

\(\sqrt{\overline{\text{VE}}}\) is the \(\mu\)-weighted root-mean-square error of the value estimates.

Because we can't make every state correct, \(\mu\) says how much we care about each one, and the natural choice is the fraction of time spent in it. Two caveats travel with this objective. First, it is not obviously the right one: what we ultimately want is a good policy, and a small average error can hide a large error in one rarely visited but decisive state. Second, for nonlinear \(\hat v\) we can usually only reach a local minimum. It is still the objective the theory of Days 62–66 is built on.

The on-policy distribution

When we evaluate \(\pi\) from experience generated by \(\pi\), \(\mu\) is the on-policy distribution. In a continuing task it is the stationary distribution of the chain \(P_\pi\) (Day 6): \(\mu^\top P_\pi = \mu^\top\). Episodic tasks need a little more care, because the distribution depends on where episodes start.

Derivation · episodic on-policy distribution (S&B §9.2)

Let \(h(s)\) be the probability that an episode starts in \(s\), and \(\eta(s)\) the expected number of time steps spent in \(s\) in one episode. Time is spent in \(s\) either because an episode starts there or because the agent arrives from some state \(\bar s\) it was in on the previous step:

$$\eta(s) = h(s) + \sum_{\bar s} \eta(\bar s) \sum_a \pi(a \mid \bar s)\, p(s \mid \bar s, a), \qquad \mu(s) = \frac{\eta(s)}{\sum_{s'} \eta(s')}.$$

In matrix form, with \(P_\pi\) restricted to non-terminal states (rows sum to less than 1 where the episode can end), \(\boldsymbol\eta = \mathbf h + P_\pi^\top \boldsymbol\eta\), so \(\boldsymbol\eta = (I - P_\pi^\top)^{-1}\mathbf h\). This is the fundamental matrix of an absorbing chain from Day 6. With discounting, S&B suggest treating it as a form of termination by multiplying the second term by \(\gamma\).

S&B's 1000-state random walk (Example 9.1) is the test bed for the next few days. States are numbered 1 to 1000 and every episode starts in state 500. Each step jumps to one of the 100 states to the left or the 100 to the right, all equally likely; jumps that would pass an end terminate the episode there, with reward −1 on the left and +1 on the right. All other rewards are 0 and \(\gamma = 1\).

import numpy as np

N, K, START = 1000, 100, 499          # states 1..1000 stored as 0..999; episodes start in state 500
P = np.zeros((N, N))                  # transitions between non-terminal states only
r = np.zeros(N)                       # expected reward on leaving each state
for s in range(N):
    for d in range(1, K + 1):
        for s2, R in ((s - d, -1.0), (s + d, 1.0)):
            if 0 <= s2 < N:
                P[s, s2] += 0.5 / K
            else:
                r[s] += 0.5 / K * R   # jumping off an end terminates with reward -1 or +1

h = np.zeros(N); h[START] = 1.0       # start-state distribution
eta = np.linalg.solve(np.eye(N) - P.T, h)    # eta = h + P^T eta: expected visits per episode
mu = eta / eta.sum()                         # the on-policy distribution
v_pi = np.linalg.solve(np.eye(N) - P, r)     # true values, gamma = 1

print(f"expected episode length {eta.sum():.1f}, mu peaks at state {mu.argmax() + 1}")
print(f"v(1) = {v_pi[0]:.3f}, v(500) = {v_pi[START]:.3f}, v(1000) = {v_pi[-1]:.3f}")

Episodes last about 83 steps on average. \(\mu\) has a spike of about 0.0137 at the start state, which every episode visits at least once, on top of a tent shape that peaks near 0.0017 beside it: the two scale marks on S&B's Figure 9.1. \(v_\pi\) runs from about −0.92 at state 1 to +0.92 at state 1000, nearly linearly except near the ends. Day 62 plots both.

Partial observability, handled implicitly

Function approximation also covers a case the tabular theory assumed away. If the parameterized form cannot let \(\hat v\) depend on some aspect of the state, it is just as if that aspect were unobservable (S&B Ch. 9 introduction). A linear value function of a feature vector that omits velocity treats two states that differ only in velocity as the same state, exactly as an agent that can't observe velocity would. So all the results of this module apply unchanged when the features are only a partial view of the state.

Intuition · what FA can and can't do about hidden state

Function approximation can ignore information gracefully: aliased states share one estimate, which converges to some average of their true values. It cannot recover information. If the current observation doesn't determine the future, no function of the current observation fixes that; you need memory, such as stacked frames (Day 74) or a recurrent state (Day 121).

What breaks
  • μ moves with the policy. In control, every policy improvement changes the on-policy distribution, and hence the objective the approximator is fitting.
  • Low VE is not a good policy. The objective averages; a large error in a rare state just before a cliff costs almost nothing in \(\overline{\text{VE}}\) and everything in return.
  • Interference. In a table, updates are isolated. With generalization, a burst of updates in one region (the agent stuck in a corner) can overwrite what was learned elsewhere.
  • Off-policy data weights the wrong states. If experience comes from a behaviour policy, its distribution is the one implicitly being fitted. Day 69 shows how badly that can go.

DAY 62

SGD & Semi-Gradient Methods

45m video90m practice

Stochastic gradient descent on \(\overline{\text{VE}}\) needs the true value \(v_\pi(S_t)\) as its target. Replace it with an unbiased sample, the return, and you have a true gradient method with the usual guarantees. Replace it with a bootstrapped TD target and the update ignores how that target depends on \(\mathbf w\): it becomes a semi-gradient method, faster and fully online, but no longer the gradient of any objective.

SGD on the value error

Derivation

Differentiate the objective of Day 61:

$$\nabla \overline{\text{VE}}(\mathbf w) = -2\sum_s \mu(s)\,\big[v_\pi(s) - \hat v(s, \mathbf w)\big]\,\nabla \hat v(s, \mathbf w).$$

If states arrive distributed according to \(\mu\), as they do on-policy, then \(-2\big[v_\pi(S_t) - \hat v(S_t, \mathbf w)\big]\nabla\hat v(S_t, \mathbf w)\) is an unbiased sample of this gradient. A step of size \(\tfrac12\alpha\) against it gives

$$\mathbf w_{t+1} = \mathbf w_t + \alpha\,\big[v_\pi(S_t) - \hat v(S_t, \mathbf w_t)\big]\,\nabla \hat v(S_t, \mathbf w_t).$$

We don't know \(v_\pi(S_t)\), so substitute a target \(U_t\):

$$\mathbf w_{t+1} = \mathbf w_t + \alpha\,\big[U_t - \hat v(S_t, \mathbf w_t)\big]\,\nabla \hat v(S_t, \mathbf w_t).$$

If \(U_t\) is unbiased, \(\E[U_t \mid S_t = s] = v_\pi(s)\), then the expected update is still exactly \(-\tfrac12\alpha\nabla\overline{\text{VE}}\), and with step sizes satisfying the Robbins–Monro conditions (Day 5) \(\mathbf w_t\) converges to a local optimum (S&B §9.3).

Gradient Monte Carlo: a true gradient method

The Monte Carlo return \(G_t\) is an unbiased estimate of \(v_\pi(S_t)\) by definition, so plugging \(U_t = G_t\) into the update gives a genuine SGD method on \(\overline{\text{VE}}\).

Algorithm · Gradient Monte Carlo prediction
  1. Input: the policy \(\pi\), a differentiable \(\hat v(s, \mathbf w)\), a step size \(\alpha > 0\). Initialize \(\mathbf w\) (for example to 0).
  2. Loop for each episode:
    1. Generate an episode \(S_0, A_0, R_1, \dots, S_{T-1}, A_{T-1}, R_T\) with \(\pi\).
    2. For \(t = 0, 1, \dots, T-1\): \(\mathbf w \leftarrow \mathbf w + \alpha\big[G_t - \hat v(S_t, \mathbf w)\big]\nabla\hat v(S_t, \mathbf w)\).

Why the TD target makes it semi-gradient

Now use the bootstrapped target \(U_t = R_{t+1} + \gamma\hat v(S_{t+1}, \mathbf w)\). It is biased (it depends on the current estimate), but the real problem is structural.

Derivation · the dropped term

The TD update is

$$\mathbf w \leftarrow \mathbf w + \alpha\,\delta_t\,\nabla\hat v(S_t, \mathbf w), \qquad \delta_t = R_{t+1} + \gamma\hat v(S_{t+1}, \mathbf w) - \hat v(S_t, \mathbf w).$$

This is SGD on \(\tfrac12\delta_t^2\) as if the target were a constant. The full gradient of that squared error is

$$\nabla\,\tfrac12\delta_t^2 = \delta_t\,\big[\gamma\nabla\hat v(S_{t+1}, \mathbf w) - \nabla\hat v(S_t, \mathbf w)\big],$$

and semi-gradient TD keeps only the second half: it moves the estimate towards the target, but ignores the effect the same step has on the target. Hence "semi-gradient".

Result · the TD update is not a gradient field

For a linear \(\hat v = \mathbf w^\top\mathbf x(s)\) (Day 63), the expected semi-gradient TD update is \(\mathbf b - A\mathbf w\) with \(A = \E\big[\mathbf x_t(\mathbf x_t - \gamma\mathbf x_{t+1})^\top\big]\). A vector field \(F(\mathbf w)\) is the gradient of some scalar function only if its Jacobian is symmetric. Here the Jacobian is \(-A\), and \(A\) is not symmetric in general, because \(\E[\mathbf x_t\mathbf x_{t+1}^\top] \ne \E[\mathbf x_{t+1}\mathbf x_t^\top]\). So there is no objective \(J\) with \(-\nabla J(\mathbf w) = \mathbf b - A\mathbf w\): semi-gradient TD is not descending anything.

What you lose and what you keep

  • Lost: the guarantee that a well-defined objective decreases, and with it the general convergence argument. Tsitsiklis & Van Roy (1997) give an example in which semi-gradient TD with a nonlinear approximator diverges even on-policy, and Day 69 shows linear semi-gradient TD diverging off-policy.
  • Kept: with linear features and on-policy data, semi-gradient TD provably converges, to a point called the TD fixed point (Day 63).
  • Gained: everything that made TD attractive in Module 5. Updates are online and immediate, work in continuing tasks, and usually learn much faster than Monte Carlo because the targets have far lower variance.

Why not take the full gradient of \(\delta_t^2\)? That is the residual-gradient method (Baird 1995), and it does descend an objective, the mean squared TD error. But with stochastic transitions, the expected squared TD error is not the squared Bellman error, and estimating the latter's gradient without bias needs two independent samples of \(S_{t+1}\) from the same \(S_t\), which a real environment can't provide. It also tends to converge slowly, and S&B (§11.5) show it can converge to clearly wrong values. Practical methods use the semi-gradient.

Algorithm · Semi-gradient TD(0) prediction
  1. Input: \(\pi\), a differentiable \(\hat v\) with \(\hat v(\text{terminal}, \cdot) = 0\), a step size \(\alpha > 0\). Initialize \(\mathbf w\).
  2. Loop for each episode: initialize \(S\); loop for each step:
    1. \(A \sim \pi(\cdot \mid S)\); take \(A\), observe \(R, S'\).
    2. \(\mathbf w \leftarrow \mathbf w + \alpha\big[R + \gamma\hat v(S', \mathbf w) - \hat v(S, \mathbf w)\big]\nabla\hat v(S, \mathbf w)\), with \(\hat v(S', \mathbf w) = 0\) if \(S'\) is terminal.
    3. \(S \leftarrow S'\), until \(S\) is terminal.

State aggregation, the simplest approximator

Partition the states into groups and give each group one weight: \(\hat v(s, \mathbf w) = w_{g(s)}\). The gradient \(\nabla\hat v(s, \mathbf w)\) is 1 in component \(g(s)\) and 0 elsewhere, so each update moves only the weight of the current state's group. Aggregation is the special case of linear function approximation (Day 63) with one-hot group features.

Derivation · what gradient MC converges to under aggregation

\(\overline{\text{VE}}\) separates by group: \(\sum_g \sum_{s \in g} \mu(s)\,(v_\pi(s) - w_g)^2\). Setting the derivative with respect to \(w_g\) to zero,

$$w_g^* = \frac{\sum_{s \in g} \mu(s)\, v_\pi(s)}{\sum_{s \in g} \mu(s)},$$

the \(\mu\)-weighted average of the true values within the group. Within a group, states visited more often pull the estimate harder.

import numpy as np

N, K, GROUPS = 1000, 100, 10
rng = np.random.default_rng(0)

def episode():
    """One episode of the 1000-state random walk: visited states (0..999) and the final reward."""
    s, states = 499, []                          # start in state 500
    while 0 <= s < N:
        states.append(s)
        s += int(rng.integers(1, K + 1)) * (1 if rng.random() < 0.5 else -1)
    return states, (1.0 if s >= N else -1.0)

group = lambda s: s * GROUPS // N                # one-hot group features: grad v_hat = x(s)

def gradient_mc(n_episodes=100_000, alpha=2e-5):
    w = np.zeros(GROUPS)
    for _ in range(n_episodes):
        states, G = episode()                    # gamma = 1 and only the last reward is non-zero,
        for s in states:                         # so G_t = G for every t
            w[group(s)] += alpha * (G - w[group(s)])
    return w

def semi_gradient_td(n_episodes=100_000, alpha=2e-4):
    w = np.zeros(GROUPS)
    for _ in range(n_episodes):
        states, R = episode()
        for t, s in enumerate(states):
            if t + 1 < len(states):              # reward 0: bootstrap from the next state's estimate
                target = w[group(states[t + 1])]
            else:                                # final transition: reward R, v_hat(terminal) = 0
                target = R
            w[group(s)] += alpha * (target - w[group(s)])
    return w

print("MC:", gradient_mc().round(2))
print("TD:", semi_gradient_td().round(2))

About a minute and a half per method in pure Python; S&B use \(\alpha = 2 \times 10^{-5}\) for gradient MC. The TD loop replays a stored episode, which is equivalent to updating online because the walk doesn't depend on \(\mathbf w\). In the reference run the learned weights matched the exact solutions in the figure to about two decimal places.

What breaks
  • Gradients through the target. In autodiff code, forgetting no_grad or detach on the TD target turns semi-gradient TD into the residual-gradient method, a different algorithm with different fixed points (Day 9).
  • Nonlinear approximators can diverge even on-policy. The linear convergence result of Day 63 does not extend to neural networks.
  • "TD converged" doesn't mean "TD is accurate". TD's limit is a different point from the \(\overline{\text{VE}}\) minimum, and can be noticeably worse, as in the figure.
  • Step size depends on the features. With one-hot groups, \(\alpha\) is the per-group step. With features of larger norm, the same \(\alpha\) moves \(\hat v\) much further (Day 63 gives the rule of thumb).

DAY 63

Linear Function Approximation

40m video90m practice

With \(\hat v = \mathbf w^\top\mathbf x(s)\) the gradient is simply the feature vector, gradient Monte Carlo finds the global minimum of \(\overline{\text{VE}}\), and semi-gradient TD provably converges to a single point, the TD fixed point \(\mathbf w_{TD} = A^{-1}\mathbf b\), whose error is within a factor \(1/(1-\gamma)\) of the best possible. This is the only setting in which function approximation and bootstrapping come with clean guarantees.

Feature vectors and linear values

Definition · linear value function

Each state is represented by a feature vector \(\mathbf x(s) = \big(x_1(s), \dots, x_d(s)\big)^\top\), and

$$\hat v(s, \mathbf w) = \mathbf w^\top\mathbf x(s) = \sum_{i=1}^d w_i\, x_i(s), \qquad \nabla\hat v(s, \mathbf w) = \mathbf x(s).$$

Stack the feature vectors as the rows of \(X \in \R^{|\mathcal S| \times d}\) and let \(D = \operatorname{diag}(\mu)\). Then the vector of all estimates is \(X\mathbf w\).

The general SGD update becomes \(\mathbf w \leftarrow \mathbf w + \alpha\big[U_t - \mathbf w^\top\mathbf x(S_t)\big]\mathbf x(S_t)\). \(\overline{\text{VE}}(\mathbf w) = (\mathbf v_\pi - X\mathbf w)^\top D(\mathbf v_\pi - X\mathbf w)\) is a convex quadratic, so if the features are linearly independent on the states with \(\mu > 0\) it has exactly one minimum, the \(\mu\)-weighted least-squares fit

$$\mathbf w_{\overline{\text{VE}}} = (X^\top DX)^{-1}X^\top D\,\mathbf v_\pi,$$

and linear gradient Monte Carlo converges to it under the usual step-size conditions. There are no local minima to worry about.

The TD fixed point

Derivation · the expected TD update

Write \(\mathbf x_t = \mathbf x(S_t)\). Linear semi-gradient TD(0) is

$$\mathbf w_{t+1} = \mathbf w_t + \alpha\big(R_{t+1} + \gamma\mathbf w_t^\top\mathbf x_{t+1} - \mathbf w_t^\top\mathbf x_t\big)\mathbf x_t = \mathbf w_t + \alpha\Big(R_{t+1}\mathbf x_t - \mathbf x_t(\mathbf x_t - \gamma\mathbf x_{t+1})^\top\mathbf w_t\Big).$$

In steady state on-policy, take the expectation given \(\mathbf w_t\):

$$\E[\mathbf w_{t+1} \mid \mathbf w_t] = \mathbf w_t + \alpha(\mathbf b - A\mathbf w_t), \qquad \mathbf b \doteq \E[R_{t+1}\mathbf x_t] \in \R^d, \quad A \doteq \E\big[\mathbf x_t(\mathbf x_t - \gamma\mathbf x_{t+1})^\top\big] \in \R^{d \times d}.$$

If the iteration converges, it must be to a point where \(\mathbf b - A\mathbf w = 0\):

$$\mathbf w_{TD} = A^{-1}\mathbf b.$$

In matrix form, with \(\mathbf r\) the expected one-step rewards and \(P\) the state-transition matrix under \(\pi\): \(A = X^\top D(I - \gamma P)X\) and \(\mathbf b = X^\top D\mathbf r\).

Why it converges on-policy

Theorem · linear TD(0) converges on-policy (Tsitsiklis & Van Roy 1997; S&B §9.4)

If \(P\) is irreducible and \(\mu\) is its stationary distribution (so every \(\mu(s) > 0\)), \(\gamma < 1\), and \(X\) has full column rank, then \(A\) is positive definite. Hence the expected update converges to \(\mathbf w_{TD}\) for any sufficiently small \(\alpha\), and the stochastic algorithm converges to it with probability 1 under the usual decreasing step sizes.

Proof sketch

Positive definite implies convergence. \(\mathbf w_{t+1} - \mathbf w_{TD} = (I - \alpha A)(\mathbf w_t - \mathbf w_{TD})\), which shrinks to zero when every eigenvalue of \(I - \alpha A\) lies inside the unit circle. If \(\mathbf y^\top A\mathbf y > 0\) for all \(\mathbf y \ne 0\), every eigenvalue \(\lambda\) of \(A\) has \(\operatorname{Re}\lambda > 0\), so \(|1 - \alpha\lambda| < 1\) for small enough \(\alpha\).

The key matrix. \(\mathbf y^\top A\mathbf y = (X\mathbf y)^\top M(X\mathbf y)\) with \(M = D(I - \gamma P)\), so it suffices that \(M\) is positive definite. Its diagonal entries \(\mu_i(1 - \gamma P_{ii})\) are positive and its off-diagonal entries \(-\gamma\mu_i P_{ij}\) are non-positive. Its row sums are \(D(I - \gamma P)\mathbf 1 = (1 - \gamma)\boldsymbol\mu > 0\). Its column sums are

$$\mathbf 1^\top D(I - \gamma P) = \boldsymbol\mu^\top - \gamma\boldsymbol\mu^\top P = (1 - \gamma)\boldsymbol\mu^\top > 0,$$

using stationarity, \(\boldsymbol\mu^\top P = \boldsymbol\mu^\top\). The symmetric part \(\tfrac12(M + M^\top)\) therefore has a positive diagonal, non-positive off-diagonals and positive row sums: it is strictly diagonally dominant, hence positive definite by Gershgorin's theorem. Since \(\mathbf y^\top M\mathbf y = \mathbf y^\top\tfrac12(M + M^\top)\mathbf y\), \(M\) is positive definite, and so is \(A\) when \(X\) has full column rank. ∎

The column-sum step is the only place the proof uses the fact that the data are on-policy. Replace \(\mu\) by some other distribution (that of a behaviour policy) and \(\boldsymbol\mu^\top P \ne \boldsymbol\mu^\top\); the column sums can turn negative, \(A\) can lose positive definiteness, and the iteration can diverge. That is Day 69.

How good is the fixed point?

Theorem · TD error bound (S&B eq. 9.14) $$\overline{\text{VE}}(\mathbf w_{TD}) \;\le\; \frac{1}{1-\gamma}\,\min_{\mathbf w}\overline{\text{VE}}(\mathbf w).$$
Proof

Write \(\|\mathbf v\|_\mu^2 = \sum_s \mu(s)v(s)^2\), so \(\overline{\text{VE}}(\mathbf w) = \|\mathbf v_\pi - X\mathbf w\|_\mu^2\). Let \(\Pi = X(X^\top DX)^{-1}X^\top D\) be the \(\mu\)-weighted projection onto the representable functions \(\{X\mathbf w\}\), so \(\Pi\mathbf v_\pi = X\mathbf w_{\overline{\text{VE}}}\), and let \(T\mathbf v = \mathbf r + \gamma P\mathbf v\) be the Bellman operator, with \(T\mathbf v_\pi = \mathbf v_\pi\).

Step 1: the TD fixed point is a projected Bellman fixed point. With \(\hat{\mathbf v} = X\mathbf w_{TD}\), the condition \(A\mathbf w = \mathbf b\) reads \(X^\top D(\mathbf r + \gamma P\hat{\mathbf v} - \hat{\mathbf v}) = 0\): the Bellman residual is \(\mu\)-orthogonal to every feature. Hence \(\Pi(T\hat{\mathbf v} - \hat{\mathbf v}) = 0\), that is, \(\hat{\mathbf v} = \Pi T\hat{\mathbf v}\).

Step 2: \(T\) is a \(\gamma\)-contraction in \(\|\cdot\|_\mu\). \(\|T\mathbf u - T\mathbf v\|_\mu = \gamma\|P(\mathbf u - \mathbf v)\|_\mu\), and for any \(\mathbf z\), by Jensen's inequality and then stationarity,

$$\|P\mathbf z\|_\mu^2 = \sum_s \mu(s)\Big(\sum_{s'}P_{ss'}z_{s'}\Big)^2 \le \sum_s \mu(s)\sum_{s'}P_{ss'}z_{s'}^2 = \sum_{s'}(\boldsymbol\mu^\top P)_{s'}\,z_{s'}^2 = \|\mathbf z\|_\mu^2.$$

Step 3: Pythagoras. \(\mathbf v_\pi - \Pi\mathbf v_\pi\) is \(\mu\)-orthogonal to the subspace and \(\Pi\mathbf v_\pi - \hat{\mathbf v}\) lies in it, so

$$\|\mathbf v_\pi - \hat{\mathbf v}\|_\mu^2 = \|\mathbf v_\pi - \Pi\mathbf v_\pi\|_\mu^2 + \|\Pi\mathbf v_\pi - \hat{\mathbf v}\|_\mu^2.$$

For the second term, \(\Pi\mathbf v_\pi - \hat{\mathbf v} = \Pi T\mathbf v_\pi - \Pi T\hat{\mathbf v}\), and \(\Pi\) is non-expansive in \(\|\cdot\|_\mu\), so it is at most \(\gamma^2\|\mathbf v_\pi - \hat{\mathbf v}\|_\mu^2\). Rearranging,

$$\overline{\text{VE}}(\mathbf w_{TD}) \le \frac{1}{1-\gamma^2}\,\min_{\mathbf w}\overline{\text{VE}}(\mathbf w) \le \frac{1}{1-\gamma}\,\min_{\mathbf w}\overline{\text{VE}}(\mathbf w),$$

since \(1 - \gamma^2 = (1 - \gamma)(1 + \gamma) \ge 1 - \gamma\). ∎

The bound is loose when \(\gamma\) is close to 1 (a factor of 100 in S&B's form at \(\gamma = 0.99\), about 50 in the \(1/(1-\gamma^2)\) form), and in practice TD is often much closer to the optimum than that. It still matters: it says that semi-gradient TD can't wander arbitrarily far from the best that the features allow, as long as the data are on-policy.

import numpy as np

rng = np.random.default_rng(0)
n, d, gamma = 50, 5, 0.9
P = rng.dirichlet(np.ones(n) * 0.3, size=n)       # a random ergodic chain under pi
r = rng.normal(size=n)                            # expected reward r_pi(s)
X = rng.normal(size=(n, d))                       # feature matrix: row s is x(s)

evals, evecs = np.linalg.eig(P.T)                 # on-policy (stationary) distribution mu
mu = np.real(evecs[:, np.argmin(np.abs(evals - 1))])
mu /= mu.sum()
D = np.diag(mu)
v_pi = np.linalg.solve(np.eye(n) - gamma * P, r)

A = X.T @ D @ (np.eye(n) - gamma * P) @ X         # A = E[x (x - gamma x')^T]
b = X.T @ D @ r                                   # b = E[R x]
w_td = np.linalg.solve(A, b)                      # the TD fixed point
w_ve = np.linalg.solve(X.T @ D @ X, X.T @ D @ v_pi)   # argmin VE: mu-weighted least squares

VE = lambda w: mu @ (v_pi - X @ w) ** 2
print(f"min VE {VE(w_ve):.3f}   VE(w_TD) {VE(w_td):.3f}   bound {VE(w_ve) / (1 - gamma):.3f}")
print("A + A^T positive definite:", np.linalg.eigvalsh(A + A.T).min() > 0)

With five random features for fifty states the approximation is poor, but the reference run gives min VE ≈ 1.384 and VE(wTD) ≈ 1.415, far inside the bound of ≈ 13.8, and confirms \(A + A^\top\) is positive definite.

Why linear is the only case with clean theory

Three facts made the analysis work, and each depends on linearity. The objective \(\overline{\text{VE}}\) is a convex quadratic in \(\mathbf w\), so MC has a unique global optimum. The expected TD update is affine, \(\mathbf b - A\mathbf w\), so it has a single fixed point characterized by one matrix. And the representable set is a linear subspace, so \(\Pi\) is a fixed linear map that is non-expansive in the same norm in which \(T\) contracts. With a neural network, the representable set is a curved manifold, "project onto it" is neither linear nor unique, and the expected update is a nonlinear vector field whose fixed points can be many, unstable, or absent. Deep value-based RL (Module 8) runs without any of these guarantees, which is why it needs target networks and replay to behave.

Choosing α for linear methods (S&B §9.6)

A useful rule of thumb: to learn in about \(\tau\) experiences with roughly the same feature vector, set \(\alpha = \big(\tau\,\E[\mathbf x^\top\mathbf x]\big)^{-1}\). For tile coding with \(n\) active binary features, \(\mathbf x^\top\mathbf x = n\), which gives the \(\alpha/n\) scaling of Day 65.

What breaks
  • Off-policy weighting. The proof needs \(\mu\) to be stationary for the policy being evaluated. Under a behaviour policy's distribution, \(A\) may not be positive definite (Day 69).
  • Dependent features. If \(X\) loses column rank, \(A\) is singular and there are many fixed points. TD still runs, but LSTD (Day 66) needs regularization.
  • Feature scale. Doubling every feature quadruples \(\mathbf x^\top\mathbf x\) and effectively quadruples the step size. Normalize features, or scale \(\alpha\) as in the note.
  • The bound is a \(\mu\)-average. States with tiny \(\mu\) can carry large errors without violating it.

Feature Construction I

40m video90m practice

A linear method is only as good as its features. Aggregation, polynomials and Fourier bases are three ways to turn a continuous state into a feature vector. Fourier features are global, smooth and orthogonal under a uniform weighting, which makes them far easier for SGD than polynomials of the same order.

State aggregation revisited

Aggregation (Day 62) is one-hot coding over a partition: complete generalization within a cell, none across a boundary. Its only design choice is resolution. Coarse cells learn fast but represent only a staircase; fine cells represent detail but each one sees little data. Aggregation is also tile coding with a single tiling, and Day 65 shows how overlapping several offset partitions removes most of its weakness.

Polynomial bases and their scaling problems

Definition · polynomial basis of order n

For a state \(\mathbf s = (s_1, \dots, s_k)\), each feature is a monomial

$$x_i(\mathbf s) = \prod_{j=1}^k s_j^{\,c_{i,j}}, \qquad c_{i,j} \in \{0, 1, \dots, n\},$$

giving \((n+1)^k\) features. For \(k = 2\), \(n = 2\): \(1, s_1, s_2, s_1s_2, s_1^2, s_2^2, s_1^2s_2, s_1s_2^2, s_1^2s_2^2\).

Products such as \(s_1s_2\) are interaction terms: they let the value's dependence on one variable change with another, which no sum of single-variable features can do. Polynomials have two problems. The count \((n+1)^k\) grows exponentially with the dimension (order 5 in 4 dimensions is already 1,296 features), so in practice you must pick a subset. And monomials are badly conditioned, which is the problem that actually ruins SGD.

Derivation · polynomials are ill-conditioned, Fourier features are not

SGD on a quadratic converges at a rate set by the condition number of the feature Gram matrix \(\E[\mathbf x\mathbf x^\top]\) (Day 5: the steepest direction caps \(\alpha\), and the flattest then crawls). Take one dimension with \(s\) uniform on \([0, 1]\). For monomials,

$$\E[s^i s^j] = \int_0^1 s^{i+j}\,ds = \frac{1}{i+j+1},$$

which is the Hilbert matrix, notorious for an exponentially growing condition number. Numerically: about \(1.5\times10^4\) at order 3, \(1.5\times10^7\) at order 5, and \(5\times10^{14}\) at order 10. For the cosines used by the Fourier basis,

$$\int_0^1 \cos(\pi i s)\cos(\pi j s)\,ds = \begin{cases} 1 & i = j = 0,\\ \tfrac12 & i = j \ge 1,\\ 0 & i \ne j,\end{cases}$$

so the Gram matrix is diagonal and its condition number is exactly 2, at any order. Under a non-uniform \(\mu\) the cosines are no longer exactly orthogonal, but they stay far better conditioned than monomials.

This is why S&B do not recommend polynomials for online learning.

Fourier bases

Definition · Fourier cosine basis of order n (Konidaris et al. 2011; S&B §9.5.2)

Rescale the state so that \(\mathbf s \in [0, 1]^k\). For each integer vector \(\mathbf c^i = (c^i_1, \dots, c^i_k)\) with \(c^i_j \in \{0, \dots, n\}\),

$$x_i(\mathbf s) = \cos\!\big(\pi\,\mathbf s^\top\mathbf c^i\big),$$

giving \((n+1)^k\) features. \(\mathbf c^i = \mathbf 0\) is the constant feature.

Each \(\mathbf c^i\) is a vector of frequencies. Its non-zero entries say which dimensions the feature varies along, and how fast. A vector with a single non-zero entry, such as \((2, 0)\), gives a feature that varies along one dimension only. A vector with several, such as \((1, 1)\), varies along a diagonal: this is coupling, the Fourier version of an interaction term. If you believe interactions are weak, the uncoupled basis keeps only the vectors with at most one non-zero entry, \(kn + 1\) features instead of \((n+1)^k\) (21 instead of 1,296 for \(k = 4\), \(n = 5\)). The order \(n\) sets the highest frequency, and hence the finest detail representable.

Why cosines only? On \([0, 1]\), any reasonable function can be extended to an even function on \([-1, 1]\), and an even function has a cosine-only Fourier series, so no sine terms are needed. Why do they work well? They are global and smooth, which suits the smooth value functions of many control problems; they are orthogonal under uniform weighting, which keeps SGD well conditioned; and higher orders add detail without disturbing what lower orders represent. Konidaris et al. (2011) also recommend a separate step size per feature, \(\alpha_i = \alpha / \|\mathbf c^i\|_2\) (and \(\alpha\) for \(\mathbf c = \mathbf 0\)), so that high-frequency features move more cautiously.

import itertools
import numpy as np

class FourierBasis:
    """x_i(s) = cos(pi * c_i . s) for s rescaled to [0, 1]^k (Konidaris et al. 2011)."""
    def __init__(self, low, high, order, coupled=True):
        self.low = np.asarray(low, float)
        self.span = np.asarray(high, float) - self.low
        k = len(self.low)
        if coupled:                              # every c in {0..n}^k: (n + 1)^k features
            C = list(itertools.product(range(order + 1), repeat=k))
        else:                                    # at most one non-zero entry: k*n + 1 features
            C = [(0,) * k] + [tuple(c if j == i else 0 for j in range(k))
                              for i in range(k) for c in range(1, order + 1)]
        self.C = np.array(C, dtype=float)
        norms = np.linalg.norm(self.C, axis=1)
        self.lr_scale = 1.0 / np.where(norms > 0, norms, 1.0)   # alpha_i = alpha / ||c_i||

    def __call__(self, s):
        z = (np.asarray(s, float) - self.low) / self.span       # into [0, 1]^k
        return np.cos(np.pi * self.C @ z)

# Gradient MC on the 1000-state walk with an order-10 basis (episode() is Day 62's):
fb = FourierBasis(low=[0], high=[999], order=10)
w, alpha = np.zeros(len(fb.C)), 5e-5
for _ in range(5000):
    states, G = episode()
    for s in states:
        x = fb([s])
        w += alpha * fb.lr_scale * (G - w @ x) * x               # per-feature step sizes

S&B's Figure 9.5 compares Fourier and polynomial bases of orders 5, 10 and 20 for gradient MC on the 1000-state walk, and the Fourier basis learns much better at every order. A 5,000-episode reference run of this code showed the same ordering, with noticeably lower \(\sqrt{\overline{\text{VE}}}\) for Fourier features at each order.

Feature normalization

The Fourier basis assumes every input lies in \([0, 1]\), and the assumption is load-bearing: \(\cos\) is even and periodic, so a state rescaled to \(-0.3\) produces exactly the same features as one at \(0.3\), and \(1.3\) the same as \(0.7\). Those states become indistinguishable. Use the environment's declared bounds (Gymnasium's observation_space.low and high) when they are finite. For unbounded dimensions, such as CartPole's velocities, choose bounds from data and clip. Polynomials and neural networks prefer standardized inputs (zero mean, unit variance), for the conditioning reasons above. Whatever the basis, the effective step size scales with \(\mathbf x^\top\mathbf x\) (Day 63), so a change of feature scale is a change of learning rate.

Manual feature engineering and interaction terms

Hand-designed features can encode knowledge that would take a generic basis many terms to discover. In Mountain Car (Day 67) the dynamics are \(\dot x_{t+1} = \dot x_t + 0.001A_t - 0.0025\cos(3x_t)\), so the car's mechanical energy is

$$E(x, \dot x) = \tfrac12\dot x^2 + \tfrac{0.0025}{3}\sin(3x),$$

and the solution is essentially "pump energy until it suffices to reach the top". A single energy feature captures what a grid needs dozens of cells for. In CartPole, angle and angular velocity matter mostly together: a pole tilting right while rotating right is in trouble, while one tilting right but rotating back is recovering. That is an interaction, \(\theta\dot\theta\), which a linear function of \(\theta\) and \(\dot\theta\) separately can't express. TD-Gammon's later versions added hand-crafted backgammon features to the raw board encoding. The general lesson: when the effect of one variable depends on another, the features must contain the product, a coupled term, or a nonlinearity.

Feature Construction II — Tile Coding & RBFs

45m video105m practice

Coarse coding represents a state by which of many overlapping receptive fields it falls into. Tile coding is the practical version: several offset grids with exactly one active tile in each, so a value is a sum of \(n\) weights, costs \(O(n)\) to compute, and generalizes to a neighbouring state in proportion to the number of tiles the two share.

Coarse coding and generalization width

Cover the state space with overlapping regions, such as circles in two dimensions, and give each a binary feature that is 1 when the state is inside it. A state activates the few features whose regions contain it. Two states share exactly the features whose regions contain both, so an update at one changes the other's value in proportion to their overlap. The size and shape of the regions set how far and in which directions learning generalizes; their number and density set the finest detail that can eventually be represented. S&B's Example 9.3 shows the two are separate: learning a one-dimensional square wave with narrow, medium and broad intervals, broad features generalize much further early in learning, but after enough examples the three learned functions are nearly equally detailed, because acuity is set by the number of features rather than their width.

Tile coding

Definition · tile coding

A tiling is a partition of the (bounded) state space into tiles, usually a uniform grid. Use \(n\) tilings, each offset from the others by a fraction of a tile width. Every tile of every tiling is one binary feature, so a state activates exactly \(n\) features, one per tiling, and

$$\hat v(s, \mathbf w) = \sum_{i \in \mathcal I(s)} w_i, \qquad |\mathcal I(s)| = n.$$

Because exactly \(n\) features are active and each equals 1, an update at \(s\) adds \(\alpha(U - \hat v(s))\) to each of the \(n\) active weights, which moves \(\hat v(s)\) by \(n\alpha(U - \hat v(s))\). Setting \(\alpha = \beta/n\) therefore moves \(\hat v(s)\) a fraction \(\beta\) of the way to the target in one update: \(\alpha = 1/n\) jumps all the way, and S&B suggest values like \(\alpha = 1/(10n)\) to move a tenth of the way. A nearby state that shares \(m\) of the \(n\) tiles moves by the fraction \(\beta m/n\), which is the generalization.

Offsets: uniform vs asymmetric

The obvious choice offsets tiling \(j\) by \(j/n\) of a tile in every dimension, a displacement vector \((1, 1, \dots)\). All the tilings then slide along the main diagonal, and generalization is stretched along that diagonal: a state shares more tiles with neighbours displaced diagonally than with neighbours displaced the same distance along an axis. Miller & Glanz (1996) recommend displacement vectors made of the first odd integers, \((1, 3, 5, \dots, 2k-1)\), which spread the tilings more evenly and give more uniform, closer to spherical, generalization. S&B add that \(n\) should be a power of 2 and at least \(4k\) for \(k\) dimensions.

Computational efficiency and hashing

Tile coding never builds a feature vector. The active index in each tiling is arithmetic: scale the state to tile units, add the tiling's offset, take the floor in each dimension, and flatten. Evaluating \(\hat v\) costs \(O(nk)\) whatever the total number of features, and an update touches only \(n\) weights. Memory is the problem: \(n\) tilings of \(T\) tiles per dimension in \(k\) dimensions need \(n(T+1)^k\) weights (the \(+1\) because offsets push states into one extra tile per dimension), exponential in \(k\). Two remedies are standard. Hashing maps each (tiling, tile coordinates) pair pseudo-randomly into a table of fixed size \(M\); most of a large state space is never visited, collisions are rare and scattered, and their effect is small. Sutton's tile-coding software implements this with an index hash table. Tiling subsets of dimensions (each pair of variables, or each variable alone) trades interactions between distant variables for linear rather than exponential memory.

import numpy as np

class TileCoder:
    """n_tilings uniform grids over a box; tiling j is shifted by j * (1, 3, 5, ...) / n_tilings of a tile."""
    def __init__(self, low, high, tiles_per_dim, n_tilings):
        self.low = np.asarray(low, float)
        self.scale = tiles_per_dim / (np.asarray(high, float) - self.low)  # tiles per unit of input
        self.k, self.n, self.T = len(self.low), n_tilings, tiles_per_dim
        disp = 2 * np.arange(self.k) + 1                                   # asymmetric (1, 3, 5, ...)
        self.offsets = (np.arange(n_tilings)[:, None] * disp / n_tilings) % 1.0
        self.per_tiling = (tiles_per_dim + 1) ** self.k                    # one spare tile per dim
        self.size = n_tilings * self.per_tiling                            # total binary features

    def active(self, s):
        """Indices of the n_tilings active features (exactly one per tiling)."""
        z = (np.asarray(s, float) - self.low) * self.scale                 # position in tile units
        coords = np.clip(np.floor(z + self.offsets).astype(int), 0, self.T)   # [n_tilings, k]
        flat = np.ravel_multi_index(tuple(coords.T), (self.T + 1,) * self.k)
        return np.arange(self.n) * self.per_tiling + flat

tc = TileCoder(low=[0, 0], high=[1, 1], tiles_per_dim=5, n_tilings=8)
w, alpha = np.zeros(tc.size), 0.5
v = lambda s: w[tc.active(s)].sum()                 # v_hat(s) = sum of the n active weights
s = [0.3, 0.6]
w[tc.active(s)] += alpha / tc.n * (1.0 - v(s))      # alpha / n: v_hat(s) moves halfway to 1
print(v(s), v([0.36, 0.66]), v([0.9, 0.1]))         # 0.5, 0.3125 (5 of 8 tiles shared), 0.0

For hashing, replace the last line of active with [hash((j, *c)) % M for j, c in enumerate(coords)] for a table of size M. Python's hash of a tuple of integers is deterministic across runs.

Radial basis functions

Definition · RBF features $$x_i(s) = \exp\!\left(-\frac{\|s - c_i\|^2}{2\sigma_i^2}\right),$$

with centres \(c_i\) (often on a grid) and widths \(\sigma_i\).

RBFs are the graded version of coarse coding: instead of a feature being on or off, it responds by how close the state is to its centre. The resulting approximation is smooth and differentiable. S&B's assessment is that this rarely buys much in practice over tile coding, at a higher computational cost (every feature is non-zero somewhere, so either evaluate them all or truncate) and with more tuning, and that the number of centres needed grows exponentially with dimension just as tiles do. If the centres and widths are themselves learned by gradient descent, the result is an RBF network: a nonlinear approximator, without the guarantees of Day 63.

centres = np.stack(np.meshgrid(np.linspace(0, 1, 9), np.linspace(0, 1, 9)), -1).reshape(-1, 2)
rbf = lambda s, sigma=0.1: np.exp(-((centres - np.asarray(s)) ** 2).sum(1) / (2 * sigma ** 2))

Least-Squares Methods

35m video75m practice

Semi-gradient TD approaches the fixed point \(\mathbf w_{TD} = A^{-1}\mathbf b\) one noisy step at a time. LSTD estimates \(A\) and \(\mathbf b\) from all the data seen so far and solves for the fixed point directly: no step size and the most out of every sample, for \(O(d^2)\) work per step instead of \(O(d)\).

LSTD: solving for the TD fixed point

Day 63 showed that linear TD converges to the solution of \(A\mathbf w = \mathbf b\) with \(A = \E[\mathbf x_t(\mathbf x_t - \gamma\mathbf x_{t+1})^\top]\) and \(\mathbf b = \E[R_{t+1}\mathbf x_t]\). Both are expectations, so estimate them by sums over the transitions seen so far:

$$\hat A_t = \sum_{k=0}^{t-1}\mathbf x_k(\mathbf x_k - \gamma\mathbf x_{k+1})^\top + \varepsilon I, \qquad \hat{\mathbf b}_t = \sum_{k=0}^{t-1}R_{k+1}\mathbf x_k, \qquad \mathbf w_t = \hat A_t^{-1}\hat{\mathbf b}_t.$$

Proper averages would divide both by \(t\), but the factors cancel in \(\hat A^{-1}\hat{\mathbf b}\). The small \(\varepsilon I\) keeps \(\hat A_t\) invertible before enough data has arrived. This is LSTD (Bradtke & Barto 1996; Boyan 2002), and its solution is the TD fixed point for the empirical data, with no step size to tune.

Sherman–Morrison: an O(d²) incremental inverse

Inverting \(\hat A_t\) from scratch costs \(O(d^3)\) per step. But each step adds a rank-one term to \(\hat A\), and the inverse of a rank-one update has a closed form.

Lemma · Sherman–Morrison

For invertible \(B\) and vectors \(\mathbf u, \mathbf v\) with \(1 + \mathbf v^\top B^{-1}\mathbf u \ne 0\),

$$(B + \mathbf u\mathbf v^\top)^{-1} = B^{-1} - \frac{B^{-1}\mathbf u\,\mathbf v^\top B^{-1}}{1 + \mathbf v^\top B^{-1}\mathbf u}.$$
Proof

Multiply \(B + \mathbf u\mathbf v^\top\) by the right-hand side and write \(\beta = \mathbf v^\top B^{-1}\mathbf u\), a scalar:

$$I + \mathbf u\mathbf v^\top B^{-1} - \frac{\mathbf u\mathbf v^\top B^{-1} + \mathbf u(\mathbf v^\top B^{-1}\mathbf u)\mathbf v^\top B^{-1}}{1 + \beta} = I + \mathbf u\mathbf v^\top B^{-1} - \frac{(1 + \beta)\,\mathbf u\mathbf v^\top B^{-1}}{1 + \beta} = I. \;∎$$

For LSTD, \(\mathbf u = \mathbf x_t\) and \(\mathbf v = \mathbf x_t - \gamma\mathbf x_{t+1}\). The update needs two matrix–vector products and an outer product: \(O(d^2)\).

Algorithm · LSTD for estimating v̂ ≈ vπ (S&B §9.8), O(d²) version
  1. Input: feature map \(\mathbf x\) with \(\mathbf x(\text{terminal}) = \mathbf 0\); small \(\varepsilon > 0\). Set \(\widehat{A^{-1}} \leftarrow \varepsilon^{-1}I\) and \(\hat{\mathbf b} \leftarrow \mathbf 0\).
  2. For each transition \((\mathbf x, R, \mathbf x')\) generated by \(\pi\):
    1. \(\mathbf v \leftarrow \widehat{A^{-1}}^{\,\top}(\mathbf x - \gamma\mathbf x')\)
    2. \(\widehat{A^{-1}} \leftarrow \widehat{A^{-1}} - (\widehat{A^{-1}}\mathbf x)\mathbf v^\top / (1 + \mathbf v^\top\mathbf x)\)
    3. \(\hat{\mathbf b} \leftarrow \hat{\mathbf b} + R\,\mathbf x\); \(\;\mathbf w \leftarrow \widehat{A^{-1}}\hat{\mathbf b}\)
import numpy as np

def lstd(transitions, d, gamma, eps=1e-3):
    """LSTD(0), inverse kept by Sherman-Morrison: O(d^2) per transition and no step size."""
    A_inv = np.eye(d) / eps                       # inverse of the regularizer eps * I
    b = np.zeros(d)
    for x, r, x2, terminal in transitions:
        v = x - (0.0 if terminal else gamma) * x2  # this transition adds x v^T to A
        Ax = A_inv @ x
        vA = v @ A_inv
        A_inv -= np.outer(Ax, vA) / (1.0 + vA @ x)
        b += r * x
    return A_inv @ b

LSPI: least-squares policy iteration

Lagoudakis & Parr (2003) turn LSTD into a control method. LSTDQ evaluates action values \(\hat q(s, a) = \mathbf w^\top\boldsymbol\phi(s, a)\) for a given policy \(\pi\) from samples \((s, a, r, s')\):

$$\hat A = \sum \boldsymbol\phi(s, a)\big(\boldsymbol\phi(s, a) - \gamma\boldsymbol\phi(s', \pi(s'))\big)^\top, \qquad \hat{\mathbf b} = \sum \boldsymbol\phi(s, a)\,r, \qquad \mathbf w = \hat A^{-1}\hat{\mathbf b}.$$

The next action comes from the policy being evaluated, not from the data, so the same batch of samples, collected by any behaviour policy, can evaluate every policy in turn. LSPI alternates: evaluate the current greedy policy with LSTDQ on the fixed batch, make the policy greedy with respect to the new \(\hat q\), and repeat until the policy stops changing.

Algorithm · LSPI (Lagoudakis & Parr 2003)
  1. Collect a batch \(\mathcal D\) of samples \((s, a, r, s')\) with any exploratory policy. Choose features \(\boldsymbol\phi(s, a)\); initialize \(\mathbf w\).
  2. Repeat:
    1. \(\pi(s) \leftarrow \arg\max_a \boldsymbol\phi(s, a)^\top\mathbf w\) (implicit; never stored)
    2. \(\mathbf w \leftarrow \text{LSTDQ}(\mathcal D, \boldsymbol\phi, \gamma, \pi)\)
    until the policy (or \(\mathbf w\)) stops changing. 
import numpy as np

S, GAMMA, DEG = 20, 0.9, 4
rng = np.random.default_rng(0)

def step(s, a):                                    # a = 0 left, 1 right; the move slips w.p. 0.1
    move = (1 if a == 1 else -1) * (1 if rng.random() < 0.9 else -1)
    s2 = min(max(s + move, 0), S - 1)
    return s2, float(s2 in (0, S - 1))             # reward 1 for reaching either end

def phi(s, a):                                     # polynomial in s, one block per action
    f = np.zeros(2 * (DEG + 1))
    f[a * (DEG + 1):(a + 1) * (DEG + 1)] = (s / (S - 1)) ** np.arange(DEG + 1)
    return f

samples, s = [], int(rng.integers(S))              # one batch from a uniformly random policy
for _ in range(5000):
    a = int(rng.integers(2))
    s2, r = step(s, a)
    samples.append((s, a, r, s2))
    s = s2

def lstdq(samples, policy, eps=1e-3):              # evaluate `policy` from off-policy samples
    d = 2 * (DEG + 1)
    A, b = eps * np.eye(d), np.zeros(d)
    for s, a, r, s2 in samples:
        f = phi(s, a)
        A += np.outer(f, f - GAMMA * phi(s2, policy(s2)))   # next action from the evaluated policy
        b += r * f
    return np.linalg.solve(A, b)

A 20-state slippery chain, continuing, with reward for reaching either end. In the reference run LSPI settled in five iterations on the optimal policy: left in states 0–9, right in 10–19.

LSPI is sample-efficient, needs no step size, and reuses one batch indefinitely. It also has no general convergence guarantee: Lagoudakis & Parr bound the performance of the policies it produces in terms of the approximation errors, but the iteration can oscillate between policies, and it only works if the batch covers the actions the greedy policies choose.

When LSTD beats SGD, and when it is infeasible

LSTD wins when \(d\) is small or moderate (up to a few thousand), data are expensive and computation is not, the policy is fixed (prediction, or LSPI's batch evaluation), and you want results without tuning a step size. It is infeasible when \(d\) is large (high-resolution tile coding, many hashed features), when the approximator is nonlinear (there is no closed-form fixed point for a neural network), or when the targets keep moving, as in online control where the policy improves every step and old data describe a policy you no longer follow.

What breaks
  • ε matters early. A large \(\varepsilon\) shrinks early solutions towards zero; a tiny one makes the first inverses numerically huge.
  • Round-off accumulates in long Sherman–Morrison recursions. In long runs, periodically recompute the inverse from \(\hat A\) itself.
  • It never forgets. In online control, \(\hat A\) and \(\hat{\mathbf b}\) mix data from every past policy. Use LSTDQ on a batch, or discount old data with a forgetting factor.
  • Coverage. LSTDQ can only learn about actions that appear in the batch. If the batch rarely contains the actions a greedy policy chooses, its evaluation of that policy is extrapolation through the features.
  • Off-policy \(\hat A\) need not be positive definite (Day 69); the solution can exist and still be poor.

DAY 67

Control with Function Approximation

45m video120m practice

Control with function approximation is semi-gradient TD applied to action values: features \(\mathbf x(s, a)\), a linear \(\hat q\), and \(\varepsilon\)-greedy action selection on top. On Mountain Car with eight tilings it solves, in a few hundred episodes, a task that a table can only approach by coarse discretization, and lets you watch the value function discover the counterintuitive answer of backing up the hill first.

Semi-gradient SARSA

Replace \(\hat v(s, \mathbf w)\) by \(\hat q(s, a, \mathbf w) \approx q_\pi(s, a)\). The general update is \(\mathbf w \leftarrow \mathbf w + \alpha\big[U_t - \hat q(S_t, A_t, \mathbf w)\big]\nabla\hat q(S_t, A_t, \mathbf w)\), and the one-step SARSA target is \(U_t = R_{t+1} + \gamma\hat q(S_{t+1}, A_{t+1}, \mathbf w)\). Control then follows generalized policy iteration (Day 33): act \(\varepsilon\)-greedily with respect to \(\hat q\), and learn \(\hat q\) for the policy you are following.

Algorithm · Episodic semi-gradient SARSA for estimating q̂ ≈ q* (S&B §10.1)
  1. Input: a differentiable \(\hat q(s, a, \mathbf w)\); step size \(\alpha > 0\); small \(\varepsilon > 0\). Initialize \(\mathbf w\) (for example \(\mathbf w = \mathbf 0\)).
  2. Loop for each episode:
    1. \(S, A \leftarrow\) initial state and an \(\varepsilon\)-greedy action from \(\hat q(S, \cdot, \mathbf w)\).
    2. Loop for each step: take \(A\), observe \(R, S'\).
      1. If \(S'\) is terminal: \(\mathbf w \leftarrow \mathbf w + \alpha\big[R - \hat q(S, A, \mathbf w)\big]\nabla\hat q(S, A, \mathbf w)\); go to the next episode.
      2. Choose \(A'\) \(\varepsilon\)-greedily from \(\hat q(S', \cdot, \mathbf w)\).
      3. \(\mathbf w \leftarrow \mathbf w + \alpha\big[R + \gamma\hat q(S', A', \mathbf w) - \hat q(S, A, \mathbf w)\big]\nabla\hat q(S, A, \mathbf w)\).
      4. \(S \leftarrow S'\); \(A \leftarrow A'\).

Action-value features x(s, a)

Three constructions cover almost everything:

  • Stacked state features. One copy of \(\mathbf x(s)\) per action, so \(\hat q(s, a) = \mathbf w_a^\top\mathbf x(s)\). Actions share nothing, which is right when actions are few and unrelated. The code below does this.
  • Joint coding. Tile-code \((s, a)\) together, with the action as an extra (discrete) input to the hash, as S&B's software does. With continuous or ordered actions, tiles that span neighbouring actions let them share what they learn.
  • One output per action. A network with \(|\mathcal A|\) outputs computes every \(\hat q(s, \cdot)\) in one pass. That is DQN's design (Day 71).

All three need \(\max_a \hat q(s, a)\) for the greedy action, which is cheap for a few discrete actions. With continuous actions the maximization is itself an optimization problem, one reason policy-gradient methods (Module 9) take over there.

ε-greedy over approximate values

Action selection is unchanged from the tabular case, with one subtlety worth exploiting. In Mountain Car every reward is −1, so every true action value is negative and an all-zero initial \(\hat q\) is optimistic everywhere. Whatever the agent has tried looks worse than what it hasn't, so the greedy policy explores systematically, and S&B use \(\varepsilon = 0\). Generalization spreads that optimism: one update lowers the values of a whole neighbourhood, pushing the agent towards regions it hasn't visited. As for convergence, nothing as clean as Day 63 holds for control. Linear semi-gradient SARSA does not diverge in the on-policy setting, but its weights can keep oscillating within a region rather than converging to a point (Gordon 2001).

Mountain Car

S&B's settings are 8 tilings, each an 8 × 8 grid over the bounded position–velocity box, with asymmetric offsets; one block of tile features per action; \(\alpha = 0.1/8\) (their Figure 10.2 also shows \(0.2/8\) and \(0.5/8\)); \(\varepsilon = 0\); \(\hat q\) initialized to 0; learning curves averaged over 100 runs. In Gymnasium the task is MountainCar-v0: observations are \([x, \dot x]\), actions 0, 1, 2 mean push left, no push, push right, and the episode terminates when \(x \ge 0.5\). It also has a default TimeLimit of 200 steps, which S&B's task does not: an untrained agent needs hundreds or thousands of steps to stumble onto the goal, so for a faithful reproduction raise the limit. Either way, a truncated episode must still bootstrap (Day 8).

import numpy as np
import gymnasium as gym
# TileCoder is the Day 65 class.

env = gym.make("MountainCar-v0", max_episode_steps=10_000)   # S&B's task has no 200-step cap
tc = TileCoder(low=[-1.2, -0.07], high=[0.5, 0.07], tiles_per_dim=8, n_tilings=8)
n_actions = env.action_space.n
w = np.zeros((n_actions, tc.size))         # x(s, a): one block of tile features per action
alpha, gamma, eps = 0.1 / tc.n, 1.0, 0.0   # S&B §10.1; q_hat = 0 is optimistic (all returns < 0)
rng = np.random.default_rng(0)

def q(tiles):                              # q_hat(s, a) for every action: sum of active weights
    return w[:, tiles].sum(axis=1)

def policy(tiles):                         # epsilon-greedy with random tie-breaking
    qs = q(tiles)
    if rng.random() < eps:
        return int(rng.integers(n_actions))
    return int(rng.choice(np.flatnonzero(qs == qs.max())))

steps_per_episode = []
for episode in range(500):
    obs, _ = env.reset(seed=episode)
    tiles = tc.active(obs)
    a = policy(tiles)
    for t in range(1, 10_001):
        obs2, r, terminated, truncated, _ = env.step(a)
        target = r
        if not terminated:                 # bootstrap unless the car really reached the goal
            tiles2 = tc.active(obs2)
            a2 = policy(tiles2)
            target += gamma * q(tiles2)[a2]
        w[a, tiles] += alpha * (target - q(tiles)[a])   # gradient of q_hat is x(s, a)
        if terminated or truncated:
            break
        tiles, a = tiles2, a2
    steps_per_episode.append(t)
print(steps_per_episode[:5], np.mean(steps_per_episode[-50:]))

Effect of α and the number of tilings

Keep \(\alpha\) expressed as a fraction of \(1/n\) (Day 65), so the size of each update in value terms is independent of the number of tilings. Within that, a larger fraction learns faster at first but gives noisier estimates, and too large a fraction makes learning erratic; S&B's Figure 10.2 compares \(0.1/8\), \(0.2/8\) and \(0.5/8\). More tilings at a fixed tile size give finer resolution with the same breadth of generalization, at proportionally more computation per step; fewer tilings learn a blockier surface. S&B's §10.2 also shows that \(n\)-step semi-gradient SARSA with \(n = 8\) learns this task faster than one-step SARSA, the same trade-off as Day 48.

What breaks
  • Treating the 200-step truncation as termination. The bootstrap is dropped at the time limit, so states that happen to be visited at step 200 learn a value of −1 instead of "many more steps to go". The agent learns a distorted cost-to-go and may never find the goal reliably.
  • Random exploration kills momentum. In Mountain Car an \(\varepsilon\)-random push can undo a swing. With optimistic initial values, \(\varepsilon = 0\) is both sufficient and better.
  • Forgetting α/n. \(\alpha = 0.1\) with 8 tilings is eight times S&B's step and learns much worse.
  • Deterministic tie-breaking. With all values at 0, argmax always pushes left; optimism still eventually drives exploration, but symmetric random ties learn faster.
  • Expecting convergence. The weights can keep drifting and the policy can keep changing slightly. Judge by returns averaged over runs, not by whether \(\mathbf w\) has stopped moving.

DAY 68

Continuing Tasks & Average Reward

35m video60m practice

In a continuing task with function approximation, discounting stops being a meaningful part of the problem: averaged over the states the policy actually visits, every discount factor ranks policies exactly as the average reward does. The clean formulation is to maximize the average reward \(r(\pi)\) and to learn differential values measured relative to it.

Why discounting is problematic with function approximation

A continuing task has no episodes and, in general, no distinguished start state. With a table, that doesn't matter: there is a policy that is discounted-optimal in every state at once, and we can find it. With function approximation we can't make every state's value right simultaneously, so we need a single scalar objective to rank policies, and the natural candidate, the discounted value averaged over the states the policy visits, turns out to carry no information about \(\gamma\) at all (the derivation below). Worse, the policy improvement theorem (Day 29) no longer holds: making the policy greedy with respect to an approximate \(\hat q\) can improve some states and harm others, so there is no guarantee that a greedy step improves anything. The tabular justification for discounted control does not survive.

The average-reward setting

Definition · average reward (Day 27; S&B §10.3) $$r(\pi) \doteq \lim_{h \to \infty}\frac1h\sum_{t=1}^h \E\big[R_t \mid S_0, A_{0:t-1} \sim \pi\big] = \sum_s \mu_\pi(s)\sum_a \pi(a \mid s)\sum_{s', r} p(s', r \mid s, a)\, r.$$

The second form needs ergodicity: the steady-state distribution \(\mu_\pi(s) = \lim_t \Pr(S_t = s)\) exists and doesn't depend on \(S_0\). It satisfies \(\sum_s \mu_\pi(s)\sum_a\pi(a \mid s)\,p(s' \mid s, a) = \mu_\pi(s')\).

Policies are ranked by \(r(\pi)\), the reward per step in the long run. The start state, and any transient early behaviour, have no effect on it.

Differential value functions

Returns are now measured relative to the average:

$$G_t \doteq R_{t+1} - r(\pi) + R_{t+2} - r(\pi) + R_{t+3} - r(\pi) + \cdots,$$

the differential return, and \(v_\pi(s) = \E_\pi[G_t \mid S_t = s]\), \(q_\pi(s, a) = \E_\pi[G_t \mid S_t = s, A_t = a]\) are the differential value functions: how much better than average it is to be here. They satisfy Bellman equations with \(r - r(\pi)\) in place of \(r\) and no discount:

$$q_\pi(s, a) = \sum_{s', r} p(s', r \mid s, a)\Big[r - r(\pi) + \sum_{a'}\pi(a' \mid s')\,q_\pi(s', a')\Big].$$

These equations determine values only up to an additive constant; the definition through \(G_t\) picks one, and for choosing actions only differences matter anyway. The TD errors follow directly, with \(\bar R_t\) an estimate of \(r(\pi)\):

$$\delta_t = R_{t+1} - \bar R_t + \hat q(S_{t+1}, A_{t+1}, \mathbf w_t) - \hat q(S_t, A_t, \mathbf w_t).$$

Differential semi-gradient SARSA

Algorithm · Differential semi-gradient SARSA (S&B §10.3)
  1. Input: a differentiable \(\hat q(s, a, \mathbf w)\); step sizes \(\alpha, \beta > 0\). Initialize \(\mathbf w\) and \(\bar R\) (for example to 0). Observe \(S\) and choose \(A\) (for example \(\varepsilon\)-greedily).
  2. Loop for each step:
    1. Take \(A\); observe \(R, S'\). Choose \(A'\) as a function of \(\hat q(S', \cdot, \mathbf w)\).
    2. \(\delta \leftarrow R - \bar R + \hat q(S', A', \mathbf w) - \hat q(S, A, \mathbf w)\)
    3. \(\bar R \leftarrow \bar R + \beta\delta\)
    4. \(\mathbf w \leftarrow \mathbf w + \alpha\,\delta\,\nabla\hat q(S, A, \mathbf w)\)
    5. \(S \leftarrow S'\); \(A \leftarrow A'\)

The average-reward estimate is updated with \(\delta\) rather than with \(R - \bar R\). Both errors work, but S&B's Exercise 10.8 shows why \(\delta\) works better: once the values are roughly right, the value terms in \(\delta\) cancel the predictable part of each reward, so \(\delta\) is small at every step, not merely zero on average, and \(\bar R\) settles instead of being kicked around by each individual reward.

The access-control queuing example

S&B's Example 10.2: a bank of 10 servers and a single queue of customers of four priorities, who pay 1, 2, 4 or 8 if served. At each step the customer at the head of the queue is either accepted (given a free server, collecting its payment) or rejected (reward 0); a customer is always rejected if no server is free. The queue never empties, priorities are uniformly random, and each busy server becomes free with probability 0.06 per step. The state is (number of free servers, priority of the current customer), the task is continuing and undiscounted, and S&B solve it with differential semi-gradient SARSA in tabular form, with \(\alpha = \beta = 0.01\) and \(\varepsilon = 0.1\).

import numpy as np

rng = np.random.default_rng(0)
N_SERVERS, P_FREE = 10, 0.06
PAY = np.array([1.0, 2.0, 4.0, 8.0])             # reward for serving each priority

def step(free, prio, accept):
    reward = 0.0
    if accept and free > 0:                      # with no free server the customer is rejected
        free -= 1
        reward = PAY[prio]
    free += rng.binomial(N_SERVERS - free, P_FREE)   # each busy server frees up w.p. 0.06
    return free, int(rng.integers(4)), reward    # the next customer's priority is uniform

Q = np.zeros((N_SERVERS + 1, 4, 2))              # tabular = one-hot features x(s, a)
R_bar, alpha, beta, eps = 0.0, 0.01, 0.01, 0.1   # S&B Example 10.2

def act(free, prio):
    if rng.random() < eps:
        return int(rng.integers(2))
    q = Q[free, prio]
    return int(rng.choice(np.flatnonzero(q == q.max())))

free, prio = N_SERVERS, int(rng.integers(4))
a = act(free, prio)
for t in range(2_000_000):
    free2, prio2, r = step(free, prio, a)
    a2 = act(free2, prio2)
    delta = r - R_bar + Q[free2, prio2, a2] - Q[free, prio, a]   # differential TD error
    R_bar += beta * delta                        # average-reward estimate, updated with delta
    Q[free, prio, a] += alpha * delta            # semi-gradient step (the gradient is one-hot)
    free, prio, a = free2, prio2, a2

print(f"average reward {R_bar:.2f}")
for p in range(4):                               # 1 = accept, by number of free servers 1..10
    print(int(PAY[p]), "".join(str(int(Q[f, p, 1] > Q[f, p, 0])) for f in range(1, N_SERVERS + 1)))

The futility of discounting

Suppose we insist on discounting in a continuing task and, lacking a start state, measure a policy by its discounted value averaged over the states it visits. That objective turns out to be the average reward in disguise.

Derivation · S&B §10.4

Let \(v_\pi^\gamma\) be the discounted value function and \(J(\pi) = \sum_s \mu_\pi(s)\,v_\pi^\gamma(s)\). Expand one step with the Bellman equation:

$$\begin{aligned} J(\pi) &= \sum_s \mu_\pi(s)\sum_a \pi(a \mid s)\sum_{s', r} p(s', r \mid s, a)\big[r + \gamma v_\pi^\gamma(s')\big] \\ &= r(\pi) + \gamma\sum_{s'} v_\pi^\gamma(s')\sum_s \mu_\pi(s)\sum_a \pi(a \mid s)\,p(s' \mid s, a) \\ &= r(\pi) + \gamma\sum_{s'} v_\pi^\gamma(s')\,\mu_\pi(s') \qquad \text{(stationarity of } \mu_\pi\text{)} \\ &= r(\pi) + \gamma J(\pi), \end{aligned}$$

so

$$J(\pi) = \frac{r(\pi)}{1 - \gamma}.$$

The averaged discounted objective is the average reward times a constant. It orders policies exactly as \(r(\pi)\) does for every \(\gamma\), so the discount rate has no effect on the problem. Combined with the loss of the policy improvement theorem, this is S&B's case for deprecating the discounted formulation of control with function approximation in continuing tasks. The average-reward setting loses the policy improvement theorem too; in Chapter 13, S&B point to the policy gradient theorem (Day 83) as the result that plays a similar role for parameterized policies.

In practice

Deep RL still uses \(\gamma = 0.99\) in continuing tasks. Read it as a property of the solution method (it shortens the effective horizon to about \(1/(1-\gamma)\) and reduces variance) rather than of the problem. Average-reward methods are less common in deep RL, but the differential TD error above is the whole of the change.

What breaks
  • β is a second learning rate. Too large and \(\bar R\) is noisy and the values chase it; too small and \(\bar R\) lags, biasing every TD error.
  • Ergodicity can fail. If a policy has several recurrent classes, its average reward depends on where it starts and \(r(\pi)\) is not one number.
  • Differential values are relative. Don't compare their magnitudes across runs or algorithms; they are defined only up to a constant offset by the Bellman equation.
  • Episodic environments aren't continuing. Using an episodic environment in an average-reward method means treating the reset as part of the dynamics; the transition into the reset state must not be bootstrapped from as if nothing happened.
  • Rarely visited states keep arbitrary values, as in the 10-free-server column.

The Deadly Triad & Off-Policy Stability

45m video90m practice

Function approximation, bootstrapping and off-policy training are each harmless on their own and in pairs. Together they can drive value estimates to infinity even when the true values are exactly representable, and Baird's seven-state star shows it in a few lines of code. The fixes change the objective (gradient-TD methods descend the projected Bellman error), change the distribution of updates (emphatic TD), or, in deep RL, slow the feedback loop down.

The deadly triad

Sutton & Barto (§11.3) name three ingredients:

  • Function approximation: a generalizing representation with fewer parameters than states.
  • Bootstrapping: targets that include current estimates, as in TD and DP, rather than complete returns.
  • Off-policy training: updates distributed according to a behaviour policy rather than the target policy.
CombinationExampleStable?
FA + bootstrapping, on-policylinear semi-gradient TD (Day 63)yes, converges to \(\mathbf w_{TD}\)
FA + off-policy, no bootstrappinggradient MC with importance samplingyes, a true gradient method
Bootstrapping + off-policy, tabularQ-learning (Day 45)yes
All threeoff-policy semi-gradient TD, DQNcan diverge

Instability is not caused by control, by greedy policies, or by sampling: Baird's example below diverges in pure prediction, with expected updates.

Baird's counterexample

The behaviour policy \(b\) takes the dashed action with probability 6/7 and the solid one with 1/7, so the next state is uniformly distributed and \(b\)'s on-policy distribution is uniform over all seven states. The target policy \(\pi\) always takes the solid action, so its on-policy distribution is concentrated entirely on state 7. Every reward is 0 and \(\gamma = 0.99\). The features are \(\mathbf x(i) = 2\mathbf e_i + \mathbf e_8\) for the upper states \(i = 1, \dots, 6\) and \(\mathbf x(7) = \mathbf e_7 + 2\mathbf e_8\): eight features for seven states, so many weight vectors represent the true values exactly, \(\mathbf w = \mathbf 0\) among them. Starting from \(\mathbf w = (1, 1, 1, 1, 1, 1, 10, 1)^\top\), off-policy semi-gradient TD(0) with importance ratios \(\rho = \pi/b\) (7 for solid, 0 for dashed) sends the weights to infinity. So does the semi-gradient DP version, which replaces sampling with exact expected updates over a uniform state distribution: S&B show it diverges for any positive step size.

import numpy as np

gamma, alpha = 0.99, 0.01
X = np.zeros((7, 8))                       # Baird's features: x(s) for states 1..7 as rows 0..6
for i in range(6):
    X[i, i], X[i, 7] = 2.0, 1.0            # upper states: v_hat = 2 w_i + w_8
X[6, 6], X[6, 7] = 1.0, 2.0                # lower state:  v_hat = w_7 + 2 w_8
w0 = np.array([1, 1, 1, 1, 1, 1, 10, 1], dtype=float)

# (1) off-policy semi-gradient TD(0). b: dashed w.p. 6/7, solid w.p. 1/7; pi: always solid.
rng = np.random.default_rng(0)
w, s = w0.copy(), int(rng.integers(7))
for t in range(1000):
    if rng.random() < 6 / 7:
        s2, rho = int(rng.integers(6)), 0.0    # dashed: to a random upper state; pi never does this
    else:
        s2, rho = 6, 7.0                       # solid: to the lower state; rho = 1 / (1/7)
    delta = 0.0 + gamma * X[s2] @ w - X[s] @ w # every reward is zero
    w += alpha * rho * delta * X[s]
    s = s2
print("TD after 1000 steps: ", w.round(1))

# (2) semi-gradient DP: expected updates, every state weighted equally (b's distribution)
w = w0.copy()
for k in range(1000):
    target = gamma * X[6] @ w                  # under pi every state moves to the lower state
    w += alpha / 7 * X.T @ (target - X @ w)
print("DP after 1000 sweeps:", w.round(1))

In the reference run, \(w_8\) had grown from 1 to about 317 after 1,000 TD steps and to about 335 after 1,000 DP sweeps, and it keeps growing without bound.

Why it diverges

Mechanism. Take a solid transition from upper state \(i\) to state 7. Its TD error is \(\delta = \gamma(w_7 + 2w_8) - (2w_i + w_8)\), positive at the start, and the update raises \(w_i\) by \(2\alpha\rho\delta\) and \(w_8\) by \(\alpha\rho\delta\). But \(w_8\) enters state 7's estimate with weight 2, so raising it raises the target of every future solid transition by more than it raises this state's estimate. The update that would pull \(w_8\) back down is the one from state 7 itself, where \(\delta = (\gamma - 1)\hat v(7)\), and under \(b\) state 7 receives only 1/7 of the updates. Under \(\pi\)'s own distribution it would receive all of them.

Linear algebra. The expected update is \(\mathbf w \leftarrow \mathbf w + \alpha(\mathbf b - A\mathbf w)\) with \(A = X^\top D(I - \gamma P_\pi)X\), where \(D\) is \(b\)'s uniform distribution but \(P_\pi\) is \(\pi\)'s dynamics. Day 63's proof of positive definiteness used \(\boldsymbol\mu^\top P = \boldsymbol\mu^\top\), and that fails here. Numerically, \(A\) has an eigenvalue with real part about \(-0.24\), so \(I - \alpha A\) has an eigenvalue of modulus greater than 1 for every \(\alpha > 0\), and the iteration diverges along it. Weighting the same updates by \(\pi\)'s distribution (all on state 7) leaves no eigenvalue with negative real part, and the iteration is stable.

The projected Bellman error

If semi-gradient TD isn't minimizing anything, what should an off-policy method minimize? Consider the space of all value functions, with the subspace of representable ones \(\{X\mathbf w\}\). Write \(B_\pi\) for the Bellman operator, \(\Pi\) for the \(\mu\)-weighted projection onto the subspace (Day 63), and \(\bar\delta_{\mathbf w} = B_\pi\mathbf v_{\mathbf w} - \mathbf v_{\mathbf w}\) for the Bellman error vector.

Definitions · error measures
  • \(\overline{\text{VE}}(\mathbf w) = \|\mathbf v_{\mathbf w} - \mathbf v_\pi\|_\mu^2\): the target, unknowable without \(\mathbf v_\pi\).
  • \(\overline{\text{BE}}(\mathbf w) = \|\bar\delta_{\mathbf w}\|_\mu^2\): the mean squared Bellman error.
  • \(\overline{\text{PBE}}(\mathbf w) = \|\Pi\bar\delta_{\mathbf w}\|_\mu^2\): the mean squared projected Bellman error. Zero exactly at the TD fixed point.
  • \(\overline{\text{TDE}}(\mathbf w) = \E[\delta_t^2]\): the mean squared TD error, which residual gradient minimizes (Day 62).

S&B (§11.6) show that \(\overline{\text{BE}}\) is not even learnable: two MDPs that generate identical data distributions can have different \(\overline{\text{BE}}\)-minimizing weights, so no algorithm can find its minimum from data alone. \(\overline{\text{PBE}}\) is learnable, and its minimum is the familiar TD fixed point, which makes it the objective of choice.

Derivation · the gradient of PBE (S&B §11.7)

With \(\Pi = X(X^\top DX)^{-1}X^\top D\), \(\|\Pi\mathbf v\|_\mu^2 = (X^\top D\mathbf v)^\top(X^\top DX)^{-1}(X^\top D\mathbf v)\). Off-policy, with importance ratio \(\rho_t\), \(X^\top D\bar\delta_{\mathbf w} = \E[\rho_t\delta_t\mathbf x_t]\) and \(X^\top DX = \E[\mathbf x_t\mathbf x_t^\top]\), so

$$\overline{\text{PBE}}(\mathbf w) = \E[\rho_t\delta_t\mathbf x_t]^\top\,\E[\mathbf x_t\mathbf x_t^\top]^{-1}\,\E[\rho_t\delta_t\mathbf x_t].$$

Since \(\nabla\delta_t = \gamma\mathbf x_{t+1} - \mathbf x_t\),

$$\nabla\overline{\text{PBE}}(\mathbf w) = 2\,\E\big[\rho_t(\gamma\mathbf x_{t+1} - \mathbf x_t)\mathbf x_t^\top\big]\,\E[\mathbf x_t\mathbf x_t^\top]^{-1}\,\E[\rho_t\delta_t\mathbf x_t].$$

This is a product of three expectations, and the first and last both depend on the next state, so a single sample can't give an unbiased estimate of it. The trick is to learn the last two factors separately: \(\mathbf v \approx \E[\mathbf x_t\mathbf x_t^\top]^{-1}\E[\rho_t\delta_t\mathbf x_t]\) is the least-squares solution for predicting \(\rho_t\delta_t\) from \(\mathbf x_t\), learnable by the LMS rule \(\mathbf v \leftarrow \mathbf v + \beta\rho_t(\delta_t - \mathbf v^\top\mathbf x_t)\mathbf x_t\).

Gradient-TD methods: GTD2 and TDC

With \(\mathbf v\) standing in for the last two factors, stochastic gradient descent on \(\overline{\text{PBE}}\), \(\mathbf w \leftarrow \mathbf w - \tfrac12\alpha\nabla\overline{\text{PBE}}\), becomes

$$\textbf{GTD2:}\qquad \mathbf w_{t+1} = \mathbf w_t + \alpha\rho_t(\mathbf x_t - \gamma\mathbf x_{t+1})\,\mathbf x_t^\top\mathbf v_t .$$

Rewriting \(\E[\rho_t(\mathbf x_t - \gamma\mathbf x_{t+1})\mathbf x_t^\top] = \E[\mathbf x_t\mathbf x_t^\top] - \gamma\E[\rho_t\mathbf x_{t+1}\mathbf x_t^\top]\) (using \(\E_b[\rho_t \mid S_t] = 1\)) before substituting \(\mathbf v\) gives the other form,

$$\textbf{TDC:}\qquad \mathbf w_{t+1} = \mathbf w_t + \alpha\rho_t\big(\delta_t\mathbf x_t - \gamma\mathbf x_{t+1}\,\mathbf x_t^\top\mathbf v_t\big),$$

which is ordinary off-policy semi-gradient TD plus a correction term (TD with gradient correction, also called GTD(0)). Both are \(O(d)\) per step and are proven to converge off-policy with linear features under suitable step-size conditions, in which (for TDC) the secondary learner \(\mathbf v\), with step \(\beta\), adapts faster than \(\mathbf w\) (Sutton et al. 2009).

Algorithm · TDC (one step, off-policy, linear)
  1. \(\delta \leftarrow R + \gamma\mathbf w^\top\mathbf x' - \mathbf w^\top\mathbf x\); \(\rho \leftarrow \pi(A \mid S)/b(A \mid S)\)
  2. \(\mathbf w \leftarrow \mathbf w + \alpha\rho\big(\delta\mathbf x - \gamma\mathbf x'(\mathbf x^\top\mathbf v)\big)\)
  3. \(\mathbf v \leftarrow \mathbf v + \beta\rho(\delta - \mathbf v^\top\mathbf x)\mathbf x\)
# TDC on Baird's counterexample: replace part (1) of the snippet above with this.
rng = np.random.default_rng(0)
w, v, s = w0.copy(), np.zeros(8), int(rng.integers(7))
alpha, beta = 0.005, 0.05
for t in range(20_000):
    if rng.random() < 6 / 7:
        s2, rho = int(rng.integers(6)), 0.0
    else:
        s2, rho = 6, 7.0
    x, x2 = X[s], X[s2]
    delta = gamma * x2 @ w - x @ w
    w += alpha * rho * (delta * x - gamma * x2 * (x @ v))   # TD step plus gradient correction
    v += beta * rho * (delta - v @ x) * x                    # LMS estimate of E[xx^T]^-1 E[rho delta x]
    s = s2

delta_bar = gamma * X[6] @ w - X @ w                         # expected TD error per state under pi
g = X.T @ delta_bar / 7                                      # X^T D delta_bar with D uniform
print("PBE", g @ np.linalg.solve(X.T @ X / 7, g), "VE", np.mean((X @ w) ** 2))

In the reference run the weights stopped growing at once, and \(\overline{\text{PBE}}\) fell to about \(10^{-4}\) within 5,000 steps. \(\overline{\text{VE}}\) stayed near 3.7: the estimate settled close to a constant value of about 1.9 in every state. With \(\gamma = 0.99\) a nearly constant value function has a tiny Bellman error, so TDC creeps towards the true \(\mathbf v = \mathbf 0\) along that nearly flat direction very slowly. Stable is not the same as accurate, a point S&B also make about TDC on this example (§11.7).

Emphatic TD

Gradient-TD changes the objective; emphatic TD changes the distribution of updates. The idea is to reweight each update so that, in expectation, updates are distributed as they would be under the target policy's own visitation, restoring the stability of the on-policy case (Day 63) without changing the update rule. One-step emphatic TD (S&B §11.8) is

$$\delta_t = R_{t+1} + \gamma\hat v(S_{t+1}, \mathbf w_t) - \hat v(S_t, \mathbf w_t), \qquad \mathbf w_{t+1} = \mathbf w_t + \alpha M_t\rho_t\delta_t\nabla\hat v(S_t, \mathbf w_t), \qquad M_t = \gamma\rho_{t-1}M_{t-1} + I_t,$$

with \(M_{-1} = 0\) and an interest \(I_t\) saying how much we care about \(S_t\) (often 1). The emphasis \(M_t\) accumulates discounted, importance-weighted interest along the trajectory, so states that the target policy would reach are emphasized. In expectation, emphatic TD converges on Baird's counterexample. Its sampled version, however, has such high variance that S&B report it is nearly impossible to get consistent results in computational experiments with it on this problem.

Practical mitigations in deep RL

Deep value-based RL (Module 8) has all three ingredients and none of the guarantees. What it uses instead are engineering choices that each weaken one leg of the triad.

Van Hasselt et al. (2018) studied the triad empirically in deep Q-learning on Atari. They found unbounded divergence to be rare, but "soft divergence", temporarily very large value estimates, to be common, and found that target networks, double Q-learning and multi-step returns each reduced it. Gradient-TD and emphatic methods, despite their guarantees, are rarely used in deep RL: their extra step sizes and variance cost more in practice than the stability they buy.

What breaks
  • DQN is triad-complete. Q-learning with a neural network and replay has all three ingredients; its stabilizers are what stand between you and Baird's example.
  • Importance ratios inflate variance. Here \(\rho = 7\) on one step; in \(n\)-step or trace methods the product of ratios can be enormous.
  • Gradient-TD has two step sizes, both of which need tuning, and is often slow in practice.
  • Emphatic TD's variance can make its sampled version useless even where its expected version is provably stable.
  • "It stopped diverging" is not "it is right". TDC on Baird's example is stable and still far from the true values after 20,000 steps.
