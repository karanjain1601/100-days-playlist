DAY 10

The k-Armed Bandit Problem

30m video45m practice

A bandit is reinforcement learning with the state taken away: one situation, k actions, noisy rewards, and no consequences beyond the next reward. What remains is the exploration–exploitation dilemma in its purest form, and regret is the yardstick for how well an agent resolves it.

Formal setup

You face the same choice over and over. On each step \(t = 1, 2, \dots, T\) you pick one of \(k\) actions, or arms (after the slot machine, the “one-armed bandit”), \(A_t \in \{1, \dots, k\}\), and receive a reward \(R_t\) drawn from a distribution that depends only on the arm you pulled. Only the chosen arm's reward is revealed. The arms don't interact, and for now their distributions don't change.

A note on indexing: Chapter 2 of Sutton & Barto writes the reward for \(A_t\) as \(R_t\), not \(R_{t+1}\), because there is no next state for it to arrive with. This module follows that convention; Module 2 returns to \(R_{t+1}\).

Definition · stochastic k-armed bandit
  • A bandit is a tuple of reward distributions \(\nu = (P_1, \dots, P_k)\). Choosing \(A_t = a\) yields \(R_t \sim P_a\), independently of everything else that has happened.
  • True action value: \(q_*(a) \doteq \E[R_t \mid A_t = a]\). Optimal value: \(q_* \doteq \max_a q_*(a)\), attained by an optimal arm \(a^*\).
  • Gap: \(\Delta_a \doteq q_* - q_*(a) \ge 0\), the expected cost of pulling \(a\) once instead of \(a^*\).
  • Estimate: \(Q_t(a)\), the agent's estimate of \(q_*(a)\) before step \(t\); \(N_t(a)\), the number of times \(a\) was chosen before step \(t\).
  • Policy: a rule mapping the history \(\mathcal H_{t-1} = (A_1, R_1, \dots, A_{t-1}, R_{t-1})\) to a distribution over the next arm.

The agent never sees \(q_*\). If it did, the problem would be trivial: pull \(a^*\) forever. Everything interesting comes from having to estimate \(q_*\) from the rewards of the arms you happened to choose, while those same choices are what earn you reward.

The exploration–exploitation dilemma, stated precisely

At step \(t\) the greedy action is \(\argmax_a Q_t(a)\). Choosing it is exploiting: it maximises this step's expected reward under your current beliefs. Choosing any other arm \(a\) is exploring: by your own estimates it costs \(\max_b Q_t(b) - Q_t(a)\) now, and it buys one more sample of \(a\), which shrinks the uncertainty in \(Q_t(a)\) and might reveal that \(a\) is better than you thought, changing every later decision. A single pull cannot do both, and the value of the information depends on three things the one-step view ignores:

  • Horizon. With \(T - t\) steps left, a discovery can pay off at most \(T - t\) times. On the last step, always exploit.
  • Uncertainty. An arm sampled 3 times has a lot left to reveal; one sampled 3,000 times has almost nothing.
  • Gap. An arm whose estimate is far below the leader's needs a very lucky truth to matter.
Is there an optimal answer?

Yes, in a Bayesian sense. Put a prior on the unknown values; the posterior after each step is then the state of an MDP whose transitions are Bayesian updates, and planning in that MDP gives the Bayes-optimal exploration policy. For infinite-horizon discounted bandits with independent arms, Gittins (1979) showed this policy has a beautiful form: compute one number per arm from that arm's own posterior (its Gittins index) and pull the largest. In general the planning problem is intractable, which is why this module studies cheap strategies with strong guarantees rather than exact Bayes-optimality.

Regret and cumulative regret

Definition · regret

The (pseudo-)regret of a policy after \(T\) steps is the expected reward lost by not pulling \(a^*\) every time:

$$\mathcal R_T \doteq T\,q_* - \E\Big[\sum_{t=1}^{T} R_t\Big] = \sum_{t=1}^{T} \E\big[q_* - q_*(A_t)\big].$$

The per-step term \(q_* - q_*(A_t)\) is the instantaneous regret; the running sum is the cumulative regret, which is what learning-curve plots of regret show.

Maximising total reward and minimising regret are the same objective. Regret is more informative to plot because it is zero for a perfect agent, and its growth rate separates algorithms that eventually stop paying for exploration from those that never do.

Derivation · the regret decomposition

By the tower rule (Day 3), \(\E[R_t] = \E\big[\E[R_t \mid A_t]\big] = \E[q_*(A_t)]\). Write \(n_T(a) = \sum_{t=1}^T \mathbb 1\{A_t = a\}\) for the number of pulls of \(a\) in the first \(T\) steps. Then

$$\mathcal R_T = \sum_{t=1}^{T} \E\big[q_* - q_*(A_t)\big] = \E\Big[\sum_{t=1}^{T} \sum_{a} \mathbb 1\{A_t = a\}\,\Delta_a\Big] = \sum_{a} \Delta_a\, \E\big[n_T(a)\big].$$

Regret is a gap-weighted count of mistakes. To keep it small, pull every suboptimal arm rarely, and the arms with large gaps most rarely of all.

The decomposition explains the three growth rates you will see in this module:

  • Linear regret, \(\Theta(T)\). ε-greedy with a fixed ε pulls each arm with probability at least \(\varepsilon/k\) forever, so \(\mathcal R_T \ge \varepsilon T \frac1k \sum_a \Delta_a\). Pure greedy also has linear regret, because with positive probability it locks onto a suboptimal arm and never leaves (Day 11).
  • Logarithmic regret, \(O\big(\sum_{a:\Delta_a > 0} \ln T / \Delta_a\big)\). Achieved by UCB (Day 14) and Thompson sampling (Day 16): suboptimal arms are pulled only \(O(\ln T / \Delta_a^2)\) times.
  • No better than logarithmic. The lower bound below says no reasonable algorithm can do better.
Theorem · Lai & Robbins (1985) lower bound

For one-parameter families of reward distributions (Bernoulli, or Gaussian with known variance), any policy whose regret is \(o(T^p)\) for every \(p > 0\) on every bandit in the family must satisfy, for every suboptimal arm, \(\liminf_{T\to\infty} \E[n_T(a)] / \ln T \ge 1/\KL(P_a \,\|\, P_{a^*})\). Consequently

$$\liminf_{T \to \infty} \frac{\mathcal R_T}{\ln T} \;\ge \sum_{a:\,\Delta_a > 0} \frac{\Delta_a}{\KL(P_a \,\|\, P_{a^*})}.$$

For unit-variance Gaussian arms, \(\KL = \Delta_a^2 / 2\), so the constant is \(\sum_a 2/\Delta_a\): arms that are nearly as good as the best are the expensive ones, because they take many samples to tell apart.

One variant is worth knowing by name. Simple regret scores only the arm you recommend at the end, \(q_* - q_*(\hat a_T)\), ignoring what exploration cost along the way. It is the right objective for best-arm identification, when the experiment is a means to a decision (ship one website variant, pick one hyperparameter setting) and the reward collected during it doesn't matter.

Why bandits are RL with one state

Read as an MDP (Day 20), a bandit has a single state \(s\) that every action returns to: \(p(s, r \mid s, a) = P_a(r)\). The action value \(q_*(s, a)\) is just \(q_*(a)\) with the state dropped, and since the next state is always the same, the Bellman optimality equation collapses to \(q_*(a) = \E[R \mid a]\). Once \(q_*\) is known, the optimal policy is “pull \(a^*\)” for every discount factor. Sutton & Barto call this setting nonassociative: there is no need to associate different actions with different situations.

Regret vs a clean experiment

Adaptive allocation makes ordinary statistics harder. The sample mean of an arm you stopped pulling after a run of bad luck is biased downward, and p-values from fixed-sample tests no longer apply to adaptively collected data. If the goal is to measure an effect precisely (science, regulation), a fixed-allocation experiment may be the right tool. If the goal is reward collected while learning, a bandit is.

import numpy as np

class GaussianBandit:
    """k arms; arm a pays N(q_star[a], 1). One state, so there are no transitions."""
    def __init__(self, k=10, rng=None):
        self.rng = rng if rng is not None else np.random.default_rng()
        self.k = k
        self.q_star = self.rng.normal(0.0, 1.0, k)    # true action values, hidden from the agent

    def pull(self, a):
        return self.rng.normal(self.q_star[a], 1.0)

def pseudo_regret(bandit, actions):
    """sum_t [q* - q*(A_t)] = sum_a Delta_a n_T(a), the regret decomposition."""
    gaps = bandit.q_star.max() - bandit.q_star
    return gaps @ np.bincount(actions, minlength=bandit.k)

rng = np.random.default_rng(0)
env, T, m = GaussianBandit(rng=rng), 1000, 5
uniform = rng.integers(0, env.k, T)                       # explore forever

etc = np.zeros(T, dtype=int)                              # explore-then-commit:
etc[:m * env.k] = np.repeat(np.arange(env.k), m)          # m pulls of every arm...
samples = np.array([env.pull(a) for a in etc[:m * env.k]]).reshape(env.k, m)
etc[m * env.k:] = samples.mean(axis=1).argmax()           # ...then the best sample mean forever

print(pseudo_regret(env, uniform), pseudo_regret(env, etc))   # about 1229 and 61 on this seed

Uniform exploration pays the average gap on every step. Explore-then-commit pays for 50 exploratory pulls and is cheap on this seed, but on some bandits five samples per arm pick the wrong winner and the commitment phase then pays linear regret. That gamble is what the rest of the module tries to avoid.

What breaks · the assumptions behind the model
  • Stationarity. Real click-through rates drift with novelty, seasonality and competitors. Day 12 handles drift.
  • Independent rounds. If showing an ad changes whether the user comes back, actions affect future situations, and a bandit is optimising the wrong objective (Day 17's bridge to RL).
  • Immediate feedback. Conversions arrive hours later and decisions are made in batches. Deterministic algorithms such as UCB repeat the same choice for a whole batch; randomised ones such as Thompson sampling cope better (Day 16).
  • The comparator. Regret is measured against the best single arm. If the best arm depends on who the user is, that comparator is too weak and you need contextual regret.

DAY 11

Action-Value Estimation & ε-Greedy

40m video90m practice

Estimate each arm's value by averaging its rewards, then mostly act greedily on the estimates. The “mostly” matters: a purely greedy agent locks onto whatever looked good first, and a small, permanent dose of random exploration fixes that at a price you can compute exactly.

Sample-average estimation

The natural estimate of \(q_*(a) = \E[R_t \mid A_t = a]\) is the average of the rewards actually received from \(a\):

$$Q_t(a) \doteq \frac{\sum_{i=1}^{t-1} R_i\, \mathbb 1\{A_i = a\}}{\sum_{i=1}^{t-1} \mathbb 1\{A_i = a\}} = \frac{\text{sum of rewards from } a \text{ before } t}{N_t(a)},$$

with some default \(Q_1(a)\), usually 0, while \(N_t(a) = 0\). If \(a\) is chosen infinitely often, \(Q_t(a) \to q_*(a)\) by the law of large numbers (Day 3), and its standard error is \(\sigma / \sqrt{N_t(a)}\): the uncertainty shrinks only as the square root of the number of pulls. Sutton & Barto call methods built on such estimates action-value methods.

Greedy selection and why it fails

$$A_t \doteq \argmax_a Q_t(a), \qquad \text{ties broken uniformly at random.}$$

Greedy only ever samples the arm it currently believes is best. If the best arm's first rewards come in low, its estimate stays low forever, because an estimate only changes when its arm is pulled. Concretely, with \(Q_1 = 0\) everywhere: suppose the first pull lands on an arm with \(q_*(a) = 0.5\) and the reward is positive, which happens about 69% of the time. Now \(Q(a) > 0 = Q(b)\) for every other arm, so greedy pulls \(a\) again, and because its average drifts toward \(0.5 > 0\) there is a good chance it never drops below the untried arms' 0. In those runs the arm with \(q_* = 1.5\) is never tried at all. On the testbed below, greedy ends up on the optimal arm in only about a third of runs.

ε-greedy

Algorithm · ε-greedy with sample averages
  1. Initialise, for every arm \(a\): \(Q(a) \leftarrow 0\), \(N(a) \leftarrow 0\).
  2. Loop for \(t = 1, 2, \dots\):
    1. With probability \(1 - \varepsilon\): \(A \leftarrow \argmax_a Q(a)\) (random tie-breaking); otherwise \(A \leftarrow\) an arm chosen uniformly at random.
    2. \(R \leftarrow \text{bandit}(A)\)
    3. \(N(A) \leftarrow N(A) + 1\); \(\;Q(A) \leftarrow Q(A) + \frac{1}{N(A)}\big[R - Q(A)\big]\) (the running average; Day 12 derives it)

The random arm can be the greedy one, so the greedy arm is chosen with probability \(1 - \varepsilon + \varepsilon/k\) and every other arm with probability \(\varepsilon/k\).

Result · ε-greedy in the limit

Every arm is chosen with probability at least \(\varepsilon / k\) on every step, so each is chosen infinitely often and \(Q_t(a) \to q_*(a)\) for all \(a\) almost surely. Hence \(\Pr(A_t = a^*) \to 1 - \varepsilon + \varepsilon/k\) (0.91 for \(\varepsilon = 0.1\), 0.991 for \(\varepsilon = 0.01\), with \(k = 10\)), and the expected reward per step tends to

$$\Big(1 - \varepsilon + \frac{\varepsilon}{k}\Big) q_* + \frac{\varepsilon}{k}\sum_{a \ne a^*} q_*(a) = (1 - \varepsilon)\, q_* + \frac{\varepsilon}{k} \sum_{a} q_*(a).$$

On the testbed below, \(\E[q_*]\), the expected maximum of ten standard normals, is about 1.54, and the expected mean of the ten values is 0. So the long-run reward is about \(0.9 \times 1.54 \approx 1.39\) for \(\varepsilon = 0.1\) and \(0.99 \times 1.54 \approx 1.52\) for \(\varepsilon = 0.01\). The gap to 1.54 is paid on every step forever: constant-ε exploration has linear regret.

The 10-armed testbed

Definition · the testbed (Sutton & Barto §2.3)

Generate 2,000 independent 10-armed bandits. In each, draw \(q_*(a) \sim \mathcal N(0, 1)\) for \(a = 1, \dots, 10\); pulling \(a\) returns \(R_t \sim \mathcal N(q_*(a), 1)\). Run each method for 1,000 steps on every bandit, and at each step \(t\) average two quantities over the 2,000 runs: the reward \(R_t\), and the indicator that \(A_t\) was the optimal arm (“% optimal action”).

Averaging across runs, not across time, is what turns noisy single trajectories into a learning curve. Note the scale: the reward noise (σ = 1) is as large as the spread of the true values, so one sample of an arm says very little about whether it is the best.

Building the testbed yourself

Don't loop over runs in Python. Hold every per-arm quantity in an array of shape [runs, k] and advance all 2,000 bandits in one vectorized step; each method then takes a few seconds rather than minutes.

import numpy as np

def testbed(eps, k=10, steps=1000, runs=2000, seed=0):
    """eps-greedy with sample averages on `runs` independent 10-armed bandits at once."""
    rng = np.random.default_rng(seed)
    q_star = rng.normal(0.0, 1.0, (runs, k))         # a fresh bandit for every run
    best = q_star.argmax(axis=1)
    sums, counts = np.zeros((runs, k)), np.zeros((runs, k))
    rows = np.arange(runs)
    reward, optimal = np.zeros(steps), np.zeros(steps)
    for t in range(steps):
        Q = np.where(counts > 0, sums / np.maximum(counts, 1), 0.0)   # sample averages, Q_1 = 0
        is_max = Q == Q.max(axis=1, keepdims=True)
        greedy = np.argmax(rng.random((runs, k)) * is_max, axis=1)    # random tie-breaking
        explore = rng.random(runs) < eps
        A = np.where(explore, rng.integers(0, k, runs), greedy)
        R = rng.normal(q_star[rows, A], 1.0)
        sums[rows, A] += R
        counts[rows, A] += 1
        reward[t], optimal[t] = R.mean(), (A == best).mean()
    return reward, optimal

for eps in [0.0, 0.01, 0.1]:
    r, o = testbed(eps)
    print(f"eps={eps:<5} reward(last 100)={r[-100:].mean():.2f}  optimal(last 100)={o[-100:].mean():.0%}")

The tie-breaking line multiplies uniform noise by a 0/1 mask of the maximal entries, so argmax picks uniformly among the tied maxima. Fancy indexing with rows, A updates exactly one arm per run.

Asymptotic vs early performance

Intuition · count the exploratory samples

After \(t\) steps, ε-greedy has given each arm about \(\varepsilon t / k\) exploratory pulls. At \(t = 1{,}000\) that is about 10 per arm for \(\varepsilon = 0.1\), enough to separate arms whose values differ by roughly \(2\sigma/\sqrt{10} \approx 0.6\). For \(\varepsilon = 0.01\) it is about one pull per arm: the agent is still mostly guessing. But ε = 0.1 keeps paying for its 10% exploration forever, while ε = 0.01 eventually knows almost as much and wastes ten times less. Over a long enough horizon, ε = 0.01 wins on both measures.

The right amount of exploration therefore depends on the horizon and on the noise. With reward variance 10 instead of 1, every estimate needs ten times as many samples, and heavier exploration pays off. With zero noise, one pull per arm reveals its value exactly; try each arm once, then exploit, and any further exploration is pure waste. Nonstationarity (Day 12) pushes the other way: if the values drift, exploration never stops being useful.

The usual way to get both early exploration and late exploitation is to decay ε over time. Auer, Cesa-Bianchi & Fischer (2002) analysed \(\varepsilon_t = \min\{1, ck/(d^2 t)\}\), which achieves logarithmic regret when \(d\) is a lower bound on the smallest gap. That requires knowing \(d\), and with a wrong choice the decay is either too slow (wasted pulls) or too fast (lock-in). Day 38 formalises the requirement as GLIE: greedy in the limit, with infinite exploration.

What breaks
  • np.argmax(Q) without random tie-breaking returns the first maximal index. At the start every \(Q\) is 0, so “greedy” always opens with arm 0, and every later tie is resolved toward low indices. Curves change, and with optimistic initialisation (Day 13) the agent's exploration order becomes fixed.
  • Uniform exploration is blind. ε-greedy spends as many exploratory pulls on an arm estimated at −2 after 200 samples as on one estimated at 1.4 after 3. UCB (Day 14) and Thompson sampling (Day 16) direct exploration where it can still change the decision.
  • Constant ε means linear regret. The cost \(\varepsilon\big(q_* - \tfrac1k \sum_a q_*(a)\big)\) is paid every step, forever.
  • Single runs. One bandit's learning curve is mostly noise. The 2,000-run average exists for the same reasons as multi-seed RL experiments (Day 7).

DAY 12

Incremental Updates & Nonstationarity

35m video75m practice

A running average can be updated in constant time and memory, and the update has a shape you will meet in every module of this course: move the estimate a step toward a target. Replace the shrinking step \(1/n\) with a constant \(\alpha\) and the estimate stops converging, which is exactly what you want when the world is drifting.

The incremental mean update

Storing every reward and re-averaging costs memory and time that grow without bound. Focus on one arm and let \(Q_n\) be its estimate after \(n - 1\) rewards \(R_1, \dots, R_{n-1}\) from that arm.

Derivation $$\begin{aligned} Q_{n+1} &= \frac1n \sum_{i=1}^{n} R_i = \frac1n \Big( R_n + \sum_{i=1}^{n-1} R_i \Big) = \frac1n \Big( R_n + (n - 1)\, Q_n \Big) \\ &= \frac1n \big( R_n + n Q_n - Q_n \big) = Q_n + \frac1n \big[ R_n - Q_n \big]. \end{aligned}$$

The identity holds for \(n = 1\) too: \(Q_2 = Q_1 + (R_1 - Q_1) = R_1\), whatever \(Q_1\) was. One float and one counter per arm, and \(O(1)\) work per step.

Here \(n\) counts pulls of this arm, \(N(a)\) in the algorithm of Day 11, not the global time step \(t\). Mixing them up is a common bug.

The universal update form

$$\text{NewEstimate} \;\leftarrow\; \text{OldEstimate} + \text{StepSize}\,\big[\,\text{Target} - \text{OldEstimate}\,\big].$$

The bracket is the error in the estimate. The target is a noisy indication of where the estimate should go: here a single reward, later a return or a bootstrapped guess. Constant step size

The sample average weights a reward from long ago exactly as much as yesterday's. That is optimal when \(q_*(a)\) never changes and wrong when it does. If the problem is nonstationary, recent rewards say more about the current value than old ones, and the simplest fix is a constant step size \(\alpha \in (0, 1]\):

$$Q_{n+1} = Q_n + \alpha \big[ R_n - Q_n \big].$$

The exponential recency-weighted average

Derivation · unrolling the recursion $$\begin{aligned} Q_{n+1} &= \alpha R_n + (1 - \alpha)\, Q_n \\ &= \alpha R_n + (1 - \alpha)\big[\alpha R_{n-1} + (1 - \alpha)\, Q_{n-1}\big] \\ &= \alpha R_n + (1 - \alpha)\,\alpha R_{n-1} + (1 - \alpha)^2\, Q_{n-1} \\ &= \cdots = (1 - \alpha)^n\, Q_1 + \sum_{i=1}^{n} \alpha (1 - \alpha)^{n - i} R_i . \end{aligned}$$

The weights sum to one, using the geometric series \(\sum_{j=0}^{n-1} (1-\alpha)^j = \frac{1 - (1-\alpha)^n}{\alpha}\):

$$(1 - \alpha)^n + \alpha \sum_{i=1}^{n} (1 - \alpha)^{n-i} = (1 - \alpha)^n + \alpha \cdot \frac{1 - (1 - \alpha)^n}{\alpha} = 1.$$

So \(Q_{n+1}\) is a weighted average of \(Q_1\) and the rewards, and a reward that is \(j\) pulls old carries weight \(\alpha(1 - \alpha)^j\), decaying exponentially with age.

Three properties follow from the unrolled form:

  • Memory. Since \((1 - \alpha)^{1/\alpha} \approx e^{-1}\), weights fall by a factor of \(e\) every \(1/\alpha\) pulls, and the rewards older than \(m\) pulls share total weight \((1 - \alpha)^m\). The effective window is about \(1/\alpha\) samples: 10 for \(\alpha = 0.1\), 100 for \(\alpha = 0.01\).
  • Bias. \(Q_1\) keeps weight \((1 - \alpha)^n\), so the estimate is biased toward the initial value, with the bias decaying geometrically. Day 13 turns this bias into an exploration strategy.
  • Variance floor. For i.i.d. rewards with variance \(\sigma^2\), \(\Var[Q_{n+1}] = (1 - \alpha)^2 \Var[Q_n] + \alpha^2 \sigma^2\). Its fixed point \(v\) solves \(v\,\big(1 - (1-\alpha)^2\big) = \alpha^2 \sigma^2\), so \(v = \alpha \sigma^2 / (2 - \alpha)\). With \(\alpha = 0.1\) and \(\sigma = 1\) the estimate's standard deviation never falls below about 0.23, however many samples you take. The sample average's variance \(\sigma^2 / n\) goes to zero.

Tracking a drifting bandit

Sutton & Barto's Exercise 2.5 makes the testbed nonstationary: all ten \(q_*(a)\) start equal and each takes an independent random-walk step \(\mathcal N(0, 0.01^2)\) after every time step. Compare sample averages with \(\alpha = 0.1\), both with \(\varepsilon = 0.1\), over 10,000 steps.

import numpy as np

def drifting(alpha=None, eps=0.1, k=10, steps=10_000, runs=500, walk=0.01, seed=0):
    """Nonstationary testbed: alpha=None means sample averages (1/n), else constant alpha."""
    rng = np.random.default_rng(seed)
    q_star = np.zeros((runs, k))                          # all arms start equal...
    Q, N = np.zeros((runs, k)), np.zeros((runs, k))
    rows = np.arange(runs)
    optimal = np.zeros(steps)
    for t in range(steps):
        is_max = Q == Q.max(axis=1, keepdims=True)
        greedy = np.argmax(rng.random((runs, k)) * is_max, axis=1)
        A = np.where(rng.random(runs) < eps, rng.integers(0, k, runs), greedy)
        R = rng.normal(q_star[rows, A], 1.0)
        N[rows, A] += 1
        step = 1.0 / N[rows, A] if alpha is None else alpha
        Q[rows, A] += step * (R - Q[rows, A])             # NewEstimate <- Old + step [Target - Old]
        optimal[t] = (A == q_star.argmax(axis=1)).mean()
        q_star += rng.normal(0.0, walk, (runs, k))        # ...then drift as independent random walks
    return optimal

for alpha in [None, 0.1]:
    o = drifting(alpha)
    print(f"alpha={alpha}: optimal over last 1000 steps = {o[-1000:].mean():.0%}")

Seed 0, 500 runs: about 46% optimal over the last 1,000 steps for sample averages against about 75% for α = 0.1. By then the sample-average agent's step sizes for its favourite arms have shrunk to a few thousandths, and its estimates can no longer keep up with the walk.

Intuition · α trades noise for lag

A small α averages over a long window: low noise (variance \(\alpha\sigma^2/(2-\alpha)\)) but a lag of roughly \(1/\alpha\) pulls behind a moving target. A large α follows the target closely but jitters. The best α balances the drift rate against the reward noise. This is not just an analogy: for a Gaussian random walk observed through Gaussian noise, the steady-state Kalman filter is exactly a constant-α average, with α set by the ratio of drift variance to noise variance.

Robbins–Monro conditions, and why constant α violates them

Theorem · convergence of the sample estimates

Let \(\alpha_n(a)\) be the step size used on the \(n\)-th selection of arm \(a\). For a stationary arm with finite reward variance, \(Q_n(a) \to q_*(a)\) with probability 1 if

$$\sum_{n=1}^{\infty} \alpha_n(a) = \infty \qquad\text{and}\qquad \sum_{n=1}^{\infty} \alpha_n^2(a) < \infty.$$

These are the stochastic-approximation conditions of Day 5. The first makes the steps large enough, in total, to overcome the initial condition and any early noise; the second makes them shrink fast enough for the noise to average out. The sample average's \(\alpha_n = 1/n\) passes both: the harmonic series diverges and \(\sum 1/n^2 = \pi^2/6\). A constant α fails the second, since \(\sum \alpha^2 = \infty\): the estimate never converges, and keeps fluctuating with variance \(\alpha\sigma^2/(2-\alpha)\). That failure is precisely what lets it track. Step-size sequences that satisfy the conditions tend to converge slowly or need careful tuning, so they appear mostly in theory; practical RL, deep RL included, runs on constant or slowly decayed step sizes.

Exercise 2.7 · recency weighting without initial bias

Use step size \(\beta_n = \alpha / \bar o_n\), where \(\bar o_n = \bar o_{n-1} + \alpha(1 - \bar o_{n-1})\) and \(\bar o_0 = 0\). Then \(\bar o_1 = \alpha\), so \(\beta_1 = 1\) and the first reward replaces \(Q_1\) entirely; and \(\bar o_n = 1 - (1-\alpha)^n \to 1\), so \(\beta_n \to \alpha\). The result is an exponential recency-weighted average with no weight on \(Q_1\) at all. Keep it in mind for tomorrow: it removes the bias that optimistic initialisation relies on.

What breaks
  • Global \(t\) instead of \(N(a)\) in a \(1/n\) step: every arm's step shrinks with time even if it is rarely pulled, so rarely pulled arms barely learn from the samples they do get.
  • \(1/n\) in a drifting world. The estimate freezes on the past. Nothing in the learning curve announces it except a slow decay in % optimal.
  • α too large. At \(\alpha = 1\) the estimate is just the last reward, and with σ = 1 noise the agent chases noise.
  • Constant α in a stationary world. You pay the variance floor forever, and \(Q_1\) never quite washes out. Whether that is harmful depends on \(Q_1\), which is tomorrow's lesson.

DAY 13

Optimistic Initial Values

25m video45m practice

Start every estimate above any plausible true value and even a purely greedy agent explores: each arm it tries disappoints it, so it moves on, until the estimates have been pulled down to reality. It is a cheap trick, it leaves a distinctive spike in the learning curve, and it explores only once.

Optimism as implicit exploration

Every method so far depends on the initial estimates \(Q_1(a)\); with a constant step size that bias never fully disappears (Day 12). Use it on purpose. On the testbed \(q_*(a) \sim \mathcal N(0, 1)\), so \(Q_1(a) = +5\) is wildly optimistic. A greedy agent picks an arm, the reward (around \(q_*(a) \pm 1\)) is far below 5, the estimate falls, and some untried arm, still at 5, now looks better. Exploration emerges from greed plus disappointment, without any randomness in the action choice.

The principle has a name, optimism in the face of uncertainty: act as if each uncertain option is as good as it could plausibly be. Either the optimism is justified and you gain reward, or it isn't and you learn that quickly. UCB (Day 14) turns the principle into a rule with guarantees; today's version is the crude one.

The effect of the initial value

Derivation · how long optimism lasts

Ignore the noise for a moment. Under a constant step size, after \(n\) pulls the arm's estimate is \(q_*(a) + (1 - \alpha)^n \big(Q_1 - q_*(a)\big)\). The excess optimism falls below \(\delta\) once

$$n \;\ge\; \frac{\ln\!\big((Q_1 - q_*(a))/\delta\big)}{-\ln(1 - \alpha)} \;\approx\; \frac{1}{\alpha}\,\ln\frac{Q_1 - q_*(a)}{\delta}.$$

For \(Q_1 = 5\), \(\alpha = 0.1\), \(q_*(a) \approx 0\) and \(\delta = 0.5\), that is about 22 pulls per arm, roughly 220 steps on ten arms, before the agent stops being driven by its prior. The exploration budget grows with \(1/\alpha\) but only logarithmically with the amount of optimism.

With sample averages the picture is completely different. The first update sets \(Q_2 = R_1\) whatever \(Q_1\) was (Day 12), so under \(1/n\) an optimistic start means exactly “try every arm once, then be greedy”. That is a sensible opening, the same one UCB uses, but it is not lasting exploration.

How optimistic should you be? Too little and nothing happens; too much and the agent spends hundreds of steps disappointing itself. Average reward over the first 1,000 testbed steps for greedy with \(\alpha = 0.1\) (2,000 runs, seed 0):

Spike-then-settle learning curves

The curve looks bizarre until you trace one run (this is Sutton & Barto's Exercise 2.6):

  1. Steps 1–10. All estimates are 5. Each pull drops the pulled arm to \(5 + 0.1(R - 5) = 4.5 + 0.1R\), below every untouched arm, so the agent pulls each arm exactly once, in random order. % optimal is about 10%.
  2. Step 11. Every arm now has one sample, and the estimates \(4.5 + 0.1 R_1(a)\) rank the arms by their single reward. The arm with the highest first sample is the optimal one in about 43% of runs: the spike.
  3. Steps 12–20. The arm just pulled drops again, by about \(0.1 \times (4.5 - q_*) \approx 0.4\), far below the others, whose estimates differ only by a tenth of their sample differences. So the agent avoids the optimal arm precisely because it just chose it: % optimal dips below the 10% baseline, to about 9% at step 16.
  4. After that. The rounds blur as estimates spread out, optimism drains away as derived above, and the curve climbs past realistic ε-greedy, which keeps paying for random exploration.

The UCB curve in the Day 11 demo has a spike at exactly the same step, for a closely related reason: UCB also opens with one pull of every arm and then briefly favours the best first sample. Day 14 works through it.

import numpy as np

def constant_alpha_testbed(Q1, eps, alpha=0.1, k=10, steps=1000, runs=2000, seed=0):
    rng = np.random.default_rng(seed)
    q_star = rng.normal(0.0, 1.0, (runs, k))
    best, rows = q_star.argmax(axis=1), np.arange(runs)
    Q = np.full((runs, k), float(Q1))                     # the only change: where Q starts
    optimal = np.zeros(steps)
    for t in range(steps):
        is_max = Q == Q.max(axis=1, keepdims=True)
        greedy = np.argmax(rng.random((runs, k)) * is_max, axis=1)
        A = np.where(rng.random(runs) < eps, rng.integers(0, k, runs), greedy)
        R = rng.normal(q_star[rows, A], 1.0)
        Q[rows, A] += alpha * (R - Q[rows, A])
        optimal[t] = (A == best).mean()
    return optimal

opt = constant_alpha_testbed(Q1=5.0, eps=0.0)            # optimistic, greedy
real = constant_alpha_testbed(Q1=0.0, eps=0.1)           # realistic, eps-greedy
print("step 11:", f"{opt[10]:.0%}", " steps 12-20:", np.round(100 * opt[11:20]).astype(int))

Intuition · systematic, not random

Optimistic exploration is a round-robin sweep, not a dice roll. Early on that is more efficient than ε-greedy, which wastes pulls on repeats, and it is why the optimistic curve is so jagged: thousands of runs march in lockstep through the same phases. It is also deterministic given the rewards, which matters for batched feedback (Day 16).

Why it only works for stationary problems

The drive to explore is a transient, spent at the start. Once the estimates have come down to reality, an optimistic greedy agent is simply greedy. If the values change at step 5,000, because the best arm gets worse or another improves, nothing makes the agent look again: an arm's estimate only moves when the arm is pulled. In Sutton & Barto's words, the beginning of time occurs only once, so a method that relies on the initial conditions cannot help with the general nonstationary case. Practice task 4 shows it.

Interaction with constant α

  • \(1/n\) steps: the optimism lasts one pull per arm and then vanishes.
  • Constant α: it lasts about \(\frac1\alpha \ln\frac{Q_1 - q_*}{\delta}\) pulls per arm. Smaller α means longer, more thorough exploration, but also slower learning once it is over.
  • The unbiased step size of Day 12: \(\beta_1 = 1\) wipes \(Q_1\) on the first pull, so optimism disappears too. You can have no initial bias or a useful optimistic bias, not both.

Optimistic initialisation with a constant step size remains a standard trick in tabular RL: initialise \(Q(s, a)\) high and a greedy agent sweeps a gridworld systematically. R-MAX (Day 102) makes it principled for MDPs, treating every insufficiently visited state–action pair as maximally rewarding. In deep RL it barely works, because a network has no per-state initial value to set and generalisation spreads the disappointment from visited states to unvisited ones.

What breaks
  • \(Q_1\) below the best arm's value gives no exploration at all: you need an upper bound on rewards, and if rewards can reach 100, \(Q_1 = 5\) is pessimistic.
  • \(Q_1\) far too high with small α wastes hundreds of pulls disappointing every arm many times over.
  • Noise large relative to \(Q_1 - q_*\) makes the ranking after each sweep mostly noise.
  • Nonstationarity: exploration happens once, at the start, and never again.
  • Function approximation: there is no table to initialise, and optimism leaks away through generalisation.

DAY 14

Upper Confidence Bound (UCB)

40m video75m practice

Explore where you are uncertain, not at random. UCB adds to each estimate a bonus that is large when an arm has been tried rarely and shrinks as evidence accumulates, then acts greedily on the sum. The bonus is the half-width of a confidence interval, and Hoeffding's inequality says how wide it must be.

Uncertainty-aware selection

ε-greedy's exploratory pulls are uniform: an arm estimated at −2 after 200 samples gets the same share as one estimated at 1.4 after 3. Two things should matter instead: how close an arm's estimate is to the best one, and how uncertain that estimate still is. An arm deserves a pull if it might plausibly be the best. Optimistic initialisation (Day 13) applied that idea once, at the start; UCB applies it at every step, with an optimism that is recomputed from the data.

The UCB rule, term by term

$$A_t \doteq \argmax_a \left[\, Q_t(a) + c \sqrt{\frac{\ln t}{N_t(a)}} \,\right], \qquad \text{an arm with } N_t(a) = 0 \text{ counts as maximal.}$$
  • \(Q_t(a)\): the exploitation term, the current sample-average estimate.
  • \(1/\sqrt{N_t(a)}\): the uncertainty, shrinking like the standard error. Pulling \(a\) narrows its own bonus.
  • \(\ln t\): grows slowly but without bound, so the bonus of an arm that is not being pulled creeps upward. Every arm is eventually revisited, infinitely often, but a bad arm only logarithmically often.
  • \(c > 0\): the confidence level, which must match the reward scale and noise. \(c = 0\) is greedy after the first round.

Because untried arms count as maximal, the first \(k\) steps pull every arm once. After that the rule is deterministic: the same history always produces the same action.

Confidence-interval intuition

Hoeffding's inequality, sketched

Theorem · Hoeffding's inequality

Let \(X_1, \dots, X_n\) be i.i.d. with values in \([0, 1]\), mean \(\mu\) and sample mean \(\hat\mu_n\). For every \(u > 0\),

$$\Pr\big(\hat\mu_n \ge \mu + u\big) \le e^{-2nu^2} \qquad\text{and}\qquad \Pr\big(\hat\mu_n \le \mu - u\big) \le e^{-2nu^2}.$$
Proof sketch · the Chernoff method

For any \(\lambda > 0\), exponentiate and apply Markov's inequality, then use independence:

$$\Pr\big(\hat\mu_n - \mu \ge u\big) = \Pr\Big(e^{\lambda \sum_i (X_i - \mu)} \ge e^{\lambda n u}\Big) \le e^{-\lambda n u}\, \E\Big[e^{\lambda \sum_i (X_i - \mu)}\Big] = e^{-\lambda n u} \prod_{i=1}^{n} \E\big[e^{\lambda (X_i - \mu)}\big].$$

Hoeffding's lemma bounds each factor: a variable confined to \([a, b]\) satisfies \(\E\big[e^{\lambda(X - \E X)}\big] \le e^{\lambda^2 (b-a)^2/8}\). With \([a, b] = [0, 1]\) the bound becomes \(\exp(-\lambda n u + n\lambda^2/8)\). The exponent is minimised at \(\lambda = 4u\), giving \(\exp(-4nu^2 + 2nu^2) = e^{-2nu^2}\). The lower tail is the same argument applied to \(-X_i\).

Derivation · from the tail bound to the bonus

Fix a failure probability \(\delta\) and solve \(\delta = e^{-2nu^2}\) for the deviation: \(u = \sqrt{\ln(1/\delta) / (2n)}\). So with probability at least \(1 - \delta\),

$$\mu \;\le\; \hat\mu_n + \sqrt{\frac{\ln(1/\delta)}{2n}},$$

an upper confidence bound on the arm's true value from \(n\) samples. The agent consults its bounds at every step, so the failure probability has to shrink over time for the total number of failures to stay small. Choosing \(\delta = t^{-4}\) gives

$$u = \sqrt{\frac{4 \ln t}{2n}} = \sqrt{\frac{2 \ln t}{n}},$$

which is exactly the bonus of UCB1 (Auer, Cesa-Bianchi & Fischer 2002): the rule above with \(c = \sqrt 2\), for rewards in \([0, 1]\). For Gaussian noise with standard deviation σ the tail is \(e^{-nu^2/(2\sigma^2)}\) and the bonus becomes \(\sigma \sqrt{2 \ln(1/\delta)/n}\); a δ shrinking like \(1/t\) gives \(c = \sqrt 2\, \sigma \approx 1.4\) for the testbed's unit noise.

Theorem · UCB1 regret (Auer et al. 2002)

With rewards in \([0, 1]\) and bonus \(\sqrt{2 \ln t / N_t(a)}\), for every horizon \(T\) and every suboptimal arm \(a\),

$$\E\big[n_T(a)\big] \le \frac{8 \ln T}{\Delta_a^2} + 1 + \frac{\pi^2}{3}, \qquad\text{so}\qquad \mathcal R_T \le \sum_{a:\,\Delta_a > 0} \frac{8 \ln T}{\Delta_a} + \Big(1 + \frac{\pi^2}{3}\Big) \sum_a \Delta_a .$$

The proof idea fits in a paragraph. Once a suboptimal arm has \(N \ge 8 \ln T / \Delta_a^2\) samples, its bonus is at most \(\Delta_a / 2\). UCB can then prefer it over \(a^*\) only if \(a\)'s estimate is more than \(\Delta_a / 2\) too high, or \(a^*\)'s upper bound has fallen below \(q_*\). By Hoeffding each event has probability at most \(t^{-4}\), and summing over steps and sample counts gives the finite constant \(\pi^2/3\). So beyond about \(8 \ln T / \Delta_a^2\) pulls, further pulls of \(a\) are rare accidents. The \(\ln T\) rate matches the Lai–Robbins lower bound of Day 10; the constant does not, and refinements such as KL-UCB close most of that gap.

Sweeping c

import numpy as np

def ucb_testbed(c, k=10, steps=1000, runs=2000, seed=0):
    rng = np.random.default_rng(seed)
    q_star = rng.normal(0.0, 1.0, (runs, k))
    best, rows = q_star.argmax(axis=1), np.arange(runs)
    Q, N = np.zeros((runs, k)), np.zeros((runs, k))
    reward = np.zeros(steps)
    for t in range(steps):
        bonus = c * np.sqrt(np.log(t + 1) / np.maximum(N, 1))
        U = np.where(N == 0, np.inf, Q + bonus)           # untried arms are maximal
        is_max = U == U.max(axis=1, keepdims=True)

        N[rows, A] += 1
        Q[rows, A] += (R - Q[rows, A]) / N[rows, A]
        reward[t] = R.mean()
    return reward

The demo also shows UCB's spike, Sutton & Barto's Exercise 2.8. Average reward jumps to about 1.09 at step 11 (ε-greedy is near 0.8 there) and then drops back for several steps. Steps 1–10 pull each arm once. At step 11 every \(N = 1\), so every bonus is equal and UCB picks the arm with the highest single sample, which is the optimal arm in about 44% of runs. That pull raises the arm's count to \(N = 2\) and cuts its bonus by a factor of \(\sqrt 2\), while every other arm still has \(N = 1\) and a bonus growing with \(\ln t\). With \(c = 2\) the bonus difference (about 0.9 at step 12) usually outweighs the gap in estimates, so UCB spends the next several steps on the other arms and reward falls. With smaller \(c\) the dip is shallower. The step-11 reward is identical for every c, since all bonuses are equal at that step, as the snippet's output confirms.

What breaks · large and nonstationary problems
  • Many arms. UCB must pull every arm once before its formula is even defined. With \(k\) comparable to \(T\), or a continuous action set, that is impossible without structure linking the arms: linear models (LinUCB, Day 17) or Gaussian processes (GP-UCB).
  • Nonstationarity. \(N_t(a)\) only grows. An arm pulled 5,000 times has a tiny bonus and a sample average that moves at a rate of 1/5,000, so a change in its value goes unnoticed for a long time. Discounted UCB and sliding-window UCB (Garivier & Moulines 2011) compute counts and means over recent data only.
  • No counts in large state spaces. In full RL with function approximation, states rarely repeat and \(N(s, a)\) is meaningless; pseudo-counts (Day 103) approximate them. Where counts do exist, at the nodes of a search tree, UCB thrives: UCT in Monte Carlo tree search is UCB1 at every node (Day 59).
  • Determinism under batched feedback. If you must choose 1,000 actions before seeing any result, UCB picks the same arm 1,000 times. Thompson sampling randomises naturally (Day 16).
  • Scale. c must match the reward scale. Hoeffding bounds assume a known range; with Gaussian or heavy-tailed rewards the right c is a modelling choice, not a constant.

DAY 15

Gradient Bandit Algorithms

40m video75m practice

Instead of estimating values and acting greedily on them, learn a policy directly: keep a numerical preference for each arm, turn preferences into probabilities with a softmax, and climb the gradient of expected reward. The update you derive is REINFORCE in miniature, and the baseline that makes it work is the same baseline that rescues every policy-gradient method in Module 9.

Action preferences

Each arm has a preference \(H_t(a) \in \R\), initially \(H_1(a) = 0\). Preferences are not estimates of reward and have no units; only their differences matter. Adding the same constant to every preference leaves the policy unchanged.

The softmax (Boltzmann) distribution

$$\pi_t(a) \doteq \Pr(A_t = a) = \frac{e^{H_t(a)}}{\sum_{b=1}^{k} e^{H_t(b)}}.$$

At the start all preferences are zero and the policy is uniform. Every arm always keeps a positive probability, so exploration comes from the policy's own randomness and fades only as the preferences spread apart. The name comes from the Boltzmann distribution of statistical physics, usually written with a temperature, \(e^{H(a)/\tau}\): as \(\tau \to 0\) it approaches the greedy argmax, as \(\tau \to \infty\) it approaches uniform. Here there is no explicit τ; the scale of the learned preferences plays its role. Shift invariance is also the numerically safe way to compute it: subtract \(\max_b H(b)\) before exponentiating.

Derivation · the softmax derivative

Write \(Z = \sum_b e^{H(b)}\), so \(\partial Z / \partial H(a) = e^{H(a)}\). For \(x = a\), the quotient rule gives \(\frac{e^{H(a)}}{Z} - \frac{e^{H(a)} e^{H(a)}}{Z^2} = \pi(a) - \pi(a)^2\); for \(x \ne a\), it gives \(-\frac{e^{H(x)} e^{H(a)}}{Z^2} = -\pi(x)\pi(a)\). Both cases at once:

$$\frac{\partial \pi(x)}{\partial H(a)} = \pi(x)\,\big(\mathbb 1\{a = x\} - \pi(a)\big).$$

The update rule

After choosing \(A_t\) and receiving \(R_t\), update every preference:

$$\begin{aligned} H_{t+1}(A_t) &= H_t(A_t) + \alpha\,(R_t - \bar R_t)\,\big(1 - \pi_t(A_t)\big), \\ H_{t+1}(a) &= H_t(a) - \alpha\,(R_t - \bar R_t)\,\pi_t(a) \qquad \text{for all } a \ne A_t, \end{aligned}$$

or in one line, \(H_{t+1}(a) = H_t(a) + \alpha (R_t - \bar R_t)\big(\mathbb 1\{a = A_t\} - \pi_t(a)\big)\). Here \(\bar R_t\) is the average of the rewards received before step \(t\), the baseline. A reward above the baseline raises the chosen arm's preference and lowers every other arm's in proportion to its probability; a reward below the baseline does the reverse.

Stochastic gradient ascent on expected reward

The quantity we want to increase is the expected reward under the current policy,

$$\E[R_t] = \sum_x \pi_t(x)\, q_*(x).$$

Exact gradient ascent would update \(H_{t+1}(a) = H_t(a) + \alpha\, \partial \E[R_t] / \partial H_t(a)\). We can't compute that gradient, because it involves the unknown \(q_*\). The claim is that the gradient-bandit update equals it in expectation, which makes the algorithm an instance of stochastic gradient ascent (Day 5).

The full derivation

Derivation · the gradient-bandit update is SGA

Step 1: insert a baseline for free. Since the probabilities sum to one, \(\sum_x \partial \pi_t(x)/\partial H_t(a) = \partial 1 / \partial H_t(a) = 0\). So for any scalar \(B_t\) that does not depend on \(x\),

$$\frac{\partial \E[R_t]}{\partial H_t(a)} = \sum_x q_*(x)\, \frac{\partial \pi_t(x)}{\partial H_t(a)} = \sum_x \big(q_*(x) - B_t\big)\, \frac{\partial \pi_t(x)}{\partial H_t(a)}.$$

Step 2: turn the sum into an expectation. Multiply and divide each term by \(\pi_t(x)\); the sum over \(x\) weighted by \(\pi_t(x)\) is an expectation over \(A_t \sim \pi_t\):

$$= \sum_x \pi_t(x)\, \big(q_*(x) - B_t\big)\, \frac{\partial \pi_t(x) / \partial H_t(a)}{\pi_t(x)} = \E\left[ \big(q_*(A_t) - B_t\big)\, \frac{\partial \pi_t(A_t)/\partial H_t(a)}{\pi_t(A_t)} \right].$$

Step 3: replace the unknown value by the observed reward. Given \(A_t\), the reward has mean \(q_*(A_t)\), and nothing else in the bracket depends on \(R_t\), so by the tower rule we may substitute \(R_t\):

$$= \E\left[ \big(R_t - B_t\big)\, \frac{\partial \pi_t(A_t)/\partial H_t(a)}{\pi_t(A_t)} \right].$$

Step 4: use the softmax derivative. With \(x = A_t\), \(\frac{\partial \pi_t(A_t)/\partial H_t(a)}{\pi_t(A_t)} = \mathbb 1\{a = A_t\} - \pi_t(a)\), so

$$\frac{\partial \E[R_t]}{\partial H_t(a)} = \E\Big[ \big(R_t - B_t\big)\big(\mathbb 1\{a = A_t\} - \pi_t(a)\big) \Big].$$

The quantity inside the expectation is computable from one step of experience. Using it as the update, with \(B_t = \bar R_t\), is exactly the rule above: the expected update is the true gradient.

The derivation needs only that \(B_t\) not depend on the action or reward of step \(t\). \(\bar R_t\), built from earlier rewards, qualifies; a baseline computed from \(R_t\) itself, or one that depends on which arm was chosen, would bias the gradient. Step 2 is the log-derivative trick of Day 4: \(\frac{\partial \pi / \partial H}{\pi} = \frac{\partial \log \pi}{\partial H}\), and the update is \(\alpha\,(R_t - B_t)\, \nabla_H \log \pi_t(A_t)\). That is REINFORCE with a baseline (Days 84–85) for a problem with one state and episodes of length one, and the softmax-over-preferences policy is the same parameterisation that Day 82 uses for discrete actions.

The baseline and its variance reduction

Step 1 shows the baseline doesn't change the expected update. It changes the update's variance, which decides how fast the algorithm learns in practice. Write the update direction as a vector, \(g = (R - b)(e_A - \pi)\), where \(e_A\) is the one-hot vector of the chosen arm. Its mean is the gradient whatever \(b\) is, so its total variance \(\E\|g\|^2 - \|\E g\|^2\) is minimised by minimising \(\E\|g\|^2\):

$$\frac{d}{db}\, \E\big[(R - b)^2\, w_A\big] = -2\,\E\big[(R - b)\, w_A\big] = 0 \quad\Longrightarrow\quad b^* = \frac{\E[R\, w_A]}{\E[w_A]}, \qquad w_A = \|e_A - \pi\|^2 .$$

The variance-optimal baseline is a weighted average of the reward. The plain average reward \(\bar R_t\) is a cheap, close approximation, which is why it is the standard choice; Day 85 makes the same argument for policy gradients in MDPs, where the baseline becomes a learned state-value function.

Intuition · rewards centred on +4

Shift the testbed so that \(q_*(a) \sim \mathcal N(4, 1)\). Without a baseline every reward is positive, so every pull raises the pulled arm's preference: a good arm is distinguished only by being pushed up slightly more. The common offset of 4 dominates the size of each update but carries no information about which arm is better, and early random choices get reinforced simply because they were made. With \(b = \bar R_t\), the update is centred: above-average arms go up, below-average arms go down, and the algorithm becomes essentially invariant to adding a constant to every reward.

The effect of removing the baseline

import numpy as np

def gradient_bandit(alpha, baseline=True, mean=4.0, k=10, steps=1000, runs=2000, seed=0):
    rng = np.random.default_rng(seed)
    q_star = rng.normal(mean, 1.0, (runs, k))            # true values centred on +4, not 0
    best, rows = q_star.argmax(axis=1), np.arange(runs)
    H = np.zeros((runs, k))                               # preferences: uniform policy at start
    r_bar = np.zeros(runs)                                # average of rewards before step t
    optimal = np.zeros(steps)
    for t in range(steps):
        z = np.exp(H - H.max(axis=1, keepdims=True))      # subtract the max: no overflow
        pi = z / z.sum(axis=1, keepdims=True)
        A = (rng.random((runs, 1)) > pi.cumsum(axis=1)).sum(axis=1).clip(max=k - 1)  # A ~ pi
        R = rng.normal(q_star[rows, A], 1.0)
        b = r_bar if baseline else 0.0
        one_hot = np.zeros((runs, k))
        one_hot[rows, A] = 1.0
        H += alpha * (R - b)[:, None] * (one_hot - pi)    # H(a) += alpha (R - b)(1{a=A} - pi(a))
        r_bar += (R - r_bar) / (t + 1)
        optimal[t] = (A == best).mean()
    return optimal

What breaks
  • No baseline, or a poor one: high variance and premature convergence, as in the table.
  • A baseline that depends on the current action or reward biases the gradient. State-dependent baselines are safe in MDPs; action-dependent ones need corrections (Day 85).
  • Softmax saturation. With a large α or a long run, π becomes nearly one-hot and the gradient vanishes. That is the right end state in a stationary problem and a trap in a drifting one, because the policy can no longer explore.
  • Overflow. np.exp(H) overflows once preferences reach the hundreds; always subtract the row maximum first.
  • Reward scale. Each update is proportional to \(R_t - \bar R_t\), so multiplying rewards by 100 multiplies the effective step size by 100. Value-based updates such as the sample average are scale-free in this respect; policy gradients are not, which is one reason Module 9 normalises advantages.

DAY 16

Bayesian Bandits & Thompson Sampling

35m video75m practice

Keep a full probability distribution over each arm's value, not just a point estimate. To act, draw one plausible value for every arm from its posterior and pull the arm whose draw is largest. Uncertain arms win some draws and get explored; clearly bad arms almost never do. That is Thompson sampling, the oldest bandit algorithm and often the best.

Beliefs instead of estimates

The methods so far summarise each arm by a number, \(Q_t(a)\), and bolt uncertainty on afterwards: a count, a bonus, a schedule. The Bayesian alternative treats the unknown mean of arm \(a\) as a random variable \(\theta_a\) with a prior distribution, and conditions on the observed rewards to get a posterior \(p(\theta_a \mid \mathcal H_{t-1})\), which encodes the estimate and its uncertainty at once. With independent arms and independent priors, the posteriors stay independent, and each arm's posterior is updated only when that arm is pulled.

Beta–Bernoulli conjugacy

Definition · Bernoulli arms and the Beta distribution

A Bernoulli arm pays \(R \in \{0, 1\}\) with \(\Pr(R = 1) = \theta_a\): a click, a cure, a conversion. The Beta distribution on \([0, 1]\) has density

$$p(\theta) = \frac{\theta^{\alpha - 1} (1 - \theta)^{\beta - 1}}{B(\alpha, \beta)}, \qquad \E[\theta] = \frac{\alpha}{\alpha + \beta}, \qquad \Var[\theta] = \frac{\alpha\beta}{(\alpha+\beta)^2(\alpha + \beta + 1)},$$

where \(B\) is the normalising Beta function. \(\text{Beta}(1, 1)\) is uniform. (The Beta parameters α, β have nothing to do with the step size α; for arm \(a\) we write \(\alpha_a, \beta_a\).)

Derivation · the posterior after s successes and f failures

By Bayes' rule the posterior is proportional to likelihood times prior. The likelihood of a particular sequence with \(s\) ones and \(f\) zeros is \(\theta^s (1 - \theta)^f\), whatever the order, so

$$p(\theta \mid s, f) \;\propto\; \underbrace{\theta^{s}(1 - \theta)^{f}}_{\text{likelihood}} \; \underbrace{\theta^{\alpha - 1}(1 - \theta)^{\beta - 1}}_{\text{prior}} \;=\; \theta^{\alpha + s - 1}(1 - \theta)^{\beta + f - 1},$$

which is the kernel of \(\text{Beta}(\alpha + s, \beta + f)\); the normaliser is forced, since the density must integrate to 1. The posterior is in the same family as the prior, which is what conjugate means, and the update is counting: after reward \(r \in \{0, 1\}\) from arm \(a\),

$$\alpha_a \leftarrow \alpha_a + r, \qquad \beta_a \leftarrow \beta_a + (1 - r).$$

The prior parameters act as pseudo-counts: relative to the uniform prior, \(\text{Beta}(\alpha, \beta)\) behaves as if \(\alpha - 1\) successes and \(\beta - 1\) failures had already been seen. The posterior mean \((\alpha + s)/(\alpha + \beta + s + f)\) approaches the sample mean as data accumulate, and the posterior variance shrinks like \(1/n\), the Bayesian twin of the standard error.

A posterior over each arm

Probability matching

Theorem · Thompson sampling matches probabilities

If at each step the agent draws \(\tilde\theta_a \sim p(\theta_a \mid \mathcal H_{t-1})\) for every arm and plays \(A_t = \argmax_a \tilde\theta_a\), then

$$\Pr\big(A_t = a \mid \mathcal H_{t-1}\big) = \Pr\big(\theta_a = \textstyle\max_b \theta_b \,\big|\, \mathcal H_{t-1}\big).$$
Proof

Given the history, the sampled vector \(\tilde\theta\) has exactly the posterior distribution of the true \(\theta\). So the event “\(\tilde\theta_a\) is the largest” has the same probability as “\(\theta_a\) is the largest”, which is the posterior probability that \(a\) is the optimal arm. (Ties have probability zero under continuous posteriors.) ∎

Exploration is allocated in proportion to the probability that you are wrong about which arm is best. That is the property behind the name probability matching, and behind Thompson's original 1933 proposal for allocating patients between two treatments.

The Thompson sampling algorithm

Algorithm · Thompson sampling, Bernoulli arms
  1. For every arm \(a\): \(\alpha_a \leftarrow 1\), \(\beta_a \leftarrow 1\) (uniform prior).
  2. Loop for \(t = 1, 2, \dots\):
    1. For every arm, sample \(\tilde\theta_a \sim \text{Beta}(\alpha_a, \beta_a)\).
    2. \(A_t \leftarrow \argmax_a \tilde\theta_a\); observe \(R_t \in \{0, 1\}\).
    3. \(\alpha_{A_t} \leftarrow \alpha_{A_t} + R_t\); \(\;\beta_{A_t} \leftarrow \beta_{A_t} + 1 - R_t\).

For the 10-armed testbed the rewards are Gaussian, so the conjugate pair is Gaussian–Gaussian, and you will need it in Project 1.

Derivation · Gaussian rewards with known noise variance

Let rewards be \(\mathcal N(\theta, \sigma^2)\) with σ known, and put a prior \(\theta \sim \mathcal N(\mu_0, \sigma_0^2)\). After \(n\) rewards with sum \(S\), the log posterior is, up to a constant,

$$-\frac{(\theta - \mu_0)^2}{2\sigma_0^2} - \sum_{i=1}^{n} \frac{(r_i - \theta)^2}{2\sigma^2} = -\frac12 \Big(\frac{1}{\sigma_0^2} + \frac{n}{\sigma^2}\Big)\theta^2 + \Big(\frac{\mu_0}{\sigma_0^2} + \frac{S}{\sigma^2}\Big)\theta + \text{const}.$$

A quadratic in θ is a Gaussian log density; matching it with \(-\frac{(\theta - \mu_n)^2}{2\sigma_n^2}\) reads off

$$\frac{1}{\sigma_n^2} = \frac{1}{\sigma_0^2} + \frac{n}{\sigma^2}, \qquad \mu_n = \sigma_n^2 \Big(\frac{\mu_0}{\sigma_0^2} + \frac{S}{\sigma^2}\Big).$$

Precisions add, and the posterior mean is a precision-weighted average of the prior mean and the sample mean. On the testbed the bandits really are drawn from \(\mathcal N(0, 1)\), so \(\mu_0 = 0\), \(\sigma_0 = \sigma = 1\) is the correct prior, and the posterior is \(\mathcal N\big(S/(n+1),\, 1/(n+1)\big)\).

For rewards in \([0, 1]\) that are not binary, Agrawal & Goyal (2012) use a neat trick: on observing \(r\), flip a coin with success probability \(r\) and update the Beta posterior with the coin's outcome. The expected update is unchanged, and the Beta–Bernoulli machinery applies to any bounded reward.

Posterior-sampling intuition

Intuition · one plausible world per step

Each step, Thompson sampling imagines one world consistent with everything it has seen and acts optimally in that world. An arm gets pulled exactly when some plausible world says it is the best. A narrow posterior far below the leader almost never wins a draw; a wide posterior overlapping the leader often does. As data accumulate the posteriors narrow, the overlaps disappear, and exploration fades on its own: no ε, no schedule, no c to tune, only a prior. Because it randomises, it also behaves sensibly when many decisions must be made from the same posterior. A batch of 1,000 choices spreads across the plausible arms instead of piling onto a single one, which is a large part of why Chapelle & Li (2011) recommended it for display advertising.

The two schools ask different questions. A frequentist guarantee says: for every fixed bandit, regret is at most this much. A Bayesian guarantee averages over bandits drawn from the prior, \(\E_{\theta \sim \text{prior}}[\mathcal R_T(\theta)]\), which is literally what the testbed measures, since it draws its 2,000 bandits from \(\mathcal N(0, 1)\). Thompson sampling turns out to be good in both senses: Agrawal & Goyal (2012) and Kaufmann, Korda & Munos (2012) proved frequentist logarithmic regret, the latter with the optimal Lai–Robbins constant for Bernoulli arms.

Thompson sampling is not the Bayes-optimal policy of Day 10, which would plan over how future posteriors evolve. It is myopic in a useful way. The cost of that myopia shows on problems where the most informative action is one known to be suboptimal: an arm that pays nothing but reveals which of the others is best would never be chosen by Thompson sampling, because no plausible world makes it the best arm. Information-directed sampling (Russo & Van Roy) addresses exactly that case.

Comparison against UCB

import numpy as np

def bernoulli_race(T=10_000, runs=200, k=10, seed=0):
    """Cumulative pseudo-regret of Thompson sampling vs UCB1 on Bernoulli arms."""
    rng = np.random.default_rng(seed)
    p = rng.uniform(0.0, 1.0, (runs, k))                  # true success probabilities
    gaps, rows = p.max(axis=1, keepdims=True) - p, np.arange(runs)
    regret = {}
    for name in ["thompson", "ucb1"]:
        S, F = np.zeros((runs, k)), np.zeros((runs, k))   # successes, failures per arm
        total = np.zeros(runs)
        for t in range(T):
            if name == "thompson":
                theta = rng.beta(S + 1, F + 1)            # one draw from each Beta posterior
                A = theta.argmax(axis=1)
            else:
                N = S + F
                mean = S / np.maximum(N, 1)
                U = np.where(N == 0, np.inf, mean + np.sqrt(2 * np.log(t + 1) / np.maximum(N, 1)))
                A = U.argmax(axis=1)
            r = rng.random(runs) < p[rows, A]
            S[rows, A] += r
            F[rows, A] += ~r
            total += gaps[rows, A]
        regret[name] = total.mean()
    return regret

print(bernoulli_race())    # about {'thompson': 46, 'ucb1': 357} on this seed

Ten Bernoulli arms with success probabilities drawn uniformly from [0, 1], 10,000 steps, 200 runs; the race takes a few seconds. Both methods see the same bandits, because p is drawn once.

Thompson sampling's regret is roughly an eighth of UCB1's here. UCB1's Hoeffding bonus is built for the worst case on \([0, 1]\), which is a variance-¼ coin; for arms far from ½ the true variance is much smaller and the bonus is loose. KL-UCB (Garivier & Cappé 2011), which uses a Bernoulli-specific confidence bound, closes most of the gap. On the Gaussian testbed the ordering holds but the margin is smaller: with the correct \(\mathcal N(0, 1)\) prior, Thompson sampling averages about 1.47 reward over the first 1,000 steps against 1.385 for UCB with \(c = 2\) and 1.474 for the tuned \(c = 1\), and its 10,000-step regret is about 110 against about 270 (the Day 10 figure). Chapelle & Li (2011) found the same picture on simulated problems and on real advertising and news-recommendation data: Thompson sampling was competitive with or better than UCB-style methods, and robust to delayed feedback.

What breaks
  • An overconfident or wrong prior. \(\text{Beta}(100, 1)\) on a bad arm takes around a hundred failures to overturn. On the testbed, shrinking the Gaussian prior to \(\sigma_0 = 1/16\) cuts average reward over the first 1,000 steps from about 1.47 to about 1.37, while anything from \(\sigma_0 = 1/2\) to 4 performs almost identically. Err wide.
  • A wrong likelihood. A Gaussian model with σ set too small is overconfident in exactly the same way; Beta–Bernoulli on unbounded rewards is simply invalid.
  • Nonstationarity. Posteriors only narrow, so exploration dies out even when the world keeps changing. Discount the pseudo-counts (\(\alpha_a \leftarrow \gamma\alpha_a + r\), and likewise β) or use a sliding window.
  • Intractable posteriors. With complex models (neural networks, the deep RL setting) there is no exact posterior to sample. Approximations such as ensembles, bootstrapping or Laplace approximations work to the extent that they capture uncertainty; bootstrapped DQN (Day 105) is this idea at scale, and poor approximations under-explore.
  • Run-to-run variance. A randomised policy adds variance between runs. Average over many, as always.

45m video180m practiceProject 1

Contexts and features per round

Definition · contextual bandit

On each round \(t\): the environment reveals a context \(X_t\), drawn i.i.d. from a fixed distribution and unaffected by past actions; the agent chooses \(A_t\); it observes \(R_t\) with \(\E[R_t \mid X_t = x, A_t = a] = \mu(x, a)\). A policy maps the context (and the history) to an arm, and regret is measured against the best context-dependent choice:

$$\mathcal R_T = \E\Big[\sum_{t=1}^{T} \big(\max_a \mu(X_t, a) - \mu(X_t, A_t)\big)\Big].$$

Sutton & Barto call this associative search (§2.9): it is associative, because different situations call for different actions, but each action still affects only its immediate reward. The naive solution, an independent bandit for every distinct context, fails as soon as contexts are continuous or rarely repeat. The agent must generalise across contexts, and that requires a model.

Each round, every arm is described by a feature vector \(\mathbf x_{t,a} \in \R^d\) built from the context and the arm. Two standard designs:

  • Disjoint: user features only, with a separate parameter vector \(\theta_a\) per arm. Arms share nothing; each needs its own data.
  • Shared (or hybrid): joint user × item features with one parameter vector for all arms, possibly plus per-arm terms. A brand-new arm with known features can be scored before it has ever been shown, which is what makes cold start workable.

Ridge regression per arm

Assume the expected reward is linear in the features, \(\E[R_t \mid \mathbf x_{t,a}] = \mathbf x_{t,a}^\top \theta^*_a\). For one arm, with the features it was pulled on stacked as rows of a design matrix \(D\) and the rewards in a vector \(\mathbf r\):

Derivation · the ridge estimate

Minimise \(L(\theta) = \sum_i (r_i - \mathbf x_i^\top \theta)^2 + \lambda \|\theta\|^2\). Setting the gradient to zero,

$$-2 \sum_i \mathbf x_i \big(r_i - \mathbf x_i^\top \theta\big) + 2\lambda\theta = 0 \;\Longrightarrow\; \Big(\lambda I + \sum_i \mathbf x_i \mathbf x_i^\top\Big)\theta = \sum_i r_i \mathbf x_i \;\Longrightarrow\; \hat\theta = A^{-1}\mathbf b,$$

with \(A = \lambda I + D^\top D\) and \(\mathbf b = D^\top \mathbf r\). Both are running sums, so one pull updates them in \(O(d^2)\): \(A \leftarrow A + \mathbf x\mathbf x^\top\), \(\mathbf b \leftarrow \mathbf b + r\mathbf x\). The \(\lambda I\) term makes \(A\) invertible from the first round; Li et al. use \(\lambda = 1\), initialising \(A_a = I_d\).

The confidence ellipsoid, and where the LinUCB bonus comes from

Derivation · a confidence bound for \(\mathbf x^\top\theta^*\)

Step 1: the error of the estimate. Write each reward as \(r_i = \mathbf x_i^\top\theta^* + \eta_i\) with zero-mean noise that is σ-sub-Gaussian (Gaussian with standard deviation σ, or anything with lighter tails). Substituting into \(\hat\theta = A^{-1}\sum_i \mathbf x_i r_i\) and using \(\sum_i \mathbf x_i \mathbf x_i^\top = A - \lambda I\),

$$\hat\theta - \theta^* = A^{-1} \sum_i \mathbf x_i \eta_i \;-\; \lambda A^{-1}\theta^* .$$

Step 2: one query direction, fixed design. Treat the \(\mathbf x_i\) as fixed and take any query \(\mathbf x\). The noise term \(\mathbf x^\top A^{-1}\sum_i \mathbf x_i \eta_i\) is a weighted sum of independent noise with variance \(\sigma^2\, \mathbf x^\top A^{-1} \big(\sum_i \mathbf x_i\mathbf x_i^\top\big) A^{-1}\mathbf x \le \sigma^2\, \mathbf x^\top A^{-1}\mathbf x\), because \(\sum_i \mathbf x_i\mathbf x_i^\top \preceq A\). The bias term satisfies \(\lambda\,|\mathbf x^\top A^{-1}\theta^*| \le \lambda \|\mathbf x\|_{A^{-1}} \|\theta^*\|_{A^{-1}} \le \sqrt\lambda\, \|\mathbf x\|_{A^{-1}}\|\theta^*\|\), by Cauchy–Schwarz and \(A \succeq \lambda I\). Here \(\|\mathbf v\|_M = \sqrt{\mathbf v^\top M \mathbf v}\). Applying the sub-Gaussian tail bound to the noise term, with probability at least \(1 - \delta\),

$$\big|\mathbf x^\top\hat\theta - \mathbf x^\top\theta^*\big| \;\le\; \Big(\sigma\sqrt{2\ln(2/\delta)} + \sqrt\lambda\,\|\theta^*\|\Big)\, \sqrt{\mathbf x^\top A^{-1}\mathbf x}.$$

The width is a constant times \(\|\mathbf x\|_{A^{-1}}\): large in directions of feature space the arm has rarely been pulled in, small where it has plenty of data. With one-hot features this is the familiar \(1/\sqrt{N(a)}\).

Step 3: all directions at once. Bounds of this form for every \(\mathbf x\) amount to saying that \(\theta^*\) lies in the ellipsoid \(C = \{\theta : \|\theta - \hat\theta\|_A \le \beta\}\), centred on \(\hat\theta\) and longest along the directions with least data. Optimism means scoring each arm by the most favourable parameter in \(C\):

$$\max_{\theta \in C} \mathbf x^\top\theta = \mathbf x^\top\hat\theta + \beta \sqrt{\mathbf x^\top A^{-1}\mathbf x},$$

because \(\mathbf x^\top(\theta - \hat\theta) = (A^{-1/2}\mathbf x)^\top \big(A^{1/2}(\theta - \hat\theta)\big) \le \|\mathbf x\|_{A^{-1}}\, \|\theta - \hat\theta\|_A \le \beta\, \|\mathbf x\|_{A^{-1}}\), with equality at \(\theta = \hat\theta + \beta A^{-1}\mathbf x / \|\mathbf x\|_{A^{-1}}\).

Step 4: adaptivity. The agent chooses which features it sees, so the fixed-design argument doesn't strictly apply. Abbasi-Yadkori, Pál & Szepesvári (2011) proved a self-normalised bound that does: if \(\|\mathbf x\| \le L\) and \(\|\theta^*\| \le S\), then with probability \(1 - \delta\), simultaneously for all \(t\), \(\theta^*\) lies in the ellipsoid with radius

$$\beta_t = \sigma\sqrt{2\ln(1/\delta) + d\ln\!\big(1 + tL^2/(\lambda d)\big)} + \sqrt\lambda\, S .$$

The radius grows like \(\sqrt{d \ln t}\): the price of \(d\) dimensions and of choosing your own data. In practice β is replaced by a single tuned constant α.

LinUCB

Algorithm · LinUCB with disjoint linear models (Li et al. 2010)
  1. Input \(\alpha > 0\). For every arm \(a\): \(A_a \leftarrow I_d\), \(\mathbf b_a \leftarrow \mathbf 0_d\).
  2. Loop for \(t = 1, 2, \dots\):
    1. Observe the features \(\mathbf x_{t,a}\) of every available arm.
    2. For every arm: \(\hat\theta_a \leftarrow A_a^{-1}\mathbf b_a\); \(\;p_{t,a} \leftarrow \hat\theta_a^\top \mathbf x_{t,a} + \alpha\sqrt{\mathbf x_{t,a}^\top A_a^{-1}\mathbf x_{t,a}}\).
    3. \(A_t \leftarrow \argmax_a p_{t,a}\) (ties at random); observe \(R_t\).
    4. With \(\mathbf x = \mathbf x_{t,A_t}\): \(A_{A_t} \leftarrow A_{A_t} + \mathbf x\mathbf x^\top\); \(\;\mathbf b_{A_t} \leftarrow \mathbf b_{A_t} + R_t\,\mathbf x\).

Inverting \(A_a\) every round costs \(O(d^3)\). The Sherman–Morrison identity updates the inverse directly in \(O(d^2)\):

$$\big(A + \mathbf x\mathbf x^\top\big)^{-1} = A^{-1} - \frac{A^{-1}\mathbf x\,\mathbf x^\top A^{-1}}{1 + \mathbf x^\top A^{-1}\mathbf x}.$$

Li et al. give \(\alpha = 1 + \sqrt{\ln(2/\delta)/2}\) as a theoretically motivated value; in practice α is tuned, and good values are often well below that. One sanity check connects LinUCB back to Day 14: with \(d = 1\) and \(\mathbf x = 1\) for every arm, \(A_a = 1 + N(a)\), \(\hat\theta_a\) is a slightly shrunk sample mean, and the bonus is \(\alpha/\sqrt{1 + N(a)}\). That is UCB without the \(\ln t\), a reminder that LinUCB's α carries the confidence schedule and has to be chosen.

import numpy as np

class LinUCB:
    """Disjoint LinUCB (Li et al. 2010): one ridge regression per arm."""
    def __init__(self, n_arms, d, alpha=1.0, lam=1.0):
        self.alpha = alpha
        self.A_inv = np.stack([np.eye(d) / lam for _ in range(n_arms)])   # (A_a)^-1
        self.b = np.zeros((n_arms, d))

    def select(self, X):                                  # X[a] = feature vector x_{t,a}
        theta = np.einsum("aij,aj->ai", self.A_inv, self.b)               # ridge estimates
        width = np.sqrt(np.einsum("ai,aij,aj->a", X, self.A_inv, X))      # ||x||_{A^-1}
        return int(np.argmax(np.einsum("ai,ai->a", X, theta) + self.alpha * width))

    def update(self, a, x, r):
        Ax = self.A_inv[a] @ x                            # Sherman-Morrison: O(d^2), no inverse
        self.A_inv[a] -= np.outer(Ax, Ax) / (1.0 + x @ Ax)
        self.b[a] += r * x

rng = np.random.default_rng(0)
n_arms, d, T = 5, 8, 5000
theta_star = rng.normal(0, 1, (n_arms, d)) / np.sqrt(d)   # hidden per-arm weights
agent, regret = LinUCB(n_arms, d, alpha=1.0), 0.0
for t in range(T):
    X = rng.normal(0, 1, (n_arms, d))                     # this round's context, per arm
    means = np.einsum("ai,ai->a", X, theta_star)
    a = agent.select(X)
    agent.update(a, X[a], means[a] + rng.normal(0, 0.5))
    regret += means.max() - means[a]
print(f"cumulative regret after {T} rounds: {regret:.0f}")   # about 63 on this seed

On the same 5,000 rounds, always playing the best single arm would cost about 4,500 in regret: the context-free comparator from Days 10–16 is simply too weak when the best arm changes from round to round. In update, np.outer(Ax, Ax) is \(A^{-1}\mathbf x\mathbf x^\top A^{-1}\) because \(A^{-1}\) is symmetric.

Personalisation and recommendation

The canonical deployment is Li et al.'s (2010) news recommender for the Yahoo! front page. The arms were the articles in the current pool, which changed throughout the day; the context was a handful of user features (from demographics and behaviour, compressed by clustering) together with article features; the reward was a click. They evaluated offline on traffic that had been served uniformly at random, using the replay method: step through the log, and keep only the rounds where the logged article matches the one your policy would have chosen. Because the logging policy was uniform, the kept rounds are an unbiased sample of what your policy would have experienced (Li et al. 2011). LinUCB reported a click lift of about 12.5% over a context-free bandit.

The same structure appears in choosing which notification to send and when, ranking products or content (where the action is a slate, a combinatorial arm), dynamic pricing (arms are prices), mobile-health interventions that adapt to a person's current state, and cold start for new users or items. Three engineering habits carry over to all of them: normalise the features, let arms appear and disappear (a new arm starts at \(A = I\)), and log the probability of every action you took, so that future policies can be evaluated offline with importance weighting (Day 128). A deterministic policy such as LinUCB logs probabilities of 0 and 1, which makes that evaluation impossible for any policy that would have acted differently.

From bandits to full RL

Contexts become states, and actions start to affect which state comes next. Formally, a contextual bandit is an MDP whose transitions ignore the action, \(p(s' \mid s, a) = p(s')\). Conversely, any MDP solved with \(\gamma = 0\) is a contextual bandit as far as the optimal policy is concerned, since only the immediate reward counts. As soon as \(\gamma > 0\) and actions move the state, choosing greedily on immediate reward is wrong: the value of an action is \(q_\pi(s, a) = \E[R_{t+1} + \gamma\, v_\pi(S_{t+1}) \mid S_t = s, A_t = a]\), which is the subject of Module 2 (Days 22–23).

Almost everything from this module carries over. Action-value estimates become \(Q(s, a)\); the incremental update of Day 12 becomes TD learning; ε-greedy remains the default behaviour policy through Module 8; UCB reappears inside tree search (Day 59) and as optimism in MDPs (Day 102); softmax preferences with a baseline become the policy-gradient methods of Module 9; and posterior sampling returns as randomised value functions (Day 105). What is new is that exploration must now reach states, not just try actions, and that rewards arrive late.

What breaks · contextual bandits in the wild
  • A misspecified model. If reward is not linear in the features, the ellipsoid is a confidence set for the wrong model, and LinUCB can be confidently wrong. Richer features, or ensembles of nonlinear models, are the usual fixes.
  • Drift. \(A_a\) only grows, so old behaviour is never forgotten; add discounting or windows, as on Day 12.
  • Delayed and batched feedback hurts the deterministic LinUCB for the reasons of Day 16. Linear Thompson sampling, which samples \(\tilde\theta_a \sim \mathcal N(\hat\theta_a, v^2 A_a^{-1})\), is the randomised alternative (Agrawal & Goyal 2013).
  • Actions that do affect the future. A recommender that maximises clicks per round can learn to show clickbait that erodes long-term engagement. If today's action changes tomorrow's user, the problem is RL, and a bandit is optimising the wrong objective.

import numpy as np

class Agent:
    """Acts on `runs` independent bandits at once; every per-arm array is [runs, k]."""
    def __init__(self, runs, k, rng):
        self.runs, self.k, self.rng, self.rows = runs, k, rng, np.arange(runs)

    def act(self, t):                      # -> int array [runs]
        raise NotImplementedError

    def update(self, A, R):                # A, R: arrays [runs]
        raise NotImplementedError

    def argmax_random(self, X):            # row-wise argmax, ties broken uniformly
        return np.argmax(self.rng.random(X.shape) * (X == X.max(axis=1, keepdims=True)), axis=1)

class GaussianThompson(Agent):
    def __init__(self, runs, k, rng, mu0=0.0, sigma0=1.0, sigma=1.0):
        super().__init__(runs, k, rng)
        self.prec = np.full((runs, k), 1 / sigma0**2)          # posterior precision
        self.num = np.full((runs, k), mu0 / sigma0**2)         # precision x posterior mean
        self.noise_prec = 1 / sigma**2

    def act(self, t):
        theta = self.rng.normal(self.num / self.prec, 1 / np.sqrt(self.prec))
        return self.argmax_random(theta)

    def update(self, A, R):
        self.prec[self.rows, A] += self.noise_prec
        self.num[self.rows, A] += self.noise_prec * R

def run(make_agent, runs=2000, steps=1000, k=10, mean=0.0, seed=0):
    rng = np.random.default_rng(seed)
    q_star = rng.normal(mean, 1.0, (runs, k))        # same seed -> same bandits for every method
    best, rows = q_star.argmax(axis=1), np.arange(runs)
    agent = make_agent(runs, k, rng)
    reward = np.zeros((steps, runs), dtype=np.float32)
    optimal = np.zeros((steps, runs), dtype=bool)
    regret = np.zeros((steps, runs), dtype=np.float32)
    for t in range(steps):
        A = agent.act(t)
        R = rng.normal(q_star[rows, A], 1.0)
        agent.update(A, R)
        reward[t], optimal[t] = R, A == best
        regret[t] = q_star[rows, best] - q_star[rows, A]
    return reward, optimal, regret.cumsum(axis=0)     # keep per-run arrays for bootstrap bands

reward, optimal, regret = run(lambda runs, k, rng: GaussianThompson(runs, k, rng))
