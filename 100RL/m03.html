Dynamic Programming

Module 2 defined what an optimal policy is; this module computes one. Given the model \(p(s', r \mid s, a)\), the Bellman equations turn into update rules, and three algorithms (policy evaluation, policy iteration, value iteration) solve any finite MDP exactly, with convergence proofs that all rest on a single contraction inequality. Module 4 throws the model away and replaces these expected updates with averages of sampled returns, but keeps the evaluate-then-improve structure built here, as does nearly every method after it.

DAY 28

Iterative Policy Evaluation

40m video90m practice

The Bellman expectation equation says that \(v_\pi\) is the one value function a full one-step lookahead leaves unchanged. Iterative policy evaluation turns that fixed-point condition into an assignment, applies it to every state, and repeats until nothing moves.

From an equation to an update rule

Day 23 characterised \(v_\pi\) as the solution of \(|\mathcal S|\) linear equations, one per state:

$$v_\pi(s) = \sum_a \pi(a \mid s) \sum_{s', r} p(s', r \mid s, a)\,\big[r + \gamma\, v_\pi(s')\big].$$

Day 25 solved that system directly, at \(O(|\mathcal S|^3)\) cost. Dynamic programming instead reads the right-hand side as an instruction: take any guess \(v_k\), plug it in on the right, and call the result \(v_{k+1}\).

$$v_{k+1}(s) = \sum_a \pi(a \mid s) \sum_{s', r} p(s', r \mid s, a)\,\big[r + \gamma\, v_k(s')\big] \qquad \text{for all } s \in \mathcal S.$$

In the operator notation of Day 4 this is \(v_{k+1} = T^\pi v_k\) with \(T^\pi v = r^\pi + \gamma P^\pi v\), and \(v_\pi\) is the fixed point: \(T^\pi v_\pi = v_\pi\). Nothing about the update is approximate. It is exact arithmetic on the model; what makes it iterative is only that we start from the wrong vector.

Definition · expected update

An expected update (S&B also say full backup) replaces the value of a state by the model's expectation of the one-step reward plus the discounted value of the successor. It touches every action and every possible successor, weighted by its probability, and therefore needs \(p(s', r \mid s, a)\). A sweep applies the update once to every state. Monte Carlo (Module 4) and TD (Module 5) methods replace the expectation with a single sampled successor; that is the only structural difference.

Synchronous sweeps: two arrays or one

There are two ways to run a sweep, and both converge.

  • Two-array (Jacobi style). Keep the old table frozen and compute every \(v_{k+1}(s)\) from it. This matches the maths exactly, \(v_{k+1} = T^\pi v_k\), the order of states is irrelevant, and the whole sweep is a single matrix–vector product, so it vectorizes and parallelizes trivially. It costs two copies of the table.
  • In-place (Gauss–Seidel style). Overwrite \(V(s)\) as soon as it is computed, so states later in the sweep already see this sweep's new values. A sweep is no longer \(T^\pi\) applied once, but it still converges to \(v_\pi\) (Day 33 proves this for any update order), and it is usually faster because new information travels further within one sweep. The order now matters: sweeping outward from the terminal states can carry value along a whole path in one pass.

Algorithm · Iterative policy evaluation (in-place)
  1. Input the policy \(\pi\) and a threshold \(\theta > 0\). Initialise \(V(s)\) arbitrarily for non-terminal \(s\) (zeros are fine) and set \(V(\text{terminal}) = 0\).
  2. Repeat:
    1. \(\Delta \leftarrow 0\)
    2. For each non-terminal \(s\):
      1. \(v \leftarrow V(s)\)
      2. \(V(s) \leftarrow \sum_a \pi(a \mid s) \sum_{s', r} p(s', r \mid s, a)\,[r + \gamma V(s')]\)
      3. \(\Delta \leftarrow \max(\Delta, |v - V(s)|)\)
    until \(\Delta < \theta\).
  3. Return \(V \approx v_\pi\). (for the two-array version, read \(V(s')\) from a copy taken at the start of the sweep)

The stopping criterion and what it guarantees

The loop stops when the largest change in a sweep, \(\Delta = \max_s |v_{k+1}(s) - v_k(s)|\), drops below \(\theta\). A small change is not the same thing as a small error, and the gap between them depends on \(\gamma\).

Derivation · error at the stopping point (two-array, γ < 1) $$\begin{aligned} \|v_{k+1} - v_\pi\|_\infty &= \|T^\pi v_k - T^\pi v_\pi\|_\infty \le \gamma\, \|v_k - v_\pi\|_\infty \\ &\le \gamma\,\big(\|v_k - v_{k+1}\|_\infty + \|v_{k+1} - v_\pi\|_\infty\big), \end{aligned}$$

using the contraction lemma of Day 4 and then the triangle inequality. Collect the \(\|v_{k+1} - v_\pi\|_\infty\) terms:

$$\|v_{k+1} - v_\pi\|_\infty \le \frac{\gamma}{1 - \gamma}\, \|v_{k+1} - v_k\|_\infty < \frac{\gamma\,\theta}{1 - \gamma}.$$

At \(\gamma = 0.9\) the true error can be nine times \(\theta\); at \(\gamma = 0.99\), ninety-nine times. If you need accuracy \(\varepsilon\), set \(\theta = \varepsilon(1 - \gamma)/\gamma\). Day 32 turns this into a full set of error bounds.

Why the iteration converges to vπ

For \(\gamma < 1\), the same contraction inequality applied \(k\) times gives \(\|v_k - v_\pi\|_\infty \le \gamma^k \|v_0 - v_\pi\|_\infty\). The error shrinks geometrically from any starting table, and reducing it by a factor \(\varepsilon\) takes about \(\log(1/\varepsilon) / \log(1/\gamma) \approx \log(1/\varepsilon)/(1 - \gamma)\) sweeps. That is the \(1/(1-\gamma)\) "effective horizon" of Day 19 reappearing as a computational cost.

For \(\gamma = 1\), as in the gridworld below, \(T^\pi\) is not a contraction, and convergence needs something else: that \(\pi\) reaches a terminal state with probability 1 from every state. Then the block \(Q\) of \(P^\pi\) restricted to non-terminal states is substochastic with \(\rho(Q) < 1\) (Day 6's absorbing chains), the error evolves as \(v_k - v_\pi = Q^k (v_0 - v_\pi)\), and \(Q^k \to 0\). S&B state the condition as "either \(\gamma < 1\) or eventual termination is guaranteed from all states under \(\pi\)".

Intuition · what the intermediate tables mean

Start from \(v_0 = 0\) and unroll the two-array update: \(v_k = \sum_{t=0}^{k-1} (\gamma P^\pi)^t r^\pi\). So \(v_k(s)\) is exactly the expected return over the first \(k\) steps from \(s\). Sweep 1 has seen one reward, sweep 10 has seen ten. The iteration is not a blind numerical trick; each sweep extends the horizon by one step, and discounting (or termination) makes the far tail negligible.

Full gridworld walkthrough

Sutton & Barto's Example 4.1: a 4 × 4 grid whose top-left and bottom-right corners are terminal (one terminal state drawn twice). The four actions move one cell deterministically, and a move off the grid leaves the agent in place. Every transition earns \(-1\), \(\gamma = 1\), and the policy is equiprobable random. Under these choices \(-v_\pi(s)\) is the expected number of steps a random walk from \(s\) takes to hit a corner.

import numpy as np

N, GAMMA = 4, 1.0
TERMINAL = {0, N * N - 1}
MOVES = [(-1, 0), (0, 1), (1, 0), (0, -1)]          # up, right, down, left

def step(s, a):
    """Deterministic gridworld of S&B Example 4.1: reward -1 per move, walls bounce back."""
    r, c = divmod(s, N)
    r2, c2 = r + MOVES[a][0], c + MOVES[a][1]
    if not (0 <= r2 < N and 0 <= c2 < N):
        r2, c2 = r, c
    return r2 * N + c2, -1.0

def evaluate(pi, theta=1e-4, in_place=False, show=()):
    """pi[s, a] = probability of action a in state s. Returns v_pi and the sweep count."""
    V = np.zeros(N * N)
    for k in range(1, 100_000):
        old = V.copy()
        src = V if in_place else old                  # in-place reads this sweep's new values
        for s in range(N * N):
            if s in TERMINAL:
                continue                              # terminal value stays 0
            V[s] = sum(pi[s, a] * (r + GAMMA * src[s2])
                       for a in range(4) for s2, r in [step(s, a)])
        if k in show:
            print(f"sweep {k}\n{V.reshape(N, N).round(2)}")
        if np.abs(V - old).max() < theta:
            return V, k

random_pi = np.full((N * N, 4), 0.25)
V, k = evaluate(random_pi, show=(1, 2, 3, 10))
print(f"two-array: {k} sweeps\n{V.reshape(N, N).round(1)}")
print("in-place :", evaluate(random_pi, in_place=True)[1], "sweeps")

In sweep 2 the cell next to the top-left corner averages four branches: going left reaches the terminal (\(-1 + 0\)), and the other three pay \(-1\) and land on a cell worth \(-1\), so \((-1 - 2 - 2 - 2)/4 = -1.75\). What breaks
  • Improper policies with γ = 1. Evaluate "always move left" on this grid and the cells in the left column bump into the wall forever. Their value is \(-\infty\), every sweep subtracts another 1, and \(\Delta = 1\) never drops below \(\theta\). Policy iteration can produce such a policy mid-run if ties are broken badly (Day 29). Use \(\gamma < 1\), or cap the sweep count and check.
  • Updating terminal states. If the terminal state is backed up like any other (say through a self-loop with reward), its value drifts away from 0 and drags every neighbour with it. Skip terminal states, or mask their successor values to zero.
  • Stopping early at large γ. \(\Delta < \theta\) only bounds the error by \(\gamma\theta/(1-\gamma)\). At \(\gamma = 0.999\) a "converged" table can be off by a thousand times \(\theta\).
  • Not matching published numbers. Two-array and in-place runs pass through different intermediate tables. If your sweep-2 table differs from S&B's, check which variant you wrote before hunting for a bug.

DAY 29

Policy Improvement

40m video75m practice

Knowing \(v_\pi\) tells you how to beat \(\pi\): in every state, look one step ahead and take the action with the largest \(q_\pi\). The policy improvement theorem guarantees the new policy is at least as good everywhere, and strictly better somewhere unless \(\pi\) was already optimal.

Acting greedily with respect to vπ

The action value of taking \(a\) once in \(s\) and following \(\pi\) afterwards is

$$q_\pi(s, a) = \E\big[R_{t+1} + \gamma\, v_\pi(S_{t+1}) \mid S_t = s, A_t = a\big] = \sum_{s', r} p(s', r \mid s, a)\,\big[r + \gamma\, v_\pi(s')\big].$$

If \(q_\pi(s, a) > v_\pi(s)\), then deviating to \(a\) for one step and reverting to \(\pi\) beats following \(\pi\) throughout. The greedy policy makes that deviation in every state at once:

$$\pi'(s) = \argmax_a q_\pi(s, a) = \argmax_a \sum_{s', r} p(s', r \mid s, a)\,\big[r + \gamma\, v_\pi(s')\big].$$

It is not obvious that this is safe. The one-step comparison assumes \(\pi\) is followed afterwards, but \(\pi'\) changes what happens afterwards too: every later step is also a deviation. The theorem below says the deviations compound in your favour.

The policy improvement theorem

Theorem · Policy improvement

Let \(\pi\) and \(\pi'\) be deterministic policies with \(q_\pi(s, \pi'(s)) \ge v_\pi(s)\) for every state \(s\). Then \(v_{\pi'}(s) \ge v_\pi(s)\) for every \(s\). Moreover, if the hypothesis holds strictly at some state, the conclusion holds strictly at that state.

Proof · unrolling (S&B §4.2)

Apply the hypothesis at \(S_t\), then again at \(S_{t+1}\), and so on:

$$\begin{aligned} v_\pi(s) &\le q_\pi(s, \pi'(s)) = \E\big[R_{t+1} + \gamma v_\pi(S_{t+1}) \mid S_t = s, A_t = \pi'(s)\big] \\ &= \E_{\pi'}\big[R_{t+1} + \gamma v_\pi(S_{t+1}) \mid S_t = s\big] \\ &\le \E_{\pi'}\big[R_{t+1} + \gamma q_\pi(S_{t+1}, \pi'(S_{t+1})) \mid S_t = s\big] \\ &= \E_{\pi'}\big[R_{t+1} + \gamma R_{t+2} + \gamma^2 v_\pi(S_{t+2}) \mid S_t = s\big] \\ &\le \cdots \le \E_{\pi'}\big[R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots \mid S_t = s\big] = v_{\pi'}(s). \end{aligned}$$

The second line holds because \(\pi'\) picks \(A_t = \pi'(s)\) anyway. The fourth expands \(q_\pi\) and folds the inner expectation into the outer one with the tower rule (Day 3). The limit needs \(\gamma^k\, \E_{\pi'}[v_\pi(S_{t+k})] \to 0\), true for \(\gamma < 1\) with bounded values, and for \(\gamma = 1\) when the policies terminate with probability 1.

Proof · operator form, with the strict part

\(T^{\pi'}\) is monotone: if \(u \ge w\) componentwise then \(T^{\pi'}u - T^{\pi'}w = \gamma P^{\pi'}(u - w) \ge 0\), because \(P^{\pi'}\) has non-negative entries. The hypothesis says exactly \(T^{\pi'} v_\pi \ge v_\pi\), since \((T^{\pi'} v_\pi)(s) = q_\pi(s, \pi'(s))\). Apply \(T^{\pi'}\) to both sides again and again:

$$v_\pi \le T^{\pi'} v_\pi \le (T^{\pi'})^2 v_\pi \le \cdots \longrightarrow v_{\pi'},$$

where the limit is Day 28's convergence of policy evaluation from any start. For the strict part: \(v_{\pi'} = T^{\pi'} v_{\pi'} \ge T^{\pi'} v_\pi\) by monotonicity, and \((T^{\pi'} v_\pi)(s) = q_\pi(s, \pi'(s)) > v_\pi(s)\) at the state where the hypothesis is strict.

Strict improvement unless already optimal

The greedy policy always satisfies the hypothesis: \(q_\pi(s, \pi'(s)) = \max_a q_\pi(s, a) \ge q_\pi(s, \pi(s)) = v_\pi(s)\). So greedy improvement never makes things worse. When does it fail to make things better? Suppose \(v_{\pi'} = v_\pi\). Then for every \(s\),

$$v_\pi(s) = v_{\pi'}(s) = (T^{\pi'} v_{\pi'})(s) = (T^{\pi'} v_\pi)(s) = \max_a \sum_{s', r} p(s', r \mid s, a)\,\big[r + \gamma\, v_\pi(s')\big],$$

which is the Bellman optimality equation of Day 24. Its solution is unique (Day 32 proves it), so \(v_\pi = v_*\) and both \(\pi\) and \(\pi'\) are optimal. Read the contrapositive: if \(\pi\) is not optimal, the greedy policy is strictly better in at least one state. Day 30 turns this into a termination proof for policy iteration.

Handling ties

Ties are common: symmetric gridworlds, the Gambler's Problem (Day 31), any state where two moves reach equally good cells. They raise three separate issues.

  • For improvement, ties don't matter. The theorem needs only \(\ge\), so any tie-breaking rule gives a policy at least as good.
  • For termination, they matter a lot. Policy iteration stops when the policy stops changing. If two actions are exactly tied and the argmax returns one or the other depending on the order of a floating-point sum, the policy flips between equally good versions forever and the loop never ends. S&B's Exercise 4.4 points out that the book's own pseudocode has this bug. The fix: keep the current action whenever it is among the maximisers, or test convergence on values rather than actions.
  • Floating-point "ties". Two mathematically equal action values can differ by \(10^{-16}\). Compare with a tolerance, as in Q >= Q.max() - 1e-9.

Improvement for stochastic policies

Nothing in the operator proof used determinism. For stochastic \(\pi'\), replace \(q_\pi(s, \pi'(s))\) by \(\sum_a \pi'(a \mid s)\, q_\pi(s, a)\), which is still \((T^{\pi'} v_\pi)(s)\), and the proof goes through word for word:

Theorem · stochastic version

If \(\sum_a \pi'(a \mid s)\, q_\pi(s, a) \ge v_\pi(s)\) for all \(s\), then \(v_{\pi'} \ge v_\pi\), strictly wherever the hypothesis is strict.

Two consequences. First, any distribution supported on the set of maximising actions is a greedy policy; splitting probability evenly among ties, as in the figure below, is as good as picking one. Second, the theorem does not require greediness. Any \(\pi'\) whose one-step average beats \(v_\pi\) improves on \(\pi\). Day 38 uses exactly this to show that \(\varepsilon\)-greedy improvement works within the class of \(\varepsilon\)-soft policies, and conservative policy updates such as TRPO and PPO (Days 90–91) are small, safe steps in the same direction.

Visualizing an improved policy

# continues from the Day 28 snippet (N, TERMINAL, GAMMA, step, evaluate)
def q_from_v(V):
    Q = np.zeros((N * N, 4))
    for s in range(N * N):
        if s in TERMINAL:
            continue
        for a in range(4):
            s2, r = step(s, a)
            Q[s, a] = r + GAMMA * V[s2]
    return Q

def greedy(Q, tol=1e-9):
    """Spread probability evenly over every action within tol of the best."""
    best = Q >= Q.max(axis=1, keepdims=True) - tol
    return best / best.sum(axis=1, keepdims=True)

V0, _ = evaluate(np.full((N * N, 4), 0.25))         # v of the random policy
pi1 = greedy(q_from_v(V0))
V1, _ = evaluate(pi1)
print(V1.reshape(N, N))                              # already v*: minus the distance to a corner
print("improved everywhere:", np.all(V1 >= V0 - 1e-9))

ARROWS = "↑→↓←"
for r in range(N):
    print(" ".join("·" if r * N + c in TERMINAL else
                   "".join(ARROWS[a] for a in range(4) if pi1[r * N + c, a] > 0).ljust(2)
                   for c in range(N)))

What breaks
  • Greedy with respect to the wrong values. The theorem needs the exact \(v_\pi\). Greedy with respect to a noisy or half-converged estimate can be worse than \(\pi\). Day 32 bounds the damage by \(2\gamma\varepsilon/(1-\gamma)\), which is large when \(\gamma\) is near 1.
  • Oscillating ties. An argmax with no tolerance and no "keep the old action" rule turns exact ties into an endless loop in policy iteration.
  • You need the model to improve from v. Computing \(q_\pi\) from \(v_\pi\) uses \(p(s', r \mid s, a)\). Without a model, \(v\) alone cannot tell you which action is best. That is why Monte Carlo control estimates \(q\) directly (Day 36).

DAY 30

Policy Iteration

40m video105m practice

Evaluate, improve, repeat. Each round produces a strictly better policy until no better one exists, and because a finite MDP has finitely many deterministic policies, the loop must stop at an optimal one, in practice after a handful of rounds.

Alternating evaluation and improvement

Days 28 and 29 gave two operations: evaluation turns a policy into its value function, and improvement turns a value function into a better policy. Chain them:

$$\pi_0 \xrightarrow{\;E\;} v_{\pi_0} \xrightarrow{\;I\;} \pi_1 \xrightarrow{\;E\;} v_{\pi_1} \xrightarrow{\;I\;} \pi_2 \xrightarrow{\;E\;} \cdots \xrightarrow{\;I\;} \pi_* \xrightarrow{\;E\;} v_*.$$

This is Howard's (1960) policy iteration. Each improvement step is a best response to the current policy's long-run consequences, computed in every state at once, so the policy can change globally in one step rather than one state at a time.

The full algorithm

Algorithm · Policy iteration (with a terminating tie rule)
  1. Initialise \(\pi(s) \in \mathcal A(s)\) and \(V(s)\) arbitrarily for every \(s\); \(V(\text{terminal}) = 0\).
  2. Evaluate. Repeat sweeps of \(V(s) \leftarrow \sum_{s', r} p(s', r \mid s, \pi(s))\,[r + \gamma V(s')]\) until \(\Delta < \theta\). (start from the previous \(V\), not from zero)
  3. Improve. \(\text{stable} \leftarrow \text{true}\). For each \(s\):
    1. \(q(a) \leftarrow \sum_{s', r} p(s', r \mid s, a)\,[r + \gamma V(s')]\) for every \(a\)
    2. if \(q(\pi(s)) < \max_a q(a) - \text{tol}\): set \(\pi(s) \leftarrow \argmax_a q(a)\) and \(\text{stable} \leftarrow \text{false}\) (otherwise keep the current action, even if tied)
  4. If stable, return \(V \approx v_*\) and \(\pi \approx \pi_*\); otherwise go to step 2.

Warm-starting evaluation from the previous \(V\) matters. Consecutive policies are similar, so their values are too, and later evaluations need far fewer sweeps. On Jack's Car Rental below the five evaluations take 126, 91, 80, 45 and 14 sweeps.

Finite convergence

Theorem · Policy iteration terminates

For a finite MDP with \(\gamma < 1\) and exact evaluation, policy iteration with the keep-the-current-action tie rule stops after at most \(|\mathcal A|^{|\mathcal S|}\) improvement steps, and the policy it returns is optimal.

Proof

Suppose \(\pi_{k+1} \ne \pi_k\). The tie rule only changes an action when the new one is strictly better, so at some state \(s\), \(q_{\pi_k}(s, \pi_{k+1}(s)) > q_{\pi_k}(s, \pi_k(s)) = v_{\pi_k}(s)\), and at every state the hypothesis of the improvement theorem holds. By Day 29, \(v_{\pi_{k+1}} \ge v_{\pi_k}\) everywhere with strict inequality at \(s\). The value vectors therefore strictly increase in the componentwise order, so no policy can ever recur (a recurrence would need equal value vectors). There are \(|\mathcal A|^{|\mathcal S|}\) deterministic policies, so the loop stops. When it stops, \(\pi\) is greedy with respect to its own value function, \(v_\pi = T^* v_\pi\), and by Day 29 that means \(v_\pi = v_*\).

Why it stops after so few iterations

The bound \(|\mathcal A|^{|\mathcal S|}\) is absurdly pessimistic: Jack's Car Rental has \(11^{441}\) deterministic policies and policy iteration visits five of them. Two facts explain the gap.

Derivation · policy iteration is Newton's method

Look for a root of \(F(v) = T^* v - v\). On the region of value space where \(\pi\) is the greedy policy, \(T^* v = r^\pi + \gamma P^\pi v\) is affine, so the Jacobian of \(F\) is \(J = \gamma P^\pi - I\). A Newton step from \(v\) is

$$v_{\text{new}} = v - J^{-1} F(v) = v + (I - \gamma P^\pi)^{-1}\big(r^\pi - (I - \gamma P^\pi)\, v\big) = (I - \gamma P^\pi)^{-1} r^\pi = v_\pi.$$

"Take the greedy policy of \(v\), then solve for its value" is precisely one Newton step on the Bellman optimality equation (Puterman & Brumelle 1979). Newton's method converges quadratically near a root, which is why the last iterations change only a few states and then stop.

Worst-case theory is less rosy but still polynomial for fixed \(\gamma\). Ye (2011) proved that policy iteration is strongly polynomial for a fixed discount factor: the number of iterations is bounded by a polynomial in the numbers of states and actions, times \(1/(1-\gamma)\) and a logarithmic factor. Hansen, Miltersen & Zwick (2013) tightened this to roughly (number of state–action pairs)\(/(1-\gamma)\) times a log factor. Without discounting the picture changes: Fearnley (2010) built total- and average-reward MDPs on which Howard's policy iteration needs exponentially many iterations. Those instances are carefully engineered; on natural problems the count barely grows with size.

Worked example: Jack's Car Rental

Definition · Jack's Car Rental (S&B Example 4.2)
  • States \((n_1, n_2)\) with \(0 \le n_i \le 20\): cars at each of two locations at the end of a day. \(21^2 = 441\) states.
  • Actions \(a \in \{-5, \dots, 5\}\): the net number of cars moved overnight from location 1 to location 2 (negative means 2 to 1), at $2 per car moved. Moving more cars than a location has is not allowed.
  • Dynamics. The next morning location \(i\) has \(m_1 = \min(n_1 - a, 20)\) and \(m_2 = \min(n_2 + a, 20)\) cars. Rental requests are Poisson with means 3 and 4. Each request that finds a car earns $10; the rest are lost. Returns are Poisson with means 3 and 2 and become available the next day. Any car beyond 20 at a location vanishes from the problem.
  • Discount \(\gamma = 0.9\); a time step is one day, and the task is continuing.

The two locations evolve independently once the move is chosen, so the model factorises. Build a \(21 \times 21\) matrix \(P_i[m, m']\) for each location (morning cars to evening cars) and its expected income \(R_i[m]\). Then the expected next value from morning state \((m_1, m_2)\) is \(\big(P_1 V P_2^\top\big)[m_1, m_2]\): two small matrix products instead of a \(441 \times 441\) one.

Why does the optimal policy look like this? Location 2 rents 4 cars a day but gets only 2 back, so it drains; location 1 is roughly balanced at 3 in and 3 out. The policy therefore moves cars from 1 to 2 whenever location 1 has a surplus and location 2 is short, up to the 5-car limit when location 1 is full and location 2 nearly empty. The broad zero band is where an extra car is unlikely to meet a request that would otherwise be turned away, so the $2 move doesn't pay. Moves in the other direction appear only when location 1 is nearly empty and location 2 nearly full, where location 2's surplus would anyway be lost to the 20-car cap. The optimal values run from about 421 with both lots empty to about 637 with both full; simulating the policy from (10, 10) for 4,000 runs gives 574 ± 1, against the DP value 574.9.

import numpy as np
from math import exp, factorial

MAX_CARS, MAX_MOVE, GAMMA = 20, 5, 0.9
n = MAX_CARS + 1
ACTIONS = np.arange(-MAX_MOVE, MAX_MOVE + 1)              # net cars moved overnight, 1 -> 2

def poisson(lam, size=2 * n):
    p = np.array([exp(-lam) * lam ** k / factorial(k) for k in range(size)])
    p[-1] += 1 - p.sum()                                  # lump the tail so rows sum to 1
    return p

def location(lam_req, lam_ret):
    """P[m, m']: m cars in the morning -> m' at night.  R[m]: expected rental income."""
    P, R = np.zeros((n, n)), np.zeros(n)
    for m in range(n):
        for req, pq in enumerate(poisson(lam_req)):
            rented = min(req, m)
            R[m] += pq * 10 * rented
            for ret, pr in enumerate(poisson(lam_ret)):
                P[m, min(m - rented + ret, MAX_CARS)] += pq * pr
    return P, R

P1, R1 = location(3, 3)
P2, R2 = location(4, 2)
s1, s2 = np.meshgrid(np.arange(n), np.arange(n), indexing="ij")
M1 = np.clip(s1[..., None] - ACTIONS, 0, MAX_CARS)        # morning cars after the move
M2 = np.clip(s2[..., None] + ACTIONS, 0, MAX_CARS)
legal = (ACTIONS <= s1[..., None]) & (-ACTIONS <= s2[..., None])

def q_values(V):                                          # Q[s1, s2, action index]
    EV = P1 @ V @ P2.T                                    # EV[m1, m2] = E[V(night) | morning]
    Q = -2 * np.abs(ACTIONS) + R1[M1] + R2[M2] + GAMMA * EV[M1, M2]
    return np.where(legal, Q, -np.inf)

pi, V = np.full((n, n), MAX_MOVE), np.zeros((n, n))       # start: never move a car
for it in range(1, 50):
    while True:                                           # evaluation, warm-started from V
        V_new = np.take_along_axis(q_values(V), pi[..., None], 2)[..., 0]
        converged = np.abs(V_new - V).max() < 1e-4
        V = V_new
        if converged:
            break
    Q = q_values(V)
    keep = np.take_along_axis(Q, pi[..., None], 2)[..., 0] >= Q.max(2) - 1e-9
    new_pi = np.where(keep, pi, Q.argmax(2))              # switch only on strict improvement
    print(f"iteration {it}: {(new_pi != pi).sum()} states changed")
    if (new_pi == pi).all():
        break
    pi = new_pi
print(ACTIONS[pi][::-1])                                  # top row = 20 cars at location 1

Prints 318, 272, 79, 8, 0 states changed and the policy map above. The evaluation loop computes all eleven action values and keeps one, which wastes work but keeps the code short; it still runs in a few seconds.

Computational profile

  • One evaluation sweep costs one backup per state, each a sum over successors: \(O(|\mathcal S|^2)\) for dense dynamics. Exact evaluation by a linear solve costs \(O(|\mathcal S|^3)\) once.
  • One improvement costs \(|\mathcal A|\) backups per state: \(O(|\mathcal S|^2 |\mathcal A|)\).
  • Memory for a dense model is \(|\mathcal S|^2|\mathcal A|\) numbers. Jack's needs \(441 \cdot 441 \cdot 11 \approx 2.1\) million (17 MB), but at \(10^5\) states that becomes \(10^{11}\). Large DP is only feasible with sparse or factored models, like the per-location factorisation here.
  • Jack's in numbers: 5 evaluations totalling 356 sweeps plus 5 improvement passes, about \(356 \cdot 441 + 5 \cdot 441 \cdot 11 \approx 181{,}000\) single-action backups. Day 31 compares this with value iteration.
What breaks
  • Non-termination from ties. Without the keep-the-current-action rule, two equally good actions can trade places forever. Jack's has near-ties along its region boundaries, where moving one more or one fewer car is worth almost the same.
  • Leaking probability. Truncating the Poisson distribution at, say, 11 without putting the tail mass somewhere leaves transition rows summing to less than 1. Every value comes out biased low, and the policy boundaries shift.
  • Getting the story wrong. Returns before rentals, forgetting the 20-car cap, allowing more cars to be moved than are present, or charging for the absolute move twice: each produces a plausible-looking but different policy. If your \(\pi_4\) doesn't match S&B's, check these first.
  • Sloppy evaluation at the final check. Loose evaluation in early iterations is harmless (that is modified policy iteration, Day 31), but if the last evaluation is too coarse relative to the gaps between action values, the "stable" test can pass at a policy that is not quite optimal.

DAY 31

Value Iteration

40m video105m practice

Policy iteration evaluates every policy to convergence before improving it. Value iteration stops evaluating after a single sweep and folds the improvement into the update itself: one max-backup per state per sweep, repeated until the values stop moving.

Collapsing evaluation to a single sweep

In policy iteration, the first few evaluation sweeps usually settle which action is greedy; the remaining sweeps polish values that the next improvement step throws away. Take the idea to its limit: do one sweep of evaluation, improve immediately, and fuse the two steps into a single formula.

$$v_{k+1}(s) = \max_a \sum_{s', r} p(s', r \mid s, a)\,\big[r + \gamma\, v_k(s')\big] \qquad \text{for all } s.$$

This is the Bellman optimality equation (Day 24) turned into an assignment, exactly as Day 28 did with the expectation equation: \(v_{k+1} = T^* v_k\). The policy has disappeared from the iteration; it only reappears at the end, read off greedily from the final values.

Algorithm · Value iteration
  1. Choose \(\theta > 0\). Initialise \(V(s)\) arbitrarily for non-terminal \(s\); \(V(\text{terminal}) = 0\).
  2. Repeat:
    1. \(\Delta \leftarrow 0\)
    2. For each non-terminal \(s\): \(v \leftarrow V(s)\); \(V(s) \leftarrow \max_a \sum_{s', r} p(s', r \mid s, a)\,[r + \gamma V(s')]\); \(\Delta \leftarrow \max(\Delta, |v - V(s)|)\)
    until \(\Delta < \theta\).
  3. Output the deterministic policy \(\pi(s) = \argmax_a \sum_{s', r} p(s', r \mid s, a)\,[r + \gamma V(s')]\).

Relationship to policy iteration

One identity connects the two algorithms. If \(\pi_v\) denotes a greedy policy with respect to \(v\), then by definition of the max

$$T^* v = T^{\pi_v} v.$$

So a value-iteration sweep is "improve (take the greedy policy of \(v_k\)), then run one evaluation sweep of that policy". Policy iteration is "improve, then run evaluation sweeps until convergence". Both alternate the same two steps and differ only in how much evaluation they do in between. Value iteration also has a direct meaning of its own: started from \(v_0 = 0\), \(v_k(s)\) is the best expected return achievable in \(k\) steps from \(s\), so value iteration is Bellman's backward induction for finite-horizon problems, run until the horizon stops mattering.

Modified policy iteration

Algorithm · Modified policy iteration, MPI(m)
  1. Start from any \(v\).
  2. Repeat until \(\|T^* v - v\|_\infty < \theta\):
    1. \(\pi \leftarrow\) greedy with respect to \(v\)
    2. \(v \leftarrow (T^\pi)^m v\) (\(m\) evaluation sweeps of the current policy)

\(m = 1\) is value iteration and \(m = \infty\) is policy iteration (Puterman & Shin 1978). Intermediate \(m\) is usually best, for a reason the profile on Day 30 already showed: an evaluation sweep costs one backup per state, while an improvement sweep costs \(|\mathcal A|\). The Gambler's Problem

Definition · The Gambler's Problem (S&B Example 4.3)
  • A gambler with capital \(s \in \{1, \dots, 99\}\) bets on flips of a biased coin. Heads, with probability \(p_h = 0.4\), wins as many dollars as were staked; tails loses the stake.
  • Actions: stakes \(a \in \{1, \dots, \min(s, 100 - s)\}\). (S&B also allow 0; see the trap box.)
  • The episode ends at \(s = 0\) (ruin) or \(s = 100\) (goal). Reward is +1 on reaching 100 and 0 otherwise, with \(\gamma = 1\).
  • So \(v_*(s)\) is the largest achievable probability of reaching $100 from capital \(s\), and the update is \(v(s) \leftarrow \max_a \big[p_h\, v(s + a) + (1 - p_h)\, v(s - a)\big]\) with \(v(0) = 0\), \(v(100) = 1\).

Why bold play. The coin is unfavourable: every bet loses \(0.2 \times\) stake in expectation. Many small bets let the law of large numbers grind the gambler down; a few large bets minimise the time spent exposed to the house edge. Dubins & Savage (1965) proved that bold play, always staking \(\min(s, 100 - s)\), is optimal for subfair games like this one. At $50 you bet everything and win with probability exactly 0.4; at $75 you bet $25, so \(v_*(75) = 0.4 + 0.6 \cdot v_*(50) = 0.64\); at $25 you bet $25 and need two wins, \(0.4^2 = 0.16\).

Why the plotted policy is spiky. Bold play is not the only optimal policy: 72 of the 99 states have two or more optimal stakes, and the figure shows the smallest. Read its pattern. From 13 to 24 the stake is \(25 - s\): a win lands exactly on 25. From 26 to 37 it is \(s - 25\): a loss lands exactly on 25. The same pattern repeats around 50 and 75, and below 13 the gambler doubles up, \(a = s\). So every smallest optimal stake makes either a win or a loss land exactly on one of the "milestones" 0, 25, 50, 75, 100, from which continuing boldly is optimal. The stake grows linearly with the distance to the milestone it is aiming at, and the slope reverses halfway between milestones (between 12 and 13, 37 and 38, 62 and 63, 87 and 88): those are the triangles. The spikes are the milestones themselves, where the smallest optimal stake is the whole bold bet (25 at $25 and $75, 50 at $50). The ties are exact, not approximate: bold play's value function is self-similar, \(v_*(s) = 0.4\, v_*(2s)\) for \(s \le 50\) and \(v_*(s) = 0.4 + 0.6\, v_*(2s - 100)\) for \(s \ge 50\), and solving its linear system in rational arithmetic confirms all 72 ties exactly.

A favourable coin. At \(p_h = 0.55\) everything flips: the optimal policy bets $1 in every state (timid play), because now each bet has positive expectation and many small bets let the law of large numbers work for you. Value iteration also slows down sharply, needing 2,256 in-place sweeps instead of 22, because optimal episodes are long and value must flow through a long chain of small bets.

import numpy as np

def gamblers_problem(p_heads=0.4, goal=100, theta=1e-12):
    V = np.zeros(goal + 1)
    V[goal] = 1.0                        # the only reward is reaching the goal, so V(s) = P(win)
    sweeps = 0
    while True:
        delta = 0.0
        for s in range(1, goal):
            stakes = np.arange(1, min(s, goal - s) + 1)
            best = np.max(p_heads * V[s + stakes] + (1 - p_heads) * V[s - stakes])
            delta = max(delta, abs(best - V[s]))
            V[s] = best                  # in-place sweep
        sweeps += 1
        if delta < theta:
            break
    policy = np.zeros(goal + 1, dtype=int)
    for s in range(1, goal):
        stakes = np.arange(1, min(s, goal - s) + 1)
        q = p_heads * V[s + stakes] + (1 - p_heads) * V[s - stakes]
        policy[s] = stakes[np.argmax(np.round(q, 9))]     # smallest stake among the maximisers
    return V, policy, sweeps

V, policy, sweeps = gamblers_problem()
print(sweeps, V[[25, 50, 75]])           # 22 sweeps; [0.16 0.4 0.64]
print(policy[1:100])

The rounding before argmax matters. Without it, exactly tied stakes differ in the 16th decimal and the printed policy looks like noise. In one run it bet 35 at $35 and 47 at $53: both optimal, but not the plot anyone expects, and which ties break which way can change between machines.

Iteration counts and wall-clock against policy iteration

Value iteration's sweeps are cheap and numerous; policy iteration's iterations are few and expensive. For a target error \(\varepsilon\), value iteration needs about \(\log(1/\varepsilon)/(1-\gamma)\) sweeps (Day 32 makes this precise) on a continuing task like Jack's, where nothing terminates: 34, 213, 436 and 2,222 sweeps to \(10^{-8}\) for \(\gamma\) = 0.5, 0.9, 0.95 and 0.99. Policy iteration on the same problem needs 3, 5, 5 and 6 improvement steps. In wall-clock terms the comparison depends as much on implementation as on algorithm. Vectorized with NumPy, every row of the MPI table above finishes in tens of milliseconds on a laptop. Written as Python loops over states, policy iteration took about 3 s and value iteration about 8 s. The algorithmic choice matters most when \(\gamma\) is close to 1 or \(|\mathcal A|\) is large; both favour policy iteration or MPI.

What breaks
  • Mistaking Δ < θ for accuracy. The value error at stopping is up to \(\gamma\theta/(1-\gamma)\) (Day 28), and the greedy policy is only guaranteed near-optimal (Day 32). Usually it is exactly optimal much earlier, as the demo shows, but that is not a guarantee.
  • The zero stake. If the Gambler's action set includes 0, then \(q(s, 0) = v(s)\) ties with the optimum at convergence. That is harmless inside the max, but a policy extracted with 0 allowed may "bet nothing" forever, never terminate, and win with probability 0.
  • Floating-point ties. Exactly tied actions produce a noisy policy plot unless you round or use a tolerance before the argmax.
  • γ = 1. \(T^*\) is not a contraction. The Gambler's Problem converges only because every policy that stakes at least $1 ends with probability 1; in an undiscounted task with a cycle of zero-reward states, value iteration can wander without converging.

DAY 32

Why DP Converges

40m video60m practice

Every algorithm in this module repeatedly applies a Bellman operator, and with \(\gamma < 1\) every Bellman operator shrinks distances by a factor \(\gamma\) in the sup norm. The Banach fixed-point theorem turns that one inequality into existence, uniqueness, convergence from any starting point, and explicit bounds on how far you are from the answer.

The Bellman operator as a mapping

Definition · Bellman operators

For a finite MDP, value functions are vectors in \(\R^{|\mathcal S|}\). Define two maps from \(\R^{|\mathcal S|}\) to itself:

$$(T^\pi v)(s) = \sum_a \pi(a \mid s) \sum_{s', r} p(s', r \mid s, a)\,\big[r + \gamma v(s')\big], \qquad (T^* v)(s) = \max_a \sum_{s', r} p(s', r \mid s, a)\,\big[r + \gamma v(s')\big].$$

\(T^\pi = r^\pi + \gamma P^\pi(\cdot)\) is affine. \(T^*\) is a pointwise maximum of affine maps, so it is convex, piecewise affine and nonlinear. Every DP algorithm is a way of finding their fixed points: policy evaluation iterates \(T^\pi\), value iteration iterates \(T^*\), and policy iteration alternates "greedy" with "solve \(v = T^\pi v\)". Two structural properties are used repeatedly:

  • Monotonicity. \(u \le w\) componentwise implies \(T u \le T w\), for \(T = T^\pi\) and \(T = T^*\).
  • Constant shift. \(T(v + c\mathbf 1) = Tv + \gamma c\,\mathbf 1\): raising every value by \(c\) raises every backed-up value by exactly \(\gamma c\).

γ-contraction under the sup norm

Lemma · max is 1-Lipschitz

For any functions \(f, g\) on a finite set, \(\big|\max_a f(a) - \max_a g(a)\big| \le \max_a |f(a) - g(a)|\).

Proof. Let \(a^*\) maximise \(f\). Then \(\max f - \max g \le f(a^*) - g(a^*) \le \max_a |f(a) - g(a)|\). Swap the roles of \(f\) and \(g\) for the other direction.

Theorem · contraction

For \(0 \le \gamma < 1\) and all \(u, w \in \R^{|\mathcal S|}\): \(\|T^* u - T^* w\|_\infty \le \gamma \|u - w\|_\infty\) and \(\|T^\pi u - T^\pi w\|_\infty \le \gamma \|u - w\|_\infty\).

Proof

Write \(q_u(s, a) = \sum_{s', r} p(s', r \mid s, a)\,[r + \gamma u(s')]\). For each state \(s\), using the lemma and then the fact that \(p(\cdot \mid s, a)\) is a probability distribution,

$$\begin{aligned} \big|(T^* u)(s) - (T^* w)(s)\big| &= \big|\max_a q_u(s, a) - \max_a q_w(s, a)\big| \le \max_a \big|q_u(s, a) - q_w(s, a)\big| \\ &= \gamma \max_a \Big|\sum_{s'} p(s' \mid s, a)\,\big(u(s') - w(s')\big)\Big| \le \gamma \max_a \sum_{s'} p(s' \mid s, a)\, \|u - w\|_\infty = \gamma\, \|u - w\|_\infty. \end{aligned}$$

Take the max over \(s\). The rewards cancel in the second line, so the contraction factor has nothing to do with \(r\). For \(T^\pi\) the argument is the same with an average over actions instead of a max (it is Day 4's lemma).

The norm matters. A stochastic matrix need not shrink Euclidean length: with \(P = \begin{pmatrix}1 & 0\\ 1 & 0\end{pmatrix}\) and \(v = (1, 0)\), \(\|Pv\|_2 = \sqrt 2 > \|v\|_2\), so \(T^\pi\) is not a contraction in \(L_2\) once \(\gamma > 1/\sqrt 2\). Function approximation fits values in a weighted \(L_2\) norm, and Day 69's divergence examples live in exactly this gap.

The Banach fixed-point theorem

Theorem · Banach fixed point

Let \((X, d)\) be a complete metric space and \(T: X \to X\) satisfy \(d(Tx, Ty) \le \gamma\, d(x, y)\) with \(\gamma < 1\). Then \(T\) has exactly one fixed point \(x^*\), and for every starting point \(x_0\) the iterates \(x_{k+1} = T x_k\) converge to it with \(d(x_k, x^*) \le \gamma^k d(x_0, x^*)\).

Proof

Cauchy. By induction \(d(x_{j+1}, x_j) \le \gamma^j d(x_1, x_0)\). For \(m > k\), the triangle inequality and a geometric series give

$$d(x_m, x_k) \le \sum_{j=k}^{m-1} \gamma^j\, d(x_1, x_0) \le \frac{\gamma^k}{1 - \gamma}\, d(x_1, x_0) \xrightarrow[k \to \infty]{} 0.$$

Existence. The space is complete, so the Cauchy sequence converges to some \(x^*\). \(T\) is Lipschitz, hence continuous, so \(x^* = \lim x_{k+1} = \lim T x_k = T x^*\).

Uniqueness. If \(Tx = x\) and \(Ty = y\) then \(d(x, y) = d(Tx, Ty) \le \gamma\, d(x, y)\), which forces \(d(x, y) = 0\).

Rate. \(d(x_k, x^*) = d(T x_{k-1}, T x^*) \le \gamma\, d(x_{k-1}, x^*) \le \cdots \le \gamma^k d(x_0, x^*)\).

\((\R^{|\mathcal S|}, \|\cdot\|_\infty)\) is complete (every finite-dimensional normed space is), so the theorem applies to \(T^\pi\) and \(T^*\) at once. That single application proves Day 28 (policy evaluation converges to the unique \(v_\pi\) from any start) and the convergence of value iteration (Day 31).

Uniqueness of v*, and why the fixed point is optimal

Banach says \(v = T^* v\) has exactly one solution \(\bar v\). That is not yet the statement we want, which is that \(\bar v\) equals \(v_* = \max_\pi v_\pi\) and that some policy achieves it.

Proof

No policy beats \(\bar v\). For any stationary policy \(\pi\), \(T^\pi \bar v \le T^* \bar v = \bar v\), since an average over actions is at most their max. Applying the monotone \(T^\pi\) repeatedly gives \((T^\pi)^k \bar v \le \bar v\) for all \(k\), and the left side converges to \(v_\pi\). So \(v_\pi \le \bar v\).

Some policy attains it. Let \(\bar\pi\) be greedy with respect to \(\bar v\). Then \(T^{\bar\pi} \bar v = T^* \bar v = \bar v\), so \(\bar v\) is a fixed point of \(T^{\bar\pi}\), whose only fixed point is \(v_{\bar\pi}\). Hence \(\bar v = v_{\bar\pi}\).

Together: \(\bar v = \max_\pi v_\pi = v_*\), attained by a deterministic stationary policy. This is the rigorous version of Day 25's proof sketch. A standard extension of the same argument shows that history-dependent policies can't do better either (Puterman 1994, Ch. 6).

Error bounds

Theorem · value-iteration error bounds

Let \(v_k = (T^*)^k v_0\) and \(\gamma < 1\). Then

$$\text{(a)}\;\; \|v_k - v_*\|_\infty \le \gamma^k \|v_0 - v_*\|_\infty, \qquad \text{(b)}\;\; \|v_k - v_*\|_\infty \le \frac{\gamma^k}{1 - \gamma}\, \|v_1 - v_0\|_\infty, \qquad \text{(c)}\;\; \|v_k - v_*\|_\infty \le \frac{\gamma}{1 - \gamma}\, \|v_k - v_{k-1}\|_\infty.$$
Derivation

(a) is the Banach rate. For (b), bound the unknown starting error by something computable: \(\|v_0 - v_*\| \le \|v_0 - v_1\| + \|v_1 - v_*\| \le \|v_1 - v_0\| + \gamma \|v_0 - v_*\|\), so \(\|v_0 - v_*\| \le \|v_1 - v_0\|/(1 - \gamma)\); substitute into (a). (c) is the same argument started at \(v_{k-1}\) instead of \(v_0\): it is Day 28's stopping-rule bound, now for \(T^*\).

You will often see the bound quoted as

$$\|v_k - v_*\|_\infty \le \frac{\gamma^k}{1 - \gamma}\, \|v_0 - v_*\|_\infty .$$

It is true, since it is weaker than (a) (\(1/(1-\gamma) \ge 1\)), and the \(1/(1-\gamma)\) factor is exactly the price of replacing the unknown starting error with something you can compute. Either use the first change, as in (b), or start from \(v_0 = 0\) with rewards bounded by \(R_{\max}\): then \(\|v_0 - v_*\|_\infty = \|v_*\|_\infty \le R_{\max}/(1-\gamma)\) and \(\|v_k - v_*\|_\infty \le \gamma^k R_{\max}/(1 - \gamma)\). Solving for \(k\) gives the cost of accuracy:

$$k \ge \frac{\log\big(R_{\max} / (\varepsilon (1 - \gamma))\big)}{\log(1/\gamma)} \quad\Longrightarrow\quad \|v_k - v_*\|_\infty \le \varepsilon.$$

Policy loss bounds from value error

We act with the greedy policy of an approximate value function, so the question that matters is how much return an error in \(v\) costs.

Theorem · greedy policy loss (Singh & Yee 1994; Williams & Baird 1993)

If \(\|v - v_*\|_\infty \le \varepsilon\) and \(\pi\) is greedy with respect to \(v\), then \(\|v_\pi - v_*\|_\infty \le \dfrac{2\gamma\varepsilon}{1 - \gamma}\).

Proof

Greediness means \(T^\pi v = T^* v\). Insert \(\pm T^* v\):

$$v_* - v_\pi = T^* v_* - T^\pi v_\pi = \big(T^* v_* - T^* v\big) + \big(T^\pi v - T^\pi v_\pi\big).$$

The first bracket has sup norm at most \(\gamma\varepsilon\) by the contraction. The second is at most \(\gamma\|v - v_\pi\|_\infty \le \gamma\big(\|v - v_*\|_\infty + \|v_* - v_\pi\|_\infty\big) \le \gamma\varepsilon + \gamma\|v_* - v_\pi\|_\infty\). So \(\|v_* - v_\pi\|_\infty \le 2\gamma\varepsilon + \gamma\|v_* - v_\pi\|_\infty\); rearrange.

Combined with bound (c): stopping value iteration at \(\Delta < \theta\) guarantees a greedy policy within \(2\gamma^2\theta/(1-\gamma)^2\) of optimal. The bound is worst-case and can be nearly attained (Williams & Baird construct examples), but on a given finite MDP the greedy policy is usually exactly optimal much sooner, for a simple reason:

Why the policy converges before the values

Let the action gap \(g = \min_s \min_{a \text{ not optimal in } s} \big[v_*(s) - q_*(s, a)\big] > 0\), which is positive in any finite MDP. If \(\|v - v_*\|_\infty \le \varepsilon\), every one-step lookahead value is within \(\gamma\varepsilon\) of \(q_*\). A suboptimal action then scores at most \(v_*(s) - g + \gamma\varepsilon\) and an optimal one at least \(v_*(s) - \gamma\varepsilon\), so once \(2\gamma\varepsilon < g\) the greedy policy is exactly optimal. That is why the demo's arrows freeze around sweep 8 of 23, and why in the snippet below the greedy loss hits zero at sweep 5 while the value error is still about 6.

import numpy as np

rng = np.random.default_rng(0)
S, A, gamma = 50, 4, 0.9

R = rng.normal(size=(S, A))                          # expected reward r(s, a)

What breaks
  • γ = 1. \(T^*\) is then only a non-expansion. Fixed points can fail to exist (values infinite) or fail to be unique (add a constant on a recurrent set of zero-reward states). Undiscounted episodic tasks need the stochastic-shortest-path assumptions: some policy terminates with probability 1, and every policy that doesn't has infinitely negative return (Bertsekas & Tsitsiklis 1996). The gridworld and the Gambler's Problem satisfy them; a gridworld with zero step reward and an unreachable goal does not.
  • Approximate backups. The proof needs the backup to be exact, or at least itself a sup-norm non-expansion. "Averagers" such as state aggregation and nearest-neighbour interpolation keep the guarantee (Gordon 1995); least-squares fitting in general does not, and fitted value iteration can diverge.
  • Treating the bound as a forecast. \(2\gamma\varepsilon/(1-\gamma)\) is 198ε at γ = 0.99, and it describes the worst MDP, not yours. Measure the policy's actual return.

DAY 33

Asynchronous DP & GPI

35m video60m practice

DP does not need orderly sweeps. Back up any state, in any order, and the values still converge as long as no state is starved. That freedom lets you spend computation where it matters, and the evaluate-and-improve loop, run at any granularity you like, is the shape of nearly every algorithm in the rest of the course.

In-place and asynchronous updates

An asynchronous DP method picks one state at a time, by any rule, and applies the backup to that state alone using whatever values are currently stored. In-place sweeps are the special case of a fixed cyclic order. Others: random order, states near recent changes first, only states the agent is currently visiting.

Theorem · asynchronous value iteration (Bertsekas & Tsitsiklis 1989)

For \(\gamma < 1\), asynchronous value iteration converges to \(v_*\) from any starting values provided every state is backed up infinitely often. The same holds for asynchronous policy evaluation and \(v_\pi\).

Proof sketch

Call an interval of updates a round if every state is backed up at least once during it, and let \(e = \|v - v_*\|_\infty\) at the start of the round. Backing up a single state \(s\) gives \(|v(s) - v_*(s)| = |(T^* v)(s) - (T^* v_*)(s)| \le \gamma\|v - v_*\|_\infty\) and leaves every other state untouched. So no update ever raises the maximum error above \(e\), and every state, from the moment it is backed up in the round, has error at most \(\gamma e\) (later updates of other states can't push it back up, because they never raise the maximum). After the round, \(\|v - v_*\|_\infty \le \gamma e\). Infinitely many rounds drive the error to zero.

The theorem licenses three practical tricks: sweep in whatever order propagates information fastest, parallelise updates across workers without synchronising every sweep, and skip states that currently don't matter. On the maze below, in-place sweeps in row-major order (away from the goal) take 80 sweeps; the same sweeps in reverse order take 17.

Prioritized sweeping

Most states have nothing to learn most of the time: their Bellman error \(|(T^* v)(s) - v(s)|\) is zero until a neighbour's value changes. Prioritized sweeping (Moore & Atkeson 1993) keeps a priority queue of states keyed by Bellman error, always backs up the worst one, and after changing \(v(s)\) recomputes the error only of the predecessors of \(s\), the only states whose backups read \(v(s)\).

Algorithm · Prioritized sweeping (planning with a known model)
  1. Build predecessor sets \(\text{pred}(s) = \{\bar s : p(s \mid \bar s, a) > 0 \text{ for some } a\}\).
  2. For every \(s\), push \(s\) with priority \(|(T^* v)(s) - v(s)|\) if it exceeds \(\theta\).
  3. While the queue is non-empty:
    1. Pop the state \(s\) with the largest priority; recompute its error and skip it if it is now below \(\theta\) (stale entry)
    2. \(v(s) \leftarrow (T^* v)(s)\)
    3. For each \(\bar s \in \text{pred}(s)\): \(e \leftarrow |(T^* v)(\bar s) - v(\bar s)|\); if \(e > \theta\), push \(\bar s\) with priority \(e\)
import heapq
import numpy as np

n, gamma, theta = 40, 0.95, 1e-6
rng = np.random.default_rng(1)
wall = rng.random((n, n)) < 0.25
wall[0, 0] = wall[-1, -1] = False
GOAL = (n - 1, n - 1)
cells = [(r, c) for r in range(n) for c in range(n) if not wall[r, c] and (r, c) != GOAL]

def nxt(s, a):                                       # deterministic moves; walls block
    r, c = s[0] + (-1, 0, 1, 0)[a], s[1] + (0, 1, 0, -1)[a]
    return (r, c) if 0 <= r < n and 0 <= c < n and not wall[r, c] else s

def backup(V, s):                                    # +1 for entering the (terminal) goal
    return max(1.0 if nxt(s, a) == GOAL else gamma * V[nxt(s, a)] for a in range(4))

# 1) in-place sweeps in row-major order
V, sweeps = {s: 0.0 for s in cells} | {GOAL: 0.0}, 0
while True:
    delta = 0.0
    for s in cells:
        new = backup(V, s); delta = max(delta, abs(new - V[s])); V[s] = new
    sweeps += 1
    if delta < theta:
        break
print(f"in-place sweeps: {sweeps} sweeps = {sweeps * len(cells)} backups")

# 2) prioritized sweeping: always back up the state with the largest Bellman error
preds = {s: set() for s in cells + [GOAL]}
for s in cells:
    for a in range(4):
        preds[nxt(s, a)].add(s)
W = {s: 0.0 for s in cells} | {GOAL: 0.0}
heap = [(-abs(backup(W, s) - W[s]), s) for s in cells]
heapq.heapify(heap)
updates = 0
while heap:
    _, s = heapq.heappop(heap)
    new = backup(W, s)
    if abs(new - W[s]) < theta:                      # stale entry: already fixed by a later update
        continue
    W[s], updates = new, updates + 1
    for p in preds[s] - {GOAL}:                      # only predecessors can have changed error
        err = abs(backup(W, p) - W[p])
        if err >= theta:
            heapq.heappush(heap, (-err, p))
print(f"prioritized: {updates} backups, max diff vs sweeps "
      f"{max(abs(V[s] - W[s]) for s in cells):.1e}")

On a deterministic problem like this it behaves like Dijkstra's algorithm, fixing each state's value once in order of distance from the goal. Real-time dynamic programming

Sweeps of any kind still touch every state. Real-time DP (Barto, Bradtke & Singh 1995) touches only the states an agent actually visits: run the greedy policy from the start state, and back up each state as you pass through it.

Algorithm · Real-time DP (undiscounted episodic task)
  1. Initialise \(V\) optimistically: \(V(s) \ge v_*(s)\) for all \(s\) (for example \(V = 0\) when every step costs at least 1), and \(V(\text{goal}) = 0\).
  2. For each episode: \(s \leftarrow\) a start state; while \(s\) is not a goal:
    1. \(V(s) \leftarrow \max_a \sum_{s', r} p(s', r \mid s, a)\,[r + V(s')]\) and let \(a\) be a maximising action
    2. sample \(s' \sim p(\cdot \mid s, a)\) from the model (or the real world); \(s \leftarrow s'\)

Its guarantee (S&B §8.7, from Barto et al. 1995): if goal states have value 0, some policy reaches a goal with probability 1 from every start state, every reward from a non-goal state is strictly negative, and all initial values are at least the optimal ones, then RTDP converges with probability 1 to a policy that is optimal on all relevant states, those reachable from a start state under some optimal policy. It may never back up the rest at all. Optimism does the exploring: an overestimated action keeps being tried until its value is pulled down, and a state the optimal policy never visits can keep its silly optimistic value forever without harm. On S&B's racetrack, RTDP reached an optimal policy with roughly half the computation of sweep-based value iteration.

Generalized policy iteration

Strip away the bookkeeping and every algorithm in this module runs two interacting processes. Evaluation makes \(v\) consistent with the current \(\pi\). Improvement makes \(\pi\) greedy with respect to the current \(v\). They compete, since making \(\pi\) greedy invalidates \(v\) and re-evaluating can make \(\pi\) no longer greedy, but they cooperate in the long run: the only point where neither wants to move is \(v = v_*\), \(\pi = \pi_*\), because a policy greedy with respect to its own value function satisfies the Bellman optimality equation. Sutton & Barto call this pattern generalized policy iteration (GPI).

The curse of dimensionality, quantified

DP is efficient as a function of the number of states: a value-iteration sweep costs \(O(|\mathcal S|^2 |\mathcal A|)\) for dense dynamics, or \(O(|\mathcal S||\mathcal A| b)\) with \(b\) successors per state-action pair, and policy iteration needs few iterations. Compared with searching \(|\mathcal A|^{|\mathcal S|}\) policies directly, DP is exponentially faster. The trouble is \(|\mathcal S|\) itself. A state described by \(d\) variables with \(k\) values each has \(k^d\) states, which is what Bellman called the curse of dimensionality.

When DP is actually usable

  • You have the model, or can build it from a specification, as for inventory control, queues, maintenance scheduling and small games.
  • |S| × |A| fits in memory with sparse or factored transitions. S&B note that DP handles problems with millions of states on ordinary hardware; with careful sparse code, a single machine can go further.
  • As ground truth. Even when you plan to use RL, solving a small version exactly tells you what the right answer is. Project 2 builds exactly that toolkit, and Day 41 uses DP on Blackjack to score the Monte Carlo agents.

When the model is unknown, replace expected updates with sampled ones (Modules 4–5). When \(|\mathcal S|\) is too large, approximate \(v\) with a parametric function (Module 7) or plan only from the current state (Module 6's tree search). Both keep GPI's structure.

What breaks
  • Starved states. The asynchronous theorem needs every state backed up infinitely often. A method that never revisits some state leaves its value wrong forever. RTDP gets away with it only because of optimism and the relevant-state argument; drop either and it can lock in a bad route.
  • Pessimistic RTDP. Initialise below \(v_*\) and the greedy agent stops trying the action it underestimated, so the underestimate is never corrected.
  • Stale priorities. Python's heapq has no decrease-key. Push duplicates and, as in the snippet, recheck the error when an entry is popped; otherwise you waste backups or, worse, stop early on an outdated priority.
  • Counting sweeps. Comparing asynchronous methods by "sweeps" is meaningless. Count backups (and priority evaluations).

import numpy as np

def tabular_model(env):
    """Dense arrays from a Gymnasium toy-text env's env.unwrapped.P."""
    S, A = env.observation_space.n, env.action_space.n
    P, R = np.zeros((S, A, S)), np.zeros((S, A))
    terminal = np.zeros(S, dtype=bool)
    for s in range(S):
        for a in range(A):
            for prob, s2, reward, term in env.unwrapped.P[s][a]:   # list of 4-tuples
                P[s, a, s2] += prob
                R[s, a] += prob * reward
                terminal[s2] |= bool(term)          # holes and the goal are absorbing
    return P, R, terminal

def value_iteration(P, R, terminal, gamma, theta=1e-8):
    V, sweeps = np.zeros(len(R)), 0
    while True:
        Q = R + gamma * P @ np.where(terminal, 0.0, V)   # no bootstrap from terminal states
        V_new, sweeps = Q.max(axis=1), sweeps + 1
        if np.abs(V_new - V).max() < theta:
            return V_new, Q.argmax(axis=1), sweeps
        V = V_new

Two things to notice and explain in the write-up. On the continuing task (Jack's), value-iteration sweeps grow like \(1/(1-\gamma)\), exactly as Day 32 predicts. On the episodic lakes they grow much more slowly as \(\gamma \to 1\), because termination, not discounting, does most of the contracting. And \(\gamma\) changes the answer, not just the cost: on the slippery 4 × 4 lake the \(\gamma = 0.9\) policy succeeds 78% of the time without a step limit, against 82% for \(\gamma = 0.99\), because heavier discounting buys speed with risk.

A trap you will hit

Run value iteration on the deterministic lake with \(\gamma = 1\). Every safe cell gets value exactly 1, every non-fatal action ties, and argmax picks action 0 (left) from the start, which bumps into the wall forever: 0% success from an "optimal" value function. Undiscounted values carry no preference for getting there sooner. Either use \(\gamma < 1\) or break ties by a secondary criterion such as expected steps.
