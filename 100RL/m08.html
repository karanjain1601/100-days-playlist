DAY 70

Neural Networks as Value Approximators

40m video90m practice

A deep Q-network is linear function approximation on features the network learns for itself. That buys an expressiveness tile coding never had, and it costs the guarantees of Module 7: the features move every time you update, and so do the targets you are regressing onto.

From hand-built features to learned ones

In Module 7 the approximator was \(\hat q(s, a, \mathbf w) = \mathbf w^\top \mathbf x(s, a)\) with features you designed: tiles, Fourier terms, RBFs. A neural network keeps a linear last layer and learns the features underneath it:

$$\hat q(s, a; \theta) = \mathbf w_a^\top \boldsymbol\phi(s; \vartheta) + b_a, \qquad \theta = (\vartheta, \mathbf w, \mathbf b),$$

where \(\boldsymbol\phi(s; \vartheta)\) is the output of the penultimate layer. The semi-gradient update of Day 62 is unchanged,

$$\theta \leftarrow \theta + \alpha\,\big[Y_t - \hat q(S_t, A_t; \theta)\big]\,\nabla_\theta \hat q(S_t, A_t; \theta),$$

but \(\nabla_\theta \hat q\) is no longer a fixed feature vector: it depends on \(\theta\), so each step changes how every other state is represented. That is the source of the power (an Atari agent discovers “where the ball is” without being told) and of the trouble. The linear TD fixed point of Day 63 has no nonlinear counterpart, and with a nonlinear approximator even on-policy semi-gradient TD can diverge; Tsitsiklis & Van Roy (1997) give an example.

MLPs for state vectors. When the observation is a short vector of physically meaningful numbers, a two-hidden-layer MLP is the default. CleanRL's dqn.py uses 120 and 84 units for CartPole; most libraries use 64 or 256. Width matters less than you might expect, and depth beyond two or three hidden layers rarely helps in value-based RL while making optimization harder. Inputs should be roughly unit scale: if one feature is in metres and another in thousands of rpm, the large one dominates the first layer's pre-activations and the network spends its early training learning to ignore it.

CNNs for pixels. A fully connected first layer on 84 × 84 × 4 = 28,224 inputs would waste parameters and would not transfer what it learns about a sprite at one position to the same sprite elsewhere. Convolutions share weights across positions (translation equivariance), the right prior for objects moving on a screen. The Nature DQN network is still the default Atari torso. It has no pooling layers: pooling throws away the exact position of small objects such as the ball, and the value depends on exactly that. Strides do the downsampling instead.

Derivation · shapes and parameter counts

A convolution with kernel \(k\), stride \(s\) and no padding maps width \(n\) to \(\lfloor (n - k)/s \rfloor + 1\). So \(84 \to \lfloor 76/4 \rfloor + 1 = 20\), then \(20 \to \lfloor 16/2 \rfloor + 1 = 9\), then \(9 \to 7\), and the flattened feature vector has \(7 \cdot 7 \cdot 64 = 3136\) entries. A layer has (kernel area × in-channels + 1) × out-channels parameters: \(8^2 \cdot 4 \cdot 32 + 32 = 8{,}224\); \(4^2 \cdot 32 \cdot 64 + 64 = 32{,}832\); \(3^2 \cdot 64 \cdot 64 + 64 = 36{,}928\); then \(3136 \cdot 512 + 512 = 1{,}606{,}144\) and \(513\,|\mathcal A|\) for the head. The convolutions that “see” are cheap; the fully connected layer that combines what they see is where the memory goes.

import torch
import torch.nn as nn

class MLPQ(nn.Module):
    """State-vector input (CartPole: 4 numbers) -> one Q-value per action."""
    def __init__(self, obs_dim, n_actions, hidden=(120, 84)):
        super().__init__()
        layers, d = [], obs_dim
        for h in hidden:
            layers += [nn.Linear(d, h), nn.ReLU()]
            d = h
        self.body = nn.Sequential(*layers)
        self.head = nn.Linear(d, n_actions)          # linear output: Q is unbounded
        with torch.no_grad():                         # start with small, nearly equal Q-values
            self.head.weight.mul_(0.01)
            self.head.bias.zero_()

    def forward(self, x):
        return self.head(self.body(x))

class NatureCNN(nn.Module):
    """4 stacked 84x84 uint8 frames -> one Q-value per action (Mnih et al. 2015)."""
    def __init__(self, n_actions, in_ch=4):
        super().__init__()
        self.net = nn.Sequential(
            nn.Conv2d(in_ch, 32, 8, stride=4), nn.ReLU(),     # 84 -> 20
            nn.Conv2d(32, 64, 4, stride=2), nn.ReLU(),        # 20 -> 9
            nn.Conv2d(64, 64, 3, stride=1), nn.ReLU(),        #  9 -> 7
            nn.Flatten(),                                     # 7 * 7 * 64 = 3136
            nn.Linear(3136, 512), nn.ReLU(),
            nn.Linear(512, n_actions),
        )

    def forward(self, x):
        return self.net(x.float() / 255.0)                    # store uint8; scale once, here

q = NatureCNN(n_actions=6)
print(q(torch.zeros(2, 4, 84, 84, dtype=torch.uint8)).shape)  # torch.Size([2, 6])
print(sum(p.numel() for p in q.parameters()))                 # 1687206

Weight initialization

For a layer \(y = Wx\) with fan-in \(n\), independent zero-mean weights and inputs, \(\Var[y_j] = n\,\Var[w]\,\E[x^2]\). A ReLU zeroes half of a symmetric pre-activation, halving its second moment, so keeping the activation scale constant through depth needs \(\Var[w] = 2/n\): He (Kaiming) initialization. PyTorch's default for Linear and Conv2d draws from \(U(-1/\sqrt n, 1/\sqrt n)\), a variance of \(1/(3n)\), smaller than He's but perfectly adequate for the three-to-five-layer networks used here. Orthogonal initialization with gain \(\sqrt 2\) is common in policy-gradient code (Day 92); CleanRL's DQN scripts keep the PyTorch defaults.

The RL-specific question is the output layer, because the initial Q-values are the initial bootstrap targets. If \(\hat q(s', \cdot)\) starts as a wide random spread across actions, \(\max_{a'}\) picks the largest piece of noise, and bootstrapping copies that upward bias into every predecessor state (the \(\E[\max] \ge \max \E\) trap of Day 3). Scaling the last layer's weights down, as in MLPQ above, starts all actions near zero and nearly equal, so early targets are close to the immediate rewards.

Activation functions

ReLU is the standard (DQN, Rainbow and their descendants): cheap, non-saturating, and its piecewise-linear features suit regression. tanh is common in small PPO MLPs. Whatever you choose for hidden layers, the Q output must be linear and unbounded. A final ReLU forbids negative values; a final tanh caps \(|\hat q| \le 1\) while discounted returns with \(\gamma = 0.99\) reach about 100. Both bugs train without errors and silently cap what the agent can represent.

Long, non-stationary training also wears ReLU networks down. Units that stop activating for every input receive no gradient and never recover, and networks trained on a long sequence of changing targets gradually lose their ability to fit new ones (Lyle et al. 2022, “Understanding and Preventing Capacity Loss in Reinforcement Learning”; Sokar et al. 2023, “The Dormant Neuron Phenomenon in Deep Reinforcement Learning”). Periodic resets of the last layers and LayerNorm are the usual mitigations; they matter most when you do many updates per environment step (Day 72).

Normalization, and why BatchNorm misbehaves

Inputs. Divide pixels by 255 inside forward, so the buffer can store uint8 (Day 72). For state vectors, either rescale by known bounds or keep a running mean and standard deviation. Remember that updating those statistics changes the function the network computes, which is one more moving target; freeze them early, or let them change slowly.

BatchNorm normalizes each feature by the current minibatch's mean and variance during training, and by running averages in evaluation mode. Each part of that design breaks in value-based RL:

  • Acting and learning use different functions. The agent acts on one state at a time, so it must use evaluation mode (in training mode BatchNorm1d rejects a batch of one, and statistics from one state would be meaningless anyway); it learns in training mode with batch statistics. The Q-function you act with is not the one you are fitting, and forgetting a .eval()/.train() switch is a classic silent bug.
  • Statistics are non-stationary. The state distribution drifts as the policy improves, the running averages lag behind it, and a target network carries frozen statistics from an older distribution.
  • Samples are coupled. In training mode \(\hat q(s, a)\) depends on the other states in the minibatch. The online network normalizes over a batch of \(s\), the target network over a batch of \(s'\), so part of every TD error is an artifact of normalization rather than a disagreement about values.

LayerNorm normalizes each sample over its own features: no batch dependence, the same computation when acting and learning, and it is increasingly used in value networks as a stabilizer. The exception that proves the rule is CrossQ (Bhatt et al. 2024), which makes BatchNorm work in off-policy actor-critic by removing the target network and passing \((s, a)\) and \((s', a')\) through the critic in one joint batch, so both sides share statistics.

The non-stationary target problem, stated clearly

Definition · the deep Q-learning regression

At every step the network takes a gradient step on

$$L(\theta) = \E_{(s, a, r, s') \sim d}\Big[\big(Y(\bar\theta) - \hat q(s, a; \theta)\big)^2\Big], \qquad Y(\bar\theta) = r + \gamma \max_{a'} \hat q(s', a'; \bar\theta),$$

with the gradient taken only through the prediction. In naive deep Q-learning \(\bar\theta = \theta\); DQN uses a lagged copy \(\theta^-\) (Day 73). Compared with supervised regression, three things move: the labels \(Y\) depend on \(\bar\theta\); the data distribution \(d\) depends on the policy derived from \(\theta\); and the features \(\boldsymbol\phi(s; \vartheta)\) change with every step.

The first of these is the most dangerous, and a one-line calculation shows why.

Derivation · when does a TD step make its own error worse?

Take one semi-gradient step on a single transition, \(\Delta\theta = \alpha\,\delta\,\nabla_\theta \hat q(s, a)\), with \(\delta = Y - \hat q(s, a)\) and the target computed with the same parameters. Write \(k(x, x') = \nabla_\theta \hat q(x)^\top \nabla_\theta \hat q(x')\) for the network's tangent kernel between state–action pairs, and \(a^* = \argmax_{a'} \hat q(s', a')\). To first order the prediction rises by \(\alpha\delta\,k\big((s, a), (s, a)\big)\) and the target by \(\gamma\,\alpha\delta\,k\big((s', a^*), (s, a)\big)\), so

$$\delta_{\text{new}} \approx \delta\,\Big(1 - \alpha\big[k\big((s,a),(s,a)\big) - \gamma\,k\big((s',a^*),(s,a)\big)\big]\Big).$$

The error shrinks only if \(k\big((s,a),(s,a)\big) > \gamma\,k\big((s',a^*),(s,a)\big)\) and \(\alpha\) is small. In a table the cross term is zero unless \((s', a^*) = (s, a)\), so this always holds. With a network, consecutive Atari frames are nearly identical, so the cross term is nearly as large as the diagonal one: the margin is roughly \((1 - \gamma)\,k\), about 1% of the step, and anything that tips the balance (a larger gradient at \(s'\), a large step size) makes the update increase the error it was meant to reduce. This is the analysis of Achiam et al. (2019) and the deep-network face of the deadly triad of Day 69.

Everything else in this module manages that inequality: target networks (Day 73) stop the target from moving within an update, replay (Day 72) mixes transitions from many places so no region is hammered repeatedly, and Huber losses and clipping bound the step.

What breaks
  • An activation on the output. ReLU or tanh on the Q-head caps or truncates values. It trains without errors and plateaus.
  • Unscaled pixels. Feeding 0–255 values makes first-layer pre-activations about 255 times too large; early updates are huge and many ReLUs die immediately.
  • BatchNorm in the Q-network, for the three reasons above. Use LayerNorm or nothing.
  • A wide initial Q spread, which the max turns into an optimistic bias that bootstrapping spreads through the state space before any reward has been seen.
  • Pooling layers borrowed from image classifiers, which discard the positions the value depends on.

DAY 71

DQN — The Core Algorithm

45m video105m practice

DQN is Q-learning recast as a sequence of regression problems: a network is regressed onto bootstrapped targets computed by a frozen copy of itself, on minibatches drawn from a memory of past experience. Each ingredient is there because the naive version diverges.

From a Q-table to a Q-network

Tabular Q-learning (Day 45) updates one entry:

$$Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha\big[R_{t+1} + \gamma \max_{a'} Q(S_{t+1}, a') - Q(S_t, A_t)\big].$$

Replace the entry with a network output and the increment with a gradient step, and you have semi-gradient Q-learning:

$$\theta \leftarrow \theta + \alpha\big[R_{t+1} + \gamma \max_{a'} \hat q(S_{t+1}, a'; \theta) - \hat q(S_t, A_t; \theta)\big]\,\nabla_\theta \hat q(S_t, A_t; \theta).$$

The tabular rule is the special case where \(\theta\) is the table and the gradient is a one-hot vector. This update had been known since the early 1990s and had a bad reputation: it diverges on simple counterexamples (Baird 1995, Day 69), and after TD-Gammon most attempts to pair it with neural networks were unreliable. Riedmiller's Neural Fitted Q Iteration (2005) made a network work by going to batch mode: collect a dataset, fit the network to targets computed on the whole dataset, recompute the targets, repeat. DQN is, in effect, an online minibatch version of that idea.

The loss function

Definition · the DQN loss

At update \(i\), with online parameters \(\theta_i\), target-network parameters \(\theta_i^-\) held fixed, and replay memory \(\mathcal D\):

$$L_i(\theta_i) = \E_{(s, a, r, s', \text{term}) \sim U(\mathcal D)}\Big[\big(\underbrace{r + \gamma\,(1 - \text{term}) \max_{a'} \hat q(s', a'; \theta_i^-)}_{y} - \hat q(s, a; \theta_i)\big)^2\Big].$$

Its semi-gradient treats \(y\) as a constant: \(\nabla_{\theta_i} L_i = -2\,\E\big[(y - \hat q(s, a; \theta_i))\,\nabla_{\theta_i} \hat q(s, a; \theta_i)\big]\). In code, \(y\) is computed under torch.no_grad(). Only terminated zeroes the bootstrap; a time-limit truncation does not (Day 8).

Derivation · what minimizing the loss computes

Fix \(\theta^-\). For any function \(Q\), add and subtract \(\E[y \mid s, a]\) inside the square. The cross term vanishes by the tower rule, leaving

$$\E\big[(y - Q(s, a))^2\big] = \underbrace{\E\big[(y - \E[y \mid s, a])^2\big]}_{\text{target noise, independent of } Q} + \E\big[(\E[y \mid s, a] - Q(s, a))^2\big].$$

So the best possible \(Q\) is \(\E[y \mid s, a] = r(s, a) + \gamma \sum_{s'} p(s' \mid s, a) \max_{a'} \hat q(s', a'; \theta^-) = (T \hat q_{\theta^-})(s, a)\), the Bellman optimality backup of the target network. A finite network fitted on the buffer's distribution \(d_{\mathcal D}\) gets the projection \(\argmin_\theta \| T\hat q_{\theta^-} - \hat q_\theta \|^2_{d_{\mathcal D}}\). Each target-network period is one step of approximate value iteration (Day 31), done by SGD.

Two practical consequences follow. The loss has a floor equal to the variance of the target given \((s, a)\), so a non-zero loss does not mean the network is wrong. And the loss at two different times measures two different regression problems (different \(\theta^-\)), so a loss curve is not a progress curve. Day 81 turns this into the first question of the debugging checklist.

One output head per action

There are two ways to parameterize \(\hat q(s, a)\): feed \((s, a)\) in and get a scalar out, or feed \(s\) in and get a vector of \(|\mathcal A|\) values out. DQN uses the second. The target needs \(\max_{a'} \hat q(s', a')\), which then costs one forward pass instead of \(|\mathcal A|\), and the shared torso learns features useful for every action. Each transition trains only the output of the action actually taken (selected with gather); the other outputs get no gradient from it, though they still move through the shared layers. The design needs a small discrete action set. For continuous actions the max is intractable, so Module 9's DDPG and SAC (Day 93, Day 95) take \((s, a)\) as input and train an actor to perform the max.

The training loop

Algorithm · Deep Q-learning with experience replay (Mnih et al. 2015)
  1. Initialize replay memory \(\mathcal D\) with capacity \(N\), online parameters \(\theta\), target parameters \(\theta^- \leftarrow \theta\).
  2. Observe \(S_0\). For \(t = 0, 1, 2, \dots\):
    1. With probability \(\varepsilon_t\) pick a random action, else \(A_t = \argmax_a \hat q(S_t, a; \theta)\). (ε annealed linearly, e.g. 1 → 0.1)
    2. Step the environment; store \((S_t, A_t, R_{t+1}, S_{t+1}, \text{terminated})\) in \(\mathcal D\).
    3. If \(|\mathcal D| \ge\) replay start size and \(t \bmod k = 0\): sample \(B\) transitions uniformly; compute \(y_j = r_j + \gamma(1 - \text{term}_j)\max_{a'} \hat q(s'_j, a'; \theta^-)\) without gradient; take one optimizer step on \(\tfrac1B \sum_j \ell\big(y_j - \hat q(s_j, a_j; \theta)\big)\).
    4. Every \(C\) updates, \(\theta^- \leftarrow \theta\).
    5. If terminated or truncated, reset the environment.

import random
import numpy as np
import gymnasium as gym
import torch
import torch.nn as nn
import torch.nn.functional as F

env = gym.wrappers.RecordEpisodeStatistics(gym.make("CartPole-v1"))
obs_dim, n_actions = env.observation_space.shape[0], env.action_space.n
make_q = lambda: nn.Sequential(nn.Linear(obs_dim, 120), nn.ReLU(),
                               nn.Linear(120, 84), nn.ReLU(), nn.Linear(84, n_actions))
q, q_target = make_q(), make_q()
q_target.load_state_dict(q.state_dict())
opt = torch.optim.Adam(q.parameters(), lr=2.5e-4)

N, T, gamma, B = 10_000, 500_000, 0.99, 128               # CleanRL dqn.py defaults
S, S2 = np.zeros((N, obs_dim), np.float32), np.zeros((N, obs_dim), np.float32)
A, R, D = np.zeros(N, np.int64), np.zeros(N, np.float32), np.zeros(N, np.float32)
ptr = size = 0

obs, _ = env.reset(seed=0)
for t in range(T):
    eps = max(0.05, 1.0 - t / (0.5 * T))                   # linear decay over half the run
    if random.random() < eps:
        action = env.action_space.sample()
    else:
        with torch.no_grad():
            action = int(q(torch.as_tensor(obs)).argmax())
    next_obs, reward, terminated, truncated, info = env.step(action)
    S[ptr], A[ptr], R[ptr], S2[ptr], D[ptr] = obs, action, reward, next_obs, terminated
    ptr, size = (ptr + 1) % N, min(size + 1, N)
    obs = next_obs
    if terminated or truncated:                            # next_obs stored above is the true final state
        print(t, info["episode"]["r"])
        obs, _ = env.reset()

    if t >= 10_000 and t % 10 == 0:                        # learning starts; one update per 10 steps
        idx = np.random.randint(0, size, B)
        s, a, r, s2, d = (torch.as_tensor(x[idx]) for x in (S, A, R, S2, D))
        with torch.no_grad():                              # the target is a label: no gradient
            y = r + gamma * (1.0 - d) * q_target(s2).max(dim=1).values
        q_sa = q(s).gather(1, a.unsqueeze(1)).squeeze(1)   # Q(s, a) for the actions taken
        loss = F.mse_loss(q_sa, y)
        opt.zero_grad()
        loss.backward()
        opt.step()
    if t % 500 == 0:                                       # hard target update every 500 steps
        q_target.load_state_dict(q.state_dict())

Why naive online deep Q-learning diverges

“Naive” means the semi-gradient update applied to each transition as it arrives, with the same network producing the target. It is all three legs of the deadly triad of Day 69: function approximation (the network), bootstrapping (the target uses \(\hat q\)) and off-policy learning (the target is greedy while behaviour is ε-greedy). Baird's counterexample shows that combination can diverge even with linear features. Deep networks add four aggravating factors:

  1. Correlated updates. Consecutive transitions are near-duplicates. A hundred SGD steps in the same corner of the state space act like one step with a hundred times the learning rate there, overwriting what was learned elsewhere (catastrophic interference).
  2. A feedback loop between Q and data. If \(\hat q\) overrates “left”, the agent goes left, the incoming data becomes almost all left, and the network specializes to that narrow distribution. Data generated by the current estimate reinforces the current estimate.
  3. Targets that chase predictions. Generalization moves \(\hat q(s', \cdot)\) whenever \(\hat q(s, a)\) moves; Day 70's kernel calculation shows the target can move almost as far as the prediction.
  4. Maximization bias. The max over noisy estimates is biased upward, and bootstrapping compounds the bias step after step (Day 75).

Replay attacks the first two, the target network the third, Double DQN the fourth. None of them removes the triad. They make divergence rare enough in practice: van Hasselt et al. (2018) found that unbounded divergence almost never happened in DQN-style agents, while temporary blow-ups of the value estimates, which they called “soft divergence”, were common.

What breaks · the signatures of divergence
  • Mean \(\max_a \hat q\) rising steadily past any plausible return, for example above \(r_{\max}/(1 - \gamma) = 100\) on CartPole or clipped Atari.
  • Returns that improve, then collapse while the Q-values keep rising.
  • A TD loss growing by orders of magnitude rather than drifting.
  • All actions' Q-values moving up together. The network is extrapolating, not learning differences.

The 2013 and 2015 papers in context

The 2013 workshop paper (Mnih et al., “Playing Atari with Deep Reinforcement Learning”) trained on seven Atari games with replay but no target network and a smaller network. It beat earlier methods on six of the games and a human expert on three. The 2015 Nature paper (“Human-level control through deep reinforcement learning”) scaled this to 49 games with a single architecture and a single set of hyperparameters, added the target network and error clipping, and introduced the human-normalized evaluation of Day 74. It reached more than 75% of the human tester's score on more than half of the games. Earlier ALE agents relied on hand-designed features; DQN's contribution was a general recipe that worked end to end from pixels, and the rest of this module is the community fixing its weaknesses one by one.

DAY 72

Experience Replay

40m video90m practice

A replay buffer turns a stream of correlated, policy-dependent transitions into something close to a slowly changing dataset that SGD can digest. It works because one-step Q-learning is off-policy: a transition's target does not care which policy collected it.

Breaking temporal correlation

SGD's guarantees assume each minibatch is an unbiased sample of the loss you are minimizing. Consecutive environment transitions are nothing like that: two Atari frames 1/15 s apart are almost identical, and a minibatch of the last 32 transitions is effectively one transition repeated 32 times. Its gradient points the same way for many steps in a row, the effective batch size is close to 1, and the network overfits whatever region of the state space the agent happens to be in. Lin (1992) introduced experience replay to reuse costly experience; DQN uses it mainly to decorrelate.

i.i.d.-ifying the data

Sampling uniformly from a buffer of the last \(N\) transitions draws from the mixture of state–action distributions of the recent behaviour policies,

$$d_{\mathcal D}(s, a) = \frac{1}{N}\sum_{j=t-N+1}^{t} \mathbb 1\{(S_j, A_j) = (s, a)\},$$

which changes only slowly as old data leaves and new data arrives. Minibatches are not truly i.i.d., since the buffer itself drifts, but each one spans thousands of episodes and many regions of the state space. Three effects follow: gradients are decorrelated; the training distribution is smoothed over many past policies, which damps the Q-to-data feedback loop of Day 71; and states the current policy no longer visits stay in the training set long enough not to be forgotten at once. As a bonus, every transition is used several times, which improves data efficiency.

Sampling uniformly, and the replay ratio

Definition · replay ratio

The replay ratio is the number of gradient updates per environment step: \(\rho = 1/k\) if you update every \(k\) steps. Its batch-size-aware cousin, samples per insert, is \(B\rho\): how many transitions are replayed for each one added. Nature DQN has \(\rho = 1/4\) and \(B\rho = 8\); the CartPole defaults of Day 71 have \(\rho = 1/10\) and \(B\rho = 12.8\).

Derivation · how often is each transition replayed?

Once the buffer is full, a transition lives for \(N\) environment steps before it is overwritten, so it is present for \(N\rho\) updates. Each update draws \(B\) indices uniformly with replacement, picking it with probability \(1/N\) per draw. The expected number of replays is

$$N\rho \cdot B \cdot \frac{1}{N} = B\rho,$$

independent of \(N\). The chance it is never replayed is \((1 - 1/N)^{BN\rho} \approx e^{-B\rho}\), which is about \(3 \times 10^{-4}\) for \(B\rho = 8\). Buffer size changes how old the replayed data is, not how often each transition is reused.

The replay ratio is the main knob for data efficiency. Raising it squeezes more learning out of each environment step but costs compute, and past a point it causes overfitting to early data and loss of plasticity (Day 70). Agents built for small interaction budgets, such as Atari 100k, use far higher ratios than DQN and combine them with periodic network resets (Nikishin et al. 2022; D'Oro et al. 2023). Report your ratio: two agents with the same number of environment steps but different ratios have done very different amounts of learning.

Buffer capacity and its effect

Capacity sets the age of the data. Fedus et al. (2020) make this precise with the age of the oldest policy, the number of gradient updates since the oldest transition in the buffer was collected, which equals \(N\rho\).

  • Too small, and you are back to near-online learning: correlated batches, forgetting, and the feedback loop. Very small buffers also overfit, because the same few thousand transitions are replayed many times.
  • Too large, and the buffer is dominated by data from much worse policies, so improvements are reflected slowly; memory grows linearly. Zhang & Sutton (2017) showed that large buffers can hurt on simple tasks, and proposed always including the newest transition in each batch (“combined experience replay”).

Fedus et al. found that more capacity helps when the age of the oldest policy is held fixed, that Rainbow benefits from larger buffers while plain DQN barely does, and traced most of that difference to Rainbow's n-step returns (Day 78). Typical values: 1M transitions for Atari, 10k–100k for classic control, 1M for continuous-control actor-critics.

Why replay requires an off-policy learner

A buffer holds data from many past policies \(\mu_1, \mu_2, \dots\), none of them the current greedy policy. One-step Q-learning does not mind:

Derivation · the one-step target ignores the behaviour policy $$\E\big[y \mid s, a\big] = \sum_{s', r} p(s', r \mid s, a)\,\Big[r + \gamma\,(1 - \text{term}) \max_{a'} \hat q(s', a'; \theta^-)\Big].$$

Given \((s, a)\), the only randomness is the environment's. The behaviour policy chose \(a\), but that choice is conditioned on, and the next action is replaced by a max rather than taken from the data. No importance weight is needed. The behaviour policies affect only which \((s, a)\) pairs are in the buffer, and so where the approximation is accurate.

Methods whose targets depend on the behaviour's later actions are different. SARSA's target uses \(A_{t+1}\) from a stale policy, n-step returns use several stale actions (Day 78), and policy gradients need samples from the current policy, which is why PPO discards its data after each update (Day 91). Off-policy actor-critics (DDPG, TD3, SAC) can replay because their critics also bootstrap through the current actor rather than the stored action.

A circular buffer

import numpy as np
import torch

class ReplayBuffer:
    """Uniform circular replay buffer on preallocated arrays."""
    def __init__(self, capacity, obs_shape, obs_dtype=np.float32, seed=0):
        self.capacity, self.ptr, self.size = capacity, 0, 0
        self.obs = np.zeros((capacity, *obs_shape), dtype=obs_dtype)     # uint8 for pixels
        self.next_obs = np.zeros((capacity, *obs_shape), dtype=obs_dtype)
        self.act = np.zeros(capacity, dtype=np.int64)
        self.rew = np.zeros(capacity, dtype=np.float32)
        self.term = np.zeros(capacity, dtype=np.float32)   # terminated only, never truncated
        self.rng = np.random.default_rng(seed)

    def add(self, obs, act, rew, next_obs, terminated):
        i = self.ptr
        self.obs[i], self.act[i], self.rew[i] = obs, act, rew
        self.next_obs[i], self.term[i] = next_obs, terminated
        self.ptr = (self.ptr + 1) % self.capacity          # overwrite the oldest when full
        self.size = min(self.size + 1, self.capacity)

    def sample(self, batch_size, device="cpu"):
        idx = self.rng.integers(0, self.size, size=batch_size)   # uniform, with replacement
        to = lambda x: torch.as_tensor(x[idx], device=device)
        return to(self.obs), to(self.act), to(self.rew), to(self.next_obs), to(self.term)

Preallocating avoids Python-object overhead and makes sampling a single fancy-index per field. A deque of tuples works for CartPole and is far too slow for Atari.

An Atari observation is four stacked 84×84 frames. Storing every transition naively is ruinous:

Libraries differ. Stable-Baselines3's ReplayBuffer(optimize_memory_usage=True), which CleanRL's dqn_atari.py uses, stores observation stacks once and reads \(s'\) from the following slot, the third row of the table. Dopamine-style buffers store single frames, the fourth row. Whichever you use, test it against the wrapper's own stacks at episode boundaries.

What breaks
  • Storing done = terminated or truncated. Every time-limit cut-off becomes a fake terminal state (Day 8).
  • Reusing the next slot as \(s'\) loses the final observation. After an episode ends, the next slot holds the reset observation. That is harmless when terminated masks the bootstrap and wrong at a truncation. SB3 refuses to combine optimize_memory_usage=True with timeout handling for exactly this reason.
  • Float32 frames, four times the memory of uint8, which on Atari means swapping to disk or an out-of-memory crash hours into a run.
  • Learning before the buffer has any variety. Training on the first few hundred transitions overfits them; use a replay start size (10k–50k steps).
  • Replay with an on-policy learner, such as SARSA or plain policy gradients, from stale data.

DAY 73

Target Networks & Stabilization

40m video90m practice

A target network holds the regression labels still for thousands of updates, so each stretch of training is an honest supervised problem. Huber loss, gradient clipping and reward clipping then bound how hard any single transition can push the network.

The moving-target problem

With the target computed by the network being trained, every step moves the labels (Day 70). Freeze a copy \(\theta^-\) and, for as long as it stays frozen, the loss

$$L(\theta) = \E_{\mathcal D}\Big[\big(r + \gamma\,(1 - \text{term}) \max_{a'} \hat q(s', a'; \theta^-) - \hat q(s, a; \theta)\big)^2\Big]$$

is a fixed regression problem. The cross term in Day 70's kernel calculation vanishes, because the target no longer responds to the step, and ordinary SGD reasoning applies inside the period. The price is speed: if each period were fitted exactly, it would perform one Bellman backup, \(\hat q_{k+1} = T\hat q_k\), and value information would travel one step back in time per target update.

Derivation · how many target periods do you need?

In the exact-fit idealization, period \(k\) is value iteration, so by the contraction property (Day 32) \(\|\hat q_K - q_*\|_\infty \le \gamma^K \|\hat q_0 - q_*\|_\infty\). Shrinking the initial error a hundredfold needs \(K \ge \ln 100 / \ln(1/\gamma)\), about 460 periods for \(\gamma = 0.99\). With \(C = 10{,}000\) updates per period that is 4.6M updates before any slack for imperfect fits. This is the trade-off in one line: a large \(C\) makes each period a clean regression but leaves fewer periods in the budget; a small \(C\) brings the moving target back.

Hard target updates every C steps

The Nature DQN rule is \(\theta^- \leftarrow \theta\) every \(C\) updates. Inside a period the targets are constant; at the boundary all of them jump at once, which shows up as a sawtooth in the TD loss. The paper uses \(C = 10{,}000\) and states it in parameter updates. Reimplementations disagree on whether \(C\) counts updates or environment steps; with one update per four steps that is a factor of four, so always state which. Values in use on Atari range from roughly 1,000 to 10,000 environment steps; CleanRL's CartPole script copies every 500 steps.

Polyak (soft) updates

Instead of copying occasionally, move the target a small step towards the online network after every update:

$$\theta^- \leftarrow \tau\,\theta + (1 - \tau)\,\theta^-, \qquad 0 < \tau \ll 1.$$
Derivation · the target is an exponential moving average

Unrolling the recursion, \(\theta^-_t = \sum_{j \ge 0} \tau (1 - \tau)^j\,\theta_{t-j}\) (plus a vanishing term from the initial value). The weights sum to 1, and the mean lag is

$$\sum_{j \ge 0} j\,\tau(1 - \tau)^j = \frac{1 - \tau}{\tau} \approx \frac{1}{\tau}.$$

A hard update with period \(C\) has a lag that cycles uniformly through \(0, \dots, C - 1\), a mean of \((C - 1)/2\). Equal mean lags give \(\tau \approx 2/(C + 1)\): copying every 1,000 updates is comparable to \(\tau \approx 0.002\).

Soft updates have no jumps, but the target is never fully frozen, so a small cross term of order \(\tau\) remains. Averaging the parameters of a nonlinear network is not the same as averaging the functions it computes; it works because consecutive parameter vectors are close, so to first order the two agree. DDPG introduced soft targets with \(\tau = 0.001\), and TD3 and SAC use \(\tau = 0.005\) (Module 9). DQN-family agents mostly use hard updates, though both work.

import torch
import torch.nn.functional as F

@torch.no_grad()
def update_target(target, online, tau=1.0):
    """tau = 1: hard copy (call every C updates). tau < 1: Polyak averaging (call every update)."""
    for p_t, p in zip(target.parameters(), online.parameters()):
        p_t.lerp_(p, tau)                             # p_t <- p_t + tau * (p - p_t)
    for b_t, b in zip(target.buffers(), online.buffers()):
        b_t.copy_(b)                                  # running statistics etc., if any

# Huber's gradient is the clipped TD error; clipping the *loss* instead kills large-error gradients
delta = torch.tensor([-3.0, -0.5, 0.25, 4.0])         # prediction minus target

    "clipped loss": lambda d: torch.clamp(0.5 * d ** 2, max=0.5),
}
for name, f in losses.items():

    print(f"{name:13s}", [g + 0.0 for g in d.grad.tolist()])   # + 0.0 prints -0.0 as 0.0

Huber loss vs MSE

Definition · Huber loss $$L_\kappa(\delta) = \begin{cases} \tfrac12 \delta^2 & |\delta| \le \kappa \\ \kappa\big(|\delta| - \tfrac12 \kappa\big) & |\delta| > \kappa \end{cases}$$

Quadratic near zero, linear in the tails, and the two pieces meet with equal value \(\tfrac12\kappa^2\) and equal slope \(\kappa\) at \(|\delta| = \kappa\).

Derivation · the gradient is the clipped error

Differentiating piecewise, \(L_\kappa'(\delta) = \delta\) for \(|\delta| \le \kappa\) and \(\kappa \operatorname{sign}(\delta)\) otherwise, that is \(L_\kappa'(\delta) = \clip(\delta, -\kappa, \kappa)\). With \(\delta = y - \hat q(s, a; \theta)\) and \(y\) held constant,

$$\nabla_\theta L_\kappa = -\clip(\delta, -\kappa, \kappa)\,\nabla_\theta \hat q(s, a; \theta).$$

The MSE gradient is \(-\delta\,\nabla_\theta \hat q\). The Nature paper's “clip the error term to \([-1, 1]\)” means clipping \(\delta\) in that expression, which is exactly Huber with \(\kappa = 1\). Clipping the loss value, \(\min(\tfrac12\delta^2, \tfrac12)\), is a different and harmful thing: its gradient is zero for every transition with \(|\delta| > 1\), so the most surprising data is ignored entirely. The snippet above prints all three.

Huber also changes what is estimated. The minimizer of \(\E[\tfrac12(y - c)^2]\) is the mean of \(y\); that of \(\E|y - c|\) is the median; Huber's minimizer solves \(\E[\clip(y - c, -\kappa, \kappa)] = 0\) and lies between them. With heavy-tailed targets the fixed point is therefore not exactly \(\E[y \mid s, a]\). With clipped rewards most TD errors sit in the quadratic zone, so in practice the difference is the bounded step size for outliers. In PyTorch, F.huber_loss(delta=κ) is \(L_\kappa\) and F.smooth_l1_loss(beta=β) is \(L_\beta/\beta\); they coincide at 1. SB3 and Dopamine use Huber for DQN; CleanRL's DQN scripts use MSE with Adam, which works because Adam's per-parameter normalization already damps large gradients.

Gradient clipping

torch.nn.utils.clip_grad_norm_(params, c) rescales the whole gradient, \(g \leftarrow g \cdot \min(1, c/\|g\|_2)\), between backward() and step(). It complements Huber rather than duplicating it: Huber bounds each sample's pull on the output, and norm clipping bounds the total parameter step, which can still be large when many samples agree or when \(\nabla_\theta \hat q\) itself is large. A threshold of 10 is common for DQN-family agents (SB3's default; the dueling paper also clipped to 10). With Adam, clipping matters less for the step size but still protects the second-moment estimate from being inflated by one spike, which would otherwise slow learning for thousands of steps afterwards.

Reward clipping

Nature DQN replaced every reward with its sign: \(+1\), \(-1\) or 0. Since Atari rewards are integers, that equals clipping to \([-1, 1]\). It does three things:

  • It lets one learning rate work across 49 games whose scores differ by orders of magnitude.
  • It bounds the values: \(|q| \le 1/(1 - \gamma) = 100\), which also makes C51's fixed support \([-10, 10]\) workable (Day 79).
  • It changes the task. The agent maximizes the discounted number of rewarding events, not the score, so in Ms. Pac-Man a ghost worth hundreds of points counts the same as a 10-point pellet. Train on clipped rewards, but always evaluate and report the raw game score.

Later agents avoid clipping with scale-invariant targets. PopArt (van Hasselt et al. 2016) adaptively normalizes targets while preserving the network's outputs. Value rescaling (Pohlen et al. 2018), used in R2D2 (Day 121), trains on \(h(y)\) with \(h(x) = \operatorname{sign}(x)\big(\sqrt{|x| + 1} - 1\big) + \epsilon x\), \(\epsilon = 10^{-3}\), and inverts \(h\) inside the target.

Ablation: what happens when you remove each

The Nature paper ablated replay and the target network on five games (Breakout, Enduro, River Raid, Seaquest, Space Invaders). Both helped on all five; removing replay hurt far more than removing the target network; removing both was worst, close to random play on several games. The other stabilizers are less often ablated, and their effect depends on the rest of the configuration:

  • \(C = 1\), or \(\tau = 1\) every step. Both are “no target network”, often arrived at by a unit mix-up in target_network_frequency.

The Atari Pipeline

40m video90m practice

Half of an Atari result is the preprocessing and the evaluation protocol. The same algorithm behind different wrappers, or scored under different rules, produces numbers that cannot be compared.

The Arcade Learning Environment

The ALE (Bellemare et al. 2013) emulates the Atari 2600: 210×160 RGB frames at 60 Hz, 18 joystick actions (each game also has a minimal action set of 4–18 actions), and a reward equal to the change in game score. In Gymnasium it comes from the ale-py package:

import gymnasium as gym
import ale_py

gym.register_envs(ale_py)                 # makes the "ALE/..." ids available
env = gym.make("ALE/Breakout-v5")         # v5 defaults: frameskip=4, repeat_action_probability=0.25
print(env.action_space, env.unwrapped.get_action_meanings())

For a DQN-style pipeline, where wrappers do the frame skipping and max-pooling, create the environment with frameskip=1. Older code uses ids such as BreakoutNoFrameskip-v4, which have no frame skip and no sticky actions. Know which one your baseline used.

Grayscale and downsampling to 84×84

The Nature paper extracts the luminance channel and rescales it to 84×84; the 2013 paper downsampled to 110×84 and cropped an 84×84 playing area. Either way the input shrinks by a factor of about 14 (100,800 numbers to 7,056), which pays for a buffer of a million transitions and a fast CNN. It is a lossy choice: colour is rarely needed to play, but in a few games objects differ mainly in colour, and fine details can disappear at 84×84.

Frame stacking for velocity

A single frame is not a Markov state: it shows where the ball is, not where it is going (Day 6). Stacking the \(k = 4\) most recent processed frames as channels gives the network velocity and some acceleration. Stacking is a short-memory fix. Anything that must be remembered for longer than the stack, such as which key was collected two rooms ago, needs a recurrent agent (Day 121). Gymnasium's wrapper is FrameStackObservation (renamed from FrameStack in 1.0).

Action repeat / frame skip

The agent chooses an action every \(k = 4\) frames; the action is repeated for those frames and the rewards are summed. That makes training four times cheaper per second of play, and it makes each decision matter more, since a single 1/60 s frame rarely changes anything. The 2013 paper used \(k = 3\) for Space Invaders, because with \(k = 4\) the blinking lasers were invisible. Frame skip is also the source of the most common reporting confusion. Budgets are quoted in emulator frames: the standard 200M frames are 50M agent steps, which is what the Nature paper calls “50 million frames”, about 38 days of play at 60 Hz. Before comparing two curves, check whether their x-axes count frames or steps.

Max-pooling over frames for flicker

The Atari 2600 can draw only a few sprites per scanline, so many games draw some objects on even frames and others on odd frames. A single frame can be missing enemies or projectiles entirely. DQN takes the pixel-wise maximum over the last two frames of each four-frame skip window, which recovers objects drawn on either frame. Gymnasium's AtariPreprocessing does this when frame_skip > 1.

The episodic-life wrapper

Many games give several lives. The episodic-life trick tells the learner that losing a life is terminal, so the value of a life-losing state is learned at once rather than through a long chain of bootstraps until game over, while the emulator is reset only when the game really ends. DQN and most reimplementations used it, typically together with a wrapper that presses FIRE after a reset in games that need it. Machado et al. (2018) recommend against it: it uses game-specific information, and it blurs what an episode is. If you use it, implement it as a flag stored in the buffer rather than as a reset, and always evaluate on full games.

import numpy as np
import gymnasium as gym
import ale_py

gym.register_envs(ale_py)

def make_atari(env_id="ALE/Breakout-v5", sticky=0.25, clip_rewards=True):
    env = gym.make(env_id, frameskip=1, repeat_action_probability=sticky)  # wrappers do the skipping
    env = gym.wrappers.RecordEpisodeStatistics(env)          # inside the clip: logs the raw game score
    env = gym.wrappers.AtariPreprocessing(
        env, noop_max=30, frame_skip=4, screen_size=84,      # max-pools the last two frames of each skip
        terminal_on_life_loss=False, grayscale_obs=True, scale_obs=False)
    env = gym.wrappers.FrameStackObservation(env, stack_size=4)
    if clip_rewards:                                         # training only
        env = gym.wrappers.TransformReward(env, lambda r: float(np.sign(r)))
    return env

env = make_atari()
obs, info = env.reset(seed=0)
print(obs.shape, obs.dtype, info["lives"])                   # (4, 84, 84) uint8 5

obs, reward, terminated, truncated, info = env.step(env.action_space.sample())
life_lost = info["lives"] < lives      # optional episodic life: store (terminated or life_lost), reset only on game over
lives = info["lives"]

Keep observations uint8 and scale inside the network; scale_obs=True plus a / 255 in forward divides twice. terminal_on_life_loss=True would make the training loop reset the whole game at every lost life.

No-op starts and sticky actions

The emulator is deterministic: the same actions from the same start produce the same game. An agent can therefore score well by memorizing one trajectory. Machado et al. showed that “Brute”, a search over open-loop action sequences that ignores the screen entirely, does well on several games in the deterministic setting. Protocols inject stochasticity in different ways:

  • No-op starts (Nature): after each reset, take a random number (up to 30) of no-op actions. This varies only the start state.
  • Human starts (Nair et al. 2015): begin evaluation episodes from 100 states sampled from human play, so the agent must cope with situations it did not steer itself into.
  • Sticky actions (Machado et al. 2018): at every emulator frame, with probability \(\varsigma\) the previous action is executed instead of the agent's choice,
$$a^{\text{emu}}_f = \begin{cases} a^{\text{emu}}_{f-1} & \text{with probability } \varsigma, \\ a^{\text{agent}}_f & \text{otherwise,} \end{cases} \qquad \varsigma = 0.25.$$

Sticky actions keep the randomness going throughout the episode, apply to every agent equally, and behave like a slight reaction lag, so a memorized sequence drifts off course within seconds. They are the default in the ALE's v5 environments.

The standard 30-minute evaluation protocol

Definition · evaluation protocols you will see
  • Nature (2015): 30 evaluation episodes per game, up to 30 no-op starts, ε = 0.05, episodes up to 5 minutes.
  • 30-minute protocol (later DQN-family papers, including Rainbow): episodes truncated at 108,000 frames, i.e. 30 minutes at 60 Hz or 27,000 agent steps, with up to 30 no-op starts and a small ε (0.05, or as little as 0.001 in some papers), averaged over many episodes or a fixed number of evaluation steps.
  • Human starts: as above, but starting from human-play states.
  • Machado et al. (2018): sticky actions with \(\varsigma = 0.25\), game over as the only terminal signal, results reported at several frame budgets (10M, 50M, 100M, 200M), summarized from the training episodes themselves (for example, the mean over the last 100 episodes before each budget) rather than from a separate, separately tuned evaluation.

None of these is “correct”; what matters is that you state yours and compare only like with like. Results under no-op starts in a deterministic emulator are systematically higher than under sticky actions, and best-checkpoint reporting (the maximum over training) is higher still.

Human-normalized scores

Definition · human-normalized score $$\text{HNS} = \frac{\text{score}_{\text{agent}} - \text{score}_{\text{random}}}{\text{score}_{\text{human}} - \text{score}_{\text{random}}}.$$

0 means random play, 1 (100%) means the human reference. The Nature reference is a professional games tester after about two hours of practice per game; later papers sometimes use other tables, so quote the one you used.

Raw scores differ by orders of magnitude between games, so normalization is what makes aggregation possible. Aggregate with the median over games, or better with the interquartile mean and stratified bootstrap intervals (Agarwal et al. 2021, Day 7). The arithmetic mean is dominated by a handful of games where agents reach thousands of percent:

  • Frames vs steps: a factor of four on the x-axis, in either direction.
  • Reporting clipped returns or per-life “episodes” as game scores.
  • Evaluating with ε = 0 in a deterministic emulator. A greedy agent that never presses FIRE waits until the 108,000-frame cap, and a memorized loop looks great with no-op starts and collapses with sticky actions.

Double DQN

35m video75m practice

The max in the DQN target picks whichever action's estimate happens to be too high, so DQN systematically overestimates. Double DQN separates choosing the action from evaluating it, using the two networks DQN already has, at the cost of one extra forward pass.

Maximization bias in the deep setting

You met the tabular version on Day 3 (\(\E[\max] \ge \max \E\)) and its fix on Day 47 (Double Q-learning). In DQN the estimation errors come from everywhere: sampling noise, approximation error, non-stationary targets, imperfect fits within each target period. The max does not need much to work with:

Theorem · van Hasselt, Guez & Silver 2016

Let state \(s\) have \(m \ge 2\) actions whose true values all equal \(v_*(s)\). Let the estimates \(Q(s, a)\) be unbiased on average, \(\sum_a \big(Q(s, a) - v_*(s)\big) = 0\), but not all exact: \(\tfrac1m \sum_a \big(Q(s, a) - v_*(s)\big)^2 = C > 0\). Then

$$\max_a Q(s, a) \ \ge\ v_*(s) + \sqrt{\frac{C}{m - 1}},$$

and the bound is tight. Under the same conditions, the lower bound on the absolute error of the double estimator is zero.

Proof sketch

Write \(\varepsilon_a = Q(s, a) - v_*(s)\) and \(M = \max_a \varepsilon_a\). The positive errors sum to some \(P\), and the negative ones to \(-P\), since the total is zero. At most \(m - 1\) errors are positive, each at most \(M\), so \(P \le (m - 1)M\). The squares of the positive errors sum to at most \(MP\), and those of the negative errors to at most \(P^2\). Hence

$$mC = \sum_a \varepsilon_a^2 \le MP + P^2 \le (m - 1)M^2 + (m - 1)^2 M^2 = m(m - 1)M^2,$$

so \(M \ge \sqrt{C/(m - 1)}\). Equality holds when \(m - 1\) errors equal \(M\) and one equals \(-(m - 1)M\).

Errors that cancel on average still produce a max that is strictly too high. This is not only a noise effect: van Hasselt et al. show that even a noiseless but imperfect fit (a polynomial through a few sampled true values) overestimates, more so with more actions. Bootstrapping then compounds the bias, since each backup adds the overestimate at \(s'\) into \(\hat q(s, a)\), and over an effective horizon of \(1/(1 - \gamma)\) steps the biases accumulate. Uniform overestimation would be harmless, because it leaves the argmax unchanged. The damage comes from uneven overestimation, which inflates the actions and states the network is most uncertain about, and from the instability it feeds.

Select with the online network, evaluate with the target

Definition · DQN vs Double DQN targets $$Y^{\text{DQN}} = r + \gamma\,(1 - \text{term})\ \hat q\big(s', \argmax_{a'} \hat q(s', a'; \theta^-);\ \theta^-\big),$$ $$Y^{\text{Double}} = r + \gamma\,(1 - \text{term})\ \hat q\big(s', \argmax_{a'} \hat q(s', a'; \theta);\ \theta^-\big).$$

DQN uses the same numbers to pick the action and to score it. Double DQN picks with the online network and scores with the target network.

Derivation · why decoupling removes the upward bias

Model the two networks as \(Q = q + \varepsilon\) and \(Q^- = q + \varepsilon^-\) at \(s'\), with \(\varepsilon^-\) independent of \(\varepsilon\) and zero-mean. The selected action \(\hat a = \argmax_a Q(s', a)\) depends only on \(\varepsilon\), so

$$\E\big[Q^-(s', \hat a)\big] = \E\big[q(s', \hat a)\big] + \E\big[\E[\varepsilon^-(\hat a) \mid \varepsilon]\big] = \E\big[q(s', \hat a)\big] \le \max_a q(s', a).$$

The evaluation is unbiased for the chosen action, and the chosen action is at best the true argmax, so the estimate can only err low. In DQN \(\varepsilon^- = \varepsilon\) and the conditional expectation does not vanish.

The independence is only approximate. \(\theta^-\) is a lagged copy of \(\theta\), so their errors are correlated, and immediately after a hard copy the two networks are identical and Double DQN's target equals DQN's. The original Double Q-learning (2010) trained two independent estimators and swapped their roles at random. Double DQN accepts partial decoupling in exchange for not adding a third network: in the paper's words, the minimal possible change to DQN.

Value-estimate plots: overestimation and its correction

To see overestimation you need the true value of the policy, which you get by running it. Van Hasselt et al. compared DQN's average value estimates during training with the actual discounted returns of the final policies. On most games DQN's estimates sat well above the truth; on some, such as Asterix and Wizard of Wor, they grew by orders of magnitude while the scores collapsed at the same time. Double DQN's estimates stayed close to the true values and its learning curves were more stable.

import numpy as np
import torch

@torch.no_grad()
def overestimation(env, q, gamma=0.99, episodes=10, seed=1000):
    """Mean of Q(S_t, A_t) minus the discounted return actually obtained from t, greedy policy."""
    gaps = []
    for ep in range(episodes):
        obs, _ = env.reset(seed=seed + ep)
        qs, rewards, done = [], [], False
        while not done:
            qv = q(torch.as_tensor(obs, dtype=torch.float32).unsqueeze(0))[0]
            a = int(qv.argmax())
            qs.append(float(qv[a]))
            obs, r, terminated, truncated, _ = env.step(a)
            rewards.append(float(r))
            done = terminated or truncated
        G, returns = 0.0, []
        for r in reversed(rewards):                   # discounted return-to-go
            G = r + gamma * G
            returns.append(G)
        returns.reverse()
        keep = len(rewards) - (int(1 / (1 - gamma)) if truncated else 0)   # a cut-off tail undercounts G
        gaps += [qq - g for qq, g in zip(qs[:keep], returns[:keep])]
    return float(np.mean(gaps)) if gaps else float("nan")

If the episode was truncated, the returns of its last steps are missing their future, so the last ~\(1/(1 - \gamma)\) steps are dropped rather than counted as overestimation. Pass the same γ the agent trains with.

Atari score improvements

With the network, hyperparameters and protocol of Nature DQN unchanged, Double DQN raised the median human-normalized score over the 49 games from roughly 94% to roughly 115% under no-op starts, with a larger relative gain under human starts, which are harder to exploit by memorization. A lightly tuned variant did better still: target period raised from 10,000 to 30,000, training ε lowered from 0.1 to 0.01, evaluation ε from 0.05 to 0.001, and a single shared bias for all action values in the output layer. Double DQN is now a default part of almost every DQN-family agent. Rainbow's ablation (Day 80) found that removing it costs little once distributional learning is present, which is a statement about the combination, not about Double DQN alone.

What breaks
  • Expecting it to cure divergence. It removes one source of upward bias, not the deadly triad, and it can underestimate.
  • Nearly identical networks. With Polyak averaging at a large \(\tau\), or right after every hard copy, \(\theta \approx \theta^-\) and the decoupling vanishes.
  • Swapping the roles (select with the target, evaluate with the online network) still decouples, but brings the fast-moving network back into the label.
  • Computing the online argmax outside no_grad. The result is the same, but you build and keep a useless graph every step.
  • Mis-measuring the bias: comparing greedy Q-values with returns of an ε-greedy policy, using a different γ, or counting truncated tails.

Dueling Networks

35m video75m practice

Split the Q-head into a state-value stream and an advantage stream, so that every update improves \(V(s)\) for all actions at once. The split is not identifiable on its own; subtracting the mean advantage fixes that without changing the greedy action.

Decomposing Q into V(s) + A(s, a)

Definition · advantage

\(A^\pi(s, a) = q^\pi(s, a) - v^\pi(s)\): how much better action \(a\) is than the policy's average in \(s\). Because \(v^\pi(s) = \E_{a \sim \pi}[q^\pi(s, a)]\), advantages average to zero under the policy, \(\E_{a \sim \pi}[A^\pi(s, a)] = 0\). For the optimal greedy policy \(v_*(s) = \max_a q_*(s, a)\), so \(\max_a A_*(s, a) = 0\).

The value says how good the situation is; the advantage says how much the choice matters. They live on very different scales and change at different rates, which suggests learning them separately. Baird's advantage updating (1993) did this for tabular and linear learners. Wang et al. (2016) made it an architecture: keep the convolutional torso, then branch into a value stream that outputs a scalar \(V(s; \theta, \beta)\) and an advantage stream that outputs a vector \(A(s, \cdot\,; \theta, \alpha)\), and recombine them in a fixed, parameter-free aggregation layer that outputs \(Q(s, \cdot)\). Everything downstream (targets, loss, Double DQN, replay) is unchanged, because the network still outputs Q-values.

The identifiability problem

The obvious aggregator, \(Q = V + A\), cannot work as intended. For any function \(c(s)\), the pair \((V + c,\ A - c)\) produces exactly the same \(Q\), and the loss sees only \(Q\). Nothing in training determines how much of each Q-value belongs to \(V\) and how much to \(A\): the streams can drift in opposite directions at no cost, \(V\) need not resemble a value at all, and the hoped-for division of labour does not reliably happen. Wang et al. report that the plain sum performs worse in practice. The fix is to constrain \(A\) so that only one decomposition fits.

The mean-subtraction aggregator

Two constraints suggest themselves. Forcing the best action's advantage to zero mirrors \(\max_a A_* = 0\); forcing the average to zero mirrors \(\E_\pi[A^\pi] = 0\):

$$Q(s, a) = V(s) + \Big(A(s, a) - \max_{a'} A(s, a')\Big) \qquad\text{or}\qquad Q(s, a) = V(s) + \Big(A(s, a) - \frac{1}{|\mathcal A|}\sum_{a'} A(s, a')\Big).$$
Derivation · the mean aggregator is identifiable

Write \(\bar A(s) = \tfrac{1}{|\mathcal A|}\sum_{a'} A(s, a')\). Averaging the mean-aggregated \(Q\) over actions gives

$$\frac{1}{|\mathcal A|}\sum_a Q(s, a) = V(s) + \bar A(s) - \bar A(s) = V(s).$$

So \(V\) is uniquely determined by \(Q\): it is the mean action value. And \(A(s, a) - \bar A(s) = Q(s, a) - V(s)\) is determined too; the only freedom left is a constant added to every advantage, which the aggregator cancels and which does not affect \(Q\). The gradients show the division of labour: \(\partial Q(s, a)/\partial V(s) = 1\) for every \(a\), so every transition trains \(V\), and \(\partial Q(s, a)/\partial A(s, b) = \mathbb 1\{a = b\} - 1/|\mathcal A|\), so updating one action's advantage nudges the others down to keep the mean fixed.

With the max aggregator, \(V\) would estimate \(\max_a Q = v_*\) exactly, which is more interpretable. Wang et al. nevertheless chose the mean, because it is more stable: the max version's correction jumps whenever the argmax switches between actions, while the mean moves smoothly, so the advantages only have to change as fast as their average. The price is semantic: under the mean aggregator \(V\) is the mean action value, off from \(v_*\) by a state-dependent constant, so do not read it as \(v_*\). The greedy action is unaffected in both cases, since \(\argmax_a Q(s, a) = \argmax_a A(s, a)\).

import torch
import torch.nn as nn

class DuelingQ(nn.Module):
    """Nature CNN torso, then separate value and advantage streams (Wang et al. 2016)."""
    def __init__(self, n_actions, in_ch=4):
        super().__init__()
        self.torso = nn.Sequential(
            nn.Conv2d(in_ch, 32, 8, stride=4), nn.ReLU(),
            nn.Conv2d(32, 64, 4, stride=2), nn.ReLU(),
            nn.Conv2d(64, 64, 3, stride=1), nn.ReLU(), nn.Flatten())
        self.value = nn.Sequential(nn.Linear(3136, 512), nn.ReLU(), nn.Linear(512, 1))
        self.adv = nn.Sequential(nn.Linear(3136, 512), nn.ReLU(), nn.Linear(512, n_actions))

    def forward(self, x):
        h = self.torso(x.float() / 255.0)
        if h.requires_grad:                               # both streams backprop into h: scale by 1/sqrt(2)
            h.register_hook(lambda g: g / 2 ** 0.5)
        v, a = self.value(h), self.adv(h)                  # [B, 1], [B, |A|]
        return v + a - a.mean(dim=1, keepdim=True)         # keepdim matters: see "What breaks"

q = DuelingQ(n_actions=6)
x = torch.randint(0, 256, (3, 4, 84, 84), dtype=torch.uint8)
with torch.no_grad():
    v = q.value(q.torso(x.float() / 255.0))
    print(torch.allclose(q(x).mean(dim=1, keepdim=True), v, atol=1e-5))   # True: V = mean_a Q

Why it helps when actions don't matter much

In many states the choice of action barely affects the return. Driving in Enduro with no car ahead, every action has nearly the same value; the choice matters only when a collision is imminent. A single-stream network has to learn that common value level separately in each action's output, from that action's samples only. The dueling network learns it once in \(V\), from every sample, and spends the advantage stream on the differences.

There is also a scale argument. Differences between action values are often tiny compared with the values themselves. In the paper's Seaquest example the average gap between the best and second-best action is roughly 0.04, while the average state value is about 15. Estimation noise far smaller than the value scale is then enough to reorder the actions and make the greedy policy flicker. Representing the small differences in their own stream, separate from the large common level, makes the ordering more robust to noise in \(V\). Wang et al. checked this in a corridor policy-evaluation task: the dueling network's advantage over a single stream grew as the number of (mostly redundant) actions went from 5 to 10 to 20.

Saliency-map evidence

To see what each stream attends to, Wang et al. computed gradient saliency maps (Simonyan et al. 2014): the absolute Jacobian of each stream's output with respect to the input pixels, \(|\nabla_s V(s)|\) and \(|\nabla_s A(s, \argmax_a A(s, a))|\). On Enduro the value stream attends to the road, especially the horizon where new cars appear, and to the score. The advantage stream pays little attention when the road ahead is clear and focuses on the car immediately in front when a collision is near, which is exactly when the action matters.

def saliency(q, obs):
    """|d stream / d pixel| for one stacked observation; returns two 84x84 maps."""
    x = torch.as_tensor(obs, dtype=torch.float32).unsqueeze(0).requires_grad_(True)
    h = q.torso(x / 255.0)
    v, a = q.value(h), q.adv(h)
    g_v, = torch.autograd.grad(v.sum(), x, retain_graph=True)
    g_a, = torch.autograd.grad(a[0, a.argmax()], x)
    return g_v.abs()[0].amax(dim=0), g_a.abs()[0].amax(dim=0)   # max over the 4 stacked frames

Treat saliency maps as suggestive, not as proof of mechanism. Gradient saliency is noisy, sensitive to small input changes, and in some cases barely depends on the trained weights at all (Adebayo et al. 2018). The architectural argument and the score improvements carry the case; the maps make it intuitive.

Results and training details

Combined with Double DQN targets, the dueling architecture beat the single-stream Double DQN baseline on most of the 57 Atari games, and combined with prioritized replay (Day 77) it set a new state of the art at the time. Two training details matter when reproducing it: gradients were clipped to a norm of 10, and the gradient entering the last convolutional layer was scaled by \(1/\sqrt 2\), since both streams backpropagate into it and would otherwise double its effective step size. Rainbow (Day 80) keeps the dueling head, applying the aggregation to the logits of each return atom.

What breaks
  • Dropping keepdim=True. a.mean(dim=1) has shape [B], and [B, |A|] - [B] broadcasts along the wrong axis. With a batch of one (acting) it happens to be right; with \(B \ne |\mathcal A|\) it raises an error; with \(B = |\mathcal A|\) it silently subtracts the wrong means. LunarLander has 4 actions, so a unit test with a batch of 4 passes with wrong numbers.
  • The plain sum \(V + A\), which leaves the decomposition unidentified.
  • Reading \(V\) as \(v_*\) under the mean aggregator. It is the mean action value.
  • Aggregating after a softmax in a distributional head. Aggregate the logits, then normalize (Day 80).
  • Over-reading saliency maps as explanations of the policy.

Prioritized Experience Replay

45m video105m practice

Replay transitions in proportion to how much there is still to learn from them, measured by the TD error, and correct the distribution shift this causes with importance-sampling weights that are annealed to full strength by the end of training.

Sampling by TD-error magnitude

Uniform replay spends most of its updates on transitions the network already predicts well. Schaul et al. (2016) made the point with the Blind Cliffwalk: a chain of \(n\) states where one action moves right and the other ends the episode with reward 0, and only reaching the far end pays 1. A random policy reaches the end with probability \(2^{-n}\), so the one informative transition is exponentially rare in the buffer, and uniform replay needs exponentially many updates to propagate it. Replaying in the right order is exponentially faster. This is the same insight as prioritized sweeping in planning (Day 57): spend updates where values are about to change.

The proxy for “how much is left to learn” is the magnitude of the TD error, \(|\delta_i| = |y_i - \hat q(s_i, a_i)|\), which is cheap because it is computed during the update anyway. Greedy prioritization (always replay the largest \(|\delta|\)) fails in three ways: priorities are stale because they are refreshed only when a transition is replayed, so one with a small initial error may never be seen again; noisy rewards keep \(|\delta|\) high forever, and the agent fixates on the noise; and replaying a small high-error subset overfits it.

Proportional vs rank-based prioritization

Definition · stochastic prioritization $$P(i) = \frac{p_i^\alpha}{\sum_k p_k^\alpha}.$$

\(\alpha = 0\) is uniform replay and \(\alpha = 1\) is fully proportional; \(\alpha\) interpolates. Two choices of priority \(p_i\):

  • Proportional: \(p_i = |\delta_i| + \epsilon\), with a small \(\epsilon > 0\) so that no transition's probability is exactly zero.
  • Rank-based: \(p_i = 1/\operatorname{rank}(i)\), where rank 1 is the largest \(|\delta|\). \(P\) is then a power law in the rank.

New transitions have no TD error yet, so they enter with the current maximum priority, which guarantees each is replayed at least once soon after it arrives.

Rank-based priorities ignore the scale of the errors, so they are robust to outliers: one enormous \(|\delta|\) gets rank 1, not most of the probability mass. They are implemented with an approximately sorted heap that is re-sorted only occasionally, plus a precomputed split of the rank distribution into \(B\) segments of equal probability, one sample per segment. Proportional priorities use the error magnitudes directly and need a sum-tree. In the paper the two performed similarly; proportional prioritization is what most implementations, Rainbow included, use, because the sum-tree is simple and exact.

The sum-tree data structure

Sampling from \(P\) naively, with a cumulative sum over \(N = 10^6\) priorities, costs \(O(N)\) per minibatch, and every update changes the priorities. A sum-tree is a complete binary tree whose leaves hold the \(p_i^\alpha\) and whose internal nodes hold the sum of their children, so the root holds \(\sum_k p_k^\alpha\). Each leaf owns an interval of the line \([0, \text{total})\) whose length is its priority. Both operations then cost \(O(\log N)\):

  • Sample: draw \(u \sim U(0, \text{total})\) and descend from the root. If \(u\) is less than the left child's sum, go left; otherwise subtract the left sum from \(u\) and go right. The leaf you reach is drawn with probability exactly \(p_i^\alpha/\text{total}\).
  • Update: set the leaf, then recompute each ancestor's sum on the way up to the root.
import numpy as np

class SumTree:
    """Leaves hold priorities p_i^alpha; each internal node holds the sum of its two children."""
    def __init__(self, capacity):
        self.n = 1
        while self.n < capacity:                    # round up to a power of two: a complete tree
            self.n *= 2
        self.tree = np.zeros(2 * self.n)             # node 1 is the root; leaves live at [n, 2n)

    def total(self):
        return self.tree[1]

    def get(self, idx):
        return self.tree[idx + self.n]

    def update(self, idx, value):                    # O(log N): set the leaf, then fix each ancestor
        i = idx + self.n
        self.tree[i] = value
        i //= 2
        while i >= 1:
            self.tree[i] = self.tree[2 * i] + self.tree[2 * i + 1]
            i //= 2

    def find(self, u):                               # O(log N): the leaf whose interval contains u
        i = 1
        while i < self.n:
            left = 2 * i
            if u < self.tree[left]:
                i = left
            else:
                u -= self.tree[left]
                i = left + 1
        return i - self.n

Recomputing each ancestor from its children, rather than adding a difference, keeps floating-point drift from accumulating over millions of updates. Keep the tree in float64.

Importance-sampling weights to correct the bias

Prioritized sampling changes the distribution the expected update is taken under, and therefore the solution the estimates converge to. The fix is the importance sampling of Day 39, applied to the choice of transition.

Derivation · IS weights for prioritized replay

Uniform replay's expected update is \(\bar g = \tfrac1N \sum_i g_i\) with \(g_i = \delta_i \nabla_\theta \hat q(s_i, a_i)\). Under prioritized sampling, weight each sample by \(w_i = \big(\tfrac{1}{N}\cdot\tfrac{1}{P(i)}\big)^\beta = \big(N P(i)\big)^{-\beta}\). With \(\beta = 1\),

$$\E_{i \sim P}\big[w_i\, g_i\big] = \sum_i P(i)\,\frac{1}{N P(i)}\, g_i = \frac1N \sum_i g_i = \bar g,$$

so the correction is exact. With \(\beta < 1\) the expected update is \(\propto \sum_i P(i)^{1 - \beta} g_i\), the update you would get from sampling with exponent \(\alpha(1 - \beta)\) and no weights: \(\beta\) slides the effective prioritization from \(\alpha\) down to uniform. For stability the weights are divided by their maximum, \(w_i \leftarrow w_i / \max_j w_j\), so they only ever scale updates down; that changes the effective step size but not the direction of the expected update.

Without the weights, and with \(\alpha = 1\), the expected update is \(\propto \sum_i |\delta_i|\,\delta_i \nabla_\theta \hat q_i\), the gradient of \(\tfrac13\sum_i |\delta_i|^3\) under uniform sampling (treating priorities as fixed). Uncorrected PER behaves like replacing the squared loss with a cubic one, which weights outliers even more heavily (Fujimoto et al. 2020 develop this equivalence).

The weights also help with a second issue. High-priority transitions have the smallest weights, so the large-error samples that are replayed most often take the smallest steps. With a nonlinear network, whose first-order approximation is valid only for small steps, that is a reasonable side effect. In code, the weights multiply the per-sample loss (Huber or MSE) before averaging. Implementations normalize by the batch maximum, as here, or by the buffer-wide maximum, which needs the minimum priority and so a second, min-tree.

Annealing β

Exact correction matters most at the end of training, when the estimates are supposed to settle at the uniform-replay solution. Early on, the targets and the policy are changing so fast that the small bias from prioritization is irrelevant next to the non-stationarity, and the speed-up is worth more. So \(\beta\) is annealed linearly from \(\beta_0\) to 1 over training: \(\beta_t = \beta_0 + (1 - \beta_0)\min(1, t/T)\). Leaving \(\beta\) at \(\beta_0\) gives a permanently biased agent; setting \(\beta = 1\) from the start gives up some of the early speed-up.

Implementation walkthrough

Algorithm · Double DQN with proportional prioritization (after Schaul et al. 2016)
  1. On insert: store the transition at the write pointer and set its leaf to \(\max_i p_i^\alpha\) seen so far.
  2. On sample: split \([0, \text{total})\) into \(B\) equal segments and draw one \(u\) per segment (stratified: lower variance than \(B\) independent draws); descend the tree for each.
  3. Compute \(P(i)\), the weights \(w_i = (N P(i))^{-\beta}\), and normalize by the maximum.
  4. Compute Double DQN targets and the per-sample loss; minimize \(\tfrac1B \sum_i w_i\,\ell(\delta_i)\).
  5. Write the new \(|\delta_i|\) back: leaf \(i \leftarrow (|\delta_i| + \epsilon)^\alpha\), and update the running maximum.
  6. Anneal \(\beta\) towards 1.

        p = (np.abs(td_errors) + self.eps) ** self.alpha
        for i, pi in zip(idx, p):
            self.tree.update(int(i), pi)
        self.max_p = max(self.max_p, float(p.max()))

What breaks
  • Forgetting the IS weights, or leaving \(\beta\) fixed below 1: a biased solution, and in effect a heavier-tailed loss.
  • Index mix-ups between data slots and tree leaves, especially after wraparound: the priority you update must belong to the transition you replayed.
  • New transitions at priority 0, or \(\epsilon = 0\): they are never sampled.
  • Sampling an empty leaf because round-off pushed \(u\) past the last real priority, giving \(P = 0\) and an infinite weight.
  • More instability. Stronger prioritization makes soft divergence more frequent (van Hasselt et al. 2018); if Q-values start running away, lower \(\alpha\) or the step size.
  • A slow pure-Python tree that silently becomes the training bottleneck at 1M transitions. Profile it.

Multi-Step Returns & Noisy Nets

40m video90m practice

Two cheap changes. Bootstrap after \(n\) real rewards instead of one, which propagates credit faster at the price of a small off-policy bias that nearly everyone ignores; and replace ε-greedy dithering with learned noise in the network's weights, which makes exploration depend on the state.

n-step targets in the deep off-policy setting

The tabular n-step return of Day 48 carries over directly. For a transition starting at \(t\),

$$G_t^{(n)} = \sum_{k=0}^{n-1} \gamma^k R_{t+k+1} + \gamma^n \max_{a'} \hat q(S_{t+n}, a'; \theta^-),$$

and the loss regresses \(\hat q(S_t, A_t; \theta)\) onto it. If the episode ends at step \(t + m\) with \(m \le n\), the sum stops at \(m\) rewards. On termination there is no bootstrap; on truncation you bootstrap from the final observation with weight \(\gamma^m\). Two things improve. A reward now reaches \(n\) steps back per update instead of one, so in the exact-fit picture of Day 73 each target period performs an n-step backup, whose operator contracts at rate \(\gamma^n\) rather than \(\gamma\). And the error in the bootstrapped estimate, which early in training is large, is discounted by \(\gamma^n\).

The simplest implementation builds n-step transitions before they enter the buffer, from a sliding window of the last \(n\) one-step transitions, and stores the discount to apply at the bootstrap alongside each one:

from collections import deque

class NStep:
    """Turns 1-step transitions into n-step ones before they enter the replay buffer."""
    def __init__(self, n, gamma):
        self.n, self.gamma, self.window = n, gamma, deque()

    def push(self, s, a, r, s2, terminated, truncated):
        self.window.append((s, a, r))
        out = []
        if len(self.window) == self.n:                 # full window: emit the oldest transition
            out.append(self._emit(s2, terminated))
            self.window.popleft()
        if terminated or truncated:                    # episode over: flush the shorter tails too
            while self.window:
                out.append(self._emit(s2, terminated))
                self.window.popleft()
        return out                                     # list of (s, a, R, s_boot, terminated, gamma^m)

    def _emit(self, s_boot, terminated):
        R = sum(self.gamma ** k * r for k, (_, _, r) in enumerate(self.window))
        s, a, _ = self.window[0]
        return s, a, R, s_boot, terminated, self.gamma ** len(self.window)

#   y = R + gamma_m * (1 - terminated) * q_target(s_boot)[argmax_a q(s_boot)]

At a truncation the tails are flushed with terminated = False, so they still bootstrap from the true final observation. Storing gamma instead of gamma ** m is a classic bug.

The (usually ignored) off-policy correction

One-step Q-learning needs no correction for replayed data (Day 72). An n-step return does: the rewards \(R_{t+2}, \dots, R_{t+n}\) were earned by the behaviour policy's actions \(A_{t+1}, \dots, A_{t+n-1}\), not the greedy ones the target policy would have taken.

Derivation · the bias of an uncorrected two-step return

Let \(x(s', a') = r(s', a') + \gamma\,\E\big[\max_{a''} \hat q(S'', a''; \theta^-)\big]\), the one-step backup at \((s', a')\). The correct two-step target for \(q_*\) maximizes over the middle action; the uncorrected return averages over the behaviour policy \(\mu\):

$$\E\big[G^{(2)}_t \mid s, a\big] = r(s, a) + \gamma\,\E_{s'}\Big[\textstyle\sum_{a'} \mu(a' \mid s')\, x(s', a')\Big] \quad\text{vs}\quad r(s, a) + \gamma\,\E_{s'}\big[\max_{a'} x(s', a')\big].$$

If \(\mu\) is ε-greedy and its greedy action is also the argmax of \(x\), then \(\sum_{a'} \mu(a' \mid s')\,x(s', a') = \max_{a'} x - \varepsilon\big(\max_{a'} x - \tfrac{1}{|\mathcal A|}\sum_{a'} x\big)\). The bias is downward, of size about \(\varepsilon\) times the gap between the best and the average action, for each intermediate step. If the old policy's greedy action differs from the current one, the bias grows.

Exact corrections exist. Per-decision importance sampling with ratios \(\pi(a \mid s)/\mu(a \mid s)\) (Sutton & Barto §7.3) is zero whenever the behaviour action was not greedy, so it cuts the return at the first exploratory action; so do Watkins's Q(λ) and Tree Backup (Day 49, Day 52). Retrace(λ) (Munos et al. 2016) uses truncated traces \(c = \lambda\min(1, \pi/\mu)\) and is both safe and efficient. All of them need \(\mu(a \mid s)\) stored with each transition, and all of them shorten the effective return, which removes much of the benefit early in training when exploration is frequent. Rainbow, Ape-X and most DQN-family agents simply ignore the problem. That works because \(n\) is small, ε is small after the first few million frames, and the downward bias partly offsets the max's upward bias. Hernandez-Garcia & Sutton (2019) studied the uncorrected target systematically and found it works well in practice for small \(n\).

NoisyNet layers with learnable noise

Definition · noisy linear layer (Fortunato et al. 2018)

A linear layer with \(p\) inputs and \(q\) outputs becomes

$$y = \big(\mu^w + \sigma^w \odot \varepsilon^w\big)\,x + \mu^b + \sigma^b \odot \varepsilon^b,$$

where \(\mu^w, \sigma^w \in \R^{q \times p}\) and \(\mu^b, \sigma^b \in \R^q\) are learned and \(\varepsilon^w, \varepsilon^b\) are zero-mean noise, resampled regularly. The agent acts greedily with respect to the noisy network, \(A_t = \argmax_a \hat q(S_t, a; \mu + \sigma \odot \varepsilon)\), and ε-greedy is switched off.

Training minimizes the expected loss over the noise, \(\bar L(\mu, \sigma) = \E_\varepsilon\big[L(\mu + \sigma \odot \varepsilon)\big]\), by sampling: one draw per training step for the online network, and an independent draw for the target network. Gradients reach both \(\mu\) and \(\sigma\) through the reparameterization \(w = \mu + \sigma \odot \varepsilon\): \(\nabla_\mu \bar L = \E[\nabla_w L]\) and \(\nabla_\sigma \bar L = \E[\varepsilon \odot \nabla_w L]\).

Derivation · what drives σ

For a single weight with unit-variance noise, a second-order expansion gives \(\E_\varepsilon[L(\mu + \sigma\varepsilon)] \approx L(\mu) + \tfrac12 \sigma^2\, \partial^2 L/\partial w^2\), so \(\partial \bar L/\partial \sigma \approx \sigma\, \partial^2 L/\partial w^2\). Gradient descent shrinks \(\sigma\) in proportion to the loss's curvature in that weight: noise is removed where it hurts the fit and left where it does not. Nothing in the objective rewards exploration directly. The noise level is set by the TD loss, weight by weight, instead of by a hand-written schedule, and in practice it changes over training and differs between games.

State-dependent exploration replacing ε-greedy

ε-greedy perturbs actions independently of the state and of what the agent knows, one step at a time. The probability of a specific \(k\)-step exploratory detour falls like \(\varepsilon^k\), which is why ε-greedy explores deep environments so poorly. Parameter noise behaves differently in two ways:

  • It depends on the state. The perturbation of \(\hat q(s, \cdot)\) is \(\sum_i (\sigma \odot \varepsilon)_{\cdot i}\, x_i(s)\), so it is large in states whose features feed into high-σ weights and small elsewhere.
  • It is coherent. One noise sample defines a whole perturbed greedy policy. If the sample is held for several steps, the agent commits to a consistent alternative behaviour rather than jittering, much like the parameter-space noise of Plappert et al. (2018).

This is a heuristic, not a posterior: the learned \(\sigma\) is not an uncertainty estimate in any Bayesian sense, unlike the posterior-sampling methods of Day 105. NoisyNet nevertheless improved DQN, Dueling and A3C on many Atari games, and Rainbow uses it in place of ε-greedy.

Factorized Gaussian noise

Independent noise needs \(pq + q\) Gaussian samples per layer per draw, about 1.6M for the 3136 → 512 layer. Factorized noise needs \(p + q\): sample \(\varepsilon_i\) for each input and \(\varepsilon_j\) for each output, and set

$$\varepsilon^w_{j, i} = f(\varepsilon_i)\, f(\varepsilon_j), \qquad \varepsilon^b_j = f(\varepsilon_j), \qquad f(x) = \operatorname{sign}(x)\sqrt{|x|}.$$

The square root keeps the product of two noise variables on the scale of one: each \(f(\varepsilon)\) has variance \(\E|\varepsilon| = \sqrt{2/\pi}\), so each weight's noise has variance \(2/\pi\) rather than the heavy-tailed, sharply peaked distribution of a raw product. Initialization for factorized layers: \(\mu \sim U[-1/\sqrt p, 1/\sqrt p]\) and \(\sigma = \sigma_0/\sqrt p\) with \(\sigma_0 = 0.5\). Independent layers, which Fortunato et al. used for A3C, start with \(\mu \sim U[-\sqrt{3/p}, \sqrt{3/p}]\) and \(\sigma = 0.017\).

import math
import torch
import torch.nn as nn
import torch.nn.functional as F

class NoisyLinear(nn.Module):
    """Factorized Gaussian NoisyNet layer (Fortunato et al. 2018)."""
    def __init__(self, p, q, sigma0=0.5):
        super().__init__()
        self.p, self.q = p, q
        bound = 1 / math.sqrt(p)
        self.mu_w = nn.Parameter(torch.empty(q, p).uniform_(-bound, bound))
        self.mu_b = nn.Parameter(torch.empty(q).uniform_(-bound, bound))
        self.sigma_w = nn.Parameter(torch.full((q, p), sigma0 * bound))
        self.sigma_b = nn.Parameter(torch.full((q,), sigma0 * bound))
        self.register_buffer("eps_in", torch.zeros(p))
        self.register_buffer("eps_out", torch.zeros(q))
        self.reset_noise()

    @staticmethod
    def f(x):
        return x.sign() * x.abs().sqrt()

    def reset_noise(self):                            # call once per acting step and per training step
        self.eps_in.copy_(self.f(torch.randn(self.p, device=self.eps_in.device)))
        self.eps_out.copy_(self.f(torch.randn(self.q, device=self.eps_out.device)))

    def forward(self, x):
        w = self.mu_w + self.sigma_w * torch.outer(self.eps_out, self.eps_in)   # p + q draws, not p * q
        b = self.mu_b + self.sigma_b * self.eps_out
        return F.linear(x, w, b)

What breaks
  • Never resampling the noise. The agent then acts with one fixed random perturbation, which is a different network, not exploration.
  • Sharing one noise sample between online selection and target evaluation, which reintroduces the coupling Double DQN removes.
  • Leaving ε-greedy on on top of NoisyNet, which double-counts exploration and hides what the noise is doing.
  • n-step bookkeeping errors: bootstrapping past a termination inside the window, dropping the last \(n - 1\) transitions of every episode, storing \(\gamma\) instead of \(\gamma^m\), or treating truncation as termination.
  • Large n with large ε, where the uncorrected bias dominates; the return then estimates the behaviour policy's value, not the greedy one's.

Distributional RL — C51

50m video105m practice

Learn the whole distribution of the return, not only its mean: put probability on a fixed grid of 51 return values, apply the Bellman update to the grid, project the result back onto it, and train with cross-entropy. The agent still acts on the mean, and it still learns better.

Modeling Z(s, a) instead of its mean

Definition · return distribution

\(Z^\pi(s, a)\) is the random return \(G_t\) obtained by starting in \(s\), taking \(a\), then following \(\pi\). Its mean is the action value, \(q^\pi(s, a) = \E[Z^\pi(s, a)]\). It satisfies the distributional Bellman equation

$$Z^\pi(s, a) \overset{D}{=} R(s, a) + \gamma\, Z^\pi(S', A'), \qquad S' \sim p(\cdot \mid s, a),\ A' \sim \pi(\cdot \mid S'),$$

where \(\overset{D}{=}\) means equality in distribution: both sides are random variables with the same law.

An action that pays 10 with probability 0.1 and 0 otherwise has the same Q-value as one that pays 1 for sure, but the two return distributions have nothing in common. Return distributions are routinely multimodal, because of stochastic transitions (did the enemy fire or not), state aliasing (two different situations that look the same in four frames), and the policy's own randomness. A scalar Q-head regressed with squared error has to represent the average of those modes, a value that is never actually observed.

The distributional Bellman operator

Define \((\mathcal T^\pi Z)(s, a) \overset{D}{=} R(s, a) + \gamma\, Z(S', A')\). To talk about convergence you need a distance between distributions. For the \(p\)-Wasserstein metric \(W_p\), and its maximal form \(\bar d_p(Z_1, Z_2) = \sup_{s, a} W_p\big(Z_1(s, a), Z_2(s, a)\big)\):

Theorem · Bellemare, Dabney & Munos 2017

\(\mathcal T^\pi\) is a \(\gamma\)-contraction in \(\bar d_p\), so repeated application converges to \(Z^\pi\). The control operator, which uses \(A' = \argmax_{a'} \E[Z(S', a')]\), is not a contraction in any metric: the means converge as in ordinary Q-learning, but the distributions themselves need not converge.

Proof sketch (evaluation case)

Shifting two random variables by the same reward leaves their Wasserstein distance unchanged, and scaling both by \(\gamma\) multiplies it by \(\gamma\): \(W_p(r + \gamma X, r + \gamma Y) = \gamma\, W_p(X, Y)\). Mixing over the next state and action is a weighted average of such distances, which cannot exceed the worst case \(\bar d_p(Z_1, Z_2)\). Hence \(\bar d_p(\mathcal T^\pi Z_1, \mathcal T^\pi Z_2) \le \gamma\, \bar d_p(Z_1, Z_2)\).

The same paper shows why you cannot simply minimize \(W_p\) by SGD: its gradient estimated from sampled transitions is biased. C51 therefore takes another route, with a fixed categorical support, a projection, and a KL loss. QR-DQN (Day 80) takes a third, quantile regression.

The categorical representation with 51 atoms

Definition · categorical return distribution

Fix a support of \(N\) atoms \(z_i = V_{\min} + i\,\Delta z\), \(i = 0, \dots, N - 1\), with \(\Delta z = (V_{\max} - V_{\min})/(N - 1)\). The network outputs \(N\) logits per action, \(\theta_i(s, a)\), and the probabilities are a softmax over atoms:

$$p_i(s, a) = \frac{e^{\theta_i(s, a)}}{\sum_j e^{\theta_j(s, a)}}, \qquad \hat q(s, a) = \sum_{i} z_i\, p_i(s, a).$$

C51 uses \(N = 51\), \(V_{\min} = -10\), \(V_{\max} = 10\), so \(\Delta z = 0.4\). The authors tried 5, 11, 21 and 51 atoms; 51 performed best, which gave the algorithm its name. The range is a design choice that leans on reward clipping: with \(\gamma = 0.99\) the theoretical bound is \(\pm 100\), but clipped Atari returns mostly lie well inside \(\pm 10\), and any mass outside the range is clipped onto the edge atoms. The network is the Nature CNN with an output layer of size \(|\mathcal A| \cdot N\), reshaped to \([B, |\mathcal A|, N]\). Actions are still chosen greedily on \(\hat q\).

The projection step Φ

Apply the sample Bellman update to the target network's distribution at \((s', a^*)\), with \(a^* = \argmax_a \hat q(s', a; \theta^-)\) (or the online network's argmax, Double-style): atom \(z_j\) with probability \(p_j(s', a^*)\) moves to

$$\hat{\mathcal T} z_j = r + \gamma\,(1 - \text{term})\, z_j.$$

The moved atoms are shifted and squeezed, so they no longer sit on the grid, and the prediction and the target have different supports. A KL divergence between them would be infinite. The projection \(\Phi\) splits each moved atom's mass between its two nearest grid atoms, in proportion to closeness:

$$\big(\Phi \hat{\mathcal T} Z_{\theta^-}(s, a)\big)_i = \sum_{j=0}^{N-1} \left[1 - \frac{\big|[\hat{\mathcal T} z_j]_{V_{\min}}^{V_{\max}} - z_i\big|}{\Delta z}\right]_0^1 p_j(s', a^*),$$

where \([\cdot]_a^b\) clips to \([a, b]\).

Derivation · Φ as an index computation, and what it preserves

Let \(b_j = \big([\hat{\mathcal T} z_j]_{V_{\min}}^{V_{\max}} - V_{\min}\big)/\Delta z \in [0, N - 1]\), with \(l = \lfloor b_j \rfloor\) and \(u = \lceil b_j \rceil\). The formula above gives atom \(l\) the mass \(p_j\,(u - b_j)\) and atom \(u\) the mass \(p_j\,(b_j - l)\).

  • Mass: when \(l \ne u\), the two shares sum to \(p_j\). When \(b_j\) is an integer, \(l = u\) and both expressions are 0, so an implementation must give the whole \(p_j\) to that atom. This case is common: a terminal transition with \(r = 0\) lands exactly on the atom at 0.
  • Mean: \(z_l(u - b_j) + z_u(b_j - l) = V_{\min} + \Delta z\,[\,l(u - b_j) + u(b_j - l)\,] = V_{\min} + \Delta z\, b_j\), using \(u - l = 1\). That is \(\hat{\mathcal T} z_j\) itself, so without clipping \(\sum_i z_i m_i = r + \gamma(1 - \text{term})\,\hat q(s', a^*; \theta^-)\). The projected target's mean is exactly the DQN target.
  • Terminal transitions: every \(\hat{\mathcal T} z_j\) equals \(r\), so all the mass collapses onto the one or two atoms around \(r\).

Rowland et al. (2018) show that \(\Phi\) is the orthogonal projection onto the categorical distributions in the Cramér distance, and that \(\Phi\mathcal T^\pi\) is a \(\sqrt\gamma\)-contraction in its maximal form, so categorical policy evaluation converges.

import torch
import torch.nn as nn

def project(next_probs, rewards, terminated, gamma, z):
    """C51's projection Phi. next_probs: [B, N] at (s', a*); rewards, terminated: [B]; z: [N] support."""
    B, N = next_probs.shape
    v_min, v_max = z[0].item(), z[-1].item()
    dz = (v_max - v_min) / (N - 1)
    tz = (rewards[:, None] + gamma * (1.0 - terminated[:, None]) * z[None, :]).clamp(v_min, v_max)
    b = (tz - v_min) / dz                                  # fractional atom index in [0, N-1]
    l, u = b.floor().long(), b.ceil().long()
    l[(u > 0) & (l == u)] -= 1                             # b exactly on an atom: separate l and u
    u[(l < N - 1) & (l == u)] += 1                         # so the whole mass still lands on it
    m = torch.zeros(B, N, device=next_probs.device)
    m.scatter_add_(1, l, next_probs * (u.float() - b))    # share to the lower neighbour
    m.scatter_add_(1, u, next_probs * (b - l.float()))    # and to the upper one
    return m

                                 nn.Linear(hidden, hidden), nn.ReLU(),
                                 nn.Linear(hidden, n_actions * n_atoms))

    def forward(self, x):
        return self.net(x).view(-1, self.n_actions, self.n_atoms)

The cross-entropy loss

With the target \(m = \Phi\hat{\mathcal T} Z_{\theta^-}(s, a)\) on the same support as the prediction, the natural loss is the KL divergence:

$$\KL\big(m \,\|\, p(s, a; \theta)\big) = \sum_i m_i \log \frac{m_i}{p_i(s, a; \theta)} = \underbrace{\sum_i m_i \log m_i}_{\text{constant in } \theta} - \sum_i m_i \log p_i(s, a; \theta).$$

Minimizing it is minimizing the cross-entropy \(-\sum_i m_i \log p_i\). Its gradient with respect to the logits is \(p_i - m_i\), each entry in \([-1, 1]\), whatever the scale of the rewards: the loss behaves like classification, not like regression on an unbounded target. Compute it with log_softmax, never log(softmax(·)), which produces \(-\infty\) once a probability underflows. With prioritized replay, the per-sample KL (or cross-entropy) replaces \(|\delta|\) as the priority, which is what Rainbow does.

Why it helps even when you only act on the mean

C51 beat DQN and Double DQN by a wide margin across the 57 Atari games and set the state of the art in 2017. Yet its policy is greedy on the mean, as in DQN, and the derivation above shows the mean of its target equals the DQN target. Why should predicting more of the distribution produce a better mean? The honest answer is that this is not fully settled. The main hypotheses:

  • A richer learning signal. Each transition supplies \(N\) targets instead of one, which shapes the shared representation the way an auxiliary task does.
  • A better-behaved loss. Bounded, scale-free gradients from a classification-style objective. Farebrother et al. (2024) found that training value functions with classification losses scales better than regression even when the target is a scalar.
  • Multimodality is kept, not averaged. The network never has to output a value that lies between modes and is never observed, which may make targets less noisy under aliasing.

One result constrains the explanation. Lyle, Castro & Bellemare (2019) showed that in the tabular setting, and with linear function approximation, categorical distributional updates give the same expected values as ordinary expected updates (and can be worse with linear features). The benefit therefore comes from the interaction with deep, nonlinear function approximation, not from the distributional Bellman operator itself.

What breaks
  • Losing mass when \(b\) is an integer. Every terminal transition with \(r = 0\) hits the atom at 0 exactly, so without the fix the target sums to less than 1 for a large share of the batch.
  • A support that does not match the returns. Too narrow and mass piles up on the edge atoms, capping every Q-value; too wide and the resolution is wasted on returns that never happen. Derive it from the reward scale and \(\gamma\): CartPole's discounted returns lie in \([0, 100]\).
  • Softmax over the wrong axis (actions instead of atoms), or the dueling aggregation applied after the softmax.
  • Choosing \(a^*\) by the largest logit rather than the largest mean.
  • Gradients through the projection. The target block belongs under no_grad, like every target in this module.

DAY 80

QR-DQN, IQN & Rainbow

45m video90m practice

C51 fixes where probability mass may sit and learns how much goes where. Quantile regression does the reverse: it fixes the probabilities and learns the locations, which removes both the projection and the value range. IQN takes the idea to its limit by learning the whole quantile function. Rainbow then shows that the extensions of this module largely add up.

Quantile regression as an alternative representation

Definition · quantile representation (QR-DQN)

Represent \(Z(s, a)\) by \(N\) equally weighted Diracs at learned locations:

$$Z_\theta(s, a) = \frac1N \sum_{i=1}^N \delta_{\theta_i(s, a)}, \qquad \hat q(s, a) = \frac1N \sum_{i=1}^N \theta_i(s, a).$$

The network outputs \(|\mathcal A| \times N\) real numbers, with no softmax. Location \(\theta_i\) is trained to be the quantile of the return distribution at the midpoint fraction \(\hat\tau_i = \frac{2i - 1}{2N}\).

Why midpoints? Among all distributions made of \(N\) Diracs of weight \(1/N\), the one closest to a target distribution with CDF \(F\) in the 1-Wasserstein distance places its atoms at \(F^{-1}(\hat\tau_i)\) (Dabney et al. 2018, Lemma 2). And the Bellman update keeps you inside the representation: \(r + \gamma\,\theta_j(s', a^*)\) is again a set of \(N\) equally weighted Diracs, wherever they land. No projection onto a grid, no \(V_{\min}\) or \(V_{\max}\) to choose, and the support adapts to the returns, which matters as soon as rewards are not clipped. The quantile-projected evaluation operator is a \(\gamma\)-contraction in the maximal \(\infty\)-Wasserstein metric, so the distributional theory of Day 79 carries over.

The quantile Huber loss

Derivation · quantile regression finds quantiles from samples

For \(\tau \in (0, 1)\) define the pinball loss \(\rho_\tau(u) = u\,\big(\tau - \mathbb 1\{u < 0\}\big)\). For a random \(Z\) with CDF \(F\),

$$\frac{d}{d\theta}\,\E\big[\rho_\tau(Z - \theta)\big] = \frac{d}{d\theta}\Big[\int_{z < \theta} (\tau - 1)(z - \theta)\,dF(z) + \int_{z \ge \theta} \tau (z - \theta)\,dF(z)\Big] = F(\theta) - \tau,$$

which is zero exactly at \(\theta = F^{-1}(\tau)\). The per-sample gradient \(-(\tau - \mathbb 1\{z < \theta\})\) has this expectation, so it is unbiased. This is the property the Wasserstein loss lacks (Day 79), and it is why quantile regression can be trained by SGD on sampled targets.

The pinball loss has a kink at zero, and its gradient keeps magnitude \(\tau\) or \(1 - \tau\) all the way down to \(u = 0\), which deep networks optimize poorly. QR-DQN smooths it with the Huber loss of Day 73:

$$\rho^\kappa_\tau(u) = \big|\tau - \mathbb 1\{u < 0\}\big|\;\frac{L_\kappa(u)}{\kappa}, \qquad \mathcal L = \frac{1}{N'}\sum_{j=1}^{N'} \sum_{i=1}^{N} \rho^\kappa_{\hat\tau_i}\big(\mathcal T\theta_j - \theta_i(s, a)\big),$$

with target samples \(\mathcal T\theta_j = r + \gamma\,(1 - \text{term})\,\theta_j(s', a^*; \theta^-)\) and \(a^* = \argmax_a \frac1N \sum_j \theta_j(s', a; \theta^-)\). Every predicted quantile is regressed against every target sample, an \(N \times N'\) matrix of pairwise TD errors per transition. As \(\kappa \to 0\) the loss recovers the pinball loss; QR-DQN uses \(\kappa = 1\) and \(N = 200\) quantiles on Atari, and outperformed C51.

import torch

def quantile_huber_loss(pred, target, kappa=1.0):
    """pred: [B, N] quantiles theta_i(s, a); target: [B, N'] samples r + gamma * theta_j(s', a*), no grad."""
    N = pred.shape[1]
    tau = (torch.arange(N, device=pred.device, dtype=torch.float32) + 0.5) / N   # (2i - 1) / 2N
    u = target[:, None, :] - pred[:, :, None]                                     # [B, N, N'] pairwise errors
    huber = torch.where(u.abs() <= kappa, 0.5 * u ** 2, kappa * (u.abs() - 0.5 * kappa))
    weight = (tau[None, :, None] - (u.detach() < 0).float()).abs()               # |tau - 1{u < 0}|
    return (weight * huber / kappa).sum(dim=1).mean(dim=1).mean()                # sum over i, mean over j

# QR-DQN step (q, q_target output [B, |A|, N] quantile values; s, a, r, s2, d from the buffer)
B = s.shape[0]
with torch.no_grad():
    next_q = q_target(s2)
    a_star = next_q.mean(dim=2).argmax(dim=1)                                    # greedy on the mean
    target = r[:, None] + gamma * (1.0 - d[:, None]) * next_q[torch.arange(B), a_star]
loss = quantile_huber_loss(q(s)[torch.arange(B), a], target)

The broadcast puts predictions on axis 1 and targets on axis 2. Swapping them, so that the τ weights attach to the targets, is the most common QR-DQN bug, and it still trains, just to the wrong quantiles.

Implicit quantile networks and risk-sensitive policies

QR-DQN learns \(N\) fixed quantiles. IQN (Dabney, Ostrovski, Silver & Munos 2018) learns the whole quantile function: it takes a fraction \(\tau \in [0, 1]\) as an extra input and outputs \(Z_\tau(s, a) \approx F^{-1}_{Z(s, a)}(\tau)\) for every action. The fraction is embedded with cosine features and merged with the state features by an elementwise product:

$$\phi_j(\tau) = \operatorname{ReLU}\Big(\sum_{i=0}^{n-1} \cos(\pi i \tau)\, w_{ij} + b_j\Big), \qquad Z_\tau(s, a) = f\big(\psi(s) \odot \phi(\tau)\big)_a,$$

with \(n = 64\) cosines, \(\psi\) the convolutional torso and \(f\) the fully connected head. Training samples fractions \(\tau_i \sim U[0, 1]\) for the prediction and \(\tau'_j \sim U[0, 1]\) for the target and applies the quantile Huber loss to all pairs, \(\rho^\kappa_{\tau_i}\big(r + \gamma Z_{\tau'_j}(s', a^*) - Z_{\tau_i}(s, a)\big)\). The paper used 64 samples on each side of the loss and 32 for acting. Because the network can be queried at any \(\tau\), the policy can be computed from any functional of the return distribution, not only the mean.

Definition · distortion risk measures

Choose a distortion \(\beta : [0, 1] \to [0, 1]\) and act greedily on

$$Q_\beta(s, a) = \E_{\tau \sim U[0, 1]}\big[Z_{\beta(\tau)}(s, a)\big] \approx \frac1K \sum_{k=1}^K Z_{\beta(\tilde\tau_k)}(s, a).$$

\(\beta(\tau) = \tau\) is risk-neutral (the mean). \(\beta(\tau) = \eta\tau\) gives \(\operatorname{CVaR}_\eta\), the mean of the worst \(\eta\)-fraction of outcomes, since \(\operatorname{CVaR}_\eta(Z) = \tfrac1\eta \int_0^\eta F^{-1}(\tau)\,d\tau = \E_{u \sim U}[F^{-1}(\eta u)]\). This is risk-averse. Other distortions studied in the paper include cumulative probability weighting from prospect theory, Wang's transform, and a power law.

On Atari, several risk-averse distortions did as well as the risk-neutral policy or better on some games. Risk-sensitive control is a real use case beyond benchmark scores: in safety-critical settings you care about the bad tail, not the mean (Day 122). With little else added to DQN, IQN outperformed QR-DQN and came close to Rainbow's Atari results.

import math
import torch
import torch.nn as nn
import torch.nn.functional as F

class IQNHead(nn.Module):
    """Maps state features psi(s) and fractions tau to quantile values Z_tau(s, a)."""
    def __init__(self, feat_dim, n_actions, n_cos=64, hidden=512):
        super().__init__()
        self.register_buffer("i_pi", math.pi * torch.arange(n_cos, dtype=torch.float32))
        self.phi = nn.Linear(n_cos, feat_dim)
        self.out = nn.Sequential(nn.Linear(feat_dim, hidden), nn.ReLU(), nn.Linear(hidden, n_actions))

    def forward(self, psi, tau):                     # psi: [B, D] state features; tau: [B, K] in (0, 1)
        cos = torch.cos(tau[..., None] * self.i_pi)  # [B, K, n_cos]: cos(pi * i * tau)
        phi = F.relu(self.phi(cos))                  # [B, K, D]
        return self.out(psi[:, None, :] * phi)       # [B, K, |A|]

@torch.no_grad()
def act(head, psi, K=32, eta=1.0):
    """eta = 1: risk-neutral mean. eta < 1: CVaR_eta, the mean of the worst eta-fraction of returns."""
    tau = eta * torch.rand(psi.shape[0], K, device=psi.device)
    return head(psi, tau).mean(dim=1).argmax(dim=1)

Rainbow: combining all six extensions

Hessel et al. (2018) asked whether the extensions are complementary. Rainbow is DQN plus all six: Double Q-learning, prioritized replay, dueling networks, multi-step returns, distributional (C51) learning and noisy nets. Each pair has to be made to fit:

  • Distributional + multi-step: the target distribution is \(R^{(n)}_t + \gamma^n z\) at \(S_{t+n}\), projected with \(\Phi\), and the loss is the KL of Day 79.
  • + Double: \(a^*\) is chosen by the online network's mean at \(S_{t+n}\); its distribution comes from the target network.
  • + PER: the priority is the KL loss rather than \(|\delta|\), which Hessel et al. found more robust to noisy stochastic environments.
  • + Dueling: the value stream outputs \(N\) logits and the advantage stream \(|\mathcal A| \times N\); they are aggregated per atom, \(v_i + a_i(\cdot, a) - \tfrac{1}{|\mathcal A|}\sum_{a'} a_i(\cdot, a')\), and only then soft-maxed over atoms.
  • + Noisy nets: every linear layer of the head is a factorized NoisyLinear, and ε-greedy is off.

Algorithm · one Rainbow update
  1. Sample \(B\) n-step transitions \((s, a, R^{(n)}, s_n, \text{term}, \gamma^m)\) with probability \(\propto p_i^{0.5}\); compute IS weights with the current \(\beta\).
  2. Resample the noise in the online and target networks, independently.
  3. \(a^* = \argmax_{a'} \sum_i z_i\, p_i(s_n, a'; \theta)\). (online network selects)
  4. \(m = \Phi\big(R^{(n)} + \gamma^m (1 - \text{term})\, z,\ p(s_n, a^*; \theta^-)\big)\). (target network evaluates; project)
  5. Loss \(\tfrac1B\sum_b w_b \cdot \big(-\sum_i m_{b,i} \log p_i(s_b, a_b; \theta)\big)\); one Adam step.
  6. Set each sampled transition's priority to its new KL loss; every 32K frames copy \(\theta^- \leftarrow \theta\).

Rainbow beat every individual extension on median human-normalized score across 57 games, and was dramatically more data-efficient, reaching DQN's final performance in a small fraction of DQN's frames. To ask which parts mattered, Hessel et al. removed one component at a time from the full agent:

Reading an ablation

“Rainbow minus X” measures X's marginal value given the other five, with hyperparameters tuned for the full agent. It does not measure what X adds to plain DQN, which is what each component's own paper reported. Components overlap (Double Q and the bounded distributional support both limit overestimation; n-step returns and PER both speed up credit propagation), so their marginal values are smaller than their stand-alone ones. And a median over 57 games hides large per-game swings. Ceron & Castro (2021) repeat the ablation on small environments you can run on a laptop, which is a good way to build intuition before spending Atari-scale compute.

What breaks
  • Comparing Rainbow numbers across protocols: no-op vs sticky actions, best checkpoint vs final, 200M vs 50M frames (Day 74).
  • Quantile loss with the axes swapped, so that the τ weights attach to the targets.
  • Using \(\gamma\) instead of \(\gamma^n\) in the multi-step distributional projection.
  • Dueling after the softmax instead of on the logits.
  • Priorities from \(|\delta|\) of the mean while training the distribution: it works, but it is not Rainbow, so say so.
  • Too few IQN samples: with small \(K\), CVaR estimates of the tail are very noisy and the risk-averse policy jitters.

The deep-RL debugging checklist

Deep RL bugs are quiet. A wrong mask, a missing no_grad or a broken wrapper usually produces an agent that learns something, just worse, and the seed-to-seed noise hides the difference. Train your agent for a few thousand steps on each probe with ε-greedy exploration, then assert that the learned Q-values are within about 0.05 of the table. Put these in your test suite and run them on every change.

1 · Is the loss meaningful?

The TD loss is a regression loss on moving targets (Day 71), so its value is not a progress measure. Healthy: noisy, not monotone, a sawtooth at hard target updates, and often rising as the agent improves, because returns and therefore targets get larger. Red flags:

  • Near zero almost immediately with non-zero rewards: the target is being dragged to the prediction (gradient through the target), \(\gamma = 0\), every transition stored as terminal, or a target network that is the online network.
  • Perfectly flat: the optimizer is not stepping, its parameter list is not the network you call, or zero_grad() runs between backward() and step().
  • NaN or inf: a learning rate that is too large, log(0) in a distributional loss, or an infinite PER weight.
  • Falling steadily while the return is flat: the network is accurately predicting the value of a bad policy. Look at exploration and rewards, not at the optimizer.

Log the loss together with the mean and maximum \(|\delta|\), the gradient norm before clipping, and how often clipping triggers.

2 · Are Q-values exploding?

Log the batch mean and maximum of \(\hat q(s, a)\) and of the targets, and every so often compare them with two references: the analytic bound \(r_{\max}/(1 - \gamma)\) (100 for CartPole and for clipped Atari with \(\gamma = 0.99\)), and the Monte Carlo returns of the current greedy policy (Day 75's overestimation). Healthy Q-values track the Monte Carlo returns with modest overestimation. A steady climb past the bound is soft divergence. In rough order of likelihood: the terminal mask is missing or wrong (all values drift towards \(r/(1 - \gamma)\), even next to failure states); the learning rate is too high; \(C\) is too small, or counted in the wrong units; Double DQN or Huber is missing; rewards are unclipped and large; PER's \(\alpha\) is too high. Q-values that are identical across actions point to an indexing bug or a network that ignores its input.

3 · Is the replay buffer diverse?

Log the action histogram of the buffer, the fraction of terminal transitions, the distribution of episode returns represented in it, a coarse histogram of state coverage (cart position for CartPole; landed vs crashed for LunarLander), and the mean age of sampled transitions. Typical failures: ε decays to its floor before the agent has ever seen a reward, so the buffer fills with near-identical failures; one action makes up almost all the data; learning starts on a few hundred transitions; or the buffer is so small that it holds only the current policy's behaviour. Fixes, in order: a longer ε schedule, a larger replay start size, a larger capacity.

4 · Is the environment wrapper wrong?

Look at exactly what the network receives. Save one stacked observation as images and check the frame order, the dtype (uint8), the range (scaled once), the channel axis, and that flickering sprites are present. Print rewards before and after clipping, and check that the episode statistics wrapper sits inside the clipping so that it logs real scores. Check the frame skip (a v5 environment plus another skip wrapper gives 16 frames per action), life-loss handling, FIRE-on-reset, sticky actions, and that truncated from the time limit is not stored as terminal. Then run a random agent: its score must match the published random baseline for that game (Pong: about −20 to −21). This catches more bugs than any other check on Atari.

General rules
  • Start from a known-good implementation (CleanRL's dqn.py and dqn_atari.py), reproduce its curve, then change one thing at a time.
  • Never conclude anything from one seed (Day 7). Debug on one seed; decide on five or more.
  • Index every plot by environment steps, and log wall-clock time alongside.

The seed-sensitivity study

  1. Run the CartPole baseline with 10 seeds and identical configuration. Plot every seed's curve thinly, plus the mean with a bootstrap 95% band.
  2. Report each seed's final performance (mean episodic return over the last 50k steps), and the mean, median and IQM with bootstrap intervals. Report the fraction of seeds that reach Gymnasium's threshold (475 for CartPole-v1; 200 for LunarLander).
  3. Split the 10 seeds at random into two groups of 5 and run a Welch t-test on final performance. Repeat for 1,000 random splits and report how often \(p < 0.05\), and how large the largest apparent “improvement” is. This is the Henderson et al. (2018) experiment in miniature: two copies of one algorithm can look like two different algorithms.
  4. From the seed standard deviation \(\sigma\), estimate the seeds per arm needed to detect a difference \(\Delta\) at 5% significance and 80% power, \(n \approx 2(z_{0.975} + z_{0.8})^2 \sigma^2/\Delta^2 \approx 15.7\,\sigma^2/\Delta^2\), for \(\Delta\) equal to 10% of the mean. Compare it with the 5 seeds you used for LunarLander.

Expected results, honestly

  • CartPole: most seeds hit the 500-step cap at some point within the first 100k–300k steps, and DQN on CartPole is notoriously unstable afterwards: expect some seeds to fall back and recover repeatedly. Seed-to-seed spread in final performance is large, and the IQM over 10 seeds is a more honest summary than the mean.
  • LunarLander: with these settings most seeds of the baseline cross an average return of 200 within a few hundred thousand steps, while one or two of five may hover or crash for much longer. The differences between variants are typically modest and seed-noisy; with 5 seeds the intervals often overlap. PER most often shows up as faster early learning. Do not expect Atari's rankings to reproduce on an 8-dimensional task.
  • Atari: Pong starts at about −21. A working DQN usually begins winning points within the first one or two million agent steps and approaches the maximum of +21 within a few million. Breakout is slower: tens of points after a few million steps, and a few hundred by 10M steps in CleanRL's reported runs. A 10M-step run takes many hours on one GPU, so start it early and let it run overnight.

If your numbers fall far outside these ranges, run the checklist before concluding anything about the algorithm.
