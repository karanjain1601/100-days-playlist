DAY 1

What Reinforcement Learning Actually Is

30m video30m practice

Reinforcement learning is learning to act from evaluative, delayed feedback. An agent chooses actions, the world answers with a new situation and a single number, and the agent has to work out which of its earlier choices deserve the credit.

The agent–environment loop

Time moves in discrete steps \(t = 0, 1, 2, \dots\). At each step the agent observes a state \(S_t\), picks an action \(A_t\), and the environment responds with a reward \(R_{t+1}\) and a next state \(S_{t+1}\). Interaction produces a trajectory

$$S_0,\ A_0,\ R_1,\ S_1,\ A_1,\ R_2,\ S_2,\ A_2,\ R_3,\ \dots$$

Mind the indexing: the reward caused by \(A_t\) is \(R_{t+1}\), and it arrives together with \(S_{t+1}\). This is the Sutton & Barto convention and the one used throughout the course.

Definition
  • State \(S_t \in \mathcal S\): the information the agent's decision is allowed to depend on.
  • Action \(A_t \in \mathcal A(S_t)\): what the agent does.
  • Reward \(R_{t+1} \in \mathbb R\): a scalar chosen by whoever designed the problem.
  • Policy \(\pi(a \mid s) = \Pr(A_t = a \mid S_t = s)\): the agent's behaviour, and the thing we learn.
  • Return \(G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots\) with discount \(0 \le \gamma \le 1\). The goal is to maximise \(\E_\pi[G_t]\). Day 19 explains the discount properly.

The reward hypothesis

Hypothesis

“All of what we mean by goals and purposes can be well thought of as the maximization of the expected value of the cumulative sum of a received scalar signal (called reward).” (Sutton & Barto, §3.2)

This is a modelling stance, not a theorem. Its strength is a single interface for chess, robot locomotion, data-centre cooling and chat assistants. Its weakness is that you get exactly what you reward. Day 26 (reward hacking) and Days 123–126 (RLHF) are about the gap between the reward you wrote and the behaviour you wanted. Some goals, such as hard safety constraints or risk aversion, don't fit naturally into a single expected sum; Day 122 handles those.

Trial and error, and delayed credit

Two features separate RL from other kinds of learning:

  • Evaluative feedback. The reward says how good the chosen action was, not what the best action would have been. You only learn by trying.
  • Delayed consequences. A chess move is rewarded forty moves later, if at all. The agent must solve temporal credit assignment: which of the many actions before the reward caused it?
Intuition

You win a game of chess (+1) after 40 moves. Monte Carlo methods give every move the same credit, the final outcome (Day 35). Temporal-difference learning credits each move through the value of the position it produced (Day 42). Eligibility traces interpolate between the two (Day 50). Most of Modules 4–5 is different answers to this one question.

Sequential decisions vs one-shot prediction

In supervised learning, a prediction doesn't change the next input. In RL, actions change the data: the states you see tomorrow depend on what you did today. Three consequences follow you through the whole course:

  • The data are not i.i.d. Consecutive states are correlated, and the distribution shifts whenever the policy changes.
  • The agent decides what it gets to learn about. A state it never visits is a state it never learns.
  • Evaluating a policy means running it, or correcting for having run a different one (importance sampling, Day 39).
import random

class Corridor:
    """Five cells, start in the middle, +1 for reaching the right end."""
    def reset(self):
        self.pos = 2
        return self.pos

    def step(self, action):                 # 0 = left, 1 = right
        self.pos += 1 if action == 1 else -1
        done = self.pos in (0, 4)
        reward = 1.0 if self.pos == 4 else 0.0
        return self.pos, reward, done

env, returns = Corridor(), []
for episode in range(1000):
    state, done, G = env.reset(), False, 0.0
    while not done:
        action = random.choice([0, 1])      # the policy: uniformly random
        state, reward, done = env.step(action)
        G += reward
    returns.append(G)
print(sum(returns) / len(returns))          # about 0.5, the chance of exiting right

Every algorithm in this course is a smarter replacement for the line action = ….

What breaks · three day-one mistakes
  • Off-by-one rewards. Storing the reward that came back from step(A_t) as \(R_t\) instead of \(R_{t+1}\) shifts every return by one step. It is invisible on this corridor and wrecks discounted returns later.
  • Observation ≠ state. The corridor's position is a complete description of the situation. A single Atari frame or a pendulum angle is not, and an agent fed one is solving a different, harder problem (Day 27, Day 121).
  • Reward ≠ goal. Reward the agent for “moving right” instead of “reaching the end” and it will learn to oscillate between cells if the environment lets it. The reward is the only specification the agent ever sees.

DAY 2

RL vs Everything Else

35m video30m practice

Supervised learning is told the right answer. Unsupervised learning is told nothing. Reinforcement learning is told how well it did, and only for the actions it actually tried. That last clause is why exploration exists.

Why there are no labels

A label would be “the optimal action in this state”. If you had that, you would already have the optimal policy. Instead you see the reward for the action you took, and the counterfactual (“what if I had gone left?”) is never observed. This is the same missing-data structure as causal inference, and it is called bandit feedback.

Definition · three feedback models

At round \(t\) the learner sees an input \(x_t\) and picks an action \(a_t\) from \(K\) options. What it observes next defines the problem:

  • Supervised: the correct action \(a_t^*\) (equivalently, the loss of every action).
  • Full-information online learning: the loss \(\ell_t(a)\) of every action \(a\), but no “correct” label.
  • Bandit: only \(\ell_t(a_t)\), the loss of the action actually taken.

Full RL is bandit feedback plus state: \(a_t\) also changes the next input \(x_{t+1}\). Regret bounds make the cost of the missing information concrete. Against \(K\) actions, the best achievable worst-case regret over \(T\) rounds grows like \(\sqrt{T \log K}\) with full information but like \(\sqrt{TK}\) with bandit feedback. Module 1 develops regret for the bandit case.

Exploration is the defining difficulty

Because feedback only covers chosen actions, the learner controls its own training data. Act greedily on current estimates and you may never discover a better action, since the estimate for an action you never try never improves. Act randomly and you throw away reward. This exploration–exploitation dilemma has no counterpart in supervised learning. Module 1 isolates it in its simplest form; Module 11 confronts it at scale.

Intuition

You have eaten at restaurant A ten times (average 7/10) and at B once (5/10). Is B worse, or did you catch it on a bad night? Only another meal at B tells you, at the cost of a probably worse dinner. Every exploration strategy in this course is a policy for deciding when that dinner is worth it.

Where imitation learning sits

Imitation learning is given demonstrations: (state, expert action) pairs. That is supervised learning applied to a sequential problem, and the sequential part bites. Small mistakes take the learner into states the expert never visited, where it has no data, so errors compound: the cost gap grows quadratically with the horizon (Day 106). Imitation gives a strong start; RL lets you improve past the demonstrator. AlphaGo and modern LLM post-training do both, in that order.

When RL is the wrong tool

Use something else when…
  • Your actions don't affect future inputs: it's a contextual bandit (Day 17) or plain supervised learning.
  • You have labels for the right action: use supervised learning or imitation.
  • You know the dynamics and can afford to plan: use dynamic programming, search or optimal control (Module 3). RL is what you do when you can't.
  • You can't simulate and real trials are expensive or dangerous: offline RL at best (Module 12), and expect pain.
  • You can't write down a reward that captures what you want: fix that first (Day 26).

RL is sample-hungry, high-variance and fiddly. Reach for it when the sequential, interactive structure genuinely is the problem.

DAY 3

Probability You Genuinely Need

45m video90m practice

Every equation in this course is an expectation. Once you can manipulate conditional expectations, and the law of total expectation in particular, the Bellman equations stop being magic and become one-line consequences of the definitions.

Random variables and distributions

A discrete random variable has a probability mass function \(p(x) = \Pr(X = x)\). A continuous one has a density \(f\) with \(\Pr(a \le X \le b) = \int_a^b f(x)\,dx\). Tabular RL is mostly discrete: finite states and actions, often discrete rewards. Continuous control (Days 93–95) has continuous states and actions, and you will meet densities in policy gradients.

Joint, marginal and conditional

$$p(x, y) = p(y \mid x)\, p(x), \qquad p(y) = \sum_x p(x, y), \qquad p(y \mid x) = \frac{p(x, y)}{p(x)}.$$

The environment is a conditional distribution: \(p(s', r \mid s, a)\), the probability of landing in \(s'\) with reward \(r\) after taking \(a\) in \(s\) (Day 20). Every other quantity is a marginal of it. For example, \(p(s' \mid s, a) = \sum_r p(s', r \mid s, a)\) and \(r(s, a) = \sum_{s', r} r\, p(s', r \mid s, a)\).

Expectation, linearity, variance

Definitions

\(\E[X] = \sum_x x\, p(x)\). Linearity: \(\E[aX + bY] = a\,\E[X] + b\,\E[Y]\), always, even when \(X\) and \(Y\) are dependent.

\(\Var[X] = \E\big[(X - \E X)^2\big] = \E[X^2] - (\E X)^2\),   \(\operatorname{Cov}(X, Y) = \E[XY] - \E X\, \E Y\),   \(\Var[X + Y] = \Var X + \Var Y + 2\operatorname{Cov}(X, Y)\).

Linearity is why the expected return splits into a sum of expected rewards. The covariance term is why baselines reduce variance in policy gradients (Day 85): subtracting something correlated with your estimate cancels part of its noise without changing its mean.

Conditional expectation and the tower rule

Theorem · Law of total expectation

\(\E[X] = \E\big[\E[X \mid Y]\big]\), and more generally \(\E[X \mid Z] = \E\big[\E[X \mid Y, Z] \mid Z\big]\).

Derivation · discrete case $$\E\big[\E[X \mid Y]\big] = \sum_y p(y) \sum_x x\, p(x \mid y) = \sum_x x \sum_y p(x, y) = \sum_x x\, p(x) = \E[X].$$

Why this is the engine of every Bellman equation

Define the value of a state as its expected return, \(v(s) = \E[G_t \mid S_t = s]\). The return obeys \(G_t = R_{t+1} + \gamma G_{t+1}\). Take expectations and condition on the next state:

$$\begin{aligned} v(s) &= \E[R_{t+1} + \gamma G_{t+1} \mid S_t = s] \\ &= \E[R_{t+1} \mid S_t = s] + \gamma\, \E\big[\, \E[G_{t+1} \mid S_{t+1}, S_t = s] \;\big|\; S_t = s \big] \\ &= \E[R_{t+1} + \gamma\, v(S_{t+1}) \mid S_t = s]. \end{aligned}$$

The last step uses the Markov property, \(\E[G_{t+1} \mid S_{t+1}, S_t] = v(S_{t+1})\), which Day 6 makes precise. That is the Bellman expectation equation of Day 23, obtained from nothing but linearity and the tower rule.

Law of large numbers and Monte Carlo estimation

Theorem · LLN and standard error

If \(X_1, \dots, X_n\) are i.i.d. with mean \(\mu\) and variance \(\sigma^2 < \infty\), the sample mean \(\bar X_n = \tfrac1n \sum_i X_i\) converges to \(\mu\), and \(\Var[\bar X_n] = \sigma^2 / n\). The standard error is \(\sigma/\sqrt n\): halving the error costs four times the samples.

Monte Carlo methods (Module 4) estimate \(v(s)\) exactly this way, by averaging the returns observed after visiting \(s\). Their cost is this \(1/\sqrt n\) rate together with the variance of a whole episode's return.

import numpy as np

rng = np.random.default_rng(0)

def episode_return(rng, gamma=0.9):
    """Reward 1 every step; the episode ends with probability 0.2 after each step."""
    G, discount = 0.0, 1.0
    while True:
        G += discount * 1.0
        if rng.random() < 0.2:
            return G
        discount *= gamma

for n in [10, 100, 1_000, 10_000]:
    xs = np.array([episode_return(rng) for _ in range(n)])
    half = 1.96 * xs.std(ddof=1) / np.sqrt(n)
    print(f"n={n:>6}  mean={xs.mean():.3f}  ±{half:.3f}")
# exact: v = 1 + 0.9 * 0.8 * v, so v = 1 / (1 - 0.72) = 3.571...
What breaks · E[max] ≠ max E

Give each of 10 arms an unbiased but noisy estimate. The largest estimate is biased upward: \(\E\big[\max_i \hat Q_i\big] \ge \max_i \E\big[\hat Q_i\big]\), by Jensen's inequality, since max is convex. Q-learning takes a max over noisy estimates at every update, so it inherits this bias. That is maximization bias, and Day 47 fixes it with Double Q-learning.

DAY 4

Linear Algebra & Calculus Toolkit

45m video90m practice

Value functions are vectors and dynamics are matrices. Every convergence proof in Modules 3 and 7 is an argument about how a matrix shrinks vectors, and the two tools that measure the shrinking are the sup norm and the spectral radius.

Value functions are vectors, dynamics are matrices

With \(n\) states, a value function is a vector \(v \in \R^n\). Fix a policy and its dynamics become a row-stochastic matrix \(P^\pi\) with \(P^\pi_{ij} = \Pr(S_{t+1} = j \mid S_t = i)\): non-negative entries, every row summing to 1. Then

$$(P^\pi v)_i = \sum_j P^\pi_{ij}\, v_j = \E[v(S_{t+1}) \mid S_t = i],$$

so a matrix–vector product is a one-step expectation. With \(r^\pi_i\) the expected immediate reward in state \(i\), the Bellman equation from Day 3 becomes a linear system:

$$v^\pi = r^\pi + \gamma P^\pi v^\pi.$$

Eigenvalues and the spectral radius

Definition

\(\lambda\) is an eigenvalue of \(A\) if \(Av = \lambda v\) for some \(v \ne 0\). The spectral radius is \(\rho(A) = \max_i |\lambda_i|\). Key facts: \(A^k \to 0\) if and only if \(\rho(A) < 1\), and in that case the Neumann series converges, \(\sum_{k \ge 0} A^k = (I - A)^{-1}\).

Theorem

For a row-stochastic \(P\), \(\rho(P) = 1\). Hence \(\rho(\gamma P) = \gamma < 1\) for \(\gamma < 1\), the matrix \(I - \gamma P^\pi\) is invertible, and

$$v^\pi = (I - \gamma P^\pi)^{-1} r^\pi = \sum_{k=0}^{\infty} (\gamma P^\pi)^k\, r^\pi.$$
Proof

Suppose \(Pv = \lambda v\) and pick \(i\) maximising \(|v_i|\). Then \(|\lambda|\,|v_i| = \big|\sum_j P_{ij} v_j\big| \le \sum_j P_{ij}\,|v_j| \le |v_i|\), so \(|\lambda| \le 1\). The value \(\lambda = 1\) is attained by \(v = \mathbf 1\), because every row sums to 1.

Read the series term by term: expected reward now, plus \(\gamma\) times the expected reward one step later, plus \(\gamma^2\) times two steps later, and so on. That is the definition of expected discounted return, recovered from linear algebra. Day 25 solves MDPs this way and shows why the \(O(n^3)\) solve stops scaling.

Norms, and why the sup norm matters

Definition

\(\|v\|_1 = \sum_i |v_i|\),   \(\|v\|_2 = \big(\sum_i v_i^2\big)^{1/2}\),   \(\|v\|_\infty = \max_i |v_i|\).

Lemma · stochastic matrices don't expand the sup norm

\(\|Pv\|_\infty \le \|v\|_\infty\). Proof: \(|(Pv)_i| \le \sum_j P_{ij}\,|v_j| \le \max_j |v_j| \sum_j P_{ij} = \|v\|_\infty\).

The consequence is the most important inequality in tabular RL. The Bellman operator \(Tv = r + \gamma P v\) satisfies

$$\|Tv - Tu\|_\infty = \gamma\,\|P(v - u)\|_\infty \le \gamma\,\|v - u\|_\infty,$$

so \(T\) is a \(\gamma\)-contraction. That one line is the convergence proof for policy evaluation and value iteration (Day 32). The same statement is false in the \(L_2\) norm in general, which is part of why function approximation (Module 7) loses these guarantees.

Derivatives, gradients, Jacobians, chain rule

For \(f: \R^d \to \R\), the gradient \(\nabla f(\theta) = (\partial f/\partial\theta_1, \dots, \partial f/\partial\theta_d)\) points in the direction of steepest ascent. For \(g: \R^d \to \R^m\), the Jacobian \(J_g \in \R^{m \times d}\) has entries \(\partial g_i / \partial \theta_j\). The chain rule reads \(\nabla_\theta f(g(\theta)) = J_g(\theta)^\top\, \nabla f(g(\theta))\). Backpropagation (Day 9) is this rule applied mechanically, layer by layer.

Taking a gradient through an expectation

RL objectives look like \(J(\theta) = \E_{x \sim p_\theta}[f(x)]\): the parameters change the distribution of the data, not the function being averaged. There are two ways to differentiate this.

Derivation · score function (log-derivative) trick $$\nabla_\theta\, \E_{x \sim p_\theta}[f(x)] = \sum_x f(x)\, \nabla_\theta p_\theta(x) = \sum_x f(x)\, p_\theta(x)\, \nabla_\theta \log p_\theta(x) = \E_{x \sim p_\theta}\big[f(x)\, \nabla_\theta \log p_\theta(x)\big].$$

The middle step uses \(\nabla p = p\, \nabla \log p\). No derivative of \(f\) is needed, so \(f\) can be a black-box reward. This is the heart of REINFORCE and the policy gradient theorem (Days 83–84).

The alternative, the reparameterization trick, writes \(x = g_\theta(\varepsilon)\) with noise \(\varepsilon\) whose distribution doesn't depend on \(\theta\), then differentiates \(f(g_\theta(\varepsilon))\) directly. It usually has much lower variance but needs a differentiable \(f\). SAC uses it for its actor (Day 95).

import numpy as np

rng = np.random.default_rng(0)
mu, sigma, n = 0.5, 1.0, 200_000
f = lambda x: x ** 2                  # E[f] = mu^2 + sigma^2, so d/dmu E[f] = 2*mu = 1.0

x = rng.normal(mu, sigma, n)
score = (x - mu) / sigma ** 2         # d/dmu of log N(x; mu, sigma^2)
g_score = f(x) * score                # score-function samples

eps = rng.normal(0.0, 1.0, n)
g_reparam = 2 * (mu + sigma * eps)    # d/dmu of f(mu + sigma*eps)

print(g_score.mean(), g_reparam.mean())   # both about 1.0
print(g_score.var(), g_reparam.var())     # the score estimator is far noisier
What breaks
  • γ close to 1 makes everything slow. Repeated application of \(T\) shrinks the error by \(\gamma\) per step, so reaching tolerance \(\varepsilon\) takes about \(\ln(1/\varepsilon)/(1 - \gamma)\) iterations: roughly 140 for \(\gamma = 0.9\), but about 1,400 for \(\gamma = 0.99\) at \(\varepsilon = 10^{-6}\). The same factor \(1/(1-\gamma)\) reappears in every error bound in Module 3.
  • Never form the inverse. Solve \((I - \gamma P)v = r\) with np.linalg.solve; np.linalg.inv is slower and less accurate, and \(I - \gamma P\) becomes badly conditioned as \(\gamma \to 1\).
  • The sup-norm argument doesn't transfer. “\(T\) is a contraction” is a statement about \(\|\cdot\|_\infty\). Combine \(T\) with a least-squares projection, which is non-expansive only in a weighted \(L_2\) norm, and the composition can expand. That is the mechanism behind the divergence examples of Day 69.
  • Score-function gradients are noisy by default. The estimator is unbiased, but its variance scales with \(f^2\). Without a baseline, adding a constant to every reward changes nothing in expectation and makes the gradient noisier.

Practice · 90 min

  1. Build a random 4-state row-stochastic \(P\) (normalise random rows). Compute np.linalg.eigvals(P) and confirm the largest modulus is 1.
  2. Solve \(v = r + \gamma P v\) three ways: np.linalg.solve, a truncated Neumann series, and repeated application of \(T\). Count the iterations each iterative method needs to reach \(10^{-6}\) for \(\gamma = 0.5, 0.9, 0.99\).
  3. Write out the proof that \(T\) is a \(\gamma\)-contraction in \(\|\cdot\|_\infty\), justifying every step.
  4. Run the gradient snippet and report the variance ratio. Then use \((f(x) - b)\cdot\text{score}\) with \(b = \E[f]\). The mean is unchanged; what happens to the variance? (You have just invented the baseline of Day 85.)

DAY 5

Optimization for RL

40m video60m practice

Almost every RL algorithm is stochastic gradient descent on an objective that keeps moving. Knowing exactly what SGD, momentum and Adam do, and what the Robbins–Monro conditions guarantee, is how you tell a bug from a learning-rate problem.

Objectives and landscapes

We minimise a loss \(L(\theta)\), or maximise an objective such as expected return. If \(L\) is convex, every local minimum is global and gradient descent with a suitable step converges to it. Neural-network losses are non-convex, with saddle points and flat plateaus, and we settle for good stationary points. In RL there is an extra twist: even the objective moves, as you'll see at the end of this lesson.

Gradient descent and SGD

Algorithm · SGD
  1. Sample a minibatch \(B\) and compute \(g = \frac{1}{|B|}\sum_{i \in B} \nabla_\theta \ell_i(\theta)\). It is unbiased: \(\E[g] = \nabla L(\theta)\).
  2. Update \(\theta \leftarrow \theta - \alpha\, g\).

Minibatch noise has variance proportional to \(1/|B|\). On a quadratic with curvatures \(\lambda_{\min} \le \dots \le \lambda_{\max}\), plain gradient descent is stable only for \(\alpha < 2/\lambda_{\max}\), and then the flattest direction contracts by \(1 - \alpha\lambda_{\min}\) per step. Badly conditioned problems are slow because the steepest direction caps the step size for every other direction.

Momentum, RMSProp and Adam

Algorithm · Adam
  1. \(m \leftarrow \beta_1 m + (1 - \beta_1)\, g\) (momentum: running mean of gradients)
  2. \(v \leftarrow \beta_2 v + (1 - \beta_2)\, g^2\) (RMSProp: running mean of squared gradients)
  3. \(\hat m = m / (1 - \beta_1^t)\), \(\hat v = v / (1 - \beta_2^t)\) (bias correction for the zero start)
  4. \(\theta \leftarrow \theta - \alpha\, \hat m / (\sqrt{\hat v} + \epsilon)\)

Momentum alone averages gradients over roughly \(1/(1 - \beta_1)\) steps, which smooths noise. RMSProp alone divides each coordinate by its running RMS, giving per-parameter step sizes that undo bad conditioning. Adam is both plus bias correction. The defaults are \(\beta_1 = 0.9\) and \(\beta_2 = 0.999\).

RL practice

Deep RL often changes \(\epsilon\). Rainbow-style DQN agents use Adam with a learning rate around \(6.25\times10^{-5}\) and \(\epsilon = 1.5\times10^{-4}\); common PPO implementations use \(2.5\times10^{-4}\) to \(3\times10^{-4}\) with \(\epsilon = 10^{-5}\). A larger \(\epsilon\) stops the update from exploding when gradient variance estimates are tiny. Take the exact values from the implementation you are reproducing, since they are part of the algorithm.

Learning-rate schedules

The common choices are constant, linear decay to zero (PPO's usual default), cosine decay, and warm-up followed by decay. Constant step sizes are far more common in RL than in supervised learning, because the problem is nonstationary: a step size decayed towards zero can no longer track a moving target.

Robbins–Monro: when do noisy updates converge?

Theorem · stochastic approximation (simplified)

Consider \(\theta_{k+1} = \theta_k + \alpha_k (Y_k - \theta_k)\) where \(\E[Y_k \mid \text{past}] = \mu\) and the noise has bounded variance. Then \(\theta_k \to \mu\) almost surely provided

$$\sum_{k} \alpha_k = \infty \qquad\text{and}\qquad \sum_k \alpha_k^2 < \infty.$$

The first condition makes the steps large enough, in total, to overcome any initial condition. The second makes them eventually small enough to average out the noise. The choice \(\alpha_k = 1/k\) satisfies both, and it is exactly the running sample mean. A constant \(\alpha\) violates the second condition: the estimate keeps jittering, with variance proportional to \(\alpha\), but in exchange it tracks a drifting target (Day 12). Every tabular convergence proof in Modules 4–5, Q-learning's included, assumes these conditions.

Why RL optimization is non-stationary

What breaks · three moving parts
  1. Moving targets. A TD target \(r + \gamma \max_{a'} Q(s', a'; \theta)\) depends on \(\theta\), so the regression labels change with every update. Target networks (Day 73) slow this down.
  2. Policy-dependent data. Improving the policy changes which states you visit, so the training distribution shifts under you.
  3. Exploration schedules. \(\varepsilon\) decays and entropy bonuses shrink, so the behaviour policy itself changes during training.

The upshot: RL loss curves are neither monotone nor very informative, and a falling loss does not mean a better policy. Track returns.

import numpy as np

rng = np.random.default_rng(0)
A = np.diag([1.0, 50.0])                          # badly conditioned quadratic
grad = lambda th: A @ th + rng.normal(0, 1.0, 2)  # noisy gradient

def sgd(th, lr=0.015, steps=200):
    for _ in range(steps):
        th = th - lr * grad(th)
    return th

def adam(th, lr=0.05, b1=0.9, b2=0.999, eps=1e-8, steps=200):
    m = v = np.zeros_like(th)
    for t in range(1, steps + 1):
        g = grad(th)
        m = b1 * m + (1 - b1) * g
        v = b2 * v + (1 - b2) * g ** 2
        m_hat, v_hat = m / (1 - b1 ** t), v / (1 - b2 ** t)
        th = th - lr * m_hat / (np.sqrt(v_hat) + eps)
    return th

th0 = np.array([5.0, 5.0])
print("SGD :", sgd(th0.copy()))    # flat axis still far from 0: lr is capped by the steep axis
print("Adam:", adam(th0.copy()))   # per-coordinate scaling removes the conditioning problem

DAY 6

Stochastic Processes & Markov Chains

40m video75m practice

A Markov chain is an MDP with the decisions taken out, or equivalently an MDP once a policy is fixed and folded in. Everything about long-run behaviour in RL (stationary distributions, mixing, the on-policy state distribution \(\mu\) of Module 7) is Markov chain theory.

Stochastic processes and the Markov property

Definition

A stochastic process is a sequence of random variables \((X_t)_{t \ge 0}\). It is Markov if

$$\Pr(X_{t+1} = j \mid X_t = i, X_{t-1}, \dots, X_0) = \Pr(X_{t+1} = j \mid X_t = i),$$

and time-homogeneous if this probability doesn't depend on \(t\). Its values form the transition matrix \(P_{ij}\).

“The future is independent of the past given the present.” This is a property of the state representation, not of the world. A pendulum's angle alone is not Markov, because you can't tell which way it is swinging; angle plus angular velocity is. Choosing a Markov state is half of modelling, which is why Atari agents stack frames (Day 74) and partially observed agents use memory (Day 121).

Transition matrices and n-step transitions

Theorem · Chapman–Kolmogorov

\(\Pr(X_{t+n} = j \mid X_t = i) = (P^n)_{ij}\). If \(X_0 \sim \pi_0\), written as a row vector, then \(X_t \sim \pi_t = \pi_0 P^t\).

Derivation

Condition on the intermediate state: \(\Pr(X_{t+2} = j \mid X_t = i) = \sum_k P_{ik} P_{kj} = (P^2)_{ij}\). Induct on \(n\).

Irreducible, aperiodic, ergodic

Definitions
  • Irreducible: every state can reach every other, so \((P^n)_{ij} > 0\) for some \(n\).
  • Period of \(i\): \(\gcd\{n \ge 1 : (P^n)_{ii} > 0\}\). The chain is aperiodic if every state has period 1; a single self-loop is enough in an irreducible chain.
  • Ergodic (for finite chains): irreducible and aperiodic.

Stationary distributions

Theorem

A distribution \(\pi\) is stationary if \(\pi = \pi P\). A finite irreducible chain has exactly one, with every \(\pi_i > 0\) and \(\pi_i = 1 / \E[\text{return time to } i]\). If the chain is also aperiodic, \(\pi_t \to \pi\) from any starting distribution. Without aperiodicity \(\pi_t\) may oscillate forever, but time averages still converge: \(\frac1T \sum_{t < T} \mathbb 1\{X_t = i\} \to \pi_i\) almost surely.

To compute \(\pi\), solve the linear system \(\pi P = \pi\) together with \(\sum_i \pi_i = 1\); equivalently, take the left eigenvector of \(P\) for eigenvalue 1 and normalise it. Try all three chains below. The ergodic one converges within a few dozen steps. The cycle never settles in \(\pi_t\), yet its visit frequencies converge. The checkout chain ends in its absorbing state every time.

Absorbing states

A state is absorbing if \(P_{ii} = 1\). Episodic RL tasks are exactly chains with absorbing terminal states once a policy is fixed. Order the transient states first:

$$P = \begin{pmatrix} Q & R \\ 0 & I \end{pmatrix}, \qquad N = (I - Q)^{-1} = \sum_{k \ge 0} Q^k.$$

\(N_{ij}\) is the expected number of visits to transient state \(j\) starting from \(i\). Expected steps to absorption are \(t = N\mathbf 1\), and absorption probabilities are \(B = NR\).

Intuition

This is the Neumann series of Day 4 again, with the substochastic \(Q\) (some probability leaks into absorption every step) playing the role of \(\gamma P\). Discounting by \(\gamma\) is equivalent to an undiscounted chain that terminates with probability \(1 - \gamma\) at every step.

import numpy as np

P = np.array([[0.70, 0.20, 0.10],
              [0.30, 0.40, 0.30],
              [0.20, 0.40, 0.40]])

# 1) left eigenvector for eigenvalue 1
w, V = np.linalg.eig(P.T)
pi = np.real(V[:, np.argmin(np.abs(w - 1))])
pi /= pi.sum()

# 2) linear system: (P^T - I) pi = 0 plus the constraint sum(pi) = 1
A = np.vstack([P.T - np.eye(3), np.ones(3)])
pi_ls = np.linalg.lstsq(A, np.r_[0, 0, 0, 1], rcond=None)[0]

# 3) simulation: long-run visit frequencies
rng, x, counts = np.random.default_rng(0), 0, np.zeros(3)
for _ in range(100_000):
    x = rng.choice(3, p=P[x])
    counts[x] += 1

print(pi, pi_ls, counts / counts.sum())   # all about [0.462, 0.308, 0.231]
What breaks
  • Reducible chains have many stationary distributions. With two closed classes, every mixture of their stationary distributions is stationary too, and the eigenvector you get back depends on numerical accident. Check irreducibility before trusting a unique \(\pi\).
  • np.linalg.eig returns any eigenvector. It can be complex-typed, negative or unnormalised. Take the real part, divide by the sum, and check that every entry is non-negative.
  • Power iteration from a point mass never converges on a periodic chain (the demo's cycle). Averaging the iterates, or using the lazy chain \((P + I)/2\), fixes it without changing \(\pi\).
  • Slow mixing looks like convergence. If the chain has nearly separate regions, empirical frequencies can sit at the wrong values for a very long time. In RL this is exactly the agent stuck in one part of the state space, and it is why exploration (Module 11) matters.

RL results are noisy enough that a careless experiment proves nothing. Fast vectorized code lets you afford many seeds; seeding, logging and confidence intervals let you trust what those seeds tell you.

Vectorize the value table

Tabular RL is linear algebra over arrays indexed by state, action and next state. A Python loop over states is typically one to two orders of magnitude slower than the equivalent single einsum, and that difference decides whether you can afford 50 seeds.

import numpy as np

S, A, gamma = 500, 4, 0.95
rng = np.random.default_rng(0)
P = rng.dirichlet(np.ones(S), size=(S, A))   # P[s, a, s'] sums to 1 over s'
R = rng.normal(size=(S, A))                   # expected reward r(s, a)

def backup_loop(V):                           # one Bellman optimality backup
    out = np.empty(S)
    for s in range(S):
        out[s] = max(R[s, a] + gamma * P[s, a] @ V for a in range(A))
    return out

def backup_vec(V):                            # Q[s,a] = R[s,a] + gamma * sum_s' P[s,a,s'] V[s']
    return (R + gamma * np.einsum("sat,t->sa", P, V)).max(axis=1)

V = rng.normal(size=S)
assert np.allclose(backup_loop(V), backup_vec(V))

Seed everything

import random
import numpy as np
import torch

def seed_everything(seed: int) -> np.random.Generator:
    random.seed(seed)
    np.random.seed(seed)                      # legacy global RNG, for libraries that still use it
    torch.manual_seed(seed)                   # CPU and every CUDA device
    torch.backends.cudnn.deterministic = True
    torch.backends.cudnn.benchmark = False
    return np.random.default_rng(seed)        # prefer passing this Generator around explicitly

rng = seed_everything(42)

env.action_space.seed(42)                     # ...and the action space, if you sample from it
Reproducible is not the same as robust

Seeding makes a run repeatable on the same machine with the same library versions. It does not make your conclusion seed-independent, which is the property you actually care about. GPU determinism also costs speed, and some operations have no deterministic kernel at all; torch.use_deterministic_algorithms(True) will raise an error naming them.

Log everything you'll want later

Log per-episode return and length, every loss term, Q-value or value magnitudes, policy entropy, gradient norms, the learning rate, and both wall-clock time and environment steps. With TensorBoard that is writer.add_scalar("charts/episodic_return", G, global_step), and Weights & Biases is equivalent. Index everything by environment steps, not updates or episodes: that is the axis papers compare on, and it is the only one that is fair across algorithms with different update rates.

Multiple seeds and confidence intervals

Definition · intervals over seeds

For \(N\) independent seeds with final returns \(x_1, \dots, x_N\): the mean is \(\bar x\), the standard error is \(s/\sqrt N\), and a 95% t-interval is \(\bar x \pm t_{0.975,\,N-1}\, s/\sqrt N\). With \(N = 5\), \(t \approx 2.78\), so the interval is wide. A bootstrap interval (resample seeds with replacement, recompute the mean, take percentiles) avoids the normality assumption. For aggregates across many tasks, the interquartile mean with stratified bootstrap intervals, as in the rliable library, is the current recommendation.

import numpy as np
import matplotlib.pyplot as plt

def plot_with_ci(curves, label, n_boot=2000, rng=np.random.default_rng(0)):
    """curves: array of shape [n_seeds, n_points] on a shared x-axis (env steps)."""
    curves = np.asarray(curves)
    idx = rng.integers(0, len(curves), size=(n_boot, len(curves)))
    boot = curves[idx].mean(axis=1)                      # [n_boot, n_points]
    lo, hi = np.percentile(boot, [2.5, 97.5], axis=0)
    x = np.arange(curves.shape[1])
    plt.plot(x, curves.mean(axis=0), label=label)
    plt.fill_between(x, lo, hi, alpha=0.25)

Why single-seed RL results are meaningless

Henderson et al. (2018) ran one algorithm with two disjoint sets of five seeds and obtained learning curves that looked like two different algorithms, with a statistically significant gap between them. Variation across seeds is often larger than the difference between methods. Agarwal et al. (2021) showed that several published conclusions on the Atari 100k benchmark change once uncertainty is reported properly.

What breaks · ways to manufacture a result
  • Reporting the best seed, or the best checkpoint of each seed.
  • Tuning hyperparameters on the same seeds you then report.
  • Comparing a tuned new method against a baseline with default hyperparameters.
  • Smoothing curves so heavily that the variance disappears.

Any one of these alone can produce a fake improvement. Day 128 turns this into a full evaluation checklist.

Gymnasium Deep Dive

Gymnasium is the interface every algorithm in this course talks to. Two of its details, the five-value step return and the difference between terminated and truncated, decide whether your value targets are correct.

The API

import gymnasium as gym

env = gym.make("CartPole-v1")
obs, info = env.reset(seed=0)
episode_return, done = 0.0, False
while not done:
    action = env.action_space.sample()
    obs, reward, terminated, truncated, info = env.step(action)
    episode_return += reward
    done = terminated or truncated
env.close()
print(episode_return)

reset returns (obs, info) and step returns five values. Gymnasium is the maintained successor of OpenAI Gym. Older tutorials use the pre-0.26 four-value form obs, reward, done, info; if you see that, the code is for the old API.

Terminated vs truncated: the bug that ruins value targets

Definition

terminated: the MDP reached a terminal state (the pole fell, the goal was reached). The future return really is 0.

truncated: the episode was cut off for a reason outside the MDP, usually a time limit. The state is not terminal and its future return is not 0.

So the TD target must bootstrap through a truncation and stop at a termination:

$$y = r + \gamma\,(1 - \text{terminated})\,\max_{a'} Q(s', a').$$ 
# WRONG: treats a time-limit cut-off as if the world ended
target = r + gamma * (1 - (terminated or truncated)) * q_next

# RIGHT: only true termination removes the bootstrap
target = r + gamma * (1 - terminated) * q_next
What breaks

Pre-0.26 Gym folded both cases into a single done, and a generation of code zeroed the bootstrap at time limits. On CartPole-v1, with its 500-step limit, that teaches the agent the state at step 499 is worth nothing, even though time isn't part of the observation and the agent can't tell step 499 from step 5. Pardo et al. (2018) measure the damage.

A second trap lives in vector environments, which reset automatically. In Gymnasium 0.26–0.29 the true final observation of a finished episode is in info["final_observation"], while obs is already the next episode's first observation. Gymnasium 1.0 switched to a next-step autoreset, where the reset happens on the following step call. Read your version's documentation before trusting obs at an episode boundary.

Synchronous vector envs step every copy in one process, which is right for cheap environments. Asynchronous ones use subprocesses, which pays off when each step is expensive. A2C and PPO (Days 87 and 91) are built around the batches these produce.

Writing a custom environment

import numpy as np
import gymnasium as gym
from gymnasium import spaces

class GridWorld(gym.Env):
    metadata = {"render_modes": []}

    def __init__(self, size=5, max_steps=100):
        self.size, self.max_steps = size, max_steps
        self.observation_space = spaces.Discrete(size * size)
        self.action_space = spaces.Discrete(4)                 # up, right, down, left
        self._moves = np.array([[-1, 0], [0, 1], [1, 0], [0, -1]])

    def reset(self, seed=None, options=None):
        super().reset(seed=seed)                               # seeds self.np_random
        self.pos, self.t = np.array([0, 0]), 0
        return self._obs(), {}

    def step(self, action):
        self.pos = np.clip(self.pos + self._moves[action], 0, self.size - 1)
        self.t += 1
        terminated = bool((self.pos == self.size - 1).all())  # reached the far corner
        truncated = self.t >= self.max_steps
        reward = 1.0 if terminated else -0.01
        return self._obs(), reward, terminated, truncated, {}

    def _obs(self):
        return int(self.pos[0] * self.size + self.pos[1])

from gymnasium.utils.env_checker import check_env
check_env(GridWorld())                                        # catches API mistakes early

PyTorch Crash Course for RL

45m video105m practice

Deep RL is ordinary PyTorch with one unusual habit: deciding what not to differentiate. A large share of deep-RL bugs are a missing detach(), a stale target, or a gradient flowing somewhere it shouldn't.

Tensors and devices

import torch

device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
obs_t = torch.as_tensor(obs, dtype=torch.float32, device=device)   # NumPy -> tensor
batch = torch.randn(32, 4, device=device)                         # 32 states of dimension 4

Keep environments on the CPU in NumPy and networks on the device, and convert once per step at the boundary. Small MLPs on CartPole are often faster on the CPU; the GPU wins with convolutional networks and large batches.

Autograd

Tensors created with requires_grad=True (every nn.Parameter) record the operations applied to them in a computation graph. loss.backward() walks that graph in reverse and adds \(\partial\,\text{loss}/\partial\theta\) into each θ.grad. Because gradients accumulate, you call optimizer.zero_grad() before every backward pass.

nn.Module, layers and initialization

import torch.nn as nn

class QNet(nn.Module):
    def __init__(self, obs_dim, n_actions, hidden=128):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(obs_dim, hidden), nn.ReLU(),
            nn.Linear(hidden, hidden), nn.ReLU(),
            nn.Linear(hidden, n_actions),            # one output per action (Day 71)
        )

    def forward(self, x):
        return self.net(x)

def init_orthogonal(m, gain=2 ** 0.5):
    if isinstance(m, nn.Linear):
        nn.init.orthogonal_(m.weight, gain)
        nn.init.zeros_(m.bias)

q = QNet(obs_dim=4, n_actions=2).apply(init_orthogonal)

PyTorch's default Linear initialization is a scaled uniform. Many PPO implementations use orthogonal initialization with gain \(\sqrt 2\) for hidden layers and very small gains (0.01) for the policy output layer, so the initial policy is close to uniform (Day 92).

Losses and optimizers

The losses you'll meet: mean squared error (F.mse_loss); Huber (F.smooth_l1_loss), which is quadratic near zero and linear for large errors, so a single huge TD error can't dominate an update (Day 73); and cross-entropy for distributional RL (Day 79). The optimizer is almost always torch.optim.Adam(params, lr=...), with the RL-specific eps values from Day 5.

detach(), and why it's everywhere in RL

Intuition

A TD target \(r + \gamma \max_{a'} Q(s', a')\) is a label, not a prediction. If gradients flow through it, the optimizer lowers the loss by also dragging the target towards the prediction. That is a different algorithm, the residual-gradient method, with different fixed points and its own problems. Blocking the gradient gives semi-gradient TD (Day 62), which is what DQN and nearly every practical method use.

Definition · semi-gradient vs residual gradient

For one transition with loss \(\tfrac12\big(y - Q_\theta(s, a)\big)^2\) and target \(y = r + \gamma\, Q_\theta(s', a')\):

$$\text{semi-gradient (y held fixed):}\qquad -\big(y - Q_\theta(s, a)\big)\, \nabla_\theta Q_\theta(s, a)$$ $$\text{residual gradient (through y):}\qquad -\big(y - Q_\theta(s, a)\big)\, \big(\nabla_\theta Q_\theta(s, a) - \gamma\, \nabla_\theta Q_\theta(s', a')\big)$$

The residual gradient is a true gradient of the squared TD error, but with random transitions it minimises the wrong quantity: the expected squared TD error includes the variance of \(s'\), so it prefers value functions that make \(s'\) predictable rather than correct. A target network (Day 73) computes \(y\) with separate parameters \(\theta^-\), so \(y\) is a constant with respect to \(\theta\) by construction; no_grad enforces the same thing in code.

import torch.nn.functional as F

q_sa = q(obs).gather(1, actions.unsqueeze(1)).squeeze(1)    # Q(s, a) for the actions taken
with torch.no_grad():                                        # targets carry no gradient
    q_next = target_q(next_obs).max(dim=1).values
    y = rewards + gamma * (1 - terminated.float()) * q_next
loss = F.smooth_l1_loss(q_sa, y)

optimizer.zero_grad()
loss.backward()
torch.nn.utils.clip_grad_norm_(q.parameters(), max_norm=10.0)
optimizer.step()

torch.no_grad() stops graph construction for everything inside the block; .detach() returns a single tensor cut off from the graph. Here they have the same effect, and no_grad also saves memory.

What breaks · other places you need it
  • The advantage in a policy-gradient loss weights the score function. It must be detached, or the critic is trained through the actor's loss (Day 86).
  • DDPG's actor maximises \(Q(s, \mu(s))\): gradients must flow through the critic into the action, but only the actor's optimizer may step (Day 93).
  • SAC's temperature loss uses detached log-probabilities (Day 95).

Gradient clipping and checkpoints

clip_grad_norm_ goes between backward() and step(). It rescales the whole gradient vector whenever its norm exceeds the threshold. PPO commonly uses 0.5 (Day 92); DQN-style agents often use 10.

torch.save({"q": q.state_dict(), "opt": optimizer.state_dict(), "step": step}, "ckpt.pt")

ckpt = torch.load("ckpt.pt", map_location=device)
q.load_state_dict(ckpt["q"])
optimizer.load_state_dict(ckpt["opt"])

Save the optimizer as well: Adam's moment estimates are part of the training state, and resuming without them causes a visible jolt in the learning curve. For an exact resume you also need the RNG states and, for off-policy methods, the replay buffer.

A tiny end-to-end training loop

This fits the values of the 5-state random walk you'll meet on Day 42 (true values \(1/6, \dots, 5/6\)) with a small network and semi-gradient TD(0). It uses every piece above.

import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(0)
true_v = torch.arange(1, 6) / 6
net = nn.Sequential(nn.Linear(5, 32), nn.ReLU(), nn.Linear(32, 1))
opt = torch.optim.Adam(net.parameters(), lr=1e-2)
onehot = torch.eye(5)

for episode in range(2000):
    s, transitions = 2, []
    while 0 <= s < 5:                                    # one episode, start in the middle
        s2 = s + (1 if torch.rand(()) < 0.5 else -1)
        transitions.append((s, 1.0 if s2 == 5 else 0.0, s2))
        s = s2
    states, rewards, nxt = map(torch.tensor, zip(*transitions))
    terminal = (nxt < 0) | (nxt > 4)
    with torch.no_grad():                                 # semi-gradient TD(0) target, gamma = 1
        v_next = net(onehot[nxt.clamp(0, 4)]).squeeze(1)
        y = rewards + (~terminal).float() * v_next
    loss = F.mse_loss(net(onehot[states]).squeeze(1), y)
    opt.zero_grad()
    loss.backward()
    opt.step()

print(net(onehot).squeeze(1).detach(), true_v)

  3. Add gradient-norm clipping, log the pre-clipping gradient norm every episode, and plot it.
  4. Save a checkpoint at episode 1000, stop the process, resume from the checkpoint, and confirm the loss curve continues smoothly. Then resume without the optimizer state and compare.
