Monte Carlo Methods

Dynamic programming needed the whole model. Monte Carlo methods need only experience: they estimate a value by averaging the returns that actually followed it, and improve policies with the same evaluate-and-improve loop as Module 3. Without a model, exploration stops being optional, and the module's second half is about the three ways to guarantee it: exploring starts, ε-soft policies, and learning off-policy with importance sampling. Module 5 keeps the sampling but stops waiting for the episode to end.

DAY 35

Monte Carlo Prediction

40m video90m practice

A state's value is its expected return, so estimate it by averaging the returns you actually observed after visiting it. No model and no bootstrapping: just complete episodes and the law of large numbers.

Learning from complete episodes, with no model

Every algorithm in Module 3 needed \(p(s', r \mid s, a)\). Monte Carlo (MC) methods need only the ability to generate episodes, either by acting in the real environment or by running a simulator. That is a much weaker requirement than it sounds. To write down Blackjack's transition probabilities for "stick" you would have to compute the distribution of the dealer's final total for every showing card, which is tedious and error-prone. Simulating a hand takes ten lines. S&B make the point directly: a sample model is often easy when a distribution model is not.

The idea follows from the definition of value. \(v_\pi(s) = \E_\pi[G_t \mid S_t = s]\), so if you follow \(\pi\), record every return that follows a visit to \(s\), and average them, the average converges to \(v_\pi(s)\) by the law of large numbers (Day 3). Two properties set MC apart from DP:

  • No bootstrapping. The estimate for each state is built only from returns observed after that state, never from other states' estimates. The cost of estimating one state's value is independent of how many states there are, so you can evaluate just the states you care about.
  • Sample backups. Instead of averaging over every successor with its probability, MC follows one sampled trajectory all the way to the end.

First-visit Monte Carlo

A state can occur several times in one episode. First-visit MC uses only the return that follows the first occurrence of \(s\) in each episode; every-visit MC uses the returns after every occurrence. Computing the returns is cheapest backwards, with the recursion \(G_t = R_{t+1} + \gamma G_{t+1}\) of Day 19.

Algorithm · First-visit MC prediction
  1. Input the policy \(\pi\). Initialise \(V(s)\) arbitrarily and \(N(s) \leftarrow 0\) for all \(s\).
  2. Repeat for each episode:
    1. Generate \(S_0, A_0, R_1, S_1, \dots, S_{T-1}, A_{T-1}, R_T\) by following \(\pi\).
    2. \(G \leftarrow 0\)
    3. For \(t = T-1, T-2, \dots, 0\):
      1. \(G \leftarrow \gamma G + R_{t+1}\)
      2. If \(S_t\) does not appear among \(S_0, \dots, S_{t-1}\): \(N(S_t) \leftarrow N(S_t) + 1\); \(V(S_t) \leftarrow V(S_t) + \frac{1}{N(S_t)}\big[G - V(S_t)\big]\)

(every-visit MC drops the "does not appear" test)

Bias and consistency: first-visit vs every-visit

For first-visit MC, the returns collected for \(s\) come from different, independent episodes, and each has expectation \(v_\pi(s)\) by the Markov property. They are i.i.d., so the average is unbiased, its variance is \(\sigma^2/n\), and it converges by the law of large numbers. Every-visit returns from the same episode overlap (they share their tails) and the number of visits per episode is random, so the every-visit average is biased for any finite number of episodes. It is still consistent: it converges to \(v_\pi(s)\) as the number of episodes grows.

Derivation · biased but consistent, on a one-state example

One non-terminal state \(s\). Each step earns \(+1\) and returns to \(s\) with probability \(p\), terminating otherwise; \(\gamma = 1\). Write \(q = 1 - p\). The episode length \(T\) is geometric with \(\E[T] = 1/q\) and \(\E[T^2] = (2 - q)/q^2\), and \(v(s) = \E[T] = 1/q\).

First visit. The first-visit return is \(T\) itself, so \(\E[\hat v] = 1/q\): unbiased.

Every visit, one episode. The visits are followed by returns \(T, T-1, \dots, 1\), whose average is \((T+1)/2\). Its expectation is \(\tfrac12(1/q + 1) \ne 1/q\) whenever \(p > 0\): biased low.

Every visit, many episodes. Pool all visits from \(n\) episodes: \(\hat v_n = \sum_i T_i(T_i + 1)/2 \,\big/\, \sum_i T_i\). By the law of large numbers in the numerator and denominator,

$$\hat v_n \;\longrightarrow\; \frac{\E[T^2] + \E[T]}{2\,\E[T]} = \frac{(2 - q)/q^2 + 1/q}{2/q} = \frac{2 - q + q}{2q} = \frac1q = v(s).$$

Consistent, as claimed. Yet with a single episode the every-visit estimate has the lower mean squared error: its variance is a quarter of first-visit's, which more than pays for its bias (MSE \(p(1+p)/(4q^2)\) against \(p/q^2\)). Singh & Sutton (1996) analyse the two in general; in their examples every-visit tends to win early and first-visit asymptotically.

Incremental implementation

Storing every return and re-averaging is wasteful. The running-mean update of Day 12 does the same job in constant memory:

$$V(S_t) \leftarrow V(S_t) + \frac{1}{N(S_t)}\big[G_t - V(S_t)\big].$$

Replace \(1/N\) with a constant step size and you get constant-α MC, \(V(S_t) \leftarrow V(S_t) + \alpha[G_t - V(S_t)]\), which forgets old returns exponentially and so tracks a changing policy or environment. It is also the exact starting point for TD(0) on Day 42: replace \(G_t\) with \(R_{t+1} + \gamma V(S_{t+1})\).

Why MC needs episodic tasks

  • The target exists only at the end. \(G_t\) includes every reward until termination, so no update can happen before the episode finishes. Long episodes mean long delays between experience and learning.
  • Continuing tasks have no end. You could truncate at a horizon \(H\), but then the target is biased by up to \(\gamma^H R_{\max}/(1-\gamma)\). Bootstrapping methods (Module 5) remove the problem.
  • Variance grows with episode length. \(G_t\) sums many random rewards, so its variance generally grows with the number of steps that remain.
  • A bad policy may never terminate. During control, a policy that walks into a wall forever produces an episode that never ends. Every MC implementation needs a time limit, and a truncated episode's return is not an unbiased sample of \(v_\pi\) (Day 8's terminated versus truncated distinction).

Running MC on Blackjack

Definition · Blackjack (S&B Example 5.1)
  • Cards are dealt from an infinite deck (with replacement). Face cards count 10; an ace counts 1 or 11. The player and dealer each get two cards; one dealer card is face up.
  • A natural (ace plus a ten-card) wins outright, unless the dealer also has one, which is a draw.
  • Otherwise the player hits (takes a card) or sticks. Going over 21 is a bust and loses. After the player sticks, the dealer hits until reaching 17 or more (an ace counts 11 if that doesn't bust); a dealer bust is a win for the player; otherwise the closer total to 21 wins.
  • Rewards \(+1, 0, -1\) for win, draw, loss, all at the end; \(\gamma = 1\).
  • State: the player's sum (12–21), the dealer's showing card (ace–10), and whether the player holds a usable ace (one counted as 11 without busting). That is 200 states. Below 12 the player always hits, since no card can bust.

Gymnasium's gym.make("Blackjack-v1", sab=True) implements exactly these rules (sab stands for Sutton and Barto); observations are (player_sum, dealer_card, usable_ace) with the ace as 1, and actions are 0 = stick, 1 = hit. It also shows you sums below 12, where you should simply hit. The self-contained simulator below follows the same rules and adds one thing Gymnasium lacks, the ability to start an episode in a chosen state, which Day 37 needs.

import random

class Blackjack:
    """S&B Example 5.1 rules (= Gymnasium Blackjack-v1 with sab=True), infinite deck.
    State (player sum 12-21, dealer's showing card 1-10, usable ace). Actions 0 = stick, 1 = hit."""
    def __init__(self, seed=0):
        self.rng = random.Random(seed)

    def draw(self):
        return min(self.rng.randint(1, 13), 10)             # ace = 1; J, Q, K count 10

    @staticmethod
    def total(hand):                                        # (sum, usable ace?)
        s = sum(hand)
        return (s + 10, True) if 1 in hand and s + 10 <= 21 else (s, False)

    def state(self):
        s, ace = self.total(self.player)
        return s, self.dealer[0], ace

    def reset(self, start=None):
        self.dealer = [self.draw(), self.draw()]
        if start is None:
            self.player = [self.draw(), self.draw()]
            while self.total(self.player)[0] < 12:          # below 12, hitting is free: no decision
                self.player.append(self.draw())
        else:                                               # exploring start (sum, showing, usable)
            s, self.dealer[0], ace = start
            self.player = [1, s - 11] if ace else ([10, s - 10] if s < 21 else [10, 9, 2])
        return self.state()

    def step(self, action):                                 # -> (next state, reward, done)
        if action == 1:
            self.player.append(self.draw())
            bust = self.total(self.player)[0] > 21
            return (None, -1.0, True) if bust else (self.state(), 0.0, False)
        while self.total(self.dealer)[0] < 17:              # stick: dealer draws to 17 or more
            self.dealer.append(self.draw())
        p, d = self.total(self.player)[0], self.total(self.dealer)[0]
        if sorted(self.player) == [1, 10] and sorted(self.dealer) != [1, 10]:
            return None, 1.0, True                          # a natural wins outright
        return None, 1.0 if d > 21 else float((p > d) - (p < d)), True

def play_episode(env, policy, start=None, first_action=None):
    """[(S_t, A_t, R_t+1), ...]; first_action forces A_0 (exploring starts)."""
    state, episode, done = env.reset(start), [], False
    action = policy(state) if first_action is None else first_action
    while not done:
        next_state, reward, done = env.step(action)
        episode.append((state, action, reward))
        state = next_state
        if not done:
            action = policy(state)
    return episode

# continues from the Day 35 snippet (Blackjack, play_episode)
from collections import defaultdict

def first_visit_mc(policy, n_episodes, gamma=1.0, seed=0):
    env = Blackjack(seed)
    V, N = defaultdict(float), defaultdict(int)
    for _ in range(n_episodes):
        episode = play_episode(env, policy)
        states = [s for s, _, _ in episode]
        G = 0.0
        for t in reversed(range(len(episode))):          # walk backwards: G_t = R_t+1 + gamma*G_t+1
            s, _, r = episode[t]
            G = gamma * G + r
            if s not in states[:t]:                      # first visit of s in this episode
                N[s] += 1
                V[s] += (G - V[s]) / N[s]                # incremental sample mean
    return V, N

stick_on_20 = lambda s: 0 if s[0] >= 20 else 1
for n in (10_000, 500_000):
    V, N = first_visit_mc(stick_on_20, n)
    print(f"{n:>7} episodes: V(21, 10, no ace) = {V[21, 10, False]:.3f}, "
          f"V(13, 2, ace) = {V[13, 2, True]:.3f} from {N[13, 2, True]} visits")

Evaluates S&B's policy "stick only on 20 or 21". Exact values (by DP on the known card probabilities, Day 41) are 0.889 and −0.277; the run prints 0.889 and −0.667 after 10,000 episodes (6 visits) and 0.888 and −0.316 after 500,000 (510 visits). In Blackjack the player's state can never repeat within a hand, so first-visit and every-visit MC coincide.

This reproduces S&B Figure 5.1. Against the exact values, the root-mean-square error over the 100 no-usable-ace states falls from 0.072 after 10,000 episodes to 0.011 after 500,000; over the usable-ace states it falls from 0.28 to 0.037. Usable-ace states are visited six to seven times less often per hand, so their surface stays ragged for longer. The shape is easy to read: values are high only at 20 and 21, where this policy sticks, and negative everywhere it keeps hitting, worst (down to about −0.79) when the dealer shows an ace.

What breaks
  • Off-by-one returns. Accumulate \(G \leftarrow \gamma G + R_{t+1}\) before crediting \(S_t\), with the reward that followed \(A_t\), not the one that preceded it.
  • The wrong first-visit test. "First visit" means \(S_t\) does not occur at an earlier time. Testing later times gives a last-visit estimator, which is biased.
  • Naive confidence intervals for every-visit MC. Returns from the same episode are correlated, so treating them as independent samples makes intervals too narrow. Bootstrap over episodes instead.
  • Episodes that never end. Add a step limit, and remember that a truncated return is not an unbiased target.
  • Blackjack's soft 21. In Gymnasium a natural shows up as the observation (21, dealer card, usable ace), the same observation as a three-card soft 21. The two have different values (a natural also beats a dealer's three-card 21), so that observation's estimate is a mixture: 0.916 rather than 0.889 against a dealer 10. It is not a bug in your code, but it will look like one when you compare with a published figure that removed naturals.

DAY 36

MC Estimation of Action Values

30m video60m practice

Without a model, state values cannot tell you which action to take. Estimating \(q_\pi(s, a)\) directly fixes that, but only for the actions you actually try, so exploration becomes part of the estimation problem itself.

Why v alone is useless without a model

Policy improvement (Day 29) picks \(\pi'(s) = \argmax_a \sum_{s', r} p(s', r \mid s, a)\,[r + \gamma v_\pi(s')]\). Every term needs the model. In Blackjack, knowing \(v_\pi\) of every state does not tell you whether to hit 16 against a dealer 10: "stick" leads to a terminal outcome whose probabilities depend on the dealer's drawing, and "hit" leads to a distribution over next sums. Without those probabilities, \(v\) is a scoreboard with no instructions. Action values make the decision model-free:

$$\pi'(s) = \argmax_a q_\pi(s, a).$$

That is why every model-free control method in this course, from Monte Carlo control to DQN, learns action values or a policy directly, never state values alone.

Estimating qπ(s, a)

Definition

\(q_\pi(s, a) = \E_\pi[G_t \mid S_t = s, A_t = a]\): the expected return from taking \(a\) in \(s\) and following \(\pi\) afterwards. A visit to the pair \((s, a)\) is a time step with \(S_t = s\) and \(A_t = a\).

The estimators are exactly Day 35's with pairs in place of states. First-visit MC averages the return after the first visit to \((s, a)\) in each episode, is unbiased, and converges at the \(1/\sqrt n\) rate; every-visit MC is biased but consistent. The only new cost is size: there are \(|\mathcal S||\mathcal A|\) quantities to estimate instead of \(|\mathcal S|\), each from its own share of the data.

The problem of unvisited state–action pairs

If \(\pi\) is deterministic, each state is only ever paired with one action, \(\pi(s)\). The returns for every other action are never observed, their estimates never improve, and improvement has nothing to compare. Run S&B's stick-on-20 policy for 200,000 hands and exactly half of the 400 pairs are never tried: "stick" below 20 and "hit" at 20 or 21.

The danger is concrete. After those 200,000 hands, \(\hat Q(16, 10, \text{hit}) = -0.687\) from thousands of returns, while \(\hat Q(16, 10, \text{stick}) = 0\), its initial value, from none. A greedy step would switch to sticking on the strength of no evidence at all. Here that happens to be close to right; in general it is a coin flip decided by your initialisation.

The exploring-starts assumption

Definition · exploring starts

Every episode begins in a state–action pair \((S_0, A_0)\) drawn from a distribution that gives every pair positive probability. After the first action, the policy is followed as usual. With infinitely many episodes, every pair is then visited infinitely often, which is what convergence of the averages requires.

With exploring starts the same 200,000 hands leave no pair untried, and the two estimates at 16 against 10 become \(-0.586\) (stick) and \(-0.659\) (hit, then follow stick-on-20). The assumption is still unrealistic in most problems:

  • It needs a resettable simulator. You must be able to place the environment in any state and force the first action. With a real robot, a patient, or a customer you start wherever the world puts you.
  • The start distribution must reach everything. States that only occur deep inside episodes must still be possible starting points, and in many environments you cannot even enumerate the valid states.
  • It wastes samples at scale. Uniform starts over a huge state space spend almost all their effort on states the optimal policy never visits.

Exploring starts are useful for understanding and for simulators you control, which is why Day 37 uses them. Days 38–40 replace them with the two general solutions: keep the policy itself stochastic, or learn about one policy while following another.

Maintaining visit counts

Store a count \(N(s, a)\) next to each estimate. It drives the incremental mean \(Q \leftarrow Q + (G - Q)/N\); it gives the standard error \(\hat\sigma/\sqrt{N}\) of each estimate; it exposes coverage holes (\(N = 0\)) before they corrupt an improvement step; and later it drives exploration schedules (\(\varepsilon = c/N(s)\), Day 38) and importance weights (Day 40). Blackjack returns lie in \([-1, 1]\), so \(\sigma \le 1\), and a 95% interval of \(\pm 0.01\) needs roughly \((1.96/0.01)^2 \approx 38{,}000\) visits to a pair. Differences between the best and second-best action are often smaller than that (Day 41 finds five states where they are under 0.02), so near-ties stay unresolved for a long time.

# continues from the Day 35 snippet (Blackjack, play_episode)
import random
from collections import defaultdict

STATES = [(s, d, u) for s in range(12, 22) for d in range(1, 11) for u in (False, True)]

def mc_q(policy, n_episodes, exploring_starts, seed=0):
    env, rng = Blackjack(seed), random.Random(seed + 1)
    Q, N = defaultdict(float), defaultdict(int)
    for _ in range(n_episodes):
        if exploring_starts:                         # every (s, a) pair has probability > 0
            episode = play_episode(env, policy, start=rng.choice(STATES),
                                   first_action=rng.randint(0, 1))
        else:
            episode = play_episode(env, policy)
        G = 0.0
        for s, a, r in reversed(episode):            # Blackjack never revisits a state, so
            G += r                                   # first-visit and every-visit coincide
            N[s, a] += 1
            Q[s, a] += (G - Q[s, a]) / N[s, a]
    return Q, N

stick_on_20 = lambda s: 0 if s[0] >= 20 else 1
for es in (False, True):
    Q, N = mc_q(stick_on_20, 200_000, exploring_starts=es)
    never = sum(N[s, a] == 0 for s in STATES for a in (0, 1))
    print(f"exploring starts={es!s:5}: {never} of 400 pairs never tried; "
          f"Q(16, 10, no ace): stick {Q[(16, 10, False), 0]:+.3f}, hit {Q[(16, 10, False), 1]:+.3f}")

Prints 200 untried pairs and 0.000 versus −0.687 without exploring starts; 0 untried pairs and −0.586 versus −0.659 with them.

What breaks
  • Initial values posing as estimates. An untried action keeps \(Q = 0\). In Blackjack, where most values are negative, that makes it look attractive; in a task with positive returns it looks terrible and is never tried. Always check \(N\) before trusting a comparison.
  • Exploring the state but not the action. A random start state with \(A_0 = \pi(S_0)\) is not an exploring start; the first action must be random too.
  • Thin start distributions. Exploring starts guarantee every pair positive probability, not enough data. A pair with start probability \(10^{-5}\) may still have a handful of visits after a million episodes. Look at the smallest \(N\), not the average.
  • Impossible starts. In environments with constraints, a random state may be unreachable or invalid. Learning its value wastes samples, or crashes the simulator.

DAY 37

MC Control with Exploring Starts

35m video90m practice

Plug Monte Carlo evaluation into generalized policy iteration: average returns into \(Q\), act greedily on \(Q\), and let exploring starts keep every action in play. On Blackjack this rediscovers the optimal strategy from nothing but simulated hands, even though nobody has proved that it must in general.

GPI with Monte Carlo evaluation

Policy iteration (Day 30) alternates complete evaluation with greedy improvement. With action values, the improvement step needs no model:

$$\pi_{k+1}(s) = \argmax_a q_{\pi_k}(s, a), \qquad q_{\pi_k}(s, \pi_{k+1}(s)) = \max_a q_{\pi_k}(s, a) \ge q_{\pi_k}(s, \pi_k(s)) = v_{\pi_k}(s),$$

so the policy improvement theorem applies unchanged and \(\pi_{k+1}\) is at least as good as \(\pi_k\). Two assumptions would make this an exact algorithm: every pair is explored (exploring starts), and each evaluation uses infinitely many episodes. The second is the impractical one, and the fix is the one value iteration used (Day 31): don't evaluate to convergence. After each episode, update \(Q\) with that episode's returns and immediately make the policy greedy at the states it visited. Evaluation and improvement now interleave at the finest grain Monte Carlo allows, one episode.

The MCES algorithm

Algorithm · Monte Carlo with Exploring Starts (MCES)
  1. Initialise \(\pi(s)\) arbitrarily, \(Q(s, a)\) arbitrarily and \(N(s, a) \leftarrow 0\).
  2. Repeat for each episode:
    1. Choose \(S_0\) and \(A_0\) at random so that every pair has positive probability. (the exploring start)
    2. Generate an episode from \(S_0, A_0\) following \(\pi\): \(S_0, A_0, R_1, \dots, S_{T-1}, A_{T-1}, R_T\).
    3. \(G \leftarrow 0\). For \(t = T-1, \dots, 0\):
      1. \(G \leftarrow \gamma G + R_{t+1}\)
      2. If \((S_t, A_t)\) does not appear among \((S_0, A_0), \dots, (S_{t-1}, A_{t-1})\):
        1. \(N(S_t, A_t) \leftarrow N(S_t, A_t) + 1\); \(Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \frac{1}{N(S_t, A_t)}\big[G - Q(S_t, A_t)\big]\)
        2. \(\pi(S_t) \leftarrow \argmax_a Q(S_t, a)\)

(S&B keep a list of returns per pair and average it; the running mean is the same number in constant memory)

Convergence: what is known and what isn't

There is a clean argument that MCES cannot settle on a suboptimal policy. If the policy stopped changing at some \(\pi\), the averages would converge to \(q_\pi\), and the greedy step would then change \(\pi\) unless \(\pi\) were already optimal. So the only stable point is optimal. What that argument does not show is that the process ever settles. Sutton & Barto call the convergence of MCES "one of the most fundamental open theoretical questions in reinforcement learning".

The difficulty is that \(Q(s, a)\) is not an estimate of any single policy's action value. It averages returns generated by a sequence of different policies, weighted by the random order in which pairs happened to be visited, while the policy changes asynchronously, one state at a time. The current state of knowledge, roughly:

  • Bertsekas & Tsitsiklis (1996) give a counterexample showing that a version of the algorithm need not converge.
  • Tsitsiklis (2002) proves convergence when the estimates of all state–action pairs are updated at the same rate and \(\gamma < 1\), which is not how MCES is run in practice.
  • Wang, Yuan, Shao & Ross (2022) prove almost-sure convergence of the original algorithm for "optimal policy feed-forward" MDPs, in which an optimal policy never revisits a state within an episode. Blackjack is one; general MDPs remain open.

Treat MCES as a well-behaved heuristic in feed-forward problems, and as a stepping stone to the methods that come next.

Full implementation on Blackjack

Exploring starts are easy here because we control the simulator: deal any of the 200 states and force either first action. Following S&B Example 5.3, the initial policy is stick-on-20 and \(Q\) starts at zero.

import random
from collections import defaultdict

STATES = [(s, d, u) for s in range(12, 22) for d in range(1, 11) for u in (False, True)]
# the exact optimal policy, derived by DP on Day 41: stick iff the sum reaches a threshold
STICK_AT = {False: dict(zip(range(1, 11), (17, 13, 13, 12, 12, 12, 17, 17, 17, 17))),
            True:  dict(zip(range(1, 11), (19, 18, 18, 18, 18, 18, 18, 18, 19, 19)))}

def mc_exploring_starts(n_episodes, seed=0):

What breaks
  • Scoring by matching cells. Near-tie states (hard 12 against 4, 16 against 10) flip back and forth for millions of episodes. Count mismatches if you like, but judge the policy by its return.
  • Averaging stale returns. Early returns were generated by bad policies, and a sample average never forgets them. That slows MCES down, though it does not stop it here. A constant step size forgets faster, at the cost of extra noise.
  • Exploring starts that aren't. Starting in a random state but taking \(\pi(S_0)\) explores nothing at that state. Both the state and the first action must be random.
  • Tie-breaking before any data. With \(Q = 0\) everywhere, the argmax silently prefers whichever action comes first. Harmless with exploring starts, which will try both anyway; harmful without them (Day 36).

DAY 38

On-Policy MC Control with ε-Soft Policies

40m video90m practice

Drop exploring starts by never letting the policy become deterministic: keep every action's probability at least \(\varepsilon/|\mathcal A|\). The policy improvement theorem still holds inside that class, so on-policy Monte Carlo control finds the best \(\varepsilon\)-soft policy, which is close to optimal but not optimal unless \(\varepsilon\) is decayed, and decayed with care.

ε-greedy as an ε-soft policy

Definition · soft, ε-soft, ε-greedy

A policy is soft if \(\pi(a \mid s) > 0\) for every state and action, and \(\varepsilon\)-soft if \(\pi(a \mid s) \ge \varepsilon/|\mathcal A(s)|\). The \(\varepsilon\)-greedy policy with respect to \(Q\) gives the greedy action probability \(1 - \varepsilon + \varepsilon/|\mathcal A(s)|\) and every other action \(\varepsilon/|\mathcal A(s)|\).

Every \(\varepsilon\)-greedy policy is \(\varepsilon\)-soft, and among all \(\varepsilon\)-soft policies it is the one closest to greedy: it puts as much probability on the best action as the constraint allows. That makes it the natural "improvement" step within the class.

Dropping exploring starts

If the policy itself always explores, episodes can start wherever the environment puts them. Every action keeps being tried in every state the policy visits, so the action values of all reachable pairs keep improving.

Algorithm · On-policy first-visit MC control (ε-soft)
  1. Choose \(\varepsilon > 0\). Initialise \(Q(s, a)\) arbitrarily, \(N(s, a) \leftarrow 0\), and \(\pi\) to any \(\varepsilon\)-soft policy.
  2. Repeat for each episode:
    1. Generate an episode following \(\pi\), from the environment's own start distribution.
    2. \(G \leftarrow 0\). For \(t = T-1, \dots, 0\): \(G \leftarrow \gamma G + R_{t+1}\); if \((S_t, A_t)\) is a first visit:
      1. \(N(S_t, A_t) \mathrel{+}= 1\); \(Q(S_t, A_t) \mathrel{+}= \frac{1}{N(S_t, A_t)}[G - Q(S_t, A_t)]\)
      2. \(A^* \leftarrow \argmax_a Q(S_t, a)\); for all \(a\): \(\pi(a \mid S_t) \leftarrow 1 - \varepsilon + \varepsilon/|\mathcal A|\) if \(a = A^*\), else \(\varepsilon/|\mathcal A|\)

The policy improvement theorem for ε-soft policies

Theorem · ε-greedy improvement

Let \(\pi\) be any \(\varepsilon\)-soft policy and \(\pi'\) the \(\varepsilon\)-greedy policy with respect to \(q_\pi\). Then \(v_{\pi'}(s) \ge v_\pi(s)\) for every \(s\).

Proof (S&B §5.4)

Write \(m = |\mathcal A(s)|\). For every state \(s\),

$$\begin{aligned} \sum_a \pi'(a \mid s)\, q_\pi(s, a) &= \frac{\varepsilon}{m} \sum_a q_\pi(s, a) + (1 - \varepsilon) \max_a q_\pi(s, a) \\ &\ge \frac{\varepsilon}{m} \sum_a q_\pi(s, a) + (1 - \varepsilon) \sum_a \frac{\pi(a \mid s) - \varepsilon/m}{1 - \varepsilon}\, q_\pi(s, a) \\ &= \frac{\varepsilon}{m} \sum_a q_\pi(s, a) - \frac{\varepsilon}{m} \sum_a q_\pi(s, a) + \sum_a \pi(a \mid s)\, q_\pi(s, a) = v_\pi(s). \end{aligned}$$

The inequality holds because the weights \(\big(\pi(a \mid s) - \varepsilon/m\big)/(1 - \varepsilon)\) are non-negative (that is exactly the \(\varepsilon\)-soft condition) and sum to 1 (since \(\sum_a \pi(a \mid s) = 1\) and \(\sum_a \varepsilon/m = \varepsilon\)), and a weighted average never exceeds the maximum. The hypothesis of the stochastic policy improvement theorem (Day 29) therefore holds at every state, and \(v_{\pi'} \ge v_\pi\).

The ε-soft optimality caveat

When does the improvement stop? S&B's argument moves the randomness into the environment. Imagine a modified environment that, with probability \(\varepsilon\), ignores the agent's chosen action and substitutes a uniformly random one. Any policy in the new environment behaves like an \(\varepsilon\)-soft policy in the old one, so the best value achievable there, \(\tilde v_*\), is the best value achievable by \(\varepsilon\)-soft policies here. It is the unique solution of

$$\tilde v_*(s) = (1 - \varepsilon) \max_a \tilde q_*(s, a) + \frac{\varepsilon}{m} \sum_a \tilde q_*(s, a), \qquad \tilde q_*(s, a) = \sum_{s', r} p(s', r \mid s, a)\big[r + \gamma \tilde v_*(s')\big],$$

unique because the right-hand side is again a \(\gamma\)-contraction (Day 32). If \(\varepsilon\)-greedy improvement leaves \(\pi\) unchanged, then \(\pi\) is \(\varepsilon\)-greedy with respect to its own \(q_\pi\), and substituting shows \(v_\pi\) satisfies exactly this equation, so \(v_\pi = \tilde v_*\). The algorithm therefore converges (in the idealised policy-iteration sense) to the best \(\varepsilon\)-soft policy, not to \(\pi_*\).

GLIE

Definition · GLIE (Singh, Jaakkola, Littman & Szepesvári 2000)

A sequence of policies is greedy in the limit with infinite exploration if

  1. every state–action pair is visited infinitely often, and
  2. the policies converge to greedy: \(\lim_{k \to \infty} \pi_k(a \mid s) = \mathbb 1\{a = \argmax_{a'} Q_k(s, a')\}\).

\(\varepsilon\)-greedy with a state-dependent rate \(\varepsilon(s) = c/n(s)\), where \(n(s)\) counts visits to \(s\), is GLIE: \(\varepsilon \to 0\), and because \(\sum_n c/n = \infty\), every action is still tried infinitely often (the second Borel–Cantelli lemma, since the exploration coin flips are independent). GLIE is the condition under which SARSA is proved to converge to \(q_*\) (Singh et al. 2000), and David Silver's lectures state the corresponding result for GLIE Monte Carlo control; a rigorous proof for the Monte Carlo version runs into the same averaging-across-policies difficulty as MCES.

def on_policy_mc(n_episodes, epsilon, seed=0):
    """First-visit on-policy MC control with an epsilon-greedy (hence epsilon-soft) policy.
    epsilon(n) is the exploration rate at a state that has now been visited n times."""
    env, rng = Blackjack(seed), random.Random(seed + 1)
    Q, N, visits = defaultdict(float), defaultdict(int), defaultdict(int)
    greedy = lambda s: 0 if Q[s, 0] >= Q[s, 1] else 1
    def act(s):                                     # improvement is implicit: act() reads Q
        visits[s] += 1
        return rng.randint(0, 1) if rng.random() < epsilon(visits[s]) else greedy(s)
    for _ in range(n_episodes):
        G = 0.0
        for s, a, r in reversed(play_episode(env, act)):
            G += r
            N[s, a] += 1
            Q[s, a] += (G - Q[s, a]) / N[s, a]
    return {s: greedy(s) for s in STATES}

What breaks
  • Reporting the behaviour policy's return. The returns you observe during training include the exploration. Evaluate the greedy policy separately, with \(\varepsilon = 0\), before comparing methods.
  • Decaying too fast. A schedule that hits a tiny \(\varepsilon\) before the values settle locks in whatever the noise said at the time. If the learning curve flattens early at a poor level, suspect the schedule before the algorithm.
  • Never decaying, and calling it optimal. A constant \(\varepsilon\) converges, at best, to the best \(\varepsilon\)-soft policy. That is a different policy, and in risky tasks a noticeably different one.
  • Episode-based schedules on unevenly visited states. \(\varepsilon_k = 1/k\) per episode decays the same everywhere, so rare states stop exploring long before they have been explored. State-dependent counts \(n(s)\) avoid this.

DAY 39

Off-Policy Prediction & Importance Sampling

45m video90m practice

To learn about one policy from data generated by another, reweight each return by how much more (or less) likely its trajectory is under the policy you care about. The reweighting is exact in expectation and needs no model. The price is variance, and sometimes that variance is infinite.

Behaviour policy b vs target policy π

On-policy control is a compromise: it learns the values of a policy that still explores, so it can only reach the best \(\varepsilon\)-soft policy (Day 38). Off-policy methods separate the two jobs. The target policy \(\pi\) is the one we want to evaluate or improve, typically greedy. The behaviour policy \(b\) generates the data and does the exploring. On-policy learning is the special case \(b = \pi\).

Separating them buys a lot: you can learn the greedy policy while acting exploratorily, learn from logged data produced by someone else (a human, an older version of the system, a fixed rule), and learn about many policies from one stream of experience. The cost is variance and slower learning. Today's problem is prediction: \(\pi\) and \(b\) are both fixed and known, and we want \(v_\pi\) or \(q_\pi\) from episodes generated by \(b\).

The coverage assumption

Definition · coverage

\(b\) covers \(\pi\) if \(\pi(a \mid s) > 0\) implies \(b(a \mid s) > 0\): every action the target might take, the behaviour policy takes at least sometimes.

It is a necessary condition, not a technicality. If \(b\) never takes an action that \(\pi\) takes, the data contain no information about what that action leads to, and no reweighting can invent it. Coverage forces \(b\) to be stochastic wherever it differs from \(\pi\), while \(\pi\) itself may be deterministic, which is the case that matters for control.

The importance-sampling ratio

Start at \(S_t\) and look at the rest of the episode, \(A_t, S_{t+1}, A_{t+1}, \dots, S_T\). Its probability under \(\pi\) is \(\prod_{k=t}^{T-1} \pi(A_k \mid S_k)\, p(S_{k+1} \mid S_k, A_k)\), and similarly under \(b\). Their ratio is

$$\rho_{t:T-1} \doteq \prod_{k=t}^{T-1} \frac{\pi(A_k \mid S_k)\, p(S_{k+1} \mid S_k, A_k)}{b(A_k \mid S_k)\, p(S_{k+1} \mid S_k, A_k)} = \prod_{k=t}^{T-1} \frac{\pi(A_k \mid S_k)}{b(A_k \mid S_k)}.$$

The dynamics cancel. The ratio depends only on the two policies and the actions that were actually taken, so computing it needs no model.

Theorem · importance sampling is unbiased

If \(b\) covers \(\pi\), then \(\E_b\big[\rho_{t:T-1}\, G_t \mid S_t = s\big] = v_\pi(s)\).

Proof

Sum over the possible continuations \(\tau = (A_t, S_{t+1}, \dots, S_T)\) that have positive probability under \(b\), writing \(G(\tau)\) for the return along \(\tau\) and \(\Pr_b(\tau \mid s)\), \(\Pr_\pi(\tau \mid s)\) for its probabilities:

$$\E_b\big[\rho\, G \mid S_t = s\big] = \sum_{\tau:\, \Pr_b(\tau \mid s) > 0} \Pr_b(\tau \mid s)\, \frac{\Pr_\pi(\tau \mid s)}{\Pr_b(\tau \mid s)}\, G(\tau) = \sum_{\tau:\, \Pr_b(\tau \mid s) > 0} \Pr_\pi(\tau \mid s)\, G(\tau) = v_\pi(s).$$

The last step is where coverage enters. Every \(\tau\) with \(\Pr_\pi(\tau \mid s) > 0\) uses only actions that \(\pi\) takes, hence actions that \(b\) takes, so it also has \(\Pr_b(\tau \mid s) > 0\) and appears in the sum. Without coverage, trajectories that \(\pi\) can produce would be missing, and the estimate would be biased.

Ordinary importance sampling

Number time steps consecutively across episodes, let \(\mathcal T(s)\) be the set of (first-)visit times to \(s\), and \(T(t)\) the termination time of the episode containing \(t\). Ordinary importance sampling averages the reweighted returns:

$$V(s) = \frac{\sum_{t \in \mathcal T(s)} \rho_{t:T(t)-1}\, G_t}{|\mathcal T(s)|}.$$

With first visits, each term is an independent sample of \(\rho G\) whose mean is \(v_\pi(s)\) by the theorem, so the estimate is unbiased. Its variance, however, is governed by \(\E_b[\rho^2 G^2]\), and ratios are products: if \(\pi\) is deterministic and \(b\) picks uniformly between two actions, any episode in which \(b\) happens to agree with \(\pi\) for \(k\) steps gets weight \(2^k\), and every other episode gets weight 0. The variance of ordinary IS is unbounded in general, and can be infinite.

Weighted importance sampling

Weighted importance sampling normalises by the total weight instead of the count:

$$V(s) = \frac{\sum_{t \in \mathcal T(s)} \rho_{t:T(t)-1}\, G_t}{\sum_{t \in \mathcal T(s)} \rho_{t:T(t)-1}} \qquad (\text{and } 0 \text{ if the denominator is } 0).$$
  • Biased. With a single return the ratio cancels and the estimate is just \(G\), whose expectation is \(v_b(s)\), not \(v_\pi(s)\). The bias shrinks to zero as data accumulate: the estimator is consistent.
  • Bounded. It is a weighted average of observed returns, so it can never leave the range of the returns. With bounded returns its variance converges to zero even when the ratios themselves have infinite variance (S&B, citing Precup, Sutton & Dasgupta 2001).
  • Preferred in practice. Its far lower variance almost always outweighs its vanishing bias.

Every-visit versions of both estimators exist; both are then biased, but they need no first-visit bookkeeping and extend more naturally to function approximation, so they are often used in practice. A concrete infinite-variance example

Derivation · the variance is infinite

Under \(b\), only episodes made entirely of lefts have nonzero \(\rho G\). An episode of \(k\) lefts that loops back \(k - 1\) times and then exits has probability \((\tfrac12 \cdot 0.9)^{k-1}(\tfrac12 \cdot 0.1)\), ratio \(\rho = 2^k\), and return \(G = 1\). So

$$\E_b[\rho G] = \sum_{k \ge 1} 0.45^{k-1} \cdot 0.05 \cdot 2^k = 0.1 \sum_{j \ge 0} 0.9^j = 1 = v_\pi(s), \qquad \E_b\big[(\rho G)^2\big] = \sum_{k \ge 1} 0.45^{k-1} \cdot 0.05 \cdot 4^k = 0.2 \sum_{j \ge 0} 1.8^j = \infty.$$

The mean is right, as the theorem promised, but the second moment diverges, so the variance of every ordinary-IS estimate built from these samples is infinite. The law of large numbers still applies (the mean is finite), so the estimate does converge, but there is no central limit theorem and no useful rate. S&B show ordinary IS still visibly off after 100 million episodes.

import numpy as np

def one_state_episode(rng):
    """S&B Example 5.5 run under b(left) = b(right) = 1/2; target pi = always left, gamma = 1.
    Returns (rho, G): the episode's importance ratio and return."""
    rho = 1.0
    while True:
        if rng.random() < 0.5:            # right: episode ends with reward 0, and pi(right) = 0
            return 0.0, 0.0
        rho *= 1.0 / 0.5                  # left: pi(left) / b(left) = 2
        if rng.random() < 0.1:            # left ends the episode with +1 w.p. 0.1 ...
            return rho, 1.0               # ... otherwise it loops back to s with reward 0

What breaks
  • Missing coverage. A behaviour policy that never takes some action of \(\pi\) (say, a greedy logging policy) produces ratios that are silently wrong, not undefined: the trajectories that would have carried the weight simply never appear. Assert \(b(a \mid s) > 0\) wherever \(\pi(a \mid s) > 0\).
  • Off-by-one in the ratio. For \(V(S_t)\) the product starts at \(t\) (it includes \(A_t\)). For \(Q(S_t, A_t)\) it starts at \(t+1\): the action is given, so it needs no correction.
  • Recomputing b later. Store \(b(A_t \mid S_t)\) at the moment the action is taken. If \(b\) changes during learning (an \(\varepsilon\)-greedy policy built on a changing \(Q\)), recomputing it afterwards gives the wrong ratio.
  • Overflow and underflow. Products of hundreds of ratios overflow or round to zero. Accumulate \(\log\rho\), or keep episodes short; clipping ratios is a common fix but introduces bias (Day 121's V-trace does this on purpose).
  • Weighted IS with zero total weight. Until some episode has nonzero weight, the weighted estimate is undefined. Decide what you report (0, or a prior value) and say so.

Incremental & Per-Decision IS

40m video75m practice

Weighted importance sampling fits the same incremental update as every other average, with the step size replaced by a ratio of weights. Plugged into GPI it gives off-policy Monte Carlo control. Two refinements, per-decision and discounting-aware importance sampling, cut variance by refusing to multiply a reward by ratios that could not have affected it.

The incremental weighted-IS update

Derivation · cumulative weight C

Suppose a state has received returns \(G_1, \dots, G_n\) with weights \(W_1, \dots, W_n\) (each \(W_k\) is that return's ratio). Let \(C_n = \sum_{k \le n} W_k\) and \(V_n = \sum_{k \le n} W_k G_k / C_n\). Then

$$C_n V_n = C_{n-1} V_{n-1} + W_n G_n = (C_n - W_n)\, V_{n-1} + W_n G_n,$$

and dividing by \(C_n\):

$$V_n = V_{n-1} + \frac{W_n}{C_n}\big[G_n - V_{n-1}\big], \qquad C_n = C_{n-1} + W_n, \qquad C_0 = 0.$$

The step size \(W_n/C_n\) plays the role of \(1/n\). With every weight equal to 1 it is \(1/n\), and the update is on-policy MC again. A return with weight 0 changes nothing, and a return with a large weight moves the estimate a long way, but never past the new return itself, since \(W_n/C_n \le 1\).

The running-weight trick

Each time step needs its own ratio \(\rho_{t:T-1}\), and computing each product from scratch costs \(O(T^2)\) per episode. Walking backwards, the ratios nest: \(\rho_{t:T-1} = \frac{\pi(A_t \mid S_t)}{b(A_t \mid S_t)}\, \rho_{t+1:T-1}\). So keep one running weight \(W\), starting at 1 at the end of the episode, and multiply in one factor per step. For action values, the pair \((S_t, A_t)\) needs \(\rho_{t+1:T-1}\), the ratio of the actions after \(A_t\), so update \(Q(S_t, A_t)\) with the current \(W\) first and multiply by the factor for \(A_t\) afterwards. Once \(W\) hits zero, every earlier step has weight zero too, and the loop can stop.

Algorithm · Off-policy MC prediction of qπ (weighted, incremental)
  1. Initialise \(Q(s, a)\) arbitrarily and \(C(s, a) \leftarrow 0\).
  2. For each episode, generated by any \(b\) that covers \(\pi\):
    1. \(G \leftarrow 0\), \(W \leftarrow 1\)
    2. For \(t = T-1, \dots, 0\), while \(W \ne 0\):
      1. \(G \leftarrow \gamma G + R_{t+1}\)
      2. \(C(S_t, A_t) \leftarrow C(S_t, A_t) + W\)
      3. \(Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \frac{W}{C(S_t, A_t)}\big[G - Q(S_t, A_t)\big]\)
      4. \(W \leftarrow W\, \pi(A_t \mid S_t) / b(A_t \mid S_t)\)

Off-policy MC control

Now let the target be greedy with respect to \(Q\), and let \(b\) be any soft policy. Because \(\pi\) is deterministic, \(\pi(A_t \mid S_t)\) is 1 if \(A_t\) is the greedy action and 0 otherwise. So the weight update becomes \(W \leftarrow W / b(A_t \mid S_t)\), and the loop ends the first time (walking backwards) that the behaviour took a non-greedy action.

Algorithm · Off-policy MC control (S&B §5.7)
  1. Initialise \(Q(s, a)\) arbitrarily, \(C(s, a) \leftarrow 0\), \(\pi(s) \leftarrow \argmax_a Q(s, a)\).
  2. For each episode:
    1. Pick any soft \(b\) and generate an episode with it, recording \(b(A_t \mid S_t)\).
    2. \(G \leftarrow 0\), \(W \leftarrow 1\). For \(t = T-1, \dots, 0\):
      1. \(G \leftarrow \gamma G + R_{t+1}\); \(C(S_t, A_t) \mathrel{+}= W\); \(Q(S_t, A_t) \mathrel{+}= \frac{W}{C(S_t, A_t)}[G - Q(S_t, A_t)]\)
      2. \(\pi(S_t) \leftarrow \argmax_a Q(S_t, a)\)
      3. If \(A_t \ne \pi(S_t)\), exit the loop. (earlier steps would get weight 0)
      4. \(W \leftarrow W / b(A_t \mid S_t)\)

def off_policy_mc_control(n_episodes, seed=0):
    """Off-policy MC control with incremental weighted importance sampling (S&B section 5.7)."""
    env, rng = Blackjack(seed), random.Random(seed + 1)
    Q, C = defaultdict(float), defaultdict(float)             # C = cumulative IS weight per pair
    target = {s: 0 if s[0] >= 20 else 1 for s in STATES}      # greedy target policy pi
    behaviour = lambda s: rng.randint(0, 1)                   # b(a|s) = 1/2: soft, covers pi
    for _ in range(n_episodes):
        G, W = 0.0, 1.0
        for s, a, r in reversed(play_episode(env, behaviour)):
            G += r                                            # gamma = 1
            C[s, a] += W
            Q[s, a] += (W / C[s, a]) * (G - Q[s, a])          # weighted running average
            target[s] = 0 if Q[s, 0] >= Q[s, 1] else 1
            if a != target[s]:
                break                                         # pi(a|s) = 0: earlier steps get weight 0
            W /= 0.5                                          # W *= pi(a|s) / b(a|s) = 1 / 0.5
    return target

Per-decision importance sampling

Ordinary IS multiplies the whole return by the whole ratio. But a reward cannot depend on actions taken after it was received, so the later factors only add noise.

Derivation · dropping the factors that come after a reward

Expand \(\rho_{t:T-1} G_t = \sum_{k=t}^{T-1} \gamma^{k-t}\, \rho_{t:T-1} R_{k+1}\) and split one term as \(\rho_{t:k} R_{k+1} \cdot \rho_{k+1:T-1}\). A single ratio has conditional mean 1 under \(b\):

$$\E_b\!\left[\frac{\pi(A_j \mid S_j)}{b(A_j \mid S_j)} \,\middle|\, S_j\right] = \sum_a b(a \mid S_j)\, \frac{\pi(a \mid S_j)}{b(a \mid S_j)} = \sum_a \pi(a \mid S_j) = 1.$$

Condition on everything up to \(R_{k+1}\) and apply this to the factors \(j = T-1, T-2, \dots, k+1\) one at a time with the tower rule: \(\E_b[\rho_{k+1:T-1} \mid \text{history to } R_{k+1}] = 1\). Since \(\rho_{t:k} R_{k+1}\) is fixed by that history, \(\E_b[\rho_{t:T-1} R_{k+1}] = \E_b[\rho_{t:k} R_{k+1}]\). Summing over \(k\),

$$\E_b\big[\rho_{t:T-1} G_t\big] = \E_b\big[\tilde G_t\big], \qquad \tilde G_t = \sum_{k=t}^{T-1} \gamma^{k-t}\, \rho_{t:k}\, R_{k+1}.$$

The per-decision estimator \(V(s) = \sum_{t \in \mathcal T(s)} \tilde G_t / |\mathcal T(s)|\) is unbiased, like ordinary IS, with lower variance: each reward carries only the ratios of the actions that preceded it. It also has a recursive form, \(\tilde G_t = \rho_t\,\big(R_{t+1} + \gamma \tilde G_{t+1}\big)\) with \(\tilde G_T = 0\), which is exactly the structure off-policy \(n\)-step TD uses on Day 49. One gap remains: S&B note that every weighted (normalised) per-decision estimator proposed so far is inconsistent, so per-decision IS is used in its ordinary form.

Discounting-aware importance sampling

When \(\gamma < 1\), think of discounting as a chance of the episode ending: with probability \(1 - \gamma\) after each step. Then the return is a mixture of undiscounted flat partial returns \(\bar G_{t:h} = R_{t+1} + R_{t+2} + \cdots + R_h\):

$$G_t = (1 - \gamma) \sum_{h=t+1}^{T-1} \gamma^{h-t-1}\, \bar G_{t:h} \;+\; \gamma^{T-t-1}\, \bar G_{t:T}.$$

(Check: the coefficient on \(R_j\) is \(\sum_{h=j}^{T-1} (1-\gamma)\gamma^{h-t-1} + \gamma^{T-t-1} = \gamma^{j-t-1}(1 - \gamma^{T-j}) + \gamma^{T-t-1} = \gamma^{j-t-1}\), as it should be.) Each flat partial return \(\bar G_{t:h}\) depends only on actions up to \(A_{h-1}\), so it needs only the ratio \(\rho_{t:h-1}\). Reweight each piece by its own ratio:

$$N_t = (1 - \gamma) \sum_{h=t+1}^{T(t)-1} \gamma^{h-t-1}\, \rho_{t:h-1}\, \bar G_{t:h} + \gamma^{T(t)-t-1}\, \rho_{t:T(t)-1}\, \bar G_{t:T(t)}, \qquad D_t = (1 - \gamma) \sum_{h=t+1}^{T(t)-1} \gamma^{h-t-1}\, \rho_{t:h-1} + \gamma^{T(t)-t-1}\, \rho_{t:T(t)-1}.$$

The discounting-aware estimators are then

$$V_{\text{ordinary}}(s) = \frac{\sum_{t \in \mathcal T(s)} N_t}{|\mathcal T(s)|}, \qquad V_{\text{weighted}}(s) = \frac{\sum_{t \in \mathcal T(s)} N_t}{\sum_{t \in \mathcal T(s)} D_t}.$$

import numpy as np

def is_estimates(rewards, ratios, gamma):
    """Three estimates of G_0 under pi, each unbiased, from one episode generated by b.
    rewards[k] = R_{k+1}, ratios[k] = pi(A_k | S_k) / b(A_k | S_k)."""
    T = len(rewards)
    rho = np.cumprod(ratios)                         # rho[k] = rho_{0:k}
    disc = gamma ** np.arange(T)
    ordinary = rho[-1] * np.sum(disc * rewards)      # every reward carries the full product
    per_decision = np.sum(disc * rho * rewards)      # R_{k+1} carries only rho_{0:k}
    h = np.arange(1, T + 1)                          # flat partial returns G_bar_{0:h}
    w = np.where(h < T, (1 - gamma) * gamma ** (h - 1), gamma ** (T - 1))
    discount_aware = np.sum(w * rho * np.cumsum(rewards))   # G_bar_{0:h} carries rho_{0:h-1}
    return ordinary, per_decision, discount_aware

# a 20-step task: reward 1 whenever action 0 is taken; pi(0) = 0.9, b(0) = 0.5
rng, T, gamma = np.random.default_rng(0), 20, 0.9
true_v = 0.9 * (1 - gamma ** T) / (1 - gamma)
est = []
for _ in range(100_000):
    a = rng.random(T) < 0.5                          # True means action 0, drawn from b
    est.append(is_estimates(a.astype(float), np.where(a, 0.9 / 0.5, 0.1 / 0.5), gamma))
est = np.array(est)
print(f"true v = {true_v:.3f}")

The tail-collapse problem in long episodes

Off-policy MC control learns only from the tail of each episode, the part after the last action on which \(b\) disagreed with the greedy target. If \(b\) is \(\varepsilon\)-greedy over \(|\mathcal A|\) actions, the chance that the last \(k\) actions all agree with the target is \((1 - \varepsilon + \varepsilon/|\mathcal A|)^k\). With \(\varepsilon = 0.1\) and four actions that is 0.46 for \(k = 10\), 0.02 for \(k = 50\), and 0.0004 for \(k = 100\). States more than a few dozen steps from the end of an episode almost never receive an update, and early states in long episodes are exactly the ones that matter. S&B flag this as the method's main weakness.

With a stochastic target the same thing happens more gradually: the variance of a product of \(k\) ratios grows like \(\big(\E_b[\rho^2]\big)^k\), exponentially in the horizon, and the effective sample size \(\big(\sum W\big)^2 / \sum W^2\) of a batch of weighted returns collapses towards 1 as episodes get longer. The cures come later in the course: bootstrapping, so that each update needs only one ratio or none (Q-learning on Day 45, off-policy \(n\)-step methods and tree backup on Day 49), and truncated, clipped ratios (Retrace; V-trace on Day 121).

What breaks
  • Exiting too early. The pair \((S_t, A_t)\) is updated from the tail after it, whether or not \(A_t\) is greedy. Update first, then test \(A_t \ne \pi(S_t)\). Testing first throws away the most useful update in every episode.
  • Dividing by today's b. If \(b\) is \(\varepsilon\)-greedy on a changing \(Q\), divide by the probability recorded when the action was taken.
  • A behaviour policy that becomes greedy. As \(\varepsilon \to 0\), \(b(A_t \mid S_t)\) for exploratory actions shrinks and \(W\) explodes, while the episodes that agree with the target carry ever less information. Keep \(b\) genuinely soft.
  • Trusting a flat learning curve. If almost every episode exits after one step, the method is learning only about states near the end. Log the average tail length.

The answer key: exact DP on an infinite deck

With an infinite deck every card is drawn independently with known probabilities (1/13 each for ace to 9, 4/13 for a ten-card), so the game is a small, known MDP and the methods of Module 3 solve it exactly. The dealer's final total depends only on the showing card; a player hand's value depends only on its total, whether it holds an ace, and the dealer's card. Since hitting always increases the hard total, the recursion has no cycles and memoisation evaluates it in a fraction of a second.

from functools import lru_cache

CARDS = range(1, 11)
P_CARD = {c: (4 if c == 10 else 1) / 13 for c in CARDS}      # infinite deck

def total(hard, ace):                                       # (sum, usable ace?)
    return (hard + 10, True) if ace and hard + 10 <= 21 else (hard, False)

@lru_cache(None)
def dealer(hard, ace):
    """Distribution of the dealer's final total (22 = bust) from hard total and has-ace flag."""
    s = total(hard, ace)[0]
    if s >= 17:                                             # dealer stands on 17+, soft 17 included
        return {min(s, 22): 1.0}
    out = {}
    for c in CARDS:
        for k, p in dealer(hard + c, ace or c == 1).items():
            out[k] = out.get(k, 0.0) + P_CARD[c] * p
    return out

@lru_cache(None)
def stick(s, up):                                           # expected reward for sticking on s
    value = 0.0
    for hidden in CARDS:
        for k, p in dealer(up + hidden, up == 1 or hidden == 1).items():
            value += P_CARD[hidden] * p * (1.0 if k == 22 or s > k else 0.0 if s == k else -1.0)
    return value

@lru_cache(None)
def v_star(hard, ace, up):                                  # optimal value of a player hand
    s = total(hard, ace)[0]
    if s > 21:
        return -1.0
    hit = sum(P_CARD[c] * v_star(hard + c, ace or c == 1, up) for c in CARDS)
    return hit if s < 12 else max(stick(s, up), hit)

def q_star(s, up, usable):                                  # (stick, hit) action values
    hard = s - 10 if usable else s
    return stick(s, up), sum(P_CARD[c] * v_star(hard + c, usable or c == 1, up) for c in CARDS)

def expected_return(policy):
    """Exact return per hand of policy(sum, up, usable) -> 0 stick / 1 hit, from a fresh deal."""
    @lru_cache(None)
    def V(hard, ace, up):
        s, usable = total(hard, ace)
        if s > 21:
            return -1.0
        if s >= 12 and policy(s, up, usable) == 0:
            return stick(s, up)
        return sum(P_CARD[c] * V(hard + c, ace or c == 1, up) for c in CARDS)
    p_dealer_natural = {1: P_CARD[10], 10: P_CARD[1]}
    ret = 0.0
    for c1 in CARDS:
        for c2 in CARDS:
            for up in CARDS:
                p = P_CARD[c1] * P_CARD[c2] * P_CARD[up]
                if {c1, c2} == {1, 10} and policy(21, up, True) == 0:   # natural, and we stick
                    ret += p * (1.0 - p_dealer_natural.get(up, 0.0))
                else:
                    ret += p * V(c1 + c2, 1 in (c1, c2), up)
    return ret

optimal = lambda s, up, usable: int(q_star(s, up, usable)[1] > q_star(s, up, usable)[0])
stick_on_20 = lambda s, up, usable: 0 if s >= 20 else 1
print(f"optimal {expected_return(optimal):+.4f}   stick-on-20 {expected_return(stick_on_20):+.4f}")
