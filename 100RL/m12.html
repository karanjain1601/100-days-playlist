Imitation & Offline RL

Seven lessons on learning without trial and error: from an expert's demonstrations (behaviour cloning, DAgger, inverse RL, adversarial imitation) and from a fixed log of someone else's experience (offline RL). One problem runs through both halves: distribution shift. A policy trained on someone else's data is judged on the states and actions it chooses itself. Module 11 assumed the agent could collect whatever data it needed; Module 13 returns to online agents and adds hierarchy, meta-learning, multiple agents and scale.

DAY 106

Behavior Cloning & DAgger

40m video105m practice

Behaviour cloning is supervised learning on an expert's state–action pairs, and it fails in a specific, predictable way. The learner's small mistakes take it into states the expert never visited, where its mistakes get worse, and the cost gap grows with the square of the horizon. DAgger fixes this by collecting expert labels on the states the learner itself visits, which makes the gap linear.

Imitation as supervised learning

Roll out an expert \(\pi^*\) and record \(\mathcal D = \{(s_i, a^*_i)\}\). Behaviour cloning (BC) fits a policy by maximum likelihood:

$$\hat\pi = \argmin_{\pi}\ \E_{s \sim d_{\pi^*}}\big[\ell\big(\pi(\cdot \mid s), \pi^*(s)\big)\big],$$

with cross-entropy for discrete actions and a Gaussian negative log-likelihood (or MSE) for continuous ones. It needs no reward, no simulator and no interaction, which is why it was the first thing tried: ALVINN (Pomerleau, 1989) steered a van from camera images with a small network trained this way. The catch is in the subscript: the loss is measured on \(d_{\pi^*}\), the expert's state distribution, but the learner will be run on \(d_{\hat\pi}\), its own.

Compounding error and covariate shift

Setup · Ross & Bagnell (2010)

Horizon \(T\); per-step cost \(c(s, a) \in [0, 1]\); \(J(\pi) = \E\big[\sum_{t=1}^{T} c(s_t, a_t)\big]\) under \(\pi\). Let \(\varepsilon_t\) be the probability that \(\hat\pi\) disagrees with the expert on the expert's state distribution at time \(t\), and \(\varepsilon = \frac1T\sum_t \varepsilon_t\): the classification error that supervised training drives down.

Theorem · behaviour cloning is quadratic in the horizon $$J(\hat\pi) \le J(\pi^*) + T^2 \varepsilon,$$

and there are problems where this is tight up to constants.

Proof sketch

As long as \(\hat\pi\) has agreed with the expert at every step so far, it is in the expert's states, where its error rate is \(\varepsilon_t\). Once it makes its first mistake it may be in a state the expert never visited. There it has no training data, nothing guarantees it can recover, and in the worst case it pays cost 1 at every remaining step. A first mistake at step \(t\) therefore costs at most \(T - t + 1 \le T\) extra, and it happens with probability at most \(\varepsilon_t\). Summing over \(t\),

$$J(\hat\pi) - J(\pi^*) \le \sum_{t=1}^{T} \varepsilon_t\,(T - t + 1) \le T \sum_{t=1}^{T} \varepsilon_t = T^2 \varepsilon.$$

The worst case is real: a car that drifts a little towards the kerb sees a view no expert ever recorded, since experts don't drift, so it has no idea that it should steer back.

This is covariate shift: the input distribution at test time differs from the training distribution because of the learner's own actions. A supervised learner with 1% error per step is excellent; a 1,000-step task run by that learner can be a disaster. The data were never wrong, only in the wrong places.

DAgger: let the expert label the learner's mistakes

Ross, Gordon & Bagnell (2011) change where the labels come from rather than how the learner is trained.

Algorithm · DAgger (Dataset Aggregation)
  1. \(\mathcal D \leftarrow\) expert demonstrations (or \(\emptyset\)); train \(\hat\pi_1\) on \(\mathcal D\).
  2. For \(i = 1, \dots, N\):
    1. Run \(\pi_i = \beta_i \pi^* + (1 - \beta_i)\hat\pi_i\) for a few episodes. (β₁ = 1 and then β = 0 is common, or β decaying geometrically)
    2. Ask the expert what it would have done in every state visited: \(\mathcal D_i = \{(s, \pi^*(s))\}\).
    3. Aggregate, \(\mathcal D \leftarrow \mathcal D \cup \mathcal D_i\), and train \(\hat\pi_{i+1}\) on all of \(\mathcal D\).
  3. Return the best \(\hat\pi_i\) on validation rollouts.
Theorem · DAgger is linear in the horizon (Ross et al. 2011)

Let \(\varepsilon_N\) be the loss of the best policy in hindsight on the aggregated data, and suppose that a single deviation from the expert followed by expert play increases the expected cost-to-go by at most \(u\). With \(N = \tilde O(uT)\) iterations, some \(\hat\pi_i\) in the sequence satisfies

$$J(\hat\pi_i) \le J(\pi^*) + u\,T\,\varepsilon_N + O(1).$$

Why linear? DAgger is a reduction to no-regret online learning. Each iteration is a round in which the learner suffers its classification loss on the states its own policy reached. Training on all data so far ("follow the leader") is a no-regret strategy for well-behaved losses, so on average the learner does as well on its own distributions as the best fixed policy would. Errors are now measured where the learner actually goes, and each one costs at most \(u\) (the expert can recover from it) instead of the rest of the episode. When the expert can recover quickly, \(u\) is a small constant; in the worst case \(u = T\) and nothing is gained. The price is an interactive expert: someone or something that can label arbitrary states, including states it would never have reached itself.

import gymnasium as gym
import numpy as np
import torch
import torch.nn as nn
import torch.nn.functional as F

def expert(obs):                                   # a PD controller that balances CartPole
    return int(obs[2] + 0.5 * obs[3] > 0)          # pole angle + 0.5 * angular velocity

def rollout(env, policy, n_episodes, seed, max_steps=500):
    states, returns = [], []
    for ep in range(n_episodes):
        obs, _ = env.reset(seed=seed + ep)
        done, G, t = False, 0.0, 0
        while not done and t < max_steps:
            states.append(obs)
            obs, r, terminated, truncated, _ = env.step(policy(obs))
            G, t, done = G + r, t + 1, terminated or truncated
        returns.append(G)
    return np.array(states, dtype=np.float32), float(np.mean(returns))

def fit(S, A, epochs=500):
    net = nn.Sequential(nn.Linear(4, 64), nn.Tanh(), nn.Linear(64, 2))
    opt = torch.optim.Adam(net.parameters(), lr=1e-2)
    S_t, A_t = torch.as_tensor(S), torch.as_tensor(A, dtype=torch.long)
    for _ in range(epochs):                         # full-batch cross-entropy: plain classification
        loss = F.cross_entropy(net(S_t), A_t)
        opt.zero_grad()
        loss.backward()
        opt.step()
    return lambda o: int(net(torch.as_tensor(o, dtype=torch.float32)).argmax())

env = gym.make("CartPole-v1")
S, _ = rollout(env, expert, 1, seed=0, max_steps=20)        # BC: one short demonstration
A = np.array([expert(s) for s in S])
pi = fit(S, A)
print("BC return:", rollout(env, pi, 20, seed=1000)[1])
for it in range(5):                                          # DAgger
    S_new, ret = rollout(env, pi, 3, seed=100 + 10 * it)     # run the LEARNER ...
    S = np.concatenate([S, S_new])
    A = np.concatenate([A, [expert(s) for s in S_new]])      # ... and have the expert label its states
    pi = fit(S, A)                                           # retrain on everything so far
    print(f"DAgger iteration {it}: return while collecting {ret:.0f}, dataset size {len(S)}")
print("DAgger return:", rollout(env, pi, 20, seed=1000)[1])

The expert balances all 500 steps on every seed we tried. In a check with a comparable small network, BC from this single 20-step demonstration averaged about half the maximum return, while DAgger reached 500 within one or two iterations. Exact numbers vary with the seed and the network, so run several seeds.

When BC is enough

BC is the default in much of modern robot learning, and often works. The bound explains when.

  • The data cover the learner's mistakes. Inject noise into the expert's actions while recording its intended actions (DART; Laskey et al., 2017), so the data contain recoveries. NVIDIA's end-to-end driving system (Bojarski et al., 2016) added cameras mounted to the left and right of the centre camera, and labelled their images with steering corrections that would bring the car back to the lane centre.
  • Mistakes wash out. If the dynamics are self-stabilizing or the horizon is short, \(u\) is small and the \(T^2\) never materializes.
  • ε is tiny. With a great deal of consistent data and an expressive policy class, the per-step error can be made small enough that \(T^2\varepsilon\) is acceptable. Predicting chunks of several future actions at once (action chunking) also shortens the effective horizon over which errors compound.

Two failures are not about horizon at all. Multimodal demonstrations: if experts pass a tree on the left half the time and on the right half the time, an MSE-trained policy averages the two and drives into the tree; use a mixture, discretized or diffusion-based policy. Causal confusion (de Haan et al., 2019): a driving policy that can see the brake-light indicator on the dashboard learns "brake when the light is on", which predicts the expert perfectly and is causally backwards. More information in the observation can make imitation worse.

Practical data-collection strategy

  • Record demonstrations in the learner's observation space: what the robot's camera sees, not what the human operator sees.
  • Prefer consistent demonstrators or a protocol. Mixed strategies create multimodality.
  • Collect recoveries deliberately: noise injection, perturbations, or human-gated corrections, in which the expert takes over only when the learner starts to fail (HG-DAgger; Kelly et al., 2019). This gets labels on the learner's distribution without asking a human to label states while not in control, which people do poorly.
  • Spend the labelling budget on uncertain states, for example where an ensemble of policies disagrees.
  • Validate by rollouts, with whole trajectories held out. A low validation loss on expert states says nothing about closed-loop performance.
What breaks
  • Covariate shift, which no amount of model capacity fixes if the data never leave the expert's path.
  • Mode averaging with unimodal policies on multimodal data.
  • Causal confusion from observations that contain effects of the expert's own actions.
  • Non-Markovian experts. A human uses memory and intent the state doesn't contain; a memoryless policy can't reproduce that.
  • DAgger's expert requirement. A scripted expert or a planner with privileged information can label anything. A human usually can't, and labels given while not in control are often inconsistent with how the human would really act.

DAY 107

Inverse Reinforcement Learning

45m video90m practice

Inverse RL asks for the reward that explains the expert, on the theory that a reward is a more compact and more transferable description of a task than a policy. The problem is ill-posed, since many rewards explain any behaviour, and each classic method is a different rule for choosing among them: maximum margin, maximum entropy, or a posterior.

Recovering reward from demonstrations

Given an MDP without its reward (states, actions, dynamics, discount) and demonstrations from an expert assumed to be acting well, find a reward \(R\) under which the expert's behaviour is optimal or nearly so. Rewards are usually parameterized as linear in features, \(R(s) = w^\top \phi(s)\), or as a neural network. Russell (1998) posed the problem; Ng & Russell (2000) gave the first algorithms, and the first thing they proved was that the problem, as stated, has too many solutions.

The fundamental ambiguity

  • \(R \equiv 0\) makes every policy optimal, so it "explains" any demonstration. So does any constant.
  • Positive scaling \(cR\) leaves the optimal policies unchanged.
  • Potential-based shaping \(R'(s, a, s') = R(s, a, s') + \gamma\Phi(s') - \Phi(s)\) leaves the optimal policies unchanged too (Day 26). At best a reward can be identified up to shaping, and from a finite set of demonstrations, not even that.
Derivation · Ng & Russell's characterization

Take a finite MDP with state rewards \(R \in \R^{S}\), and suppose the expert takes action \(a_1\) in every state (relabel actions so this holds). Its value is \(v = (I - \gamma P_{a_1})^{-1} R\). The policy is optimal if and only if no one-step deviation improves on it, \(P_{a_1} v \succeq P_a v\) for every \(a\), componentwise. Substituting \(v\):

$$\big(P_{a_1} - P_a\big)\big(I - \gamma P_{a_1}\big)^{-1} R \;\succeq\; 0 \qquad \text{for all } a.$$

The solution set is a convex cone, and it contains \(R = 0\). Ng & Russell pick one point in it by a linear program: maximize the total gap between the expert's action and the best alternative, \(\sum_s \big(Q(s, a_1) - \max_{a \ne a_1} Q(s, a)\big)\), minus an \(L_1\) penalty \(\lambda\|R\|_1\) that prefers simple rewards.

Feature matching and apprenticeship learning

Abbeel & Ng (2004) changed the goal: instead of recovering the reward, find a policy that performs as well as the expert under whatever the true reward is. With \(R(s) = w^\top\phi(s)\), \(\|w\|_2 \le 1\), define the feature expectations of a policy,

$$\mu(\pi) = \E\Big[\sum_{t \ge 0} \gamma^t \phi(s_t) \;\Big|\; \pi\Big], \qquad \text{so that} \qquad V_w(\pi) = w^\top \mu(\pi).$$
Lemma · matching features matches performance

If \(\|\mu(\tilde\pi) - \mu_E\|_2 \le \varepsilon\), then for every \(w\) with \(\|w\|_2 \le 1\): \(|V_w(\tilde\pi) - V_w(\pi_E)| = |w^\top(\mu(\tilde\pi) - \mu_E)| \le \|w\|_2\,\|\mu(\tilde\pi) - \mu_E\|_2 \le \varepsilon\), by Cauchy–Schwarz. The true reward never has to be found.

Algorithm · apprenticeship learning (projection method)
  1. Estimate \(\mu_E\) from the demonstrations. Pick any \(\pi^{(0)}\), compute \(\mu^{(0)}\), and set \(\bar\mu^{(0)} = \mu^{(0)}\).
  2. Repeat for \(i = 1, 2, \dots\):
    1. \(w^{(i)} = \mu_E - \bar\mu^{(i-1)}\), and \(t^{(i)} = \|w^{(i)}\|_2\). Stop if \(t^{(i)} \le \varepsilon\).
    2. RL step: \(\pi^{(i)}\) = an optimal policy for reward \(R = w^{(i)\top}\phi\). Compute \(\mu^{(i)}\).
    3. \(\bar\mu^{(i)}\) = the orthogonal projection of \(\mu_E\) onto the line through \(\bar\mu^{(i-1)}\) and \(\mu^{(i)}\).
  3. Return a mixture of the \(\pi^{(j)}\) whose feature expectations are within \(\varepsilon\) of \(\mu_E\). (terminates within a number of iterations polynomial in k and 1/ε)

The original max-margin variant instead picks \(w^{(i)}\) to maximize \(\min_{j < i} w^\top(\mu_E - \mu^{(j)})\), an SVM-like quadratic program.

Maximum-entropy IRL and the partition function

Feature matching is still ambiguous: many policies, and mixtures of policies, match the expert's features. Ziebart et al. (2008) resolve it with the principle of maximum entropy: among all distributions over trajectories that match the expert's feature counts, choose the one that commits to nothing else.

Derivation · MaxEnt IRL (deterministic dynamics)

Let \(f_\tau = \sum_t \phi(s_t)\) be a trajectory's feature counts and \(\tilde f\) the expert's average. Maximize \(-\sum_\tau P(\tau)\log P(\tau)\) subject to \(\sum_\tau P(\tau) f_\tau = \tilde f\) and \(\sum_\tau P(\tau) = 1\). Setting the derivative of the Lagrangian to zero gives an exponential family, in which the multipliers \(w\) play the role of reward weights:

$$P(\tau \mid w) = \frac{\exp(w^\top f_\tau)}{Z(w)}, \qquad Z(w) = \sum_\tau \exp(w^\top f_\tau).$$

Trajectories with higher reward are exponentially more likely, and ties are broken as evenly as possible. Fit \(w\) by maximum likelihood on the \(M\) demonstrations:

$$L(w) = \frac1M\sum_{m} \log P(\tau_m \mid w) = w^\top \tilde f - \log Z(w).$$

Differentiate. Since \(\nabla_w \log Z = \frac{1}{Z}\sum_\tau \exp(w^\top f_\tau)\, f_\tau = \E_{P(\cdot \mid w)}[f_\tau]\),

$$\nabla_w L = \tilde f - \E_{\tau \sim P(\cdot \mid w)}[f_\tau] = \underbrace{\tilde f}_{\text{expert features}} - \underbrace{\sum_s D_s\, \phi(s)}_{\text{expected features}},$$

where \(D_s\) is the expected number of visits to \(s\) under the current MaxEnt policy. \(\log Z\) is convex, so \(L\) is concave and gradient ascent finds the global optimum, where expected features equal expert features.

The partition function is the hard part: \(Z(w)\) sums over all trajectories, a number exponential in the horizon. Dynamic programming computes it, and the visitation counts \(D_s\), with a backward pass (soft value iteration, which yields the MaxEnt policy) and a forward pass (propagate the start distribution through that policy). With stochastic dynamics, Ziebart et al. (2008) put the expectation over next states inside the exponential, which makes the policy optimistic about lucky transitions. The later maximum causal entropy formulation (Ziebart, Bagnell & Dey, 2010) uses \(Q(s, a) = r(s) + \E_{s'}[V(s')]\), \(V(s) = \log\sum_a \exp Q(s, a)\): exactly the soft Bellman equation of SAC (Day 95). The code below uses that form; for deterministic dynamics the two coincide.

import numpy as np

def maxent_irl(P, phi, expert_feats, p0, T, lr=0.05, iters=300):
    """P: [S, A, S] dynamics; phi: [S, F] state features; expert_feats: [F] mean over demos of
    sum_t phi(s_t); p0: [S] start distribution; T: horizon. Reward r(s) = phi(s) @ w."""
    S, A, _ = P.shape
    w = np.zeros(phi.shape[1])
    for _ in range(iters):
        r = phi @ w
        V, policies = np.zeros(S), []
        for t in range(T):                                 # backward pass: soft value iteration
            Q = r[:, None] + P @ V                         # [S, A]
            V = np.logaddexp.reduce(Q, axis=1)             # soft max over actions
            policies.append(np.exp(Q - V[:, None]))        # MaxEnt policy pi(a | s)
        policies.reverse()                                 # policies[t] acts at time t
        d, D = p0.copy(), np.zeros(S)
        for t in range(T):                                 # forward pass: expected visitation
            D += d
            d = np.einsum("s,sa,sat->t", d, policies[t], P)
        w += lr * (expert_feats - phi.T @ D)               # expert features - expected features
    return w

Tested on a deterministic 5×5 grid with one-hot state features, 10-step episodes and 200 demonstrations from a soft-optimal expert rewarded only in the far corner: the recovered reward is about 4.2 on the goal cell and between −0.7 and 0.4 everywhere else, and the learned policy's visitation matches the expert's to within 0.04 visits per state.

For high-dimensional problems the dynamic program is out of reach. Guided cost learning (Finn et al., 2016) estimates \(Z\) by importance sampling from a policy trained alongside the reward. Alternating "improve the reward so the demonstrations look likely" with "improve the policy under that reward" is, as Day 108 shows, a GAN.

Bayesian IRL

Ramachandran & Amir (2007) treat the reward as unknown and compute a posterior. Model the expert as Boltzmann-rational with confidence \(\alpha\):

$$P(a \mid s, R) = \frac{\exp\big(\alpha\, Q^*_R(s, a)\big)}{\sum_b \exp\big(\alpha\, Q^*_R(s, b)\big)}, \qquad P(R \mid \mathcal D) \propto P(R) \prod_i P(a_i \mid s_i, R).$$

The posterior is sampled with MCMC; their PolicyWalk algorithm takes random-walk steps on a grid of reward vectors and reuses the previous policy to warm-start each new policy iteration. The output is a distribution, so you can take the posterior mean (the estimate that minimizes squared error), act to maximize expected value under the posterior, or ask the expert for labels where the posterior is most uncertain. The cost: every likelihood evaluation requires solving an MDP.

When you'd want the reward instead of the policy

  • Transfer to new dynamics. A reward describes what to achieve; a policy also encodes how, for one body in one environment. After a change of robot or a moved wall, re-plan with the reward. AIRL (Day 108) is built for this.
  • Doing better than the demonstrations. RL on the recovered reward can act sensibly in states the expert never visited, and can outperform an imperfect expert.
  • Predicting and understanding behaviour. Ziebart et al. used MaxEnt IRL to model the route preferences of taxi drivers from GPS traces and predict their routes.
  • Specifying hard-to-write objectives. Driving style, or the helicopter aerobatics that Abbeel et al. learned through apprenticeship learning, are easier to demonstrate than to write down. Learning reward models from human preferences (Day 123) is the same idea with comparisons instead of demonstrations.

If you only need to reproduce behaviour in the same environment, BC, DAgger or GAIL is simpler: IRL puts an entire RL problem inside every iteration.

What breaks
  • Degenerate and shaped solutions. Without margins, entropy or priors, the optimizer happily returns trivial rewards. With them, the answer still depends on the features you chose and is identified only up to shaping.
  • The inner loop. Every gradient step needs a (soft) optimal policy for the current reward; in large problems that is an RL run per step.
  • Suboptimal or inconsistent experts. The Boltzmann model of irrationality is a convenience, not a fact. Systematic human biases get baked into the reward.
  • The non-causal MaxEnt model with stochastic dynamics is risk-seeking: it explains demonstrations as if the expert expected lucky transitions.

DAY 108

GAIL & Adversarial Imitation

40m video90m practice

GAIL skips the reward. It trains a discriminator to tell the expert's state–action pairs from the policy's, and trains the policy with RL to fool it. At the optimum the policy's occupancy measure matches the expert's, which is what running IRL and then RL would have produced anyway. AIRL constrains the discriminator's form so that a reward that transfers to new dynamics falls out as a by-product.

Occupancy measures

Definition · occupancy measure

\(\rho_\pi(s, a) = \pi(a \mid s) \sum_{t \ge 0} \gamma^t \Pr(s_t = s \mid \pi)\): the discounted frequency with which \(\pi\) takes \(a\) in \(s\). Expected return is linear in it, \(\E_\pi\big[\sum_t \gamma^t r(s_t, a_t)\big] = \sum_{s, a} \rho_\pi(s, a)\, r(s, a)\).

Valid occupancy measures are exactly the non-negative solutions of the Bellman flow constraints \(\sum_a \rho(s', a) = p_0(s') + \gamma \sum_{s, a} P(s' \mid s, a)\, \rho(s, a)\), and they correspond one-to-one with policies through \(\pi_\rho(a \mid s) = \rho(s, a)/\sum_{a'} \rho(s, a')\) (Syed et al., 2008; this is also the dual of the LP formulation of Day 25).

So imitation can be posed as occupancy-measure matching: make \(\rho_\pi\) equal to \(\rho_{\pi_E}\). Unlike BC, this compares the two policies on the states each one actually visits, so covariate shift is built into the objective. Apprenticeship learning (Day 107) matched only a linear projection of \(\rho\), the feature expectations; occupancy matching asks for all of it.

From IRL to GAIL

Ho & Ermon (2016) start from MaxEnt IRL with a convex regularizer \(\psi\) on the cost function, followed by entropy-regularized RL on the recovered cost. They show that the composition, RL after IRL, solves

$$\operatorname{RL}\circ\operatorname{IRL}_\psi(\pi_E) = \argmin_\pi\; -H(\pi) + \psi^*\big(\rho_\pi - \rho_{\pi_E}\big),$$

where \(\psi^*\) is the convex conjugate. The regularizer chooses the distance between occupancy measures. No regularizer gives exact matching, which is hopeless in large spaces. Restricting costs to a linear class recovers apprenticeship learning. And one particular regularizer, \(\psi_{GA}\), makes \(\psi^*\) the optimal value of a binary classification problem. That gives GAIL:

$$\min_\pi \max_{D}\; \E_{\pi_E}\big[\log D(s, a)\big] + \E_{\pi}\big[\log\big(1 - D(s, a)\big)\big] - \lambda H(\pi).$$

Here \(D(s, a) \in (0, 1)\) is the probability that \((s, a)\) came from the expert. (The paper writes \(D\) as the probability that the pair came from the policy, which is the same objective with \(D \mapsto 1 - D\).) The policy only affects the second term, so it is trained with RL to make its own pairs look like the expert's, with reward \(-\log(1 - D(s, a))\) or \(\log D(s, a)\).

Derivation · the inner maximum is a Jensen–Shannon divergence

Normalize \(\rho\)'s to probability distributions (multiply by \(1 - \gamma\)). For fixed \(\pi\), the objective is \(\sum_{s,a} \big[\rho_E \log D + \rho_\pi \log(1 - D)\big]\), maximized pointwise in \(D\). Setting the derivative \(\rho_E/D - \rho_\pi/(1 - D)\) to zero gives

$$D^*(s, a) = \frac{\rho_E(s, a)}{\rho_E(s, a) + \rho_\pi(s, a)}.$$

Substitute and write \(m = \tfrac12(\rho_E + \rho_\pi)\):

$$\sum \rho_E \log\frac{\rho_E}{2m} + \rho_\pi \log\frac{\rho_\pi}{2m} = \KL(\rho_E \,\|\, m) + \KL(\rho_\pi \,\|\, m) - 2\log 2 = 2\,\operatorname{JS}(\rho_E \,\|\, \rho_\pi) - \log 4.$$

So with a perfect discriminator, the policy is minimizing the Jensen–Shannon divergence between its occupancy measure and the expert's, which is zero exactly when they match. It is the GAN argument (Goodfellow et al., 2014) applied to state–action visitation instead of images.

Algorithm · GAIL (Ho & Ermon 2016)
  1. Collect trajectories with the current policy \(\pi_\theta\).
  2. Take a gradient step on the discriminator: ascend \(\hat\E_{\pi_E}[\log D_w] + \hat\E_{\pi_\theta}[\log(1 - D_w)]\), i.e. logistic regression with expert pairs labelled 1 and policy pairs labelled 0.
  3. Take a policy step (TRPO in the paper) with reward \(-\log(1 - D_w(s, a))\) and an entropy bonus.
  4. Repeat. (the expert demonstrations are reused every iteration; only the policy data are fresh)

Training stability tricks

  • Mind the reward's sign. \(-\log(1 - D) \ge 0\) pays a positive reward every step, so it implicitly rewards surviving longer; \(\log D \le 0\) charges every step and implicitly rewards ending episodes early. On tasks with termination this survival bias can dominate the imitation signal. Kostrikov et al. (2019, Discriminator-Actor-Critic) handle it by learning a reward for absorbing states, and also make adversarial imitation off-policy with TD3, cutting environment interactions by about an order of magnitude.
  • Keep the discriminator from winning. A discriminator that separates the two sets perfectly saturates, and the reward stops varying between good and bad policy actions. Use a gradient penalty or spectral normalization, a small network, few discriminator steps per policy step, and stop training it when its accuracy gets near 100%.
  • Use a stable policy optimizer (TRPO or PPO, with observation and reward normalization), and warm-start the policy with BC to save environment steps.
  • Without expert actions, use a state-only discriminator \(D(s, s')\) (GAIfO; Torabi et al., 2018).
import torch
import torch.nn as nn
import torch.nn.functional as F

class Discriminator(nn.Module):
    """Outputs the logit of 'this (s, a) pair came from the expert'."""
    def __init__(self, obs_dim, act_dim, hidden=256):
        super().__init__()
        self.net = nn.Sequential(nn.Linear(obs_dim + act_dim, hidden), nn.Tanh(),
                                 nn.Linear(hidden, hidden), nn.Tanh(), nn.Linear(hidden, 1))

    def forward(self, s, a):
        return self.net(torch.cat([s, a], -1)).squeeze(-1)

def discriminator_loss(D, s_E, a_E, s_pi, a_pi, gp_coef=10.0):
    """Expert and policy batches must have the same size for the interpolation below."""
    logit_E, logit_pi = D(s_E, a_E), D(s_pi, a_pi)
    bce = F.binary_cross_entropy_with_logits(logit_E, torch.ones_like(logit_E)) \
        + F.binary_cross_entropy_with_logits(logit_pi, torch.zeros_like(logit_pi))
    # gradient penalty on interpolated inputs keeps D smooth, and so keeps the reward informative
    eps = torch.rand(len(s_E), 1)
    s_mix = (eps * s_E + (1 - eps) * s_pi).requires_grad_(True)
    a_mix = (eps * a_E + (1 - eps) * a_pi).requires_grad_(True)
    grads = torch.autograd.grad(D(s_mix, a_mix).sum(), [s_mix, a_mix], create_graph=True)
    gp = (torch.cat(grads, -1).norm(dim=-1) - 1).pow(2).mean()
    return bce + gp_coef * gp

def gail_reward(D, s, a):
    with torch.no_grad():
        return -F.logsigmoid(-D(s, a))        # -log(1 - D): positive, so beware survival bias

\(-\log(1 - \sigma(x)) = -\log\sigma(-x)\), computed stably by logsigmoid. Returning the logit itself, \(\log D - \log(1 - D)\), gives a reward with no fixed sign; that is the form AIRL uses.

AIRL: recovering a transferable reward

GAIL's discriminator is not a reward you can reuse: at the optimum it outputs \(\tfrac12\) everywhere, and before that it encodes the current policy as much as the task. Fu, Luo & Levine (2018) give the discriminator a special form:

$$D_\theta(s, a, s') = \frac{\exp f_\theta(s, a, s')}{\exp f_\theta(s, a, s') + \pi(a \mid s)}, \qquad f_\theta(s, a, s') = g_\theta(s) + \gamma\, h_\phi(s') - h_\phi(s).$$

The policy's reward is \(\log D - \log(1 - D) = f_\theta(s, a, s') - \log\pi(a \mid s)\): entropy-regularized RL on \(f\). The form of \(f\) mirrors the ambiguity of Day 107. \(g\) is a state-only reward and \(h\) a potential, so \(\gamma h(s') - h(s)\) is exactly a potential-based shaping term. The paper shows that, under deterministic dynamics and a ground-truth reward that depends on states only, at the optimum \(g^*\) recovers the true reward up to a constant, \(h^*\) the optimal value function up to a constant, and \(f^*\) the optimal advantage. The shaping, which depends on the dynamics, is absorbed by \(h\), which leaves \(g\) disentangled from the dynamics. Re-optimize a policy for \(g\) in an environment with different dynamics and it still does the task. The paper demonstrates this on a maze whose wall moves and on a quadruped with disabled legs, where rewards recovered by GAIL-style or state–action AIRL variants fail to transfer.

What breaks
  • GAN pathologies. Oscillation between discriminator and policy, and mode collapse: with multimodal demonstrations the policy can imitate one mode perfectly and ignore the rest.
  • Survival or termination bias from the reward's sign, which can look like successful imitation on tasks where long episodes are good.
  • Memorization. With few demonstrations the discriminator can memorize the expert's exact states, after which its reward is uninformative everywhere else.
  • A moving reward. The critic in the policy's RL step chases a reward that changes every iteration; this is part of why on-policy methods are the default.
  • AIRL's guarantee is conditional on deterministic dynamics and a state-only reward. With stochastic dynamics or action-dependent rewards, \(g\) need not be the true reward.

DAY 109

The Offline RL Problem

40m video90m practice

Offline RL learns a policy from a fixed dataset, with no further interaction. Off-policy algorithms look as though they should work, but they rely on trying their own mistakes. Offline, every Bellman target that evaluates an action the data doesn't contain is an unchecked extrapolation, and the max in the backup seeks out the worst of those errors and compounds them.

Learning purely from a fixed dataset

The data are \(\mathcal D = \{(s_i, a_i, r_i, s'_i)\}\), collected once by some behaviour policy \(\pi_\beta\): typically unknown, often a mixture of policies, scripts and people. The goal is a policy with high return in the real MDP, found without running anything in it. The motivation is that interaction is often the expensive, slow or dangerous part (medicine, driving, robotics, recommendation), while logs of past decisions are plentiful. Offline RL promises what supervised learning has: train on a big dataset, deploy the result. Levine et al.'s tutorial (2020) is the standard map of the problem.

Why off-policy algorithms fail offline

Tabular Q-learning converges for any behaviour policy that covers every state–action pair (Day 45), so it is tempting to take DQN or SAC and run it on the dataset. Two of the things those algorithms quietly rely on are missing. Coverage: the learned policy will choose actions the data don't contain. Corrective feedback: online, an action whose value is overestimated gets chosen, its real outcome is observed, and the estimate falls. Offline it is chosen and nothing happens.

Fujimoto et al. (2019) made the failure concrete. They trained DDPG offline on three datasets of a million transitions each from a MuJoCo task: the final replay buffer of an online DDPG agent; data collected concurrently by an online DDPG agent while it trained; and data from an expert policy. Offline DDPG failed on all three, with value estimates that diverged. It failed even on expert data, and even in the concurrent setting, where it saw exactly the same transitions as an online agent that learned well. The only difference was who had chosen the actions.

Distributional shift and out-of-distribution action queries

Two distribution shifts are at work. The first is the one from Day 106: the learned policy visits states the data don't cover, which hurts at deployment. The second is specific to value-based learning and happens during training. The Bellman target

$$y = r + \gamma \max_{a'} Q(s', a') \qquad \text{or} \qquad y = r + \gamma\, \E_{a' \sim \pi(\cdot \mid s')}\big[Q(s', a')\big]$$

evaluates \(Q\) at actions \(a'\) chosen by the max or by the current policy, not by the data. \(Q\) was fitted only on dataset actions, so its value at a very different action is an extrapolation, unconstrained by any data. Unconstrained errors go both ways, but the max (or the actor's gradient ascent on \(Q\)) systematically selects the overestimates. Bootstrapping then copies them into the targets of every predecessor state, and no new data ever correct them. This is the deadly triad of Day 69 in its worst form: function approximation, bootstrapping and off-policy data, with no way to collect more.

Definition · extrapolation error (Fujimoto et al. 2019)

\(\epsilon_{\text{MDP}}(s, a) = Q^\pi(s, a) - Q^\pi_{\mathcal D}(s, a)\): the gap between a policy's value in the true MDP and its value in the MDP implied by the data, whose transitions are the empirical ones in \(\mathcal D\). It satisfies a Bellman-like recursion, so error at the pairs \((s', \pi(s'))\) the data poorly support propagates to every state that leads to them. Kumar et al. (2019) analyse the same phenomenon as bootstrapping error.

Extrapolation error, demonstrated

The smallest demonstration needs only NumPy. The behaviour policy only ever takes small actions; the features can represent \(Q\) well on those actions but extrapolate freely beyond them. Fitted Q iteration with a max over all actions diverges; the same procedure with the in-sample target, using the action actually logged at \(s'\), does not.

import numpy as np

rng = np.random.default_rng(0)
gamma, n = 0.9, 1000

def feats(s, a):                       # features of (s, a), cubic in the action
    s, a = np.broadcast_arrays(s, a)
    return np.stack([np.ones_like(s), s, s * s, a, s * a, a**2, s * a**2, a**3, s * a**3], -1)

# A fixed dataset. The behaviour policy only ever takes small actions, |a| <= 0.2.
s = rng.uniform(-1, 1, n)
a = rng.uniform(-0.2, 0.2, n)
s2 = np.clip(s + a, -1, 1)
r = -np.abs(s2)                        # every reward <= 0, so every true Q lies in [-10, 0]
a2 = rng.uniform(-0.2, 0.2, n)         # the behaviour policy's next action, as logged
X, all_actions = feats(s, a), np.linspace(-1, 1, 41)

for target in ["max over all actions", "in-sample (logged a')"]:
    w = np.zeros(X.shape[1])
    for k in range(31):
        if target.startswith("max"):   # Q-learning: query Q at actions the data never contains
            q_next = (feats(s2[:, None], all_actions[None, :]) @ w).max(axis=1)
        else:                          # SARSA-style: only actions that appear in the data
            q_next = feats(s2, a2) @ w
        w = np.linalg.lstsq(X, r + gamma * q_next, rcond=None)[0]   # fitted Q iteration
        if k % 10 == 0:
            print(f"{target:24s} iter {k:2d}: mean Q on the data = {np.mean(X @ w):.3g}")

Output: with the max, the mean predicted Q goes −0.49, 4×10⁴, 6×10⁷, 5×10¹⁰ at iterations 0, 10, 20, 30, for a problem in which no value can exceed 0. With the in-sample target it goes −0.49, −3.6, −4.7, −5.2, converging to the behaviour policy's value. The in-sample version is stable but only evaluates \(\pi_\beta\); getting improvement without the explosion is what Days 110–111 are about. (With purely quadratic features this particular problem is well specified and both targets behave. Extrapolation error is a property of the function class and the data together.)

What breaks
  • Divergent Q-values are the signature failure: if Q estimates grow far beyond any plausible return, you are looking at extrapolation error, not a learning-rate problem.
  • Offline in name only. Most papers tune hyperparameters and pick checkpoints by running the policy in the environment, which a real offline setting can't do. Offline policy evaluation and selection are hard open problems (Paine et al., 2020).
  • Benchmark artefacts. On expert and medium datasets plain BC is a strong baseline; always report it. Normalized scores hide variance, and mixing D4RL versions makes comparisons meaningless.
  • Deployment shift remains. Even a well-behaved offline Q-function says nothing reliable about states the dataset never reached.

Policy-Constraint Methods — BCQ & BEAR

40m video90m practice

If out-of-distribution actions are the problem, keep the policy where the data are. BCQ only chooses among actions that a generative model of the data proposes, nudged slightly. BEAR constrains the policy's support to lie inside the behaviour policy's support. Both need a model of the behaviour policy. Implicit methods solve the constrained problem in closed form and avoid that model altogether.

Constraining the learned policy to the data support

Day 109's failure needs a policy that picks unsupported actions. Forbid that, and the Bellman targets only ever query \(Q\) where it was trained. In the tabular case Fujimoto et al. (2019) make this exact: batch-constrained Q-learning takes the max in the target only over actions observed at \(s'\),

$$Q(s, a) \leftarrow (1 - \alpha)\, Q(s, a) + \alpha\Big(r + \gamma \max_{a' :\, (s', a') \in \mathcal D} Q(s', a')\Big),$$
Theorem · batch-constrained Q-learning (tabular, informal)

Under the usual step-size conditions, batch-constrained Q-learning converges to the optimal batch-constrained policy: the best policy that only takes state–action pairs present in \(\mathcal D\), evaluated in the MDP the data define. Such policies never query an unseen pair, so with enough data per pair (and exactly, for deterministic dynamics) their values carry no extrapolation error.

The constraint is a dial. Too tight and the learned policy can do no better than \(\pi_\beta\); too loose and extrapolation error returns. Every method in this lesson is a way of setting that dial in continuous action spaces, where "the action at \(s'\) appears in \(\mathcal D\)" is never literally true.

BCQ: a generative model plus a perturbation network

Continuous BCQ (Fujimoto, Meger & Precup, 2019) has three learned parts.

  • A generative model \(G_\omega(s)\) of the behaviour policy: a conditional VAE trained on \(\mathcal D\) to reconstruct actions. At decode time the latent is sampled from a clipped normal, so samples stay in high-density regions.
  • A perturbation network \(\xi_\phi(s, a, \Phi) \in [-\Phi, \Phi]\) that adjusts a proposed action by a small amount, trained by deterministic policy gradient (Day 93) to maximize \(Q_{\theta_1}(s, a + \xi_\phi(s, a, \Phi))\).
  • Twin critics \(Q_{\theta_1}, Q_{\theta_2}\), with a soft clipped double-Q target that mostly takes the minimum: \(y = r + \gamma \max_{a_i}\big[\lambda \min_j Q_{\theta'_j}(s', a_i) + (1-\lambda)\max_j Q_{\theta'_j}(s', a_i)\big]\), with \(\lambda = 0.75\).

The policy is never a network of its own. It is a procedure:

$$\pi(s) = \argmax_{a_i + \xi_\phi(s, a_i, \Phi)} Q_{\theta_1}\big(s, a_i + \xi_\phi(s, a_i, \Phi)\big), \qquad \{a_i \sim G_\omega(s)\}_{i=1}^{n},$$

with \(n = 10\) and \(\Phi = 0.05\) (actions scaled to \([-1, 1]\)) in the paper. The two hyperparameters interpolate between familiar algorithms: \(n = 1, \Phi = 0\) is behaviour cloning (a sample from the VAE); \(\Phi = 0\) with large \(n\) is greedy selection among data-like actions; large \(\Phi\) with \(n \to \infty\) is ordinary Q-learning.

import torch
import torch.nn as nn

class Perturb(nn.Module):
    """xi_phi(s, a, Phi): a bounded correction to an action proposed by the generative model."""
    def __init__(self, obs_dim, act_dim, max_action=1.0, phi=0.05, hidden=400):
        super().__init__()
        self.net = nn.Sequential(nn.Linear(obs_dim + act_dim, hidden), nn.ReLU(),
                                 nn.Linear(hidden, 300), nn.ReLU(), nn.Linear(300, act_dim))
        self.max_action, self.phi = max_action, phi

    def forward(self, s, a):
        xi = self.phi * self.max_action * torch.tanh(self.net(torch.cat([s, a], -1)))
        return (a + xi).clamp(-self.max_action, self.max_action)

@torch.no_grad()
def bcq_act(s, vae, perturb, q1, n=10):
    """s: [obs_dim]. Sample n candidates near the data, nudge them, keep the best by Q1."""
    s_rep = s.unsqueeze(0).repeat(n, 1)
    cand = perturb(s_rep, vae.decode(s_rep))        # decode() samples a clipped latent
    return cand[q1(s_rep, cand).argmax()]

@torch.no_grad()
def bcq_target(r, s2, term, vae, perturb_t, q1_t, q2_t, n=10, lam=0.75, gamma=0.99):
    B = s2.shape[0]
    s_rep = s2.repeat_interleave(n, 0)              # [B * n, obs_dim]
    a_rep = perturb_t(s_rep, vae.decode(s_rep))
    q1v, q2v = q1_t(s_rep, a_rep), q2_t(s_rep, a_rep)
    q = lam * torch.min(q1v, q2v) + (1 - lam) * torch.max(q1v, q2v)
    return r + gamma * (1 - term) * q.view(B, n).max(1).values   # best candidate per next state

def perturb_loss(s, vae, perturb, q1):              # DPG through the perturbation network only
    a = vae.decode(s).detach()
    return -q1(s, perturb(s, a)).mean()

A fragment: the VAE (decode samples actions given states), the critics and the optimizers are assumed. The critics regress onto bcq_target with ordinary MSE, and target networks are Polyak-averaged as in TD3. Discrete BCQ (Fujimoto et al., 2019b) is simpler still: fit a behaviour classifier \(G(a \mid s)\) and take the max only over actions with \(G(a \mid s)/\max_{\hat a} G(\hat a \mid s) > \tau\), with \(\tau = 0.3\).

BEAR: support matching with MMD

Kumar et al. (2019) point out that BCQ-style closeness to \(\pi_\beta\) is the wrong kind of constraint when \(\pi_\beta\) is poor. Constraining the distribution, for example \(\KL(\pi \,\|\, \pi_\beta) \le \varepsilon\), forces the policy to imitate the behaviour policy's preferences, including its bad ones: with mostly random data it keeps the policy nearly random. Constraining the support only forbids actions the behaviour policy (almost) never takes, and leaves the policy free to put all its mass on the best of the supported ones.

BEAR measures support mismatch with the maximum mean discrepancy, estimated from samples:

$$\operatorname{MMD}^2(P, Q) = \E_{x, x' \sim P}[k(x, x')] - 2\,\E_{x \sim P,\, y \sim Q}[k(x, y)] + \E_{y, y' \sim Q}[k(y, y')],$$

with a Gaussian or Laplacian kernel \(k\). With many samples, MMD is a distance between distributions. The paper's empirical observation is that with only a few samples per state it behaves more like a support test, staying small for distributions that share a support even when their densities differ. The actor solves a constrained problem, maximizing a conservative ensemble estimate of \(Q\) subject to the MMD staying below a threshold, using a Lagrange multiplier updated by dual gradient ascent:

$$\max_\pi\ \E_{s \sim \mathcal D}\,\E_{a \sim \pi(\cdot \mid s)}\Big[\min_{j = 1..K} Q_j(s, a)\Big] \quad \text{s.t.} \quad \E_{s \sim \mathcal D}\big[\operatorname{MMD}\big(\hat\pi_\beta(\cdot \mid s), \pi(\cdot \mid s)\big)\big] \le \varepsilon.$$

The dataset has one action per state, so the samples from \(\hat\pi_\beta\) come from a fitted model, again a VAE. The critics are an ensemble with BCQ's soft clipped target, maximized over a few actions sampled from \(\pi\) at \(s'\).

import torch

def mmd2_laplacian(x, y, sigma=10.0):
    """Squared MMD between sample sets x: [B, n, d] and y: [B, m, d], one value per state."""
    k = lambda u, v: torch.exp(-(u.unsqueeze(2) - v.unsqueeze(1)).abs().sum(-1) / sigma)
    return k(x, x).mean((1, 2)) - 2 * k(x, y).mean((1, 2)) + k(y, y).mean((1, 2))

def bear_actor_losses(s, policy, vae, critics, log_alpha, eps=0.05, n=5):
    a_pi = policy.rsample(s, n)                        # [B, n, act], reparameterized samples
    a_beta = vae.decode_multiple(s, n).detach()        # [B, n, act] from the behaviour model
    mmd = mmd2_laplacian(a_beta, a_pi)                 # [B]
    q = torch.stack([c(s, a_pi[:, 0]) for c in critics]).min(0).values
    actor_loss = (-q + log_alpha.exp().detach() * mmd).mean()
    alpha_loss = -(log_alpha * (mmd.detach() - eps)).mean()   # raise alpha while MMD exceeds eps
    return actor_loss, alpha_loss

A fragment with the policy, VAE and critic ensemble assumed. The threshold, kernel and bandwidth are dataset-dependent hyperparameters; the values here are only placeholders.

Explicit vs implicit constraints

Explicit methods put a divergence to \(\hat\pi_\beta\) into the actor's objective, as a constraint or a penalty: BEAR's MMD; BRAC (Wu, Tucker & Nachum, 2019), which compares KL, MMD and Wasserstein penalties applied to the policy or to the value; TD3+BC (Fujimoto & Gu, 2021), which simply adds a BC term on dataset actions, \(\max_\pi \E_{(s, a) \sim \mathcal D}\big[\lambda Q(s, \pi(s)) - (\pi(s) - a)^2\big]\) with \(\lambda = \alpha / \overline{|Q|}\) and \(\alpha = 2.5\), and is a strong baseline for that little effort. Implicit methods solve the constrained improvement step in closed form and never need \(\hat\pi_\beta\) at all.

Derivation · the KL-constrained improvement step in closed form

At each state solve \(\max_\pi \E_{a \sim \pi}[A(s, a)] - \lambda\,\KL\big(\pi(\cdot \mid s)\,\|\,\pi_\beta(\cdot \mid s)\big)\) over distributions. With a multiplier \(\nu\) for normalization, the stationarity condition is \(A(s, a) - \lambda\big(\log\pi(a \mid s) - \log\pi_\beta(a \mid s) + 1\big) + \nu = 0\), so

$$\pi^*(a \mid s) = \frac{1}{Z(s)}\,\pi_\beta(a \mid s)\,\exp\!\big(A(s, a)/\lambda\big).$$

Project this onto a parametric policy by minimizing \(\E_s\, \KL(\pi^* \,\|\, \pi_\theta)\), which is equivalent to maximizing \(\E_s \E_{a \sim \pi^*}[\log\pi_\theta(a \mid s)]\). Write the expectation under \(\pi^*\) as one under \(\pi_\beta\), and drop the per-state constant \(Z(s)\):

$$\max_\theta\ \E_{(s, a) \sim \mathcal D}\Big[\exp\!\big(A(s, a)/\lambda\big)\, \log\pi_\theta(a \mid s)\Big].$$

An expectation under \(\pi_\beta\) is just an average over the dataset, so no behaviour model is needed. The result is behaviour cloning with each logged action weighted by its exponentiated advantage: AWR (Peng et al., 2019), AWAC (Nair et al., 2020), CRR (Wang et al., 2020), and IQL's policy extraction on Day 111.

Behaviour-policy estimation

BCQ's generator, BEAR's MMD samples and BRAC's KL all depend on a model \(\hat\pi_\beta\), and its errors leak straight into the constraint. Real datasets are usually mixtures: several policies, a replay buffer, or many human operators. A single Gaussian fitted to a multimodal mixture puts its mass between the modes, which is exactly where the data are not. That is why these methods use VAEs, and why later work uses mixtures, normalizing flows or diffusion models. Underestimating the support shuts out good actions; overestimating it lets extrapolation back in. And the model must generalize across states, since each state usually appears once with one action. Implicit methods avoid all of this, which is a large part of why they took over.

On results: BCQ was far better than offline DDPG on all of Fujimoto et al.'s datasets and particularly strong on expert data. BEAR was more robust on random and medium-quality data, where a tight closeness constraint hurts. On D4RL both have since been overtaken by simpler or more conservative methods: TD3+BC, CQL and IQL.

What breaks
  • The dial is dataset-dependent. Good values of Φ, ε or the penalty weight differ between expert and random data, and are usually chosen by evaluating online, which a true offline user can't do.
  • A bad behaviour model breaks the constraint in both directions, as above.
  • MMD is finicky. The kernel, its bandwidth and the number of samples change whether it behaves like a support test or a distribution match.
  • Ceilings. A constrained policy can't stray far from the data. If good behaviour needs actions that appear only rarely in the data, the constraint can rule them out.

DAY 111

Value-Regularization — CQL & IQL

45m video105m practice

Instead of constraining the policy, change what the critic believes. CQL adds a penalty that pushes \(Q\) down on actions the policy favours and up on actions in the data, which provably makes the policy's estimated value a lower bound on its true value. IQL never evaluates an unseen action at all: it learns an upper expectile of in-sample values and extracts a policy by advantage-weighted regression.

Conservative Q-Learning: penalize out-of-distribution values

Kumar, Zhou, Tucker & Levine (2020) start from the policy-evaluation step of an actor-critic, \(\hat Q^{k+1} = \argmin_Q \tfrac12\E_{\mathcal D}\big[(Q - \hat{\mathcal B}^\pi \hat Q^k)^2\big]\), where \(\hat{\mathcal B}^\pi\) is the empirical Bellman operator for the current policy \(\pi\), and add a term that penalizes large \(Q\)-values under some distribution \(\mu\) over actions.

Derivation · why the penalty gives a lower bound (tabular, exact backups)

First version. \(\hat Q^{k+1} = \argmin_Q\ \alpha\,\E_{s \sim \mathcal D, a \sim \mu}[Q(s, a)] + \tfrac12\E_{(s, a) \sim \mathcal D}\big[(Q(s, a) - \mathcal B^\pi\hat Q^k(s, a))^2\big]\). The data put state \(s\) and action \(a\) at frequencies \(d(s)\,\pi_\beta(a \mid s)\), so setting the derivative with respect to each \(Q(s, a)\) to zero gives \(d(s)\big[\alpha\,\mu(a \mid s) + \pi_\beta(a \mid s)\big(Q(s, a) - \mathcal B^\pi \hat Q^k(s, a)\big)\big] = 0\), that is

$$\hat Q^{k+1}(s, a) = \mathcal B^\pi \hat Q^k(s, a) - \alpha\,\frac{\mu(a \mid s)}{\pi_\beta(a \mid s)}.$$

Every backup subtracts something non-negative, so the fixed point satisfies \(\hat Q^\pi = Q^\pi - \alpha(I - \gamma P^\pi)^{-1}\big[\mu/\pi_\beta\big] \le Q^\pi\) at every \((s, a)\): a pointwise lower bound. Notice where the penalty is largest: where \(\mu\) puts mass and the data don't.

Second version (the one used). Also maximize \(Q\) on the data: add \(-\alpha\,\E_{(s, a) \sim \mathcal D}[Q(s, a)]\). The same calculation gives \(\hat Q^{k+1} = \mathcal B^\pi \hat Q^k - \alpha\big(\mu(a \mid s) - \pi_\beta(a \mid s)\big)/\pi_\beta(a \mid s)\), which can be positive for some actions, so the pointwise bound is lost. But take \(\mu = \pi\) and average over the policy's actions:

$$\E_{a \sim \pi}\Big[\frac{\pi(a \mid s) - \pi_\beta(a \mid s)}{\pi_\beta(a \mid s)}\Big] = \sum_a \frac{\pi(a \mid s)^2}{\pi_\beta(a \mid s)} - 1 \;\ge\; 0,$$

since \(\sum_a \pi^2/\pi_\beta \ge (\sum_a \pi)^2 / \sum_a \pi_\beta = 1\) by Cauchy–Schwarz (it is a chi-squared divergence). So the value \(\hat V^\pi(s) = \E_{a \sim \pi}[\hat Q^\pi(s, a)]\) is a lower bound on \(V^\pi(s)\). The bound is tighter than the first version's, and it is exact where \(\pi = \pi_\beta\), on the data's own behaviour.

Theorem · CQL lower bound (Kumar et al. 2020, informal)

With sampling error in the empirical backup, the same conclusions hold with high probability provided \(\alpha\) is large enough to dominate the error, which shrinks like \(1/\sqrt{|\mathcal D(s, a)|}\). The first version lower-bounds \(Q^\pi\) pointwise; the second lower-bounds \(V^\pi\). A policy improved against a lower bound can't be fooled by overestimated, unsupported actions.

The CQL objective and its α term. Rather than fixing \(\mu = \pi\), choose the \(\mu\) that maximizes the penalty, regularized by its entropy. Since \(\max_\mu \E_{a \sim \mu}[Q(s, a)] + \mathcal H(\mu) = \log\sum_a \exp Q(s, a)\), attained at \(\mu = \operatorname{softmax}(Q)\) (the Gibbs variational principle), the inner maximization has a closed form. That gives CQL(\(\mathcal H\)):

$$\min_Q\ \alpha\,\E_{s \sim \mathcal D}\Big[\log\sum_a \exp Q(s, a) - \E_{a \sim \hat\pi_\beta(\cdot \mid s)}\big[Q(s, a)\big]\Big] + \frac12\,\E_{(s, a, s') \sim \mathcal D}\Big[\big(Q(s, a) - \hat{\mathcal B}^{\pi_k}\hat Q^k(s, a)\big)^2\Big].$$

The \(\alpha\) term pushes down a soft maximum of \(Q\) over all actions and pushes up \(Q\) at the logged actions, so it widens the gap between in-distribution and out-of-distribution values. Its expectation over \(\hat\pi_\beta\) is just an average over dataset pairs, so no behaviour model is needed. In continuous action spaces the log-sum-exp is estimated by importance sampling, using a handful of actions drawn uniformly and from the current policy at \(s\) and \(s'\). \(\alpha\) is either fixed (values from about 1 to 10 are common, and the right value depends on the reward scale) or tuned automatically by a Lagrangian that raises it while the gap exceeds a threshold \(\tau\). The paper reports strong D4RL results, with its largest margins over earlier methods on the harder AntMaze, Kitchen and Adroit datasets.

import torch
import torch.nn.functional as F

def cql_dqn_loss(q, q_targ, s, a, r, s2, term, alpha=1.0, gamma=0.99):
    """Discrete CQL(H) on top of a DQN-style TD loss. a: [B] long; r, term: [B] float."""
    q_all = q(s)                                            # [B, A]
    q_data = q_all.gather(1, a[:, None]).squeeze(1)         # Q at the logged actions
    with torch.no_grad():
        y = r + gamma * (1 - term) * q_targ(s2).max(1).values
    td = 0.5 * F.mse_loss(q_data, y)
    # push down a soft maximum over all actions, push up the actions in the data
    conservative = (torch.logsumexp(q_all, dim=1) - q_data).mean()
    return td + alpha * conservative

With discrete actions the log-sum-exp is exact. For continuous control, replace it with a sampled estimate and replace the max in the target with the actor's action, as in SAC.

Implicit Q-Learning: expectile regression that never queries OOD actions

The in-sample target of Day 109 (use the logged \(a'\)) never touches an unseen action, but it evaluates \(\pi_\beta\) instead of improving on it. Kostrikov, Nair & Levine (2022) want a max over actions, restricted to actions the data contain, without ever sampling an action. Expectiles provide exactly that.

Definition · expectile regression $$L_2^\tau(u) = \big|\tau - \mathbb 1(u < 0)\big|\, u^2, \qquad \tau \in (0, 1).$$

The \(\tau\)-expectile \(m_\tau\) of a random variable \(X\) minimizes \(\E[L_2^\tau(X - m)]\). Setting the derivative to zero gives \(\tau\,\E[(X - m)_+] = (1 - \tau)\,\E[(m - X)_+]\): the expected excess above \(m\), weighted by \(\tau\), balances the expected shortfall below it, weighted by \(1 - \tau\). For \(\tau = 0.5\) this is the mean; as \(\tau \to 1\) the shortfall weight vanishes and \(m_\tau\) rises to the maximum of \(X\)'s support.

IQL trains three things, using only \((s, a, r, s')\) tuples from the data:

$$L_V(\psi) = \E_{(s, a) \sim \mathcal D}\Big[L_2^\tau\big(Q_{\hat\theta}(s, a) - V_\psi(s)\big)\Big], \qquad L_Q(\theta) = \E_{(s, a, s') \sim \mathcal D}\Big[\big(r + \gamma V_\psi(s') - Q_\theta(s, a)\big)^2\Big],$$ $$L_\pi(\phi) = -\E_{(s, a) \sim \mathcal D}\Big[\exp\!\big(\beta\,(Q_{\hat\theta}(s, a) - V_\psi(s))\big)\, \log\pi_\phi(a \mid s)\Big].$$

\(V_\psi(s)\) is an upper expectile of \(Q\) over the dataset's actions at \(s\): a soft max over in-support actions. \(Q\) then regresses onto \(r + \gamma V(s')\), which is a Bellman optimality backup restricted to the support. As \(\tau \to 1\) the paper shows this approaches the optimal \(Q\)-function over policies that stay in the support. Why a separate \(V\), instead of applying the expectile directly to \(r + \gamma Q(s', a')\)? That target is also random through \(s'\), and an upper expectile of it would reward lucky transitions, not good actions. \(V(s)\) depends only on \(s\), so its expectile is over actions alone, while the \(Q\) regression averages over next states with an ordinary mean.

Advantage-weighted regression for policy extraction. The value functions never use the policy. Once \(Q\) and \(V\) are learned (or concurrently), \(L_\pi\) extracts a policy by weighted behaviour cloning, Day 110's closed form with temperature \(1/\beta\): logged actions with positive advantage are imitated strongly, those with negative advantage barely at all. The weights are clipped (at 100 in the paper) to stop a few large advantages from dominating.

import torch
import torch.nn.functional as F

def expectile_loss(diff, tau=0.7):
    """L2^tau(u) = |tau - 1(u < 0)| * u^2, with u = Q - V."""
    weight = torch.where(diff < 0, 1 - tau, tau)
    return (weight * diff.pow(2)).mean()

def iql_update(batch, q1, q2, q1_t, q2_t, v, policy, opt_v, opt_q, opt_pi,
               tau=0.7, beta=3.0, gamma=0.99):
    s, a, r, s2, term = batch                              # dataset tuples only
    # 1) V: upper expectile of the target Q over *logged* actions; no policy sampling anywhere
    with torch.no_grad():
        q_t = torch.min(q1_t(s, a), q2_t(s, a))
    v_s = v(s)
    loss_v = expectile_loss(q_t - v_s, tau)
    # 2) Q: regress onto r + gamma V(s'); V carries the max, the mean handles random s'
    with torch.no_grad():
        y = r + gamma * (1 - term) * v(s2)
    loss_q = F.mse_loss(q1(s, a), y) + F.mse_loss(q2(s, a), y)
    # 3) policy: advantage-weighted regression on logged actions
    with torch.no_grad():
        w = torch.exp(beta * (q_t - v_s)).clamp(max=100.0)
    loss_pi = -(w * policy.log_prob(s, a)).mean()
    for opt, loss in ((opt_v, loss_v), (opt_q, loss_q), (opt_pi, loss_pi)):
        opt.zero_grad()
        loss.backward()
        opt.step()
    # then Polyak-average q1_t, q2_t towards q1, q2 (rate 0.005)

The three losses touch disjoint parameters, so the three backward passes are independent. The paper's settings include \(\tau = 0.7, \beta = 3\) for the locomotion datasets and \(\tau = 0.9, \beta = 10\) for AntMaze, with rewards rescaled per domain; treat those as starting points.

Why IQL is simple and strong

  • No out-of-distribution queries, by construction. Every \(Q\) and \(V\) evaluation is at a dataset pair or a dataset state, so there is nothing to extrapolate and nothing to constrain.
  • No behaviour model and no sampling. No VAE, no log-sum-exp estimate, no actor in the value updates. It is three regressions, which makes it fast and stable.
  • It still does dynamic programming. Because \(V\) approximates an in-support max and \(Q\) backs it up, value propagates across trajectories that share states. That is why IQL is strong on AntMaze, which requires stitching, where return-conditioned methods (Day 112) are weak.
  • It fine-tunes well. The paper shows that IQL-pretrained agents improve smoothly when online interaction is later allowed.

The reported D4RL results put IQL on par with CQL on the locomotion datasets and ahead on AntMaze, with a fraction of the implementation complexity.

What breaks
  • CQL's α. Too large and \(Q\) is so pessimistic the policy collapses towards behaviour cloning; too small and overestimation returns. Its scale is tied to the reward scale, which is why the Lagrangian variant exists.
  • Pessimism costs you online. CQL's deliberately low values make online fine-tuning start with an "unlearning" dip as the critic recalibrates; Cal-QL (Nakamoto et al., 2023) is one fix.
  • IQL's τ near 1 approximates a hard max, which is noisy and unstable; \(\beta\) too large makes a few weights dominate the policy loss, and too small turns it into BC.
  • The support is a ceiling. IQL can't recommend an action the data never contain, however good it might be.
  • Online tuning again. The published settings were chosen by evaluating in the environment.

DAY 112

Decision Transformer & RL as Sequence Modeling

40m video90m practice

Decision Transformer drops value functions and policy gradients altogether. It trains a causal transformer to predict actions from the recent trajectory and a desired return-to-go, then asks for a high return at test time. It is simple and stable, and it inherits the limits of conditioning on outcomes: it can't stitch together the best parts of different trajectories, and in stochastic environments it confuses luck with skill.

Casting RL as conditional sequence prediction

A trajectory is a sequence, and sequence models are very good at predicting the next element of one. The trick is to put the outcome into the sequence as an input: learn \(\pi(a \mid \text{history}, \text{desired return})\) by maximum likelihood on the dataset, then at test time ask for a return as high as the best in the data. This is return-conditioned supervised learning; Schmidhuber's "upside-down RL" (2019) and RvS ("reinforcement learning via supervised learning") are related framings. There is no Bellman backup and no bootstrapping, so none of the deadly-triad machinery of Days 109–111 is needed. The question this lesson answers is what that costs.

Return-to-go conditioning

Decision Transformer (Chen et al., 2021) represents each trajectory as interleaved tokens

$$\tau = \big(\hat R_1, s_1, a_1,\ \hat R_2, s_2, a_2,\ \dots,\ \hat R_T, s_T, a_T\big), \qquad \hat R_t = \sum_{t' = t}^{T} r_{t'},$$

where \(\hat R_t\) is the undiscounted return-to-go from step \(t\) and \(r_{t'}\) is the reward received after \(a_{t'}\) (the paper's indexing). Conditioning on what is left to achieve, rather than on rewards already received, makes the same input mean the same thing at every point in an episode. At test time you choose \(\hat R_1\), say an expert-level return, and after each step subtract the reward actually received, \(\hat R_{t+1} = \hat R_t - r_t\).

The transformer over (R, s, a) tokens

  • Embeddings. Each modality has its own linear embedding (a convolutional encoder for Atari frames) into dimension \(d\). A learned embedding of the episode timestep \(t\), the absolute step in the episode and not the position in the context window, is added to all three tokens of step \(t\).
  • Backbone. A GPT-style causal transformer over the last \(K\) timesteps, \(3K\) tokens (\(K = 20\) for the MuJoCo tasks, 30 for most Atari games). Each token attends only to earlier tokens.
  • Head and loss. The output at each state token \(s_t\) predicts \(a_t\), with MSE for continuous actions or cross-entropy for discrete ones. Only actions are predicted; the paper found that also predicting states or returns did not help.
Algorithm · Decision Transformer
  1. Preprocess. For every trajectory in the dataset compute the returns-to-go \(\hat R_t\) and timesteps \(t\). Scale returns by a fixed constant (for example, divide by 1,000 on MuJoCo).
  2. Train. Repeat: sample a window of \(K\) consecutive steps from a random trajectory (longer trajectories more often), embed its \(3K\) tokens, and minimize the action-prediction loss at every state token. (pad short windows and mask the padding in attention and in the loss)
  3. Act. Choose a target return \(\hat R_1\). At each step:
    1. Feed the last \(K\) steps of \((\hat R, s, a)\), with a placeholder for the current action.
    2. Execute the action predicted at the newest state token; observe \(r_t\) and \(s_{t+1}\).
    3. Append \(\hat R_{t+1} = \hat R_t - r_t\) and \(s_{t+1}\) to the context.
import torch
import torch.nn as nn

class DecisionTransformer(nn.Module):
    def __init__(self, obs_dim, act_dim, d=128, n_layer=3, n_head=1, max_ep_len=1000):
        super().__init__()
        self.embed_R, self.embed_s = nn.Linear(1, d), nn.Linear(obs_dim, d)
        self.embed_a, self.embed_t = nn.Linear(act_dim, d), nn.Embedding(max_ep_len, d)
        self.ln = nn.LayerNorm(d)
        layer = nn.TransformerEncoderLayer(d, n_head, 4 * d, dropout=0.1, batch_first=True)
        self.gpt = nn.TransformerEncoder(layer, n_layer)
        self.predict_a = nn.Sequential(nn.Linear(d, act_dim), nn.Tanh())

    def forward(self, R, s, a, t):
        """R: [B, K, 1] returns-to-go; s: [B, K, obs]; a: [B, K, act]; t: [B, K] long timesteps."""
        B, K, _ = s.shape
        te = self.embed_t(t)                                   # added to all three tokens of a step
        tokens = torch.stack([self.embed_R(R) + te, self.embed_s(s) + te, self.embed_a(a) + te],
                             dim=2).reshape(B, 3 * K, -1)      # R1 s1 a1 R2 s2 a2 ...
        causal = torch.triu(torch.ones(3 * K, 3 * K, dtype=torch.bool), diagonal=1)
        h = self.gpt(self.ln(tokens), mask=causal).reshape(B, K, 3, -1)
        return self.predict_a(h[:, :, 1])                      # read out at the s_t tokens

def returns_to_go(rewards):
    """Undiscounted R_t = r_t + r_{t+1} + ... + r_T, as Decision Transformer uses."""
    out, running = [0.0] * len(rewards), 0.0
    for t in reversed(range(len(rewards))):
        running += rewards[t]
        out[t] = running
    return out

# training step on random length-K windows of dataset trajectories:
#   loss = ((model(R, s, a, t) - a) ** 2).mean()        # mask padded steps in short windows
import numpy as np
import torch

@torch.no_grad()
def run_dt(model, env, target_return, K=20, scale=1000.0, max_ep_len=1000):
    obs, _ = env.reset(seed=0)
    act_dim = env.action_space.shape[0]
    R, S, A, T = [target_return / scale], [obs], [np.zeros(act_dim)], [0]
    ctx = lambda xs: torch.as_tensor(np.array(xs[-K:]), dtype=torch.float32)[None]
    total = 0.0
    for t in range(max_ep_len):
        a = model(ctx(R)[..., None], ctx(S), ctx(A), torch.as_tensor(T[-K:])[None])[0, -1]
        A[-1] = a.numpy()                                  # fill the placeholder for a_t
        obs, r, terminated, truncated, _ = env.step(A[-1])
        total += r
        if terminated or truncated:
            break
        R.append(R[-1] - r / scale)                        # decrement the return-to-go
        S.append(obs)
        A.append(np.zeros(act_dim))
        T.append(t + 1)
    return total

The defaults follow the paper's MuJoCo configuration (3 layers, 1 head, \(d = 128\), \(K = 20\), returns divided by 1,000); the original uses GPT-2 blocks, but any causal transformer works. The placeholder action for the current step is harmless: the causal mask hides it from the \(s_t\) token. The paper reports DT competitive with CQL on the D4RL locomotion datasets and on the Atari datasets it used, and strong on a Key-to-Door task built to need credit assignment over long horizons.

Trajectory Transformer and beam search

Janner, Li & Levine (2021) model everything, not just actions. Each dimension of the state, the action and the reward (plus a reward-to-go estimate) is discretized independently into 100 bins and becomes its own token, so one transition is a run of \(N_s + N_a + 2\) tokens. A GPT trained on these sequences is at once a dynamics model, a behaviour policy and a reward model. Planning is beam search, the same procedure language models use for decoding. For imitation, the beam keeps the most likely continuations. For offline RL, it keeps the continuations with the highest predicted cumulative reward plus predicted reward-to-go at the end of a short planning horizon. For goal reaching, a goal token is placed at the start of the sequence. The paper shows its long-horizon predictions compound far less error than single-step models, and reports results competitive with the strong offline methods of the time on D4RL locomotion. The cost is inference: every real action needs a beam of candidates expanded token by token, which is very slow.

Three findings temper the enthusiasm. Emmons et al. (2022) showed that a plain MLP conditioned on return or goal (RvS) matches DT on many D4RL tasks, so the transformer is not the key ingredient there; careful conditioning and regularization are. Brandfonbrener et al. (2022) proved that return-conditioned supervised learning needs near-deterministic dynamics and good coverage of high-return trajectories to work, and can be arbitrarily suboptimal otherwise. Paster et al. (2022) showed the stochastic failure concretely: conditioning on a high return selects the trajectories where the environment happened to be kind, so the policy imitates gambles that paid off rather than choices that pay off on average. And the target return itself is a hyperparameter: within the range of the data, achieved return tracks the target; above the data's best return it typically does not.

The stitching failure

Stitching is what D4RL's AntMaze datasets test, and it is where return-conditioned methods do worst and IQL does best. Fixes graft dynamic programming back on: Q-conditioned DT (Yamagata et al., 2023) relabels returns-to-go with learned \(Q\)-values so that the conditioning reflects what is achievable from each state; Elastic DT (Wu et al., 2023) varies the history length so the model can drop a bad trajectory's past; Online DT (Zheng et al., 2022) adds online fine-tuning. Each step back towards value functions recovers some of what return conditioning gave up.

What breaks
  • Stitching, as above: on datasets of partial or suboptimal trajectories, return conditioning can't combine their good parts.
  • Stochasticity: conditioning on high returns rewards luck. Check your environment's stochasticity before choosing DT.
  • Choosing the target return. Too low wastes the model; above the dataset's best, behaviour becomes unpredictable. In papers it is tuned with online rollouts.
  • Implementation details: returns must be scaled consistently between training and evaluation, the return-to-go must be decremented at every step, padded windows need attention and loss masks, and the timestep embedding can't handle episodes longer than its table.
  • Cost per action. A transformer forward pass per step for DT; a full beam search per step for Trajectory Transformer.
