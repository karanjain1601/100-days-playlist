L62 · DAY 44

Graph Representations & Input Handling

45m video

Most graph bugs in Python contests happen before the algorithm starts: a slow parse, an off-by-one vertex index, a matrix that cannot fit in memory, a missing reverse edge. Choose the representation from the density and the operations you need, build it in one bulk pass, and everything later in this phase sits on top of it.

Vocabulary you will be held to

Definition
  • A graph \(G = (V, E)\) has \(n = |V|\) vertices and \(m = |E|\) edges. Directed edges are ordered pairs \(u \to v\); undirected edges are unordered. A weighted graph adds \(w(e)\) to each edge.
  • Simple: no self-loops \((v, v)\) and no parallel edges. A multigraph allows both. Input data is a multigraph unless the statement promises otherwise.
  • Degree \(\deg v\): incident edge endpoints (a self-loop counts twice). In a digraph: in-degree and out-degree.
  • A path repeats no vertex (a walk may); a cycle is a closed path. Connected: a path between every pair. DAG: no directed cycle. Tree: connected and acyclic. Bipartite: \(V\) splits into two sides with every edge crossing.
Theorem · Three counting facts
  1. Handshake lemma. \(\sum_v \deg v = 2m\). So the number of odd-degree vertices is even.
  2. A tree on \(n\) vertices has exactly \(n - 1\) edges; a forest with \(c\) components has \(n - c\).
  3. A simple undirected graph has at most \(\binom{n}{2} = n(n-1)/2\) edges; a simple digraph at most \(n(n-1)\).
Proof

(1) Each edge adds exactly 2 to the degree sum, and an even total cannot contain an odd number of odd terms. (2) Add the edges one at a time to \(n\) isolated vertices. In a forest no edge closes a cycle, so each one merges two components, and \(c = n - m\). (3) At most one edge per unordered pair.

These are sanity checks for parsed input: if the statement says "tree" and \(m \ne n-1\), you read it wrong.

Three representations and what they cost

The adjacency matrix answers "is \(uv\) an edge?" in \(O(1)\) but costs \(\Theta(n^2)\) memory and \(\Theta(n)\) to list a vertex's neighbours. The adjacency list costs \(\Theta(n + m)\) and lists neighbours in \(O(\deg v)\), which is what BFS, DFS and Dijkstra need. The edge list is the raw input; keep it when the algorithm loops over edges (Kruskal, Bellman–Ford). Measured in CPython 3.12 for \(n = 10^5\), \(m = 2\cdot 10^5\):

CSR and forward-star: flat arrays

Compressed sparse row stores every neighbour list end to end in one array adj, with start[v] marking where \(v\)'s slice begins. It is built in two passes: count degrees, take prefix sums to get start, then drop each endpoint into the next free slot of its owner. The forward-star form (head, nxt, to) is a linked list threaded through arrays. It is built in one pass, and edge \(i\) lives in slots \(2i\) and \(2i+1\), so e ^ 1 is the reverse edge. Bridges (L73) and flows (L78) rely on that.

Implementation

import sys
from itertools import accumulate

def read_edges():
    """Bulk read: n m, then m lines u v (1-indexed). Returns 0-indexed lists."""
    data = sys.stdin.buffer.read().split()
    n, m = int(data[0]), int(data[1])
    us = [int(x) - 1 for x in data[2:2 + 2 * m:2]]
    vs = [int(x) - 1 for x in data[3:3 + 2 * m:2]]
    return n, us, vs

def build_lists(n, us, vs):
    g = [[] for _ in range(n)]
    for u, v in zip(us, vs):
        g[u].append(v)
        g[v].append(u)
    return g

def build_csr(n, us, vs):
    """Undirected CSR: neighbours of v are adj[start[v]:start[v + 1]]."""
    deg = [0] * n
    for u in us: deg[u] += 1
    for v in vs: deg[v] += 1
    start = list(accumulate(deg, initial=0))   # pass 1: counts -> offsets
    pos = start[:-1]                           # next free slot of each vertex
    adj = [0] * start[n]
    for u, v in zip(us, vs):                   # pass 2: fill
        adj[pos[u]] = v; pos[u] += 1
        adj[pos[v]] = u; pos[v] += 1
    return start, adj

def build_star(n, us, vs):
    """Forward star: edge i is stored at 2i (u->v) and 2i+1 (v->u); e ^ 1 is the reverse."""
    head = [-1] * n
    nxt = [0] * (2 * len(us)); to = [0] * (2 * len(us))
    for i, (u, v) in enumerate(zip(us, vs)):
        to[2 * i], nxt[2 * i], head[u] = v, head[u], 2 * i
        to[2 * i + 1], nxt[2 * i + 1], head[v] = u, head[v], 2 * i + 1
    return head, nxt, to

Iterate CSR with for v in adj[start[u]:start[u + 1]]; iterate forward star with e = head[u]; while e != -1: v = to[e]; e = nxt[e].

Benchmark · what actually got faster

One CPython 3.12 run with \(n = 2\cdot10^5\), \(m = 4\cdot10^5\) (best of three):

  • Build: list of lists 1.08 s, CSR 0.91 s, forward-star 0.42 s (it is preallocated, with no append), defaultdict(list) 1.17 s.
  • Full DFS: lists 0.51 s, CSR 0.60 s, CSR stored as array('i') 0.43 s, forward-star 0.90 s. The while loop costs more than it saves.
  • Parsing the same input: input() per line 1.77 s, sys.stdin.buffer.readline 0.98 s, one bulk read().split() 0.51 s.

In CPython, flat arrays cost about the same time as lists and save 5–10× memory. The multi-fold time win comes from bulk parsing (L2). PyPy stores int lists unboxed, which is where flat layouts are usually reported to pull ahead. Benchmark on your own judge.

Why defaultdict in a hot loop costs you. Every access hashes the key, and a missing key inserts one. So for v in g[u] on an isolated vertex silently adds a key, and len(g) stops being the vertex count. With dense integer ids, a list is faster and has no side effects. Use defaultdict only for non-integer labels, and compress those to 0…n−1 when the graph is large.

Indexing discipline, self-loops and multi-edges

Convert once at the read (subtract 1 in the parser) and once at the output (add 1). Mixing conventions gives an IndexError on vertex \(n\), or a silently wrong answer because vertex 0 was never connected.

  • A self-loop \((v, v)\) puts \(v\) in its own list twice, so DFS sees an immediate "back edge". In a matrix it overwrites the diagonal entry that Floyd–Warshall uses as \(d[v][v]\).
  • Parallel edges break the "neighbour is my parent, so skip it" test (L64, L73). A matrix silently overwrites them, so keep the minimum weight on purpose. A set of neighbours silently deduplicates them, which is wrong for flows and Euler tours.

Problems

CSES — Building Roads

Observation. With \(c\) connected components you need exactly \(c - 1\) new roads: connect the representative of component \(i\) to the representative of component \(i + 1\). Fewer cannot work, since each road reduces the component count by at most one. Approach: bulk parse, CSR, an iterative stack flood, and one representative per component. \(O(n + m)\). The input has up to \(2\cdot10^5\) edges, so the parse dominates the running time.

def building_roads():
    n, us, vs = read_edges()
    start, adj = build_csr(n, us, vs)
    comp = [-1] * n
    reps = []
    for s in range(n):
        if comp[s] != -1:
            continue
        c = len(reps); reps.append(s); comp[s] = c
        stack = [s]
        while stack:
            u = stack.pop()
            for v in adj[start[u]:start[u + 1]]:
                if comp[v] == -1:
                    comp[v] = c
                    stack.append(v)
    out = [str(len(reps) - 1)]
    out += [f"{reps[i] + 1} {reps[i + 1] + 1}" for i in range(len(reps) - 1)]
    sys.stdout.write("\n".join(out) + "\n")

if __name__ == "__main__":
    building_roads()

Degree / handshake warm-up. Count degrees with the first loop of build_csr, then assert sum(deg) == 2 * m and that the odd-degree count is even. If the statement promises a tree, also assert \(m = n - 1\) and one component. These asserts catch most parse bugs before any algorithm runs.

What breaks
  • Per-line input() on \(2\cdot10^5\) lines: about 3.5× slower than one bulk read (measured above). That alone can turn AC into TLE.
  • Forgetting the reverse edge in an undirected graph: BFS reaches half the graph, and nothing crashes.
  • \(m = 0\): code that reads data[2] unconditionally, or builds a structure from the first edge, crashes on an edgeless test.
  • Multi-test files: a global adj that keeps growing across tests. Reallocate per test.

BFS and Unweighted Shortest Paths

55m video

BFS settles vertices in order of distance, one layer at a time, so in an unweighted graph the first time it reaches a vertex is along a shortest path. Mark vertices when you push them, keep a parent array, and the same twenty lines handle single-source, multi-source, grid and implicit state-space problems.

The algorithm and the visited-on-push invariant

Algorithm · BFS
  1. Set dist[s] = 0, dist[v] = -1 elsewhere; queue = [s].
  2. Pop \(u\) from the front. For each neighbour \(v\) with dist[v] == -1: set dist[v] = dist[u] + 1 and parent[v] = u, then push \(v\) (mark on push).
  3. Repeat until the queue is empty. Unreached vertices keep −1.
Theorem · BFS computes shortest paths

In an unweighted graph, when BFS from \(s\) finishes, dist[v] equals the edge-count distance \(\delta(s, v)\) for every \(v\), and following parent from \(v\) traces a shortest path.

Proof

Invariant: the queue's labels are non-decreasing from front to back and differ by at most 1. This holds initially. Popping \(u\) with label \(d\) leaves labels in \(\{d, d+1\}\), and every push carries \(d + 1\). So vertices are popped in non-decreasing label order. Now induct on \(k = \delta(s,v)\). For \(k = 0\) it is \(s\). For \(v\) at distance \(k + 1\), take a neighbour \(u\) at distance \(k\) on a shortest path. By induction \(u\) gets label \(k\) and is popped. When it is popped, either \(v\) is unlabelled and gets \(k+1\), or it was labelled earlier by a vertex popped no later than \(u\), whose label is \(\le k\). That gives \(v\) a label \(\le k + 1\). A label is always the length of a real walk (the parent chain), so it cannot be below \(\delta\). Hence the label is exactly \(k+1\).

The bug when you mark on pop. If you push every neighbour whose popped flag is unset, a vertex can enter the queue once per incoming edge. Distances usually stay right, but the queue holds \(\Theta(m)\) entries instead of \(n\). From vertex 0 of the complete graph \(K_n\), mark-on-pop pushes about \(n^2/2\) entries and mark-on-push pushes \(n - 1\). With 8-neighbour grids the blow-up is up to 8× in time and memory. If you also write dist[v] at push time without a check, later pushes overwrite good distances with worse ones.

Implementation with reconstruction

def bfs(adj, src):
    n = len(adj)
    dist = [-1] * n
    par = [-1] * n
    dist[src] = 0
    q = [src]
    for u in q:                      # the list grows while we iterate: q doubles as the BFS order
        du = dist[u] + 1
        for v in adj[u]:
            if dist[v] < 0:          # dist doubles as the visited flag, set on push
                dist[v] = du
                par[v] = u
                q.append(v)
    return dist, par

def path_to(par, t):
    p = []
    while t != -1:
        p.append(t)
        t = par[t]
    return p[::-1]

A for loop over a list visits items appended during the loop. In my CPython timings this ran about as fast as deque.popleft(), not faster, and it keeps the visit order for free. Use a deque when you need to push at the front (L65). Each vertex is pushed once and each adjacency entry is scanned once: \(O(n + m)\).

Multi-source BFS and grids

"Distance from each cell to the nearest X" is BFS from a super-source joined by 0-weight edges to every X. You never build it: seeding all sources at distance 0 is exactly the state after the super-source's first layer, so the proof above applies unchanged. Rotting oranges, nearest exit and "monsters chase you" are all this one move.

On grids, keep a cell as one int r * W + c, store rows as bytes, and use a direction table. Pass a limit array to forbid entering a cell at time \(t\) unless \(t\) is below the limit. That turns two BFS runs into a race.

MOVES = ((-1, 0, "U"), (1, 0, "D"), (0, -1, "L"), (0, 1, "R"))

def grid_bfs(H, W, grid, sources, limit=None):
    """grid: list of bytes rows, b'#' is a wall. Returns dist and the move index used to enter each cell."""
    INF = 1 << 30
    dist = [INF] * (H * W)
    how = [-1] * (H * W)
    for s in sources:
        dist[s] = 0
    q = list(sources)
    for cell in q:
        r, c = divmod(cell, W)
        d = dist[cell] + 1
        for k, (dr, dc, _) in enumerate(MOVES):
            nr, nc = r + dr, c + dc
            if 0 <= nr < H and 0 <= nc < W and grid[nr][nc] != 35:      # 35 == ord('#')
                nxt = nr * W + nc
                if dist[nxt] == INF and (limit is None or d < limit[nxt]):
                    dist[nxt] = d
                    how[nxt] = k
                    q.append(nxt)
    return dist, how

Implicit state graphs and bidirectional BFS

When the vertices are states (a word, a lock combination, a board), encode each state as a hashable value, ideally a small int, and generate neighbours on the fly. Word ladder has \(N\) words of length \(L\). Comparing all pairs costs \(O(N^2 L)\). Instead, bucket each word under its \(L\) wildcard patterns (h*t). Two words are adjacent iff they share a bucket. Expanding each bucket only once keeps the total work near \(O(N L^2)\) including slicing: once a bucket is expanded from distance \(d\), every word in it has distance \(\le d+1\), so expanding it again can never improve anything.

from collections import defaultdict

def ladder_length(begin, end, words):
    words = set(words)
    if end not in words:
        return 0
    words.add(begin)
    buckets = defaultdict(list)
    for w in words:
        for i in range(len(w)):
            buckets[w[:i] + "*" + w[i + 1:]].append(w)
    dist = {begin: 1}
    q = [begin]
    for w in q:
        if w == end:
            return dist[w]
        for i in range(len(w)):
            key = w[:i] + "*" + w[i + 1:]
            for x in buckets[key]:
                if x not in dist:
                    dist[x] = dist[w] + 1
                    q.append(x)
            buckets[key] = []        # never expand a bucket twice
    return 0

Bidirectional BFS. If each state has about \(b\) neighbours and the answer is \(d\), one-sided BFS touches about \(b^d\) states. Searching from both ends until the frontiers meet touches about \(2b^{d/2}\), roughly the square root. Expand the smaller frontier a whole layer at a time. When a layer finds a vertex already seen by the other side, take the minimum of \(d_A + 1 + d_B\) over that entire layer. Stopping at the first hit can be off by one.

What breaks
  • Mark on pop: queue blow-up (above). On dense graphs this alone causes TLE or MLE.
  • list.pop(0) as a queue: \(O(n)\) per pop, so \(O(n^2)\) overall.
  • Tuples (r, c) as queue items and dict-based dist on a \(1000\times1000\) grid. Each step allocates and hashes a tuple; flat ints into a list do neither.
  • Monsters ties: use <, not <=. Arriving at the same time as a monster is death.
  • Unreachable target: path_to on a −1 distance returns the single vertex [t]. Check dist[t] first.
  • Implicit graphs: forgetting to mark the start as visited, or generating neighbour states as lists (unhashable).

L64 · DAY 45

DFS: Components, Cycle Detection, Bipartiteness

55m video

DFS explores one branch to the bottom before backing up. The set of vertices currently "open" (entered but not finished) is always a single root-to-node path, and every structural fact in this phase (cycles, bridges, SCCs) is read off edges that point back into that path. In Python, write it with an explicit stack and a per-vertex iterator, never with recursion.

Iterative DFS with an iterator pointer

Recursive DFS on a path of \(10^5\) vertices exceeds CPython's default recursion limit of 1000. Raising the limit and running in a thread with a large stack sometimes works and sometimes segfaults, depending on the judge. The robust form keeps the recursion's state yourself. The stack holds the open vertices, and it[u] is the index of the next neighbour of \(u\) to try. Look at the top \(u\): if it has an untried neighbour, advance it[u] and maybe push. Otherwise \(u\) is finished, so pop it. This gives true pre-order and post-order events, which the "pop, then push all neighbours" shortcut does not. That shortcut is fine for flood fill and wrong for anything needing finish times.

Definition · three colours

White: not yet discovered. Grey: discovered, not finished, so it is on the stack and an ancestor of the current vertex. Black: finished, with its whole subtree explored. Each vertex moves white → grey (push, record tin) → black (pop, record tout), once.

Exploring \(u \to v\) in a directed DFS classifies the edge by \(v\)'s colour:

Edge typeColour of v when u→v is examinedMeaning
treewhitev becomes u's child
backgreyv is an ancestor of u: a cycle
forwardblack, tin[u] < tin[v]v is a finished descendant
crossblack, tin[v] < tin[u]v is in an earlier, finished branch

In an undirected DFS only tree and back edges exist. A "cross" edge \(uv\) would have been explored from whichever endpoint was discovered first, while the other was still white. The bridges and articulation points of L73 and the SCCs of L74 are built entirely on this classification.

Components

For plain reachability, order does not matter, so the cheap stack ("pop, push all white neighbours, mark on push") is enough. One launch per unvisited vertex gives the component labels, the count and the sizes in \(O(n + m)\).

def components(adj):
    n = len(adj)
    comp = [-1] * n
    sizes = []
    for s in range(n):
        if comp[s] != -1:
            continue
        c = len(sizes); comp[s] = c; stack = [s]; size = 0
        while stack:
            u = stack.pop(); size += 1
            for v in adj[u]:
                if comp[v] == -1:
                    comp[v] = c
                    stack.append(v)
        sizes.append(size)
    return comp, sizes

Cycle detection, with the cycle as a certificate

Theorem · Grey-node argument

A directed graph has a cycle iff some DFS examines an edge \(u \to v\) with \(v\) grey.

Proof

(⇐) Grey \(v\) is an ancestor of \(u\), so the tree path \(v \leadsto u\) plus \(u \to v\) is a cycle. (⇒) Let \(v\) be the first vertex of a cycle \(C\) to turn grey. At that moment the rest of \(C\) is white and reachable from \(v\) along \(C\), so by the white-path theorem it all becomes a descendant of \(v\) before \(v\) finishes. In particular this holds for \(v\)'s predecessor \(u\) on \(C\). When \(u\) examines \(u \to v\), the vertex \(v\) is still open, so it is grey.

Since grey vertices are exactly the stack, the cycle is the stack segment from \(v\) up to \(u\). Walking par from \(u\) to \(v\) recovers it.

def directed_cycle(adj):
    """Returns a cycle [v, ..., u, v] or None. Iterative, O(n + m)."""
    n = len(adj)
    color = [0] * n                 # 0 white, 1 grey, 2 black
    par = [-1] * n
    it = [0] * n
    for s in range(n):
        if color[s]:
            continue
        color[s] = 1
        stack = [s]
        while stack:
            u = stack[-1]
            if it[u] < len(adj[u]):
                v = adj[u][it[u]]
                it[u] += 1
                if color[v] == 0:
                    color[v] = 1; par[v] = u; stack.append(v)
                elif color[v] == 1:                 # back edge u -> v
                    cyc = [u]
                    while cyc[-1] != v:
                        cyc.append(par[cyc[-1]])
                    return cyc[::-1] + [v]
            else:
                color[u] = 2
                stack.pop()
    return None

Undirected graphs. The usual test "a visited neighbour that is not my parent means a cycle" fails with parallel edges. Two edges between \(u\) and \(p\) form a genuine 2-cycle, but the second edge also leads to "my parent" and gets skipped. Store edge ids in the adjacency and skip only the edge you arrived by (if i == pe[u]: continue), never the parent vertex. Then a back edge is any edge to a grey vertex, as in the directed case. Self-loops show up as 1-cycles, so filter them if the problem wants length ≥ 3. The same edge-id discipline is mandatory for bridges in L73.

Bipartiteness with an odd-cycle certificate

Theorem · König (1936)

A graph is bipartite iff it has no odd cycle.

Colour by BFS parity. If an edge joins two same-colour vertices, the graph has an odd cycle. BFS edges join layers that differ by at most 1, so same parity means the same layer. Climb both endpoints' parent pointers in lockstep until they meet at their lowest common ancestor. The two climbs have equal length \(k\), so the cycle has \(2k + 1\) edges. That makes "IMPOSSIBLE" checkable rather than just claimed.

def bipartite(adj):
    """(True, colour) or (False, odd cycle as a vertex list)."""
    n = len(adj)
    color = [-1] * n
    par = [-1] * n
    for s in range(n):
        if color[s] != -1:
            continue
        color[s] = 0
        q = [s]
        for u in q:
            for v in adj[u]:
                if color[v] == -1:
                    color[v] = color[u] ^ 1; par[v] = u; q.append(v)
                elif color[v] == color[u]:          # same BFS layer
                    a, b = [u], [v]
                    while a[-1] != b[-1]:
                        a.append(par[a[-1]]); b.append(par[b[-1]])
                    return False, a + b[-2::-1]     # u .. lca .. v, then the edge v-u closes it
    return True, color

Grids, 0-1 BFS, and Implicit State-Space Search

50m video

Most "hard" grid problems are ordinary BFS on a graph you never write down. A vertex is a position plus whatever else the future depends on (keys held, walls broken, direction faced). When edge costs are only 0 and 1, a deque replaces Dijkstra's heap and the search stays linear.

Grids as graphs

A cell's neighbours are computed, not stored. Flatten (r, c) to r * W + c so the visited and distance arrays are flat lists. A further trick: pad the grid with a wall border. Then the four neighbours of an interior cell are cell ± 1 and cell ± W, and no bounds check is needed, which removes four comparisons from the innermost loop.

  • Flood fill / island counting: one BFS or DFS launch per unvisited land cell (L64).
  • Area is the component size. Perimeter \(= 4 \cdot \text{land} - 2 \cdot \text{(adjacent land pairs)}\), since each shared side hides two unit edges. No search is needed for it.
  • Multi-layer grids: with keys and doors, the same cell with a different key set is a different situation. The state becomes (cell, mask), and a door is passable only if its key's bit is set.

0-1 BFS

Algorithm · 0-1 BFS
  1. dist[s] = 0, deque = [s].
  2. Pop \(u\) from the front. For each edge \((u, v, w)\), \(w \in \{0, 1\}\): if dist[u] + w < dist[v], update and push \(v\) to the front if \(w = 0\), to the back if \(w = 1\).
Theorem · Deque invariant

At every moment the labels in the deque are non-decreasing from front to back and span at most two values \(d, d+1\). Hence vertices are popped in non-decreasing distance order, exactly as Dijkstra pops them, and 0-1 BFS computes correct shortest paths in \(O(n + m)\).

Proof

The invariant is trivially true initially. Suppose it holds, and the front has label \(d\), the minimum. After popping it the deque holds labels in \(\{d, d+1\}\), sorted. A 0-edge pushes label \(d\) to the front, which is still sorted with span ≤ 1. A 1-edge pushes \(d+1\) to the back, which is likewise sorted. So the deque acts as a priority queue that always yields a minimum label, and Dijkstra's correctness proof (L67) applies verbatim. Cost: once \(v\) is labelled \(d+1\) while the front is at \(d\), its only possible improvement is to \(d\). So each vertex is pushed at most twice, and each edge is scanned at most twice.

from collections import deque

def min_walls_removed(grid):
    """grid: list of lists of 0/1 (1 = wall, entering it costs 1). LeetCode 2290."""
    H, W = len(grid), len(grid[0])
    INF = H * W + 1
    dist = [INF] * (H * W)
    dist[0] = 0
    dq = deque([0])
    while dq:
        cell = dq.popleft()
        r, c = divmod(cell, W)
        d = dist[cell]
        for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
            if 0 <= nr < H and 0 <= nc < W:
                w = grid[nr][nc]
                nxt = nr * W + nc
                if d + w < dist[nxt]:
                    dist[nxt] = d + w
                    if w:
                        dq.append(nxt)
                    else:
                        dq.appendleft(nxt)
    return dist[H * W - 1]

A stale back-copy of a vertex is popped later and re-scans its edges harmlessly. Add if done[cell]: continue to skip it.

When it replaces Dijkstra. Use it whenever the weights are in \(\{0, 1\}\), or in \(\{0, k\}\) (divide by \(k\)). Dial's algorithm generalises to small integer weights \(0..C\). Keep an array of buckets indexed by tentative distance and sweep it upward, \(O(n + m + D)\) where \(D \le (n-1)C\) is the largest distance. With \(C + 1\) circular buckets the memory is \(O(n + C)\).

Designing a state space

Ask: what must I know at this moment to decide the rest optimally? That tuple is the state. "Shortest path if you may remove at most \(k\) obstacles" is BFS over (cell, removals used), with edges into a wall incrementing the second coordinate. "Moves with modes" (facing, speed, parity, fuel) work the same way. Encode the state as one int, for example (cell * (k + 1) + used), to keep it hashable and cheap.

Memory estimates before you code

States × bytes per state. A Python list of ints costs 8 bytes per slot plus the int objects (small ints are shared). A bytearray visited set costs 1 byte per state. LeetCode 1293 allows a \(40 \times 40\) grid with \(k\) up to 1600, giving \(1600 \cdot 1601 \approx 2.6\cdot10^6\) states: fine as a bytearray, about 20 MB as a list. Better, if \(k \ge H + W - 3\) the Manhattan path is free (its interior has only \(H+W-3\) cells), so return \(H + W - 2\) immediately and the effective \(k\) drops below 80. Keys-and-doors (LeetCode 864) with ≤ 6 keys has \(30 \cdot 30 \cdot 2^6 = 57{,}600\) states.

def sliding_puzzle(board):
    """LeetCode 773: 2x3 board, 0 is the blank. BFS over permutations encoded as strings."""
    start = "".join(str(x) for row in board for x in row)
    nbrs = ((1, 3), (0, 2, 4), (1, 5), (0, 4), (1, 3, 5), (2, 4))   # blank's swaps by index
    dist = {start: 0}
    q = [start]
    for s in q:
        if s == "123450":
            return dist[s]
        z = s.index("0")
        for j in nbrs[z]:
            t = list(s)
            t[z], t[j] = t[j], t[z]
            t = "".join(t)
            if t not in dist:
                dist[t] = dist[s] + 1
                q.append(t)
    return -1

There are 720 arrangements and 360 are reachable (a parity invariant). For larger puzzles (8-puzzle, 9!/2 states), encode the state as an int and use a list or bytearray instead of a dict.

A* in one paragraph. Pop by \(g + h\), where \(g\) is the cost so far and \(h\) a heuristic lower bound on the remaining cost, such as Manhattan distance on a 4-grid. If \(h\) is consistent (\(h(u) \le w(u,v) + h(v)\)), it is Dijkstra on reduced costs, and the first pop of the goal is optimal. A* changes the order of exploration, not the worst case. In contests it rarely beats a well-designed BFS, and an inadmissible \(h\) silently gives wrong answers.

Topological Sort and DAG DP

50m video

A topological order lists the vertices so that every edge points forward. It exists exactly when the graph has no directed cycle, and once you have it, any "best path" or "count paths" question becomes a single left-to-right DP pass. That is why DAGs are the graphs where hard path problems turn easy.

Kahn's algorithm

Algorithm · Kahn (1962)
  1. Compute every in-degree. Put every vertex with in-degree 0 in a queue.
  2. Pop \(u\) and append it to the order. For each \(u \to v\), decrement indeg[v]; if it hits 0, push \(v\).
  3. If the order has fewer than \(n\) vertices, the graph has a cycle.

Correctness. A vertex is output only after all its in-edges were removed, that is, after all its predecessors were output, so every edge points forward. Conversely, the vertices of a cycle can never reach in-degree 0: each still has an in-edge from the cycle vertex before it, which has not been output either. So a short output is the cycle detector, and the vertices left with positive in-degree contain every cycle. The cost is \(O(n + m)\).

DFS order: reverse postorder

Theorem · Finish times order a DAG

In any DFS of a DAG, every edge \(u \to v\) has \(\text{tout}[v] < \text{tout}[u]\). So listing the vertices by decreasing finish time is a topological order.

Proof

Consider the moment \(u \to v\) is examined (\(u\) is grey). If \(v\) is white, it becomes a descendant of \(u\) and finishes first. If \(v\) is black, it has already finished. If \(v\) were grey, \(u \to v\) would be a back edge and there would be a cycle (L64). In both possible cases \(v\) finishes before \(u\).

A memoised DFS (f(u) = combine(f(v) for v in succ(u))) is this order in disguise: f(u) returns only after every successor has, which is exactly postorder. Memoised recursion over a DAG is DAG DP. Its only defect in Python is recursion depth, so for long chains convert it to an explicit topological order and loop.

import heapq

def kahn(adj, smallest=False):
    """Topological order, or None if there is a cycle. smallest=True gives the lexicographically smallest order."""
    n = len(adj)
    indeg = [0] * n
    for u in range(n):
        for v in adj[u]:
            indeg[v] += 1
    if smallest:
        h = [u for u in range(n) if indeg[u] == 0]
        heapq.heapify(h)
        order = []
        while h:
            u = heapq.heappop(h)
            order.append(u)
            for v in adj[u]:
                indeg[v] -= 1
                if indeg[v] == 0:
                    heapq.heappush(h, v)
    else:
        order = [u for u in range(n) if indeg[u] == 0]
        for u in order:                         # the list doubles as the queue
            for v in adj[u]:
                indeg[v] -= 1
                if indeg[v] == 0:
                    order.append(v)
    return order if len(order) == n else None

def topo_dfs(adj):
    """Reverse postorder with an explicit stack; None if a grey vertex is met."""
    n = len(adj)
    state = [0] * n
    it = [0] * n
    post = []
    for s in range(n):
        if state[s]:
            continue
        state[s] = 1
        stack = [s]
        while stack:
            u = stack[-1]
            if it[u] < len(adj[u]):
                v = adj[u][it[u]]
                it[u] += 1
                if state[v] == 0:
                    state[v] = 1
                    stack.append(v)
                elif state[v] == 1:
                    return None
            else:
                state[u] = 2
                post.append(u)
                stack.pop()
    return post[::-1]

Specific orders: smallest and counted

A DAG usually has many topological orders. Replacing Kahn's queue with a min-heap produces the lexicographically smallest sequence. At each step the smallest available vertex goes next, and any order that put something larger first would compare larger at that position. This costs \(O((n+m)\log n)\). Watch for a different requirement that looks the same: "vertex 1 as early as possible, then vertex 2, …". That one is solved by running a max-heap on the reversed graph and reversing the result, and it gives a different answer. Counting all topological orders is #P-complete in general. For \(n \le 20\) it is a bitmask DP over the set of placed vertices, \(O(2^n n)\) (L91).

DP on a DAG

A DP needs its subproblems ordered so each depends only on finished ones. On a graph, "depends on" follows the edges. If there were a cycle, some value would depend on itself, which is why DP needs a DAG. In topological order, every predecessor of \(v\) is final before \(v\) is read:

$$\text{best}[v] = \max_{u \to v} \big(\text{best}[u] + w(u,v)\big), \qquad \text{ways}[v] = \sum_{u \to v} \text{ways}[u].$$

Min-cost, max-cost, longest path in vertices or in weight: each is the same loop with a different combine, in \(O(n + m)\), and negative weights are fine. Contrast: longest simple path in a general graph is NP-hard. A simple path with \(n - 1\) edges is a Hamiltonian path. In a DAG every walk is already simple, so the DP never has to remember which vertices it used.

def dag_paths(adj, order, s, MOD=10**9 + 7):
    """best[v]: most vertices on an s->v path (0 = unreachable); ways[v]: number of s->v paths."""
    n = len(adj)
    best = [0] * n
    ways = [0] * n
    par = [-1] * n
    best[s] = ways[s] = 1
    for u in order:
        if not best[u]:
            continue                            # not reachable from s: must not contribute
        bu, wu = best[u] + 1, ways[u]
        for v in adj[u]:
            ways[v] = (ways[v] + wu) % MOD
            if bu > best[v]:
                best[v] = bu
                par[v] = u
    return best, ways, par

Dijkstra's Algorithm

55m video

With non-negative weights, the unsettled vertex with the smallest tentative distance cannot be improved by anything still unsettled, so it can be finalised now. Dijkstra is that one greedy step repeated with a heap, and most of its contest variants just change what a "vertex" or a "distance" is.

The greedy invariant

Theorem · Dijkstra (1959)

With all \(w \ge 0\), when a vertex \(u\) is popped with the minimum label \(d(u)\) among unsettled vertices, \(d(u) = \delta(s, u)\).

Proof

Let \(S\) be the settled set, all correct by induction. Suppose \(\delta(u) < d(u)\). Follow a shortest \(s \leadsto u\) path and let \(y\) be its first vertex outside \(S\), with predecessor \(x \in S\). When \(x\) was settled it relaxed \((x, y)\), so \(d(y) \le \delta(x) + w(x,y) = \delta(y)\). The rest of the path from \(y\) to \(u\) has non-negative weight, so \(\delta(y) \le \delta(u)\). Then \(d(y) \le \delta(u) < d(u)\), contradicting that \(u\) had the minimum label. Non-negativity is used exactly once, in \(\delta(y) \le \delta(u)\).

Implementation: the lazy heap

Python's heapq has no decrease-key. The lazy version pushes a new entry on every improvement and ignores stale entries when they surface. There are at most \(m + 1\) pushes, so the cost is \(O((n + m)\log m) = O((n+m)\log n)\), since \(\log m \le 2\log n\). The eager version (an indexed heap with decrease-key) keeps at most \(n\) entries but is slower to write and, in Python, usually slower to run. For dense graphs (\(m \approx n^2\)), skip the heap: scan an array for the minimum unsettled vertex, \(O(n^2)\) total, which beats \(O(n^2 \log n)\).

from heapq import heappush, heappop

def dijkstra(adj, s):
    """adj[u] = [(v, w), ...] with w >= 0. Returns dist (INF = unreachable) and parents."""
    INF = 1 << 62
    n = len(adj)
    dist = [INF] * n
    par = [-1] * n
    dist[s] = 0
    pq = [(0, s)]
    while pq:
        d, u = heappop(pq)
        if d > dist[u]:
            continue                    # stale entry: the single most important line
        for v, w in adj[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                par[v] = u
                heappush(pq, (nd, v))
    return dist, par

Without the stale-entry guard the output is still correct, but a vertex can be re-expanded once per stale entry. On adversarial tests that is a quadratic number of edge scans and a TLE.

Why it fails with negative edges. Take edges \(s\to a\,(1)\), \(s \to b\,(2)\), \(b \to a\,(-2)\), \(a \to t\,(1)\). Dijkstra settles \(a\) at 1 and sets \(t = 2\), then settles \(b\) and finds \(a = 0\) too late. The true answer is \(t = 1\). The lazy version happens to re-push \(a\) and recover here, but with negative edges it can re-expand vertices exponentially often, and nothing guarantees correctness. Negative weights belong to L68.

Variants

  • Counting shortest paths, plus min and max edge count among them. Keep parallel arrays and update them on < (reset) and == (merge). This is correct when all weights are positive: every predecessor of \(u\) on a shortest path has a strictly smaller distance, so it was popped first and had already contributed.
  • State graphs. "Shortest path with one discount" (or \(k\) discounts, or fuel, or parity) runs Dijkstra on (vertex, coupons used), encoded as one int.
  • k shortest walks. Allow each vertex to be popped \(k\) times. The \(j\)-th pop of \(t\) is the \(j\)-th shortest walk. Cost \(O(k\,m \log(km))\).
  • Second shortest path is the \(k = 2\) case. Keep d1 and d2 per vertex and push on improving either. If the problem wants a strictly longer second path, use strict inequality on the update.
  • Bottleneck (min-max) path. Replace d + w with max(d, w). Max is monotone along paths, so the proof goes through unchanged. Max-probability path works the same with products of numbers ≤ 1 and a max-heap via negation.
def investigation(adj, MOD=10**9 + 7):
    """CSES Investigation: min price 0 -> n-1, number of min-price routes, min and max flights among them."""
    INF = 1 << 62
    n = len(adj)
    dist = [INF] * n; cnt = [0] * n; lo = [0] * n; hi = [0] * n
    dist[0] = 0; cnt[0] = 1
    pq = [(0, 0)]
    while pq:
        d, u = heappop(pq)
        if d > dist[u]:
            continue
        for v, w in adj[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd; cnt[v] = cnt[u]; lo[v] = lo[u] + 1; hi[v] = hi[u] + 1
                heappush(pq, (nd, v))
            elif nd == dist[v]:
                cnt[v] = (cnt[v] + cnt[u]) % MOD
                lo[v] = min(lo[v], lo[u] + 1); hi[v] = max(hi[v], hi[u] + 1)
    return dist[-1], cnt[-1], lo[-1], hi[-1]

def flight_discount(adj):
    """CSES Flight Discount: one edge may be halved (floor). State x = 2*v + used."""
    INF = 1 << 62
    n = len(adj)
    dist = [INF] * (2 * n)
    dist[0] = 0
    pq = [(0, 0)]
    while pq:
        d, x = heappop(pq)
        if d > dist[x]:
            continue
        u, used = x >> 1, x & 1
        for v, w in adj[u]:
            y = 2 * v + used                    # pay full price, stay in this layer
            if d + w < dist[y]:
                dist[y] = d + w
                heappush(pq, (d + w, y))
            if not used:                        # spend the coupon: move to layer 1
                y, nd = 2 * v + 1, d + w // 2
                if nd < dist[y]:
                    dist[y] = nd
                    heappush(pq, (nd, y))
    return min(dist[2 * n - 2], dist[2 * n - 1])

def k_shortest(adj, s, t, k):
    """CSES Flight Routes: the k smallest s->t walk lengths."""
    pops = [0] * len(adj)
    res = []
    pq = [(0, s)]
    while pq and len(res) < k:
        d, u = heappop(pq)
        if pops[u] == k:
            continue
        pops[u] += 1
        if u == t:
            res.append(d)
        for v, w in adj[u]:
            if pops[v] < k:
                heappush(pq, (d + w, v))
    return res

Python performance

  • Keep dist a list and INF an int. A dict for distances costs a hash per relaxation.
  • Packing heap entries as one int, d << 17 | v for \(n < 2^{17}\), avoids a tuple allocation per push. In one CPython 3.12 run with \(n = 10^5\) and \(m = 2\cdot10^5\) it was about 15–25% faster than tuples. Python ints never overflow, so large \(d\) is safe, only slower.
  • Bind heappush and heappop to local names (as above). PyPy typically runs this loop several times faster than CPython. Use it on Codeforces for \(m \ge 5\cdot10^5\).

Bellman–Ford, Negative Cycles, SPFA

50m video

Bellman–Ford is a DP over the number of edges: after round \(i\), every vertex knows the cheapest walk with at most \(i\) edges. With no negative cycle, \(n-1\) rounds are enough. If round \(n\) still improves something, a negative cycle is reachable, and the parent pointers lead you to it.

The algorithm and why n − 1 rounds suffice

Algorithm · Bellman–Ford
  1. dist[s] = 0, all others ∞.
  2. Repeat \(n - 1\) times: for every edge \((u, v, w)\), if dist[u] + w < dist[v], relax it (stop early if a full round changes nothing).
  3. One more round: any edge that still relaxes certifies a negative cycle reachable from \(s\).
Theorem · Rounds = edges

After round \(i\), dist[v] ≤ the minimum weight of an \(s \leadsto v\) walk with at most \(i\) edges, and dist[v] is always the weight of some real walk. If no negative cycle is reachable from \(s\), some shortest walk is a simple path. A simple path has at most \(n - 1\) edges, so after \(n - 1\) rounds dist \(= \delta\).

Proof

Induct on \(i\). Let a best walk with \(\le i\) edges end with \((u, v)\). Its prefix has \(\le i - 1\) edges, so after round \(i - 1\), dist[u] is at most the prefix's weight. Round \(i\) relaxes \((u,v)\), which makes dist[v] at most the whole walk's weight. Values only ever decrease, so the bound survives the rest of round \(i\). Without negative cycles, deleting a cycle from a walk never increases its weight. So a shortest walk can be taken simple, with at most \(n-1\) edges. Cost: \(O(nm)\). Early termination helps in practice and does not change the worst case.

In the layered-graph view, the vertices are copied once per round, and each edge runs from layer \(i - 1\) to layer \(i\), plus a "stay" edge. Bellman–Ford is DAG DP over these layers (L66). In-place updates mix layers, which can only lower values, so the theorem still holds.

Negative cycles: detect, extract, propagate

To find any negative cycle (not just one reachable from \(s\)), start every dist at 0. That is equivalent to a virtual source with 0-edges to every vertex. Run \(n\) rounds. Let \(x\) be the last vertex relaxed in round \(n\). Following par from \(x\) can never reach a root (a vertex with no parent) within \(n - 1\) steps: that would give a short walk from the virtual source whose weight bounds dist[x] from below, yet round \(n\) just pushed dist[x] below every walk of at most \(n\) edges. So the parent chain cycles. After \(n\) steps back you are on that cycle, and every cycle in the parent graph has negative weight, which is the standard predecessor-subgraph lemma of CLRS ch. 24.

def find_negative_cycle(n, edges):
    """edges: (u, v, w). Returns a negative cycle [c0, c1, ..., c0] or None. O(nm)."""
    dist = [0] * n                   # virtual source: every vertex starts at 0
    par = [-1] * n
    x = -1
    for _ in range(n):
        x = -1
        for u, v, w in edges:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                par[v] = u
                x = v
        if x == -1:
            return None              # converged: no negative cycle anywhere
    for _ in range(n):
        x = par[x]                   # walk back n steps: now x is on the cycle
    cyc = [x]
    y = par[x]
    while y != x:
        cyc.append(y)
        y = par[y]
    cyc.append(x)
    return cyc[::-1]

Reachable from a negative cycle. Detecting a cycle is not enough when the question is about a specific target. A vertex has distance \(-\infty\) iff it is reachable from a negative cycle that is itself reachable from \(s\). The vertices still relaxable after \(n-1\) rounds include at least one vertex of every such cycle. If no edge \(c_i \to c_{i+1}\) of a cycle were relaxable, summing \(d[c_{i+1}] \le d[c_i] + w_i\) around it would give \(0 \le w(C) < 0\). So a second pass, a plain DFS from all of them, marks every \(-\infty\) vertex.

def high_score(n, edges):
    """CSES High Score: max score 0 -> n-1, or -1 if it is unbounded."""
    INF = float("inf")
    E = [(u, v, -w) for u, v, w in edges]       # maximise score = minimise its negation
    dist = [INF] * n
    dist[0] = 0
    for _ in range(n - 1):
        changed = False
        for u, v, w in E:
            if dist[u] + w < dist[v]:           # INF + w stays INF, so unreachable u never relaxes
                dist[v] = dist[u] + w
                changed = True
        if not changed:
            break
    adj = [[] for _ in range(n)]
    for u, v, _ in E:
        adj[u].append(v)
    bad = [False] * n
    stack = []
    for u, v, w in E:
        if dist[u] + w < dist[v] and not bad[v]:
            bad[v] = True
            stack.append(v)
    while stack:                                # second pass: everything downstream is -infinity
        u = stack.pop()
        for v in adj[u]:
            if not bad[v]:
                bad[v] = True
                stack.append(v)
    return -1 if bad[n - 1] else -dist[n - 1]

At most k edges: the layered DP made explicit

When the walk is limited to \(k\) edges (LeetCode 787: \(K\) stops means \(K + 1\) edges), in-place updates are wrong because they can chain several edges in one round. Read from a copy of the previous round. For exactly \(k\) edges, also start each round from ∞ rather than from the previous values.

def cheapest_k_edges(n, edges, s, t, k):
    INF = float("inf")
    dist = [INF] * n
    dist[s] = 0
    for _ in range(k):
        prev = dist[:]                          # this round may use only one more edge
        for u, v, w in edges:
            if prev[u] + w < dist[v]:
                dist[v] = prev[u] + w
    return dist[t] if dist[t] < INF else -1

SPFA: fast on random data, \(O(nm)\) on purpose-built data

SPFA is Bellman–Ford with a queue: only vertices whose distance just changed get their edges rescanned. It reports a negative cycle once some vertex's path reaches \(n\) edges. It is often near-linear on random graphs, but its worst case is still \(\Theta(nm)\). Codeforces setters routinely add grid-like tests built to force that worst case, and heuristics such as SLF and LLL do not save it. Use SPFA only where Bellman–Ford's bound already fits.

Applications: difference constraints and arbitrage

Theorem · Difference constraints

A system \(x_j - x_i \le c_{ij}\) is feasible iff the graph with an edge \(i \to j\) of weight \(c_{ij}\) has no negative cycle. Then \(x = \) the distances from a virtual source with 0-edges to all vertices is a solution: every \(x_v \le 0\), and among such solutions it is the pointwise maximum.

Feasibility comes from the triangle inequality: \(d(j) \le d(i) + c_{ij}\) is literally the constraint. Infeasibility: summing the constraints around a negative cycle gives \(0 \le w(C) < 0\). Rewrite every constraint into this shape first: \(x_j - x_i \ge c\) becomes \(x_i - x_j \le -c\), and \(x_j = x_i + c\) becomes two inequalities. Scheduling with "at least / at most this gap" constraints is this problem in disguise.

def difference_constraints(n, cons):
    """cons: (i, j, c) meaning x[j] - x[i] <= c. Returns a solution list, or None if infeasible."""
    x = [0] * n                                 # virtual source already applied
    for _ in range(n):
        changed = False
        for i, j, c in cons:
            if x[i] + c < x[j]:
                x[j] = x[i] + c
                changed = True
        if not changed:
            return x
    return None                                 # still changing in round n: negative cycle

Arbitrage. Exchange rates \(r_{ij}\) admit a profitable cycle iff \(\prod r > 1\) around it, iff \(\sum (-\log r) < 0\). Run find_negative_cycle on weights \(-\log r_{ij}\), and relax only when the improvement exceeds about \(10^{-12}\). Otherwise rounding error manufactures "cycles" from rates whose product is exactly 1.

All-Pairs Shortest Paths: Floyd–Warshall and Johnson

50m video

Floyd–Warshall is a three-line DP whose loop order is the DP order: allow intermediate vertices one at a time, outermost. Johnson's algorithm fixes negative edges for Dijkstra by adding a potential to every vertex. That reweighting idea comes back in min-cost flow.

The DP: intermediate vertices at most k

Definition

\(d_k[i][j]\) = length of a shortest \(i \leadsto j\) path whose intermediate vertices all lie in \(\{0, \dots, k-1\}\). So \(d_0\) is the edge matrix (0 on the diagonal), and \(d_n\) is the answer.

Derivation

Take an optimal path for \(d_{k+1}[i][j]\). Either it avoids vertex \(k\), and then it is \(d_k[i][j]\). Or it passes through \(k\) exactly once (with no negative cycle, a repeated visit could be cut out), and splits into \(i \leadsto k\) and \(k \leadsto j\), each with intermediates in \(\{0..k-1\}\):

$$d_{k+1}[i][j] = \min\big(d_k[i][j],\ d_k[i][k] + d_k[k][j]\big).$$

Why one matrix suffices. In round \(k\), row \(k\) and column \(k\) do not change: \(d[i][k] \leftarrow \min(d[i][k], d[i][k] + d[k][k])\), and \(d[k][k] = 0\) when there is no negative cycle. So reading them in place reads layer-\(k\) values.

Why k must be outermost. Layer \(k + 1\) needs all of layer \(k\), so \(k\) is the DP's time axis. Put it innermost and each \(d[i][j]\) is computed once, from whatever its neighbours hold at that moment. On the chain \(3 \to 2 \to 1 \to 0\), the \(i, j, k\) order evaluates \(d[3][0]\) before \(d[2][0]\) and \(d[3][1]\) exist, and leaves it at ∞. (It has been shown that repeating the wrong order three times does give correct results, which is a curiosity, not a technique.)

Implementation with reconstruction

def floyd(n, edges):
    """edges (u, v, w). Returns d and nxt; d[i][i] < 0 afterwards means a negative cycle through i."""
    INF = float("inf")                 # INF + negative stays INF, unlike a big int
    d = [[INF] * n for _ in range(n)]
    nxt = [[-1] * n for _ in range(n)]
    for i in range(n):
        d[i][i] = 0
        nxt[i][i] = i
    for u, v, w in edges:
        if w < d[u][v]:                 # keep the lightest parallel edge
            d[u][v] = w
            nxt[u][v] = v
    for k in range(n):
        dk = d[k]
        for i in range(n):
            dik = d[i][k]
            if dik == INF:
                continue
            di, ni = d[i], nxt[i]
            nik = ni[k]
            for j in range(n):
                if dik + dk[j] < di[j]:
                    di[j] = dik + dk[j]
                    ni[j] = nik         # first step towards j is the first step towards k
    return d, nxt

def fw_path(nxt, i, j):
    if nxt[i][j] == -1:
        return None
    p = [i]
    while i != j:
        i = nxt[i][j]
        p.append(i)
    return p
Python speed · be honest about n

The inner loop runs \(n^3\) times. In one CPython 3.12 run, \(n = 250\) took 2.9 s with the loop above. Rebuilding each row with a list comprehension was slower (5.6 s), because it rebuilds the row even when nothing changes. So \(n = 500\) (CSES Shortest Routes II) is roughly 8× that, which is out of reach in CPython. Use PyPy, or numpy where the judge has it: d = np.minimum(d, d[:, k, None] + d[None, k, :]) per \(k\) does each round as one vectorised operation. The dik == INF skip helps a lot on sparse graphs.

What the same loop computes

  • Negative cycles: \(d[i][i] < 0\) after the loop. A pair \((i, j)\) is \(-\infty\) iff some \(k\) has \(d[i][k] < \infty\), \(d[k][k] < 0\) and \(d[k][j] < \infty\).
  • Transitive closure: replace min/+ with or/and. With int bitsets reach[i], round \(k\) is if reach[i] >> k & 1: reach[i] |= reach[k], which is \(O(n^3/w)\) word operations and handles \(n = 2000\) (L115).
  • Diameter / eccentricities: maxima over the finished matrix.
  • Minimax (bottleneck) paths: max(d[i][k], d[k][j]) in place of the sum. The best path's heaviest edge is minimised, and the derivation is unchanged because max, like +, is monotone.
  • Incremental updates. Adding an edge \((a, b, w)\): \(d[i][j] \leftarrow \min(d[i][j], d[i][a] + w + d[b][j])\) for all pairs, \(O(n^2)\). Adding a vertex is exactly one more Floyd round with it as \(k\), after computing its own row and column. Problems that delete vertices one by one are solved by adding them back in reverse, one round each (Codeforces — Greg and Graph).

Johnson: potentials make Dijkstra legal

Theorem · Reweighting

For any potential \(h: V \to \R\), define \(w_h(u, v) = w(u, v) + h(u) - h(v)\). Every \(s \leadsto t\) path's weight changes by exactly \(h(s) - h(t)\), so shortest paths are preserved. If \(h(v) = \delta(q, v)\) for a virtual source \(q\) with 0-edges to all vertices, then \(w_h \ge 0\).

Proof

Along a path the potential terms telescope: \(\sum (w + h(v_{i}) - h(v_{i+1})) = w(P) + h(s) - h(t)\), the same shift for every \(s \leadsto t\) path. Non-negativity is the triangle inequality \(\delta(q,v) \le \delta(q,u) + w(u,v)\).

So run Bellman–Ford once (\(O(nm)\), which also detects negative cycles), then Dijkstra from every vertex on \(w_h\), \(O(nm\log n)\), and undo the shift. For sparse graphs this beats \(n^3\). The same potentials keep Dijkstra valid on the residual graphs of min-cost flow (L79).

def johnson(n, edges):
    """APSP with negative edges allowed. Returns a matrix (inf = unreachable) or None on a negative cycle.
    Uses dijkstra(adj, s) from L67."""
    h = [0] * n                                  # Bellman-Ford from a virtual source
    for _ in range(n):
        changed = False
        for u, v, w in edges:
            if h[u] + w < h[v]:
                h[v] = h[u] + w
                changed = True
        if not changed:
            break
    else:
        return None
    adj = [[] for _ in range(n)]
    for u, v, w in edges:
        adj[u].append((v, w + h[u] - h[v]))      # reduced weight, >= 0
    res = []
    for s in range(n):
        dist, _ = dijkstra(adj, s)
        res.append([dist[v] - h[s] + h[v] if dist[v] < 1 << 62 else float("inf") for v in range(n)])
    return res

Disjoint Set Union I

50m video

A disjoint-set union (DSU) keeps a partition of \(\{0, \dots, n-1\}\) under "merge these two sets" and "are these two in the same set?", each in effectively constant time. Two small heuristics, union by size and path compression, are responsible for all of that speed. In Python, find must be iterative.

The problem and the naive forest

Incremental connectivity: edges arrive one at a time, and queries ask whether \(u\) and \(v\) are connected now. BFS per query is \(O(n + m)\) each. A DSU stores each set as a rooted tree through a parent array, and the root is the set's name. find(x) walks up to the root. union(a, b) links one root under the other. Linked carelessly, the trees become paths: union \(1\) with \(0\), then \(2\) with \(0\), and so on, each time hanging the old root under the new vertex. Then every find(0) walks the whole chain, so \(n\) operations cost \(\Theta(n^2)\).

Union by size: logarithmic height

Theorem · Union by size

If every union hangs the smaller tree's root under the larger tree's root, every tree of size \(s\) has height at most \(\log_2 s\). So find is \(O(\log n)\).

Proof

A vertex's depth grows by 1 only when its tree is hung under a tree at least as large, so the size of the tree containing it at least doubles. Sizes never exceed \(n\), so this happens at most \(\log_2 n\) times. Union by rank (an upper bound on height) gives the same bound by the same argument.

Path compression and the α(n) bound

During find(x), after locating the root, re-point every vertex on the path directly at the root. A later find on any of them takes one step. Path halving (point each visited vertex at its grandparent, in one pass) is a simpler variant with the same bounds.

Theorem · Tarjan (1975); Tarjan & van Leeuwen (1984)

With union by size (or rank) and path compression, any sequence of \(m\) operations on \(n\) elements takes \(O(m\,\alpha(n))\) time, where \(\alpha\) is the inverse Ackermann function. Path compression alone gives \(O(\log n)\) amortised per operation (more precisely \(O(\log_{1 + m/n} n)\)). Fredman and Saks (1989) showed \(\alpha\) cannot be beaten in the cell-probe model.

The honest version. The proof is out of scope here. It is a careful potential argument over "how far a node's rank is below its parent's". What matters in practice: \(\alpha(n) \le 4\) for any \(n\) that fits in the universe, so treat each operation as \(O(1)\). The intuition is that compression makes trees flat exactly where you look, and union by size keeps them shallow everywhere else.

Implementation

class DSU:
    __slots__ = ("p", "sz", "count")

    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n
        self.count = n                     # number of sets

    def find(self, x):
        p = self.p
        root = x
        while p[root] != root:             # pass 1: find the root
            root = p[root]
        while p[x] != root:                # pass 2: point the path at it
            p[x], x = root, p[x]
        return root

    def union(self, a, b):
        a, b = self.find(a), self.find(b)
        if a == b:
            return False
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]
        self.count -= 1
        return True

    def same(self, a, b):
        return self.find(a) == self.find(b)

    def size(self, x):
        return self.sz[self.find(x)]

p[x], x = root, p[x] evaluates the right side first, then assigns p[x] (old x) before x. Path halving is while p[x] != x: p[x] = p[p[x]]; x = p[x].

Why not recursive find? The textbook p[x] = find(p[x]) recurses once per level. With union by size the depth is at most \(\log_2 n\), so it fits. Quick contest code often drops the size rule (p[a] = b), and then a \(10^5\)-long chain hits CPython's recursion limit. Even when it fits, a Python call costs far more than a loop iteration. In hot loops, inline find as a local closure over a list rather than calling a method.

Benchmark · what each heuristic buys

Adversarial chain (\(n = 4000\): \(n-1\) unions that each hang the old root under a new vertex, then \(n\) finds from the deepest vertex): naive 3.10 s, size only 0.024 s, compression only 0.008 s, both 0.006 s. Random (\(n = 2\cdot10^5\), \(4\cdot10^5\) unions): size only 0.98 s, compression only 1.42 s, both 0.65 s. The naive version is quadratic on the chain and was not run at the random size.

DSU with extra data

Anything that combines associatively when two sets merge can live at the root: size, min, max, sum, a count of special elements, or the component's edge count (which tells you "is this component a tree?"). Update it in union and read it at find(x). Parity / offset DSU stores, per vertex, its relation to its parent: colour xor for bipartiteness, or a numeric offset for "\(x_a - x_b = d\)" systems. Compression must accumulate the relation along the path.

class ParityDSU:
    """x[v] = colour(v) xor colour(parent). Detects odd cycles as edges arrive."""
    def __init__(self, n):
        self.p = list(range(n))
        self.x = [0] * n
        self.sz = [1] * n

    def find(self, a):
        """(root, colour(a) xor colour(root)), with path compression."""
        p, x = self.p, self.x
        path = []
        while p[a] != a:
            path.append(a)
            a = p[a]
        acc = 0
        for v in reversed(path):           # nearest the root first: accumulate parity to the root
            acc ^= x[v]
            x[v] = acc
            p[v] = a
        return a, (x[path[0]] if path else 0)

    def union(self, a, b, d=1):
        """Impose colour(a) xor colour(b) == d. False means contradiction (an odd cycle when d = 1)."""
        (ra, pa), (rb, pb) = self.find(a), self.find(b)
        if ra == rb:
            return (pa ^ pb) == d
        if self.sz[ra] < self.sz[rb]:
            ra, rb, pa, pb = rb, ra, pb, pa
        self.p[rb] = ra
        self.x[rb] = pa ^ pb ^ d           # so that colour(a) ^ colour(b) comes out as d
        self.sz[ra] += self.sz[rb]
        return True

DSU II: Rollback, Offline Tricks, Kruskal Reconstruction Tree

50m video

A DSU cannot delete an edge, but it can undo its most recent merge. When the queries are known in advance, you can schedule them so that only undos are needed (divide and conquer over time), or so that only insertions are needed (sort by weight). For bottleneck questions, record the merges themselves as a tree.

Rollback: undo, not delete

Deleting an arbitrary edge can split a component, and nothing in the parent array says where. Undoing the last union is easy if you remember what it changed: one parent pointer and one size. Path compression ruins this. A single find rewrites many pointers, so the undo log would be long. Worse, the amortised analysis assumes expensive finds are paid for by later cheap ones, and an adversary can undo the flattening and make you pay again. So a rollback DSU uses union by size only. That gives \(O(\log n)\) worst-case find (L70) and \(O(1)\) undo.

class RollbackDSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n
        self.count = n
        self.hist = []                     # one entry per union call: the attached root, or -1

    def find(self, x):
        p = self.p
        while p[x] != x:                   # no compression: O(log n) by union by size
            x = p[x]
        return x

    def union(self, a, b):
        a, b = self.find(a), self.find(b)
        if a == b:
            self.hist.append(-1)
            return False
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]
        self.count -= 1
        self.hist.append(b)
        return True

    def snapshot(self):
        return len(self.hist)

    def rollback(self, snap):
        while len(self.hist) > snap:
            b = self.hist.pop()
            if b != -1:
                a = self.p[b]
                self.sz[a] -= self.sz[b]
                self.p[b] = b
                self.count += 1

Offline dynamic connectivity: divide and conquer on time

Suppose edges are added and removed over time \(0..T-1\), and you need the component count (or "are \(u, v\) connected?") at each time. Each edge is alive on an interval \([l, r)\). Build a segment tree over time and store the edge at the \(O(\log T)\) canonical nodes that tile \([l, r)\). DFS the tree: at a node, union its edges; recurse into the children; then roll back to the snapshot. When you reach leaf \(t\), the DSU holds exactly the edges alive at \(t\), because those are the edges stored on the root-to-leaf path. Each edge is united \(O(\log T)\) times at \(O(\log n)\) each, for a total of \(O(m \log T \log n)\).

def offline_connectivity(n, T, intervals):
    """intervals: (l, r, u, v) = edge uv alive at times l..r-1. Returns the component count at each time."""
    size = 1
    while size < T:
        size *= 2
    seg = [[] for _ in range(2 * size)]
    for l, r, u, v in intervals:           # canonical cover of [l, r), bottom-up
        l += size; r += size
        while l < r:
            if l & 1:
                seg[l].append((u, v)); l += 1
            if r & 1:
                r -= 1; seg[r].append((u, v))
            l >>= 1; r >>= 1
    dsu = RollbackDSU(n)
    ans = [0] * T

    def go(node, lo, hi):                  # recursion depth is only log2(size)
        snap = dsu.snapshot()
        for u, v in seg[node]:
            dsu.union(u, v)
        if hi - lo == 1:
            if lo < T:
                ans[lo] = dsu.count
        else:
            mid = (lo + hi) // 2
            go(2 * node, lo, mid)
            go(2 * node + 1, mid, hi)
        dsu.rollback(snap)

    go(1, 0, size)
    return ans

Answer queries in a useful order

The insertion-only special case needs no rollback. If each query asks about the graph restricted to edges with weight \(\le L\) (or added before time \(t\)), sort the queries by \(L\), sweep the edges in weight order with a plain DSU, and answer each query when its threshold is reached. This is the "process queries in the order that makes the structure monotone" pattern from L24. Kruskal reconstruction tree

Process edges by increasing weight. Each time an edge \(e\) of weight \(w\) merges two components with roots \(a\) and \(b\), create a new node \(z\) with weight \(w\) and children \(a\) and \(b\), and make \(z\) the new root. The result has the \(n\) original vertices as leaves, at most \(n - 1\) internal nodes, and weights that never decrease going up.

Theorem · Bottleneck = LCA weight

For connected \(u, v\), the minimum over all \(u\)–\(v\) paths of the maximum edge weight equals the weight of \(\mathrm{LCA}(u, v)\) in the Kruskal reconstruction tree.

Proof

Let \(z = \mathrm{LCA}(u,v)\), created by edge \(e\) of weight \(w\). Just before \(e\), \(u\) and \(v\) lay in the two components that \(e\) joined, each connected using already-processed edges of weight \(\le w\). Adding \(e\) gives a \(u\)–\(v\) path with maximum \(\le w\). Conversely, \(u\) and \(v\) were disconnected using only the edges processed before \(e\), so every \(u\)–\(v\) path uses some edge processed at \(e\) or later, of weight \(\ge w\).

def kruskal_tree(n, edges):
    """edges: (w, u, v). Returns par, wt of the reconstruction forest; leaves 0..n-1, par[x] > x."""
    dsu = list(range(2 * n))
    par = [-1] * (2 * n)
    wt = [0] * (2 * n)

    def find(x):
        r = x
        while dsu[r] != r:
            r = dsu[r]
        while dsu[x] != r:
            dsu[x], x = r, dsu[x]
        return r

    z = n
    for w, u, v in sorted(edges):
        a, b = find(u), find(v)
        if a != b:
            par[a] = par[b] = z
            dsu[a] = dsu[b] = z            # the new node is the set's representative
            wt[z] = w
            z += 1
    return par[:z], wt[:z]

def bottleneck_queries(n, edges, queries):
    """For each (a, b): the minimum possible maximum edge on an a-b path, or -1 if disconnected."""
    par, wt = kruskal_tree(n, edges)
    N = len(par)
    depth = [0] * N
    for x in range(N - 1, -1, -1):          # parents have larger ids: no DFS needed
        if par[x] != -1:
            depth[x] = depth[par[x]] + 1
    up = [[p if p != -1 else x for x, p in enumerate(par)]]
    for _ in range(N.bit_length() - 1):
        prev = up[-1]
        up.append([prev[prev[x]] for x in range(N)])
    res = []
    for a, b in queries:
        if depth[a] < depth[b]:
            a, b = b, a
        diff, k = depth[a] - depth[b], 0
        while diff:
            if diff & 1:
                a = up[k][a]
            diff >>= 1; k += 1
        if a != b:
            for k in range(len(up) - 1, -1, -1):
                if up[k][a] != up[k][b]:
                    a, b = up[k][a], up[k][b]
            a, b = up[0][a], up[0][b]
        res.append(wt[a] if a == b else -1)   # a == b on input gives wt[a] = 0
    return res

DSU as a "next free slot" pointer

Keep nxt[i] = the smallest unused index \(\ge i\). When \(i\) gets used, set nxt[i] = i + 1, and find with compression skips whole used runs. Painting problems where later operations override earlier ones become one pass in reverse: each cell is painted once, by the last operation that covers it, in \(O((n + q)\,\alpha)\). The same idiom assigns the "first free seat or day at or after \(t\)".

def paint_last_wins(n, ops):
    """ops: (l, r, colour) on cells l..r inclusive, later ops win. 0 = never painted."""
    nxt = list(range(n + 1))
    def find(x):
        r = x
        while nxt[r] != r:
            r = nxt[r]
        while nxt[x] != r:
            nxt[x], x = r, nxt[x]
        return r
    colour = [0] * n
    for l, r, c in reversed(ops):
        i = find(l)
        while i <= r:
            colour[i] = c
            nxt[i] = i + 1
            i = find(i + 1)
    return colour

Minimum Spanning Trees

55m video

Two exchange arguments, the cut property and the cycle property, are the whole theory of minimum spanning trees. Kruskal, Prim and Borůvka are three schedules for applying the cut property, and second-best MST, bottleneck trees and clustering all fall out of the same swap.

Cut and cycle properties

Definition

A spanning tree of a connected graph uses \(n-1\) edges to connect all vertices. An MST minimises the total weight. A cut \((S, V \setminus S)\) is crossed by edges with one endpoint on each side.

Theorem · Cut and cycle properties
  1. Cut: for any cut, a minimum-weight crossing edge belongs to some MST. If it is the unique minimum, it belongs to every MST.
  2. Cycle: if \(e\) is strictly the heaviest edge on some cycle, \(e\) belongs to no MST.

Consequently, if all weights are distinct, the MST is unique.

Proof

(1) Let \(T\) be an MST and \(e\) a lightest crossing edge, with \(e \notin T\). Then \(T + e\) contains a cycle through \(e\). A cycle crosses a cut an even number of times, so it contains another crossing edge \(f \in T\), with \(w(f) \ge w(e)\). \(T' = T + e - f\) is a spanning tree with \(w(T') \le w(T)\), so it is an MST containing \(e\). If \(e\) is the unique minimum, \(w(T') < w(T)\) and \(T\) was not minimal. (2) Suppose \(e \in T\). Deleting \(e\) splits \(T\) into two sides. The rest of the cycle reconnects them, so it contains a crossing edge \(f\) with \(w(f) < w(e)\), and \(T - e + f\) is lighter.

Kruskal and Prim

Kruskal sorts the edges and adds each one that joins two different DSU components. When it adds \(e\) joining component \(A\) to another, every lighter edge leaving \(A\) was seen earlier and would have merged \(A\) already. So \(e\) is the lightest edge across \((A, V\setminus A)\), and the cut property applies. Cost: \(O(m \log m)\), all of it the sort. Prim grows one tree from a root and always takes the lightest edge leaving it, which is the cut property for \((\text{tree}, \text{rest})\). It is Dijkstra's loop with w in place of d + w: \(O(m \log n)\) with a heap. On dense graphs, scanning an array for the cheapest non-tree vertex is \(O(n^2)\), which beats any heap there.

from heapq import heappush, heappop

def kruskal(n, edges):
    """edges: (w, u, v). Returns (total, indices of tree edges), or (None, ...) if disconnected."""
    p = list(range(n))
    def find(x):
        r = x
        while p[r] != r:
            r = p[r]
        while p[x] != r:
            p[x], x = r, p[x]
        return r
    total, used = 0, []
    for i in sorted(range(len(edges)), key=edges.__getitem__):
        w, u, v = edges[i]
        a, b = find(u), find(v)
        if a != b:
            p[a] = b
            total += w
            used.append(i)
    return (total if len(used) == n - 1 else None), used

def prim(adj):
    """adj[u] = [(v, w)]. MST weight, or None if disconnected."""
    n = len(adj)
    seen = [False] * n
    total, cnt = 0, 0
    pq = [(0, 0)]
    while pq:
        w, u = heappop(pq)
        if seen[u]:
            continue
        seen[u] = True
        total += w
        cnt += 1
        for v, wv in adj[u]:
            if not seen[v]:
                heappush(pq, (wv, v))
    return total if cnt == n else None

Borůvka: in each round, every component picks its cheapest outgoing edge (break ties by edge index, or cycles can form), and all of them are added at once. Each component merges with at least one other, so the count at least halves, giving \(O(\log n)\) rounds and \(O(m \log n)\) total. Every round is independent per component, which makes it the parallel-friendly MST algorithm. It is also a building block of the Karger–Klein–Tarjan randomised linear-time MST algorithm.

Variants

  • Maximum spanning tree: sort descending.
  • Forced edge: union it first and add its weight, then run Kruskal.
  • Minimum bottleneck spanning tree (minimise the heaviest edge): every MST is one. If some tree had a lighter maximum, the MST's heaviest edge \(e\) would be the strictly heaviest edge on a cycle closed by that tree, which the cycle property forbids. The converse fails: a bottleneck tree need not be an MST. The minimax path between two vertices runs along the MST (L71's KRT).
  • Counting MSTs: group edges of equal weight and apply Kirchhoff's matrix-tree theorem to each group on the contracted graph. Mention-level; it needs determinants mod \(p\) (Phase 8).
  • Geometric MST: on \(n\) points with Manhattan distance, the complete graph is too big. For each point, only its nearest neighbour in each of 8 octants can be an MST edge, and a sweep finds them in \(O(n \log n)\), leaving \(O(n)\) candidate edges for Kruskal. For \(n \le 2000\), just run dense Prim.
  • Clustering: deleting the \(k - 1\) heaviest MST edges gives the \(k\)-clustering with maximum minimum spacing (single linkage).

Second-best MST

Theorem · One swap suffices

Among spanning trees other than a given MST \(T\), a lightest one is \(T + e - f\) for some non-tree edge \(e = (u, v)\), where \(f\) is the heaviest edge of \(T\) on the \(u\)–\(v\) path. (CLRS Problem 23-1.)

So the answer is \(\min_{e \notin T} \big(w(T) - \text{maxOnPath}_T(u, v) + w(e)\big)\). Path maxima come from binary lifting with a max table alongside the ancestor table (L57), or from KRT LCAs. That is \(O(m \log n)\) overall. A strictly larger second-best needs the largest path edge that is strictly below \(w(e)\), so keep the top two distinct maxima per jump.

def second_best_mst(n, edges):
    """edges (w, u, v), graph connected. Returns (w(T), lightest spanning tree != T, or None)."""
    total, used = kruskal(n, edges)
    in_tree = [False] * len(edges)
    adj = [[] for _ in range(n)]
    for i in used:
        w, u, v = edges[i]
        in_tree[i] = True
        adj[u].append((v, w)); adj[v].append((u, w))
    LOG = max(1, n.bit_length())
    up = [[0] * n for _ in range(LOG)]
    mx = [[0] * n for _ in range(LOG)]
    depth = [0] * n
    seen = [False] * n; seen[0] = True
    order = [0]
    for u in order:                                   # BFS: parents, depths, parent-edge weights
        for v, w in adj[u]:
            if not seen[v]:
                seen[v] = True; depth[v] = depth[u] + 1
                up[0][v] = u; mx[0][v] = w
                order.append(v)
    for k in range(1, LOG):
        uk, mk, up1, mx1 = up[k], mx[k], up[k - 1], mx[k - 1]
        for v in range(n):
            mid = up1[v]
            uk[v] = up1[mid]
            mk[v] = max(mx1[v], mx1[mid])

    def path_max(a, b):
        res = float("-inf")
        if depth[a] < depth[b]:
            a, b = b, a
        diff, k = depth[a] - depth[b], 0
        while diff:
            if diff & 1:
                res = max(res, mx[k][a]); a = up[k][a]
            diff >>= 1; k += 1
        if a == b:
            return res
        for k in range(LOG - 1, -1, -1):
            if up[k][a] != up[k][b]:
                res = max(res, mx[k][a], mx[k][b])
                a, b = up[k][a], up[k][b]
        return max(res, mx[0][a], mx[0][b])

    best = None
    for i, (w, u, v) in enumerate(edges):
        if not in_tree[i] and u != v:
            cand = total - path_max(u, v) + w
            if best is None or cand < best:
                best = cand
    return total, best

Bridges, Articulation Points, Biconnected Components

55m video

An undirected DFS has only tree edges and back edges, so a subtree can escape to the rest of the graph only through a back edge to an ancestor. Record, for each vertex, the highest ancestor its subtree can reach (low). Bridges and articulation points are then a single comparison per tree edge.

tin, low, and what they mean

Definition

A bridge is an edge whose removal increases the number of components. An articulation point (cut vertex) is a vertex whose removal does. In a DFS, tin[v] is the discovery time, and

$$\text{low}[v] = \min\big(\text{tin}[v],\ \min\{\text{tin}[w] : (x, w) \text{ a back edge},\ x \in \text{subtree}(v)\}\big),$$

where the tree edge from \(v\) to its parent does not count as a back edge. In words, low[v] is the earliest vertex the subtree of \(v\) can reach with at most one back edge.

It is computed bottom-up: low[v] = min(tin[v], tin[w] for back edges v–w, low[c] for children c). "The parent edge does not count" must be enforced by edge id, not by parent vertex. With two parallel edges \(p\)–\(v\), the second one is a real back edge, and it means \(p\)–\(v\) is not a bridge.

Theorem · Bridge and articulation conditions
  1. A tree edge \((p, v)\) is a bridge iff \(\text{low}[v] > \text{tin}[p]\).
  2. A non-root \(p\) is an articulation point iff some child \(v\) has \(\text{low}[v] \ge \text{tin}[p]\).
  3. The DFS root is an articulation point iff it has at least two DFS children.
Proof

Undirected DFS has no cross edges (L64), so every edge leaving subtree(\(v\)) other than \((p,v)\) is a back edge to a proper ancestor of \(v\). (1) Removing \((p, v)\) isolates subtree(\(v\)) iff no such back edge exists. Any such back edge reaches \(p\) or above, so it exists iff \(\text{low}[v] \le \text{tin}[p]\). (2) Removing \(p\) cuts subtree(\(v\)) off from \(p\)'s ancestors iff no back edge from subtree(\(v\)) reaches strictly above \(p\), that is, iff \(\text{low}[v] \ge \text{tin}[p]\). A non-root \(p\) has ancestors, so something is cut off. (3) The root has no ancestors. Different child subtrees can only be joined through cross edges, which do not exist, so removing the root disconnects them iff there are at least two.

Iterative Tarjan for bridges and articulation points

def bridges_and_cut_vertices(n, edges):
    """edges: list of (u, v); parallel edges allowed. Returns (bridge edge ids, is_cut list). O(n + m)."""
    adj = [[] for _ in range(n)]
    for i, (u, v) in enumerate(edges):
        adj[u].append((v, i))
        adj[v].append((u, i))
    tin = [-1] * n
    low = [0] * n
    pedge = [-1] * n                       # edge id used to enter each vertex
    it = [0] * n
    is_cut = [False] * n
    bridges = []
    timer = 0
    for root in range(n):
        if tin[root] != -1:
            continue
        tin[root] = low[root] = timer; timer += 1
        stack = [root]
        children = 0
        while stack:
            u = stack[-1]
            if it[u] < len(adj[u]):
                v, eid = adj[u][it[u]]
                it[u] += 1
                if eid == pedge[u]:
                    continue               # skip the edge we came in by, by id
                if tin[v] == -1:
                    pedge[v] = eid
                    tin[v] = low[v] = timer; timer += 1
                    stack.append(v)
                    if u == root:
                        children += 1
                elif tin[v] < low[u]:      # back edge to an ancestor
                    low[u] = tin[v]
            else:
                stack.pop()
                if stack:                  # finish u: report to its parent p
                    p = stack[-1]
                    if low[u] < low[p]:
                        low[p] = low[u]
                    if low[u] > tin[p]:
                        bridges.append(pedge[u])
                    if low[u] >= tin[p] and p != root:
                        is_cut[p] = True
        if children >= 2:
            is_cut[root] = True
    return bridges, is_cut

The recursion is mandatory to remove at \(n = 10^5\) in Python. The parent's low is updated when the child is popped, which is exactly where the recursive version would return.

Bridge tree and biconnected components

Delete the bridges. What remains splits into 2-edge-connected components: inside one, every pair is joined by two edge-disjoint paths. Contract each component to a node and put the bridges back. The result is a tree (a forest if the graph was disconnected), because any cycle in it would contain a bridge, and a bridge lies on no cycle. Questions about "edges you cannot avoid" become tree questions: the bridges on any \(u\)–\(v\) route are exactly the edges on the tree path between their components. Answer them with LCA (L57). The classic "add the fewest edges to make the graph bridgeless" (connected case) has answer \(\lceil L/2 \rceil\), where \(L\) is the number of leaves of the bridge tree (0 if it is one node). Pairing leaf \(i\) with leaf \(i + L/2\) in DFS order achieves it.

def bridge_tree(n, edges, bridges):
    """Label 2-edge-connected components; return (comp, adjacency of the bridge tree)."""
    is_bridge = [False] * len(edges)
    for i in bridges:
        is_bridge[i] = True
    adj = [[] for _ in range(n)]
    for i, (u, v) in enumerate(edges):
        if not is_bridge[i]:
            adj[u].append(v); adj[v].append(u)
    comp = [-1] * n
    c = 0
    for s in range(n):
        if comp[s] == -1:
            comp[s] = c
            stack = [s]
            while stack:
                u = stack.pop()
                for v in adj[u]:
                    if comp[v] == -1:
                        comp[v] = c; stack.append(v)
            c += 1
    tree = [[] for _ in range(c)]
    for i in bridges:
        u, v = edges[i]
        tree[comp[u]].append(comp[v]); tree[comp[v]].append(comp[u])
    return comp, tree
Algorithm · Vertex-biconnected components (edge stack)
  1. In the same DFS, push every edge onto an edge stack the first time it is examined: tree edges when you descend, back edges when \(\text{tin}[v] < \text{tin}[u]\).
  2. When finishing child \(v\) of \(p\) with \(\text{low}[v] \ge \text{tin}[p]\), pop edges down to and including \((p, v)\). Those edges form one biconnected component (a "block").
  3. Cut vertices are exactly the vertices in two or more blocks. Joining each block to its cut vertices gives the block-cut tree, the vertex analogue of the bridge tree.

  • CSES — Necessary Roads: print the bridges. Necessary Cities: print the cut vertices. Both come from one call, \(O(n + m)\) for \(n = 10^5\), \(m = 2\cdot10^5\).
  • LeetCode 1192 (Critical Connections): bridges. 1568 (Minimum Number of Days to Disconnect Island): the answer is 0, 1 or 2. It is 0 if the land is not exactly one island, and 1 if the land graph has a cut vertex (or only one cell). Otherwise it is 2, because a corner-most cell can always be isolated by removing its at most two neighbours.
  • Codeforces bridge-tree problems: the recurring shape is "a route must pass some edges, maximise or count them". Build the bridge tree, then use a tree diameter or path queries.
What breaks
  • Skipping the parent vertex instead of the parent edge: parallel edges get reported as bridges.
  • low[u] = min(low[u], low[v]) for a back edge: it must be tin[v]. Using low[v] is harmless for bridges but wrong for articulation points.
  • Forgetting the root rule: a leaf root, or a root with one child, is not a cut vertex, yet \(\text{low}[v] \ge \text{tin}[\text{root}] = 0\) always holds.
  • Disconnected graphs: loop over all roots, and reset children per root.
  • Recursion: depth \(10^5\) on a path graph.

Strongly Connected Components and Condensation

55m video

Collapse every strongly connected component of a directed graph to a single node and what remains is a DAG. That one reduction turns "cycles make this hard" into "DP on a DAG" (L66). Kosaraju gets the components from two DFS passes and a finish-order lemma; Tarjan gets them in one pass with low-links.

Strong connectivity and the condensation

Definition

\(u\) and \(v\) are strongly connected if each reaches the other. This is an equivalence relation, and its classes are the SCCs. The condensation has one node per SCC and an edge \(C \to C'\) whenever some edge goes from \(C\) to \(C'\). It is a DAG: a cycle through several SCCs would make them mutually reachable, hence one SCC.

Kosaraju: two passes and one lemma

Lemma · Finish order

Run a full DFS on \(G\) and let \(f(C)\) be the latest finish time of any vertex in SCC \(C\). If the condensation has an edge \(C \to C'\), then \(f(C) > f(C')\).

Proof

If the DFS enters \(C\) first, at \(x\), then everything in \(C \cup C'\) is white and reachable from \(x\). By the white-path theorem it all finishes before \(x\), so \(f(C) = f(x) > f(C')\). If it enters \(C'\) first, it cannot reach \(C\) from there (that would merge them), so all of \(C'\) finishes while \(C\) is still white, and \(f(C') < f(C)\).

Algorithm. DFS on \(G\) and record the finish order. Then process vertices in decreasing finish time, running a DFS on the reversed graph \(G^T\) from each unassigned one, and label everything it reaches as one SCC. Why it works: the first start vertex lies in the SCC \(C\) with the largest \(f\). An edge leaving \(C\) in \(G^T\) is an edge entering \(C\) in \(G\), from some \(C''\) with \(f(C'') > f(C)\), which is impossible. So the reverse DFS cannot escape \(C\). Remove \(C\) and repeat the argument. Components come out in topological order of the condensation. Cost: \(O(n + m)\) plus building \(G^T\).

Tarjan: one pass with low-links

DFS once, pushing each vertex onto a component stack when it is discovered. low[u] = the smallest tin reachable from \(u\)'s subtree through edges to vertices still on the stack. A vertex whose finished subtree cannot reach above it (low[u] == tin[u]) is the root of an SCC. Pop the stack down to \(u\), and that is the component. Vertices already popped belong to finished SCCs, which are sinks relative to the current one, so edges to them are ignored. That is what the on-stack flag is for. Components come out in reverse topological order, sinks first.

def kosaraju(adj):
    """Returns (count, comp) with components numbered in topological order."""
    n = len(adj)
    radj = [[] for _ in range(n)]
    for u in range(n):
        for v in adj[u]:
            radj[v].append(u)
    seen = [False] * n
    it = [0] * n
    order = []                                  # vertices by finish time
    for s in range(n):
        if seen[s]:
            continue
        seen[s] = True
        stack = [s]
        while stack:
            u = stack[-1]
            if it[u] < len(adj[u]):
                v = adj[u][it[u]]
                it[u] += 1
                if not seen[v]:
                    seen[v] = True
                    stack.append(v)
            else:
                order.append(u)
                stack.pop()
    comp = [-1] * n
    c = 0
    for s in reversed(order):
        if comp[s] != -1:
            continue
        comp[s] = c
        stack = [s]
        while stack:                            # plain flood on G^T: order irrelevant here
            u = stack.pop()
            for v in radj[u]:
                if comp[v] == -1:
                    comp[v] = c
                    stack.append(v)
        c += 1
    return c, comp

def tarjan_scc(n, adj):
    """Returns (count, comp) with components numbered in REVERSE topological order."""
    tin = [-1] * n; low = [0] * n; onst = [False] * n; comp = [-1] * n
    it = [0] * n
    st = []
    timer = c = 0
    for s in range(n):
        if tin[s] != -1:
            continue
        tin[s] = low[s] = timer; timer += 1
        st.append(s); onst[s] = True
        call = [s]
        while call:
            u = call[-1]
            if it[u] < len(adj[u]):
                v = adj[u][it[u]]
                it[u] += 1
                if tin[v] == -1:
                    tin[v] = low[v] = timer; timer += 1
                    st.append(v); onst[v] = True
                    call.append(v)
                elif onst[v] and tin[v] < low[u]:
                    low[u] = tin[v]
            else:
                call.pop()
                if call and low[u] < low[call[-1]]:
                    low[call[-1]] = low[u]
                if low[u] == tin[u]:            # u roots an SCC: pop it off
                    while True:
                        x = st.pop()
                        onst[x] = False
                        comp[x] = c
                        if x == u:
                            break
                    c += 1
    return c, comp

Which to memorise: Kosaraju is easier to get right iteratively. Tarjan saves the reverse graph and is what L75's 2-SAT code calls (tarjan_scc(n, adj)).

Condensation + DAG DP

The standard reduction: label SCCs, aggregate per component (sum of coins, size, min cost), build the condensation edges, then DP in topological order. CSES — Coin Collector: the best route may loop inside an SCC and collect everything in it, so the node value is the component's coin total and the answer is the maximum-weight path in the DAG.

def coin_collector(adj, coins):
    c, comp = kosaraju(adj)
    val = [0] * c
    for v, k in enumerate(coins):
        val[comp[v]] += k
    cadj = [[] for _ in range(c)]
    for u in range(len(adj)):
        for v in adj[u]:
            if comp[u] != comp[v]:
                cadj[comp[u]].append(comp[v])
    best = val[:]
    for x in range(c - 1, -1, -1):              # reverse topological: successors are done
        for y in cadj[x]:
            if val[x] + best[y] > best[x]:
                best[x] = val[x] + best[y]
    return max(best)

  • CSES — Planets and Kingdoms: print the labels. Planets Cycles: a functional graph (out-degree exactly 1). Each weak component is one cycle with in-trees hanging off it (a rho, ρ). Floyd's tortoise and hare (L31) finds the cycle from one start. For all starts at once, walk and colour.
def planets_cycles(nxt):
    """Functional graph: for each start, the number of steps until some vertex repeats."""
    n = len(nxt)
    ans = [0] * n
    state = [0] * n                             # 0 new, 1 on the current walk, 2 solved
    for s in range(n):
        if state[s]:
            continue
        path = []
        u = s
        while state[u] == 0:
            state[u] = 1
            path.append(u)
            u = nxt[u]
        if state[u] == 1:                       # the walk closed a new cycle at u
            i = path.index(u)
            for x in path[i:]:
                ans[x] = len(path) - i
                state[x] = 2
            path = path[:i]
        for x in reversed(path):                # tail vertices: one more than their successor
            ans[x] = ans[nxt[x]] + 1
            state[x] = 2
    return ans

What breaks
  • Kosaraju's first pass with "pop, push all neighbours": wrong finish order. It needs the iterator stack.
  • Tarjan without the on-stack check: edges into finished SCCs lower low and merge components.
  • Assuming an id order: Kosaraju gives topological ids and Tarjan reverse topological. Mixing them up flips 2-SAT assignments and DAG DP directions.
  • Duplicate condensation edges: harmless for DP, but they inflate in-degrees if you run Kahn on the condensation. Count distinct pairs or use DFS order.

2-SAT

50m video

A clause with two literals, \(a \lor b\), is the same as two implications, \(\lnot a \to b\) and \(\lnot b \to a\). Satisfiability then becomes reachability in the implication graph: the formula is satisfiable iff no variable shares an SCC with its own negation, and the SCC order hands you an assignment. Linear time, for a problem whose 3-literal version is NP-complete.

The implication graph

Definition

A 2-CNF formula is a conjunction of clauses \((\ell_1 \lor \ell_2)\) over literals \(x_i, \lnot x_i\). Its implication graph has \(2n\) nodes, one per literal, and for each clause \((a \lor b)\) the two edges \(\lnot a \to b\) and \(\lnot b \to a\). Encode \(x_i\) as node \(2i\) and \(\lnot x_i\) as \(2i + 1\), so negation is ^ 1.

The graph is skew-symmetric: \(u \to v\) is an edge iff \(\lnot v \to \lnot u\) is (the contrapositive). Paths follow forced consequences: if \(a\) is set true and \(a \leadsto b\), then \(b\) must be true.

The theorem and the assignment rule

Theorem · Aspvall, Plass & Tarjan (1979)

A 2-CNF formula is satisfiable iff for no \(i\) do \(x_i\) and \(\lnot x_i\) lie in the same SCC. When it is satisfiable, setting \(x_i = \) true exactly when \(\mathrm{comp}(x_i)\) comes after \(\mathrm{comp}(\lnot x_i)\) in a topological order of the condensation satisfies every clause.

Proof

(⇒) If \(x \leadsto \lnot x\) and \(\lnot x \leadsto x\), then \(x\) true forces \(\lnot x\) true, and \(x\) false forces \(x\) true. Neither value works. (⇐) Write \(t(\ell)\) for the topological position of \(\ell\)'s component. Every edge \(u \to v\) has \(t(u) \le t(v)\). Suppose the rule leaves a clause \((a \lor b)\) false. Then \(a\) false means \(t(a) < t(\lnot a)\), and \(b\) false means \(t(b) < t(\lnot b)\). The clause's edges \(\lnot a \to b\) and \(\lnot b \to a\) give \(t(\lnot a) \le t(b)\) and \(t(\lnot b) \le t(a)\). Chaining: \(t(a) < t(\lnot a) \le t(b) < t(\lnot b) \le t(a)\), a contradiction.

Intuition for "later wins": choose the literal closer to the sinks, so that whatever it forces is also late. With Tarjan's numbering (L74), which is reverse topological, the rule reads comp[2i] < comp[2i+1] ⇒ true. Total cost \(O(n + m)\) for \(n\) variables and \(m\) clauses.

Implementation

class TwoSat:
    """Variable i: literal 2*i is x_i, 2*i + 1 is (not x_i); negate with ^ 1. Uses tarjan_scc from L74."""
    def __init__(self, n):
        self.n = n
        self.adj = [[] for _ in range(2 * n)]

    @staticmethod
    def lit(i, value=True):
        return 2 * i if value else 2 * i + 1

    def new_var(self):
        self.adj += [[], []]
        self.n += 1
        return self.n - 1

    def add_clause(self, a, b):            # a OR b
        self.adj[a ^ 1].append(b)          # not a -> b
        self.adj[b ^ 1].append(a)          # not b -> a

    def implies(self, a, b):               # a -> b  ==  (not a) OR b
        self.add_clause(a ^ 1, b)

    def force(self, a):                    # a must hold
        self.add_clause(a, a)

    def at_most_one(self, lits):
        """Prefix encoding: O(k) clauses and k helper variables instead of k^2 / 2 clauses."""
        prev = None
        for x in lits:
            s = 2 * self.new_var()         # s = "some literal up to here is true"
            self.implies(x, s)
            if prev is not None:
                self.implies(prev, s)
                self.implies(prev, x ^ 1)  # an earlier one is true, so x is false
            prev = s

    def solve(self):
        _, comp = tarjan_scc(2 * self.n, self.adj)
        res = []
        for i in range(self.n):
            if comp[2 * i] == comp[2 * i + 1]:
                return None
            res.append(comp[2 * i] < comp[2 * i + 1])   # reverse topological ids: smaller = later
        return res                         # helper variables are appended at the end; ignore them

The signal is that every object has exactly two options (left or right, on or off, slot A or slot B, this orientation or that), and the constraints forbid pairs of choices. Write one boolean per object, then list every forbidden pair \((i = p, j = q)\) as the clause \(\lnot(i{=}p) \lor \lnot(j{=}q)\). Typical sources are conflicts between geometric placements (two labels overlap), interval collisions, and "these two switches cannot both be on".

def schedule(options):
    """options[i] = ((s0, e0), (s1, e1)), half-open intervals. Pick one per meeting, no overlaps.
    Variable i true means meeting i takes option 0. Returns a list of chosen options or None."""
    n = len(options)
    ts = TwoSat(n)
    for i in range(n):
        for j in range(i + 1, n):
            for a in range(2):
                for b in range(2):
                    (s1, e1), (s2, e2) = options[i][a], options[j][b]
                    if s1 < e2 and s2 < e1:                          # overlap: forbid (i=a and j=b)
                        ts.add_clause(ts.lit(i, a == 1), ts.lit(j, b == 1))
    res = ts.solve()
    return None if res is None else [0 if res[i] else 1 for i in range(n)]

"Meeting i takes option a" is the literal lit(i, a == 0), so its negation is lit(i, a == 1). The \(O(n^2)\) pair loop dominates; a sweep can cut it when the intervals are sparse.

Where 2-SAT shows up, and why 3-SAT does not

In contests 2-SAT tends to appear in the harder problems of a set, disguised as switches and doors, binary choices on a grid, team splits, or "choose a direction for each segment". Often a binary search over a threshold sits outside it (is there an assignment where all conflicting pairs are farther apart than \(D\)?). 3-SAT is NP-complete (Cook–Levin), so if your model needs a clause on three or more variables that cannot be split, the model is wrong or the intended solution is something else. Usually the problem has more structure than you used.

What breaks
  • Adding only one implication per clause: you lose the contrapositive, and the theorem no longer applies.
  • Flipping the assignment rule: Kosaraju ids (topological) need comp[x] > comp[¬x], and Tarjan ids need <. Swap them and the solver returns assignments that violate clauses. Always verify the assignment against the clauses in testing.
  • "Exactly one of k ≥ 3": at-least-one is not 2-SAT. Rethink the model.
  • Pairwise at-most-one on large groups: \(k^2/2\) clauses. With \(k = 10^4\) that is \(5\cdot10^7\) clauses, so use the prefix encoding.
  • Recursive SCC: \(2\cdot10^5\) literal nodes means deep recursion. Iterate.

Eulerian Paths and Circuits

50m video

Using every edge exactly once is decided entirely by degrees plus connectivity. Hierholzer's algorithm builds the tour in linear time by walking until stuck and splicing in detours as it backtracks. It is one of the few "visit everything" problems that is easy; its vertex twin, the Hamiltonian path, is NP-hard.

Existence: degrees and connectivity

Theorem · Euler (1736), Hierholzer (1873)

Assume all edges lie in one connected component (isolated vertices do not matter; for digraphs, connectivity ignoring directions).

  • Undirected: an Euler circuit exists iff every degree is even. An Euler path exists iff exactly 0 or 2 vertices have odd degree, and with 2 it runs between them.
  • Directed: a circuit exists iff in = out at every vertex. A path exists iff additionally one vertex may have out − in = 1 (the start) and one in − out = 1 (the end).
Proof sketch

Necessity: each time a tour passes through a vertex it uses one edge in and one out, so only the endpoints can be unbalanced. Sufficiency is constructive. Walk from the start, always taking an unused edge. With balanced degrees you can only get stuck at the start, because every other vertex you enter has an unused exit. If unused edges remain, connectivity puts one at some vertex on the closed walk; walk a closed detour from there and splice it in. Hierholzer's algorithm is exactly this, done with a stack. For digraphs, balanced degrees plus weak connectivity already imply strong connectivity of the non-isolated part.

In code, check the degree conditions and then check that the produced path has \(m + 1\) vertices. The length check catches disconnected edges, and it is easier than a separate connectivity pass.

Hierholzer, iteratively

Algorithm · Hierholzer with a stack
  1. stack = [start]; path = [].
  2. Look at the top \(u\). Advance ptr[u] past used edges. If an unused edge \(u \to v\) remains, mark it used and push \(v\).
  3. Otherwise pop \(u\) and append it to path (u is finished: every detour through it is done).
  4. When the stack is empty, path reversed is the Euler path.

The recursive textbook version recurses once per edge, so \(m = 2\cdot10^5\) means depth \(2\cdot10^5\) and a crash in Python. The per-vertex pointer ptr[u] only moves forward, so all scans together cost \(O(m)\). Each edge is pushed and popped once, so the total is \(O(n + m)\). In undirected graphs each edge appears in two lists, so mark it used by edge id. That also makes parallel edges and self-loops work without special cases.

def euler_undirected(n, edges, start):
    """Euler path/circuit from start using every edge once, or None. Check degrees first."""
    adj = [[] for _ in range(n)]
    for i, (u, v) in enumerate(edges):
        adj[u].append((v, i))
        adj[v].append((u, i))
    used = [False] * len(edges)
    ptr = [0] * n
    stack = [start]
    path = []
    while stack:
        u = stack[-1]
        a = adj[u]
        while ptr[u] < len(a) and used[a[ptr[u]][1]]:
            ptr[u] += 1
        if ptr[u] == len(a):
            path.append(stack.pop())
        else:
            v, i = a[ptr[u]]
            ptr[u] += 1
            used[i] = True
            stack.append(v)
    return path[::-1] if len(path) == len(edges) + 1 else None

def euler_directed(n, edges, start):
    adj = [[] for _ in range(n)]
    for u, v in edges:
        adj[u].append(v)
    ptr = [0] * n
    stack = [start]
    path = []
    while stack:
        u = stack[-1]
        if ptr[u] < len(adj[u]):
            stack.append(adj[u][ptr[u]])
            ptr[u] += 1
        else:
            path.append(stack.pop())
    return path[::-1] if len(path) == len(edges) + 1 else None

def mail_delivery(n, edges):               # CSES: circuit from vertex 0
    deg = [0] * n

def teleporters(n, edges):                 # CSES: path from 0 to n-1
    out, inn = [0] * n, [0] * n
    for u, v in edges:
        out[u] += 1; inn[v] += 1
    if out[0] - inn[0] != 1 or inn[n - 1] - out[n - 1] != 1:
        return None
    if any(out[v] != inn[v] for v in range(1, n - 1)):
        return None
    return euler_directed(n, edges, 0)

Why the degree check is not optional: on a star with centre 0 and three leaves, Hierholzer from 0 still pops 4 vertices (\(= m + 1\)), but the "path" jumps between non-adjacent leaves. The length check alone proves nothing when the degrees are wrong.

Applications: de Bruijn sequences and reconstruction

A binary de Bruijn sequence of order \(n\) contains every \(n\)-bit string exactly once as a window, in length \(2^n + n - 1\). Make each \((n-1)\)-bit string a vertex, and each \(n\)-bit string \(b_1 \dots b_n\) the edge from \(b_1..b_{n-1}\) to \(b_2..b_n\). Every vertex has in = out = 2 and the graph is connected, so an Euler circuit exists. Walking it and writing one bit per edge produces the sequence. The same construction over \(k\) symbols gives LeetCode 753 (Cracking the Safe).

def de_bruijn_binary(n):
    """CSES De Bruijn Sequence: a shortest bit string containing every n-bit string."""
    if n == 1:
        return "01"
    m = 1 << (n - 1)
    mask = m - 1
    ptr = [0] * m                          # next bit to try at each (n-1)-bit vertex
    stack = [0]
    out = []
    while stack:
        u = stack[-1]
        if ptr[u] < 2:
            b = ptr[u]
            ptr[u] += 1
            stack.append(((u << 1) | b) & mask)
        else:
            out.append(stack.pop())
    out.reverse()                          # vertex sequence of the circuit
    return "0" * (n - 1) + "".join(str(v & 1) for v in out[1:])

Reconstruction from k-mers (genome assembly): with all length-\(k\) substrings given, make \((k-1)\)-mers vertices and k-mers edges. Any Euler path spells a consistent string. Word and domino chains: letters or pip values are vertices and words or dominoes are edges. "Draw without lifting the pen" is the undirected path condition.

The hard contrasts

Hamiltonian path (every vertex once) is NP-hard. The contest answer is bitmask DP over (visited set, last vertex) in \(O(2^n n^2)\) for \(n \le 20\) (L91). Chinese postman (shortest closed walk using every edge at least once) is often quoted as hard, but that is only true for mixed graphs. On undirected graphs it is polynomial: duplicate edges along a minimum-weight perfect matching of the odd-degree vertices (Edmonds & Johnson, 1973). On directed graphs it is a min-cost flow problem (L79).

Bipartite Matching: Kuhn's Algorithm and the Theorems

55m video

A matching can be enlarged exactly when an augmenting path exists, so the maximum is found by repeatedly searching for one. In bipartite graphs, the leftover search also hands you a minimum vertex cover of the same size. That equality (König), and Hall's condition, are the modelling tools here; the algorithm itself is short.

Matchings and augmenting paths

Definition

A matching \(M\) is a set of edges with no shared endpoint. A path is alternating if its edges alternate between non-\(M\) and \(M\). It is augmenting if it is alternating and starts and ends at unmatched vertices. Flipping an augmenting path (swap \(M\) and non-\(M\) along it) yields a matching with one more edge.

Theorem · Berge (1957)

A matching is maximum iff it admits no augmenting path. This holds in every graph, not only bipartite ones.

Proof

(⇒) An augmenting path would enlarge it. (⇐) Suppose \(|M^*| > |M|\). In \(M \oplus M^*\) every vertex has degree ≤ 2, so it splits into alternating paths and even cycles. Cycles and even paths contain equally many edges of each matching, so some component has more \(M^*\) edges than \(M\) edges. That component is a path starting and ending with \(M^*\) edges, whose endpoints are unmatched in \(M\): an augmenting path.

Kuhn's algorithm

For each left vertex \(u\), search for an augmenting path starting at \(u\). The classic version is a DFS try(u): for each neighbour \(v\) not yet visited in this attempt, mark it, and succeed if \(v\) is free or try(match[v]) succeeds, in which case re-match \(v\) to \(u\). Each attempt is \(O(E)\), so the total is \(O(VE)\). Two facts make it correct and fast:

  • One attempt per vertex suffices. If no augmenting path starts at \(u\) now, none will after other augmentations either (a standard lemma), so failed vertices are never retried.
  • The visited reset. Visited marks must be cleared before each attempt. Otherwise right vertices explored by a failed attempt block later ones, and the answer comes out too small. Allocating a fresh list per attempt costs \(O(V)\) each, which is quadratic overall. Stamping with the attempt number (vis[v] == root) resets in \(O(1)\).

Greedy pre-matching (match each left vertex to any free neighbour first) typically settles most of the matching in one linear pass, leaving few augmenting searches. The version below searches by BFS instead of DFS. It is the same algorithm and bound, with no recursion.

def max_matching(nl, nr, adj):
    """adj[u] = right neighbours of left u. Returns (size, match_l, match_r). O(VE), iterative."""
    match_l = [-1] * nl
    match_r = [-1] * nr
    for u in range(nl):                         # greedy start
        for v in adj[u]:
            if match_r[v] == -1:
                match_l[u] = v; match_r[v] = u
                break
    vis = [-1] * nr                             # vis[v] == root: seen in this attempt (O(1) reset)
    prev = [0] * nr
    for root in range(nl):
        if match_l[root] != -1:
            continue
        q = [root]
        found = -1
        for u in q:                             # BFS over alternating paths
            for v in adj[u]:
                if vis[v] != root:
                    vis[v] = root
                    prev[v] = u
                    if match_r[v] == -1:
                        found = v
                        break
                    q.append(match_r[v])        # continue through v's matched partner
            if found != -1:
                break
        while found != -1:                      # flip the path back to root
            u = prev[found]
            nxt = match_l[u]
            match_l[u] = found; match_r[found] = u
            found = nxt
    return sum(x != -1 for x in match_l), match_l, match_r

König: max matching = min vertex cover

Theorem · König (1931)

In a bipartite graph, the maximum matching size equals the minimum vertex cover size. Given a maximum matching, let \(Z\) be the vertices reachable from unmatched left vertices by alternating paths. Then \((L \setminus Z) \cup (R \cap Z)\) is a minimum vertex cover.

Proof

It covers. Take an edge \(lr\). If \(l \notin Z\), it is covered. If \(l \in Z\) and \(lr \notin M\), the alternating search continues to \(r\), so \(r \in Z\). If \(lr \in M\), then \(l\) is matched, so it was entered through its partner \(r\), and \(r \in Z\). Its size is \(|M|\). Every \(r \in R \cap Z\) is matched, otherwise there would be an augmenting path. Every \(l \in L \setminus Z\) is matched, because the unmatched ones are in \(Z\) by definition. No matching edge has both ends in the cover: if \(r \in Z\) then its partner is in \(Z\). So the cover picks exactly one endpoint of each matching edge. Any cover needs at least \(|M|\) vertices (one per matching edge), so this one is minimum.

def konig_cover(nl, adj, match_l, match_r):
    """Minimum vertex cover (left list, right list) from a maximum matching."""
    zl = [False] * nl
    zr = [False] * len(match_r)
    q = [u for u in range(nl) if match_l[u] == -1]
    for u in q:
        zl[u] = True
    for u in q:
        for v in adj[u]:
            if not zr[v] and match_l[u] != v:   # non-matching edge left -> right
                zr[v] = True
                w = match_r[v]                  # matching edge right -> left (v is matched)
                if w != -1 and not zl[w]:
                    zl[w] = True
                    q.append(w)
    return [u for u in range(nl) if not zl[u]], [v for v in range(len(match_r)) if zr[v]]

Hall, independent sets, path covers

Theorem · Hall (1935)

A bipartite graph has a matching saturating \(L\) iff \(|N(S)| \ge |S|\) for every \(S \subseteq L\).

Necessity is obvious. Sufficiency follows from König. If the maximum matching is smaller than \(|L|\), a minimum cover \(C\) has \(|C| < |L|\). Then \(S = L \setminus C\) has all its neighbours in \(R \cap C\), and \(|N(S)| \le |C| - |L \cap C| < |S|\). Hall is the tool for proofs. For example, every \(k\)-regular bipartite graph (\(k \ge 1\)) has a perfect matching, since \(|N(S)| \cdot k \ge |S| \cdot k\) by counting edges.

  • Maximum independent set (bipartite) \(= |V| - \) max matching: the complement of a minimum vertex cover is independent.
  • Minimum vertex-disjoint path cover of a DAG \(= n - \) max matching in the split graph, with each vertex split into an "out" copy on the left and an "in" copy on the right, and an edge \(u_{out} \to v_{in}\) per DAG edge. Each matched edge glues two paths into one. If paths may share vertices, take the transitive closure first.
  • Beyond Kuhn: Hopcroft–Karp augments along a maximal set of shortest paths per phase, \(O(E\sqrt V)\). It is the same bound as Dinic on unit networks (L78). Weighted matching (assignment) is the Hungarian algorithm or min-cost flow (L79).
def dag_path_cover(n, edges):
    """Minimum number of vertex-disjoint paths covering a DAG, and the paths."""
    adj = [[] for _ in range(n)]
    for u, v in edges:
        adj[u].append(v)                        # out-copy u -> in-copy v
    k, ml, mr = max_matching(n, n, adj)
    paths = []
    for s in range(n):
        if mr[s] == -1:                         # nothing glued in front of s: a path starts here
            p = [s]
            while ml[p[-1]] != -1:
                p.append(ml[p[-1]])
            paths.append(p)
    return n - k, paths

Recognising hidden bipartite structure

  • Rows and columns: cell \((r, c)\) is the edge \(r\)–\(c\). "Place non-attacking rooks", "cover all marked cells with fewest lines" (König).
  • Chessboard colouring: on a grid, \((r + c)\) parity splits the cells, and a domino always covers one of each colour. Maximum dominoes on a board with holes = max matching. Minimum cells to delete so that no two remaining ones are adjacent = min vertex cover = matching.
  • Two categories: workers/jobs, boys/girls, people/time slots, with "each used at most once".

  • Mixing left and right index spaces: use separate arrays, or offset right vertices by \(n_L\) consistently.

Maximum Flow I: Ford–Fulkerson, Edmonds–Karp, Dinic

60m video

Pushing flow greedily along paths gets stuck at a bad local optimum, unless every push also creates a reverse edge that lets a later path undo it. With reverse edges, "repeat until no augmenting path" is optimal. Which path you choose (any, shortest, or a whole layer at a time) only sets the running time; Dinic's choice is the one to keep in the library.

Flow networks

Definition

A directed graph with capacities \(c(u,v) \ge 0\), a source \(s\) and a sink \(t\). A flow \(f\) satisfies \(0 \le f(u,v) \le c(u,v)\) (capacity) and inflow = outflow at every \(v \ne s, t\) (conservation). Its value is the net flow out of \(s\). The residual capacity is \(c_f(u,v) = c(u,v) - f(u,v)\), plus \(f(v,u)\) available on the reverse edge \(u \to v\) for undoing. An augmenting path is an \(s \leadsto t\) path in the residual graph.

Reverse edges are undo buttons. Pushing \(x\) units along \(u \to v\) adds \(x\) of residual capacity to \(v \to u\). A later path that uses \(v \to u\) is not sending flow backwards in reality. It is cancelling part of the earlier decision and rerouting it. Without them, the first path can block the optimum forever:

Ford–Fulkerson and its bad case

Ford–Fulkerson: while an augmenting path exists, push its bottleneck along it. With integer capacities each push adds at least 1, so it terminates after at most \(|f^*|\) augmentations, each \(O(E)\). That also proves the integrality theorem: some maximum flow is integral, which is what makes matchings and disjoint paths expressible as flows. The bound depends on the answer, and it is tight. Take \(s \to a, s \to b, a \to t, b \to t\) with capacity \(C\) each, plus \(a \to b\) with capacity 1. Paths that alternate through \(a\to b\) and its reverse gain 1 each time, for \(2C\) augmentations in total. With irrational capacities it may not even terminate.

Edmonds–Karp and Dinic

Edmonds–Karp always augments along a shortest path (by edge count), found with BFS. The residual distance \(d(s, v)\) never decreases, and each edge can be the bottleneck only \(O(V)\) times. That gives \(O(VE)\) augmentations and \(O(VE^2)\) total, independent of the capacities.

Algorithm · Dinic (1970)
  1. BFS from \(s\) in the residual graph to get levels. Stop if \(t\) is unreachable.
  2. Find a blocking flow in the level graph (only edges with level[v] = level[u] + 1): push along level-increasing paths until none is left.
  3. Keep an iterator it[u] per vertex: an edge that is saturated or leads to a dead end is never re-examined in this phase. Repeat from step 1.
Theorem · Dinic's bounds

Each phase strictly increases \(d(s,t)\), so there are at most \(V - 1\) phases. A blocking flow costs \(O(VE)\) with iterator pointers, for \(O(V^2 E)\) in total. With unit capacities the number of phases is \(O(\sqrt E)\) (and \(O(V^{2/3})\)). On unit networks such as bipartite matching it is \(O(\sqrt V)\), giving \(O(E\sqrt V)\), the Hopcroft–Karp bound.

Why phases lengthen. After a blocking flow, every shortest \(s \leadsto t\) path in the old level graph has a saturated edge. New residual edges are reverses of level-graph edges, so they go down a level. A path using only old edges with levels \(+1\) has been blocked, and a path using any edge that does not climb a level is longer. So the new distance exceeds the old one.

Implementation

class Dinic:
    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(n)]           # edge ids out of each vertex
        self.to = []
        self.cap = []                             # residual capacities; edge e ^ 1 is the reverse of e

    def add_edge(self, u, v, c, rc=0):
        """rc = c gives an undirected edge. Returns the forward edge id."""
        self.g[u].append(len(self.to)); self.to.append(v); self.cap.append(c)
        self.g[v].append(len(self.to)); self.to.append(u); self.cap.append(rc)
        return len(self.to) - 2

    def _bfs(self, s, t):
        level = [-1] * self.n
        level[s] = 0
        q = [s]
        to, cap, g = self.to, self.cap, self.g
        for u in q:
            for e in g[u]:
                if cap[e] and level[to[e]] < 0:
                    level[to[e]] = level[u] + 1
                    q.append(to[e])
        self.level = level
        return level[t] >= 0

    def _augment(self, s, t):
        """One s-t path in the level graph, found iteratively; returns the amount pushed (0 = blocked)."""
        to, cap, g, level, it = self.to, self.cap, self.g, self.level, self.it
        path = []
        u = s
        while True:
            if u == t:
                f = min(cap[e] for e in path)
                for e in path:
                    cap[e] -= f
                    cap[e ^ 1] += f
                return f
            gu, i, nl = g[u], it[u], level[u] + 1
            while i < len(gu) and not (cap[gu[i]] and level[to[gu[i]]] == nl):
                i += 1
            it[u] = i
            if i < len(gu):
                e = gu[i]
                path.append(e)
                u = to[e]                         # advance
            else:
                if not path:
                    return 0
                level[u] = -1                     # dead end for the rest of this phase
                e = path.pop()
                u = to[e ^ 1]                     # retreat and skip that edge
                it[u] += 1

    def max_flow(self, s, t):
        flow = 0
        while self._bfs(s, t):
            self.it = [0] * self.n
            f = self._augment(s, t)
            while f:
                flow += f
                f = self._augment(s, t)
        return flow

    def min_cut(self, s):
        """After max_flow: seen[v] is True on the source side of a minimum cut."""
        seen = [False] * self.n
        seen[s] = True
        q = [s]
        for u in q:
            for e in self.g[u]:
                if self.cap[e] and not seen[self.to[e]]:
                    seen[self.to[e]] = True
                    q.append(self.to[e])
        return seen
Python notes and honest limits
  • Flat arrays to and cap with the reverse at e ^ 1 (the forward-star idea from L62). The original flow on edge \(e\) is its starting capacity minus cap[e].
  • The DFS is iterative: an explicit path, advance and retreat, and level[u] = -1 to prune dead ends. Each found path costs \(O(V)\) plus pointer advances, which is the textbook bound.
  • Capacity scaling (only use edges with residual ≥ \(\Delta\), halving \(\Delta\)) helps when capacities are huge and the graph is small.
  • Realistic expectation in CPython: a few thousand vertices and tens of thousands of edges, or unit-capacity matchings of about \(10^4\) edges. Beyond that, use PyPy, or look for a structure that avoids general flow.

Sanity checks and debugging

Verify three facts on every test: each edge has \(0 \le f \le c\); conservation holds at every non-terminal vertex; and the value equals the capacity of the cut returned by min_cut (L79 explains why it must). For a brute force on small random networks, enumerate all \(2^{n-2}\) cuts \(S \ni s\), \(S \not\ni t\), and take the minimum capacity. By max-flow min-cut, that is the max-flow value. When a modelled solution is wrong, print the flow on each modelled edge (person → task, etc.), because the bug is almost always in the model, not in Dinic.

What breaks
  • Forgetting reverse edges, or adding them as independent edges instead of the e ^ 1 twin: the "undo" no longer updates its pair.
  • Undirected edges as two directed pairs: legal, but add_edge(u, v, c, c) is half the edges and correct.

  • Recursive DFS in _augment: depth up to \(V\).
  • Using DFS (not BFS) to pick paths in an "Edmonds–Karp": that is Ford–Fulkerson, with the \(2C\) behaviour above.

Maximum Flow II: Min Cut, Modelling, and Min-Cost Max-Flow

60m video

Max flow equals min cut, and the cut can be read off the final residual graph. Most contest flow problems are cut problems in disguise: each object goes on one side, and every bad decision costs one edge's capacity. Adding a price per unit gives min-cost flow, kept fast by Johnson's potentials.

Max-flow min-cut

Theorem · Ford & Fulkerson (1956)

For a flow \(f\), these are equivalent: (1) \(f\) is maximum; (2) the residual graph has no augmenting path; (3) \(|f| = c(S, T)\) for some cut \((S, T)\) with \(s \in S\), \(t \in T\). Hence max flow = min cut capacity.

Proof

Weak duality. For any cut, summing conservation over \(S\) gives \(|f| = f(S \to T) - f(T \to S) \le c(S, T)\). (1⇒2): an augmenting path would increase \(|f|\). (2⇒3): let \(S\) be the vertices reachable from \(s\) in the residual graph, so \(t \notin S\). Every edge \(S \to T\) has zero residual capacity, so it is saturated. Every edge \(T \to S\) carries zero flow, since otherwise its reverse would be residual and its tail reachable. So \(|f| = c(S,T)\). (3⇒1): by weak duality, no flow can exceed \(c(S,T)\).

Extracting the cut is therefore one BFS over positive-residual edges after max_flow: Dinic.min_cut from L78. The cut edges are the original edges from a reached vertex to an unreached one.

def police_chase(n, roads):
    """CSES Police Chase: fewest roads to close so 0 cannot reach n-1 (undirected). Uses Dinic (L78)."""
    D = Dinic(n)
    for a, b in roads:
        D.add_edge(a, b, 1, 1)                  # undirected unit edge
    k = D.max_flow(0, n - 1)
    side = D.min_cut(0)
    return k, [(a, b) for a, b in roads if side[a] != side[b]]

The modelling checklist

  1. What are the nodes? Objects, plus their states or copies (time layers, in/out halves).
  2. What does one unit of flow mean? One person assigned, one path, one parcel.
  3. What does a cut mean? For cut models: source side = "chosen" / category A, sink side = category B. Every edge \(u \to v\) charges its capacity when \(u\) is chosen and \(v\) is not. Make ∞ edges for "must not happen".
  • Vertex capacities: split \(v\) into \(v_{in} \to v_{out}\) with capacity \(c(v)\). In-edges go to \(v_{in}\), out-edges leave \(v_{out}\).
  • Many sources or sinks: a super-source and a super-sink, with supplies as capacities.
  • Lower bounds \(\ell \le f \le c\): use capacity \(c - \ell\) and move \(\ell\) of forced flow into vertex demands. Add \(t \to s\) with ∞ and a new \(S'\), \(T'\) feeding those demands. A flow is feasible iff the \(S'\) edges all saturate.
  • Project selection / maximum closure. Projects have profits \(p_i\) of either sign, and "choosing \(i\) requires \(j\)". Add \(s \to i\) with \(p_i\) if \(p_i > 0\), \(i \to t\) with \(-p_i\) if \(p_i < 0\), and \(i \to j\) with ∞ for each requirement. Best profit = (sum of positive \(p_i\)) − min cut, and the source side is the chosen set.
  • Two categories with penalties (image segmentation): \(s \to v\) costs what \(v\) pays for being in B, \(v \to t\) what it pays for being in A, and \(u \leftrightarrow v\) with \(p_{uv}\) charges for separating neighbours.
  • Minimum vertex cover (bipartite): \(s \to L\) with 1, \(L \to R\) with ∞, \(R \to t\) with 1. The cut picks \(L \cap T\) and \(R \cap S\), which is König again (L77).
  • Menger: max edge-disjoint \(s\)–\(t\) paths = min edges separating them (unit capacities). For vertex-disjoint paths, node-split with capacity 1.
def project_selection(profit, requires):
    """profit[i] any sign; requires: (i, j) means choosing i forces j. Returns (best profit, chosen ids)."""
    n = len(profit)
    s, t = n, n + 1
    INF = sum(abs(p) for p in profit) + 1       # larger than any finite cut
    D = Dinic(n + 2)
    for i, p in enumerate(profit):
        if p > 0:
            D.add_edge(s, i, p)
        elif p < 0:
            D.add_edge(i, t, -p)
    for i, j in requires:
        D.add_edge(i, j, INF)
    cut = D.max_flow(s, t)
    side = D.min_cut(s)
    return sum(p for p in profit if p > 0) - cut, [i for i in range(n) if side[i]]

Min-cost max-flow

Each edge has a cost per unit, and its reverse has the negated cost (undoing a unit refunds it). Successive shortest paths repeatedly augments along a cheapest residual \(s \leadsto t\) path. With no negative cost cycle initially, each intermediate flow is the cheapest of its value. Reverse edges have negative costs, so plain Dijkstra fails, and Bellman–Ford per augmentation (\(O(F \cdot VE)\)) is slow.

Theorem · Potentials keep Dijkstra valid

Keep \(h(v)\) = the shortest residual distance from \(s\) found in the previous round. Then every residual edge has reduced cost \(c(u,v) + h(u) - h(v) \ge 0\), and after augmenting along a shortest path, setting \(h \leftarrow h + d\) preserves this.

Old edges satisfy the triangle inequality for the new \(d\). New residual edges reverse path edges of reduced cost 0, so they have reduced cost 0 too. This is Johnson's reweighting (L69) maintained incrementally. Cost: \(O(F \cdot E \log V)\) for total flow \(F\).

from heapq import heappush, heappop

class MCMF:
    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(n)]
        self.to, self.cap, self.cost = [], [], []

    def add_edge(self, u, v, cap, cost):
        self.g[u].append(len(self.to)); self.to.append(v); self.cap.append(cap); self.cost.append(cost)
        self.g[v].append(len(self.to)); self.to.append(u); self.cap.append(0); self.cost.append(-cost)

    def flow(self, s, t, maxf=float("inf")):
        """Returns (flow, cost). Assumes initial costs >= 0 (else seed h with Bellman-Ford)."""
        n, g, to, cap, cost = self.n, self.g, self.to, self.cap, self.cost
        INF = float("inf")
        h = [0] * n
        flow = total = 0
        while flow < maxf:
            dist = [INF] * n
            dist[s] = 0
            pe = [-1] * n
            pq = [(0, s)]
            while pq:
                d, u = heappop(pq)
                if d > dist[u]:
                    continue
                hu = h[u]
                for e in g[u]:
                    if cap[e]:
                        v = to[e]
                        nd = d + cost[e] + hu - h[v]      # reduced cost, >= 0
                        if nd < dist[v]:
                            dist[v] = nd; pe[v] = e
                            heappush(pq, (nd, v))
            if dist[t] == INF:
                break
            for v in range(n):
                if dist[v] < INF:
                    h[v] += dist[v]
            f, v = maxf - flow, t
            while v != s:
                f = min(f, cap[pe[v]]); v = to[pe[v] ^ 1]
            v = t
            while v != s:
                e = pe[v]; cap[e] -= f; cap[e ^ 1] += f; v = to[e ^ 1]
            flow += f
            total += f * h[t]                           # h[t] = true s-t distance (h[s] stays 0)
        return flow, total

Vertices unreachable in one round stay unreachable forever (augmentations only touch reachable vertices), so leaving their \(h\) alone is safe.

Assignment: MCMF or Hungarian

As MCMF, an \(n \times n\) cost matrix is \(n^2\) edges and \(n\) Dijkstras, \(O(n^3 \log n)\) with a heavy constant. The Hungarian algorithm (Kuhn 1955, in its \(O(n^3)\) form) keeps row and column potentials in plain arrays, and is the choice for pure assignment at \(n \approx 200\)–\(500\). Use MCMF when there is more structure: capacities, extra nodes, or partial flow.

def hungarian(a):
    """Min-cost assignment for an n x m cost matrix (n <= m). Returns (cost, column of each row)."""
    n, m = len(a), len(a[0])
    INF = float("inf")
    u = [0] * (n + 1); v = [0] * (m + 1); p = [0] * (m + 1); way = [0] * (m + 1)
    for i in range(1, n + 1):
        p[0] = i; j0 = 0
        minv = [INF] * (m + 1); used = [False] * (m + 1)
        while True:
            used[j0] = True
            i0, delta, j1 = p[j0], INF, 0
            row, ui0 = a[i0 - 1], u[i0]
            for j in range(1, m + 1):
                if not used[j]:
                    cur = row[j - 1] - ui0 - v[j]
                    if cur < minv[j]:
                        minv[j] = cur; way[j] = j0
                    if minv[j] < delta:
                        delta = minv[j]; j1 = j
            for j in range(m + 1):
                if used[j]:
                    u[p[j]] += delta; v[j] -= delta
                else:
                    minv[j] -= delta
            j0 = j1
            if p[j0] == 0:
                break
        while j0:                                       # augment along the alternating path
            j1 = way[j0]; p[j0] = p[j1]; j0 = j1
    res = [0] * n
    for j in range(1, m + 1):
        if p[j]:
            res[p[j] - 1] = j - 1
    return -v[0], res

What breaks
  • Cut edges read from the residual graph instead of the original edge list: reverse edges show up as phantom cuts.
  • INF too small in ∞ edges: a "forbidden" edge gets cut. Make it exceed the sum of all finite capacities.
  • MCMF with negative initial costs and \(h = 0\): Dijkstra sees negative reduced costs. Seed \(h\) with Bellman–Ford.
  • Negative cost cycles: successive shortest paths assumes none. Cancel them first, or remodel.

Recognising flow

A statement never says "flow". The signals: (a) "each X used at most once" with a capacity-like limit; (b) "minimum number of things to remove so A and B are separated" (a cut); (c) each object goes into one of two groups, with costs for groups and for separating pairs (a cut with s-side = group A); (d) choose a set closed under "if you take this, you must take that" (project selection); (e) sizes small enough for \(O(V^2 E)\) in Python (a few hundred vertices). If a greedy seems to work but you can build a counterexample where an early choice must be undone, the reverse edges of a flow are the fix.

Editorial

P1 · BFS modelling: portals

Problem. A grid with walls, where letter cells are portals. Stepping to a neighbour costs 1, and from a letter cell you may jump to any cell with the same letter for cost 1. Find the shortest S → T. Observation: all edges cost 1, so BFS. But a letter used by \(k\) cells has \(k^2\) jump edges. Fix: the first time BFS pops any cell of letter \(x\), enqueue every unvisited cell of \(x\), then clear \(x\)'s list. Later pops of \(x\)-cells would reach them at the same or a larger distance, so nothing is lost. This is the same argument as the word-ladder buckets in L63. \(O(HW)\).

P2 · Dijkstra variant: k free edges

Problem. Shortest path when you may make up to \(k \le 10\) edges free. Run Dijkstra on states \((v, j)\) with \(j\) free edges used: from \((u, j)\), pay \(w\) to reach \((v, j)\), or pay 0 to reach \((v, j+1)\). The answer is \(\min_j d(t, j)\). \(O(k\,m \log(kn))\). Encode the state as v * (k + 1) + j. Pitfall: answering with \(d(t, k)\) only. Using a free pass is never worse, but only if a path has at least \(k\) edges.

P3 · DSU offline: pairs under a threshold

Problem. For each query \(w\), count the unordered pairs \(\{u, v\}\) connected using only edges of weight \(\le w\). Sort edges and queries together and sweep with a DSU. A union of components of sizes \(a\) and \(b\) creates exactly \(ab\) new pairs. \(O((m + q)\log)\).

def connected_pairs(n, edges, queries):
    """edges (w, u, v); for each threshold, pairs joined by edges of weight <= threshold."""
    edges = sorted(edges)
    p = list(range(n)); sz = [1] * n
    def find(x):
        while p[x] != x:
            p[x] = p[p[x]]; x = p[x]           # path halving
        return x
    ans = [0] * len(queries)
    pairs = i = 0
    for qi in sorted(range(len(queries)), key=queries.__getitem__):
        while i < len(edges) and edges[i][0] <= queries[qi]:
            _, u, v = edges[i]; i += 1
            a, b = find(u), find(v)
            if a != b:
                if sz[a] < sz[b]:
                    a, b = b, a
                pairs += sz[a] * sz[b]
                p[b] = a; sz[a] += sz[b]
        ans[qi] = pairs
    return ans
P4 · Bridges: make every road one-way

Problem. Orient each road of a connected city so every junction can still reach every other, or report that it is impossible. Robbins' theorem: it is possible iff the graph is connected and bridgeless. A bridge, whichever way it points, cuts one side off. Construction: one DFS that orients each edge the first time it is seen. Tree edges then point down, and each back edge points up from descendant to ancestor, so every subtree can climb out. \(O(n + m)\), using bridges_and_cut_vertices from L73.

def orient_strongly(n, edges):
    """Edge i becomes res[i] = (from, to), or None if no strongly connected orientation exists."""
    bridges, _ = bridges_and_cut_vertices(n, edges)
    if bridges:
        return None
    adj = [[] for _ in range(n)]
    for i, (u, v) in enumerate(edges):
        adj[u].append((v, i)); adj[v].append((u, i))
    seen = [False] * n; seen[0] = True
    it = [0] * n
    res = [None] * len(edges)
    stack = [0]
    while stack:
        u = stack[-1]
        if it[u] < len(adj[u]):
            v, i = adj[u][it[u]]; it[u] += 1
            if res[i] is None:
                res[i] = (u, v)                    # first sighting: tree edge down, or back edge up
                if not seen[v]:
                    seen[v] = True; stack.append(v)
        else:
            stack.pop()
    return res if all(seen) else None
P5 · DAG DP: critical jobs

Problem. Jobs with durations and prerequisites. Find the minimum total time, and the number of jobs whose delay would delay everything (zero slack), or −1 on a cycle. In Kahn order compute earliest starts \(es[v] = \max_{u \to v}(es[u] + d_u)\), with \(T = \max(es + d)\). In reverse order compute latest finishes \(lf[u] = \min_{u \to v}(lf[v] - d_v)\), starting from \(T\). A job is critical iff \(lf - es - d = 0\). This is two DAG DPs, \(O(n + m)\), with kahn from L66.

P6 · Matching modelling: rooks with walls

Problem. Place the most rooks on a board where walls block attacks. Observation: a rook "owns" its maximal horizontal run and its maximal vertical run of free cells, and two rooks conflict iff they share a run. So each free cell is an edge between its row-run and its column-run, and the answer is a maximum bipartite matching (L77). Without walls this degenerates to \(\min(H, W)\).

def max_rooks(grid):
    """grid: list of strings, '#' = wall. Uses max_matching from L77."""
    H, W = len(grid), len(grid[0])
    rid = [[-1] * W for _ in range(H)]
    cid = [[-1] * W for _ in range(H)]
    nr = nc = 0
    for r in range(H):
        for c in range(W):
            if grid[r][c] == ".":
                if c == 0 or grid[r][c - 1] == "#":
                    nr += 1                        # a new horizontal run starts here
                rid[r][c] = nr - 1
    for c in range(W):
        for r in range(H):
            if grid[r][c] == ".":
                if r == 0 or grid[r - 1][c] == "#":
                    nc += 1
                cid[r][c] = nc - 1
    adj = [[] for _ in range(nr)]
    for r in range(H):
        for c in range(W):
            if grid[r][c] == ".":
                adj[rid[r][c]].append(cid[r][c])
    return max_matching(nr, nc, adj)[0]
