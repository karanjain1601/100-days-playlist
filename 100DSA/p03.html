Strings: From Basics to Suffix Structures

Phase 3 is the string toolkit, from Python's own string traps through polynomial hashing, KMP, the Z-function and Manacher to tries, Aho–Corasick and suffix arrays. Every algorithm comes with its correctness argument, an implementation measured honestly in CPython, and a stress test against slicing brute force, and together they form the strings.py file of your library. The automata built here return as DP states in Phase 6, and the LCP array meets range-minimum structures in Phase 7.

By the end of this phase you can

  • Handle strings in Python without hidden quadratic costs: join instead of repeated concatenation, bytes in fast I/O, 26-slot count arrays in hot loops.
  • Compare any two substrings in O(1) with a randomised polynomial hash, bound its collision probability, and combine it with binary search on the answer.
  • Derive the prefix function and the Z-function from their invariants, prove both linear, and use them for matching, borders, periods and compression.
  • Compute every maximal palindrome in O(n) with Manacher's algorithm and convert radii back to indices without off-by-one errors.
  • Build tries and binary tries in memory-safe flat arrays, and answer prefix-count and maximum-XOR queries with them.
  • Build an Aho–Corasick automaton by BFS, count all pattern occurrences in one pass, and run a DP over its states.
  • Build a suffix array and LCP array and solve distinct-substring, longest-repeat, longest-common-substring and k-th-substring problems with them.

String Fundamentals & Python-Specific Traps

45m video

Python strings are immutable arrays of code points, so every "edit" builds a new string and every slice copies. Fast string code in Python means knowing which operations run in C over the whole string, building output once with join, and replacing dictionaries with 26-slot lists in the loops that run a million times.

Immutability and the real cost of string operations

s[i] = 'x' is a TypeError. To edit, convert once to a list of characters (or a bytearray for ASCII), edit in place, and ''.join at the end. Hashes are cached after the first hash(s), which makes strings good dict keys, but a new slice is a new object with its hash recomputed.

The quadratic concatenation trap

r = r + c copies r, so building a string of length \(n\) one piece at a time is \(\Theta(n^2)\) in principle. CPython hides this for the common case: when r has no other reference it resizes the string in place. The optimisation is fragile. Measured on CPython 3.12 for \(n = 2\cdot10^5\) one-character appends:

PyPy has no such optimisation. The rule: collect pieces in a list and join once; for output, join all lines and write once.

ord, chr, frequency arrays, and bytes

For lowercase letters, ord(c) - 97 maps 'a'..'z' to 0..25 and chr(97 + k) maps back. For counting a whole string once, a C loop wins: Counter(s) took 0.10 s on \(10^6\) letters and 26 calls of s.count took 0.05 s, against 0.21 s for a Python loop over a 26-list. The picture flips inside a hot loop that updates counts step by step and compares them (the sliding-window anagram check over \(10^6\) characters):

Lists index by a small int with no hashing, and comparing two 26-lists is one C call. Bytes in fast I/O: sys.stdin.buffer.read().split() yields bytes; iterating or indexing bytes gives ints directly (b'abc'[0] == 97), so the ord call disappears. Bytes compare lexicographically by byte value, exactly like ASCII str, and hash fine as keys. Decode only what you print, or write bytes to sys.stdout.buffer.

Palindromes and anagrams

A palindrome check is two pointers moving inward, or t == t[::-1], which runs in C and is usually faster. Almost palindrome (delete at most one character): walk inward until the first mismatch \(s_i \ne s_j\); the answer is whether \(s[i+1..j]\) or \(s[i..j-1]\) is a palindrome.

Claim · two checks suffice

If deleting any one character makes \(s\) a palindrome, then deleting \(s_i\) or \(s_j\) does. The outer pairs already match and \(s_i \ne s_j\), so one of the two positions must change partner. Deleting some \(s_k\) with \(k > j\) shifts the right side by one, and the matched outer characters then face their right neighbours; for the result to be a palindrome this forces \(s_j = s_{j+1} = \dots = s_k\), and deleting any character of a run gives the same string, so deleting \(s_j\) works too (symmetrically on the left). Two checks, \(O(n)\). (Verified exhaustively on all binary strings up to length 10.)

Anagrams are strings with equal multisets of characters. Two canonical forms: ''.join(sorted(w)), \(O(k\log k)\), and the count signature tuple(cnt), \(O(k + 26)\). Grouping by a canonical form, so that equivalent objects collide on purpose, is the idea polynomial hashing turns into \(O(1)\) substring comparison in L37.

def almost_palindrome(s):                   # LeetCode 680
    i, j = 0, len(s) - 1
    while i < j and s[i] == s[j]:
        i += 1; j -= 1
    if i >= j:
        return True
    a, b = s[i + 1:j + 1], s[i:j]           # delete s[i] or s[j]
    return a == a[::-1] or b == b[::-1]

def group_anagrams(words):                  # LeetCode 49
    groups = {}
    for w in words:
        cnt = [0] * 26
        for x in w.encode():
            cnt[x - 97] += 1
        groups.setdefault(tuple(cnt), []).append(w)
    return list(groups.values())

def longest_pal_brute(s):                   # LeetCode 5, O(n^2): Manacher in L40
    best = ""
    for c in range(2 * len(s) - 1):         # centre between c//2 and (c+1)//2
        l, r = c // 2, (c + 1) // 2
        while l >= 0 and r < len(s) and s[l] == s[r]:
            l -= 1; r += 1
        if r - l - 1 > len(best):
            best = s[l + 1:r]
    return best

Lexicographic order and the next permutation

Python compares strings by code point, left to right; a proper prefix is smaller ('ab' < 'abc'), and every uppercase letter precedes every lowercase one ('Z' < 'a'). min/max/sorted on strings use this order; each comparison costs \(O(\text{LCP})\). The next permutation in this order is found from the right.

Algorithm · next permutation
  1. Find the largest \(i\) with \(a_i < a_{i+1}\). If none, the sequence is the last permutation.
  2. Find the largest \(j > i\) with \(a_j > a_i\) (the suffix is non-increasing, so this is the smallest larger value, rightmost among equals).
  3. Swap \(a_i, a_j\); the suffix stays non-increasing; reverse it to make it ascending.

\(O(n)\) per step. With >=/<= as below, duplicates are handled and each distinct arrangement appears once, so starting from the sorted sequence enumerates all distinct permutations in order.

def next_permutation(a):                    # in place; False (and reset to sorted) after the last
    i = len(a) - 2
    while i >= 0 and a[i] >= a[i + 1]:
        i -= 1
    if i < 0:
        a.reverse()
        return False
    j = len(a) - 1
    while a[j] <= a[i]:
        j -= 1
    a[i], a[j] = a[j], a[i]
    a[i + 1:] = a[:i:-1]                    # reversed suffix
    return True

String Hashing (Polynomial Rolling Hash) & Rabin–Karp

55m video

Map every substring to a number so that equal substrings get equal numbers and different ones almost surely don't. With prefix hashes, any substring's number takes O(1) to compute, so "are these two substrings equal?" becomes an O(1) question, and many string problems become binary search plus a set.

The polynomial hash

Definition

For a string \(s_0 s_1 \dots s_{k-1}\) with character codes \(s_i \ge 1\), a base \(B\) and a prime modulus \(M\), $$H(s) = \Big(\sum_{i=0}^{k-1} s_i\, B^{\,k-1-i}\Big) \bmod M,$$ computed left to right by Horner's rule: \(h \leftarrow (hB + s_i) \bmod M\). Use \(M = 2^{61}-1\) (a Mersenne prime) with \(B\) drawn at random from \([2^{20}, M-1)\) on every run; or two independent hashes with primes near \(10^9\) and compare the pair.

Python's integers never overflow, so the 122-bit product \(hB\) is exact, and % with a positive modulus always returns a value in \([0, M)\): the negative-remainder fix-up that C++ and Java need ((x % M + M) % M) is unnecessary. The cost is speed: building the prefix and power tables for \(10^6\) characters took about 2 s in CPython 3.12, so build each table once and inline the arithmetic in hot loops.

Prefix hashes: any substring in O(1)

Let \(h_i = H(s[0:i])\), so \(h_0 = 0\) and \(h_{i+1} = (h_i B + s_i) \bmod M\). Precompute \(p_k = B^k \bmod M\).

Derivation · substring hash

Unrolling Horner's rule from position \(l\) to \(r\): \(h_r = h_l\, B^{\,r-l} + \sum_{i=l}^{r-1} s_i B^{\,r-1-i} \pmod M\). The sum is exactly \(H(s[l:r])\), so $$H(s[l:r]) = \big(h_r - h_l\, p_{r-l}\big) \bmod M.$$ Shifting the prefix \(s[0:l]\) left by \(r - l\) digits in base \(B\) and subtracting it leaves the digits of \(s[l:r]\).

Implementation

import random

class Hashing:
    """Prefix hashes mod 2^61 - 1. get(l, r) = hash of s[l:r]. Share `base` to compare two strings."""
    M = (1 << 61) - 1

    def __init__(self, s, base=None):
        M = self.M
        self.B = B = base or random.randrange(1 << 20, M - 1)
        vals = s if isinstance(s, (bytes, bytearray, list)) else [ord(c) for c in s]
        h, p = [0] * (len(vals) + 1), [1] * (len(vals) + 1)
        for i, c in enumerate(vals):
            h[i + 1] = (h[i] * B + c) % M
            p[i + 1] = p[i] * B % M
        self.h, self.p = h, p

    def get(self, l, r):
        return (self.h[r] - self.h[l] * self.p[r - l]) % self.M

Double hashing: two Hashing objects with different moduli (say \(10^9+7\) and \(998244353\)) and independent bases, compared as a tuple. With \(2^{61}-1\) one hash is enough and half the work. Codes must be non-zero (or lengths compared separately), or "\0" and "\0\0" collide.

Rabin–Karp

To find pattern \(P\) (length \(m\)) in text \(T\) (length \(n\)), compare \(H(P)\) with the hash of every length-\(m\) window of \(T\). With prefix hashes each window is one get; the classic formulation updates a rolling hash instead: drop \(T_i \cdot B^{m-1}\), multiply by \(B\), add \(T_{i+m}\). Either way, \(O(n + m)\) arithmetic. Verifying candidate matches with a real comparison makes the answer certain, at \(O(m)\) per reported match.

def rabin_karp(text, pat):                       # start positions; text and pat as bytes
    n, m = len(text), len(pat)
    if m > n:
        return []
    H = Hashing(text)
    target = Hashing(pat, H.B).get(0, m)
    h, pm, M = H.h, H.p[m], H.M                  # inline get() in the hot loop
    return [i for i in range(n - m + 1) if (h[i + m] - h[i] * pm) % M == target]

How often does it lie?

Theorem · collision probability

Let \(u \ne v\) be strings of equal length \(k\) and \(B\) uniform on \(\mathbb{Z}_M\), \(M\) prime. Then \(H(u) = H(v)\) iff \(B\) is a root of the non-zero polynomial \(D(x) = \sum_i (u_i - v_i)\, x^{k-1-i}\) over the field \(\mathbb{Z}_M\), which has at most \(k-1\) roots. So $$\Pr[H(u) = H(v)] \le \frac{k-1}{M}.$$ Over \(q\) comparisons, a union bound gives at most \(q(k-1)/M\). The bound holds for every pair of strings, including ones an adversary chose, provided the base is drawn after the input is fixed.

For "how many distinct substrings", every pair among \(N\) values must stay apart. Treating hashes as random, the birthday estimate is about \(N^2/(2M)\) collisions. With \(N = 2\cdot10^5\) and \(M \approx 10^9\) that is about 20: measured on random 26-letter strings, counting distinct length-20 windows with a single \(10^9+7\) hash lost 22, 14 and 20 of 199,981 over three seeds; with \(2^{61}-1\), none. A single \(10^9\) modulus is fine for one pattern search and wrong for set-based counting.

Anti-hash tests. With a fixed, known base and modulus, a hacker constructs colliding strings offline (birthday or lattice-style searches). Hashing modulo \(2^{64}\) by letting integers overflow (the C++ shortcut) is broken for every base by strings built from the Thue–Morse sequence, a well-known Codeforces construction. Random base per run plus a large prime modulus defeats both: the test is fixed before your random choice.

Applications

  • Distinct substrings of length \(k\): len({H.get(i, i+k) for i in range(n-k+1)}), \(O(n)\).
  • Longest common substring by binary search on the answer + hash set, one of the most reused CP patterns: if a common substring of length \(L\) exists, so does one of length \(L-1\) (its prefix), so the predicate is monotone. Each check hashes all windows of one string into a dict and probes with the other: \(O((n+m)\log \min(n,m))\).
  • Palindrome test in O(1): hash \(s\) and its reverse with the same base; \(s[l:r]\) is a palindrome iff F.get(l, r) == R.get(n - r, n - l).
  • 2D matching: hash each row's width-\(c\) windows, then hash each column of those row hashes with a second base; an \(r\times c\) block is then one number, \(O(nm)\) for all blocks.
def longest_common_substring(s, t):
    B = random.randrange(1 << 20, Hashing.M - 1)
    hs, ht = Hashing(s, B), Hashing(t, B)
    def common(L):                               # start in s of a common substring of length L, or -1
        seen = {hs.get(i, i + L): i for i in range(len(s) - L + 1)}
        for j in range(len(t) - L + 1):
            i = seen.get(ht.get(j, j + L))
            if i is not None:
                return i
        return -1
    lo, hi = 0, min(len(s), len(t))              # invariant: length lo is achievable
    while lo < hi:
        mid = (lo + hi + 1) // 2
        if common(mid) >= 0:
            lo = mid
        else:
            hi = mid - 1
    i = common(lo) if lo else 0
    return s[i:i + lo]

  • CSES — Finding Borders. Every \(k < n\) with H.get(0, k) == H.get(n - k, n).

What breaks
  • Fixed base and modulus on Codeforces: hacked. Random base each run.
  • Single \(10^9\) modulus with a set of many hashes: birthday collisions, about \(N^2/2M\) (measured above).
  • Comparing hashes of different lengths, or codes of 0: equal hashes for different strings.
  • Two strings hashed with different bases: their hashes are unrelated. Pass the same base.
  • Off-by-one in get: it is half-open \([l, r)\); \(H(s[l..r])\) inclusive is get(l, r + 1).
  • Python speed: a method call per window costs as much as the arithmetic. Inline h, p, M into locals inside loops over \(10^6\) windows; for a single window length, skip the power table and use pow(B, m, M).

KMP and the Prefix Function

55m video

When a match attempt fails after j matched characters, those j characters are known, so the next alignment worth trying is determined by the pattern alone: the longest proper prefix of what matched that is also a suffix of it. Precomputing that length for every prefix (the prefix function) gives deterministic O(n + m) matching and a family of border and period tricks.

The naive matcher's worst case

Trying every alignment and comparing left to right costs \(O(nm)\). The bad case is easy to build: text "a" * n, pattern "a" * (m-1) + "b". Every alignment matches \(m-1\) characters before failing, so the matcher does about \((n-m+1)\,m\) comparisons: \(10^{9}\) for \(n = 10^6\), \(m = 1000\). It re-reads text characters it has already matched. KMP never moves backwards in the text.

The prefix function

Definition

A border of a string is a proper prefix that is also a suffix ("ab" is a border of "abcab"). The prefix function of \(s\) is \(\pi[i]\) = the length of the longest border of \(s[0..i]\), with \(\pi[0] = 0\). For "aabaaab", \(\pi = [0, 1, 0, 1, 2, 2, 3]\).

Lemma · borders of borders

If \(u\) is the longest border of \(s\), then the borders of \(s\) are exactly \(u\) and the borders of \(u\). (A border \(v\) of \(s\) shorter than \(u\) is a prefix of \(u\), being a prefix of \(s\), and a suffix of \(u\), being a suffix of \(s\) that fits inside the suffix \(u\).) So all borders of \(s[0..i]\), longest first, have lengths \(\pi[i], \pi[\pi[i]-1], \pi[\pi[\pi[i]-1]-1], \dots, 0\).

Computing π in O(n)

A border of \(s[0..i]\) of length \(j+1 \ge 1\) is a border of \(s[0..i-1]\) of length \(j\) extended by one character with \(s[j] = s[i]\). So the candidates for \(\pi[i]\) are the borders of \(s[0..i-1]\), tried longest first, which the lemma lists: start with \(j = \pi[i-1]\); while \(j > 0\) and \(s[i] \ne s[j]\), fall back to \(j = \pi[j-1]\); then extend if \(s[i] = s[j]\). The fallback is the failure-link idea: "where can I retry without re-reading?"

Proof · linear time

Track \(j\) across the whole loop. Each iteration of the outer loop raises \(j\) by at most 1, so the total increase is at most \(n-1\). Each fallback strictly decreases \(j\), and \(j \ge 0\) always. Total decrease cannot exceed total increase, so there are at most \(n - 1\) fallbacks in all, and the algorithm makes at most \(2n\) character comparisons.

Implementation

def prefix_function(s):
    pi = [0] * len(s)
    for i in range(1, len(s)):
        j = pi[i - 1]
        while j and s[i] != s[j]:
            j = pi[j - 1]                       # next shorter border of s[:i]
        if s[i] == s[j]:
            j += 1
        pi[i] = j
    return pi

def kmp_search(text, pat):                      # all start positions, overlaps included
    if not pat:
        return list(range(len(text) + 1))
    pi, m, j, out = prefix_function(pat), len(pat), 0, []
    for i, c in enumerate(text):
        while j and c != pat[j]:
            j = pi[j - 1]
        if c == pat[j]:
            j += 1
        if j == m:
            out.append(i - m + 1)
            j = pi[j - 1]
    return out

def kmp_automaton(pat, alphabet):
    """aut[j][c] = state after reading alphabet[c] in state j, for j = 0..m."""
    pi, m, A = prefix_function(pat), len(pat), len(alphabet)
    code = [alphabet.index(ch) for ch in pat]
    aut = [[0] * A for _ in range(m + 1)]
    for j in range(m + 1):
        for c in range(A):
            if j < m and code[j] == c:
                aut[j][c] = j + 1
            elif j:
                aut[j][c] = aut[pi[j - 1]][c]   # row pi[j-1] < j is already built
    return aut

Matching by concatenation. The textbook alternative computes \(\pi\) of pat + '#' + text and reports positions where \(\pi = m\). It is correct only if '#' occurs in neither string: otherwise a border can run through a '#' inside the text, exceed \(m\), and hide a match. kmp_search avoids the question. On bytes, the safe separator is a value outside 0..255, so convert to a list of ints and use \(-1\).

The automaton. Row \(j\) copies row \(\pi[j-1]\) except for the one forward edge, so the table costs \(O(m\Sigma)\) time and memory and makes every step \(O(1)\) with no fallback loop. Its real use is DP over strings (L88): to count strings of length \(n\) that avoid a pattern, the state is the automaton node, and the pattern occurs iff the walk reaches state \(m\).

The Z-Function

45m video

The Z-function records, for every position, how far the string from there agrees with its own beginning. It is computed in O(n) by remembering the furthest-reaching match seen so far and copying answers out of it, and it says the same things as the prefix function in a form that is often easier to use.

Definition, and the naive version

Definition

For a string \(s\) of length \(n\), \(z[i]\) is the length of the longest common prefix of \(s\) and \(s[i:]\), for \(1 \le i < n\); by convention \(z[0] = 0\). For "aabxaab", \(z = [0, 1, 0, 0, 3, 1, 0]\). A z-box is a segment \([i, i + z[i])\): a copy of the prefix of that length.

Comparing from scratch at every \(i\) is \(O(n^2)\) on "aaaa…". Keep it anyway: it is the reference implementation for the stress test.

The [l, r) window and its three cases

Maintain the z-box \([l, r)\) with the largest right end found so far, so \(s[l:r] = s[0:r-l]\). For a new \(i\):

  1. \(i \ge r\): nothing is known; compare naively from \(s[0]\) and \(s[i]\).
  2. \(i < r\) and \(z[i-l] < r - i\): position \(i\) inside the box mirrors position \(i - l\) inside the prefix, and the match starting there ends strictly inside the mirrored region, followed by a known mismatch. So \(z[i] = z[i-l]\) exactly; no comparison succeeds.
  3. \(i < r\) and \(z[i-l] \ge r - i\): the first \(r - i\) characters are known to match, but beyond \(r\) nothing is known. Start at \(z[i] = r - i\) and compare from \(s[r]\) onwards.
Theorem · linear time

Invariants: \(s[l:r] = s[0:r-l]\), and \(r\) is the maximum of \(j + z[j]\) over \(j < i\). Each successful character comparison happens at a position \(\ge r\) (cases 1 and 3) and is followed by moving \(r\) at least that far, so successful comparisons number at most \(n\) in total; each \(i\) adds at most one failing comparison. Hence at most \(2n\) comparisons: \(O(n)\).

Implementation, twice, and a stress test

import random

def z_naive(s):                                 # O(n^2) reference
    n = len(s); z = [0] * n
    for i in range(1, n):
        while i + z[i] < n and s[z[i]] == s[i + z[i]]:
            z[i] += 1
    return z

def z_function(s):
    n = len(s); z = [0] * n
    l = r = 0                                   # s[l:r] == s[:r-l], r maximal so far
    for i in range(1, n):
        if i < r:
            z[i] = min(r - i, z[i - l])         # cases 2 and 3
        while i + z[i] < n and s[z[i]] == s[i + z[i]]:
            z[i] += 1                           # succeeds only beyond r
        if i + z[i] > r:
            l, r = i, i + z[i]
    return z

for _ in range(10_000):
    s = "".join(random.choice("ab") for _ in range(random.randint(1, 20)))
    assert z_function(s) == z_naive(s), s

Matching, and converting between Z and π

Matching: compute \(z\) of pat + sep + text; the pattern occurs at text position \(i - m - 1\) wherever \(z[i] = m\). As with KMP, sep must occur in neither string, which also guarantees \(z \le m\) in the text part.

π from Z: a z-box \([i, i + z[i])\) says that for every \(j < z[i]\) the prefix of length \(j + 1\) ends at \(i + j\), a border candidate. The longest border ending at a position comes from the leftmost box covering it, so process \(i\) in increasing order and fill each position once, from the right end of the box inwards, stopping at the first already-filled one: \(O(n)\). Z from π: the prefix function determines the string's equality structure, so rebuild a string with the same \(\pi\) (a fresh symbol where \(\pi[i] = 0\), otherwise a copy of \(t[\pi[i]-1]\)) and run z_function on it. Both conversions were checked exhaustively against direct computation on all 88,572 strings over {a, b, c} of length up to 10.

def z_search(text, pat, sep="\0"):
    m = len(pat)
    return [i - m - 1 for i, v in enumerate(z_function(pat + sep + text)) if v == m]

def z_to_pi(z):
    pi = [0] * len(z)
    for i in range(1, len(z)):
        for j in range(z[i] - 1, -1, -1):
            if pi[i + j]:
                break                           # an earlier box already gave a longer border here
            pi[i + j] = j + 1
    return pi

def pi_to_z(pi):
    t = []
    for i, v in enumerate(pi):
        t.append(t[v - 1] if v else i)          # i is a symbol used nowhere else
    return z_function(t)

Applications

  • Periodicity: \(p\) is a period iff \(p + z[p] = n\); the smallest such \(p\) is the smallest period, and \(s\) compresses to \(s[0:p]\) repeated iff also \(n \bmod p = 0\).
  • Rotation: \(t\) is a rotation of \(s\) iff \(|t| = |s|\) and \(t\) occurs in \(s + s\): every rotation is a length-\(n\) window of the doubled string.
  • Longest palindromic prefix: in \(u = s + \text{sep} + \text{reverse}(s)\), a position \(j\) in the reversed half with \(j + z[j] = |u|\) marks a suffix of \(\text{reverse}(s)\) equal to a prefix of \(s\); such a suffix of length \(L\) is \(\text{reverse}(s[0:L])\), so \(s[0:L]\) is a palindrome. Take the largest.
  • Distinct substrings (intuition): appending a character \(c\) to \(s\) creates new substrings exactly among the suffixes of \(s + c\); with \(t\) = reverse(\(s + c\)), the number of new ones is \(|t| - \max z_t\). Summed over all prefixes this counts distinct substrings in \(O(n^2)\), fine for \(n \le 5000\); suffix arrays do it in \(O(n\log n)\) (L45).
def longest_pal_prefix(s):

When Z reads better than KMP. Whenever the question is about LCPs with the pattern at each text position ("how much of the pattern matches starting here?"), \(z\) is the answer itself, while \(\pi\) talks about borders of prefixes and needs translating. The loop also has no nested fallback chain, so it is easier to write correctly under pressure. KMP keeps two advantages: it processes the text as a stream, and it yields an automaton (L38).

What breaks

  • Forgetting the cap min(r - i, …): copies a value that runs past what is known. Wrong answers only on periodic strings.
  • Updating the box when \(i + z[i] \le r\): harmless for correctness here but a classic bug in variants that rely on \(l\).

Manacher's Algorithm: All Palindromic Substrings in O(n)

50m video

Inside a long palindrome, the right half mirrors the left, so a palindrome centred on the right is (almost) a copy of one already found on the left. Manacher's algorithm reuses those copies and only compares characters beyond the furthest palindrome seen, which gives the maximal palindrome at every centre in O(n).

The inventory, and the O(n²) baseline

Every palindrome has a centre: a character (odd length) or a gap between two characters (even length). Expanding outward from all \(2n-1\) centres finds every maximal palindrome in \(O(n^2)\) (L36). Manacher keeps the expansion but skips the comparisons it can predict.

One case instead of two: the #a#b# transform

Interleave a separator: \(t = \#\,s_0\,\#\,s_1\,\#\cdots\#\,s_{n-1}\,\#\), length \(2n+1\). Every palindrome of \(s\), odd or even, is an odd-length palindrome of \(t\) centred at a letter (odd length in \(s\)) or at a separator (even length). Define \(p[i]\) as the largest radius with \(t[i-p..i+p]\) a palindrome. Then the maximal palindrome of \(s\) at that centre has length exactly \(p[i]\) and starts at index \((i - p[i])/2\). Comparisons at equal distance from a centre always pair letters with letters and separators with separators, so the separator may even occur in \(s\).

Mirrors and the right boundary

Keep the palindrome with the furthest right end found so far: centre \(c\), right end \(r = c + p[c]\), left end \(2c - r\). For a new centre \(i < r\), its mirror is \(j = 2c - i\), whose \(p[j]\) is already known. Inside \([2c-r, r]\), \(t\) reads the same in both directions around \(c\), so the palindrome around \(j\) appears around \(i\) as well, as far as the box allows.

Theorem · the three cases

Let \(i < r\), \(j = 2c - i\), \(L = 2c - r\). Mirror symmetry inside the box gives \(p[i] \ge \min(p[j], r - i)\).

If \(p[j] < r - i\), then \(p[i] = p[j]\): the mismatching pair just outside \(j\)'s palindrome lies inside the box, so its mirror image, just outside \(i\)'s, mismatches too.

If \(p[j] > r - i\), then \(p[i] = r - i\). By maximality of \(c\)'s palindrome, \(t[L-1] \ne t[r+1]\). Since \(p[j] > j - L\), the palindrome at \(j\) covers \(L-1\), so \(t[L-1] = t[2j - L + 1]\); that position lies inside the box, and reflecting it through \(c\) gives \(t[2j-L+1] = t[2i - r - 1]\). If \(p[i]\) exceeded \(r - i\), then \(t[2i-r-1] = t[r+1]\), so \(t[L-1] = t[r+1]\): contradiction.

If \(p[j] = r - i\): nothing is known beyond \(r\); compare from there.

Proof · linear time

Every successful comparison in the expansion loop extends \(i\)'s palindrome past the current \(r\) (in case 1 of the expansion, \(i \ge r\); in the last case it starts at \(r\)), after which \(r\) is moved to the new end. So successful comparisons number at most \(|t| = 2n+1\) overall, and each centre adds at most one failed comparison: \(O(n)\).

Implementation and outputs

def manacher(s):
    """p[i] for t = sep, s0, sep, s1, ..., sep: radius in t = length of that palindrome in s."""
    t = [None] * (2 * len(s) + 1)
    t[1::2] = s                                 # works for str, bytes and lists
    n, p = len(t), [0] * len(t)
    c = r = 0                                   # rightmost palindrome: centre c, right end r
    for i in range(n):
        if i < r:
            p[i] = min(r - i, p[2 * c - i])     # mirror
        a, b = i - p[i] - 1, i + p[i] + 1
        while a >= 0 and b < n and t[a] == t[b]:
            a -= 1; b += 1
        p[i] = b - i - 1
        if b - 1 > r:
            c, r = i, b - 1
    return p

def longest_palindrome(s):                      # LeetCode 5, CSES Longest Palindrome
    p = manacher(s)
    i = max(range(len(p)), key=p.__getitem__)
    start = (i - p[i]) // 2
    return s[start:start + p[i]]

def count_palindromes(s):                       # LeetCode 647
    return sum((v + 1) // 2 for v in manacher(s))

def palindrome_checker(s):                      # O(1) test for s[l..r], inclusive
    p = manacher(s)
    return lambda l, r: p[l + r + 1] >= r - l + 1
  • Back to indices of \(s\). Letters sit at odd positions of \(t\); a maximal palindrome of \(t\) begins and ends on separators, so it starts at \(t\)-index \(i - p[i]\) (even), and its first letter is \(s[(i - p[i])/2]\). The centre of \(s[l..r]\) is \(t\)-index \(l + r + 1\), which is the checker's formula.
  • Counting. A centre with radius \(p\) holds palindromes of lengths \(p, p-2, \dots\) down to 1 or 2: \(\lceil p/2 \rceil\) of them. In the two-array formulation (\(d_1\) odd, \(d_2\) even, counting palindromes per centre) this is the familiar "sum of the radii", \(\sum d_1 + \sum d_2\).
  • Palindromic prefix / suffix. Centres with \(i = p[i]\) give palindromes starting at 0; centres with \(i + p[i] = 2n\) give palindromes ending at \(n - 1\).
  • Splitting into palindromes. With the \(O(1)\) checker, the DP "fewest palindromic pieces of \(s[0:i]\)" is \(O(n^2)\) instead of \(O(n^3)\) (L87).

Manacher vs hashing vs the eertree

Hashing (L37) finds the maximal radius at each centre by binary search: \(O(n\log n)\), slower, but it adapts to variants such as "palindromes with at most one mismatch". Manacher is exact, deterministic, \(O(n)\), and answers every centre at once. The eertree (palindromic tree) stores each distinct palindrome as a node (a string of length \(n\) has at most \(n\) distinct non-empty palindromic substrings), supports appending characters online, and counts occurrences per palindrome; reach for it when the question is about distinct palindromes.

Trie (Prefix Tree)

50m video

A trie stores a set of strings as a tree of shared prefixes, so every question about prefixes ("how many words start with this?", "which stored word is a prefix of this text?") costs time proportional to the query's length, not the dictionary's size. In Python the hard part is not the idea but the memory layout.

Why a trie beats a hash set for prefixes

A set of words answers "is \(w\) present?" in \(O(|w|)\) (hashing reads the whole string), but "how many words start with \(p\)?" needs either a scan of the set or every prefix of every word stored separately (\(\sum |w|^2/2\) characters). A trie stores each distinct prefix once, as a node; the path from the root spells it.

Definition

A trie over alphabet \(\Sigma\) is a rooted tree whose edges carry characters, with distinct characters on the edges leaving any node. Node \(v\) represents the string read along the root-to-\(v\) path. Each node stores pass[v] (words in the set having this prefix) and end[v] (words equal to it). Insert, search and prefix count are \(O(|w|)\); the number of nodes is at most \(1 + \sum |w|\).

Operations: insert, search, prefix count, delete

Insert walks the word, creating missing children and incrementing pass along the path, then increments end. Search and startsWith walk without creating; a missing child means "absent". Delete by counting: walk the path decrementing pass and finally end. Nodes are never removed, so a node can exist with pass = 0; every query must test counts, not existence. This avoids the fiddly bottom-up node removal and keeps the flat arrays valid.

class TrieNode:
    __slots__ = ("ch", "pass_", "end")
    def __init__(self):
        self.ch, self.pass_, self.end = {}, 0, 0

class Trie:                                     # LeetCode 208, plus counts and delete
    def __init__(self):
        self.root = TrieNode()

    def insert(self, w):
        v = self.root
        v.pass_ += 1
        for c in w:
            nx = v.ch.get(c)
            if nx is None:
                nx = v.ch[c] = TrieNode()
            v = nx
            v.pass_ += 1
        v.end += 1

    def _walk(self, w):
        v = self.root
        for c in w:
            v = v.ch.get(c)
            if v is None:
                return None
        return v

    def search(self, w):
        v = self._walk(w); return bool(v and v.end)
    def starts_with(self, p):
        v = self._walk(p); return bool(v and v.pass_)
    def count_prefix(self, p):
        v = self._walk(p); return v.pass_ if v else 0

    def delete(self, w):                        # w must be present
        v = self.root
        v.pass_ -= 1
        for c in w:
            v = v.ch[c]
            v.pass_ -= 1
        v.end -= 1

def find_words(board, words):                   # LeetCode 212
    root = {}
    for w in words:
        node = root
        for c in w:
            node = node.setdefault(c, {})
        node["$"] = w
    R, C, out = len(board), len(board[0]), []
    def dfs(i, j, parent):
        c = board[i][j]
        node = parent[c]
        w = node.pop("$", None)
        if w:
            out.append(w)
        board[i][j] = "#"                       # visited on this path
        for a, b in ((i + 1, j), (i - 1, j), (i, j + 1), (i, j - 1)):
            if 0 <= a < R and 0 <= b < C and board[a][b] in node:
                dfs(a, b, node)
        board[i][j] = c
        if not node:
            del parent[c]                       # prune: nothing left below
    for i in range(R):
        for j in range(C):
            if board[i][j] in root:
                dfs(i, j, root)
    return out

Compressed tries, and where suffix trees come from

Chains of single-child nodes waste memory. A compressed trie (radix tree, Patricia trie) merges each chain into one edge labelled with a string; with \(k\) words it has at most \(2k\) nodes. Insert all suffixes of a text into a compressed trie and you have its suffix tree: every substring is a path from the root. Suffix arrays (L44) carry the same information in two integer arrays, which is why they replaced suffix trees in contest practice (L45).

Binary Trie & XOR Problems

50m video

Store numbers as bit strings, most significant bit first, in a trie with two children per node. Because one high bit outweighs all lower bits together, "maximise x XOR y" becomes a walk from the root choosing the opposite bit whenever it exists, and counting or ranking XOR values becomes the same walk with subtree counts.

XOR is bitwise independent

Bit \(b\) of \(x \oplus y\) depends only on bit \(b\) of \(x\) and of \(y\): no carries. XOR is associative and commutative, \(x \oplus x = 0\) and \(x \oplus 0 = x\). The consequence for arrays: with prefix XORs \(P_0 = 0\), \(P_{i+1} = P_i \oplus a_i\), the XOR of \(a[l..r]\) is \(P_{r+1} \oplus P_l\). Every subarray question becomes a question about pairs of prefixes, as with prefix sums (L12).

The binary trie

Definition

Fix a width \(B\) with all values \(< 2^B\) (30 bits for values up to \(10^9\), 60 for \(10^{18}\)). Insert \(x\) by walking from the root through bits \(B-1, \dots, 0\), going to child 0 or 1. Every number is a root-to-leaf path of length exactly \(B\), and each node stores cnt, the number of stored values below it, so a multiset with deletions is just cnt -= 1 along the path. Every operation is \(O(B)\); the trie has at most \(1 + nB\) nodes.

Maximum XOR pair: why the greedy descent is optimal

Theorem · bit significance dominates

\(2^b > \sum_{i<b} 2^i = 2^b - 1\). So among the stored \(y\), any \(y\) giving bit \(b\) of \(x \oplus y\) equal to 1 beats every \(y\) giving 0 there, provided the higher bits agree. By induction from the top bit: after deciding bits \(B-1..b+1\) optimally, the candidates are exactly the values under the current node, and choosing the opposite-bit child when it is non-empty is forced. The walk returns \(\max_y x \oplus y\) in \(O(B)\). Inserting all values and querying each gives the best pair in \(O(nB)\).

Implementation

class BinaryTrie:
    """Multiset of ints in [0, 2**B). Node 0 is the root; a child index of 0 means none."""
    def __init__(self, B=30):
        self.B, self.c0, self.c1, self.cnt = B, [0], [0], [0]

    def add(self, x, d=1):                  # d = -1 erases one copy (x must be present)
        c0, c1, cnt = self.c0, self.c1, self.cnt
        v = 0
        cnt[0] += d
        for b in range(self.B - 1, -1, -1):
            ch = c1 if x >> b & 1 else c0
            if not ch[v]:
                ch[v] = len(cnt)
                c0.append(0); c1.append(0); cnt.append(0)
            v = ch[v]
            cnt[v] += d

    def max_xor(self, x):                   # max x ^ y over stored y (non-empty)
        c0, c1, cnt = self.c0, self.c1, self.cnt
        v = res = 0
        for b in range(self.B - 1, -1, -1):
            xb = x >> b & 1
            opp = (c0 if xb else c1)[v]
            if opp and cnt[opp]:
                v, res = opp, res | 1 << b
            else:
                v = (c1 if xb else c0)[v]
        return res

    def count_less(self, x, k):             # number of stored y with x ^ y < k
        c0, c1, cnt = self.c0, self.c1, self.cnt
        if k >> self.B:
            return cnt[0]                   # every XOR is below 2**B <= k
        v = res = 0
        for b in range(self.B - 1, -1, -1):
            xb, kb = x >> b & 1, k >> b & 1
            same = (c1 if xb else c0)[v]    # child where the XOR bit is 0
            if kb:
                res += cnt[same] if same else 0
                v = (c0 if xb else c1)[v]   # continue with XOR bit 1
            else:
                v = same
            if not v:
                break
        return res

    def kth_max_xor(self, x, k):            # k-th largest x ^ y, 1 <= k <= size
        c0, c1, cnt = self.c0, self.c1, self.cnt
        v = res = 0
        for b in range(self.B - 1, -1, -1):
            xb = x >> b & 1
            opp = (c0 if xb else c1)[v]
            c = cnt[opp] if opp else 0
            if c >= k:
                v, res = opp, res | 1 << b
            else:
                k -= c
                v = (c1 if xb else c0)[v]
        return res

def max_xor_subarray(a, B=30):
    t, pre, best = BinaryTrie(B), 0, 0
    t.add(0)                                # the empty prefix P_0
    for x in a:
        pre ^= x
        best = max(best, t.max_xor(pre))
        t.add(pre)
    return best

count_less: when \(k\)'s bit is 1, every value whose XOR bit is 0 here is already smaller than \(k\) whatever follows, so add that whole subtree and continue on the XOR-bit-1 side. Pairs with XOR in \([L, R]\): count_less(x, R + 1) - count_less(x, L).

Python notes. Three parallel lists keep nodes as plain ints. At \(nB\) above a few million nodes, preallocate array('i') storage as in L41, and shrink \(B\) to max(a).bit_length(). For the plain maximum XOR pair there is a trie-free method that runs in C-speed set operations: decide the answer's bits from the top, keeping the set of value prefixes {x >> b}, and test whether some pair of prefixes XORs to the candidate.

def max_xor_pair(nums, B=31):               # LeetCode 421 with sets: O(nB)
    ans = 0
    for b in range(B - 1, -1, -1):
        cand = ans | 1 << b
        pref = {x >> b for x in nums}
        if any(cand >> b ^ p in pref for p in pref):
            ans = cand
    return ans

Deletions, persistence, and the XOR basis

Deletions are add(x, -1); queries skip children with cnt == 0, exactly the trick from L41. Persistent binary trie (L109): make each insertion copy the \(B+1\) nodes on its path instead of modifying them, keeping a root per version. With version \(i\) = "first \(i\) values inserted", the counts of version \(r\) minus version \(l\) describe the values in \(a[l..r-1]\), so "max \(x \oplus a_j\) for \(l \le j < r\)" is one simultaneous walk down two roots. XOR of any subset is a different question: the reachable XORs form a vector space over \(\mathbb{F}_2\), and a basis built by elimination answers "maximum subset XOR" (theory in L125):

def max_subset_xor(a):                      # XOR basis by elimination over GF(2)
    basis = []
    for x in a:
        for b in basis:
            x = min(x, x ^ b)               # clears b's leading bit from x if present
        if x:
            basis.append(x)
    best = 0
    for b in sorted(basis, reverse=True):
        best = max(best, best ^ b)
    return best

What breaks
  • Inconsistent widths: inserting with 30 bits and querying with 31, or a value \(\ge 2^B\) (its top bits are silently ignored).
  • Forgetting \(P_0 = 0\) in subarray problems: subarrays starting at index 0 are missed.

Aho–Corasick: Multi-Pattern Matching

55m video

Aho–Corasick is KMP run on a trie: put all patterns in one trie, give every node a failure link to the longest proper suffix of its string that is also in the trie, and scan the text once. Every pattern occurrence is then visible from the current node, and the resulting automaton is also the state space for DP over strings that must avoid (or contain) a set of words.

The problem, and the trie

Given patterns \(p_1, \dots, p_k\) of total length \(L\) and a text of length \(n\), report or count every occurrence. Running KMP once per pattern costs \(O(kn + L)\), which is \(5\cdot10^{10}\) at CSES sizes. First insert every pattern into a trie (L41); node \(v\) represents a string \(\text{str}(v)\), and patterns end at marked nodes. Reading the text while walking down the trie works until a character has no edge; the question, as in KMP, is where to continue without re-reading.

Suffix links, built by BFS

Definition · suffix (failure) link

\(\text{link}(v)\) is the node for the longest proper suffix of \(\text{str}(v)\) that is a node of the trie (the root for the empty string). For one pattern, the trie is a path and \(\text{link}\) of the node at depth \(j\) is the node at depth \(\pi[j-1]\): exactly KMP's failure link (L38).

Theorem · the link recurrence

For the child \(u\) of \(v\) along character \(c\) (with \(v\) not the root), \(\text{link}(u) = \text{go}(\text{link}(v), c)\), where \(\text{go}(w, c)\) is "the node reached from \(w\) on \(c\), falling back along links when there is no edge". Children of the root link to the root. Why: a proper suffix of \(\text{str}(v)\,c\) that lies in the trie is a suffix of \(\text{str}(v)\) extended by \(c\); the suffixes of \(\text{str}(v)\) in the trie, longest first, are \(\text{link}(v), \text{link}(\text{link}(v)), \dots\), and \(\text{go}\) tries them in that order, as KMP's fallback loop does. BFS order is required: \(\text{link}(v)\) is strictly shallower than \(v\), so if nodes are processed by depth, everything \(\text{go}(\text{link}(v), c)\) needs is final. DFS order would read unfinished links.

Reporting matches, the automaton, and complexity

At any moment, the patterns that end at the current text position are exactly the marked nodes on the suffix-link chain from the current node. Walking the whole chain at every position can cost \(O(n \cdot \max_i |p_i|)\) (text aaaa…, patterns a, aa, aaa, …), so precompute the dictionary (output) link: the nearest marked node strictly up the chain. Following dictionary links visits only matches. Automaton form: fill in \(\text{go}(v, c)\) for every node and character during the BFS (copy \(\text{go}(\text{link}(v), c)\) when there is no edge); then scanning is one table lookup per character. Totals: \(O(L\Sigma)\) to build, \(O(n)\) to scan, plus \(O(\text{matches})\) to list them.

from collections import deque

class AhoCorasick:
    """Patterns are bytes over a-z. Node 0 is the root."""
    def __init__(self, patterns):
        go, term, self.end_of = [[-1] * 26], [[]], []
        for pid, p in enumerate(patterns):          # 1. the trie
            v = 0
            for x in p:
                c = x - 97
                if go[v][c] < 0:
                    go[v][c] = len(go)
                    go.append([-1] * 26); term.append([])
                v = go[v][c]
            term[v].append(pid)
            self.end_of.append(v)
        n = len(go)
        link, out, order, q = [0] * n, [-1] * n, [], deque()
        for c in range(26):                         # 2. depth-1 nodes link to the root
            if go[0][c] < 0:
                go[0][c] = 0
            else:
                q.append(go[0][c])
        while q:                                    # 3. BFS: links and automaton edges
            v = q.popleft()
            order.append(v)
            for c in range(26):
                u = go[v][c]
                if u < 0:
                    go[v][c] = go[link[v]][c]
                else:
                    w = link[u] = go[link[v]][c]
                    out[u] = w if term[w] else out[w]   # nearest marked node up the chain
                    q.append(u)
        self.go, self.link, self.out, self.order, self.term = go, link, out, order, term

    def matches(self, text):                        # (end index, pattern id) for every occurrence
        go, out, term, v, res = self.go, self.out, self.term, 0, []
        for i, x in enumerate(text):
            v = go[v][x - 97]
            u = v if term[v] else out[v]
            while u > 0:
                res.extend((i, pid) for pid in term[u])
                u = out[u]
        return res

    def count(self, text):                          # occurrences of each pattern
        go, hits, v = self.go, [0] * len(self.go), 0
        for x in text:
            v = go[v][x - 97]
            hits[v] += 1
        for v in reversed(self.order):              # deepest first: push counts up the links
            hits[self.link[v]] += hits[v]
        return [hits[v] for v in self.end_of]

Counting without listing: pattern \(p\) ends at position \(i\) iff \(p\)'s node is on the link chain of the state after \(i\). So record one hit per position at the current state, then sum hits over each node's subtree in the link tree, processing nodes in reverse BFS order. \(O(L\Sigma + n)\), independent of the number of matches.

DP over automaton states

"How many strings of length \(n\) contain none of the patterns?" A string avoids the patterns iff its automaton walk never visits a node whose link chain contains a marked node. Mark those nodes bad (in BFS order, bad[v] = marked(v) or bad[link[v]]), and count walks of length \(n\) that stay on good nodes: dp[v] = number of strings so far ending in state \(v\). \(O(n \cdot \text{nodes} \cdot \Sigma)\); with matrix power for huge \(n\) (L101). This (position, automaton node) state is why Aho–Corasick shows up in hard DP problems, and the single-pattern version is CSES — Required Substring (L38, L88).

def count_avoiding(patterns, n, MOD=10**9 + 7):    # length-n strings over a-z with no pattern
    ac = AhoCorasick(patterns)
    go, link, N = ac.go, ac.link, len(ac.go)
    bad = [bool(t) for t in ac.term]
    for v in ac.order:
        bad[v] = bad[v] or bad[link[v]]
    dp = [0] * N
    dp[0] = 1
    for _ in range(n):
        nd = [0] * N
        for v in range(N):
            if dp[v] and not bad[v]:
                for u in go[v]:
                    nd[u] += dp[v]
        dp = [x % MOD for x in nd]
    return sum(x for v, x in enumerate(dp) if not bad[v]) % MOD

Memory, large alphabets, and when hashing is simpler

The full table is \(\text{nodes} \times \Sigma\): for \(5\cdot10^5\) nodes and 26 letters, \(1.3\cdot10^7\) entries, which as lists of lists is well over 100 MB in CPython, and the build loop is the slow part: measured 7.4 s in CPython 3.12 to build \(3.8\cdot10^5\) nodes from \(5\cdot10^5\) random pattern characters, against 0.44 s to then count over a \(10^5\)-character text. For a large alphabet, keep only trie edges in per-node dicts and compute transitions on the fly with KMP's fallback loop; the scan stays amortised \(O(1)\) per character. Hashing is simpler when patterns have few distinct lengths: for each length \(\ell\), roll a window hash of the text and look it up in the set of pattern hashes of length \(\ell\) (L37). There are at most about \(\sqrt{2L}\) distinct lengths, so this is \(O(n\sqrt{L})\) at worst, and \(O(n)\) when all patterns share a length.

Problems

  • CSES — Pattern Positions. First occurrence of each pattern: record the first index at which each state is visited, propagate the minimum up the links in reverse BFS order, and print first - len(p) + 2 (1-based start), or \(-1\).

What breaks

  • Linking root's children to themselves (go[link[v]][c] with \(v\) = root returns the child itself): infinite loops. Root children link to 0.
  • Reporting only the current node's patterns: misses patterns that are suffixes of others (he inside she). Follow dictionary links, or propagate counts.
  • Walking the whole link chain per character: quadratic-ish on texts like aaaa… with patterns a, aa, aaa, ….
  • Duplicate patterns: two ids end at one node; keep a list, as term does, or map ids to nodes.
  • Python build time: the 26-way BFS loop is the bottleneck; use PyPy at CSES sizes.

Suffix Array: Construction and LCP

60m video

Sort all suffixes of a string and keep only their starting positions: that array, plus the longest common prefix of each adjacent pair, is a sorted dictionary of every substring. Prefix doubling builds it by sorting on pairs of ranks, and Kasai's algorithm gets the LCPs in linear time from one inequality.

What a suffix array is

Definition

For \(s\) of length \(n\), the suffix array sa is the permutation of \(0..n-1\) listing the starting positions of the suffixes \(s[i:]\) in lexicographic order; rank is its inverse (rank[sa[i]] = i). The LCP array has lcp[i] = length of the longest common prefix of suffixes sa[i-1] and sa[i] (with lcp[0] = 0). For banana: sa = [5, 3, 1, 0, 4, 2] (a, ana, anana, banana, na, nana), lcp = [0, 1, 3, 0, 0, 2].

A suffix tree holds the same information and more, but costs tens of machine words per character and an intricate construction. Two integer arrays, built with sorting, replaced it in contest practice; most suffix-tree algorithms translate into scans and range minima over sa and lcp (L45).

Naive construction

sorted(range(n), key=lambda i: s[i:]) does \(O(n \log n)\) comparisons of \(O(n)\) each, \(O(n^2\log n)\) in the worst case ("aaa…"), and the keys are \(n\) slices, \(O(n^2)\) memory. It is the oracle for stress tests up to \(n \approx 2000\), nothing more.

Prefix doubling, O(n log² n)

Rank suffixes by their first \(k\) characters; equal prefixes share a rank. To rank by the first \(2k\) characters, observe that the length-\(2k\) prefix of \(s[i:]\) is the length-\(k\) prefix of \(s[i:]\) followed by the length-\(k\) prefix of \(s[i+k:]\).

Theorem · pairs of ranks

If rank_k orders suffixes by their first \(k\) characters (shorter-than-\(k\) suffixes compared as whole strings), then ordering by the pair \((\text{rank}_k[i], \text{rank}_k[i+k])\), with \(-1\) when \(i + k \ge n\), orders them by their first \(2k\) characters. Comparing two length-\(2k\) prefixes is comparing first halves, then second halves on a tie, and ranks preserve both comparisons. The \(-1\) plays the role of a sentinel smaller than every character: a suffix that ends inside the window precedes every extension of it. After \(\lceil \log_2 n \rceil\) rounds all ranks are distinct and the order is final. Each round is one sort: \(O(n\log n)\), total \(O(n \log^2 n)\).

Implementation: sort-based and radix-based

In Python the fastest version packs each pair into one integer and lets the C sort do the work; Timsort also benefits because the previous round's order is already sorted by the first key. The \(O(n\log n)\) version replaces each sort by two counting-sort passes; on cyclic shifts, sorting by the second key is free (shift the previous order by \(k\)), so one stable counting sort by the first key suffices. Fewer operations, but all of them in Python bytecode.

def suffix_array(s):
    """Prefix doubling with integer keys and list.sort: O(n log^2 n) worst case.
    s: str, bytes, or a list of ints."""
    n = len(s)
    codes = [ord(c) for c in s] if isinstance(s, str) else list(s)
    alpha = {c: r for r, c in enumerate(sorted(set(codes)))}
    rank = [alpha[c] for c in codes]                # dense ranks 0..n-1
    sa = sorted(range(n), key=rank.__getitem__)
    k = 1
    while n and rank[sa[-1]] < n - 1:
        key = [rank[i] * (n + 1) + (rank[i + k] + 1 if i + k < n else 0) for i in range(n)]
        sa.sort(key=key.__getitem__)
        new = [0] * n
        for j in range(1, n):
            new[sa[j]] = new[sa[j - 1]] + (key[sa[j]] != key[sa[j - 1]])
        rank = new
        k *= 2
    return sa

def suffix_array_radix(s):
    """Cyclic shifts of s + sentinel, counting sort per round: O(n log n)."""
    codes = list(s) if isinstance(s, (bytes, bytearray)) else [ord(c) for c in s]
    a = [x + 1 for x in codes] + [0]                # 0 = sentinel, below every char
    n = len(a)
    m = max(a) + 1
    cnt = [0] * m
    for x in a:
        cnt[x] += 1
    for i in range(1, m):
        cnt[i] += cnt[i - 1]
    p = [0] * n
    for i in range(n - 1, -1, -1):
        cnt[a[i]] -= 1
        p[cnt[a[i]]] = i
    c = [0] * n
    for i in range(1, n):
        c[p[i]] = c[p[i - 1]] + (a[p[i]] != a[p[i - 1]])
    k = 1
    while k < n and c[p[-1]] < n - 1:
        pn = [(x - k) % n for x in p]               # already ordered by the second half
        cnt = [0] * (c[p[-1]] + 1)
        for x in c:
            cnt[x] += 1
        for i in range(1, len(cnt)):
            cnt[i] += cnt[i - 1]
        for x in reversed(pn):                      # stable counting sort by the first half
            cnt[c[x]] -= 1
            p[cnt[c[x]]] = x
        cn = [0] * n
        for i in range(1, n):
            cur, prev = p[i], p[i - 1]
            cn[cur] = cn[prev] + (c[cur] != c[prev] or c[(cur + k) % n] != c[(prev + k) % n])
        c = cn
        k *= 2
    return p[1:]                                    # drop the sentinel's suffix

def kasai(s, sa):
    """lcp[i] = LCP of suffixes sa[i-1] and sa[i]; lcp[0] = 0. O(n)."""
    n = len(s)
    rank = [0] * n
    for i, p in enumerate(sa):
        rank[p] = i
    lcp, h = [0] * n, 0
    for i in range(n):                              # suffixes in text order, not sorted order
        if rank[i]:
            j = sa[rank[i] - 1]
            while i + h < n and j + h < n and s[i + h] == s[j + h]:
                h += 1
            lcp[rank[i]] = h
            if h:
                h -= 1                              # suffix i+1 keeps at least h-1
        else:
            h = 0
    return lcp

Stress all three against sorted(range(n), key=lambda i: s[i:]) and a brute-force LCP on random strings over {a, b} (long repeats) and on "a" * n (the most rounds).

Kasai's algorithm and its proof

Proof · \(h \ge h_{\text{prev}} - 1\)

Process suffixes in text order and let \(h_i\) be the LCP of suffix \(i\) with its predecessor \(j\) in sorted order. If \(h_i > 0\), then \(s[j:] < s[i:]\) share their first character, so dropping it gives \(s[j+1:] < s[i+1:]\) with LCP \(h_i - 1\). The predecessor \(j'\) of \(s[i+1:]\) in sorted order lies between them or equals \(s[j+1:]\), and any string sorted between two strings shares their common prefix. Hence \(h_{i+1} = \text{LCP}(s[j':], s[i+1:]) \ge h_i - 1\).

Cost: starting each comparison at \(h - 1\) instead of 0, \(h\) decreases by at most 1 per step (\(\le n\) total) and never exceeds \(n\), so the total number of increments is at most \(2n\): \(O(n)\).

A sorted dictionary of all substrings

Every substring is a prefix of some suffix. Walk sa in order: suffix sa[i] contributes the prefixes of lengths lcp[i]+1 .. n-sa[i], and the shorter ones were already contributed by its predecessor. So the distinct substrings in lexicographic order are exactly "for each \(i\), the prefixes of s[sa[i]:] longer than lcp[i]", and there are \(\frac{n(n+1)}{2} - \sum \text{lcp}\) of them. Every application in L45 is a scan of this picture.

Python reality check

Measured on CPython 3.12 for \(n = 2\cdot10^5\): suffix_array took 1.15 s on random letters and 3.64 s on "a" * n (the maximum number of rounds); suffix_array_radix took 1.56 s and 4.73 s; kasai 0.5 s and 0.2 s. What breaks
  • Packed keys that collide: rank * (n+1) + second needs every rank and second key below \(n + 1\); raw character codes (up to 255) violate this for short strings. Compress characters to dense ranks first.
  • Missing sentinel semantics: a suffix that ends inside the window must sort first; use \(-1\) (or a 0 sentinel) for "past the end", never a wrap-around on non-cyclic arrays.
  • Kasai in sorted order instead of text order: the \(h - 1\) carry-over is invalid and the runtime becomes quadratic.
  • Off-by-one LCP convention: is lcp[i] between sa[i-1] and sa[i], or sa[i] and sa[i+1]? Pick one and comment it.
  • The naive oracle on big inputs: \(n^2\) memory from the slice keys; keep it to \(n \le 2000\).

Repeats, and two strings at once

The longest substring occurring twice is a common prefix of two suffixes, and the longest common prefix of any two suffixes is achieved by some adjacent pair, so it is \(\max \text{lcp}\). For the longest common substring of \(s\) and \(t\), build one suffix array of \(u = s\,\#\,t\) with a separator \(\#\) occurring in neither string. Label each suffix by origin (start \(< |s|\) or not). An answer is a common prefix of an \(s\)-suffix and a \(t\)-suffix; it cannot run through \(\#\), because the \(t\)-suffix contains no \(\#\). Between any such pair in sorted order the origin flips somewhere, and the adjacent pair at the flip has LCP at least the pair's, so scanning adjacent pairs with different origins finds the maximum. One separator per extra string extends this to \(k\) strings with a sliding window over sa.

from bisect import bisect_left, bisect_right
from itertools import accumulate
# suffix_array and kasai from L44

def longest_common_substring(s, t):
    u = s + "\x01" + t                          # "\x01" must occur in neither string
    sa = suffix_array(u)
    lcp = kasai(u, sa)
    best, pos, n1 = 0, 0, len(s)
    for i in range(1, len(u)):
        if (sa[i] < n1) != (sa[i - 1] < n1) and lcp[i] > best:
            best, pos = lcp[i], sa[i]
    return u[pos:pos + best]

def occurrences(s, sa, p):                      # start positions of p, O(|p| log n)
    key = lambda i: s[i:i + len(p)]
    lo, hi = bisect_left(sa, p, key=key), bisect_right(sa, p, key=key)
    return sorted(sa[lo:hi])

def substring_distribution(s):                  # CSES: distinct substrings of each length
    n = len(s)
    sa = suffix_array(s); lcp = kasai(s, sa)
    d = [0] * (n + 2)
    for i, p in enumerate(sa):                  # sa[i] adds lengths lcp[i]+1 .. n-p
        d[lcp[i] + 1] += 1
        d[n - p + 1] -= 1
    return list(accumulate(d))[1:n + 1]

Pattern search: suffixes starting with \(p\) form one contiguous block of sa, so two binary searches find it; bisect with key= (Python 3.10+) compares length-\(|p|\) slices. Count = block size, positions = the block.

The \(k\)-th substring, with and without repeats

Distinct (CSES — Substring Order I): walk sa, each suffix adding n - sa[i] - lcp[i] substrings in order (L44). Counted with multiplicity (CSES — Substring Order II) needs a descent. Keep the current prefix \(P\) of length \(L\) and the block sa[lo:hi] of suffixes that start with it. In sorted order with repeats, the \(hi - lo\) copies of \(P\) come first; then the extensions, grouped by the next character. With prefix sums of suffix lengths, the number of substrings longer than \(L\) inside sa[lo:x] is \(\text{PS}[x] - \text{PS}[lo] - L(x - lo)\), which increases with \(x\), so one binary search finds the suffix where \(k\) falls, and two more find its character group. Each step extends \(P\) by one character: \(O(|\text{answer}| \log n)\).

def kth_with_repeats(s, k):                     # CSES Substring Order II, 1-indexed
    n, sa = len(s), suffix_array(s)
    PS = [0] + list(accumulate(n - p for p in sa))
    lo, hi, L = 0, n, 0
    while True:
        if L:
            if k <= hi - lo:
                return s[sa[lo]:sa[lo] + L]
            k -= hi - lo
            if sa[lo] + L == n:                 # the suffix equal to P sorts first; it cannot grow
                lo += 1
        base = PS[lo] - L * lo
        cum = lambda x: PS[x] - L * x - base    # substrings longer than L in sa[lo:x]
        x = lo + bisect_left(range(lo, hi + 1), k, key=cum)
        c = s[sa[x - 1] + L]
        nxt = lambda i: s[sa[i] + L]
        g_lo = lo + bisect_left(range(lo, hi), c, key=nxt)
        g_hi = lo + bisect_right(range(lo, hi), c, key=nxt)
        k -= cum(g_lo)
        lo, hi, L = g_lo, g_hi, L + 1

LCP of arbitrary suffixes: RMQ on the LCP array

Theorem · LCP is a range minimum

For suffixes \(a \ne b\) with ranks \(x < y\), \(\text{LCP}(a, b) = \min(\text{lcp}[x+1..y])\). Proof: every suffix sorted between them starts with their common prefix \(w\), so each adjacent LCP in the range is \(\ge |w|\). Conversely, if all adjacent LCPs were \(> |w|\), all suffixes in the range, including \(a\) and \(b\), would share the character after \(w\), contradicting maximality of \(w\).

A sparse table over lcp (built once, \(O(n\log n)\)) answers each minimum in \(O(1)\); the structure itself is L103's. This is the bridge from strings to range-query structures: comparing \(s[i:]\) and \(s[j:]\) quickly ("longest common extension") makes many hashing solutions deterministic.

Suffix automaton and suffix tree

The suffix tree is the compressed trie of all suffixes (L41): \(O(n)\) nodes, built online by Ukkonen's algorithm, and its leaves read left to right are the suffix array. The suffix automaton is the smallest DFA accepting exactly the suffixes of \(s\); every substring is a path from the start. It has at most \(2n - 1\) states and \(3n - 4\) transitions (for \(n \ge 3\)), is built online one character at a time in amortised \(O(n)\) (constant alphabet), and its suffix links form the suffix tree of the reversed string. What it adds: online appends, the number of distinct substrings as \(\sum_v (\text{len}(v) - \text{len}(\text{link}(v)))\), occurrence counts for every distinct substring by propagating along links, and the shortest non-occurring string. The construction is short enough to keep in the library:

def suffix_automaton(s):
    nxt, link, length, last = [{}], [-1], [0], 0
    for ch in s:
        cur = len(length)
        nxt.append({}); length.append(length[last] + 1); link.append(0)
        p = last
        while p != -1 and ch not in nxt[p]:
            nxt[p][ch] = cur
            p = link[p]
        if p != -1:
            q = nxt[p][ch]
            if length[p] + 1 == length[q]:
                link[cur] = q
            else:                               # split q: a clone with the shorter length
                clone = len(length)
                nxt.append(dict(nxt[q])); length.append(length[p] + 1); link.append(link[q])
                while p != -1 and nxt[p].get(ch) == q:
                    nxt[p][ch] = clone
                    p = link[p]
                link[q] = link[cur] = clone
        last = cur
    return nxt, link, length

def distinct_substrings(s):
    nxt, link, length = suffix_automaton(s)
    return sum(length[v] - length[link[v]] for v in range(1, len(length)))

The "which string tool?" decision tree

Editorial

P1 (hashing + binary search). If a substring of length \(L\) occurs \(k\) times, so does its length-\(L-1\) prefix, so the predicate is monotone; the answer is at most \(n - k + 1\). For a candidate \(L\), count window hashes in a dict and stop at the first count reaching \(k\). \(O(n \log n)\) expected, with \(2^{61}-1\) and a random base (a \(10^9\) modulus would merge distinct windows, L37).

from itertools import accumulate

def p1(s, k):
    H = Hashing(s)
    h, pw, M = H.h, H.p, H.M
    def ok(L):
        cnt = {}
        for i in range(len(s) - L + 1):
            x = (h[i + L] - h[i] * pw[L]) % M
            c = cnt.get(x, 0) + 1
            if c >= k:
                return True
            cnt[x] = c
        return False
    lo, hi = 0, len(s) - k + 1                  # invariant: lo works (0 always does)
    while lo < hi:
        mid = (lo + hi + 1) // 2
        if ok(mid):
            lo = mid
        else:
            hi = mid - 1
    return lo

P2 (prefix function). The prefix-suffixes are \(n\) and the border chain \(\pi[n-1], \pi[\pi[n-1]-1], \dots\); their occurrence counts come from pushing counts down the chain (L38's prefix_occurrences). \(O(n)\).

def p2(s):
    pi, cnt = prefix_function(s), prefix_occurrences(s)
    out, b = [], len(s)
    while b:
        out.append((b, cnt[b]))
        b = pi[b - 1]
    return out[::-1]

P3 (binary trie). Subarray XOR is \(P_r \oplus P_l\) for prefix XORs, so for each \(r\) count earlier prefixes \(y\) with \(P_r \oplus y < k\): count_less, then insert \(P_r\). Insert \(P_0 = 0\) first. \(O(nB)\).

def p3(a, k, B=30):
    t, pre, total = BinaryTrie(B), 0, 0
    t.add(0)
    for x in a:
        pre ^= x
        total += t.count_less(pre, k)
        t.add(pre)
    return total

P4 (Manacher). Split at a cut \(e\): the best answer is the longest palindrome inside \(s[0..e]\) plus the longest inside \(s[e+1..]\), maximised over \(e\). The longest palindrome ending at each position comes from the radii: in Manacher's string \(t\), letter \(s_e\) sits at \(E = 2e + 1\), and a centre \(j \le E\) has a palindrome ending at \(E\) iff \(j + p[j] - 1 \ge E\), of length \(E - j + 1\). The leftmost such centre gives the longest, and a centre that cannot reach \(E\) cannot reach anything later, so one pointer sweeps all centres once: \(O(n)\). Run it on the reversed string for "longest starting at", then take prefix and suffix maxima.

def longest_ending_at(s):
    p, res, j = manacher(s), [0] * len(s), 0
    for e in range(len(s)):
        E = 2 * e + 1                           # index of s[e] in Manacher's t
        while j + p[j] - 1 < E:                 # centre j can no longer reach
            j += 1
        res[e] = E - j + 1
    return res

def p4(s):
    left = list(accumulate(longest_ending_at(s), max))
    start = longest_ending_at(s[::-1])[::-1]    # longest palindrome starting at each index
    right = list(accumulate(start[::-1], max))[::-1]
    return max(left[e] + right[e + 1] for e in range(len(s) - 1))

P5 (suffix array). A substring occurring at least twice is a common prefix of two adjacent suffixes in sorted order, and its occurrences form one contiguous block. Count it at the first adjacent pair of its block, where the LCP rises: position \(i\) contributes the lengths in \((\text{lcp}[i-1], \text{lcp}[i]]\), so the answer is \(\sum_i \max(0, \text{lcp}[i] - \text{lcp}[i-1])\). \(O(n\log^2 n)\) for the build, \(O(n)\) after.

def p5(s):
    lcp = kasai(s, suffix_array(s))
    return sum(max(0, lcp[i] - lcp[i - 1]) for i in range(1, len(s)))

Common bugs, and how to catch them

What breaks
  • Mod arithmetic: a fixed base (hackable), a \(10^9\) modulus with a set of \(10^5\) hashes (collides), or a missing % M after subtraction in a port to another language.
  • Sentinels and separators: a separator that occurs in the input, or the same separator used twice when joining several strings.
  • Half-open vs inclusive: get(l, r) is \([l, r)\); the palindrome checker took inclusive \([l, r]\); Manacher's radius is a length in \(s\). Write the convention next to every helper.
  • P1's upper bound \(n - k + 1\), and the case \(k = 1\) (answer \(n\)).
  • P3 without \(P_0\): subarrays starting at index 0 vanish.
  • P4's cut: a palindrome may not cross the cut; prefix/suffix maxima enforce it.
  • Verification: every string function above has a brute force in three lines of slicing. Not running it is the most expensive bug of all.
Algorithm · the stress loop for string code
  1. Generator: random length 1–12 over "ab" (and sometimes "abc"), plus parameters (\(k\), arrays).
  2. Brute force from definitions: enumerate s[i:j], count with str.count-free loops (it does not count overlaps), test palindromes with t == t[::-1].
  3. Compare on thousands of cases; on a mismatch, shrink the input and print both outputs (L10).
