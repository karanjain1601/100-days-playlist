Computational Geometry

Seven lessons of computational geometry done the contest way: exact integer predicates first, constructions only when they must be printed, and every degenerate case written down before the code. It reuses the sorting, sweep-line and segment-tree machinery of Phases 1, 2 and 7 and the number theory of Phase 8 (gcd for lattice points), and hands the randomised-incremental pattern on to Phase 10.

By the end of this phase you can

  • Build every geometric predicate from orient(a, b, c) in exact integer arithmetic, and say when floats, EPS or Fraction are genuinely needed.
  • Sort points by angle with a comparator that survives duplicates, collinear points and the 180° trap.
  • Decide segment intersection in every degenerate case, and compute intersection points, distances and circle intersections only as constructions.
  • Compute polygon area, centroid, point location (ray casting, winding number, \(O(\log n)\) for convex) and lattice-point counts with Pick's theorem.
  • Build a convex hull with the collinear rule the statement asks for, then use rotating calipers, closest pair and the minimum enclosing circle on top of it.
  • Solve rectangle-union area with a covered-length segment tree unaided, and use half-plane intersection and Minkowski sums where they apply.
  • Score 3+/5 on a geometry contest with a stress-tested geometry.py and a plotting habit for debugging.

Geometry I: Points, Vectors, Cross Products, Orientation

55m video

Geometry problems are lost to precision far more often than to logic. Rule one: decide every predicate (left or right, inside or outside, intersecting or not) with exact integer arithmetic, and only compute coordinates when the output demands them. Almost all of that integer arithmetic is one primitive, the 2D cross product, wrapped as orient(a, b, c).

Integers first

A Python float has a 53-bit mantissa, so integers are exact only up to \(2^{53} \approx 9\cdot10^{15}\). With coordinates up to \(10^9\), a cross product reaches \(\approx 4\cdot10^{18}\). As a float, the last few digits are already gone, and a "collinear" verdict is a coin flip. Python ints are exact and unbounded, so integer predicates cannot overflow, which is a genuine advantage over C++. The rule is predicates before constructions. Every yes/no question about integer points is a sign of a polynomial in the coordinates, so compute that polynomial in ints. Intersection points, distances and angles are constructions: compute them last, and only if they are printed.

Representation. Tuples (x, y) are the fastest to create and index. A Point class with operator overloading reads well but adds a method call to every +. complex numbers are fast ((a.conjugate() * b).imag is the cross product) but floats: fine for constructions, never for predicates. In hot loops, separate xs and ys lists are faster still.

Vectors and the dot product

A point minus a point is a vector. For vectors \(a, b\): \(a \cdot b = a_x b_x + a_y b_y = |a||b|\cos\theta\). Its sign classifies the angle: positive is acute, zero is perpendicular, negative is obtuse. That is how you ask "is the projection of \(p\) onto segment \(ab\) beyond \(b\)?" without any trigonometry. The projection length of \(b\) onto \(a\) is \(a \cdot b / |a|\). The squared norm \(|a|^2 = a \cdot a\) stays an integer. Never take a square root to compare lengths: \(|a| < |b| \iff a\cdot a < b \cdot b\).

The cross product

Definition

\(a \times b = a_x b_y - a_y b_x\), the \(z\)-component of the 3D cross product, equal to \(\det\begin{pmatrix} a_x & b_x \\ a_y & b_y\end{pmatrix}\). Then \(\text{orient}(a, b, c) = (b - a) \times (c - a)\).

Theorem · What the cross product tells you

\(a \times b = |a||b|\sin\theta\), where \(\theta\) is the signed angle from \(a\) to \(b\) (counter-clockwise positive). Hence:

  1. Orientation: \(a \times b > 0\) iff \(b\) is counter-clockwise from \(a\) (within \(180°\)). It is \(< 0\) for clockwise and \(= 0\) iff they are parallel or antiparallel.
  2. Area: \(|a \times b|\) is the area of the parallelogram on \(a, b\), so a triangle \(abc\) has area \(|\text{orient}(a,b,c)|/2\).
  3. Sine: \(\sin\theta = (a\times b)/(|a||b|)\), and together with the dot product it gives \(\theta = \operatorname{atan2}(a \times b,\ a \cdot b)\).
Proof

Write \(a = |a|(\cos\alpha, \sin\alpha)\) and \(b = |b|(\cos\beta, \sin\beta)\). Then \(a_x b_y - a_y b_x = |a||b|(\cos\alpha\sin\beta - \sin\alpha\cos\beta) = |a||b|\sin(\beta - \alpha)\). The parallelogram has base \(|a|\) and height \(|b||\sin\theta|\).

The geometry header

from functools import cmp_to_key
from fractions import Fraction

def sub(a, b):
    return (a[0] - b[0], a[1] - b[1])

def dot(a, b):
    return a[0] * b[0] + a[1] * b[1]

def cross(a, b):
    return a[0] * b[1] - a[1] * b[0]

def dist2(a, b):
    return (a[0] - b[0]) ** 2 + (a[1] - b[1]) ** 2

def orient(a, b, c):
    """> 0: c is left of a->b (counter-clockwise turn); < 0: right; 0: collinear. Exact on ints."""
    return (b[0] - a[0]) * (c[1] - a[1]) - (b[1] - a[1]) * (c[0] - a[0])

def sign(x, eps=0):
    """eps = 0 for integer (or Fraction) inputs; a tuned eps only when floats are unavoidable."""
    return (x > eps) - (x < -eps)

def half(v):
    """0 for directions with angle in [0, pi), 1 for [pi, 2pi). v must not be (0, 0)."""
    return 0 if v[1] > 0 or (v[1] == 0 and v[0] > 0) else 1

def cmp_angle(a, b):
    """A total order on nonzero vectors by polar angle; equal directions: shorter first."""
    ha, hb = half(a), half(b)
    if ha != hb:
        return ha - hb
    c = cross(a, b)
    if c:
        return -1 if c > 0 else 1
    return dot(a, a) - dot(b, b)

def sort_by_angle(points, o=(0, 0)):
    """Points sorted counter-clockwise around o, starting from the +x direction.
    Copies of o itself (no angle) come first."""
    at_o = [p for p in points if p == o]
    vs = [(x - o[0], y - o[1]) for x, y in points if (x, y) != o]
    vs.sort(key=cmp_to_key(cmp_angle))
    return at_o + [(x + o[0], y + o[1]) for x, y in vs]

Comparing angles without atan2

The classic angular-sort bug is a comparator of "\(a\) before \(b\) iff \(a \times b > 0\)". It is not a strict weak ordering. Take three vectors 120° apart: each is counter-clockwise of the previous one, so the "order" is a cycle, and the sort returns garbage without raising. The cross product only compares angles correctly within a half-plane. The fix: first split by half(v), which puts angles in \([0, \pi)\) before \([\pi, 2\pi)\), and compare with the cross product only inside a half. Then break exact ties (same direction) by length, so duplicates and collinear points sort deterministically. The zero vector has no angle, so remove it first. The price of exactness is speed. In one CPython run, cmp_to_key sorted \(2\cdot10^5\) points in 2.6 s against 0.11 s for an atan2 key. Prefer the key whenever the note below says it is safe.

When is atan2 safe?

Two distinct integer directions with coordinates \(|x|, |y| \le C\) differ in angle by at least about \(1/(2C^2)\), since \(|a \times b| \ge 1\) and \(|a||b| \le 2C^2\). A double resolves angles near \(\pi\) to about \(4\cdot10^{-16}\). So key=lambda v: atan2(v[1], v[0]) is reliable for \(C\) up to roughly \(10^6\) and unreliable at \(C = 10^9\). Even below that, exact ties (collinear points) need the exact cross-product tie-break.

EPS discipline and exact rationals

  • Integer inputs, integer predicates: no EPS at all. The smallest nonzero cross product is 1.
  • Float inputs (or float constructions such as circle intersections): sign(x, eps) everywhere, never x == 0. EPS must exceed the accumulated error and be smaller than the smallest meaningful nonzero value. With coordinates near \(10^4\), cross products near \(10^8\) carry absolute errors near \(10^{-8}\), so \(10^{-9}\) is too small there. Scale EPS with the magnitudes involved.
  • Fraction: exact rational geometry, for line intersections (L129) and exact centroids. It ran about 30× slower than ints in my test, so use it on the few constructed points, not in an \(O(n^2)\) loop.

Problems

  • CSES — Point Location Test: for each test, the sign of orient(p1, p2, p3) gives LEFT, RIGHT or TOUCH. Coordinates up to \(10^9\) make products near \(10^{18}\), which Python ints handle exactly. Read all tests with one bulk read.
  • LeetCode 1266 (Minimum Time Visiting All Points): diagonal moves make the per-leg cost the Chebyshev distance \(\max(|dx|, |dy|)\). Sum over consecutive pairs.
  • LeetCode 149 (Max Points on a Line): for each anchor \(i\), normalise every direction \(p_j - p_i\) by dividing by \(\gcd(|dx|, |dy|)\) and fixing the sign (make \(dx > 0\), or \(dx = 0, dy > 0\)). Count the directions in a dict, \(O(n^2)\) and exact. Slopes as floats are the classic wrong answer here.
  • Orientation warm-ups: do segments \(ab\) and \(cd\) properly cross (signs of four orients, L129)? Is quadrilateral \(abcd\) convex (all four consecutive orients share a sign)? Is triangle \(abc\) listed counter-clockwise?
What breaks
  • Float cross products on coordinates of \(10^9\): collinear points reported as left or right turns.
  • The cross-only angle comparator: non-transitive across 180°, so the output order is nondeterministic and wrong.
  • Zero vectors in an angular sort: half((0, 0)) is meaningless. Filter duplicates of the origin first.
  • x == 0 on floats, or one global EPS of \(10^{-9}\) used at every scale.
  • Mixing orientation conventions: decide once that \(> 0\) means counter-clockwise, in a y-up coordinate system. Screen coordinates (y down) flip it.

  3. Stress-test sort_by_angle against an atan2 sort on random points with \(|x|,|y| \le 50\), including duplicates and collinear points, and check that equal directions come out nearest-first.

Geometry II: Lines, Segments, Intersections, Distances

55m video

Segment intersection is where geometry bugs live: crossing, touching at an endpoint, overlapping along a common line, parallel, or one segment reduced to a point. List every degenerate case before writing code, decide intersection with four integer orientations, and compute the intersection point (a rational number) only when you must print it.

Three ways to write a line

  • Two points \(a, b\): best for predicates. Everything is orient(a, b, ·) (L128).
  • Implicit \(Ax + By + C = 0\), with \(A = y_1 - y_2\), \(B = x_2 - x_1\), \(C = -(Ax_1 + By_1)\). These are integers for integer points. Divide by \(\gcd(A, B, C)\) and fix the sign (first nonzero of \(A, B\) positive) to get a canonical key for hashing lines, as in "how many distinct lines?" or LeetCode 149.
  • Parametric \(p(t) = a + t\,(b - a)\): best for constructions. The segment is \(t \in [0, 1]\), projections give a \(t\), and clamping \(t\) gives the closest point on the segment.

Segment intersection, exhaustively

Theorem · The four-orientation test

Let \(d_1 = \text{orient}(c, d, a)\), \(d_2 = \text{orient}(c, d, b)\), \(d_3 = \text{orient}(a, b, c)\), \(d_4 = \text{orient}(a, b, d)\). Closed segments \(ab\) and \(cd\) intersect iff either (i) \(d_1, d_2\) have strictly opposite signs and \(d_3, d_4\) have strictly opposite signs (a proper crossing), or (ii) some \(d_i = 0\) and the corresponding point lies within the bounding box of the other segment (touching or overlap).

Proof

(i) Opposite signs of \(d_1, d_2\) mean \(a\) and \(b\) lie strictly on opposite sides of line \(cd\), so segment \(ab\) crosses that line at one interior point. Symmetrically, \(cd\) crosses line \(ab\). Two non-parallel lines meet once, so that point is on both segments. (ii) If no strict straddle exists, any common point must be an endpoint of one segment lying on the other. Such an endpoint has orientation 0 with respect to the other segment's line, and on that line, lying on the segment is equivalent to lying in its bounding box. Zero-length segments fall out for free: if \(c = d\), every orientation against \(cd\) is 0, and the box test reduces to equality of points.

def on_segment(a, b, p):
    """Assuming p is collinear with a, b: is p within the closed segment?"""
    return (min(a[0], b[0]) <= p[0] <= max(a[0], b[0])
            and min(a[1], b[1]) <= p[1] <= max(a[1], b[1]))

def segments_intersect(a, b, c, d):
    """Closed segments ab and cd share a point. Exact for integers; handles every degenerate case.
    Uses orient from L128."""
    d1, d2 = orient(c, d, a), orient(c, d, b)
    d3, d4 = orient(a, b, c), orient(a, b, d)
    if ((d1 > 0 and d2 < 0) or (d1 < 0 and d2 > 0)) and ((d3 > 0 and d4 < 0) or (d3 < 0 and d4 > 0)):
        return True                                    # proper crossing
    return ((d1 == 0 and on_segment(c, d, a)) or (d2 == 0 and on_segment(c, d, b))
            or (d3 == 0 and on_segment(a, b, c)) or (d4 == 0 and on_segment(a, b, d)))

def test_segments():
    T = segments_intersect
    assert T((0, 0), (4, 4), (0, 4), (4, 0))           # proper crossing
    assert T((0, 0), (4, 0), (2, 0), (2, 3))           # endpoint on the other's interior
    assert T((0, 0), (2, 0), (2, 0), (5, 1))           # shared endpoint
    assert T((0, 0), (4, 0), (2, 0), (6, 0))           # collinear overlap
    assert not T((0, 0), (1, 0), (2, 0), (3, 0))       # collinear, disjoint
    assert not T((0, 0), (2, 2), (3, 3), (5, 5))       # collinear diagonal, disjoint
    assert not T((0, 0), (4, 0), (0, 1), (4, 1))       # parallel
    assert not T((0, 0), (1, 1), (3, 0), (2, 1))       # lines meet outside both segments
    assert T((1, 1), (1, 1), (0, 0), (2, 2))           # point on a segment
    assert not T((1, 1), (1, 1), (0, 0), (2, 3))       # point off a segment
    assert T((1, 1), (1, 1), (1, 1), (1, 1))           # equal points
    assert not T((1, 1), (1, 1), (2, 2), (2, 2))       # distinct points

The intersection point

For lines \(a + t r\) and \(c + u s\) with \(r = b - a\), \(s = d - c\), Cramer's rule on \(a + tr = c + us\) gives

$$t = \frac{(c - a) \times s}{r \times s}, \qquad u = \frac{(c - a) \times r}{r \times s}.$$

If \(r \times s = 0\) the lines are parallel, and they coincide iff also \((c - a) \times r = 0\). The point is rational with denominator \(r \times s\). So the test stays integer, and only the printed point needs Fraction or one final division.

from fractions import Fraction

def line_intersection(a, b, c, d):
    """Lines ab and cd: an exact point (Fractions), 'parallel', or 'same'."""
    r, s, ca = sub(b, a), sub(d, c), sub(c, a)
    den = cross(r, s)
    if den == 0:
        return "same" if cross(ca, r) == 0 else "parallel"
    t = Fraction(cross(ca, s), den)
    return (a[0] + t * r[0], a[1] + t * r[1])

Distances, projections, reflections

  • Point to line \(ab\): \(|\text{orient}(a, b, p)| / |b - a|\), the parallelogram area divided by the base.
  • Foot of the perpendicular: \(t = (p - a)\cdot(b - a) / |b-a|^2\) and \(f = a + t(b - a)\). Reflection of \(p\): \(2f - p\).
  • Point to segment: the same \(t\), clamped to \([0, 1]\). If \(t \le 0\) the nearest point is \(a\), if \(t \ge 1\) it is \(b\), otherwise the foot. Segment to segment: 0 if they intersect, else the minimum of the four endpoint-to-segment distances.
def point_segment_dist2(p, a, b):
    """Exact squared distance from p to segment ab (a Fraction; take sqrt only to print)."""
    ab, ap = sub(b, a), sub(p, a)
    L = dot(ab, ab)
    t = dot(ap, ab)                                    # the projection parameter is t / L
    if L == 0 or t <= 0:
        return Fraction(dot(ap, ap))                   # nearest point is a
    if t >= L:
        return Fraction(dist2(p, b))                   # nearest point is b
    c = cross(ab, ap)
    return Fraction(c * c, L)                          # distance to the line: |cross| / sqrt(L)

Circles

Circle–line: with \(f\) the foot of the centre and \(\delta\) its distance, the points are \(f \pm \sqrt{r^2 - \delta^2}\,\hat u\). Decide 0, 1 or 2 by comparing \(\delta^2\) with \(r^2\) as rationals. Circle–circle: the chord's midpoint is \(a = (r_1^2 - r_2^2 + d^2)/(2d)\) from \(c_1\), with half-chord \(\sqrt{r_1^2 - a^2}\). The case analysis needs only \(d^2\) against \((r_1 \pm r_2)^2\), which is exact for integers. Tangents from \(p\) at distance \(D\) touch at \(\pm\arccos(r/D)\) from the direction centre → \(p\), with length \(\sqrt{D^2 - r^2}\).

import math

def circle_circle(c1, r1, c2, r2):
    """Intersection of two circles with integer data: list of 0-2 float points, None if identical."""
    dx, dy = c2[0] - c1[0], c2[1] - c1[1]
    d2 = dx * dx + dy * dy
    if d2 == 0:
        return None if r1 == r2 else []
    if d2 > (r1 + r2) ** 2 or d2 < (r1 - r2) ** 2:
        return []                                      # apart, or one strictly inside the other
    d = math.sqrt(d2)
    a = (r1 * r1 - r2 * r2 + d2) / (2 * d)
    mx, my = c1[0] + a * dx / d, c1[1] + a * dy / d
    if d2 == (r1 + r2) ** 2 or d2 == (r1 - r2) ** 2:
        return [(mx, my)]                              # tangent, decided exactly
    h = math.sqrt(max(r1 * r1 - a * a, 0.0))
    return [(mx - h * dy / d, my + h * dx / d), (mx + h * dy / d, my - h * dx / d)]

Collinearity and simple-polygon checks

Three points are collinear iff orient == 0. A closed chain \(p_0 \dots p_{n-1}\) is a simple polygon iff non-adjacent edges never intersect, and adjacent edges meet only at their shared vertex (they must not fold back collinearly). The pairwise check is \(O(n^2)\), which is fine to \(n \approx 2000\) in Python. The \(O(n \log n)\) sweep version (Shamos–Hoey) is in L133.

Problems

  • CSES — Line Segment Intersection: segments_intersect per test, with coordinates up to \(10^9\). This is exactly the degenerate-case suite.
  • LeetCode 836 (Rectangle Overlap): positive-area overlap iff \(\min(x_2, x_4) > \max(x_1, x_3)\) and the same for \(y\). Use strict inequalities, since touching edges do not count. 1229 (Meeting Scheduler, the 1D alternative framing): two pointers over sorted slots. The intersection is \([\max(\text{starts}), \min(\text{ends}))\), and you advance whichever slot ends first.
  • Intersection-counting warm-up: count intersecting pairs among \(n \le 2000\) segments, \(O(n^2)\) calls. Inline orient if it TLEs.
What breaks
  • Only testing the proper case: touching and collinear overlap answer NO, and that is WA on test 3.
  • Collinear check without the bounding box: segments on one line with a gap between them answer YES.
  • Bounding box on x only: vertical segments break it. Check both coordinates.
  • Computing the float intersection point to decide whether one exists: precision failures near endpoints. Decide with signs.
  • Zero-length segments in parametric code: a division by \(|b - a|^2 = 0\). Guard it (as point_segment_dist2 does).
  • math.sqrt of a slightly negative \(r^2 - a^2\): a ValueError. Clamp with max(·, 0), after deciding the case exactly.

Geometry III: Polygons

55m video

A polygon is a cyclic list of vertices, and nearly every question about it is a sum of cross products along that cycle: twice its area, its orientation, its centroid, how often it winds around a point. Keep everything as integers (twice the area is always an integer for lattice vertices) and the standard polygon predicates become exact.

Representation and the shoelace formula

Definition

A polygon is a vertex list \(p_0, \dots, p_{n-1}\) with edges \(p_i p_{i+1}\) (indices mod \(n\)). It is simple if non-adjacent edges never meet. It is convex if every interior angle is at most 180°, which for a simple polygon means every turn \(\text{orient}(p_i, p_{i+1}, p_{i+2})\) has the same sign (ignoring zeros). Its orientation is counter-clockwise or clockwise.

Theorem · Shoelace formula $$2A = \sum_{i=0}^{n-1} p_i \times p_{i+1} = \sum_{i} (x_i y_{i+1} - x_{i+1} y_i).$$

For a simple polygon, \(A\) is the area when the vertices are counter-clockwise and minus the area when they are clockwise. So the sign of the sum is the orientation.

Proof

\(\tfrac12\, p_i \times p_{i+1}\) is the signed area of the fan triangle \(O p_i p_{i+1}\), for an arbitrary origin \(O\). Fix a point \(x\) off all fan edges and count the fan triangles containing it, with sign \(+\) for counter-clockwise triangles and \(-\) for clockwise ones. That signed count equals the polygon's winding number around \(x\): 1 inside a counter-clockwise simple polygon and 0 outside. Integrating over the plane, the sum of the signed triangle areas is the polygon's area. With integer vertices every term is an integer, so \(2A\) is exact. Print \(2A\), or \(A\) as "\(k\)" or "\(k\).5".

Centroid. The centre of mass of the polygon region is

$$C_x = \frac{1}{6A}\sum_i (x_i + x_{i+1})(p_i \times p_{i+1}), \qquad C_y = \frac{1}{6A}\sum_i (y_i + y_{i+1})(p_i \times p_{i+1}).$$

This is the area-weighted average of the fan triangles' centroids. It differs from the vertex average: add many vertices along one edge and the vertex average drifts towards that edge, while the shape and its true centroid have not changed. Use Fraction to keep it exact.

Point in polygon

Boundary first. If orient(a, b, q) == 0 and \(q\) is in the bounding box of some edge \(ab\), the answer is BOUNDARY. That check is exact and removes every ambiguous case below. Ray casting: shoot a ray from \(q\) to the right and count the edge crossings. An odd count means inside. The vertex problem (the ray passes exactly through a vertex) is solved by the half-open rule: an edge counts only if exactly one endpoint is strictly above the ray, (a.y > q.y) != (b.y > q.y). A vertex touching the ray from above or below then counts 0 or 2 times, and a vertex the boundary passes through counts once. Horizontal edges never count. "Is the crossing to the right of \(q\)?" needs no division. The crossing's \(x\) minus \(q_x\) equals \(\text{orient}(a, b, q)/(b_y - a_y)\), so compare signs.

Winding number: sum \(+1\) for each edge crossing the ray upward with \(q\) strictly left of it, and \(-1\) for each downward crossing with \(q\) strictly right. It is nonzero iff \(q\) is inside, and it also works for self-intersecting polygons, where it counts how many times the boundary winds around \(q\). For simple polygons, ray parity and the winding number agree, which is the cross-check in the code below.

from math import gcd
from fractions import Fraction

def area2(poly):
    """Twice the signed area: > 0 counter-clockwise. Exact integer."""
    return sum(x1 * y2 - x2 * y1 for (x1, y1), (x2, y2) in zip(poly, poly[1:] + poly[:1]))

def centroid(poly):
    a2 = cx = cy = 0
    for (x1, y1), (x2, y2) in zip(poly, poly[1:] + poly[:1]):
        c = x1 * y2 - x2 * y1
        a2 += c
        cx += (x1 + x2) * c
        cy += (y1 + y2) * c
    return Fraction(cx, 3 * a2), Fraction(cy, 3 * a2)        # 6A = 3 * (2A)

def point_in_polygon(poly, q):
    """'BOUNDARY', 'INSIDE' or 'OUTSIDE' for a simple polygon (ray casting, half-open rule)."""
    inside = False
    for a, b in zip(poly, poly[1:] + poly[:1]):
        o = orient(a, b, q)
        if o == 0 and on_segment(a, b, q):                 # L128 / L129 primitives
            return "BOUNDARY"
        if (a[1] > q[1]) != (b[1] > q[1]):                 # edge straddles the ray's line
            if (o > 0) == (b[1] > a[1]):                     # crossing lies to the right of q
                inside = not inside
    return "INSIDE" if inside else "OUTSIDE"

def winding_number(poly, q):
    w = 0
    for a, b in zip(poly, poly[1:] + poly[:1]):
        if a[1] <= q[1]:
            if b[1] > q[1] and orient(a, b, q) > 0:
                w += 1                                       # upward edge, q on its left
        elif b[1] <= q[1] and orient(a, b, q) < 0:
            w -= 1                                           # downward edge, q on its right
    return w

Convex polygons: O(log n) location and convexity

For a strictly convex counter-clockwise polygon, fan it from \(p_0\). Binary search for the wedge \(p_0 p_i p_{i+1}\) whose angular range contains \(q\), using orient(p0, p_i, q) >= 0 as the monotone predicate, then test the single edge \(p_i p_{i+1}\). Answering \(10^5\) queries this way costs \(O(\log n)\) each instead of \(O(n)\). The edge cases are \(q\) on the two fan boundary rays and \(q = p_0\). Convexity check: all nonzero turns share a sign. That alone accepts a pentagram, so it assumes the polygon is simple, or else additionally requires the total turning to be exactly 360°.

def in_convex(poly, q):
    """poly strictly convex, counter-clockwise, n >= 3. O(log n)."""
    n, p0 = len(poly), poly[0]
    if orient(p0, poly[1], q) < 0 or orient(p0, poly[-1], q) > 0:
        return "OUTSIDE"
    lo, hi = 1, n - 1
    while hi - lo > 1:                                       # last i with orient(p0, p_i, q) >= 0
        mid = (lo + hi) // 2
        if orient(p0, poly[mid], q) >= 0:
            lo = mid
        else:
            hi = mid
    o = orient(poly[lo], poly[lo + 1], q)
    if o < 0:
        return "OUTSIDE"
    if o == 0 or (lo == 1 and orient(p0, poly[1], q) == 0) or (lo == n - 2 and orient(p0, poly[-1], q) == 0):
        return "BOUNDARY"
    return "INSIDE"

Pick's theorem and lattice points

Theorem · Pick (1899)

For a simple polygon with lattice vertices, \(A = I + \tfrac{B}{2} - 1\), where \(I\) counts interior lattice points and \(B\) counts boundary lattice points. Segment \((x_1,y_1)\)–\((x_2,y_2)\) contains \(\gcd(|x_2 - x_1|, |y_2 - y_1|) + 1\) lattice points, so \(B = \sum_{\text{edges}} \gcd(|dx|, |dy|)\) (L117).

So \(I = (2A - B + 2)/2\), all in integers, and instant even with coordinates near \(10^9\) where enumeration is hopeless.

def lattice_points(poly):
    """CSES Polygon Lattice Points: (interior, boundary)."""
    a2 = abs(area2(poly))
    b = sum(gcd(abs(x2 - x1), abs(y2 - y1)) for (x1, y1), (x2, y2) in zip(poly, poly[1:] + poly[:1]))
    return (a2 - b + 2) // 2, b

Cutting and triangulating

Cutting a convex polygon by a line (keep the part left of \(a \to b\)): walk the edges. Keep each vertex with \(\text{orient} \ge 0\), and wherever an edge \(pq\) changes sign, insert the point at parameter \(t = o_p/(o_p - o_q)\), since orientation is linear along the edge. This is Sutherland–Hodgman against one half-plane, \(O(n)\). Repeating it gives an \(O(nk)\) half-plane intersection, a useful brute force for L133. Triangulation by ear clipping: repeatedly cut off a convex vertex whose triangle contains no other vertex. It is \(O(n^2)\), and every simple polygon has at least two ears (Meisters' two-ears theorem).

Geometry IV: Convex Hull

55m video

After sorting the points, one orientation test per step builds the convex hull in \(O(n \log n)\): keep a stack, and pop while the last two points and the new one fail to turn left. Everything else in this lesson is what the statement decides for you (collinear points in or out) and what breaks on degenerate inputs.

The problem

Definition

The convex hull of a finite point set is the smallest convex polygon containing it. Its vertices are the extreme points: those not inside or on the boundary of the hull of the others. It appears directly ("smallest fence"), as a preprocessing step (diameter, width and enclosing rectangles in L132), and in disguise as the upper envelope of lines (the convex hull trick, L100).

Andrew's monotone chain

Algorithm · Monotone chain (Andrew 1979)
  1. Sort the points by \((x, y)\) and remove duplicates.
  2. Lower hull: scan left to right. Before pushing \(p\), pop while the stack has ≥ 2 points and orient(h[-2], h[-1], p) <= 0 (not a strict left turn).
  3. Upper hull: the same scan, right to left.
  4. Concatenate, dropping each chain's last point (it is the other chain's first). The result is counter-clockwise, starting at the lowest-leftmost point.
Theorem · Correctness and cost

After processing the points with \(x\)-order up to \(p\), the stack is exactly the lower hull of those points. Each point is pushed once and popped at most once, so after the \(O(n \log n)\) sort the scan is \(O(n)\).

Proof

The new point \(p\) is the rightmost so far, so it is on the lower hull of the prefix. A stack point \(h_{-1}\) stays on that hull iff the chain \(h_{-2}, h_{-1}, p\) turns strictly left. Otherwise \(h_{-1}\) lies on or above the segment \(h_{-2}p\), so it is not extreme and later points cannot rescue it, because they lie further right. Popping until the turn is left restores a convex chain, and every popped point is permanently non-extreme for the lower hull. Each push or pop is \(O(1)\).

def convex_hull(points, keep_collinear=False):
    """Counter-clockwise hull from the lowest-leftmost point.
    keep_collinear=True also returns points lying on hull edges (e.g. LeetCode 587)."""
    pts = sorted(set(points))
    if len(pts) <= 2:
        return pts
    if keep_collinear and all(orient(pts[0], pts[-1], p) == 0 for p in pts):
        return pts                                   # all collinear: the segment, every point once

    def chain(seq):
        h = []
        for p in seq:
            while len(h) >= 2:
                o = orient(h[-2], h[-1], p)
                if o < 0 or (o == 0 and not keep_collinear):
                    h.pop()
                else:
                    break
            h.append(p)
        return h

    lower = chain(pts)
    upper = chain(reversed(pts))
    return lower[:-1] + upper[:-1]

For all-collinear input the strict hull is its two endpoints, and the lenient one is every point in sorted order. Without the special case, the lenient version would list the interior points twice, once per chain.

Graham scan, the alternative

Pick the lowest (then leftmost) point \(p_0\). Sort the rest by angle around it with the exact comparator from L128, breaking ties by distance, then run the same stack with the same pop rule. It costs the same \(O(n \log n)\), but the angular sort is the fragile part, slower with cmp_to_key and full of tie cases. If collinear points must be kept, the points on the last ray from \(p_0\) must be visited farthest-first, so that tie group has to be reversed. Monotone chain avoids angles altogether, which is why it is the library version.

The collinear decision, and degenerate inputs

Popping on <= 0 removes points in the middle of hull edges and gives the minimal vertex set. Popping on < 0 keeps them. Neither is "correct": the problem statement decides. "Vertices of the hull" means strict. "All trees on the fence" (LeetCode 587) or "all points on the hull boundary" means lenient. A wrong choice is a WA on exactly the tests with collinear points, often a single test. Handle the degenerate inputs explicitly: \(n \le 2\); duplicates (removed by set); all points collinear; all points identical (one point remains).

Testing a hull

Check against a brute force on random small inputs, and also on adversarial ones: points on a few lines, on a small grid (many collinear triples), with duplicates, and all on one line. Assert that (1) the output is counter-clockwise and strictly convex (or only weakly, for the lenient flag); (2) every input point is inside or on it (L130's point_in_polygon); (3) every output point is an input point; (4) the strict vertex set equals the brute-force extreme set, where \(p\) is extreme iff it lies in no triangle and no segment of the other points.

Applications

  • Diameter (farthest pair): its endpoints are hull vertices. Rotating calipers then finds it in \(O(h)\) (L132).
  • Minimum-area or minimum-perimeter enclosing rectangle: one side lies along a hull edge, so try each edge with calipers (L132).
  • Is a polygon convex? Its lenient hull has as many points as it has vertices, or use the turn-sign test from L130.
  • Hull of lines (CHT). \(\max_i (m_i x + b_i) = \max_i (m_i, b_i)\cdot(x, 1)\) is the extreme point of the set \(\{(m_i, b_i)\}\) in direction \((x, 1)\), which lies on its upper hull. The convex hull trick of L100 is this hull, built by the same monotone stack when slopes arrive sorted, and queried by binary search or a moving pointer.
  • Minkowski sum preview: the sum of two convex polygons is a convex polygon whose edges are both polygons' edges merged by angle (L133).

Dynamic hulls. If points arrive in arbitrary order and queries interleave, keep the upper hull in a balanced ordered structure keyed by \(x\). On insert, check whether the point is below the hull, and if not, delete neighbours that stop being convex. That is \(O(\log n)\) amortised, and it is exactly the "dynamic CHT" / Li Chao alternative. In Python without a sorted container, Li Chao trees (L100) are usually simpler.

Problems

  • CSES — Convex Hull: print the hull's points. The statement asks for every point on the boundary, so read it and use the matching flag (collinear boundary points are included there). \(n \le 2\cdot10^5\): the sort dominates, and the scan is fast in CPython.
  • LeetCode 587 (Erect the Fence): keep_collinear=True, including the all-collinear case.
  • Classic applications: hull perimeter (sum of edge lengths, one sqrt per edge), hull area (area2), and "farthest pair" via L132.
What breaks
  • The wrong collinear flag for the statement: WA on collinear tests only.
  • Lenient hull on all-collinear input without the special case: interior points appear twice.
  • Duplicates not removed: zero-length edges, and an orient of 0 popping or keeping points unpredictably.
  • Float coordinates with orient <= 0: near-collinear points flicker in and out. Use an EPS, or scale to integers when the input has fixed decimals.
  • Graham scan with a cross-only comparator: the non-transitive sort from L128.

Geometry V: Rotating Calipers, Closest Pair, Minimum Enclosing Circle

55m video

Three ways to beat checking all pairs. Rotating calipers walk two pointers around a hull, since the farthest vertex from an edge only moves forward. Closest pair is divide and conquer, where a packing bound allows only 7 comparisons per point. The minimum enclosing circle is randomised incremental construction in expected linear time.

Rotating calipers

On a counter-clockwise convex polygon, the distance from edge \(p_i p_{i+1}\)'s line to vertex \(p_j\) rises and then falls as \(j\) goes round (it is unimodal). So the farthest, antipodal, vertex is found by advancing \(j\) while the next vertex is farther. When \(i\) moves to the next edge, its line turns counter-clockwise and the antipodal vertex only moves forward, so both pointers make one lap: \(O(n)\) after the hull.

Theorem · The calipers invariant

For a strictly convex polygon, the farthest pair of points (the diameter) is attained by an antipodal pair, two vertices that admit parallel supporting lines. Every antipodal pair appears as \((p_i, p_j)\) or \((p_{i+1}, p_j)\) for some edge \(i\) with its farthest vertex \(j\), and the monotone pointer visits all of them.

Distances to a line compare as areas: the farther vertex has the larger orient(p_i, p_{i+1}, p_j), so the walk is exact in integers. The same walk gives:

  • Width (minimum distance between two parallel supporting lines): \(\min_i \text{orient}(p_i, p_{i+1}, p_{j(i)}) / |p_i p_{i+1}|\).
  • Minimum-area (or minimum-perimeter) enclosing rectangle: an optimal rectangle has a side flush with a hull edge (Freeman & Shapira, 1975). Run three calipers per edge (the farthest vertex, plus the extreme projections in both directions along the edge), each advancing monotonically, for \(O(n)\) total.
def diameter2(points):
    """Largest squared distance between two of the points. Uses convex_hull (L131)."""
    h = convex_hull(points)                    # strict: no collinear vertices
    n = len(h)
    if n == 1:
        return 0
    if n == 2:
        return dist2(h[0], h[1])
    best, j = 0, 1
    for i in range(n):
        a, b = h[i], h[(i + 1) % n]
        while orient(a, b, h[(j + 1) % n]) > orient(a, b, h[j]):
            j = (j + 1) % n                     # the next vertex is farther from line ab
        best = max(best, dist2(a, h[j]), dist2(b, h[j]))
    return best

Closest pair by divide and conquer

Sort by \(x\) and split at the median line \(x = m\). Recurse on both halves to get \(\delta^2\) = the best squared distance found. A closer pair would have to straddle the line, so both of its points lie in the strip \(|x - m| < \delta\). Sort the strip by \(y\) and compare each point only with the following points whose \(y\) is within \(\delta\).

Theorem · Only 7 neighbours

In the \(y\)-sorted strip, each point needs comparing with at most the next 7 points. Hence the strip step is \(O(n)\), and with merging by \(y\) during the recursion, \(T(n) = 2T(n/2) + O(n) = O(n \log n)\).

Proof

Fix a strip point \(p\). Any partner \(q\) closer than \(\delta\) lies in the \(2\delta \times \delta\) rectangle spanning the strip from \(y_p\) to \(y_p + \delta\). Cut it into eight \(\tfrac\delta2 \times \tfrac\delta2\) squares, four on each side of the dividing line. Two points in one square are less than \(\tfrac{\delta}{\sqrt2} < \delta\) apart, yet points on the same side are at least \(\delta\) apart. So each square holds at most one point, and the rectangle holds at most 8 points including \(p\).

from operator import itemgetter

def closest_pair(points):
    """Smallest squared distance among >= 2 points, exact. O(n log n)."""
    pts = sorted(points)
    by_y = itemgetter(1)

    def solve(lo, hi):                          # returns (best, pts[lo:hi] sorted by y)
        if hi - lo <= 3:
            best = min((dist2(pts[i], pts[j]) for i in range(lo, hi) for j in range(i + 1, hi)),
                       default=float("inf"))
            return best, sorted(pts[lo:hi], key=by_y)
        mid = (lo + hi) // 2
        mx = pts[mid][0]
        b1, y1 = solve(lo, mid)
        b2, y2 = solve(mid, hi)
        best = min(b1, b2)
        ys = sorted(y1 + y2, key=by_y)          # Timsort merges two sorted runs in linear time
        strip = [p for p in ys if (p[0] - mx) ** 2 < best]
        for i, p in enumerate(strip):
            for j in range(i + 1, len(strip)):
                q = strip[j]
                if (q[1] - p[1]) ** 2 >= best:
                    break                       # at most 7 iterations by the packing bound
                d = dist2(p, q)
                if d < best:
                    best = d
        return best, ys

    return solve(0, len(pts))[0]
Algorithm · Python-friendly alternatives
  1. Sweep + ordered set: sort by \(x\) and keep the points with \(x > x_i - \delta\) in a structure ordered by \(y\), querying \(y \in (y_i - \delta, y_i + \delta)\). That is \(O(n \log n)\), but Python has no built-in balanced tree.
  2. Randomised grid (Rabin 1976; Khuller & Matias 1995): shuffle the points. Keep the current \(\delta\) and a dict of grid cells of side \(\delta\). Each new point checks its 3×3 neighbourhood. If it finds a closer pair, \(\delta\) shrinks and the grid is rebuilt from the points so far.
  3. By backward analysis, the \(i\)-th point changes \(\delta\) with probability \(\le 2/i\), so the expected rebuild cost is \(\sum_i i \cdot \tfrac{2}{i} = O(n)\). Expected \(O(n)\) total, using only dicts.

Minimum enclosing circle: Welzl, iteratively

Shuffle the points, then grow the circle incrementally. If \(p_i\) is outside the current circle, it must be on the boundary of the new one, so restart with it fixed. Inside that, a point outside forces a second boundary point, and inside that a third, at which point the circle is the circumcircle. The probability that \(p_i\) lies on the boundary of the enclosing circle of the first \(i\) points is at most \(3/i\), because at most 3 points define it. So the expensive inner loops run rarely and the expected time is \(O(n)\). This randomised incremental construction pattern returns in L135.

import math
import random

def _circle2(a, b):
    cx, cy = (a[0] + b[0]) / 2, (a[1] + b[1]) / 2
    return cx, cy, math.hypot(a[0] - cx, a[1] - cy)

def _circle3(a, b, c):
    bx, by, cx, cy = b[0] - a[0], b[1] - a[1], c[0] - a[0], c[1] - a[1]
    d = 2 * (bx * cy - by * cx)
    if d == 0:                                  # collinear (only via rounding): widest pair
        return max((_circle2(p, q) for p, q in ((a, b), (a, c), (b, c))), key=lambda t: t[2])
    b2, c2 = bx * bx + by * by, cx * cx + cy * cy
    ux, uy = (cy * b2 - by * c2) / d, (bx * c2 - cx * b2) / d
    return ux + a[0], uy + a[1], math.hypot(ux, uy)

def min_enclosing_circle(points, eps=1e-9):
    """(cx, cy, r). Expected O(n)."""
    pts = list(points)
    random.shuffle(pts)

    def inside(c, p):
        return math.hypot(p[0] - c[0], p[1] - c[1]) <= c[2] + eps

    c = (pts[0][0], pts[0][1], 0.0)
    for i in range(1, len(pts)):
        if inside(c, pts[i]):
            continue
        c = (pts[i][0], pts[i][1], 0.0)                 # p_i is on the boundary
        for j in range(i):
            if inside(c, pts[j]):
                continue
            c = _circle2(pts[i], pts[j])                # p_i and p_j are on the boundary
            for k in range(j):
                if not inside(c, pts[k]):
                    c = _circle3(pts[i], pts[j], pts[k])
    return c

Geometry VI: Sweep Line and Advanced Topics

60m video

A sweep turns a 2D problem into a sorted sequence of 1D updates: move a vertical line left to right, stop only at events, and keep a structure describing the line's cross-section. The art is choosing that structure. For the union area of rectangles it is a segment tree whose nodes store "covered length", a design that needs no lazy propagation.

The sweep paradigm, generalised

As in L34, events are the sorted \(x\)-coordinates where the cross-section changes, and the status structure is the cross-section. Choosing it is the whole design. For neighbour queries among objects ordered along the line, use a sorted set. For aggregates over fixed positions (covered length, depth, count), use a segment tree over compressed coordinates (L106).

Segment intersection by sweeping

Shamos–Hoey (1976) answers "any intersection?" in \(O(n \log n)\). Keep the segments crossing the sweep line ordered by \(y\). At the leftmost intersection the two segments are adjacent in the status, so it suffices to test a new segment against its neighbours on insertion, and the newly adjacent pair on deletion. Bentley–Ottmann (1979) reports all \(k\) intersections in \(O((n+k)\log n)\) by adding intersections as events. In Python the obstacle is the lack of a balanced tree. For \(n \le 2000\), the \(O(n^2)\) pair check of L129 is the honest choice.

Area of the union of rectangles

Events are \((x_1, +1)\) and \((x_2, -1)\) per rectangle, each carrying \([y_1, y_2)\). Between events the cross-section is fixed, so

$$\text{Area} = \sum_{\text{events}} L(x_k) \cdot (x_{k+1} - x_k), \qquad L = \text{length of } y \text{ covered by at least one active interval}.$$

The status supports "add or remove an interval" and "how much is covered?". Build a segment tree over the elementary intervals \([y_i, y_{i+1})\) of the compressed \(y\)-values.

Theorem · The covered-length node

Store at each node cnt, the number of active intervals that were added exactly at this node (as one of its canonical pieces), and cov, the covered length inside the node's range. Maintain cov = len(node) if cnt > 0, else the sum of the children's cov (0 at a leaf). Then cov[root] is the covered length \(L\), with no lazy propagation.

Proof

A point is covered within the node iff some interval added at the node (then cnt > 0) or strictly below it (counted in a child's cov, by induction) covers it. Intervals added at ancestors are ignored, since such an ancestor overrides the whole subtree anyway. No push-down: each removal decomposes into exactly the same canonical nodes as its insertion, so cnt rises and falls at the same places and never goes negative. Each update touches \(O(\log n)\) nodes, for \(O(n \log n)\) in total.

def union_area(rects):
    """rects: (x1, y1, x2, y2) with x1 < x2, y1 < y2. Exact area of their union. O(n log n)."""
    ys = sorted({y for r in rects for y in (r[1], r[3])})
    m = len(ys) - 1                            # elementary intervals [ys[i], ys[i+1])
    if m <= 0:
        return 0
    idx = {y: i for i, y in enumerate(ys)}
    cnt = [0] * (4 * m)
    cov = [0] * (4 * m)

    def update(node, lo, hi, l, r, v):        # node covers elementary intervals [lo, hi)
        if r <= lo or hi <= l:
            return
        if l <= lo and hi <= r:
            cnt[node] += v
        else:
            mid = (lo + hi) // 2
            update(2 * node, lo, mid, l, r, v)
            update(2 * node + 1, mid, hi, l, r, v)
        if cnt[node]:
            cov[node] = ys[hi] - ys[lo]
        elif hi - lo == 1:
            cov[node] = 0
        else:
            cov[node] = cov[2 * node] + cov[2 * node + 1]

    events = []
    for x1, y1, x2, y2 in rects:
        events.append((x1, 1, idx[y1], idx[y2]))
        events.append((x2, -1, idx[y1], idx[y2]))
    events.sort()
    area, prev = 0, events[0][0]
    for x, v, l, r in events:
        area += cov[1] * (x - prev)            # the cross-section was constant on [prev, x)
        prev = x
        update(1, 0, m, l, r, v)
    return area

Recursion depth is \(\log_2 m\). At \(n = 10^5\) (CSES) CPython is tight, so use an iterative tree or PyPy.

When a rectangle starts, count the active \(y\)-intervals overlapping its own, as "starts before my end" minus "ends before my start", using BITs over compressed \(y\). Half-plane intersection

Algorithm · Half-plane intersection, O(n log n)
  1. Each half-plane is a directed line, keeping its left side. Add a large bounding box.
  2. Sort by angle. Among same-direction parallels keep the innermost.
  3. Deque sweep: before appending \(h\), pop the back (then the front) while the last (first) two lines meet outside \(h\).
  4. Clean up both ends against each other. With fewer than 3 lines it is empty; otherwise consecutive intersections are the vertices.

Uses: feasible regions of 2-variable linear constraints (2D LP: evaluate the objective at the vertices), and the kernel of a polygon (the points that see all of it).

import math
from collections import deque

def half_plane_intersection(hps, eps=1e-9):
    """hps: (px, py, dx, dy) = the half-plane LEFT of the line p + t*d. Include a bounding box.
    Returns the polygon's vertices counter-clockwise, or [] if empty."""
    def out(h, p):                              # p strictly on the right of h
        return h[2] * (p[1] - h[1]) - h[3] * (p[0] - h[0]) < -eps

    def inter(h, g):
        t = ((g[0] - h[0]) * g[3] - (g[1] - h[1]) * g[2]) / (h[2] * g[3] - h[3] * g[2])
        return h[0] + t * h[2], h[1] + t * h[3]

    dq = deque()
    for h in sorted(hps, key=lambda h: math.atan2(h[3], h[2])):
        while len(dq) >= 2 and out(h, inter(dq[-1], dq[-2])):
            dq.pop()
        while len(dq) >= 2 and out(h, inter(dq[0], dq[1])):
            dq.popleft()
        if dq and abs(dq[-1][2] * h[3] - dq[-1][3] * h[2]) < eps:      # parallel to the last line
            if dq[-1][2] * h[2] + dq[-1][3] * h[3] < 0:
                return []                       # opposite directions met here: empty region
            if out(h, (dq[-1][0], dq[-1][1])):
                dq.pop()                        # same direction, h is tighter
            else:
                continue
        dq.append(h)
    while len(dq) >= 3 and out(dq[0], inter(dq[-1], dq[-2])):
        dq.pop()
    while len(dq) >= 3 and out(dq[-1], inter(dq[0], dq[1])):
        dq.popleft()
    if len(dq) < 3:
        return []
    return [inter(dq[i], dq[(i + 1) % len(dq)]) for i in range(len(dq))]

This follows the CP-Algorithms formulation, including the opposite-parallel shortcut, which is valid once the bounding box is present. Test it against the \(O(nk)\) brute force: repeatedly cut a big square by each half-plane (L130).

Minkowski sum of convex polygons

\(P \oplus Q = \{p + q\}\) is convex, with the edges of \(P\) and \(Q\) merged by angle. Start both at the bottom-most vertex and merge the edge sequences by cross product: \(O(n + m)\). Reduction: \(P\) and \(Q\) intersect iff the origin lies in \(P \oplus (-Q)\), one point-in-convex query (L130), and their distance is the origin's distance to it.

def minkowski(P, Q):
    """P, Q convex, counter-clockwise, no repeated vertices. Returns P + Q (may contain collinear points)."""
    def from_bottom(R):
        k = min(range(len(R)), key=lambda i: (R[i][1], R[i][0]))
        return R[k:] + R[:k]
    P, Q = from_bottom(P), from_bottom(Q)
    P, Q = P + P[:2], Q + Q[:2]                 # sentinels for the edge after the last
    i = j = 0
    res = []
    while i < len(P) - 2 or j < len(Q) - 2:
        res.append((P[i][0] + Q[j][0], P[i][1] + Q[j][1]))
        c = cross(sub(P[i + 1], P[i]), sub(Q[j + 1], Q[j]))
        if c >= 0 and i < len(P) - 2:
            i += 1
        if c <= 0 and j < len(Q) - 2:
            j += 1
    return res

Delaunay triangulations and Voronoi diagrams

The Voronoi diagram splits the plane into regions nearest to each site. Its dual, the Delaunay triangulation, has no site inside any triangle's circumcircle and maximises the minimum angle. Both have \(O(n)\) size and take \(O(n \log n)\) to build (e.g. Fortune's sweep). They matter because Euclidean MST edges, nearest neighbours and the closest pair are all Delaunay edges, which cuts \(O(n^2)\) candidates to \(O(n)\). Code: scipy.spatial (Qhull) locally, and a vetted library such as KACTL in contests. Hand-writing one under time pressure is risky.

  • Convex-polygon intersection: half-plane intersection of both edge sets, or the Minkowski test.
What breaks

Algorithm · Pre-submit precision checklist
  1. Integers wherever possible. Every predicate (orientation, inside, intersects, compare distances) is an integer sign. Did a float sneak in through /?
  2. No unnecessary square roots. Compare squared distances and squared lengths. Take sqrt only for the printed answer.
  3. EPS only where forced, and scaled to the magnitudes involved (L128), never a reflexive \(10^{-9}\).
  4. Fraction when desperate, on the handful of constructed points, not inside \(O(n^2)\) loops.
  5. Degenerate inputs: \(n \le 2\), duplicates, all points collinear, zero-length segments, vertical lines, touching rather than crossing.
  6. Statement conventions: are collinear hull points included? Is the boundary inside? Is the input clockwise? Are the closed or open rectangles the ones that count?
  7. Output: enough digits (f"{x:.10f}"), no -0.0000000000, and an exact integer where one is asked for (twice the area, the squared distance).

P1 · Orientation and area

Problem. A simple polygon's vertices are given in either orientation. Print whether they are clockwise, twice the area, and the number of interior lattice points. Solution: the sign of area2 gives the orientation, abs(area2) is twice the area, and Pick's theorem gives \(I = (2A - B + 2)/2\) with \(B = \sum \gcd\) (L130). \(O(n)\), all integer. Trap: printing \(A\) via float division loses the ".5" for odd \(2A\) at \(10^{18}\) scale. Print a2 // 2 followed by ".5" when a2 is odd.

P2 · Segment intersection with degenerate cases

Problem. \(n \le 2000\) segments with integer endpoints, some of zero length. Count the pairs sharing at least one point. Solution: segments_intersect over all \(\binom n2\) pairs (L129). That is \(2\cdot10^6\) calls, which fits if orient is inlined. Where WAs come from: zero-length segments, collinear overlaps, and T-junctions. This problem is that test suite. Write the twelve asserts before the loop.

P3 · Convex hull application

Problem. \(n \le 2\cdot10^5\) points. Print the squared diameter and the length of the shortest fence enclosing all of them. Solution: build the strict hull (L131). The fence length is the hull perimeter, a sum of math.hypot over its edges, and the diameter is diameter2 by rotating calipers (L132). \(O(n \log n)\). Traps: all points collinear (the fence is twice the segment length), a single distinct point (both answers 0), and a hull built with collinear points (calipers stall).

P4 · Sweep line: maximum overlap

Problem. \(n \le 10^5\) closed axis-parallel rectangles. What is the maximum number covering a single point? Solution: sweep \(x\). At each event add ±1 on the rectangle's \(y\)-range in a segment tree that supports range add and global max. As in L133 there is no push-down: mx[node] = add[node] + max(children). The closed-boundary detail: compress \(y\) as points (not elementary intervals), use inclusive ranges, and process openings before closings at equal \(x\), so that rectangles that only touch still count as overlapping. Swap both decisions for open rectangles.

def max_overlap(rects):
    """Closed rectangles (x1, y1, x2, y2): the largest number covering a common point."""
    ys = sorted({y for r in rects for y in (r[1], r[3])})
    idx = {y: i for i, y in enumerate(ys)}
    m = len(ys)
    add = [0] * (4 * m)
    mx = [0] * (4 * m)

    def update(node, lo, hi, l, r, v):         # inclusive point indices
        if r < lo or hi < l:
            return
        if l <= lo and hi <= r:
            add[node] += v
            mx[node] += v
            return
        mid = (lo + hi) // 2
        update(2 * node, lo, mid, l, r, v)
        update(2 * node + 1, mid + 1, hi, l, r, v)
        mx[node] = add[node] + max(mx[2 * node], mx[2 * node + 1])

    events = []
    for x1, y1, x2, y2 in rects:
        events.append((x1, 0, idx[y1], idx[y2]))   # 0 sorts first: open before close at equal x
        events.append((x2, 1, idx[y1], idx[y2]))
    events.sort()
    best = 0
    for x, kind, l, r in events:
        update(1, 0, m - 1, l, r, -1 if kind else 1)
        best = max(best, mx[1])
    return best
P5 · Mixed geometry + data structure: points in rectangles

Problem. \(n\) points and \(q\) closed query rectangles, both up to \(2\cdot10^5\). Count the points in each rectangle. Solution: offline sweep over \(x\) with a Fenwick tree over compressed \(y\) (L104). Each query becomes two events: subtract the count in \([y_1, y_2]\) just before the points at \(x_1\) are inserted, and add it just after the points at \(x_2\). Encode the order at equal \(x\) as the second tuple field (0 = before, 1 = point, 2 = after). \(O((n + q)\log n)\), the same "sort the queries into a useful order" move as L71.

from bisect import bisect_left, bisect_right

def count_points_in_rects(points, rects):
    """Closed rectangles (x1, y1, x2, y2). Offline: O((n + q) log n)."""
    ys = sorted({y for _, y in points})
    n = len(ys)
    bit = [0] * (n + 1)

    def insert(i):
        i += 1
        while i <= n:
            bit[i] += 1
            i += i & -i

    def prefix(i):                               # inserted points with y-index < i
        s = 0
        while i > 0:
            s += bit[i]
            i -= i & -i
        return s

    events = []
    for qi, (x1, y1, x2, y2) in enumerate(rects):
        lo, hi = bisect_left(ys, y1), bisect_right(ys, y2)
        events.append((x1, 0, qi, lo, hi, -1))   # before the points at x1
        events.append((x2, 2, qi, lo, hi, 1))    # after the points at x2
    for x, y in points:
        events.append((x, 1, bisect_left(ys, y), 0, 0, 0))
    events.sort()
    ans = [0] * len(rects)
    for x, kind, a, lo, hi, sgn in events:
        if kind == 1:
            insert(a)
        else:
            ans[a] += sgn * (prefix(hi) - prefix(lo))
    return ans

Seeing the bug: a plotting utility

Geometry bugs are rarely visible in numbers and usually obvious in a picture: a hull that skips a point, a ray through a vertex, a rectangle edge counted twice. Shrink the failing case with the stress tester (L10), then draw it. Keep this in a local tools/ file, never in the submission.

def plot(points=(), segments=(), polygons=(), fname="debug.png"):
    """Local debugging only: save a picture of a small failing case."""
    import matplotlib
    matplotlib.use("Agg")
    import matplotlib.pyplot as plt
    fig, ax = plt.subplots(figsize=(6, 6))
    for poly in polygons:
        xs, ys = zip(*(list(poly) + [poly[0]]))
        ax.plot(xs, ys, "-")
    for a, b in segments:
        ax.plot([a[0], b[0]], [a[1], b[1]], "-o", ms=3)
    if points:
        xs, ys = zip(*points)
        ax.scatter(xs, ys, s=14, zorder=3)

    ax.set_aspect("equal")
    ax.grid(True, alpha=0.3)
    fig.savefig(fname, dpi=120)
    plt.close(fig)
