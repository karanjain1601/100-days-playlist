L81 · DAY 57

DP Foundations: How to Invent a Recurrence

60m video

A dynamic program is a recurrence evaluated once per state over a DAG of states. The code is the easy part. The skill is choosing a state that carries exactly the information the rest of the problem needs, and writing the recurrence down in words before you type anything.

What makes a problem a DP

Definition

A problem has optimal substructure when an optimal solution is assembled from optimal solutions of smaller instances of the same problem. It has overlapping subproblems when a naive recursion meets the same smaller instance many times. Dynamic programming gives each distinct subproblem a name (a state), computes it once and stores it.

The naive call tree for Fibonacci \(F_n\) has \(\Theta(\varphi^n)\) nodes but only \(n+1\) distinct arguments; storing one answer per argument collapses the tree into a path.

The five-question method

Algorithm · Five questions, answered in English first
  1. State. Which parameters identify a subproblem: an index, a remaining capacity, the last choice, a mask?
  2. Meaning. One sentence, such as "dp[i] = minimum cost to stand on stone i". If you cannot write it, you do not have a DP yet.
  3. Transitions. Ask what did I do last? The last move splits every solution of the state into cases, and each case ends in a smaller state.
  4. Base cases. The states with no last move (empty prefix, zero capacity), plus a value for illegal states: \(+\infty\) for min, \(-\infty\) for max, 0 for counting.
  5. Answer. Which state, or which min/max/sum over states, is the question?
Worked example · AtCoder DP-A Frog 1

Stones \(0..n-1\) have heights \(h_i\). From stone \(i\) the frog jumps to \(i+1\) or \(i+2\) and pays \(|h_i - h_j|\). Find the minimum cost from stone 0 to stone \(n-1\).

  1. State: the stone index \(i\).
  2. Meaning: \(dp[i]\) = minimum cost to reach stone \(i\) from stone 0.
  3. The last jump came from \(i-1\) or \(i-2\): \(dp[i] = \min\big(dp[i-1] + |h_i - h_{i-1}|,\ dp[i-2] + |h_i - h_{i-2}|\big)\).
  4. Base: \(dp[0] = 0\). The \(i-2\) case is illegal when \(i = 1\).
  5. Answer: \(dp[n-1]\).

Correctness: induction over a topological order

Theorem · DP correctness

Suppose the transitions form a DAG on the states. If (a) every base value is correct, and (b) for every other state \(s\) the cases of the transition cover all solutions of \(s\), and each case's value is "cost of the last step + optimal value of the smaller state", then \(dp[s]\) is optimal for every \(s\). For counting DPs the cases must also be disjoint.

Proof

Induct along a topological order; base states hold by (a). For another state \(s\), every state it reads comes earlier and is optimal by induction. An optimal solution of \(s\) lies in some case; deleting its last step leaves a solution of the smaller state \(s'\) costing at least \(dp[s']\), so that case value is at most the optimum. Each case value is also achieved (an optimal solution of \(s'\) plus the last step), so none undercuts it. The minimum over cases is exactly optimal. \(\square\)

The DAG requirement is real: if a transition can return to the same state there is no evaluation order, and you need shortest paths or a linear system (L95). "Increasing \(i\)" is a valid loop order only because every transition decreases \(i\).

Complexity = states × transitions

Total work is \(\sum_s \deg^+(s) \le |S| \cdot T\). Do the multiplication before coding, against the Appendix C budget (CPython roughly \(10^7\) simple operations per second, PyPy roughly \(10^8\)):

State design is the whole skill

A state must be sufficient: any two partial solutions that reach it must have the same legal futures at the same costs. It should be minimal, because every extra dimension multiplies the state count. When a DP gives wrong answers on small inputs, the usual cause is a sufficiency failure: two partial solutions with different futures were merged into one state.

Worked example · finding a missing dimension

AtCoder DP-C Vacation: each day pick activity A, B or C with a day-specific happiness, never the same activity two days running. Try \(dp[i]\) = best total over days \(0..i\). The transition needs day \(i\)'s activity, and \(dp[i]\) has forgotten it: two prefixes with equal totals but different last activities have different futures. Add the dimension: \(dp[i][c] = a_i[c] + \max_{c' \ne c} dp[i-1][c']\). Asking "do all partial solutions in this state have the same futures?" finds the missing dimension every time.

Top-down, bottom-up, rolled

Top-down (memoised recursion) is the recurrence typed verbatim; it touches only reachable states and needs no explicit order. Bottom-up fills a table in an order you choose. Converting is mechanical: each recursive call becomes a table read, and the loop runs callees before callers. In CPython bottom-up is several times faster (no calls, no cache dictionary) and has no recursion limit; top-down wins when few states are reachable. Then check how far back the loop reads: if \(dp[i]\) needs only \(dp[i-1], dp[i-2]\), keep two variables. Rolling becomes essential in L83 and L85.

from functools import cache

def frog_top_down(h):
    @cache
    def f(i):                       # f(i) = min cost to reach stone i
        if i == 0:
            return 0
        best = f(i - 1) + abs(h[i] - h[i - 1])
        if i >= 2:
            best = min(best, f(i - 2) + abs(h[i] - h[i - 2]))
        return best
    return f(len(h) - 1)

def frog_bottom_up(h):
    dp = [0] * len(h)
    for i in range(1, len(h)):
        dp[i] = dp[i - 1] + abs(h[i] - h[i - 1])
        if i >= 2:
            dp[i] = min(dp[i], dp[i - 2] + abs(h[i] - h[i - 2]))
    return dp[-1]

def frog_rolled(h):
    a = b = 0                       # a = dp[i-2], b = dp[i-1]
    for i in range(1, len(h)):
        c = b + abs(h[i] - h[i - 1])
        if i >= 2:
            c = min(c, a + abs(h[i] - h[i - 2]))
        a, b = b, c
    return b

h = [10, 30, 40, 20]
print(frog_top_down(h), frog_bottom_up(h), frog_rolled(h))   # 30 30 30

At \(n = 10^5\) the top-down version hits the default recursion limit of 1000. Raising the limit alone can crash the interpreter, because the C-level @cache wrapper uses C stack on every level; run it in a thread after threading.stack_size(1 << 27), or go bottom-up.

DP, greedy or brute force?

  • Brute force when the search space fits (\(n \le 20\) subsets, \(n \le 10\) permutations). Write it anyway as your stress-test oracle.
  • Greedy when an exchange argument exists (L22). Without a proof, compare it with brute force on random small inputs first.
  • DP when earlier choices affect later ones only through a small summary. That summary is the state.

Problems

AtCoder DP-B — Frog 2. Jumps of length \(1..k\): \(dp[i] = \min_{1 \le d \le \min(k, i)} dp[i-d] + |h_i - h_{i-d}|\), \(O(nk) = 10^7\). A comprehension over zipped slices runs about 2.5× faster than a nested loop in CPython, but that is still borderline; submit with PyPy.

import sys
def main():
    data = sys.stdin.buffer.read().split()
    n, k = int(data[0]), int(data[1])
    h = list(map(int, data[2:2 + n]))
    dp = [0] * n
    for i in range(1, n):
        lo, hi = max(0, i - k), h[i]
        dp[i] = min([d + abs(hi - x) for d, x in zip(dp[lo:i], h[lo:i])])
    print(dp[-1])
main()

CSES — Dice Combinations. Count ordered sequences of throws (1..6) summing to \(n\). Last throw \(d\): \(dp[s] = \sum_{d=1}^{6} dp[s-d]\), \(dp[0] = 1\). Keep the sum of the last six values as a running window so each state costs \(O(1)\):

import sys
MOD = 10**9 + 7
n = int(sys.stdin.readline())
dp = [1] + [0] * n
window = 1                          # dp[s-6] + ... + dp[s-1]
for s in range(1, n + 1):
    dp[s] = window % MOD
    window += dp[s]
    if s >= 6:
        window -= dp[s - 6]
print(dp[n])

CSES — Minimizing Coins. \(dp[s]\) = fewest coins summing to \(s\). Last coin \(c\): \(dp[s] = 1 + \min_c dp[s-c]\); base \(dp[0] = 0\); illegal sums hold a sentinel larger than any answer; print \(-1\) if \(dp[x]\) still holds it. The work is \(n \cdot x \le 10^8\), so submit with PyPy if the judge offers it.

def min_coins(coins, x):
    INF = x + 1                     # more than any real answer
    dp = [0] + [INF] * x
    for c in coins:                 # ascending s lets a coin be reused (L84)
        for s in range(c, x + 1):
            if dp[s - c] + 1 < dp[s]:
                dp[s] = dp[s - c] + 1
    return dp[x] if dp[x] <= x else -1

print(min_coins([1, 5, 7], 11))     # 3  (5 + 5 + 1)
What breaks
  • Wrong loop order. Reading \(dp[j]\) before it is computed silently uses the initial value. Every read must point to an earlier iteration.
  • Illegal states initialised to 0 in a min-DP, so impossible sums look free. Use an int sentinel; float('inf') mixes floats into integer arithmetic.
  • Overlapping cases in a counting DP double-count. The cases must partition the solutions.
  • No modulus each step. Python never overflows; it just slows down as the numbers grow to thousands of digits.
  • Stale memo across test cases. A module-level @cache keeps the last test's answers; define it per test or call cache_clear().

L82 · DAY 57

1D DP Classics

50m video

Most one-dimensional DPs are one of four shapes: a Fibonacci-like sum over the last few states, take-or-skip, "best segment ending here", or "count the ways to parse a prefix". Recognise the shape and the recurrence writes itself. When it does not, the state is missing a dimension.

Fibonacci-shaped: the last step has a few sizes

If the last move covers 1, 2, …, k positions, then \(dp[i]\) combines \(dp[i-1], \dots, dp[i-k]\). Climbing Stairs (LeetCode 70) counts: \(dp[i] = dp[i-1] + dp[i-2]\). Min Cost Climbing Stairs (746) minimises: \(dp[i] = \min(dp[i-1] + c_{i-1},\ dp[i-2] + c_{i-2})\), \(dp[0] = dp[1] = 0\), answer \(dp[n]\). Tribonacci (1137) reads three back. With general k the work is \(O(nk)\); when the combine is a sum, a running window makes it \(O(n)\) (L81's Dice Combinations), and when it is a min, a monotonic deque does (L98).

Take-or-skip: House Robber and its reductions

House Robber (198): no two adjacent houses. The last house is either skipped or taken, and taking it forces skipping \(i-1\):

$$dp[i] = \max\big(dp[i-1],\ dp[i-2] + a_i\big), \qquad dp[-1] = dp[-2] = 0.$$

Circular (213): houses 0 and \(n-1\) are adjacent. Split on the wrap: in any valid choice, house 0 or house \(n-1\) is unused, so the answer is \(\max(\text{rob}(a_{1..n-1}),\ \text{rob}(a_{0..n-2}))\), with \(n = 1\) handled separately. The two cases overlap, which is fine for max (it would not be for counting). Delete and Earn (740): taking value \(v\) deletes all \(v \pm 1\), and you may as well take every copy of \(v\). Bucket \(p[v] = v \cdot \text{cnt}(v)\) and run House Robber over \(v = 0..\max\).

Kadane: best segment ending here

Theorem · Kadane's recurrence

Let \(dp[i]\) be the maximum sum of a non-empty subarray that ends at \(i\). Then \(dp[0] = a_0\), \(dp[i] = \max(a_i,\ dp[i-1] + a_i)\), and the maximum subarray sum is \(\max_i dp[i]\).

Proof

A subarray ending at \(i\) is either \([i, i]\) or \([j, i]\) with \(j < i\); the latter is a subarray ending at \(i-1\) plus \(a_i\), maximised by taking the best one, \(dp[i-1]\). Every subarray ends somewhere, so the overall best is the max over \(i\). Equivalently, restart at \(i\) exactly when \(dp[i-1] < 0\). \(O(n)\) time, \(O(1)\) space. \(\square\)

The state "ending at \(i\)" is the general trick for segment problems: "best over the prefix" does not compose, "best ending here" does.

def kadane(a):
    """Max-sum non-empty subarray as (best, l, r), a[l..r] inclusive."""
    best, bl, br = a[0], 0, 0
    cur, cl = a[0], 0                 # best sum ending at i, and its start
    for i in range(1, len(a)):
        if cur < 0:                   # dp[i-1] + a[i] < a[i]: restart
            cur, cl = a[i], i
        else:
            cur += a[i]
        if cur > best:
            best, bl, br = cur, cl, i
    return best, bl, br

def max_circular(a):                  # LeetCode 918
    best = kadane(a)[0]
    if best < 0:                      # all negative: the wrap case would be empty
        return best
    cur = worst = 0                   # min subarray sum (empty allowed)
    for x in a:
        cur = min(x, cur + x)
        worst = min(worst, cur)
    return max(best, sum(a) - worst)  # wrap = total minus a middle segment

def max_product(a):                   # LeetCode 152
    hi = lo = best = a[0]             # largest and smallest product ending here
    for x in a[1:]:
        c = (x, hi * x, lo * x)
        hi, lo = max(c), min(c)
        best = max(best, hi)
    return best

print(kadane([-2, 1, -3, 4, -1, 2, 1, -5, 4]))       # (6, 3, 6)
print(max_circular([5, -3, 5]), max_circular([-3, -2, -3]))   # 10 -2
print(max_product([2, 3, -2, 4]), max_product([-2, 3, -4]))   # 6 24

Circular maximum subarray uses the same two-case split as circular House Robber: the best segment either does not wrap (plain Kadane) or wraps, and a wrapping segment is the whole array minus a non-wrapping middle segment, so it is best when that middle is the minimum subarray. Max product needs two states because multiplying by a negative number turns the smallest product into the largest. One state is not sufficient: the best product ending at \(i-1\) can be the wrong thing to extend.

Counting parses: Decode Ways and Word Break

"How many ways to cut a prefix into valid pieces?" The last piece is the transition. Decode Ways (91): \(dp[i]\) = decodings of the first \(i\) digits; the last letter is one digit (not '0') or two digits forming 10..26.

def decode_ways(s):
    p2, p1 = 0, 1                     # dp[i-2], dp[i-1]; dp[0] = 1 (empty prefix)
    for i in range(1, len(s) + 1):
        cur = p1 if s[i - 1] != '0' else 0
        if i >= 2 and (s[i - 2] == '1' or (s[i - 2] == '2' and s[i - 1] <= '6')):
            cur += p2
        p2, p1 = p1, cur
    return p1

def word_break(s, words):             # LeetCode 139
    W, L = set(words), max(map(len, words))
    ok = [True] + [False] * len(s)    # ok[i]: s[:i] splits into words
    for i in range(1, len(s) + 1):
        for j in range(max(0, i - L), i):
            if ok[j] and s[j:i] in W:
                ok[i] = True
                break
    return ok[-1]

print(decode_ways("226"), decode_ways("06"), decode_ways("2101"))   # 3 0 1
print(word_break("applepenapple", ["apple", "pen"]))                # True

The zero rules are where Decode Ways fails: '0' cannot stand alone, so "06" has 0 decodings and "2101" has exactly one (2 | 10 | 1). Limiting \(j\) to the longest word makes Word Break \(O(nL)\) slices instead of \(O(n^2)\).

When a 1D DP secretly needs a second dimension

  • Sign (max product): add "smallest product" alongside "largest".
  • A global constraint (circular robber): add "was house 0 taken", or split into cases.
  • The previous value matters (CSES Array Description, below): add the value itself.
  • A mode (stock with cooldown, LeetCode 309): add "holding / not holding / cooling".

Problems

CSES — Removing Digits. Subtract one of \(x\)'s nonzero digits until 0, in as few steps as possible: \(dp[x] = 1 + \min_{d \in \text{digits}(x),\ d > 0} dp[x-d]\), \(O(7n)\). Greedily subtracting the largest digit also passes (it agrees with the DP on every \(x \le 2\cdot 10^4\) in a brute-force check), but the DP needs no proof.

CSES — Array Description. Fill the zeros with values in \(1..m\) so that neighbours differ by at most 1. State \((i, v)\): \(dp_i[v] = dp_{i-1}[v-1] + dp_{i-1}[v] + dp_{i-1}[v+1]\), forced to 0 unless \(x_i \in \{0, v\}\). That is \(O(nm) = 10^7\) cell updates: several seconds in CPython whether you write a loop or a comprehension (I measured them within 25% of each other), comfortable in PyPy.

import sys
MOD = 10**9 + 7
def main():
    data = sys.stdin.buffer.read().split()
    n, m = int(data[0]), int(data[1])
    x = list(map(int, data[2:2 + n]))
    dp = [0] * (m + 2)                # dp[v], v = 1..m, zero padding at both ends
    if x[0]:
        dp[x[0]] = 1
    else:
        dp[1:m + 1] = [1] * m
    for i in range(1, n):
        if x[i]:
            v, s = x[i], dp[x[i] - 1] + dp[x[i]] + dp[x[i] + 1]
            dp = [0] * (m + 2)
            dp[v] = s % MOD
        else:
            dp = [0] + [(dp[v - 1] + dp[v] + dp[v + 1]) % MOD for v in range(1, m + 1)] + [0]
    print(sum(dp) % MOD)
main()
What breaks
  • Kadane on an all-negative array returning 0 because best started at 0. Initialise with a[0], or decide explicitly whether the empty subarray is allowed.
  • Circular max returning total − total = 0 when every element is negative. Guard that case.
  • Max product updating hi before computing lo from the old hi. Compute both from the same tuple.
  • Decode Ways treating "0" as a letter or accepting "06" as a two-digit code.
  • Circular robber with n = 1: both slices are empty and the answer becomes 0 instead of a[0].

L83 · DAY 58

Knapsack I: 0/1, Subset Sum, and Space Optimisation

55m video

0/1 knapsack is a take-or-skip DP over (items considered, capacity used). One skeleton serves three questions, best value, feasibility and counting, by changing only the combine operator. Rolled to one row it needs a descending loop, and for feasibility in Python the row becomes a single big integer.

The table, from the five questions

Items \(1..n\) with weights \(w_i\) and values \(v_i\); capacity \(W\); each item used at most once.

Definition · 0/1 knapsack DP

\(dp[i][c]\) = best value using a subset of the first \(i\) items with total weight at most \(c\). Last decision: take item \(i\) or not.

$$dp[i][c] = \max\big(dp[i-1][c],\ dp[i-1][c - w_i] + v_i \ \text{ if } c \ge w_i\big), \qquad dp[0][c] = 0.$$

Answer \(dp[n][W]\). Time and memory \(O(nW)\): pseudo-polynomial, since \(W\) is a number, not an input length. If you want "weight exactly \(c\)", initialise \(dp[0][0] = 0\) and \(dp[0][c>0] = -\infty\).

Rows depend only on the previous row, so filling \(i = 1..n\) in order is a topological order, and within a row any order of \(c\) works because no cell of row \(i\) reads another cell of row \(i\).

Reconstruction. Walk back from \((n, W)\): if \(dp[i][c] \ne dp[i-1][c]\), item \(i\) must have been taken, so record it and set \(c \mathrel{-}= w_i\); otherwise skipping item \(i\) is optimal. Either way move to row \(i-1\). This needs the full 2D table (or one parent bit per cell); the rolled version cannot reconstruct.

Rolling to one row: why the loop runs downwards

Theorem · Descending capacity loop

Keep a single array \(d\). For each item, update \(d[c] \leftarrow \max(d[c],\ d[c - w_i] + v_i)\) for \(c = W, W-1, \dots, w_i\). After processing item \(i\), \(d[c] = dp[i][c]\) for all \(c\).

Proof

Induct on \(i\). Before item \(i\)'s pass, \(d = dp[i-1]\). When the pass writes \(d[c]\), it reads \(d[c]\) (not yet written in this pass) and \(d[c - w_i]\) with \(c - w_i < c\). A descending pass reaches smaller indices later, so \(d[c - w_i]\) still holds \(dp[i-1][c - w_i]\). The update is therefore exactly the 2D recurrence. In an ascending pass \(d[c - w_i]\) may already include item \(i\), so the item can be taken twice: that is the unbounded knapsack of L84. \(\square\)

Subset-sum variants are all feasibility questions on the same row: equal partition asks whether \(S/2\) is reachable; sum closest to half takes the largest reachable \(t \le S/2\) and answers \(S - 2t\); counting subsets with sum \(T\) is the counting row.

Feasibility as a big integer

A feasibility row is a set of reachable sums. Store it as an int whose bit \(s\) is set when \(s\) is reachable. Adding an item of weight \(w\) is mask |= mask << w: the shift reads the old mask in full before the OR, so 0/1 semantics come for free, and CPython executes the shift and OR in C over 30-bit digits.

import random, time

def knap_2d(wt, val, W):
    n = len(wt)
    dp = [[0] * (W + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        w, v, prev, cur = wt[i - 1], val[i - 1], dp[i - 1], dp[i]
        for c in range(W + 1):
            cur[c] = prev[c]
            if c >= w and prev[c - w] + v > cur[c]:
                cur[c] = prev[c - w] + v
    take, c = [], W                          # backward walk
    for i in range(n, 0, -1):
        if dp[i][c] != dp[i - 1][c]:
            take.append(i - 1)
            c -= wt[i - 1]
    return dp[n][W], take[::-1]

def knap_1d(wt, val, W):
    d = [0] * (W + 1)
    for w, v in zip(wt, val):
        for c in range(W, w - 1, -1):        # descending
            if d[c - w] + v > d[c]:
                d[c] = d[c - w] + v
    return d[W]

def sums_list(wt, W):
    ok = [True] + [False] * W
    for w in wt:
        for c in range(W, w - 1, -1):
            if ok[c - w]:
                ok[c] = True
    return ok

def sums_bits(wt, W):
    mask, full = 1, (1 << (W + 1)) - 1      # bit s set  <=>  sum s reachable
    for w in wt:
        mask = (mask | mask << w) & full
    return mask

Knapsack II: Unbounded, Bounded, Coin Change Family

50m video

Unbounded, 0/1 and bounded knapsack differ only in how many copies of an item a transition may use, and in a one-row DP that is decided entirely by loop direction and loop nesting. Learn the loop-order table once and combinations versus permutations stops being a coin flip.

Unbounded knapsack: the ascending loop

With unlimited copies, the last decision for \(dp[i][c]\) is "use item \(i\) zero times, or at least once", and "at least once" leaves the same item available:

$$dp[i][c] = \max\big(dp[i-1][c],\ dp[i][c - w_i] + v_i\big).$$

The second term reads row \(i\), not row \(i-1\). In one row, iterating \(c\) upwards means \(d[c - w_i]\) has already been updated for item \(i\), which is exactly that term. The single change from L83 (ascending instead of descending) is the whole difference between 0/1 and unbounded.

Theorem · Loop order decides what is counted

(a) With coins outer and sums ascending, after coin \(i\) the row holds \(d_i[s]\) = number of multisets of coins from \(\{c_1..c_i\}\) with sum \(s\). (b) With sums outer, \(d[s] = \sum_{c} d[s-c]\) is the number of ordered sequences with sum \(s\).

Proof

(a) Split the multisets with sum \(s\) by whether they contain \(c_i\): those that do not are counted by \(d_{i-1}[s]\); removing one copy of \(c_i\) from those that do is a bijection onto multisets from \(\{c_1..c_i\}\) with sum \(s - c_i\), counted by \(d_i[s - c_i]\). The ascending pass computes exactly \(d_i[s] = d_{i-1}[s] + d_i[s - c_i]\). Every multiset is built in one canonical order (all \(c_1\)'s first, then \(c_2\)'s, …), so none is counted twice. (b) Split sequences by their last coin \(c\); removing it is a bijection onto sequences with sum \(s - c\). Different last coins give different sequences, so \(2+3\) and \(3+2\) are both counted. \(\square\)

MOD = 10**9 + 7

def min_coins(coins, x):                 # 322; ascending, either nesting
    INF = x + 1
    d = [0] + [INF] * x
    for c in coins:
        for s in range(c, x + 1):
            if d[s - c] + 1 < d[s]:
                d[s] = d[s - c] + 1
    return d[x] if d[x] <= x else -1

Bounded knapsack: binary splitting

Item \(i\) may be used up to \(k_i\) times. Naively, \(dp[i][c] = \max_{0 \le t \le k_i} dp[i-1][c - t w_i] + t v_i\) costs \(O(W \sum k_i)\). Binary splitting replaces item \(i\) by \(O(\log k_i)\) ordinary 0/1 items.

Theorem · Binary splitting

Split \(k\) into pieces \(1, 2, 4, \dots, 2^{p-1}\) (the largest \(p\) with \(2^p - 1 \le k\)) and a remainder \(r = k - (2^p - 1)\), where \(0 \le r < 2^p\). The subset sums of the pieces are exactly \(\{0, 1, \dots, k\}\).

Proof

No subset exceeds the total \(k\). Any \(t \le 2^p - 1\) is a sum of the powers by its binary expansion. For \(2^p \le t \le k\), \(t - r\) lies in \([2^p - r,\ 2^p - 1] \subseteq [1,\ 2^p - 1]\) because \(r < 2^p\), so \(t = r + (\text{binary expansion of } t - r)\). Hence choosing a subset of pieces is the same as choosing a count \(0..k\), and a 0/1 knapsack over the pieces solves the bounded problem in \(O\big(W \sum_i \log k_i\big)\). \(\square\)

def bounded_knapsack(items, W):
    """items: (weight, value, count). Max value with total weight <= W."""
    d = [0] * (W + 1)
    for w, v, k in items:
        p = 1
        while k > 0:                     # pieces 1, 2, 4, ..., remainder
            t = min(p, k)
            k -= t
            pw, pv = t * w, t * v
            for c in range(W, pw - 1, -1):   # each piece is a 0/1 item
                if d[c - pw] + pv > d[c]:
                    d[c] = d[c - pw] + pv
            p *= 2
    return d[W]

print(bounded_knapsack([(2, 3, 13), (5, 9, 2)], 30))   # 48 = 10 x item 1 + 2 x item 2

An \(O(nW)\) version exists: for a fixed item, the transition for capacities in one residue class mod \(w_i\) is a sliding-window maximum of width \(k_i + 1\), solved with a monotonic deque. L98 finishes it.

More constraints, other axes, and the greedy contrast

  • Two capacities (weight and volume): \(dp[a][b]\), both loops in the same direction as the one-capacity version, \(O(nAB)\). LeetCode 474 (L83) is the 0/1 case.

def largest_number(cost, target):

    dp = [0] + [NEG] * target
    for t in range(1, target + 1):
        for c in cost:
            if c <= t and dp[t - c] != NEG and dp[t - c] + 1 > dp[t]:
                dp[t] = dp[t - c] + 1
    if dp[target] == NEG:
        return "0"
    out, t = [], target
    for d in range(9, 0, -1):
        c = cost[d - 1]
        while c <= t and dp[t - c] == dp[t] - 1 and dp[t - c] != NEG:
            out.append(str(d))
            t -= c
    return "".join(out)

LIS and LCS

55m video

Longest increasing subsequence drops from \(O(n^2)\) to \(O(n \log n)\) once you store, for every length, the smallest possible tail; that array is sorted, so each step is a binary search. Longest common subsequence is the canonical two-sequence table, and the two problems reduce to each other.

LIS in \(O(n^2)\), then the tails array

The direct DP: \(dp[i]\) = length of the longest strictly increasing subsequence ending at \(i\), \(dp[i] = 1 + \max\{dp[j] : j < i,\ a_j < a_i\}\). It is correct by the "ending here" argument of L82, and it is \(O(n^2)\): fine for \(n \le 5000\), hopeless at \(2\cdot 10^5\).

Theorem · Tails invariant

After processing a prefix, let \(T[L]\) be the smallest value that ends some strictly increasing subsequence of length \(L+1\) in that prefix. Then \(T\) is strictly increasing, and processing \(x\) changes exactly one entry: \(T[k] \leftarrow x\) where \(k\) is the first index with \(T[k] \ge x\) (append if none). The LIS length is \(|T|\).

Proof

Sorted: take an increasing run of length \(L+2\) ending in \(T[L+1]\); its first \(L+1\) elements end in a value \(< T[L+1]\), so \(T[L] < T[L+1]\). Update: \(x\) extends any run whose tail is \(< x\); the longest such has length \(k\) (since \(T[k-1] < x \le T[k]\)), giving a run of length \(k+1\) ending in \(x \le T[k]\), so \(T[k]\) becomes \(x\). No other entry changes: for \(L < k\), runs ending in \(x\) of length \(L+1\) end in \(x > T[L]\); for \(L > k\), \(x\) cannot end a run that long. That index \(k\) is bisect_left(T, x). \(\square\)

For non-decreasing subsequences, \(x\) may extend a run ending in a value equal to \(x\), so search for the first \(T[k] > x\): bisect_right. Strictness lives entirely in that one choice.

from bisect import bisect_left, bisect_right
import random

def lis(a, strict=True):
    """One longest strictly increasing (or non-decreasing) subsequence."""
    find = bisect_left if strict else bisect_right
    tails, at, parent = [], [], [-1] * len(a)   # at[L] = index holding tails[L]
    for i, x in enumerate(a):
        k = find(tails, x)
        if k == len(tails):
            tails.append(x); at.append(i)
        else:
            tails[k] = x; at[k] = i
        parent[i] = at[k - 1] if k else -1
    out, i = [], at[-1] if at else -1
    while i != -1:
        out.append(a[i]); i = parent[i]
    return out[::-1]

def lis_len_quadratic(a):
    dp = [1] * len(a)
    for i in range(len(a)):
        for j in range(i):
            if a[j] < a[i] and dp[j] + 1 > dp[i]:
                dp[i] = dp[j] + 1
    return max(dp, default=0)

Variants that reduce to LIS

  • Decreasing: run LIS on the negated array.
  • 2D / nesting (LeetCode 354 Russian Doll Envelopes): sort by width ascending and, for equal widths, height descending, then take a strict LIS on heights. The descending tie-break stops two envelopes of equal width from chaining.
  • Bitonic: \(\max_i \big(\text{inc}[i] + \text{dec}[i] - 1\big)\), with "LIS ending at \(i\)" from the left and "LDS starting at \(i\)" from the right; both come out of the tails loop as \(k+1\).
  • Counting LIS (LeetCode 673): carry \((\text{len}, \text{cnt})\) per index in the \(O(n^2)\) DP, adding counts on ties; \(O(n \log n)\) with a Fenwick tree over values storing (best length, count) pairs (L104).
Theorem · Dilworth for sequences

The minimum number of strictly increasing subsequences that partition \(a\) equals the length of the longest non-increasing subsequence.

Proof

(≥) Two elements of a non-increasing subsequence never fit in the same strictly increasing one. (≤) Label each element with the length of the longest non-increasing subsequence ending at it. If \(i < j\) share a label and \(a_i \ge a_j\), then \(j\) could extend \(i\)'s subsequence and would have a larger label; so each label class is strictly increasing, and there are as many classes as the maximum label. \(\square\)

So "how many increasing chains to cover the sequence?" is answered by one LIS call on the negated array with strict=False.

LCS: the two-sequence table

\(dp[i][j]\) = LCS length of \(a_{1..i}\) and \(b_{1..j}\). Look at the last characters: if \(a_i = b_j\), match them, \(dp[i][j] = dp[i-1][j-1] + 1\) (matching is never worse); otherwise one of them is unused, \(dp[i][j] = \max(dp[i-1][j], dp[i][j-1])\). Reconstruct by walking back from \((n, m)\) along the case that produced each value. The length alone needs only two rows, \(O(\min(n,m))\) memory; the string needs the table, or Hirschberg's divide and conquer.

def lcs(a, b):
    n, m = len(a), len(b)
    dp = [[0] * (m + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        ai, prev, cur = a[i - 1], dp[i - 1], dp[i]
        for j in range(1, m + 1):
            if ai == b[j - 1]:
                cur[j] = prev[j - 1] + 1
            else:
                cur[j] = prev[j] if prev[j] >= cur[j - 1] else cur[j - 1]
    out, i, j = [], n, m
    while i and j:
        if a[i - 1] == b[j - 1]:
            out.append(a[i - 1]); i -= 1; j -= 1
        elif dp[i - 1][j] >= dp[i][j - 1]:
            i -= 1
        else:
            j -= 1
    return "".join(reversed(out))

print(lcs("axyb", "abyxb"))                     # "axb" (length 3; "ayb" is also optimal)

Shortest common supersequence: \(|\text{SCS}| = n + m - |\text{LCS}|\). Merging both strings along an LCS shares exactly the LCS characters; conversely, in any common supersequence of length \(L\), the positions used by both strings form a common subsequence of length at least \(n + m - L\).

LCS ↔ LIS. If \(b\) has distinct characters, replace each character of \(a\) by its position in \(b\) (dropping absent ones); an LCS is then a strict LIS of that sequence, \(O(n \log n)\). With repeats, list each character's positions in \(b\) in decreasing order before running LIS (Hunt–Szymanski), \(O((n + r)\log n)\) for \(r\) matching pairs.

The \(O(nm)\) wall. At \(n = m = 10^5\) the table is \(10^{10}\) cells. The length can be computed bit-parallel: each row of the DP is encoded as one big integer and updated with an add, a subtract and an OR, \(O(nm/w)\) word operations, which CPython's big integers execute in C (the Allison–Dix / Hyyrö scheme):

def lcs_len_bits(a, b):
    full, M = (1 << len(a)) - 1, {}
    for i, ch in enumerate(a):
        M[ch] = M.get(ch, 0) | 1 << i           # positions of ch in a
    V = full
    for ch in b:
        U = V & M.get(ch, 0)
        V = ((V + U) | (V - U)) & full
    return len(a) - bin(V).count("1")

print(lcs_len_bits("axyb", "abyxb"), lcs_len_bits("ABCBDAB", "BDCABA"))   # 3 4

Treat this as a black box with a stress test; edit distance (L88) is the next stop for two-string tables.

def main():

    n, m = len(s), len(t)
    tb = np.frombuffer(t.encode(), dtype=np.uint8)
    dp = np.zeros((n + 1, m + 1), dtype=np.int32)
    for i in range(1, n + 1):
        prev, cand = dp[i - 1], dp[i - 1].copy()
        cand[1:] = np.maximum(prev[1:], prev[:-1] + (tb == ord(s[i - 1])))
        dp[i] = np.maximum.accumulate(cand)
    out, i, j = [], n, m

        if s[i - 1] == t[j - 1]:
            out.append(s[i - 1]); i -= 1; j -= 1
        elif dp[i - 1, j] >= dp[i, j - 1]:
            i -= 1
        else:
            j -= 1

Grid DP and Counting DP

50m video

A grid is a DP exactly when the allowed moves never return to an earlier cell; right and down moves make \(r + c\) a topological order. Within that shape the real decisions are the direction of the DP (forward or backward), how to compress two walkers into one state, and when to replace the table by a formula.

Come from above or from the left

With moves right and down only, every path into \((i, j)\) arrives from \((i-1, j)\) or \((i, j-1)\):

$$dp[i][j] = g_{ij} \oplus \operatorname{combine}\big(dp[i-1][j],\ dp[i][j-1]\big),$$

with combine = + for counting (LeetCode 62 Unique Paths, 63 with obstacles) and min or max for costs (64 Minimum Path Sum, maximum gold collected on a right/down path). Out-of-grid neighbours are the identity: 0 paths, \(+\infty\) cost. Blocked cells hold 0 (counting) or \(\pm\infty\). A single row suffices and can be updated in place: before the update d[j] still holds the cell above, and d[j-1] already holds the cell to the left.

import sys
MOD = 10**9 + 7
def main():                                   # CSES Grid Paths: n x n, '*' = trap
    data = sys.stdin.buffer.read().split()
    n, rows = int(data[0]), data[1:]
    d = [0] * (n + 1)                         # d[j+1] = paths to (i, j); d[0] = wall
    d[1] = 1                                  # seeds the start cell
    for i in range(n):
        row = rows[i]
        for j in range(n):
            if row[j] == 42:                  # b'*'
                d[j + 1] = 0
            else:
                d[j + 1] = (d[j + 1] + d[j]) % MOD   # above + left
    print(d[n])
main()

When a grid problem is not a DP

Theorem · Grids need an acyclic move set

If every move strictly increases a potential such as \(r + c\), the state graph is a DAG and row-major order is topological. With 4-directional movement, \((i, j) \to (i, j+1) \to (i, j)\) is a cycle, so no evaluation order exists; minimum cost is then a shortest-path problem (BFS or 0-1 BFS for small costs, L65; Dijkstra for non-negative costs, L67).

The tell is in the statement: "you may move in any of the four directions" means graph search. CSES's 7×7 Grid Paths path-description puzzle in the Introductory section is a third kind: self-avoiding walks, which need backtracking with pruning, because "cells visited so far" is far too large a state.

Counting: modulus, formulas, and blocked cells

On a clean \(H \times W\) grid every monotone path is a word with \(H-1\) downs and \(W-1\) rights, so the count is \(\binom{H+W-2}{H-1}\): no table needed. With a few blocked cells and a huge grid (AtCoder DP-Y Grid 2: \(H, W \le 10^5\), \(N \le 3000\) walls), count with inclusion–exclusion over the first wall hit. Sort walls by \((r, c)\) and append the target; let \(f_k\) be the number of paths from the start to wall \(k\) that touch no earlier wall:

$$f_k = \binom{r_k + c_k - 2}{r_k - 1} - \sum_{j < k,\ r_j \le r_k,\ c_j \le c_k} f_j \binom{(r_k - r_j) + (c_k - c_j)}{r_k - r_j}.$$

Every bad path is subtracted exactly once, at the first wall it touches. \(O(H + W + N^2)\) with factorials and inverse factorials mod \(p\) precomputed (L119, L122).

import sys
MOD = 10**9 + 7
def main():                                   # AtCoder DP-Y Grid 2
    data = sys.stdin.buffer.read().split()
    H, W, N = int(data[0]), int(data[1]), int(data[2])
    pts = sorted((int(data[3 + 2 * k]), int(data[4 + 2 * k])) for k in range(N))
    pts.append((H, W))
    F = H + W
    fact = [1] * (F + 1)
    for i in range(1, F + 1):
        fact[i] = fact[i - 1] * i % MOD
    inv = [1] * (F + 1)
    inv[F] = pow(fact[F], MOD - 2, MOD)
    for i in range(F, 0, -1):
        inv[i - 1] = inv[i] * i % MOD
    f = []
    for k, (r, c) in enumerate(pts):
        v = fact[r + c - 2] * inv[r - 1] * inv[c - 1]
        for j in range(k):
            rj, cj = pts[j]
            if rj <= r and cj <= c:
                v -= f[j] * fact[r - rj + c - cj] * inv[r - rj] * inv[c - cj]
        f.append(v % MOD)                     # one reduction per k keeps the inner loop lean
    print(f[-1])
main()

Two walkers: one diagonal, one state

LeetCode 741 Cherry Pickup: go from corner to corner and back, collecting cherries once. The return trip reversed is another forward path, so send two walkers forward together. After \(t\) steps both stand on the anti-diagonal \(r + c = t\), so \((t, r_1, r_2)\) determines both cells: \(O(n^3)\) states instead of \(O(n^4)\), each with four predecessors (each walker came from above or from the left). When the walkers share a cell, count it once.

def cherry_pickup(g):                         # LeetCode 741; -1 = thorn
    n, NEG = len(g), -10**9
    dp = [[NEG] * n for _ in range(n)]        # dp[r1][r2] on diagonal t
    dp[0][0] = g[0][0]
    for t in range(1, 2 * n - 1):
        nd = [[NEG] * n for _ in range(n)]
        lo, hi = max(0, t - n + 1), min(n - 1, t)
        for r1 in range(lo, hi + 1):
            if g[r1][t - r1] < 0:
                continue
            for r2 in range(lo, hi + 1):
                if g[r2][t - r2] < 0:
                    continue
                best = dp[r1][r2]                                  # both moved right
                if r1: best = max(best, dp[r1 - 1][r2])            # walker 1 moved down
                if r2: best = max(best, dp[r1][r2 - 1])            # walker 2 moved down
                if r1 and r2: best = max(best, dp[r1 - 1][r2 - 1])
                if best < 0:
                    continue                                       # unreachable
                nd[r1][r2] = best + g[r1][t - r1] + (g[r2][t - r2] if r1 != r2 else 0)
        dp = nd
    return max(0, dp[n - 1][n - 1])

Backwards DP: Dungeon Game

LeetCode 174: a knight walks right/down from the top-left, health changes by each cell's value, and must stay \(\ge 1\) throughout. Find the minimum starting health. Forwards, a state would need both current health and the lowest health so far, and the two trade off. Backwards the state is a single number: \(need[i][j]\) = minimum health on entering \((i, j)\) that suffices from there on, and

$$need[i][j] = \max\Big(1,\ \min\big(need[i+1][j],\ need[i][j+1]\big) - d_{ij}\Big).$$

The constraint is about the future (stay alive until the end), so the DP runs from the end. That is the general rule: run the DP in the direction that makes the remaining requirement a function of the state alone.

def dungeon(d):                               # LeetCode 174
    m, n, INF = len(d), len(d[0]), 10**18
    need = [INF] * (n + 1)                    # the row below; need[n] is the right wall
    need[n - 1] = 1                           # a virtual cell under the goal
    for i in range(m - 1, -1, -1):
        for j in range(n - 1, -1, -1):
            need[j] = max(1, min(need[j], need[j + 1]) - d[i][j])
    return need[0]

print(dungeon([[-2, -3, 3], [-5, -10, 1], [10, 30, -5]]))   # 7

What breaks

  • Grid 2 with an \(O(HW)\) table: \(10^{10}\) cells. Read the constraints first; small \(N\) with huge \(H, W\) means combinatorics.

Interval (Range) DP

55m video

When a problem on a sequence splits into a left part and a right part, the state is a segment \([l, r]\) and the transition picks the split. The step that makes or breaks the DP is choosing which operation defines the split; usually the right choice is the last operation, not the first.

The shape and the mandatory loop order

Definition · Interval DP

\(dp[l][r]\) = answer for the segment \(a_l..a_r\). Typical transition: \(dp[l][r] = \operatorname{opt}_{l \le k < r}\big(dp[l][k] \oplus dp[k+1][r] \oplus \text{cost}(l, k, r)\big)\), with single elements (or empty segments) as base cases.

Theorem · Length order is topological

Every segment read by the transition for \([l, r]\) is strictly shorter. So iterating by increasing length \(r - l\) (any order within a length) computes each value after everything it depends on. Iterating \(l\) upward with \(r\) inner is wrong, because \(dp[k+1][r]\) has \(k+1 > l\) and is not ready yet. Iterating \(l\) downward from \(n-1\) with \(r\) upward from \(l\) also works, for the same reason.

There are \(O(n^2)\) segments and \(O(n)\) splits each: \(O(n^3)\). In Python that means \(n \le\) roughly 200 in CPython and 400–500 in PyPy; beyond that you need Knuth's optimisation (L99) or a different idea.

Matrix chain multiplication

Matrices \(A_1 \cdots A_n\), where \(A_i\) is \(p_{i-1} \times p_i\). Some multiplication is performed last; it splits the chain at some \(k\) into \((A_i \cdots A_k)(A_{k+1} \cdots A_j)\), whose results are \(p_{i-1} \times p_k\) and \(p_k \times p_j\). The two halves are independent, so

$$m[i][j] = \min_{i \le k < j}\ m[i][k] + m[k+1][j] + p_{i-1}\, p_k\, p_j, \qquad m[i][i] = 0.$$

Storing the argmin \(k\) recovers the parenthesisation recursively.

def matrix_chain(p):
    """Matrix i (1-based) is p[i-1] x p[i]. Returns (min scalar mults, parenthesisation)."""
    n = len(p) - 1
    m = [[0] * (n + 1) for _ in range(n + 1)]
    split = [[0] * (n + 1) for _ in range(n + 1)]
    for length in range(2, n + 1):
        for i in range(1, n - length + 2):
            j = i + length - 1
            best = -1
            for k in range(i, j):
                c = m[i][k] + m[k + 1][j] + p[i - 1] * p[k] * p[j]
                if best < 0 or c < best:
                    best, split[i][j] = c, k
            m[i][j] = best
    def paren(i, j):
        if i == j:
            return f"A{i}"
        k = split[i][j]
        return f"({paren(i, k)} {paren(k + 1, j)})"
    return m[1][n], paren(1, n)

print(matrix_chain([30, 35, 15, 5, 10, 20, 25]))   # (15125, '((A1 (A2 A3)) ((A4 A5) A6))')

Burst Balloons: the "last operation" reframe

LeetCode 312: bursting balloon \(k\) earns \(a_{\text{left}} \cdot a_k \cdot a_{\text{right}}\) with its current neighbours. First attempt: choose the first balloon \(k\) to burst in \([l, r]\), then solve \([l, k-1]\) and \([k+1, r]\). This is wrong: once \(k\) is gone, \(k-1\) and \(k+1\) are neighbours, so the halves interact and are not independent subproblems.

Fix: choose the balloon burst last. Pad with 1s at both ends and let \(dp[l][r]\) be the best total for bursting everything strictly between \(l\) and \(r\), which stay alive. If \(k\) is last, then while the others burst, \(k\) stands between the two sides and separates them, and when \(k\) finally bursts its neighbours are exactly \(l\) and \(r\):

$$dp[l][r] = \max_{l < k < r}\ dp[l][k] + dp[k][r] + a_l\, a_k\, a_r.$$ 
def burst_balloons(nums):
    a = [1] + nums + [1]
    n = len(a)
    dp = [[0] * n for _ in range(n)]          # dp[l][r]: balloons strictly inside (l, r)
    for length in range(2, n):
        for l in range(n - length):
            r = l + length
            al, ar, row, best = a[l], a[r], dp[l], 0
            for k in range(l + 1, r):         # k is the last one burst in (l, r)
                c = row[k] + dp[k][r] + al * a[k] * ar
                if c > best:
                    best = c
            row[r] = best
    return dp[0][n - 1]

print(burst_balloons([3, 1, 5, 8]))           # 167

The same question ("what happens last?") fixes most broken interval DPs: the last cut of a stick, the last merge of piles, the last guess in a range.

Palindromes on intervals

  • Longest palindromic subsequence (LeetCode 516): \(dp[l][r] = dp[l+1][r-1] + 2\) if \(s_l = s_r\), else \(\max(dp[l+1][r], dp[l][r-1])\).
  • Minimum insertions to make a palindrome: \(n - \text{LPS}\); every character outside the LPS needs a partner.
  • Palindrome Partitioning II (132, minimum cuts): an interval table \(pal[l][r] = (s_l = s_r) \wedge pal[l+1][r-1]\), then a 1D DP \(cut[i] = \min\{cut[j-1] + 1 : pal[j][i]\}\). \(O(n^2)\), and the 1D layer is cheaper than a full interval DP over cuts.

Merging, cutting, guessing, and circular arrays

  • AtCoder DP-N — Slimes: merge adjacent slimes at cost equal to the merged size. The last merge joins \([l, k]\) and \([k+1, r]\) and always costs \(\text{sum}(l..r)\): \(dp[l][r] = \min_k dp[l][k] + dp[k+1][r] + S(l, r)\) with prefix sums. \(n \le 400\) gives about \(10^7\) inner steps: PyPy, or Knuth's \(O(n^2)\) in L99.
  • LeetCode 1000 — Minimum Cost to Merge Stones (merge exactly \(K\) adjacent piles): \(dp[l][r]\) = min cost to reduce \([l, r]\) to as few piles as possible; split points step by \(K - 1\), and add \(S(l, r)\) when \((r - l) \bmod (K-1) = 0\). Infeasible when \((n-1) \bmod (K-1) \ne 0\).
  • LeetCode 1547 — Minimum Cost to Cut a Stick: add 0 and \(n\) to the sorted cuts; \(dp[i][j] = \min_{i<k<j} dp[i][k] + dp[k][j] + (c_j - c_i)\), where \(k\) is the first cut here, which is fine because cuts do not change neighbours.
  • LeetCode 375 — Guess Number Higher or Lower II: minimax on a range, \(dp[l][r] = \min_k \big(k + \max(dp[l][k-1], dp[k+1][r])\big)\).
  • LeetCode 546 — Remove Boxes: \(dp[l][r]\) is not sufficient, because boxes to the left that match \(a_l\) change the score. Add \(t\) = number of boxes equal to \(a_l\) glued on the left: \(dp[l][r][t]\), \(O(n^4)\) worst case with memoisation.
  • Optimal polygon triangulation: vertices \(0..n-1\), the triangle on edge \((i, j)\) has apex \(k\): the same split shape as matrix chain.
  • Circular arrays: duplicate to \(a_0..a_{n-1}a_0..a_{n-1}\), run the DP on length-\(\le n\) windows of the doubled array, answer \(\operatorname{opt}_s dp[s][s+n-1]\). Same complexity order.

Problems: taking from the ends

AtCoder DP-L — Deque and CSES — Removal Game: players alternately take an end element. Let \(d[l][r]\) be the best (current player − opponent) difference on \([l, r]\); taking \(a_l\) leaves the opponent \(d[l+1][r]\), so \(d[l][r] = \max(a_l - d[l+1][r],\ a_r - d[l][r-1])\). L97 explains this relative-score trick. Rolling by length keeps one list. Removal Game asks for the first player's total, which is \((\text{sum} + d)/2\).

import sys
def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    a = list(map(int, data[1:n + 1]))
    d = a[:]                                   # length 1
    for L in range(2, n + 1):                  # d[l] = best difference on a[l : l+L]
        d = [max(a[l] - d[l + 1], a[l + L - 1] - d[l]) for l in range(n - L + 1)]
    print(d[0])                                # Removal Game: print((sum(a) + d[0]) // 2)

CSES — Rectangle Cutting: an \(a \times b\) rectangle into squares with the fewest straight cuts.   • "First operation" splits whose halves interact (Burst Balloons). If the halves are not independent, change what \(k\) means.

  • Recursive memo on intervals with @cache at \(n = 3000\): about \(4.5\cdot 10^6\) cached entries; memory and time both suffer. Go bottom-up.

String DP: Edit Distance, Matching, and DP on Automata

55m video

Two-string problems share one table, \(dp[i][j]\) over a prefix of each string, and differ only in what the last characters may do. Problems about strings that must contain or avoid a pattern use a different state: (length so far, state of a matching automaton).

The skeleton and edit distance

\(dp[i][j]\) = answer for \(a_{1..i}\) and \(b_{1..j}\); the transition looks at what happens to \(a_i\) and \(b_j\). For edit distance (insert, delete, replace, each cost 1), the last operation in an optimal script either deletes \(a_i\), inserts \(b_j\), or aligns \(a_i\) with \(b_j\) (free if equal):

$$dp[i][j] = \min\big(dp[i-1][j] + 1,\ dp[i][j-1] + 1,\ dp[i-1][j-1] + [a_i \ne b_j]\big), \quad dp[i][0] = i,\ dp[0][j] = j.$$

The cost is \(O(nm)\) time. The value needs only two rows (\(O(\min(n, m))\) memory, iterating the shorter string inside); the operation script needs the table, walked back from \((n, m)\) by checking which case produced each cell.

def edit_distance(a, b):
    n, m = len(a), len(b)
    dp = [[0] * (m + 1) for _ in range(n + 1)]
    for i in range(n + 1): dp[i][0] = i
    for j in range(m + 1): dp[0][j] = j
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            dp[i][j] = min(dp[i - 1][j] + 1, dp[i][j - 1] + 1,
                           dp[i - 1][j - 1] + (a[i - 1] != b[j - 1]))
    ops, i, j = [], n, m
    while i or j:
        if i and j and dp[i][j] == dp[i - 1][j - 1] + (a[i - 1] != b[j - 1]):
            if a[i - 1] != b[j - 1]:
                ops.append(f"replace {a[i - 1]}->{b[j - 1]} at {i - 1}")
            i, j = i - 1, j - 1
        elif i and dp[i][j] == dp[i - 1][j] + 1:
            ops.append(f"delete {a[i - 1]} at {i - 1}"); i -= 1
        else:
            ops.append(f"insert {b[j - 1]} at {i}"); j -= 1
    return dp[n][m], ops[::-1]

print(edit_distance("LOVE", "MOVIE"))   # (2, ['replace L->M at 0', 'insert I at 3'])

CSES Edit Distance and LeetCode 72 use only the value: \(n, m \le 5000\) is \(2.5\cdot 10^7\) cells, which is PyPy territory with two rolled rows.

Variants on the same table

  • Distinct Subsequences (LeetCode 115, ways \(t\) occurs as a subsequence of \(s\)): \(dp[i][j] = dp[i-1][j] + [s_i = t_j]\, dp[i-1][j-1]\). Rolled over \(j\), iterate \(j\) downwards, exactly the 0/1-knapsack direction.
  • Delete Operation for Two Strings: \(n + m - 2\,\text{LCS}\). Minimum ASCII Delete Sum (712): LCS-shaped, with \(\min(dp[i-1][j] + \text{ord}(a_i),\ dp[i][j-1] + \text{ord}(b_j))\) on a mismatch.
  • One edit apart: no table at all. Skip the common prefix, then compare the rest under the three possible edits, \(O(n)\).
  • Interleaving String (97): \(dp[i][j]\) = whether \(s_3[:i+j]\) interleaves \(s_1[:i]\) and \(s_2[:j]\); the last character of \(s_3\) came from \(s_1\) or from \(s_2\). Check \(|s_1| + |s_2| = |s_3|\) first.
  • Scramble String (87): no prefix structure, so memoise on substring pairs \((i, j, \text{len})\) and try every split, with and without swapping the halves: \(O(n^4)\), fine for \(n \le 30\). Prune when the two substrings have different letter counts.

Wildcards and regular expressions: getting * right

\(dp[i][j]\) = does \(s[:i]\) match \(p[:j]\)? Ordinary characters and the single-character wildcard (? or .) step diagonally. The star is where solutions fail, so tabulate its two cases explicitly:

Pattern ends withZero occurrencesOne more occurrence (star stays)
wildcard * (LeetCode 44): any sequence\(dp[i][j-1]\)\(dp[i-1][j]\) for any \(s_i\)
regex x* (LeetCode 10): zero or more x\(dp[i][j-2]\): drop x* entirely\(dp[i-1][j]\) if \(s_i\) matches x (or x is .)

"One more occurrence" consumes a character of \(s\) but keeps the star in the pattern, which is why it reads \(dp[i-1][j]\) and not \(dp[i-1][j-1]\). Both loops must start at \(i = 0\): an empty string can match a*b*.

def regex_match(s, p):                    # LeetCode 10 (pattern assumed valid)
    n, m = len(s), len(p)
    dp = [[False] * (m + 1) for _ in range(n + 1)]
    dp[0][0] = True
    for i in range(n + 1):
        for j in range(1, m + 1):
            if p[j - 1] == '*':
                dp[i][j] = dp[i][j - 2] or (i > 0 and p[j - 2] in (s[i - 1], '.') and dp[i - 1][j])
            else:
                dp[i][j] = i > 0 and p[j - 1] in (s[i - 1], '.') and dp[i - 1][j - 1]
    return dp[n][m]

def wildcard_match(s, p):                 # LeetCode 44
    n, m = len(s), len(p)
    dp = [[False] * (m + 1) for _ in range(n + 1)]

DP over an automaton

"How many strings of length \(n\) contain (or avoid) pattern \(P\)?" The state is not a position in a given string but how much of \(P\) is currently matched.

Definition · Automaton DP

Let \(j\) be the KMP state: the length of the longest prefix of \(P\) that is a suffix of the text written so far (L38). Appending \(c\) moves \(j\) to \(\delta(j, c)\), and \(j = |P|\) means \(P\) just appeared. Define \(dp[t][j]\) = number of length-\(t\) strings in state \(j\) that have not contained \(P\); then \(dp[t+1][\delta(j,c)] \mathrel{+}= dp[t][j]\) for every \(c\) with \(\delta(j, c) < |P|\). The state is sufficient because the future of a partial string depends only on \(j\).

The number of strings containing \(P\) is \(\sigma^n\) minus the avoiders, at a cost of \(O(n \cdot |P| \cdot \sigma)\). With several patterns, replace the KMP automaton by Aho–Corasick (L43) and forbid every node whose suffix-link chain contains a pattern end.

MOD = 10**9 + 7

def kmp_automaton(p, alphabet):
    m, pi = len(p), [0] * len(p)
    for i in range(1, m):
        k = pi[i - 1]
        while k and p[i] != p[k]:
            k = pi[k - 1]
        pi[i] = k + (p[i] == p[k])
    nxt = [[0] * len(alphabet) for _ in range(m)]
    for j in range(m):
        for c, ch in enumerate(alphabet):
            nxt[j][c] = j + 1 if p[j] == ch else (nxt[pi[j - 1]][c] if j else 0)
    return nxt                             # nxt[j][c] == m: the pattern just appeared

def count_avoiding(n, p, alphabet):
    m, nxt = len(p), kmp_automaton(p, alphabet)
    dp = [1] + [0] * (m - 1)               # dp[j]: strings so far in automaton state j
    for _ in range(n):
        nd = [0] * m
        for j, ways in enumerate(dp):
            if ways:
                for k in nxt[j]:
                    if k < m:
                        nd[k] = (nd[k] + ways) % MOD
        dp = nd
    return sum(dp) % MOD

When hashing or bitsets beat the table

  • LCS length at \(10^5 \times 10^5\): the bit-parallel row of L85.
  • Edit distance known to be at most \(k\): only cells with \(|i - j| \le k\) can lie on an optimal path, so a band of width \(2k + 1\) gives \(O(nk)\).
  • "Equal up to \(k\) mismatches" or "longest common substring": hashing with binary search on LCP (L37) is \(O(n \log n)\) or \(O(nk \log n)\) instead of \(O(nm)\).
What breaks
  • Regex star read as \(dp[i-1][j-1]\): it then matches exactly one occurrence. The star stays in the pattern.
  • Starting i at 1 in the matching loops: empty strings against a* or * come out False.
  • Negative indices: p[j - 2] with \(j = 1\) silently reads the last character in Python. Guard it if the pattern may start with *.
  • Automaton DP counting strings that contain \(P\) directly without an absorbing "seen" state: once matched, the state can fall back and the string is counted again later. Count avoiders, or add an absorbing state.
  • Distinct Subsequences rolled with \(j\) ascending: one character of \(s\) gets matched to several characters of \(t\).

Tree DP I: Subtree Aggregation and Tree Knapsack

55m video

On a rooted tree the subtrees are the subproblems and post-order is the topological order: compute each node from its children's answers. The design work is choosing what a child must report upward (often two numbers, "with me" and "without me"), and, for knapsack-style merges, bounding each merge by subtree sizes so the total is \(O(n^2)\), not \(O(n^3)\).

The pattern, iteratively

Root the tree, get any order in which parents precede children (BFS order works), and process it in reverse: every child is finished before its parent. This replaces recursive DFS, which hits Python's recursion limit on a path of \(2\cdot 10^5\) nodes (L55). The cleanest style is push-up: when a node finishes, it adds its contribution into its parent's accumulators.

def bfs_order(n, adj, root=0):
    parent = [-1] * n
    parent[root] = root                     # mark as seen
    order = [root]
    for v in order:                         # the list grows while we iterate: BFS
        for u in adj[v]:
            if parent[u] == -1:
                parent[u] = v
                order.append(u)
    parent[root] = -1
    return order, parent

def max_weight_independent_set(n, edges, w):
    adj = [[] for _ in range(n)]
    for a, b in edges:
        adj[a].append(b); adj[b].append(a)
    order, parent = bfs_order(n, adj)
    take, skip = w[:], [0] * n              # best in subtree(v) with v taken / not taken
    for v in reversed(order):               # children first
        p = parent[v]
        if p >= 0:
            take[p] += skip[v]              # p taken: v must be skipped
            skip[p] += max(take[v], skip[v])
    return max(take[0], skip[0])

edges = [(0, 1), (0, 2), (1, 3), (1, 4), (2, 5)]

Two values per node

Theorem · Include/exclude recurrence

For the maximum-weight independent set, \(take[v] = w_v + \sum_{c} skip[c]\) and \(skip[v] = \sum_c \max(take[c], skip[c])\), over the children \(c\) of \(v\).

Proof

Once we know whether \(v\) is in the set, the children's subtrees interact only through their edges to \(v\), so they are independent. If \(v\) is taken, no child may be, and each child's subtree contributes its best with the child excluded. If \(v\) is not taken, each child's subtree is unconstrained. One number per node is not sufficient, because the parent's choice depends on whether the child is in the set; that is why every child reports both. \(\square\)

The classics

  • Subtree sizes and sums: push \(size[v]\) into \(size[parent]\). CSES Subordinates prints \(size[v] - 1\).
  • Minimum vertex cover: \(in[v] = 1 + \sum \min(in[c], out[c])\), \(out[v] = \sum in[c]\) (every child edge must be covered by the child). Unweighted, it also equals \(n - \text{MIS}\), since a cover's complement is independent.
  • Tree matching (CSES Tree Matching): here the extra state is "is \(v\)'s edge to a child used". \(f_0[v] = \sum_c \max(f_0[c], f_1[c])\) with \(v\) unmatched; \(f_1[v] = f_0[v] + \max_c \big(f_0[c] + 1 - \max(f_0[c], f_1[c])\big)\), matching \(v\) to the best child. Equivalently, the edge to the parent is a resource the child either consumes or leaves.
  • Counting colourings (AtCoder DP-P Independent Set, no two adjacent black): \(white[v] = \prod (white[c] + black[c])\), \(black[v] = \prod white[c]\), modulo \(10^9+7\).
  • Leaves at each depth, longest root-to-leaf path, number of nodes with a property in each subtree: all single-value push-ups.

Diameter and path-through-node patterns

A longest path has a highest node \(v\), and it descends from \(v\) into two different child subtrees. So keep the two largest values of \(down[c] + w(v, c)\) over children, and the diameter is \(\max_v (\text{best}_1[v] + \text{best}_2[v])\). With edge weights the recurrence is the same with \(w\) in place of 1. The pattern generalises to any "best path" question: LeetCode 2246 Longest Path With Different Adjacent Characters only lets child \(c\) contribute when its character differs from \(v\)'s.

CSES — Tree Distances I (for every node, the distance to the farthest node) has a two-line answer once you have a diameter \(A\!-\!B\): the farthest node from any \(v\) is \(A\) or \(B\), so two BFS runs from the endpoints give \(\max(d_A(v), d_B(v))\). L90 solves the same problem by rerooting, which generalises when no such shortcut exists.

Tree knapsack and the \(O(n^2)\) merge

Choose exactly \(k\) nodes, maximising total value, such that a chosen node's parent is also chosen (prerequisite trees). State: \(dp[v][j]\) = best value with \(j\) nodes chosen in \(v\)'s subtree (\(v\) chosen when \(j \ge 1\)). Children merge one at a time like knapsack items, where child \(c\) offers "\(b\) nodes for \(dp[c][b]\)":

$$\text{new}[a + b] = \max\big(\text{new}[a+b],\ cur[a] + dp[c][b]\big), \quad 1 \le a \le |\text{merged so far}|,\ 0 \le b \le |T_c|.$$
Theorem · Size-bounded merging is \(O(n^2)\)

If each merge loops only up to the current sizes, the total work over the whole tree is \(O(n^2)\); capping both sides at \(k\) gives \(O(nk)\).

Proof

Merging child subtree \(T_c\) into the part of \(T_v\) already merged, \(P\), costs \(|P| \cdot |T_c|\), which is the number of node pairs \((x, y)\) with \(x \in P,\ y \in T_c\). Such a pair is counted at exactly one merge: the one at \(\operatorname{lca}(x, y)\) that first joins their sides. There are at most \(n^2\) pairs, so the total is \(O(n^2)\). Looping both indices to \(n\) (or to \(k\) without size bounds) instead costs \(O(n^3)\) or \(O(nk^2)\). \(\square\)

def tree_knapsack(parent, val, k):
    """Rooted at 0, parent[v] < v for v > 0. Pick exactly k nodes, each with its parent picked."""
    n = len(val)
    children = [[] for _ in range(n)]
    for v in range(1, n):
        children[parent[v]].append(v)
    order = [0]
    for v in order:
        order.extend(children[v])
    dp = [None] * n
    for v in reversed(order):
        cur = [0, val[v]]                   # cur[j]: j nodes picked; v picked if j >= 1
        for c in children[v]:
            ch = dp[c]
            new = cur + [None] * (len(ch) - 1)
            for a in range(1, len(cur)):    # bounded by the merged size so far
                ca = cur[a]
                for b in range(1, len(ch)):
                    s = ca + ch[b]
                    if new[a + b] is None or s > new[a + b]:
                        new[a + b] = s
            cur = new[:k + 1]
            dp[c] = None                    # release the child's table
        dp[v] = cur
    return dp[0][k] if k < len(dp[0]) else None

print(tree_knapsack([0, 0, 0, 1, 1, 2], [1, 5, 2, 7, 1, 9], 3))   # 13: nodes 0, 1, 3 (beats 0, 2, 5 = 12)

Tree DP II: Rerooting (All-Roots DP)

55m video

To answer a tree DP for every possible root in \(O(n)\) total, compute each node's view from below (its subtree) in one pass and its view from above (everything else) in a second pass. The view from above is assembled from the parent's own view from above plus the siblings' subtrees, using prefix and suffix aggregates so that no operation ever needs to be undone.

From \(O(n^2)\) to two passes

Running L89's DP from every root costs \(n\) passes of \(O(n)\). But with root \(v\), the tree splits into one "side" per neighbour of \(v\), and the answer at \(v\) is a combination of those sides' contributions. Each side is either a subtree of the original rooting (neighbour is a child) or the complement of \(v\)'s own subtree (neighbour is the parent). So two quantities suffice:

Definition · down and up

Root the tree at 0. \(down[v]\) = contribution of \(v\)'s subtree to its parent (first pass, children before parents). \(up[v]\) = contribution of everything outside \(v\)'s subtree to \(v\), seen through the edge to \(v\)'s parent (second pass, parents before children). The answer at \(v\) combines \(up[v]\) with \(down[c]\) for all children \(c\).

Theorem · The up recurrence

For a child \(c\) of \(p\): \(up[c] = \mathrm{add\_node}\Big(up[p] \oplus \bigoplus_{s \in \text{children}(p),\ s \ne c} down[s],\ p\Big)\), where \(\oplus\) is the associative merge and add_node turns "everything hanging below \(p\) on this side" into \(p\)'s side's contribution across the edge \((p, c)\).

Proof

Seen from \(c\), the side through \(p\) consists of \(p\) itself, the part above \(p\), and the subtrees of \(p\)'s other children. These are disjoint and meet only at \(p\), so their contributions merge, and \(p\) is then added on top exactly as in the first pass. \(up[p]\) is final before any child of \(p\) is processed because the second pass runs in BFS order. Induct on depth. \(\square\)

Excluding one child without division

The tempting shortcut is \(up[c] = \mathrm{add\_node}(\text{all}[p] \ominus down[c], p)\): take everything at \(p\) and remove \(c\)'s part. That works when \(\oplus\) has an inverse (plain sums), and fails otherwise:

  • max / min: if \(c\) held the maximum, \(\text{all}[p]\) no longer remembers the second-largest value.
  • products mod \(M\): dividing needs an inverse of \(down[c]\), which does not exist when \(M\) is composite (AtCoder DP-V's \(M\) is arbitrary) or when \(down[c] \equiv 0\).
  • gcd, bitwise OR, "best two": no inverse at all.

The always-correct method: for \(p\)'s children \(c_1..c_k\), compute prefix merges \(P_i = up[p] \oplus down[c_1] \oplus \cdots \oplus down[c_{i-1}]\) and suffix merges \(S_i = down[c_{i+1}] \oplus \cdots \oplus down[c_k]\); then "all except \(c_i\)" is \(P_i \oplus S_i\). Only associativity is needed, and the cost is \(O(\deg p)\) merges per node, \(O(n)\) overall.

The template

Fix a monoid \((\oplus, e)\) for contributions and a function add_node(acc, u) that turns "merged contributions hanging below \(u\)" into \(u\)'s contribution across the edge to whoever is asking. The helper returns, for every \(v\), the merge of all its neighbours' contributions with \(v\) as root; the answer is usually that value or add_node of it.

def reroot(n, adj, merge, identity, add_node, root=0):
    parent, order = [-1] * n, [root]
    parent[root] = root
    for v in order:                                  # BFS order
        for u in adj[v]:
            if parent[u] == -1:
                parent[u] = v
                order.append(u)
    parent[root] = -1
    children = [[] for _ in range(n)]
    for v in order[1:]:
        children[parent[v]].append(v)
    down = [identity] * n
    for v in reversed(order):                        # pass 1: subtrees
        acc = identity
        for c in children[v]:
            acc = merge(acc, down[c])
        down[v] = add_node(acc, v)
    up, full = [identity] * n, [identity] * n
    for v in order:                                  # pass 2: everything else
        ch = children[v]
        suf = [identity] * (len(ch) + 1)
        for i in range(len(ch) - 1, -1, -1):
            suf[i] = merge(down[ch[i]], suf[i + 1])
        pre = up[v]                                  # identity at the root
        for i, c in enumerate(ch):
            up[c] = add_node(merge(pre, suf[i + 1]), v)
            pre = merge(pre, down[c])
        full[v] = pre                                # up[v] merged with every child
    return full

def build(n, edges):
    adj = [[] for _ in range(n)]
    for a, b in edges:
        adj[a].append(b); adj[b].append(a)
    return adj

Bitmask DP I: Subsets as States

55m video

When \(n \le 20\) and the problem cares about which items are used rather than in what order, the used set itself is the state: \(2^n\) masks, sometimes paired with a "last element". Increasing numeric order of masks is a valid evaluation order whenever transitions only add bits, and the popcount of a mask often makes a second index unnecessary.

Shapes and the evaluation order

  • \(dp[mask]\): the best way to have handled exactly the items in mask (assignment, grouping, covering).
  • \(dp[mask][i]\): additionally remember the last item, when the cost of the next step depends on it (paths, tours, superstrings).
Theorem · Increasing masks are a topological order

If every transition goes from mask to a proper superset mask | add with add & ~mask ≠ 0, then for mask in range(1 << n) processes every state after all of its predecessors.

Proof

Setting at least one new bit adds a positive power of two and clears nothing, so the integer value strictly increases along every transition. A strictly increasing potential on a DAG makes increasing order topological. The same holds for "pull" transitions from proper submasks. \(\square\)

The order breaks when a transition can keep the mask unchanged. LeetCode 847 Shortest Path Visiting All Nodes moves along edges and may revisit nodes, so \((mask, v) \to (mask, u)\) is possible and the state graph has cycles; it is a BFS over \(2^n \cdot n\) states, not a mask-order DP.

TSP: \(dp[mask][last]\)

\(dp[S][i]\) = shortest path that starts at city 0, visits exactly the set \(S\) (which contains 0 and \(i\)), and ends at \(i\). The last step came from some \(j \in S \setminus \{i\}\): \(dp[S][i] = \min_j dp[S \setminus \{i\}][j] + d(j, i)\). The tour is \(\min_i dp[\text{all}][i] + d(i, 0)\). There are \(2^n n\) states and \(n\) transitions each: \(O(2^n n^2)\). Store the argmin to reconstruct. Only masks containing city 0 matter, which halves the work.

def tsp(dist):
    """Shortest Hamiltonian cycle through city 0: (cost, tour)."""
    n, INF = len(dist), 1 << 60
    FULL = 1 << n
    dp = [INF] * (FULL * n)                  # flat: dp[mask * n + i]
    par = [-1] * (FULL * n)
    dp[1 * n + 0] = 0
    for mask in range(1, FULL, 2):           # odd masks = those containing city 0
        base = mask * n
        for i in range(n):
            cur = dp[base + i]
            if cur == INF:
                continue
            row = dist[i]
            for j in range(n):
                if not mask >> j & 1:
                    k = (mask | 1 << j) * n + j
                    if cur + row[j] < dp[k]:
                        dp[k], par[k] = cur + row[j], i
    full = FULL - 1
    best, i = min((dp[full * n + i] + dist[i][0], i) for i in range(1, n))
    tour, mask = [], full
    while i != -1:                           # walk the parent pointers back to city 0
        tour.append(i)
        i, mask = par[mask * n + i], mask ^ (1 << i)
    return best, tour[::-1] + [0]

d = [[0, 10, 15, 20], [10, 0, 35, 25], [15, 35, 0, 30], [20, 25, 30, 0]]
print(tsp(d))                                # (80, [0, 2, 3, 1, 0])

The flat list avoids a list of \(2^n\) inner lists. At \(n = 20\) it holds \(2^{20}\cdot 20 \approx 2.1\cdot 10^7\) slots, about 170 MB of pointers alone; array('i') cuts that to about 84 MB when the values fit in 32 bits. Time is the harder wall: \(2^{20}\cdot 20^2 \approx 4\cdot 10^8\) steps is out of reach for CPython and heavy even for PyPy.

Popcount as the row index: assignment in \(O(2^n n)\)

Assign \(n\) workers to \(n\) jobs. The natural state is (next worker, set of jobs taken), but the next worker is always mask.bit_count() if workers are assigned in order. So \(dp[mask]\) alone suffices, and \(dp[mask \cup \{j\}] \leftarrow dp[mask] + cost[\text{popcount}(mask)][j]\): \(O(2^n n)\) instead of \(O(2^n n^2)\). AtCoder DP-O Matching (count perfect matchings, \(n \le 21\)) is the counting version; iterate only the compatible free jobs with the low-bit trick.

MOD = 10**9 + 7
def count_matchings(ok):                     # ok[i][j]: man i may pair with woman j
    n = len(ok)
    rows = [sum(1 << j for j in range(n) if ok[i][j]) for i in range(n)]
    dp = [0] * (1 << n)
    dp[0] = 1
    for mask in range((1 << n) - 1):        # the full mask has no successors
        if dp[mask]:
            free = rows[mask.bit_count()] & ~mask   # next man = popcount
            while free:
                low = free & -free
                dp[mask | low] = (dp[mask | low] + dp[mask]) % MOD
                free ^= low
    return dp[-1]

print(count_matchings([[0, 1, 1], [1, 0, 1], [1, 1, 1]]))   # 3 (AtCoder DP-O sample)

Partitioning into groups over submasks: \(O(3^n)\)

"Split the items into groups, each group's value depending only on its members" is \(dp[mask] = \operatorname{opt}_{sub \subseteq mask} \big(dp[mask \setminus sub] \oplus val[sub]\big)\). Enumerating submasks with sub = (sub - 1) & mask costs \(\sum_{mask} 2^{|mask|} = 3^n\) in total (each item is outside, in the rest, or in sub; L8). Requiring sub to contain the lowest set bit of mask fixes which group is "first", removes duplicate orderings, and halves the work.

def best_partition(n, val):                  # AtCoder DP-U Grouping shape
    """val[sub] = value of one group; returns the max total over all partitions."""
    dp = [0] * (1 << n)
    for mask in range(1, 1 << n):
        low = mask & -mask
        rest = mask ^ low
        best, sub = -1 << 60, rest
        while True:                          # every submask of rest, including 0
            g = sub | low                    # the group containing the lowest item
            c = val[g] + dp[mask ^ g]
            if c > best:
                best = c
            if sub == 0:
                break
            sub = (sub - 1) & rest
        dp[mask] = best
    return dp[-1]

def group_scores(a):                         # val[mask] = sum of a[i][j] over pairs in mask
    n = len(a)
    val = [0] * (1 << n)
    for mask in range(1, 1 << n):
        v = (mask & -mask).bit_length() - 1
        r = mask & (mask - 1)
        val[mask] = val[r] + sum(a[v][u] for u in range(n) if r >> u & 1)
    return val

Bitmask DP II: Profile and Broken-Profile DP

50m video

On a grid with one short side, sweep along the long side and keep as state only the boundary between the processed and unprocessed parts: a bitmask over the short side. Profile DP moves the boundary a whole column at a time; broken-profile DP moves it one cell at a time, so each state has at most two transitions and constraints such as forbidden cells drop in naturally.

The signal and the state

"Count tilings / colourings of an \(n \times m\) grid with \(n \le 10\) and \(m \le 1000\)" is the signal: \(2^n\) is small, \(2^{nm}\) is not. Process columns left to right. For domino tilings, the only thing column \(c\) passes to column \(c+1\) is which cells of column \(c+1\) are already covered by horizontal dominoes sticking out of column \(c\). That set is the profile, a mask of \(n\) bits, and it is sufficient: how column \(c\) was tiled internally cannot affect anything to the right.

Profile DP: column to column

Theorem · Domino transition validity

Incoming profile \(a\) (cells of column \(c\) pre-covered from the left) can lead to outgoing profile \(b\) (cells of column \(c+1\) covered by horizontals starting in column \(c\)) if and only if \(a \mathbin{\&} b = 0\) and every maximal run of zero bits in \(a \mathbin{|} b\) has even length.

Proof

A cell of column \(c\) is covered by exactly one of: a domino from the left (bit in \(a\)), a domino going right (bit in \(b\)), or a vertical domino inside the column. It cannot be both of the first two, hence \(a \mathbin{\&} b = 0\). The remaining cells must be paired by vertical dominoes, which pair adjacent cells, and a run of consecutive free cells can be paired exactly when its length is even. \(\square\)

Checking all \(2^n \times 2^n\) pairs per column is \(4^n\) work. Instead, precompute each mask's compatible successors once with a small DFS down the column; for \(n = 10\) there are only 5,741 compatible pairs in total, so a column costs 5,741 additions.

MOD = 10**9 + 7

def tilings_profile(n, m):                   # n rows (short side), m columns
    full = 1 << n
    succ = [[] for _ in range(full)]
    def fill(a, r, b, out):                  # cover column cells r.. given incoming a
        if r >= n:
            out.append(b); return
        if a >> r & 1:
            fill(a, r + 1, b, out)                       # pre-covered from the left
            return
        fill(a, r + 1, b | 1 << r, out)                  # horizontal into column c+1
        if r + 1 < n and not a >> (r + 1) & 1:
            fill(a, r + 2, b, out)                       # vertical
    for a in range(full):
        fill(a, 0, 0, succ[a])
    dp = [0] * full
    dp[0] = 1
    for _ in range(m):
        nd = [0] * full
        for a, v in enumerate(dp):
            if v:
                for b in succ[a]:
                    nd[b] = (nd[b] + v) % MOD
        dp = nd
    return dp[0]                             # nothing may stick out past the last column

print(tilings_profile(2, 3), tilings_profile(3, 4), tilings_profile(8, 8))   # 3 11 12988816

Broken profile: one cell at a time

Process cells column by column, top to bottom inside a column. The mask now describes a staircase boundary: bits for rows above the current row \(r\) refer to column \(c+1\), bits from \(r\) down refer to column \(c\). At cell \((r, c)\) with bit \(r\) of the mask:

  • bit set: the cell is already covered from the left. Clear the bit (cell \((r, c+1)\) is not covered yet) and move on. One transition.
  • bit clear: place a horizontal domino (set bit \(r\), meaning \((r, c+1)\) is now covered), or a vertical one if \(r + 1 < n\) and bit \(r+1\) is clear (set bit \(r+1\): the cell below is covered). At most two transitions.

So each state has at most 2 successors instead of up to \(2^n\), the transition rule is three lines with nothing to precompute, and a forbidden cell is just "treat as already covered, and never place a domino onto it".

MOD = 10**9 + 7

def tilings_broken(n, m, blocked=frozenset()):
    full = 1 << n
    dp = [0] * full
    dp[0] = 1
    for c in range(m):
        for r in range(n):
            bit, nd = 1 << r, [0] * full
            below = 1 << (r + 1) if r + 1 < n else 0
            hole = (r, c) in blocked
            right_ok = c + 1 < m and (r, c + 1) not in blocked
            down_ok = below and (r + 1, c) not in blocked
            for mask, v in enumerate(dp):
                if not v:
                    continue
                if mask & bit:                       # covered from the left
                    nd[mask ^ bit] = (nd[mask ^ bit] + v) % MOD
                elif hole:                           # forbidden cell: leave it empty
                    nd[mask] = (nd[mask] + v) % MOD
                else:
                    if right_ok:
                        nd[mask | bit] = (nd[mask | bit] + v) % MOD
                    if down_ok and not mask & below:
                        nd[mask | below] = (nd[mask | below] + v) % MOD
            dp = nd
    return dp[0]

print(tilings_broken(8, 8), tilings_broken(3, 3, {(1, 1)}), tilings_broken(4, 4, {(0, 0), (3, 3)}))

from itertools import product
def paint_n_by_3(n, MOD=10**9 + 7):
    rows = [r for r in product(range(3), repeat=3) if r[0] != r[1] != r[2]]
    ok = [[j for j, s in enumerate(rows) if all(x != y for x, y in zip(r, s))] for r in rows]

  • Answer read from the wrong mask: after the last column the profile must be 0, because nothing may stick out of the grid.

  • Modulus forgotten in the inner loop: counts for \(10 \times 1000\) have hundreds of digits.

SOS DP (Sum Over Subsets) and Subset Convolution

50m video

"For every mask, aggregate over all of its submasks" is a prefix sum on the hypercube, and like a 2D prefix sum it can be taken one dimension at a time: \(n\) rounds over \(2^n\) masks, \(O(2^n n)\) instead of \(O(3^n)\). The same round structure with a different 2×2 step gives the superset sum, its inverse, and the Walsh–Hadamard transform for XOR convolution.

The problem and the naive cost

Definition · Zeta transform over subsets

Given \(f : 2^{[n]} \to \mathbb{Z}\), its subset sum (zeta transform) is \(F[S] = \sum_{T \subseteq S} f[T]\), and its superset sum is \(G[S] = \sum_{T \supseteq S} f[T]\).

Enumerating submasks of every mask costs \(\sum_S 2^{|S|} = 3^n\) (L8): \(3.5\cdot 10^9\) at \(n = 20\). Instead, treat a mask as a point in \(\{0,1\}^n\); \(T \subseteq S\) means \(T \le S\) in every coordinate, so \(F\) is an \(n\)-dimensional prefix sum, computable one axis at a time.

SOS in \(O(2^n n)\), and why it is correct

Algorithm · SOS DP
  1. Start with \(F = f\).
  2. For each bit \(i = 0, \dots, n-1\) (outer loop), for every mask \(S\) containing bit \(i\): \(F[S] \mathrel{+}= F[S \oplus 2^i]\).
Theorem · Invariant

After rounds \(0..i-1\), \(F[S] = \sum f[T]\) over the \(T \subseteq S\) that agree with \(S\) on every bit \(\ge i\). After all \(n\) rounds, \(F[S] = \sum_{T \subseteq S} f[T]\).

Proof

True before round 0 (only \(T = S\) agrees everywhere). In round \(i\), if \(S\) lacks bit \(i\), so must every \(T \subseteq S\), and the set of allowed \(T\) is already right. If \(S\) has bit \(i\), the allowed \(T\) after the round have bit \(i\) either 1 (counted in the old \(F[S]\)) or 0 (counted in the old \(F[S \oplus 2^i]\)); the two groups are disjoint, so adding gives the new invariant. In-place updates are safe because \(S \oplus 2^i\) lacks bit \(i\) and is never written in round \(i\). \(\square\)

The bit loop must be outside. With the mask loop outside and bits inside, a subset reachable along two different bit orders is added twice. Any order of masks inside a round is fine.

Three transforms, one loop

Every transform below is \(n\) rounds; in round \(i\) each pair \((a, b) = (F[S], F[S \cup 2^i])\) with \(i \notin S\) is replaced by a 2×2 combination:

superset zeta(a + b, b)(a − b, b)AND-convolution
Walsh–Hadamard(a + b, a − b)same, then divide by \(2^n\)XOR-convolution

The Möbius transform \(f[S] = \sum_{T \subseteq S} (-1)^{|S \setminus T|} F[T]\) is inclusion–exclusion; undoing each round in turn computes it in \(O(2^n n)\). "OR-convolution" means \(h[S] = \sum_{A \cup B = S} f[A]\, g[B]\): transform both, multiply pointwise, invert.

def zeta_sub(f, n):                         # F[S] = sum of f[T], T subset of S
    F = f[:]
    for i in range(n):
        bit = 1 << i
        for S in range(1 << n):
            if S & bit:
                F[S] += F[S ^ bit]
    return F

def mobius_sub(F, n):                       # inverse of zeta_sub
    f = F[:]
    for i in range(n):
        bit = 1 << i
        for S in range(1 << n):
            if S & bit:
                f[S] -= f[S ^ bit]
    return f

def zeta_sup(f, n):                         # G[S] = sum of f[T], T superset of S
    G = f[:]
    for i in range(n):
        bit = 1 << i
        for S in range(1 << n):
            if not S & bit:
                G[S] += G[S | bit]
    return G

def wht(a, invert=False):                   # Walsh-Hadamard, len(a) a power of 2
    a, h = a[:], 1
    while h < len(a):
        for i in range(0, len(a), 2 * h):
            for j in range(i, i + h):
                x, y = a[j], a[j + h]
                a[j], a[j + h] = x + y, x - y
        h *= 2
    return [x // len(a) for x in a] if invert else a

def xor_convolution(f, g):
    return wht([x * y for x, y in zip(wht(f), wht(g))], invert=True)

Applications

  • For each mask, how many array elements are submasks of it: \(f[x] = \) count of \(x\), then subset zeta.
  • Pairs with \(a \mathbin{\&} b = 0\): \(b\) must be a submask of \(\bar a\) (complement within \(n\) bits), so the count of partners of \(a\) is \(F[\bar a]\). Codeforces Compatible Numbers asks for one witness per element instead of a count: run the same rounds storing "any element that is a submask of \(S\)" instead of sums.
  • Max (or top-two) over submasks: replace \(+\) by max; idempotent operations never double count, so even the overlap concern disappears. AtCoder ARC 100 E Or Plus Max keeps the top two values per mask.
  • Complement counting: Codeforces Vowels (3-letter words, 24 letters): for each vowel set \(S\), words containing a vowel = \(n\) − words using only letters outside \(S\) = \(n - F[\bar S]\). Subset convolution

\(h[S] = \sum_{T \subseteq S} f[T]\, g[S \setminus T]\) requires the two parts to be disjoint, which OR-convolution does not enforce. Track sizes: let \(\hat f_k\) be the zeta transform of \(f\) restricted to masks of popcount \(k\), and similarly \(\hat g_k\). Then \(\hat h_k = \sum_{i + j = k} \hat f_i \cdot \hat g_j\) pointwise, and \(h[S]\) is the Möbius inverse of \(\hat h_{|S|}\) read at \(S\). The size bookkeeping kills overlapping pairs, because \(|A \cup B| = |A| + |B|\) exactly when \(A \cap B = \varnothing\). Cost \(O(2^n n^2)\) against \(O(3^n)\) naively. Library Checker (judge.yosupo.jp) has Subset Convolution, Bitwise And Convolution and Bitwise Xor Convolution as test beds.

What breaks
  • Loops swapped (masks outer, bits inner): overcounts. Bits outer, always.
  • Complement without masking: ~a in Python is negative. Use full ^ a with full = (1 << n) - 1.
  • Using \(n\) = number of elements instead of the number of bits: size the table by the value range, \(2^{\lceil \log_2 (\max+1) \rceil}\).
  • WHT under a modulus: dividing by \(2^n\) needs the inverse of \(2^n\) mod \(p\), not //.
  • Expecting OR-convolution to be subset convolution: it counts overlapping pairs. Use the ranked version.

Digit DP

55m video

To count integers up to \(N\) with a digit property, build the number one digit at a time from the left. Once a digit falls below \(N\)'s digit, every later digit is free, so the count depends only on (position, a small summary of the digits so far); the tight flag tracks whether that has happened yet, and it is the whole trick.

From a range to a prefix

Count \(x \in [L, R]\) with property \(P\) as \(f(R) - f(L-1)\), where \(f(N) = |\{0 \le x \le N : P(x)\}|\). Now only the upper bound matters, and it is given as a digit string \(N = n_0 n_1 \dots n_{k-1}\).

The state, flag by flag

Definition · Digit DP state

\((pos,\ tight,\ started,\ s)\): the next digit to choose is at index \(pos\); \(tight\) says all digits so far equal \(N\)'s, so the next digit may be at most \(n_{pos}\) (otherwise up to 9); \(started\) says a nonzero digit has been placed, so later zeros are real digits rather than padding; \(s\) is whatever the property needs (last digit, digit sum mod \(k\), used-digit mask, …).

Theorem · Why tight makes it polynomial

At most one partial number per position is tight (the prefix of \(N\) itself). Every non-tight partial number of length \(pos\) has exactly the same set of completions, all \(10^{k-pos}\) digit strings, so the number of valid completions depends only on \((pos, started, s)\). The count is therefore a DP over \(O(k \cdot 2 \cdot 2 \cdot |S|)\) states with 10 transitions each.

Proof

A prefix \(p\) of length \(pos\) is less than \(N\)'s prefix, equal to it, or greater; the third kind is never generated because the digit limit is \(n_{pos}\) while tight. If \(p\) is less, then \(p\,q \le N\) for every completion \(q\), whatever its digits; if equal, a completion is allowed exactly when it is \(\le\) the rest of \(N\). Whether \(P(p\,q)\) holds depends on \(p\) only through \(s\) and \(started\) by the choice of \(s\). So prefixes with equal \((pos, tight, started, s)\) are interchangeable, which is the sufficiency condition of L81. \(\square\)

Leading zeros as their own flag. Writing 7 as 007 is how a fixed-length digit DP sees short numbers. For digit sums the padding is harmless. For "no two adjacent equal digits" or "all digits distinct", the padded zeros would wrongly count as digits, so carry started and treat zeros before it as "not yet a number". Hacks like "start the last digit at −1 and hope" break on exactly these problems.

The template

One function, parameterised by a state machine: step(s, d) returns the new state or None to reject, and value(s, started) is what a finished number contributes (1 or 0 for counting, the digit count itself for "how many 1s are written"). Recursion depth is the number of digits, so the recursion limit is no issue for 64-bit inputs.

from functools import lru_cache

def digit_dp(N, init, step, value, base=10):
    """Sum of value(state, started) over all x in [0, N]."""
    if N < 0:
        return 0
    digits = []
    while True:
        digits.append(N % base); N //= base
        if N == 0:
            break
    digits.reverse()
    k = len(digits)

    @lru_cache(maxsize=None)                    # fresh cache on every call
    def go(pos, tight, started, s):
        if pos == k:
            return value(s, started)
        total, lim = 0, digits[pos] if tight else base - 1
        for d in range(lim + 1):
            nt = tight and d == lim
            if not started and d == 0:
                total += go(pos + 1, nt, False, s)         # still padding
            else:
                ns = step(s, d)
                if ns is not None:
                    total += go(pos + 1, nt, True, ns)
        return total
    return go(0, True, False, init)

# 1) CSES Counting Numbers: no two adjacent equal digits (0 counts)
def no_adjacent(N):
    return digit_dp(N, -1, lambda s, d: None if d == s else d, lambda s, st: 1)
# 2) LeetCode 233: total number of digit 1 written in 1..N
def ones(N):
    return digit_dp(N, 0, lambda s, d: s + (d == 1), lambda s, st: s)
# 3) LeetCode 600: x in [0, N] whose binary form has no two consecutive 1s
def no_11(N):
    return digit_dp(N, 0, lambda s, d: None if s == d == 1 else d, lambda s, st: 1, base=2)

print(no_adjacent(321) - no_adjacent(122), ones(13), no_11(5))   # 171 6 5

More properties are one line each: divisible by \(k\), \(s\) = remainder, step = (s*10 + d) % k; sum of digits, \(s\) = running sum, value = s; non-decreasing digits, \(s\) = last digit, reject \(d < s\); all digits distinct (LeetCode 1012 via the complement), \(s\) = 10-bit used mask, reject repeats; digits from a given set (LeetCode 902), reject \(d \notin D\) and count only started numbers. LeetCode 2999 (numbers in a range ending with a given suffix, every digit \(\le\) a limit) fits too, with the suffix forced in the last positions.

When \(N\) has 10,000 digits

AtCoder DP-S — Digit Sum: count \(1 \le x \le K\) with digit sum divisible by \(D \le 100\), where \(K\) has up to \(10^4\) digits. The recursive template would recurse \(10^4\) deep and cache \(2\cdot 10^6\) states; roll it forward instead. The tight states form a single path (just track \(K\)'s digit sum so far), and the free states are a count per residue. Padding zeros add nothing to a digit sum, so started is not needed; subtract 1 at the end for \(x = 0\). The free update "append any digit 0–9" is a circular window sum of width 10, \(O(D)\) per position.

import sys
MOD = 10**9 + 7
def main():
    K, D = sys.stdin.read().split()
    D = int(D)
    free = [0] * D                       # free[r]: prefixes already below K, digit sum = r (mod D)
    tight = 0                            # digit sum of K's prefix (mod D)
    for ch in K:
        k = ord(ch) - 48
        ext = [free[i % D] for i in range(-9, D)]     # ext[t + 9] = free[t mod D]
        w, new = sum(ext[:10]), [0] * D
        for r in range(D):               # new[r] = sum of free[(r - d) mod D], d = 0..9
            new[r] = w % MOD
            if r + 10 < len(ext):
                w += ext[r + 10] - ext[r]
        for d in range(k):               # leave the tight path with a smaller digit
            new[(tight + d) % D] += 1
        free, tight = new, (tight + k) % D
    print((free[0] + (tight == 0) - 1) % MOD)
main()

Counting versus the \(k\)-th element

"Find the \(k\)-th positive integer with property \(P\)" inverts the counting function: \(c(x) = f(x) - f(0)\) is non-decreasing in \(x\), so binary search the smallest \(x\) with \(c(x) \ge k\) (L20). Each probe is one digit DP, so the cost is \(O(\log X)\) DP runs.

def kth_no_adjacent(k):                  # uses no_adjacent() from the template block
    lo, hi = 1, 10**18
    while lo < hi:
        mid = (lo + hi) // 2
        if no_adjacent(mid) - 1 >= k:    # minus 1 removes x = 0
            hi = mid
        else:
            lo = mid + 1
    return lo

print([kth_no_adjacent(k) for k in (1, 9, 10, 11, 100)])   # [1, 9, 10, 12, 120]

CSES — Digit Queries is the same "invert a counting function" idea without a DP: in the string 123456789101112…, there are \(9 \cdot 10^{L-1}\) numbers of length \(L\) contributing \(L\) digits each. Subtract whole blocks until position \(k\) falls inside one, then the number is \(10^{L-1} + \lfloor (k-1)/L \rfloor\) and the digit is its \(((k-1) \bmod L)\)-th.

What breaks
  • A module-level @cache keyed without the bound: the next call with a different \(N\) reuses wrong tight-state answers. Define the memoised function inside, as above, or drop tight from the cached part.
  • \(f(L - 1)\) with \(L = 0\): \(N = -1\) must return 0, not crash on its digits.
  • Leading zeros counted as digits: 7 seen as 007 has "two adjacent equal digits". Use started.
  • Whether 0 is in the set: CSES Counting Numbers includes 0 when \(a = 0\); "positive integers" problems do not. Decide in value.
  • Huge \(N\) through the recursive template: deep recursion and millions of cache entries. Iterate over positions instead.

Probability and Expected-Value DP

55m video

Expected-value DP is ordinary DP with a weighted sum as the combine: \(E[s] = \sum_t p(s \to t)\,(c + E[t])\), zero at absorbing states, evaluated backwards from the end. Before writing it, check whether linearity of expectation answers the question with no DP at all, and after writing it, check whether the state graph has cycles, in which case the recurrence becomes a linear system.

The probability you need

Definition · Tools
  • Conditional probability \(P(A \mid B) = P(A \cap B) / P(B)\); \(A, B\) independent when \(P(A \cap B) = P(A)P(B)\).
  • Law of total probability: for a partition \(B_1, B_2, \dots\), \(P(A) = \sum_i P(A \mid B_i) P(B_i)\), and likewise \(\E[X] = \sum_i \E[X \mid B_i] P(B_i)\). Conditioning on the first step of a process is exactly the DP transition.
  • Linearity: \(\E[X + Y] = \E[X] + \E[Y]\) for any random variables, independent or not.

Linearity first: three answers with no DP

Write the quantity as a sum of indicators, \(X = \sum_i [A_i]\); then \(\E[X] = \sum_i P(A_i)\), and each \(P(A_i)\) is usually easy even when the \(A_i\) are badly dependent.

  • Fixed points of a random permutation: \(P(\pi(i) = i) = 1/n\), so \(\E = 1\) for every \(n\).
  • Inversions of a random permutation: each pair \(i < j\) is inverted with probability \(1/2\), so \(\E = \binom{n}{2}/2 = n(n-1)/4\). (CSES Inverse Inversions then asks you to build a permutation with exactly \(k\) inversions; it is a greedy construction: with \(m\) values left, place the largest if \(k \ge m - 1\) and subtract \(m - 1\), else the smallest.)
  • CSES — Candy Lottery (\(n\) children each get a uniform number of candies in \(1..k\); expected maximum): \(\max = \sum_{m=1}^{k} [\max \ge m]\), so \(\E[\max] = \sum_{m=1}^{k} \big(1 - ((m-1)/k)^n\big)\). An indicator sum over thresholds, then independence for each term.

CSES — Moving Robots combines both: 64 robots on a chessboard each take \(k\) random steps; the expected number of empty squares is \(\sum_{\text{squares } q} \prod_{\text{robots } r} (1 - P_r(q))\), where \(P_r\) comes from a small forward DP (\(k \le 100\) steps on 64 cells) and independence between robots gives the product.

Expectation DP: absorbing states and direction

Theorem · Backward expectation recurrence

For a process on a finite DAG of states with absorbing states \(A\), let \(E[s]\) be the expected total cost from \(s\) until absorption. Then \(E[a] = 0\) for \(a \in A\) and \(E[s] = \sum_t p(s \to t)\big(c(s, t) + E[t]\big)\) otherwise.

Proof

Condition on the first step: by total expectation, \(\E[\text{cost} \mid S_0 = s] = \sum_t p(s \to t)\,\E[\text{cost} \mid S_0 = s, S_1 = t]\), and given \(S_1 = t\) the cost is \(c(s, t)\) plus the cost from \(t\), whose expectation is \(E[t]\) by the Markov property. On a DAG, induct in reverse topological order. \(\square\)

Backward (expected cost to finish) is usually right: the answer is one number, \(E[\text{start}]\), and absorbing states are natural base cases. Forward computes the distribution over states, \(P[t] = \sum_s P[s]\, p(s \to t)\), which is what you need when the question is a probability (DP-I, Dice Probability, Knight Probability) or when costs are attached to states reached. For expected values forward also works, as \(\sum_s P[\text{reach } s] \cdot \text{cost}(s)\), but needs care when the stopping time is random.

from fractions import Fraction
MOD = 998244353

def expected_rolls(n):                # throws of a fair die until the total is at least n
    E = [0.0] * (n + 6)               # totals >= n are absorbing: E = 0
    for s in range(n - 1, -1, -1):    # backward: E[s] reads only larger totals
        E[s] = 1 + sum(E[s + 1:s + 7]) / 6
    return E[0]

def expected_rolls_exact(n):
    E = [Fraction(0)] * (n + 6)
    for s in range(n - 1, -1, -1):
        E[s] = 1 + sum(E[s + 1:s + 7]) / 6
    return E[0]

def expected_rolls_mod(n):            # the same rational number as P * Q^(-1) mod p
    inv6 = pow(6, MOD - 2, MOD)
    E = [0] * (n + 6)
    for s in range(n - 1, -1, -1):
        E[s] = (1 + sum(E[s + 1:s + 7]) * inv6) % MOD
    return E[0]

q = expected_rolls_exact(10)
print(round(expected_rolls(10), 6), q,
      expected_rolls_mod(10) == q.numerator * pow(q.denominator, MOD - 2, MOD) % MOD)

The three versions are the same recurrence over three number systems. The modular one is what "print the expected value modulo 998244353" means: the exact answer is a fraction \(P/Q\), and modular arithmetic is a field, so every division becomes multiplication by an inverse (L119).

Self-loops and cycles: when DP alone fails

If a state can lead back to itself, the recurrence mentions the unknown on both sides. A self-loop only is a one-variable equation: solve it. AtCoder DP-J Sushi: \(n\) dishes; state \((c_1, c_2, c_3)\) = numbers of dishes with 1, 2, 3 pieces; each step picks a uniform dish and eats one piece if any. With \(c_0 = n - s\) empty dishes (\(s = c_1 + c_2 + c_3\)),

$$E = 1 + \tfrac{c_0}{n} E + \tfrac{c_1}{n} E_{(c_1-1, c_2, c_3)} + \tfrac{c_2}{n} E_{(c_1+1, c_2-1, c_3)} + \tfrac{c_3}{n} E_{(c_1, c_2+1, c_3-1)},$$

and moving \(\tfrac{c_0}{n}E\) to the left gives \(E = \big(n + c_1 E_{\cdot} + c_2 E_{\cdot} + c_3 E_{\cdot}\big)/s\), a plain DP again. Iterate \(c_3\) outer, then \(c_2\), then \(c_1\); only two \(c_3\)-layers are alive at a time.

def sushi(a):                                   # AtCoder DP-J
    n = len(a)
    c1, c2, c3 = (a.count(t) for t in (1, 2, 3))
    prev = None
    for k in range(c3 + 1):
        cur = [[0.0] * (n + 1) for _ in range(n + 1)]   # cur[j][i] = E(i, j, k)
        for j in range(c2 + c3 - k + 1):
            for i in range(n - j - k + 1):
                s = i + j + k
                if s == 0:
                    continue
                v = n
                if i: v += i * cur[j][i - 1]
                if j: v += j * cur[j - 1][i + 1]
                if k: v += k * prev[j + 1][i]
                cur[j][i] = v / s
        prev = cur
    return prev[c2][c1]

print(sushi([1, 1, 1]), sushi([1, 2]), round(sushi([1, 3, 2, 3, 3, 2, 3, 2, 1, 3]), 9))
# 5.5 4.5 54.480644575

With longer cycles no reordering helps: the unknowns \(E[s]\) satisfy a linear system \((I - P)E = c\), solvable by Gaussian elimination in \(O(V^3)\) (L125). A random walk on \(0..n\) that reflects at 0 and is absorbed at \(n\) shows both the general method and the shortcut.

from fractions import Fraction

def gauss(A, b):                       # exact solve of A x = b, A nonsingular
    n = len(A)
    M = [row[:] + [bi] for row, bi in zip(A, b)]
    for c in range(n):
        p = next(r for r in range(c, n) if M[r][c] != 0)
        M[c], M[p] = M[p], M[c]
        for r in range(n):
            if r != c and M[r][c] != 0:
                f = M[r][c] / M[c][c]
                M[r] = [x - f * y for x, y in zip(M[r], M[c])]
    return [M[i][n] / M[i][i] for i in range(n)]

def walk_expected(n):                  # n >= 2; unknowns E[0..n-1], E[n] = 0
    A = [[Fraction(0)] * n for _ in range(n)]
    for i in range(n):
        A[i][i] = Fraction(1)
        if i == 0:
            A[0][1] = Fraction(-1)                     # E0 = 1 + E1
        else:
            A[i][i - 1] = Fraction(-1, 2)              # Ei = 1 + (E(i-1) + E(i+1)) / 2
            if i + 1 < n:
                A[i][i + 1] = Fraction(-1, 2)
    return gauss(A, [Fraction(1)] * n)[0]

print([str(walk_expected(n)) for n in range(2, 7)])  # ['4', '9', '16', '25', '36']

The telescoping shortcut. Let \(d_i = E[i] - E[i+1]\). Row 0 gives \(d_0 = 1\); row \(i\) rearranges to \(d_i = d_{i-1} + 2\). So \(d_i = 2i + 1\) and \(E[0] = \sum_{i<n} d_i = n^2\), in \(O(n)\). Tridiagonal systems in general solve in \(O(n)\) by forward elimination (the Thomas algorithm).

What breaks

  • Cycles fed to a DP: the loop "converges" to garbage. Recognise cycles and use a linear system or a telescoping argument.

  • Modular division by a number divisible by \(p\): the inverse does not exist. Statements guarantee it does not happen; your intermediate formula might.

Game Theory I: Nim, Grundy Numbers, Sprague–Grundy

60m video

In an impartial game every position is a win or a loss for the player to move, found by backward induction. When a position splits into independent parts, each part is equivalent to a single Nim heap whose size is its Grundy number, and the whole position is lost exactly when the XOR of those numbers is zero. Contest game problems are mostly "compute small Grundy values by brute force, find the pattern, XOR".

Win and loss positions

Definition · Impartial game, normal play

Two players alternate; both have the same moves from every position (impartial); there is no hidden information and no chance; every play ends after finitely many moves; the player who cannot move loses (normal play). A position is a P-position if the previous player wins (the player to move loses with best play), and an N-position if the next player wins.

Theorem · Backward induction

Terminal positions are P. A non-terminal position is N if some move leads to a P-position, and P if every move leads to an N-position. Since play is finite, this labels every position.

That is already a DP over positions (L97 handles graphs with cycles). LeetCode 292 Nim Game (take 1–3 stones): P exactly when \(n \equiv 0 \pmod 4\). LeetCode 1025 Divisor Game: the first player wins exactly when \(n\) is even (an odd \(n\) has only odd divisors, so it always moves to an even number).

Nim and the XOR theorem

Theorem · Bouton (1901)

In Nim with heaps \(h_1, \dots, h_k\) (a move removes any positive number of objects from one heap), the position is P if and only if \(h_1 \oplus h_2 \oplus \cdots \oplus h_k = 0\).

Proof

Let \(X\) be the XOR. The terminal position has \(X = 0\). From \(X = 0\) every move gives \(X \ne 0\): a move changes exactly one heap \(h_i \to h_i' \ne h_i\), and the new XOR is \(X \oplus h_i \oplus h_i' = h_i \oplus h_i' \ne 0\). From \(X \ne 0\) some move gives \(X = 0\): let \(d\) be the highest set bit of \(X\); some heap \(h_i\) has bit \(d\) set (an odd number of heaps do). Then \(h_i' = h_i \oplus X\) clears bit \(d\) and changes only lower bits, so \(h_i' < h_i\) and the move \(h_i \to h_i'\) is legal; the new XOR is \(X \oplus h_i \oplus h_i' = 0\). By the backward-induction theorem, the \(X = 0\) positions are exactly the P-positions. \(\square\)

CSES Nim Game I is this theorem: print "first" when the XOR is nonzero. The proof also gives the winning move, \(h_i \to h_i \oplus X\).

mex and Grundy numbers

Definition · Grundy number

\(\operatorname{mex}(S)\) is the smallest non-negative integer not in \(S\). The Grundy number of a position is \(g(x) = \operatorname{mex}\{g(y) : x \to y\}\); terminal positions have \(g = 0\).

\(g(x) = 0\) exactly when \(x\) is P (no option has Grundy 0 means no move to a P-position, by induction). A Nim heap of size \(h\) has \(g = h\). More useful: a position with Grundy value \(g\) can move to positions of every Grundy value \(0..g-1\), just like a Nim heap of size \(g\), and any move to a larger value can be answered by moving back down. That is why it behaves like a heap.

Theorem · Sprague–Grundy

In a sum of games \(G_1 + \cdots + G_k\) (a move is a move in exactly one component), \(g(x_1, \dots, x_k) = g(x_1) \oplus \cdots \oplus g(x_k)\). In particular the sum is lost for the player to move exactly when this XOR is 0.

Proof sketch

Let \(X = \bigoplus g(x_i)\). By induction on the game, the options of the sum have Grundy values \(X \oplus g(x_i) \oplus g(y_i)\) for moves \(x_i \to y_i\). None equals \(X\), since \(g(y_i) \ne g(x_i)\) by the mex definition. For any \(v < X\), the Nim argument above finds a component with \(g(x_i) \oplus X \oplus v < g(x_i)\), and since \(g(x_i)\) is a mex, some move reaches exactly that value, giving an option of value \(v\). So the options cover \(0..X-1\) and miss \(X\): the mex is \(X\). \(\square\)

Brute force, then find the pattern

For a heap game you have not seen, compute \(g(0..30)\) by brute force, print it, and look for a period. Subtraction games (remove \(s \in S\) from a heap, \(S\) finite) are always eventually periodic. Splitting games are not always, but the brute-force table is still where you start.

def grundy_table(n_max, options):
    """options(n, g) yields the Grundy values of the positions reachable from heap n."""
    g = []
    for n in range(n_max + 1):
        seen = set(options(n, g))
        x = 0
        while x in seen:
            x += 1
        g.append(x)
    return g

def period(g, start=0):
    for p in range(1, (len(g) - start) // 2 + 1):
        if all(g[i] == g[i + p] for i in range(start, len(g) - p)):
            return p

subtract = lambda S: (lambda n, g: (g[n - s] for s in S if s <= n))
split = lambda n, g: (g[a] ^ g[n - a] for a in range(1, (n + 1) // 2))   # two unequal heaps

g = grundy_table(30, subtract((1, 3, 4)))
print(g[:14], period(g))                         # [0, 1, 0, 1, 2, 3, 2, 0, 1, 0, 1, 2, 3, 2] 7
print(grundy_table(11, subtract((1, 2, 3))))     # n mod 4: CSES Nim Game II
zeros = [n for n, v in enumerate(grundy_table(1300, split)) if v == 0]
print(len(zeros), zeros[-5:])                    # 42 [923, 926, 929, 932, 1222]

A splitting move produces two independent heaps, so its option value is the XOR of their Grundy numbers: Sprague–Grundy used inside the brute force.

Common games and their reductions

  • Nim with a cap (remove 1..k): \(g(h) = h \bmod (k+1)\). CSES Nim Game II is \(k = 3\): XOR the \(h_i \bmod 4\).
  • Staircase Nim (CSES Stair Game: move any number of balls from stair \(k \ge 2\) to stair \(k-1\)): only the even-numbered stairs matter, and the game is Nim on them. A move from an even stair is a Nim move; a move from an odd stair adds balls to an even stair, and the opponent pushes the same balls one stair further down, restoring the position.
  • CSES — Grundy's Game (split one heap into two unequal heaps): the brute-force table up to 1300 shows the last zero at 1222; published computations reportedly find no further zeros far beyond the CSES limit of \(10^6\), so the answer is "second" exactly for the listed zeros. This is the pattern workflow at its most extreme: the table is the solution.
  • CSES — Another Game (remove one coin from each heap in any non-empty set of heaps): the first player wins exactly when some heap is odd. From all-even, every move makes some heap odd; from a position with odd heaps, take one coin from exactly the odd heaps to make all even. Found by brute force on 3 heaps, then proved.
  • LeetCode 913 — Cat and Mouse is not impartial and has draws: L97's retrograde analysis.

Misère play

Under misère play the player who makes the last move loses. Misère Nim is almost unchanged: play normally until a move would leave only heaps of size 1, then leave an odd number of them. With all heaps \(\le 1\), the player to move wins exactly when the number of 1-heaps is even. But Sprague–Grundy fails for misère sums in general: the Grundy value of a component no longer determines how it combines with others, so there is no XOR rule. That is why contest problems almost always use normal play, and why a misère statement means "brute-force the whole position, not the components".

What breaks
  • XOR of heap sizes for a game that is not Nim: XOR the Grundy values, which equal heap sizes only for plain Nim.
  • Splitting moves treated as a single heap: an option that creates two heaps has value \(g(a) \oplus g(b)\), not \(\operatorname{mex}\) of anything about \(a + b\).
  • A period read from too short a table: subtraction games can have a long pre-period. Compute well past \(2 \max S\) and check the period holds to the end.
  • Stair Game indexing: "even stairs" means even in the 1-indexed statement; off by one flips every answer.
  • Misère by Sprague–Grundy: wrong. Handle misère with its own analysis or brute force.

Game Theory II: Minimax DP and Games on Graphs

50m video

A two-player zero-sum game with scores is a DP whose combine alternates between max and min. Storing the score relative to the player to move folds the two into one recurrence and removes the "whose turn" dimension. When positions can repeat, there is no evaluation order; label positions instead by a reverse BFS from the terminal ones, and whatever stays unlabelled is a draw.

Minimax, and the relative-score trick

The direct formulation keeps the turn in the state: \(V[s][\text{A}] = \max_{s \to t} \big(\text{gain} + V[t][\text{B}]\big)\) and \(V[s][\text{B}] = \min_{s \to t} \big(-\text{gain} + V[t][\text{A}]\big)\), scoring everything as A's total minus B's. If both players have the same moves and the game is zero-sum, define instead \(f(s)\) = best achievable (mover's total − opponent's total) from \(s\), whoever is to move.

Theorem · Negamax recurrence

\(f(s) = \max_{s \to t} \big(\text{gain}(s \to t) - f(t)\big)\), with \(f = 0\) at terminal positions. The player to move wins (scores more) iff \(f(\text{start}) > 0\).

Proof

After the move \(s \to t\), the roles swap: the opponent now moves and, by induction, can secure exactly \(f(t)\) for (opponent − mover) over the rest of the game, and no more. The mover's difference over the whole game is then \(\text{gain} - f(t)\), and the mover picks the best move. \(\square\)

It halves the state space because \(V[s][\text{A}]\) and \(V[s][\text{B}]\) are the same number up to sign when the rules are symmetric; only one needs storing. It needs the game to be symmetric: if the players have different move sets (Cat and Mouse below), keep the turn.

Interval games: reusing L87

Players alternately take the left or right end of an array (LeetCode 486 Predict the Winner, AtCoder DP-L Deque, CSES Removal Game). The state is the remaining segment and the negamax recurrence is

$$f[l][r] = \max\big(a_l - f[l+1][r],\ a_r - f[l][r-1]\big), \qquad f[l][l] = a_l.$$

It is an interval DP filled by length (L87), \(O(n^2)\), rolled to one list. The first player wins or ties iff \(f[0][n-1] \ge 0\); the first player's total is \((\sum a + f)/2\).

def predict_the_winner(a):                      # LeetCode 486
    n = len(a)
    f = a[:]                                    # segments of length 1
    for L in range(2, n + 1):
        f = [max(a[l] - f[l + 1], a[l + L - 1] - f[l]) for l in range(n - L + 1)]
    return f[0] >= 0                            # ties go to player 1

def stone_game_ii(piles):                       # LeetCode 1140: take 1..2M piles, M = max(M, x)
    from functools import lru_cache
    n, suf = len(piles), [0] * (len(piles) + 1)
    for i in range(n - 1, -1, -1):
        suf[i] = suf[i + 1] + piles[i]
    @lru_cache(maxsize=None)
    def best(i, M):                             # most stones the mover gets from piles[i:]
        if i + 2 * M >= n:
            return suf[i]
        return max(suf[i] - best(i + x, max(M, x)) for x in range(1, 2 * M + 1))
    return best(0, 1)

def stones(A, K):                               # AtCoder DP-K, CSES Stick Game
    win = [False] * (K + 1)                     # win[k]: player to move with k stones wins
    for k in range(1, K + 1):
        win[k] = any(not win[k - a] for a in A if a <= k)
    return win

Games on graphs with cycles: retrograde analysis

When moves can return to an earlier position, "win if some move reaches a losing position" is circular. Work backwards from what is certain instead.

Algorithm · Retrograde BFS
  1. For every position store its out-degree and its list of predecessors.
  2. Label terminal positions (and positions with no moves) LOSE for the player to move, or as the rules say, and enqueue them.
  3. Pop \(t\). For each unlabelled predecessor \(s\): if \(t\) is LOSE, label \(s\) WIN (it can move to \(t\)). If \(t\) is WIN, decrement \(s\)'s counter; at zero, every move from \(s\) gives the opponent a win, so label \(s\) LOSE. Enqueue new labels.
  4. Everything still unlabelled is a DRAW.
Theorem · Correctness of the draw label

WIN and LOSE labels are correct, and from every unlabelled position neither player can force a win: the result is infinite play under optimal strategies.

Proof

Labels are correct by induction on the order in which they are assigned; the BFS order also gives the number of moves to the end. An unlabelled \(s\) has no successor labelled LOSE (else it would be WIN), and not all of its successors are labelled WIN (else its counter would have reached zero). So it has an unlabelled successor. The player to move can always step to another unlabelled position, never handing the opponent a win, and the opponent is in the same situation. Neither can force a terminal win, so the value is a draw. \(\square\)

from collections import deque
WIN, LOSE, DRAW = 1, -1, 0

def retrograde(states, moves, terminal):
    """Outcome for the player to move. moves(s): successors; terminal(s): WIN/LOSE or None."""
    deg, pred, res = {}, {s: [] for s in states}, {}
    for s in states:
        succ = [] if terminal(s) is not None else list(moves(s))
        deg[s] = len(succ)
        for t in succ:
            pred[t].append(s)
    q = deque()
    for s in states:
        r = terminal(s)
        if r is None and deg[s] == 0:
            r = LOSE                            # cannot move: normal play
        if r is not None:
            res[s] = r
            q.append(s)
    while q:
        t = q.popleft()
        for s in pred[t]:
            if s in res:
                continue
            if res[t] == LOSE:
                res[s] = WIN; q.append(s)
            else:
                deg[s] -= 1
                if deg[s] == 0:
                    res[s] = LOSE; q.append(s)
    return {s: res.get(s, DRAW) for s in states}

def cat_and_mouse(graph):                       # LeetCode 913: 1 mouse, 2 cat, 0 draw
    n = len(graph)
    states = [(m, c, t) for m in range(n) for c in range(1, n) for t in (0, 1)]
    def terminal(s):
        m, c, t = s
        if m == 0:
            return WIN if t == 0 else LOSE      # mouse already home
        if m == c:
            return LOSE if t == 0 else WIN      # cat caught the mouse
        return None
    def moves(s):
        m, c, t = s
        if t == 0:
            return [(x, c, 1) for x in graph[m]]
        return [(m, x, 0) for x in graph[c] if x != 0]
    r = retrograde(states, moves, terminal)[(1, 2, 0)]
    return {WIN: 1, LOSE: 2, DRAW: 0}[r]

print(cat_and_mouse([[2, 5], [3], [0, 4, 5], [1, 4, 5], [2, 3], [0, 2, 3]]),
      cat_and_mouse([[1, 3], [0], [3], [0, 2]]))          # 0 1

Cat and Mouse is not symmetric (the cat may not enter the hole), so the turn stays in the state; "WIN" always means "for whoever moves now". \(O(V + E)\) with \(V = 2n^2\) states.

Draws, more outcomes, and alpha–beta

With more than two outcomes on a cyclic graph (scores, or win/draw/loss with preferences), ask a sequence of binary questions: "can the mover guarantee a result of at least \(v\)?" is a win/lose game, solved by one retrograde pass, and the answer for each position is the largest \(v\) that passes. For trees too large to tabulate (chess-like search), alpha–beta pruning computes the same minimax value while skipping branches that provably cannot change it; with good move ordering it examines on the order of \(b^{d/2}\) of the \(b^d\) leaves. In interviews the expected answer is usually the memoised minimax itself (LeetCode 464, 486, 1140), which is exactly this lesson's DP.

What breaks
  • Memoised DFS on a cyclic game: infinite recursion, or a value cached while it was still "in progress". Cycles mean retrograde BFS.
  • Negamax on an asymmetric game: if the players' moves differ, \(f(t)\) is the wrong player's value. Keep the turn.
  • Draw handled as a loss in retrograde analysis: positions that should cycle get labelled, and answers change.
  • Duplicate edges: count them consistently in both the degree and the predecessor lists, or dedupe both.
  • Stick Game at \(n = 10^6\), \(k = 100\): \(10^8\) checks. PyPy, and break out of the move loop as soon as a losing successor is found.

DP Optimisation I: Prefix Aggregates and Monotonic Deque

55m video

Many \(O(n^2)\) DPs are slow only because each state recomputes a min or max over a range of earlier states. Name that range, and the optimisation is a data-structure choice: a running aggregate for prefixes, a monotonic deque for windows whose ends both move forward, and a heap or segment tree when the eligible set is anything more complicated.

Step 1: the transition is a range query

Write the recurrence as \(dp[i] = \text{cost}(i) + \operatorname{agg}_{j \in R(i)}\, val(j)\), where \(val(j)\) depends only on \(j\) (often \(dp[j]\) plus a term in \(j\)). The shape of \(R(i)\) decides the tool:

The thing that breaks the reframe is a term that mixes \(i\) and \(j\), such as \(|h_i - h_j|\) or \((x_i - x_j)^2\). Then either split it into cases that each separate (below), or the transition is "lines evaluated at a point", which is L100's convex hull trick.

Prefix aggregates

If \(R(i) = \{j \le i - g\}\), carry \(best = \operatorname{agg}(val(0..i-g))\) and update it once per step. Counting DPs use a running sum the same way (L81's Dice Combinations window; LeetCode 837 in L95). LeetCode 2100 Find Good Days to Rob the Bank is the degenerate case: \(dec[i] = dec[i-1] + 1\) if \(a_i \le a_{i-1}\) else 0, the mirror \(inc[i]\) from the right, and day \(i\) is good when both reach time: two linear prefix DPs instead of an \(O(n \cdot time)\) scan.

Sliding window: the monotonic deque

Theorem · Deque invariant

Keep a deque of indices from the current window whose values are strictly decreasing from front to back (for a max). Before reading, pop front indices that left the window; after computing \(val(i)\), pop back indices with \(val \le val(i)\), then push \(i\). Then the front is the window maximum, and the total work is \(O(n)\).

Proof

An index \(j\) popped from the back because \(val(j) \le val(i)\) with \(j < i\) can never be the unique maximum again: every future window that contains \(j\) also contains \(i\), since windows move right. So discarding it loses nothing. The surviving indices are in increasing order with decreasing values, so the front, the oldest survivor still in the window, is the largest. Every index is pushed once and popped at most once, so the work is \(O(n)\) amortised. \(\square\)

from collections import deque

def jump_game_vi(nums, k):                      # LeetCode 1696: dp[i] = nums[i] + max dp[i-k..i-1]
    dp, dq = [0] * len(nums), deque()
    for i, x in enumerate(nums):
        while dq and dq[0] < i - k:             # left the window
            dq.popleft()
        dp[i] = x + (dp[dq[0]] if dq else 0)
        while dq and dp[dq[-1]] <= dp[i]:       # dominated by i
            dq.pop()
        dq.append(i)
    return dp[-1]

def constrained_subsequence_sum(nums, k):       # LeetCode 1425: may also start fresh
    dp, dq = [0] * len(nums), deque()
    for i, x in enumerate(nums):
        while dq and dq[0] < i - k:
            dq.popleft()
        dp[i] = x + max(0, dp[dq[0]] if dq else 0)
        while dq and dp[dq[-1]] <= dp[i]:
            dq.pop()
        dq.append(i)
    return max(dp)

print(jump_game_vi([1, -1, -2, 4, -7, 3], 2), constrained_subsequence_sum([10, 2, -10, 5, 20], 2))  # 7 37

Bounded knapsack in \(O(nW)\): one deque per residue

L84 left this open. Item \((w, v, k)\): \(new[c] = \max_{0 \le t \le k} old[c - tw] + tv\). Capacities interact only within a residue class \(c \equiv r \pmod w\). Write \(c = r + sw\); then

$$new[r + sw] = sv + \max_{s - k \le s' \le s} \big(old[r + s'w] - s'v\big),$$

a sliding-window maximum of width \(k + 1\) over the sequence \(g(s') = old[r + s'w] - s'v\). Each capacity is pushed and popped once per item: \(O(W)\) per item, \(O(nW)\) total, independent of the counts.

from collections import deque

def bounded_knapsack_deque(items, W):
    d = [0] * (W + 1)
    for w, v, k in items:
        new = d[:]
        for r in range(min(w, W + 1)):
            dq = deque()                         # (s, g) with g decreasing
            for s, c in enumerate(range(r, W + 1, w)):
                g = d[c] - s * v
                while dq and dq[-1][1] <= g:
                    dq.pop()
                dq.append((s, g))
                while dq[0][0] < s - k:          # window [s - k, s]
                    dq.popleft()
                new[c] = dq[0][1] + s * v
        d = new
    return d[W]

print(bounded_knapsack_deque([(2, 3, 13), (5, 9, 2)], 30))   # 48, as in L84

Binary splitting stays competitive because pieces heavier than \(W\) cost nothing, and its inner loop is a bare comparison rather than tuple traffic.

When the window is not a window: heaps and segment trees

When the left edge \(L(i)\) is data-dependent, for example found by a two-pointer scan over prefix sums, it is usually still non-decreasing, and the deque still works. A heap with lazy deletion is the lower-effort alternative: push \((val(j), j)\), and before reading pop the top while it is ineligible (\(j < L(i)\), or any other test that, once failed, stays failed). It costs a log factor but needs no domination argument. If eligibility depends on values rather than positions, use a segment tree over DP values (L106).

AtCoder DP-B Frog 2 with large \(k\) is the example: \(|h_i - h_j|\) mixes \(i\) and \(j\), but splitting by sign separates it. For \(h_j \le h_i\) the candidate is \((dp_j - h_j) + h_i\), for \(h_j > h_i\) it is \((dp_j + h_j) - h_i\). So keep two segment trees indexed by height rank (ties broken by index, so each \(j\) has its own leaf), query a prefix and a suffix of ranks, and delete \(j\) by writing \(+\infty\) when it leaves the window. \(O(n \log n)\) for any \(k\), against \(O(nk)\).

from bisect import bisect_right

def frog2_any_k(h, k):
    n, INF = len(h), 1 << 62
    order = sorted(range(n), key=h.__getitem__)
    rank, hs = [0] * n, [h[j] for j in order]
    for r, j in enumerate(order):
        rank[j] = r
    size = 1
    while size < n:
        size *= 2
    A, B = [INF] * (2 * size), [INF] * (2 * size)    # A: dp - h, B: dp + h, by rank
    def put(T, p, x):
        p += size; T[p] = x; p //= 2
        while p:
            T[p] = min(T[2 * p], T[2 * p + 1]); p //= 2
    def get(T, l, r):                                # min over ranks [l, r)
        res, l, r = INF, l + size, r + size
        while l < r:
            if l & 1: res = min(res, T[l]); l += 1
            if r & 1: r -= 1; res = min(res, T[r])
            l //= 2; r //= 2
        return res
    dp = [0] * n
    put(A, rank[0], -h[0]); put(B, rank[0], h[0])
    for i in range(1, n):
        if i - k - 1 >= 0:                           # j = i-k-1 leaves the window
            put(A, rank[i - k - 1], INF); put(B, rank[i - k - 1], INF)
        c = bisect_right(hs, h[i])                   # ranks [0, c) have h_j <= h_i
        dp[i] = min(get(A, 0, c) + h[i], get(B, c, n) - h[i])
        put(A, rank[i], dp[i] - h[i]); put(B, rank[i], dp[i] + h[i])
    return dp[-1]

print(frog2_any_k([10, 30, 40, 50, 20], 3), frog2_any_k([10, 20, 10], 1))   # 30 20

Slimes variants (AtCoder DP-N): the merge cost \(S(l, r)\) is a prefix-sum difference, the cheapest kind of aggregate; the remaining \(O(n^3)\) is a split-point search, which Knuth's optimisation (L99) cuts to \(O(n^2)\). CSES Subarray Squares has a cost \((S_i - S_j)^2\) that mixes \(i\) and \(j\) quadratically; no window structure helps, which is where L99 and L100 take over.

What breaks
  • Window off by one: is \(j\) in \([i-k, i-1]\) or \([i-k, i]\)? Decide whether you push \(i\) before or after reading the front, and test \(k = 1\).
  • < instead of <= when popping the back: still correct, but equal values pile up and the deque can grow to \(O(n)\) on constant input.
  • Popping the front with if when the left edge can jump by more than one per step: use while.
  • A term mixing \(i\) and \(j\) treated as if it were \(val(j)\): the deque returns the wrong argmin. Split cases or switch to CHT.
  • Segment-tree leaves keyed by value with duplicate values: deleting one \(j\) wipes the others. Key by (value, index) rank.

DP Optimisation II: Divide & Conquer Optimisation and Knuth

55m video

When the best split point moves monotonically as the subproblem grows, you never need to search all split points. Divide and conquer exploits this for layered "cut into \(k\) parts" DPs (\(O(kn^2) \to O(kn \log n)\)); Knuth's optimisation exploits a two-sided version for interval DPs (\(O(n^3) \to O(n^2)\)). Both rest on the quadrangle inequality, and in a contest you may check the monotonicity empirically instead of proving it.

The shape and the monotone-opt condition

The signature is "split an array into \(k\) contiguous parts, minimise the total cost of the parts":

$$dp_t[j] = \min_{0 \le i < j} \big(dp_{t-1}[i] + C(i, j)\big), \qquad dp_0[0] = 0,$$

where \(C(i, j)\) is the cost of the part \(a_{i+1..j}\). Naively that is \(O(n)\) per state, \(O(kn^2)\) in total. Let \(opt_t(j)\) be the largest \(i\) achieving the minimum.

Definition · Quadrangle inequality (Monge condition)

\(C\) satisfies the quadrangle inequality if \(C(a, c) + C(b, d) \le C(a, d) + C(b, c)\) for all \(a \le b \le c \le d\). In words: for two overlapping intervals, the pair "short-inside, long-outside" (\([a,d]\) and \([b,c]\)) costs at least as much as the crossing pair. Costs that grow faster than linearly in the segment, such as \((\text{sum})^2\), or "number of equal pairs inside", satisfy it.

Theorem · Quadrangle inequality implies monotone opt

If \(C\) satisfies the quadrangle inequality, then for any \(f\), the largest minimiser \(opt(j)\) of \(f(i) + C(i, j)\) is non-decreasing in \(j\).

Proof

Let \(j < j'\), \(k = opt(j)\), and \(k' < k\). Optimality of \(k\) at \(j\): \(f(k) + C(k, j) \le f(k') + C(k', j)\). The quadrangle inequality with \(k' \le k \le j \le j'\): \(C(k', j) + C(k, j') \le C(k', j') + C(k, j)\). Adding the two and cancelling gives \(f(k) + C(k, j') \le f(k') + C(k', j')\): at \(j'\), \(k\) is at least as good as every \(k' < k\), so the largest minimiser at \(j'\) is \(\ge k\). \(\square\)

Divide and conquer optimisation

Algorithm · D&C opt for one layer
  1. solve(lo, hi, olo, ohi): compute \(dp_t[j]\) for \(j \in [lo, hi]\), knowing every opt lies in \([olo, ohi]\).
  2. Take \(mid = \lfloor (lo + hi)/2 \rfloor\); scan \(i \in [olo, \min(mid - 1, ohi)]\) for the best value and its argmin \(b\).
  3. Recurse on \((lo, mid - 1, olo, b)\) and \((mid + 1, hi, b, ohi)\).

Complexity. The recursion over \([lo, hi]\) has depth \(\lceil \log_2 n \rceil\). On one level the ranges \([olo, ohi]\) of the calls overlap only at their endpoints, so the scans on that level total \(O(n + \text{number of calls}) = O(n)\). Hence \(O(n \log n)\) per layer and \(O(kn \log n)\) overall, with \(O(n)\) memory for two layers.

import random, time

def partition_dc(a, K):
    """Split a into K non-empty parts minimising the sum of (part sum)^2 (CSES Subarray Squares)."""
    n, INF = len(a), 1 << 62
    P = [0]
    for x in a:
        P.append(P[-1] + x)
    prev = [0] + [INF] * n                      # 0 parts cover only the empty prefix
    for _ in range(K):
        cur, stack = [INF] * (n + 1), [(1, n, 0, n - 1)]
        while stack:                            # explicit stack; depth is only log n anyway
            lo, hi, olo, ohi = stack.pop()
            if lo > hi:
                continue
            mid = (lo + hi) // 2
            best, b, pm = INF, olo, P[mid]
            for i in range(olo, min(mid - 1, ohi) + 1):
                v = prev[i] + (pm - P[i]) ** 2
                if v < best:
                    best, b = v, i
            cur[mid] = best
            stack.append((lo, mid - 1, olo, b))
            stack.append((mid + 1, hi, b, ohi))
        prev = cur
    return prev[n]

def partition_naive(a, K):
    n, INF = len(a), 1 << 62
    P = [0]
    for x in a:
        P.append(P[-1] + x)
    prev = [0] + [INF] * n
    for _ in range(K):
        prev = [INF] + [min(prev[i] + (P[j] - P[i]) ** 2 for i in range(j)) for j in range(1, n + 1)]
    return prev[n]

for _ in range(300):                            # cross-check on small random cases
    a = [random.randint(1, 20) for _ in range(random.randint(1, 12))]
    K = random.randint(1, len(a))
    assert partition_dc(a, K) == partition_naive(a, K)

Checking monotonicity empirically

Proving the quadrangle inequality for an unfamiliar cost can take longer than the contest. The legitimate shortcut: run the naive DP on a few hundred random small inputs, record the largest argmin for every state, and assert it never decreases along \(j\). If the assertion holds across varied random tests, use D&C; if it fails, you have a counterexample in hand. This is the same stress-testing discipline as L10, aimed at a structural property instead of an answer. (Under the quadrangle inequality the smallest minimiser is monotone too, by the symmetric argument, which is the convention the code below uses.)

Knuth's optimisation for interval DP

For \(dp[i][j] = \min_{i \le k < j} \big(dp[i][k] + dp[k+1][j]\big) + C(i, j)\), if \(C\) satisfies the quadrangle inequality and is monotone under inclusion (\(C(b, c) \le C(a, d)\) for \([b, c] \subseteq [a, d]\)), then (Knuth 1971; Yao 1980)

$$opt[i][j-1] \le opt[i][j] \le opt[i+1][j].$$

Restrict the split loop to that range. Complexity: for a fixed length \(L\), the work is \(\sum_i \big(opt[i+1][i+L-1] - opt[i][i+L-2] + 1\big)\), which telescopes to \(O(n)\); over all lengths, \(O(n^2)\). Merging adjacent piles at cost "total size" (AtCoder DP-N Slimes, optimal merging of files) has \(C(i, j) = S(i, j)\), which satisfies both conditions with equality in the quadrangle inequality. Knuth's original application was the optimal binary search tree.

def slimes_knuth(a):                            # AtCoder DP-N in O(n^2)
    n = len(a)
    P = [0]
    for x in a:
        P.append(P[-1] + x)
    dp = [[0] * n for _ in range(n)]
    opt = [[i] * n for i in range(n)]           # opt[i][i] = i
    for L in range(2, n + 1):
        for i in range(n - L + 1):
            j = i + L - 1
            best, b = -1, -1
            for k in range(opt[i][j - 1], min(opt[i + 1][j], j - 1) + 1):
                v = dp[i][k] + dp[k + 1][j]
                if best < 0 or v < best:
                    best, b = v, k
            dp[i][j], opt[i][j] = best + P[j + 1] - P[i], b
    return dp[0][n - 1]

print(slimes_knuth([10, 20, 30, 40]), slimes_knuth([10] * 5), slimes_knuth([7, 6, 8, 6, 1, 1]))   # 190 120 68

The underlying theory, and what comes next

The quadrangle inequality says the cost matrix is Monge; the matrix of candidate values \(f(i) + C(i, j)\) is then totally monotone, which is the property all of these methods exploit. SMAWK (Aggarwal et al. 1987) finds all row minima of a totally monotone \(n \times n\) matrix in \(O(n)\), an \(O(kn)\) layer, but its constant and code length rarely pay off in contests. When the layer count \(k\) itself is the problem, L101's Aliens trick removes it, provided the answer is convex in \(k\).

  • CSES — Knuth Division: repeatedly divide a segment into two at cost equal to its sum, until all parts are single elements. Run backwards it is merging, so Knuth's \(O(n^2)\) applies directly (\(n \le 5000\): PyPy).
  • CSES — Houses and Schools: choose \(k\) school positions on a line of houses with \(c_i\) children each, minimising total walking distance.   • Codeforces: Ciel and Gondolas (cost of a group = sum of pairwise unfamiliarity, from 2D prefix sums) and Yet Another Minimization Problem (cost = number of equal pairs, maintained with two moving pointers as in Mo's algorithm during the D&C) are the standard D&C-opt exercises.
What breaks
  • Applying D&C opt without the condition: wrong answers, often only on large tests. Prove the quadrangle inequality or run the empirical check.
  • Negative elements: \((\text{sum})^2\) satisfies the quadrangle inequality only when the elements are non-negative (expanding both sides leaves a slack of \(2xz\), where \(x, z\) are the sums of the two outer pieces). With negative values the same code can silently return a non-optimal answer.

  • Knuth's bounds with opt[i+1][j] undefined for length 2: initialise opt[i][i] = i and clamp the upper end to \(j - 1\).
  • Recursion overhead: recursive solve is fine (depth \(\log n\)) but each call is slow in CPython; the explicit stack above is a little faster.

DP Optimisation III: Convex Hull Trick and Li Chao Tree

55m video

If the transition cost splits into (something about \(j\)) × (something about \(i\)) plus terms of one index only, each earlier state is a line and each new state queries the minimum of all lines at one point. Keep the lower envelope: with monotone slopes and queries it is a deque with amortised \(O(1)\) operations; in any order, a Li Chao tree answers in \(O(\log C)\).

The hard step: finding the line form

Derivation · AtCoder DP-Z Frog 3

Heights \(h_1 < h_2 < \cdots < h_n\); jumping from \(j\) to \(i > j\) costs \((h_i - h_j)^2 + C\). Expand and group by what depends on \(j\):

$$dp[i] = \min_{j < i} \Big(dp[j] + h_j^2 - 2h_j h_i\Big) + h_i^2 + C = \min_{j < i} \big(m_j\, x_i + c_j\big) + h_i^2 + C,$$

with slope \(m_j = -2h_j\), intercept \(c_j = dp[j] + h_j^2\), and query point \(x_i = h_i\). The cross term \(h_j h_i\) is the only place \(i\) and \(j\) meet, and it becomes slope × \(x\).

The recipe: expand the cost, move every \(i\)-only term outside the min, and read off the term of the form \(f(j) \cdot g(i)\). Then \(f(j)\) is the slope, \(g(i)\) the query point, and everything else that depends on \(j\) the intercept. If more than one cross term remains, there is no line form (try D&C optimisation, L99).

The lower envelope

The minimum of a set of lines, as a function of \(x\), is a concave piecewise-linear curve: the lower envelope. Sorted by decreasing slope, each line is optimal on at most one interval, and some lines are optimal nowhere. The convex hull trick stores only the useful lines in slope order.

Monotone CHT: deque and pointer

Assume lines arrive with strictly decreasing slopes and queries come with non-decreasing \(x\) (both hold in Frog 3, since \(h\) increases). Append each line at the back after removing back lines that became useless; answer each query by advancing a front pointer while the next line is at least as good. Every line is added and removed once, so both operations are amortised \(O(1)\).

Theorem · Bad-line test, in integers

For slopes \(m_1 > m_2 > m_3\), line 2 is never strictly below both others iff \((c_3 - c_1)(m_1 - m_2) \le (c_2 - c_1)(m_1 - m_3)\).

Proof

Line 1 is best far left. Line 2 overtakes line 1 at \(x_{12} = (c_2 - c_1)/(m_1 - m_2)\), and line 3 overtakes line 1 at \(x_{13} = (c_3 - c_1)/(m_1 - m_3)\). Line 2 is on the envelope exactly when it overtakes line 1 first, \(x_{12} < x_{13}\). Both denominators are positive, so cross-multiplying preserves the inequality and gives the stated test with no division. \(\square\)

Floating-point intersections fail on near-parallel lines with large intercepts; the cross-multiplied form is exact. In Python the products can exceed 64 bits harmlessly, which in C++ would need 128-bit integers.

class MonotoneCHT:
    """Min of lines. Add slopes in decreasing order; query x in non-decreasing order."""
    def __init__(self):
        self.M, self.C, self.h = [], [], 0
    def add(self, m, c):
        M, C = self.M, self.C
        if M and M[-1] == m:                        # parallel: keep the lower one
            if c >= C[-1]:
                return
            M.pop(); C.pop()
        while len(M) - self.h >= 2 and \
                (c - C[-2]) * (M[-2] - M[-1]) <= (C[-1] - C[-2]) * (M[-2] - m):
            M.pop(); C.pop()                        # the last line is now useless
        M.append(m); C.append(c)
        self.h = min(self.h, len(M) - 1)
    def query(self, x):
        M, C, h = self.M, self.C, self.h
        while h + 1 < len(M) and M[h + 1] * x + C[h + 1] <= M[h] * x + C[h]:
            h += 1
        self.h = h
        return M[h] * x + C[h]

def frog3(h, C):                                    # AtCoder DP-Z
    cht, dp = MonotoneCHT(), 0
    cht.add(-2 * h[0], h[0] * h[0])                 # dp[0] = 0
    for x in h[1:]:
        dp = cht.query(x) + x * x + C
        cht.add(-2 * x, dp + x * x)
    return dp

print(frog3([1, 2, 3, 4, 5], 6), frog3([1, 3, 4, 5, 10, 11, 12, 13], 5))   # 20 62

Li Chao tree: any order

When slopes or queries are not monotone, store one line per node of a segment tree over the query coordinates. Inserting compares the new line with the node's line at the midpoint, keeps the winner there, and sends the loser down to the one half where it can still win (two lines cross at most once). A query walks root to leaf and takes the minimum of the lines it meets. Both are \(O(\log C)\) for \(C\) coordinates; compress to the actual query points when they are known in advance.

class LiChao:
    """Min of lines over the sorted query coordinates xs."""
    def __init__(self, xs):
        self.xs, self.n = xs, len(xs)
        self.t = [None] * (4 * len(xs))
    def add(self, m, c):
        node, lo, hi, new, xs = 1, 0, self.n - 1, (m, c), self.xs
        while True:
            cur = self.t[node]
            if cur is None:
                self.t[node] = new; return
            mid = (lo + hi) // 2
            if new[0] * xs[mid] + new[1] < cur[0] * xs[mid] + cur[1]:
                self.t[node], new = new, cur        # winner at mid stays here
                cur = self.t[node]
            if lo == hi:
                return
            if new[0] * xs[lo] + new[1] < cur[0] * xs[lo] + cur[1]:
                node, hi = 2 * node, mid             # loser can still win on the left
            elif new[0] * xs[hi] + new[1] < cur[0] * xs[hi] + cur[1]:
                node, lo = 2 * node + 1, mid + 1     # ... or on the right
            else:
                return
    def query(self, i):                             # i = index of the point in xs
        node, lo, hi, x, best = 1, 0, self.n - 1, self.xs[i], None
        while self.t[node] is not None:
            m, c = self.t[node]
            if best is None or m * x + c < best:
                best = m * x + c
            if lo == hi:
                break
            mid = (lo + hi) // 2
            node, lo, hi = (2 * node, lo, mid) if i <= mid else (2 * node + 1, mid + 1, hi)
        return best

def frog3_lichao(h, C):                             # same answers, no monotonicity needed
    xs = sorted(set(h))
    pos = {x: k for k, x in enumerate(xs)}
    lc, dp = LiChao(xs), 0
    lc.add(-2 * h[0], h[0] * h[0])
    for x in h[1:]:
        dp = lc.query(pos[x]) + x * x + C
        lc.add(-2 * x, dp + x * x)
    return dp

def subarray_squares_cht(a, K):                     # uses MonotoneCHT from above

What breaks

  • Li Chao over the raw range \([0, 10^9]\) with arrays: allocate per node lazily (dict) or compress to the query points.

DP Optimisation IV: Aliens Trick and Matrix Exponentiation for DP

55m video

Two ways to remove a dimension that the constraints will not allow. The Aliens trick removes "exactly \(k\) groups" by charging a price \(\lambda\) per group and binary-searching the price, which is valid when the answer is convex in \(k\). Matrix exponentiation removes a huge length \(n\) from a linear DP with a small state by squaring the one-step transition matrix.

Exactly \(k\) groups, priced away

Let \(g(k)\) be the minimum cost of a solution with exactly \(k\) groups (parts, segments, chosen items). The \(k\) dimension multiplies every earlier optimisation by \(k\), or worse. Lagrangian relaxation drops it: for a price \(\lambda\), solve the unconstrained problem in which every group costs an extra \(\lambda\),

$$h(\lambda) = \min_k \big(g(k) + \lambda k\big),$$

with a DP that has no \(k\) in its state, and record how many groups its optimum used. A higher price means fewer groups. Search for the price at which the optimum uses exactly \(k\) groups and return \(h(\lambda) - \lambda k\).

Theorem · When the relaxation is exact

If \(g\) is convex (\(g(k+1) - g(k)\) non-decreasing in \(k\)), then for every \(k\) there is a \(\lambda\) for which \(k\) minimises \(g(k') + \lambda k'\), and for that \(\lambda\), \(g(k) = h(\lambda) - \lambda k\). If \(g\) is integer-valued, an integer \(\lambda\) suffices.

Proof

Take \(-\lambda\) between the slopes on either side of \(k\): \(g(k) - g(k-1) \le -\lambda \le g(k+1) - g(k)\). Convexity extends these to every \(k'\): \(g(k') \ge g(k) - \lambda (k' - k)\), i.e. \(g(k') + \lambda k' \ge g(k) + \lambda k\). So \(k\) is a minimiser and \(h(\lambda) = g(k) + \lambda k\). With integer \(g\) the two slopes are integers, so an integer \(-\lambda\) fits between them. \(\square\)

Checking convexity, and ties

Convexity is the hypothesis that must hold. For partition problems with a cost satisfying the quadrangle inequality (L99) it does, and that covers most contest uses. Otherwise check it empirically, as with monotone opt: compute \(g(1..n)\) with the slow DP on random small inputs and assert that the differences are non-decreasing.

Ties. When \(g\) has a straight stretch, one price makes several \(k\) optimal at once, and the count your DP reports depends on its tie-breaking. Fix it deliberately: break ties towards the fewest groups, binary-search the smallest \(\lambda\) whose reported count is \(\le k\), and return \(h(\lambda) - \lambda k\) with the target \(k\), not the reported count. By the theorem, \(k\) is among that price's minimisers even if the DP reported a smaller count. A clean way to break ties exactly is to scale every cost by \(B = n + 1\) and charge \(B\lambda + 1\) per group: the \(+1\)'s never outweigh a real cost difference, and the count can be read back as the remainder mod \(B\).

Worked example: Subarray Squares in \(O(n \log C)\)

Split \(a\) (positive) into exactly \(k\) parts minimising \(\sum (\text{part sum})^2\). With the price, the DP is one-dimensional, \(dp[j] = \min_i dp[i] + (P_j - P_i)^2 + \lambda\), which is L100's monotone CHT. About \(\log_2 (P_n^2)\) prices, each one \(O(n)\) pass: no \(k\) anywhere.

class MonotoneCHT:                              # from L100 (min; slopes decreasing, x increasing)
    def __init__(self):
        self.M, self.C, self.h = [], [], 0
    def add(self, m, c):
        M, C = self.M, self.C
        while len(M) - self.h >= 2 and (c - C[-2]) * (M[-2] - M[-1]) <= (C[-1] - C[-2]) * (M[-2] - m):
            M.pop(); C.pop()
        M.append(m); C.append(c)
        self.h = min(self.h, len(M) - 1)
    def query(self, x):
        M, C, h = self.M, self.C, self.h
        while h + 1 < len(M) and M[h + 1] * x + C[h + 1] <= M[h] * x + C[h]:
            h += 1
        self.h = h
        return M[h] * x + C[h]

def aliens_partition(a, K):
    n, B = len(a), len(a) + 1
    P = [0]
    for x in a:
        P.append(P[-1] + x)
    def relaxed(lam):                           # (min of cost + lam * parts, parts), fewest parts on ties
        cht, d = MonotoneCHT(), 0
        cht.add(0, 0)                           # i = 0
        for j in range(1, n + 1):
            d = cht.query(P[j]) + B * P[j] * P[j] + B * lam + 1
            cht.add(-2 * B * P[j], d + B * P[j] * P[j])
        return d // B, d % B
    lo, hi = 0, P[n] ** 2 + 1                   # at hi one part is optimal
    while lo < hi:
        mid = (lo + hi) // 2
        if relaxed(mid)[1] <= K:
            hi = mid
        else:
            lo = mid + 1
    return relaxed(lo)[0] - lo * K

print(aliens_partition([2, 3, 1, 2, 2, 3, 4, 1], 3))   # 110, as with L99 and L100

Matrix exponentiation for linear DP

If the DP's state at step \(t + 1\) is a fixed linear function of the state at step \(t\), \(v_{t+1} = T v_t\), then \(v_n = T^n v_0\), and \(T^n\) takes \(O(\log n)\) matrix products by repeated squaring: \(O(d^3 \log n)\) for \(d\) states. The skill is building \(T\) mechanically:

Algorithm · From recurrence to matrix
  1. List what step \(t+1\) needs: for \(f_{t} = c_1 f_{t-1} + \cdots + c_d f_{t-d}\), the vector \(v_t = (f_t, f_{t-1}, \dots, f_{t-d+1})\).
  2. First row: the coefficients \(c_1..c_d\). Rows \(2..d\): shift down (a 1 just below the diagonal).
  3. A constant term \(+e\): append a component that is always 1, with \(e\) in the first row's last column and a 1 on its own diagonal.
  4. Counting walks on a graph: \(T\) is the adjacency matrix, and \((A^k)_{uv}\) is the number of walks of length \(k\) from \(u\) to \(v\).
from operator import mul, add
MOD = 10**9 + 7

def mat_mul(A, B):
    Bt = list(zip(*B))                          # columns of B, so each entry is one C-level map
    return [[sum(map(mul, row, col)) % MOD for col in Bt] for row in A]

def mat_pow(T, e):
    R = [[int(i == j) for j in range(len(T))] for i in range(len(T))]
    while e:
        if e & 1:
            R = mat_mul(R, T)
        T, e = mat_mul(T, T), e >> 1
    return R

def linear_recurrence(coef, init, n):
    """f(t) = sum coef[i] * f(t-1-i); init = [f(0), ..., f(d-1)]; returns f(n) mod p."""
    d = len(coef)
    if n < d:
        return init[n] % MOD
    T = [coef[:]] + [[int(j == i) for j in range(d)] for i in range(d - 1)]
    R = mat_pow(T, n - d + 1)
    state = init[::-1]                          # (f(d-1), ..., f(0))
    return sum(r * s for r, s in zip(R[0], state)) % MOD

def minplus_mul(A, B):                          # (min, +) product: shortest walks
    Bt = list(zip(*B))
    return [[min(map(add, row, col)) for col in Bt] for row in A]

print(linear_recurrence([1, 1], [0, 1], 10),               # Fibonacci F(10) = 55
      linear_recurrence([1] * 6, [1, 1, 2, 4, 8, 16], 6),  # Throwing Dice, n = 6: 32
      mat_pow([[0, 1], [1, 1]], 10**18)[0][1])             # F(10^18) mod p

Throwing Dice: \(f(n) = \sum_{d=1}^{6} f(n-d)\) with \(f(0) = 1\), so the first six values are 1, 1, 2, 4, 8, 16. sum(map(mul, row, col)) keeps each inner product in C; a 100 × 100 product is then a few hundredths of a second, and \(T^{10^9}\) needs about 60 products.

Problems and where else it applies

  • CSES — Fibonacci Numbers (\(n \le 10^{18}\)) and Throwing Dice: the recurrences above.
  • CSES — Graph Paths I: number of walks of exactly \(k\) edges from 1 to \(n\) is \((A^k)_{1n}\) with multi-edges counted in \(A\).
  • CSES — Graph Paths II: minimum cost of a walk with exactly \(k\) edges. Replace \((+, \times)\) by \((\min, +)\): the same squaring works because \((\min, +)\) is associative and distributes; use \(+\infty\) for missing edges.
  • Small profiles (L92): the column-to-column tiling transition is a \(2^n \times 2^n\) matrix, so \(m = 10^{18}\) columns is one matrix power, practical for \(2^n\) up to a few dozen.
  • Order-\(d\) recurrences with large \(d\): \(O(d^3 \log n)\) becomes heavy past \(d \approx 100\) in Python. Kitamasa's method computes \(x^n \bmod\) the characteristic polynomial in \(O(d^2 \log n)\), and Berlekamp–Massey recovers the recurrence from the first \(2d\) terms when you only have the sequence (L124).
What breaks
  • Aliens on a non-convex \(g\): the search lands on a neighbouring \(k\) and the answer is wrong. Check convexity on small cases.
  • Returning \(h(\lambda) - \lambda \cdot \text{reported count}\) instead of \(\lambda \cdot k\): wrong on every flat stretch of \(g\).
  • λ range too small: if even the largest λ in the search still yields more than \(k\) groups, the binary search silently returns the boundary. Bound \(\lambda\) by the largest possible cost.
  • Matrix power off by one: \(T^{n}\) versus \(T^{n-d+1}\) depending on what the initial vector holds. Test \(n = 0..d+2\) against the direct loop.
  • Forgetting the modulus inside the product: entries grow to thousands of digits after a few squarings.

Editorial

P1 — Boredom. Choosing value \(v\) deletes every \(v \pm 1\), so take all copies of \(v\) once you take one. Bucket \(p[v] = v \cdot \text{cnt}(v)\); then it is House Robber over values (L82): \(dp[v] = \max(dp[v-1],\ dp[v-2] + p[v])\). \(O(n + \max a)\).

def boredom(a):
    pts = [0] * (max(a) + 1)
    for x in a:
        pts[x] += x
    p2 = p1 = 0                                   # dp[v-2], dp[v-1]
    for v in range(1, len(pts)):
        p2, p1 = p1, max(p1, p2 + pts[v])
    return p1

P2 — Zuma (remove a palindromic substring per second; minimum seconds). \(dp[l][r]\) = seconds for \(c[l..r)\). Gem \(l\) is removed either alone (\(1 + dp[l+1][r]\)), together with an equal neighbour (\(1 + dp[l+2][r]\)), or as an outer layer of the last palindrome removed inside \(c(l..k)\) for some \(k\) with \(c_k = c_l\): then \(c_l\) and \(c_k\) cost nothing extra, \(dp[l+1][k] + dp[k+1][r]\). That last case is the "choose what happens last" reframe of L87. \(O(n^3)\) with \(n \le 500\): PyPy.

def zuma(c):
    n = len(c)
    dp = [[0] * (n + 1) for _ in range(n + 1)]   # dp[l][r] for c[l:r]
    for l in range(n - 1, -1, -1):
        for r in range(l + 1, n + 1):
            best = 1 + dp[l + 1][r]
            if r - l >= 2 and c[l] == c[l + 1]:
                best = min(best, 1 + dp[l + 2][r])
            for k in range(l + 2, r):
                if c[k] == c[l]:
                    best = min(best, dp[l + 1][k] + dp[k + 1][r])
            dp[l][r] = best
    return dp[0][n]

P3 — Appleman and Tree (count edge subsets to cut so every component has exactly one black vertex). Per node, the component still open upwards has either no black vertex yet (\(d_0\)) or exactly one (\(d_1\)). Merging child \(c\): cutting the edge requires \(c\)'s component to be finished (\(d_1[c]\)); keeping it joins the two open components. So \(d_0 \leftarrow d_0 (d_0[c] + d_1[c])\) and \(d_1 \leftarrow d_1 (d_0[c] + d_1[c]) + d_0\, d_1[c]\); answer \(d_1[\text{root}]\). Parents have smaller labels in this input, so a reverse loop is a post-order (L89).

MOD = 10**9 + 7
def appleman(n, par, black):                      # par[v] < v for v >= 1
    d0, d1 = [1 - b for b in black], black[:]
    for v in range(n - 1, 0, -1):
        p, a0, a1 = par[v], d0[v], d1[v]
        d0[p], d1[p] = d0[p] * (a0 + a1) % MOD, (d1[p] * (a0 + a1) + d0[p] * a1) % MOD
    return d1[0]

P4 — Kefa and Dishes (eat exactly \(m\) of \(n \le 18\) dishes; bonus \(c\) when \(x\) is eaten right before \(y\)). The bonus depends on the previous dish, so the state is \((mask, last)\) (L91); push \(dp[mask \cup \{y\}][y] \leftarrow dp[mask][x] + a_y + bonus[x][y]\) in increasing mask order with a flat list, take the maximum over masks of popcount \(m\), and never extend those. \(O(2^n n^2) \approx 8\cdot 10^7\) in the worst case: PyPy.

P5 — Classy Numbers (count integers in \([L, R]\), \(R \le 10^{18}\), with at most 3 nonzero digits, for \(10^4\) queries). The digit-DP state is (position, tight, nonzero digits used \(\le 3\)) (L94), but \(10^4\) memoised runs are slow in Python. Unroll it: leaving the tight path at position \(i\) leaves \(r\) free digits, and the number of completions with at most \(q\) nonzero digits is \(\sum_{t \le q} \binom{r}{t} 9^t\). (Alternative: there are only about \(6\cdot 10^5\) classy numbers up to \(10^{18}\); generate them once, sort, and answer with bisect.)

from math import comb
def classy_upto(N):                               # x in [0, N] with <= 3 nonzero digits
    if N < 0:
        return 0
    s = str(N)
    free = lambda r, q: sum(comb(r, t) * 9 ** t for t in range(q + 1)) if q >= 0 else 0
    total, used = 0, 0
    for i, ch in enumerate(s):
        d, r = int(ch), len(s) - i - 1
        if d:                                     # a 0 here, or a smaller nonzero digit
            total += free(r, 3 - used) + (d - 1) * free(r, 2 - used)
            used += 1
            if used > 3:
                return total
    return total + 1                              # N itself
# answer for a query: classy_upto(R) - classy_upto(L - 1)

P6 — Kalila and Dimna in the Logging Industry. The known reduction is \(dp[i] = \min_{j < i} dp[j] + b_j a_i\), \(dp[1] = 0\), with \(a\) increasing and \(b\) decreasing: a line with slope \(b_j\) and intercept \(dp[j]\), queried at \(a_i\). Slopes arrive decreasing and queries increasing, so it is the monotone CHT of L100, \(O(n)\); the naive \(O(n^2)\) is far too slow at \(n = 10^5\).

def kalila(a, b):
    M, C, h, dp = [b[0]], [0], 0, 0              # line j: slope b[j], intercept dp[j]
    for i in range(1, len(a)):
        x = a[i]
        while h + 1 < len(M) and M[h + 1] * x + C[h + 1] <= M[h] * x + C[h]:
            h += 1
        dp = M[h] * x + C[h]
        while len(M) - h >= 2 and (dp - C[-2]) * (M[-2] - M[-1]) <= (C[-1] - C[-2]) * (M[-2] - b[i]):
            M.pop(); C.pop()
        M.append(b[i]); C.append(dp)
        h = min(h, len(M) - 1)
    return dp

The "my DP is wrong" protocol

Algorithm · Debugging a DP
  1. Brute force first. Write the exponential solution (L10's stress loop) and compare on thousands of random inputs with \(n \le 6\).
  2. Shrink the failing input until removing anything makes it pass.
  3. Print the table for that input next to the brute-force value of every state you can compute directly. Find the first cell, in evaluation order, that is wrong.
  4. Diagnose that cell. A base case or sentinel (0 where \(\infty\) was needed)? A read of a cell not yet computed (loop order)? Two partial solutions with different futures merged into one state (add the missing dimension, as in L81's Vacation)? Or a correct table read at the wrong cell (answer extraction)?
  5. For TLE, recount states × transitions against the Python budget before micro-optimising.

State-design checklist for the first minutes of any DP: sufficient (same state ⇒ same futures)? minimal? a topological order? illegal states and their sentinel? states × transitions within the Python budget?
