Phase 2 builds the linear data structures that turn Phase 1's quadratic loops into linear and n log n ones: hash maps you can defend against anti-hash tests, stacks and monotonic stacks, queues and deques, linked lists in pointer and array form, binary heaps, and the sweep line. Hashing & Hash Maps: Internals and Anti-Hash Attacks

50m video

A hash map is an array plus a function that scatters keys across it. It is O(1) on average only because the keys look random to that function, and in Python the function for integers is public and deterministic, so anyone who writes the tests can make your dict quadratic on purpose.

Buckets, collisions, and what CPython actually does

Definition

A hash table stores key \(k\) near slot \(h(k) \bmod m\) of an array of size \(m\). Two keys with the same slot collide. Separate chaining keeps a list per slot. Open addressing keeps one entry per slot and, on a collision, follows a deterministic probe sequence to the next candidate slot. The load factor is \(\alpha = n/m\).

CPython's dict uses open addressing. Since 3.6 it is "compact": a power-of-two index table pointing into a dense entries array kept in insertion order. On a collision it probes with perturb >>= 5; i = (5*i + perturb + 1) & mask from perturb = hash: the high hash bits are mixed in for about a dozen steps, then the path is \(i \mapsto 5i+1 \bmod 2^k\), which visits every slot. Deletions leave tombstones; the table is rebuilt larger when about two-thirds full.

Theorem · cost of a hash table

If keys behave like independent uniform hashes, a lookup costs \(O(1+\alpha)\) expected under chaining, and \(O(1/(1-\alpha))\) expected probes under open addressing. Resizing by a constant factor when \(\alpha\) passes a threshold keeps \(\alpha = O(1)\), and the rehash work telescopes: growing to \(n\) rebuilds tables of sizes \(\le n, n/2, n/4, \dots\), total \(O(n)\), so inserts are amortised \(O(1)\). If \(n\) keys share one chain or probe path, the \(j\)-th insert scans \(j-1\) entries and \(n\) inserts cost \(\sum_j (j-1) = \Theta(n^2)\).

Hashable keys, and why hash(int) is the weak point

A key needs __hash__ and __eq__ with the contract a == b ⇒ hash(a) == hash(b). Mutable built-ins (list, dict, set) are unhashable; convert to tuple or frozenset. On 64-bit CPython, hash(x) for an integer is \(x \bmod (2^{61}-1)\) with the sign kept (and hash(-1) == -2), so every value below \(2.3\cdot10^{18}\) hashes to itself. Strings and bytes are hashed with SipHash under a per-process random seed (PYTHONHASHSEED); integers never are. That asymmetry is the whole anti-hash story.

Implementation: a chaining map from scratch

class HashMap:
    """Separate chaining, power-of-two buckets, doubles when load factor exceeds 1."""
    def __init__(self, cap=8):
        self.b = [[] for _ in range(cap)]
        self.size = 0

    def _chain(self, key):
        return self.b[hash(key) & (len(self.b) - 1)]

    def get(self, key, default=None):
        for k, v in self._chain(key):
            if k == key:
                return v
        return default

    def put(self, key, value):
        ch = self._chain(key)
        for i, (k, _) in enumerate(ch):
            if k == key:
                ch[i] = (key, value)
                return
        ch.append((key, value))
        self.size += 1
        if self.size > len(self.b):                 # rehash into twice as many buckets
            old, self.b = self.b, [[] for _ in range(2 * len(self.b))]
            for chain in old:
                for k, v in chain:
                    self._chain(k).append((k, v))

    def remove(self, key):
        ch = self._chain(key)
        for i, (k, _) in enumerate(ch):
            if k == key:
                ch[i] = ch[-1]; ch.pop(); self.size -= 1
                return True
        return False

Test it against dict on random put/get/remove sequences. It is a teaching tool: the built-in is roughly two orders of magnitude faster.

Anti-hash tests: passing in practice, failing on a hack

Setters' tests are random, so your dict sees well-spread keys and passes. On Codeforces anyone may add a test during a hacking phase (Educational and Div. 3 rounds have a 12-hour open one), and the hacker knows your hash function: the identity, plus the probe recurrence published in dictobject.c. Hack generators simulate that recurrence to find in-range values whose probe paths pile up. The demo uses a cruder family where every key hashes to 0.

import random, time

P = (1 << 61) - 1                       # sys.hash_info.modulus on 64-bit CPython
M64 = (1 << 64) - 1
SALT = random.getrandbits(64)

def mix(x):                             # salted splitmix64 finaliser: a random bijection of 64-bit keys
    x = (x + SALT) & M64
    x = (x ^ (x >> 30)) * 0xBF58476D1CE4E5B9 & M64
    x = (x ^ (x >> 27)) * 0x94D049BB133111EB & M64
    return x ^ (x >> 31)

def build(keys, f=lambda x: x):
    t = time.perf_counter()
    d = {}
    for k in keys:
        k = f(k)
        d[k] = d.get(k, 0) + 1
    return round(time.perf_counter() - t, 3)

bad = [i * P for i in range(1, 10_001)]  # hash(i * P) == 0 for every i
print("plain", build(bad))
print("xor  ", build(bad, lambda x: x ^ SALT))
print("mix  ", build(bad, mix))

XOR salting is in many templates and breaks tests built for exact values, but it does not destroy structure. Defences, strongest first:

  1. Don't hash. Compress values to 0..k-1 (L24) and index a list. Hack-proof and usually fastest.
  2. Hash something randomised. Count the raw bytes tokens from sys.stdin.buffer.read().split(): seeded SipHash, and no int() (0.08 s vs 0.13 s for \(2\cdot10^5\) tokens). Valid when equal numbers are written identically, as in judge input. Check your judge's PyPy seeds hashes too.
  3. Mix integer keys with the salted mix, about 2–3 µs per key in CPython.

Counter, defaultdict, canonical forms, sets

Counter(it) counts in C; defaultdict(list) groups. The recurring technique is grouping by an invariant: map each object to a canonical form that is equal exactly when the objects are equivalent. Anagrams share ''.join(sorted(w)) (\(O(k\log k)\)) or the 26-count tuple (\(O(k)\)); L37 turns this into polynomial hashes. Sets give dedup, \(O(1)\) membership, and a - b, a & b, a ^ b in linear time. Memory: a dict's tables cost about 50 bytes per entry (sys.getsizeof, \(10^5\) int keys), a list 8 bytes per slot.

def longest_consecutive(nums):
    s, best = set(nums), 0
    for x in s:
        if x - 1 not in s:
            y = x
            while y + 1 in s:
                y += 1
            best = max(best, y - x + 1)
    return best

class FreqStack:
    def __init__(self):
        self.freq, self.level = {}, [[]]
    def push(self, x):
        f = self.freq.get(x, 0) + 1
        self.freq[x] = f
        if f == len(self.level):
            self.level.append([])
        self.level[f].append(x)
    def pop(self):
        x = self.level[-1].pop()
        self.freq[x] -= 1
        if not self.level[-1]:
            self.level.pop()
        return x

Stacks: Implementation and Core Applications

40m video

A stack is the data structure of "the most recent unfinished thing". Whenever a problem nests (brackets, sub-expressions, function calls, undo history), the item you must deal with next is the last one opened, and a Python list used only at its end gives you that in O(1).

LIFO, and the list you already have

st.append(x) is push (amortised \(O(1)\), L3), st.pop() is pop, st[-1] is peek, if st: tests emptiness. Never use insert(0, x) or pop(0): those shift the whole list. The IndexError discipline: every pop() and st[-1] is either guarded by if st or provably safe because of a sentinel pushed at the start (the -1 base index below is one). An unguarded pop on malformed input is the usual runtime error on bracket problems.

Definition · stack invariant

Write down, before coding, what the stack contains after processing a prefix of the input. For brackets: the unmatched opening brackets of the prefix, in order. For the longest valid substring: the index just before the current valid run, then the indices of unmatched (. Every push and pop must preserve the sentence; correctness then follows by induction over the input.

Brackets: matching, and the longest valid substring

With several bracket types, a closer is valid iff the stack's top is its opener; the string is balanced iff the stack ends empty. For longest valid parentheses, keep indices and seed the stack with \(-1\). On ( push \(i\). On ) pop; if the stack is now empty, this ) is unmatched and becomes the new base (push \(i\)); otherwise the run ending at \(i\) starts just after st[-1] and has length \(i - \text{st}[-1]\).

Shunting-yard, derived

Postfix (reverse Polish) needs no brackets: 2 3 4 * + is \(2 + 3\cdot4\), evaluated with one operand stack. To convert infix, read tokens left to right; numbers go straight to the output. An operator cannot be emitted when read, because its right operand has not arrived. It waits on an operator stack until we know nothing to its right binds tighter. When a new operator \(o\) arrives, the operator \(t\) on top of the stack has both operands complete if \(t\) binds at least as tightly as \(o\): prec(t) > prec(o), or equal precedence and \(o\) left-associative (\(a-b-c = (a-b)-c\)). Then emit \(t\) and repeat. For a right-associative \(o\) such as ^ (\(a^{b^c} = a^{(b^c)}\)), equal precedence does not pop. A ( is a barrier that nothing pops past; ) pops down to its (.

Algorithm · Shunting-yard with unary minus
  1. Precedence: + - 1 (left), * / 2 (left), unary minus 3 (right), ^ 4 (right). So \(-2^2 = -4\) and \(-2\cdot3 = (-2)\cdot3\).
  2. A - is unary if it starts the expression or follows an operator or (. A prefix operator has no left operand to wait for, so it is pushed without popping anything.
  3. Binary operator \(o\): while the top is an operator that binds at least as tightly (rule above), pop it to the output; then push \(o\).
  4. At the end pop everything. Each token is pushed and popped at most once: \(O(n)\).

Implementation: calculator and min-stack

import re
from fractions import Fraction

PREC = {'+': (1, 'L'), '-': (1, 'L'), '*': (2, 'L'), '/': (2, 'L'), 'u': (3, 'R'), '^': (4, 'R')}

def to_postfix(expr):
    out, ops, prev = [], [], None
    for t in re.findall(r"\d+|[-+*/^()]", expr):
        if t.isdigit():
            out.append(Fraction(int(t)))
        elif t == '(':
            ops.append(t)
        elif t == ')':
            while ops[-1] != '(':
                out.append(ops.pop())
            ops.pop()
        else:
            if t == '-' and (prev is None or prev in PREC or prev == '('):
                t = 'u'                                   # prefix: pops nothing
            else:
                p = PREC[t][0]
                while ops and ops[-1] != '(':
                    q, assoc = PREC[ops[-1]]
                    if q < p or (q == p and assoc == 'R'):
                        break
                    out.append(ops.pop())
            ops.append(t)
        prev = t
    return out + ops[::-1]

def eval_postfix(post):
    st = []
    for t in post:
        if isinstance(t, Fraction):
            st.append(t)
        elif t == 'u':
            st.append(-st.pop())
        else:
            b, a = st.pop(), st.pop()
            st.append(a + b if t == '+' else a - b if t == '-' else
                      a * b if t == '*' else a / b if t == '/' else a ** b)
    return st[0]

print(eval_postfix(to_postfix("-2 ^ 2 * (3 - 1)")))   # -8
print(eval_postfix(to_postfix("2 ^ 3 ^ 2 - 7 / 2")))  # 1017/2

Min-stack. Pairs (x, min so far) give getMin in \(O(1)\) at two words per item. The encoded trick stores one value: when \(x\) is a new minimum, push \(2x - m\) (where \(m\) is the old minimum) and set \(m = x\). Since \(x < m\), \(2x - m < x\), so a stored value below the current minimum flags an encoded entry, and popping it restores \(m \leftarrow 2m - y\). In Python it saves little; in Java or C++ interviews it is the expected answer, with long to avoid overflow.

class MinStack:
    def __init__(self):
        self.st, self.mn = [], None
    def push(self, x):
        if not self.st:
            self.st.append(x); self.mn = x
        elif x < self.mn:
            self.st.append(2 * x - self.mn); self.mn = x
        else:
            self.st.append(x)
    def pop(self):
        y = self.st.pop()
        if y < self.mn:                       # encoded: the value was the minimum itself
            y, self.mn = self.mn, 2 * self.mn - y
        return y
    def top(self):
        y = self.st[-1]
        return self.mn if y < self.mn else y
    def get_min(self):
        return self.mn

Recursion is a stack you don't control

Every recursive call pushes a frame; CPython raises RecursionError at depth 1000 by default, and raising the limit risks crashing the interpreter on deep inputs (L6). Any recursion converts to a loop over an explicit list of frames: push (node, state), pop, do the next piece of work, push the continuation. DFS on a \(2\cdot10^5\)-node path is the case where you must (L64). Undo stacks and backtracking state are the same pattern: push the change, pop to revert.

    st, cur, k = [], "", 0
    for c in s:
        if c.isdigit():
            k = 10 * k + int(c)
        elif c == '[':

What breaks
  • Popping an empty stack on inputs like "())": guard, or seed a sentinel.
  • Forgetting the final check: "((" never fails a match; balanced means the stack ends empty.
  • Wrong associativity: popping on equal precedence for ^ computes \((2^3)^2 = 64\) instead of \(2^9 = 512\).
  • Unary minus treated as binary: "-3" or "2*-3" pops an empty operand stack.
  • Floor vs truncate: Python's // and % floor; most statements want truncation toward zero.
  • Multi-digit numbers read one character at a time: accumulate k = 10*k + d or tokenise with a regex.
  • cur += c in a long loop is fine in CPython for a uniquely referenced string but quadratic on PyPy; build a list and join when strings get long (L36).

Monotonic Stack: Next Greater Element and the Histogram Family

55m video

When the question is "for every element, the nearest element to one side that is bigger (or smaller)", keep a stack of the candidates that could still be an answer. Each new element pops the candidates it makes useless, the stack stays sorted, and the whole scan costs O(n) because every index is pushed and popped once.

The invariant

The brute force scans outward from each \(i\): \(O(n^2)\) on a decreasing array. Scan instead from the side where answers live (right to left for "next greater"). Index \(j\) on the stack is useless for \(i\) and for every index further left once some \(k\) between them has \(a_k \ge a_j\): \(k\) is closer and at least as large. So pop every \(j\) with \(a_j \le a_i\), read the answer off the top, push \(i\).

Theorem · monotonic stack

Invariant: after processing \(i\) (scanning right to left), the stack holds, from top to bottom, \(i\) and then exactly the indices \(j > i\) whose value is strictly greater than every value in \(a[i..j-1]\); their values strictly increase downward. The top after popping is therefore the nearest strictly greater element. Cost: each index is pushed once and popped at most once, so the total number of stack operations is at most \(2n\) even though one step may pop many: \(O(n)\) amortised.

One function, four variants

"Greater" vs "smaller" flips the comparison; "strict" vs "or equal" decides whether equal values block; "next" vs "previous" flips the scan direction. Missing answers default to the sentinels \(n\) (right) and \(-1\) (left), which is exactly what width formulas want: they behave like bars of height \(-\infty\) just outside the array.

from operator import gt, ge, lt, le

def nearest(a, side="right", cmp=gt):
    """res[i] = nearest j on `side` of i with cmp(a[j], a[i]); n or -1 if none.
    gt: greater, ge: greater-or-equal, lt: smaller, le: smaller-or-equal."""
    n = len(a)
    res = [n if side == "right" else -1] * n
    order = range(n - 1, -1, -1) if side == "right" else range(n)
    st = []
    for i in order:
        x = a[i]
        while st and not cmp(a[st[-1]], x):   # useless for i and everything beyond
            st.pop()
        if st:
            res[i] = st[-1]
        st.append(i)
    return res

Daily temperatures: nearest(t, "right", gt)[i] - i (0 if none). Stock span: i - nearest(p, "left", gt)[i]. One call on \(2\cdot10^5\) elements takes about 0.14 s in CPython 3.12; inlining the comparison saved only about 10% when measured.

Largest rectangle in a histogram

Derivation

An optimal rectangle has the height of its lowest bar, say bar \(i\) (otherwise raise it). Given that height, it should be as wide as possible: extend left until the first bar strictly lower than \(h_i\), and right likewise. With \(L_i\) = previous strictly smaller and \(R_i\) = next strictly smaller, its area is \(h_i (R_i - L_i - 1)\). Taking the maximum over \(i\) is correct, because the optimum is one of these \(n\) candidates. Two monotonic scans: \(O(n)\).

The one-pass version computes \(R_i\) at the moment bar \(i\) is popped: the bar that pops it is its next smaller-or-equal, and the new top is its previous smaller. A final sentinel bar of height 0 flushes the stack. Popping on >= underestimates the width of the earlier of two equal bars, but the later one gets the full width, so the maximum is unaffected.

def largest_rectangle(h):
    h = h + [0]                       # sentinel flushes the stack at the end
    st, best = [-1], 0                # -1: sentinel left boundary
    for i, x in enumerate(h):
        while st[-1] != -1 and h[st[-1]] >= x:
            top = st.pop()
            best = max(best, h[top] * (i - st[-1] - 1))
        st.append(i)
    return best

def maximal_rectangle(grid):          # LeetCode 85: rows of '0'/'1'
    h, best = [0] * len(grid[0]), 0
    for row in grid:
        h = [x + 1 if c == '1' else 0 for x, c in zip(h, row)]
        best = max(best, largest_rectangle(h))
    return best

Maximal rectangle in a binary matrix reduces to one histogram per row: \(h_j\) is the number of consecutive 1s ending at this row in column \(j\). \(O(nm)\).

The contribution technique: sum of subarray minimums

Summing \(\min\) over all \(n(n+1)/2\) subarrays directly is \(O(n^2)\). Reverse the loop: for each element, count the subarrays in which it is the minimum, and add \(a_i \times \text{count}\). This "sum over elements of their contribution" reappears in combinatorics (L121).

Theorem · counting with ties

Let \(L_i\) be the previous index with \(a_j < a_i\) (strict) and \(R_i\) the next index with \(a_j \le a_i\) (non-strict). Then \(a_i\) is the minimum of exactly the subarrays \([l, r]\) with \(L_i < l \le i \le r < R_i\), and every subarray is counted for exactly one \(i\): the rightmost position of its minimum value. Hence $$\sum_{\text{subarrays}} \min = \sum_i a_i\,(i - L_i)\,(R_i - i).$$ If both sides are strict, a subarray with two equal minima is counted twice; if both are non-strict, it is counted zero times. Mixed strictness is the dedup rule.

def sum_subarray_mins(a, mod=10**9 + 7):
    L = nearest(a, "left", lt)        # previous strictly smaller
    R = nearest(a, "right", le)       # next smaller-or-equal
    return sum(a[i] * (i - L[i]) * (R[i] - i) for i in range(len(a))) % mod

def trap(h):                          # LeetCode 42 with a stack: fill layer by layer
    st, water = [], 0
    for i, x in enumerate(h):
        while st and h[st[-1]] < x:
            bottom = st.pop()
            if not st:
                break
            l = st[-1]
            water += (min(h[l], x) - h[bottom]) * (i - l - 1)
        st.append(i)
    return water

Queues, Deques, Circular Buffers

40m video

A queue serves things in arrival order, and every graph lesson from here on runs on one. In Python that means collections.deque, never list.pop(0), plus two classic constructions worth understanding: the fixed-array ring buffer (modular index arithmetic) and the two-stack queue (amortised analysis).

FIFO, and why list.pop(0) is a trap

A list stores its items contiguously from index 0, so removing the front shifts all \(n-1\) remaining pointers: \(O(n)\) per pop, \(O(n^2)\) to drain. Measured on CPython 3.12, draining 20,000 items with pop(0) took 1.7 s and 40,000 took 6.6 s (quadratic), while deque.popleft() drained 40,000 in 3 ms. A BFS written with pop(0) on a \(2\cdot10^5\)-vertex graph is a TLE you will not see on small tests.

collections.deque internals

Definition · CPython deque

A doubly linked list of fixed-size blocks (64 slots each in CPython), with indices of the first and last used slot. Appending or popping at either end touches one block, allocating or freeing a block only at a boundary: \(O(1)\) worst case, no amortisation needed. Indexing d[i] walks blocks from the nearer end: \(O(\min(i, n-i)/64)\), still linear, so a deque is not a random-access array. rotate(k) is \(O(|k|)\); deque(maxlen=k) silently discards from the opposite end when full.

The circular buffer

With a fixed capacity \(C\), store items in an array and let the front move: head is the front's index, and the slot after the back is (head + size) % C. Both ends wrap with modular arithmetic, so no item ever moves.

Full vs empty. If you store only head and tail, the states "empty" and "full" both have head == tail. Either keep an explicit size (below), or sacrifice one slot and declare the buffer full when (tail + 1) % C == head.

class CircularQueue:
    """Fixed-capacity FIFO: head index + size, so full and empty never look alike."""
    def __init__(self, cap):
        self.a = [None] * cap
        self.head = self.size = 0

    def push(self, x):
        assert self.size < len(self.a), "full"
        self.a[(self.head + self.size) % len(self.a)] = x
        self.size += 1

    def pop(self):
        assert self.size, "empty"
        x, self.a[self.head] = self.a[self.head], None      # drop the reference
        self.head = (self.head + 1) % len(self.a)
        self.size -= 1
        return x

    def front(self):
        assert self.size, "empty"
        return self.a[self.head]

    def back(self):
        assert self.size, "empty"
        return self.a[(self.head + self.size - 1) % len(self.a)]

Queue from two stacks, stack from queues

Push onto inbox. To pop, take from outbox; if it is empty, first pour all of inbox into it, which reverses the order so the oldest item ends on top. Pour only when outbox is empty, or newer items would jump ahead of older ones.

class TwoStackQueue:
    def __init__(self):
        self.inbox, self.outbox = [], []
    def push(self, x):
        self.inbox.append(x)
    def _pour(self):
        if not self.outbox:
            while self.inbox:
                self.outbox.append(self.inbox.pop())
    def pop(self):
        self._pour()
        return self.outbox.pop()
    def peek(self):
        self._pour()
        return self.outbox[-1]
    def __len__(self):
        return len(self.inbox) + len(self.outbox)
Theorem · amortised O(1)

Any sequence of \(m\) operations costs \(O(m)\) list operations, although a single pop can cost \(\Theta(n)\).

Proof (potential). Let \(\Phi = 2\,|\text{inbox}| \ge 0\), with \(\Phi = 0\) initially. A push costs 1 and raises \(\Phi\) by 2: amortised 3. A pop that pours \(k\) items costs \(2k + 1\) (pop and push each item, then one pop) and lowers \(\Phi\) by \(2k\): amortised 1. Total actual cost \(\le\) total amortised cost \(\le 3m\). Equivalently: each item is moved from inbox to outbox at most once in its life.

The reverse construction has no such luck. A stack from one queue (LeetCode 225): push \(x\), then rotate the \(n-1\) older items from front to back so \(x\) is in front; pop is popleft. Push is \(\Theta(n)\) every time, because a FIFO cannot reverse order without touching everything.

Deques later, and choosing by phrasing

The monotonic deque of L16 (sliding-window maximum) is the same structure used at both ends. Breadth-first search is a queue of frontier vertices processed in order of distance (L63); 0-1 BFS pushes 0-weight edges to the front and 1-weight edges to the back (L65); and the deque optimisation of DP keeps a window of candidate transitions (L98).

from collections import deque

def josephus(n, k):
    d, out = deque(range(1, n + 1)), []
    while d:
        d.rotate(-(k % len(d)))
        out.append(d.popleft())
    return out

def shortest_subarray(a, K):
    P = [0]
    for x in a:
        P.append(P[-1] + x)
    best, dq = len(a) + 1, deque()
    for j, pj in enumerate(P):
        while dq and pj - P[dq[0]] >= K:
            best = min(best, j - dq.popleft())
        while dq and P[dq[-1]] >= pj:
            dq.pop()
        dq.append(j)
    return best if best <= len(a) else -1

Linked Lists I: Structure and Core Operations

45m video

A linked list trades random access for O(1) insertion and deletion at a node you already hold. Every bug in linked-list code is a pointer overwritten before it was read, or a special case at the head; save before you overwrite, and put a dummy node in front so the head is never special.

When a linked list beats an array

A Python list is a contiguous array of pointers: \(O(1)\) indexing, but inserting or deleting in the middle shifts everything after it. A linked list stores each item in its own node with a pointer to the next, so splicing a node in or out is a constant number of pointer writes, but reaching position \(i\) takes \(i\) steps. In CP the pointer version rarely pays: each node is a separate object (48 bytes for a two-field __slots__ class in CPython 3.12, 56 with a prev field, versus 8 bytes per list slot), and chasing pointers is slow. Interviews ask for them constantly because pointer surgery tests care. The CP-idiomatic form, index arrays, comes at the end.

Singly linked list, with a dummy head

Definition · dummy head

A node that is always present and holds no data; the real head is dummy.next. Every real node now has a predecessor, so "insert at position 0", "delete the head" and "the list is empty" need no special branches. Return dummy.next at the end. It is the single biggest bug-remover in linked-list code.

class Node:
    __slots__ = ("val", "next")
    def __init__(self, val, next=None):
        self.val, self.next = val, next

class SinglyLinkedList:
    def __init__(self, items=()):
        self.dummy, self.size = Node(None), 0
        tail = self.dummy
        for x in items:
            tail.next = Node(x); tail = tail.next; self.size += 1

    def _before(self, index):               # the node just before position `index`
        cur = self.dummy
        for _ in range(index):
            cur = cur.next
        return cur

    def get(self, index):
        if not 0 <= index < self.size:
            raise IndexError(index)
        return self._before(index).next.val

    def insert(self, index, val):           # 0 = new head, size = new tail
        if not 0 <= index <= self.size:
            raise IndexError(index)
        prev = self._before(index)
        prev.next = Node(val, prev.next)    # the new node reads prev.next before it is overwritten
        self.size += 1

    def delete_at(self, index):
        if not 0 <= index < self.size:
            raise IndexError(index)
        prev = self._before(index)
        prev.next = prev.next.next
        self.size -= 1

    def delete_value(self, val):            # every occurrence (LeetCode 203)
        cur = self.dummy
        while cur.next:
            if cur.next.val == val:
                cur.next = cur.next.next; self.size -= 1
            else:
                cur = cur.next              # advance only when nothing was removed

    def __iter__(self):
        cur = self.dummy.next
        while cur:
            yield cur.val
            cur = cur.next

Pointer-rewiring order

Rule · save before you overwrite

A pointer field is the only path to the rest of the list. Before assigning to p.next, make sure its old value is either no longer needed or already stored somewhere (in the new node, or in a local nxt). For an insertion, wire the new node's fields first and overwrite the old nodes' fields last. Python's tuple assignment evaluates the whole right-hand side before assigning, which is why a.next, b.next, prev.next = b.next, a, b (swapping a pair) is safe.

Doubly linked list with a sentinel

Give each node a prev pointer and close the list into a ring through one sentinel node: s.next is the head, s.prev is the tail, and an empty list is the sentinel pointing at itself. There are no None checks left, and any node you hold can be deleted in \(O(1)\), which is what LRU caches need (L31).

class DNode:
    __slots__ = ("val", "prev", "next")
    def __init__(self, val=None):
        self.val = val
        self.prev = self.next = self

class DoublyLinkedList:
    def __init__(self):
        self.s, self.size = DNode(), 0          # sentinel: s.next = head, s.prev = tail

    def insert_after(self, node, val):
        x = DNode(val)
        x.prev, x.next = node, node.next        # 1, 2: only the new node is written
        node.next.prev = x                      # 3: still reaches the old successor
        node.next = x                           # 4: overwrite last
        self.size += 1
        return x

    def push_front(self, val): return self.insert_after(self.s, val)
    def push_back(self, val):  return self.insert_after(self.s.prev, val)

    def remove(self, x):                        # O(1), no edge cases
        x.prev.next, x.next.prev = x.next, x.prev
        self.size -= 1
        return x.val

    def __iter__(self):
        cur = self.s.next
        while cur is not self.s:
            yield cur.val
            cur = cur.next

Array-based linked lists: the CP form

When the items are positions \(0..n-1\) of an array, store the links as two integer lists: nxt[i] and prv[i]. Deleting \(i\) is nxt[prv[i]] = nxt[i]; prv[nxt[i]] = prv[i]. No objects, no attribute lookups, several times faster in Python, and the original indices still give \(O(1)\) access to any element. The typical problem: "elements are removed in a given order; after each removal report something about the current neighbours". Built over the values in sorted order, it also answers "nearest already-inserted value above and below" for a sequence of insertions: run them backwards as deletions.

def delete_in_order(a, order):
    """Remove positions of `a` in the given order; report (left, right) neighbour values at each removal."""
    n = len(a)
    prv = list(range(-1, n - 1))            # -1 means no left neighbour
    nxt = list(range(1, n + 1))             # n means no right neighbour
    out = []
    for i in order:
        l, r = prv[i], nxt[i]
        out.append((a[l] if l >= 0 else None, a[r] if r < n else None))
        if l >= 0: nxt[l] = r
        if r < n: prv[r] = l
    return out

print(delete_in_order([10, 20, 30, 40], [1, 2, 0, 3]))
# [(10, 30), (10, 40), (None, 40), (None, None)]

Padding the array with sentinel positions 0 and \(n+1\) removes the two ifs. A circular version (nxt[n-1] = 0) simulates Josephus Problem I in \(O(n)\).

Linked Lists II: Cycles, Reversal, and LRU/LFU

55m video

Three ideas cover almost every hard linked-list question: reversing a segment in place by moving one node at a time, two pointers at different speeds (Floyd's cycle algorithm, whose proof is a two-line distance argument), and a hash map pointing into a doubly linked list, which is how an LRU cache gets O(1) everything.

Reversal: whole list, sublist, k-groups

Iteratively, walk once and point each node back at its predecessor, saving next first (L30's rule). Recursively, reverse the rest, then make the old successor point back; it is elegant but uses \(n\) stack frames, so in Python it hits RecursionError beyond about 1000 nodes. For a sublist, stop at the node before the block and repeatedly move the node after the block's first node to the block's front: \(r-l\) moves, one pass. Reversing in groups of \(k\) is the same move applied block by block, after checking that \(k\) nodes remain.

class Node:                                  # as in L30
    __slots__ = ("val", "next")
    def __init__(self, val, next=None):
        self.val, self.next = val, next

def reverse(head):
    prev = None
    while head:
        nxt = head.next                          # save before overwriting
        head.next = prev
        prev, head = head, nxt
    return prev

def reverse_rec(head):
    if head is None or head.next is None:
        return head
    new_head = reverse_rec(head.next)
    head.next.next = head                        # old successor points back
    head.next = None
    return new_head

def _front_moves(before, cur, times):            # move cur's successor to the front, `times` times
    for _ in range(times):
        nxt = cur.next
        cur.next, nxt.next, before.next = nxt.next, before.next, nxt

def reverse_between(head, left, right):          # LeetCode 92, 1-indexed
    before = dummy = Node(None, head)
    for _ in range(left - 1):
        before = before.next
    _front_moves(before, before.next, right - left)
    return dummy.next

def reverse_k_group(head, k):                    # LeetCode 25
    before = dummy = Node(None, head)
    while True:
        probe = before
        for _ in range(k):
            probe = probe.next
            if probe is None:
                return dummy.next                # fewer than k left: unchanged
        cur = before.next                        # becomes the block's tail
        _front_moves(before, cur, k - 1)
        before = cur

Floyd's tortoise and hare

Move slow one step and fast two steps at a time. If the list ends, there is no cycle. If they meet, there is one; then restart one pointer at the head, advance both one step at a time, and they meet exactly at the cycle's entry. \(O(n)\) time, \(O(1)\) space, no visited set.

Proof · why phase 2 meets at the entry

Let \(a\) be the distance from head to entry, \(L\) the cycle length. Phase 1 ends within one lap of slow. When slow reaches the entry (after \(a\) steps), fast is already on the cycle, some \(d < L\) steps behind slow along the cycle; each step closes the gap by exactly 1, so they meet within \(L\) more steps. So slow has walked \(a + b\) with \(b \le L\), where \(b\) is the meeting point's distance past the entry, and \(c = L - b\).

Distances. Fast walked twice as far and ends at the same node, so \(2(a+b) = a + b + kL\) for some \(k \ge 1\), i.e. \(a + b = kL\) and $$a = kL - b = (k-1)L + c.$$ Phase 2. A pointer from the head reaches the entry after \(a\) steps. A pointer from the meeting point, after \(a = c + (k-1)L\) steps, has walked \(c\) to the entry and then \(k-1\) full laps: it is also at the entry. Before that, the head pointer is on the tail and the other on the cycle, so they cannot meet earlier (if \(a = 0\) both start at the entry).

def cycle_entry(head):
    """Return (entry node, cycle length), or (None, 0) if the list ends."""
    slow = fast = head
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
        if slow is fast:                         # phase 1: inside the cycle
            length, p = 1, slow.next
            while p is not slow:
                p, length = p.next, length + 1
            p = head                             # phase 2: same speed, a apart
            while p is not slow:
                p, slow = p.next, slow.next
            return p, length
    return None, 0

The same rho shape describes iterating any function \(f\) on a finite set, so Floyd finds cycles in functional graphs (every node has one outgoing edge): CSES — Planets Cycles asks for each start's distance to a repeat, solved for all nodes at once in L74; Pollard's rho factorisation (L118) is Floyd on \(x \mapsto x^2 + c \bmod n\).

The two-pointer catalogue

  • Middle (876). while fast and fast.next: slow ends at the second middle of an even list; start fast = head.next for the first middle.
  • Palindrome (234). Find the middle, reverse the second half, compare, then reverse it back if the caller owns the list. \(O(1)\) space.
  • Intersection (160). Walk p over A then B, q over B then A. Both have walked \(m + n\) steps when they reach the end, so they meet at the first shared node, or at None together.
  • Remove \(n\)-th from end (19). From a dummy, move lead \(n\) steps, then both until lead.next is None; lag.next is the target. The dummy covers deleting the head.

Merge sort is the list sort

Quicksort and heapsort lean on random access. Merge sort needs only sequential access, its merge splices existing nodes (no buffer, unlike arrays), and it is stable. Top-down: split with slow/fast, sort halves, merge (L30); recursion depth \(\log_2 n\) is harmless. For \(O(1)\) extra space go bottom-up: for widths \(1, 2, 4, \dots\) cut off pairs of runs of that width and merge each pair onto a growing tail. Both \(O(n \log n)\).

def sort_list(head):                             # LeetCode 148, top-down; merge() from L30
    if head is None or head.next is None:
        return head
    slow, fast = head, head.next                 # slow ends on the first half's last node
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
    second, slow.next = slow.next, None
    return merge(sort_list(head), sort_list(second))

LRU and LFU caches

LRU evicts the least recently used key. A dict maps key → node; a doubly linked list with a sentinel keeps nodes in recency order. get moves the node to the front; put inserts at the front and, when full, unlinks sentinel.prev and deletes its key from the dict, which is why the node stores its key. Every operation is \(O(1)\). Python's OrderedDict is this structure (move_to_end, popitem(last=False)); interviewers want the hand-built one.

class LRUCache:                                  # LeetCode 146
    class _N:
        __slots__ = ("key", "val", "prev", "next")

    def __init__(self, capacity):
        self.cap, self.map = capacity, {}
        self.s = s = LRUCache._N()               # s.next = most recent, s.prev = least recent
        s.prev = s.next = s

    def _unlink(self, x):
        x.prev.next, x.next.prev = x.next, x.prev

    def _push_front(self, x):
        x.prev, x.next = self.s, self.s.next
        self.s.next.prev = x
        self.s.next = x

    def get(self, key):
        x = self.map.get(key)
        if x is None:
            return -1
        self._unlink(x); self._push_front(x)
        return x.val

    def put(self, key, val):
        x = self.map.get(key)
        if x is not None:
            x.val = val; self._unlink(x)
        else:
            if len(self.map) == self.cap:
                old = self.s.prev
                self._unlink(old); del self.map[old.key]
            x = LRUCache._N(); x.key, x.val = key, val
            self.map[key] = x
        self._push_front(x)

LFU evicts the least frequently used key, ties broken by least recent. Keep freq[key], one recency-ordered bucket per frequency (an OrderedDict used as an ordered set), and minf, the smallest non-empty frequency. A touch moves the key from bucket \(f\) to \(f+1\), and bumps minf if bucket \(f\) was the minimum and is now empty. A new key always has frequency 1, so after an insertion minf = 1; that is the observation that makes minf maintainable in \(O(1)\).

from collections import defaultdict, OrderedDict

class LFUCache:                                  # LeetCode 460
    def __init__(self, capacity):
        self.cap, self.minf, self.val, self.freq = capacity, 0, {}, {}
        self.bucket = defaultdict(OrderedDict)   # freq -> keys, least recent first

    def _touch(self, key):
        f = self.freq[key]
        del self.bucket[f][key]
        if not self.bucket[f]:
            del self.bucket[f]
            if self.minf == f:
                self.minf = f + 1
        self.freq[key] = f + 1
        self.bucket[f + 1][key] = None

    def get(self, key):
        if key not in self.val:
            return -1
        self._touch(key)
        return self.val[key]

    def put(self, key, value):
        if self.cap == 0:
            return
        if key in self.val:
            self.val[key] = value; self._touch(key)
            return
        if len(self.val) == self.cap:
            old, _ = self.bucket[self.minf].popitem(last=False)
            if not self.bucket[self.minf]:
                del self.bucket[self.minf]
            del self.val[old], self.freq[old]
        self.val[key], self.freq[key], self.minf = value, 1, 1
        self.bucket[1][key] = None

Heaps I: Binary Heap From Scratch

50m video

A binary heap answers one question fast, "what is the smallest item?", by keeping a deliberately weak order: every parent is no larger than its children. That weak order fits in a plain array with index arithmetic, costs O(log n) to repair after a push or pop, and can be built from scratch in O(n), which takes a short proof.

The priority queue, and the heap property

Definition

A priority queue supports push(x), peek() (the minimum) and pop() (remove and return the minimum). A binary min-heap is a complete binary tree (every level full except the last, which fills from the left) satisfying the heap property: key(parent) ≤ key(child). Compare the BST property (left subtree < node < right subtree, L53): a BST orders siblings and supports search and in-order iteration; a heap orders only along root-to-leaf paths, which is too weak to search but enough to find the minimum (it is the root) and cheap to maintain.

Completeness lets the tree live in an array with no pointers, level by level. For 0-indexed position \(i\): children at \(2i+1\) and \(2i+2\), parent at \((i-1)//2\). The height is \(\lfloor \log_2 n \rfloor\).

Sift-up and sift-down

Push: append \(x\) at the end (the only place that keeps the tree complete), then sift up: while \(x\) is smaller than its parent, move the parent down a level. Invariant: the heap property holds everywhere except possibly between \(x\)'s current slot and its parent. Pop: the root is the answer; move the last element to the root, then sift down: while it is larger than its smaller child, move that child up. Invariant: the property holds everywhere except between the moving element and its children. Choosing the smaller child is what makes the promoted child a valid parent of its sibling. Both walk one root-to-leaf path: \(O(\log n)\).

Heapify in O(n)

Inserting \(n\) items one by one costs \(\Theta(n\log n)\) in the worst case: each item of a descending sequence is a new minimum and climbs to the root. Bottom-up heapify instead sifts down every internal node, from the last (\(n//2 - 1\)) to the root. When node \(i\) is processed both its subtrees are already heaps, so one sift-down makes the subtree at \(i\) a heap.

Proof · heapify is linear

A heap of \(n\) nodes has at most \(\lceil n/2^{h+1}\rceil\) nodes of height \(h\) (leaves have height 0), and sift-down from height \(h\) costs at most \(h\) swaps and \(2h\) comparisons. So the total work is at most

$$\sum_{h=0}^{\lfloor \log_2 n\rfloor} \left\lceil \frac{n}{2^{h+1}} \right\rceil h \;\le\; \frac{n}{2}\sum_{h \ge 0} \frac{h}{2^{h}} + \sum_{h=0}^{\log_2 n} h \;=\; n + O(\log^2 n) = O(n),$$

using \(\sum_{h\ge0} h x^h = x/(1-x)^2 = 2\) at \(x = \tfrac12\). Intuition: half the nodes are leaves and do nothing, a quarter move at most one level, an eighth at most two; the expensive nodes are rare. Measured on descending input of size \(2^{16}\): heapq.heapify used 1.5 comparisons per item, pushing one by one used 14.0 per item (about \(\log_2 n\)). On random input one-by-one pushes average about 2.3 comparisons each, so the worst case is the one that bites.

Implementation: MinHeap and heapsort

class MinHeap:
    def __init__(self, items=()):
        self.a = list(items)
        for i in range(len(self.a) // 2 - 1, -1, -1):   # heapify, O(n)
            self._down(i)

    def __len__(self):
        return len(self.a)

    def peek(self):
        return self.a[0]

    def push(self, x):
        a = self.a
        a.append(x)
        i = len(a) - 1
        while i > 0:
            p = (i - 1) // 2
            if a[p] <= x:
                break
            a[i] = a[p]                 # move the parent down; write x once at the end
            i = p
        a[i] = x

    def pop(self):
        a = self.a
        last = a.pop()                  # IndexError on empty, like heapq
        if not a:
            return last
        top, a[0] = a[0], last
        self._down(0)
        return top

    def _down(self, i):
        a, n = self.a, len(self.a)
        x = a[i]
        while True:
            c = 2 * i + 1
            if c >= n:
                break
            if c + 1 < n and a[c + 1] < a[c]:
                c += 1                  # the smaller child
            if x <= a[c]:
                break
            a[i] = a[c]
            i = c
        a[i] = x

Moving items into the hole and writing \(x\) once halves the writes compared with swapping. Test it against heapq on \(10^5\) random push/pop sequences, including duplicates.

Heapsort builds a max-heap in place, then repeatedly swaps the root (the maximum) into the last unsorted slot and sifts the new root down within the shrunken heap: \(O(n \log n)\) worst case, \(O(1)\) extra space. It is unstable: on two equal keys \(1_a, 1_b\) the first swap sends \(1_a\) to the end, giving \(1_b, 1_a\). Long jumps between root and end ignore the original order of equal keys.

def heapsort(a):
    def down(i, n):                     # max-heap sift-down within a[:n]
        x = a[i]
        while 2 * i + 1 < n:
            c = 2 * i + 1
            if c + 1 < n and a[c + 1] > a[c]:
                c += 1
            if x >= a[c]:
                break
            a[i] = a[c]
            i = c
        a[i] = x
    n = len(a)
    for i in range(n // 2 - 1, -1, -1):
        down(i, n)
    for end in range(n - 1, 0, -1):
        a[0], a[end] = a[end], a[0]     # the maximum reaches its final slot
        down(0, end)
    return a

Two quirks. heapq is min-only: for a max-heap push -x and negate on the way out. And its private helpers are named the opposite way round: _siftdown moves an item toward the root. With tuples, (priority, item) compares item when priorities tie, which raises TypeError for dicts or custom objects and silently changes order for others. Insert a counter: (priority, next(tie), item) with tie = itertools.count().

No decrease-key. heapq cannot find an item inside the heap. Workaround 1, lazy deletion: push the new (key, item) and, when popping, discard entries that are stale (their key no longer matches the item's current best). The heap grows by one entry per update, so \(O(m \log m)\) for \(m\) updates, which is what Dijkstra does in Python (L67). Workaround 2, an indexed heap: maintain pos[item] on every move so you can sift a specific item; \(O(\log n)\) decrease-key, fiddly to get right.

When a heap is the wrong tool

A heap only knows its minimum. If you need to delete arbitrary keys often, ask for the \(k\)-th smallest, count items below \(x\), or iterate in order, reach for a Fenwick tree over compressed values (L105), a treap (L112) or a sorted-list structure. Two heaps with lazy deletion cover the special case "median of a changing multiset" (L33).

k-way merge

To merge \(k\) sorted sequences of total length \(N\), keep a heap with the first unmerged item of each. The smallest unmerged item overall is the first unmerged item of some sequence, so it is in the heap: pop it, output it, push its successor. The heap never exceeds \(k\) entries. Entries are (value, source, position); the source index breaks ties, so linked-list nodes or other unorderable payloads are never compared (LeetCode 23). heapq.merge(*iterables) does the same lazily.

import heapq

def merge_k(lists):
    h = [(l[0], i, 0) for i, l in enumerate(lists) if l]
    heapq.heapify(h)
    out = []
    while h:
        v, i, j = heapq.heappop(h)
        out.append(v)
        if j + 1 < len(lists[i]):
            heapq.heappush(h, (lists[i][j + 1], i, j + 1))
    return out

Top-k: heap, sort, or quickselect

Theorem · size-k heap

Scan the items, keeping a min-heap \(H\) of at most \(k\). When full, replace the root by \(x\) if \(x\) is larger. Invariant: after each step \(H\) holds the \(k\) largest items seen. A discarded item is smaller than \(k\) items that are kept, so it can never be among the \(k\) largest; the root is therefore the \(k\)-th largest so far. Memory \(O(k)\), time \(O(n \log k)\), and it works on a stream.

Two-heap median of a stream

Split the items into a lower half lo (a max-heap, stored negated) and an upper half hi (a min-heap) with two invariants: every item of lo is \(\le\) every item of hi, and \(|lo| - |hi| \in \{0, 1\}\). Then the median is max(lo) for odd counts and the mean of max(lo) and min(hi) for even counts. To insert \(x\), send it through lo (push, then move lo's maximum to hi): the moved item is \(\ge\) everything left in lo, so order holds. If hi is now larger, move its minimum back. Each step is \(O(\log n)\).

class MedianFinder:                     # LeetCode 295
    def __init__(self):
        self.lo, self.hi = [], []       # lo stores negatives
    def addNum(self, x):
        heapq.heappush(self.hi, -heapq.heappushpop(self.lo, -x))
        if len(self.hi) > len(self.lo):
            heapq.heappush(self.lo, -heapq.heappop(self.hi))
    def findMedian(self):
        if len(self.lo) > len(self.hi):
            return -self.lo[0]
        return (self.hi[0] - self.lo[0]) / 2

Lazy deletion: faking remove()

A sliding window must also delete the item leaving the window, and a heap cannot find it. Record the deletion in a counter instead, and keep a separate live size. Only the top matters, so before every top or pop, discard top items whose counter is positive. Cost: every item is pushed once and leaves the heap once (popped live, or discarded dead), so \(m\) operations do \(O(m)\) heap pops in total, \(O(m \log m)\) time. The heap may hold up to \(m\) dead items, so memory is \(O(m)\), not \(O(\text{window})\).

class LazyHeap:
    """Min-heap with remove(x) for an x known to be present."""
    def __init__(self):
        self.h, self.dead, self.size = [], {}, 0
    def push(self, x):
        heapq.heappush(self.h, x); self.size += 1
    def remove(self, x):
        self.dead[x] = self.dead.get(x, 0) + 1; self.size -= 1
    def _prune(self):
        h, dead = self.h, self.dead
        while h and dead.get(h[0], 0):
            dead[heapq.heappop(h)] -= 1
    def top(self):
        self._prune(); return self.h[0]
    def pop(self):
        self._prune(); self.size -= 1; return heapq.heappop(self.h)
    def __len__(self):
        return self.size

class SlidingMedian:
    """Multiset with add, remove, lower median, and sum of |x - median|."""
    def __init__(self):
        self.lo, self.hi, self.slo, self.shi = LazyHeap(), LazyHeap(), 0, 0  # lo negated
    def _balance(self):
        if len(self.lo) > len(self.hi) + 1:
            x = -self.lo.pop(); self.slo -= x; self.hi.push(x); self.shi += x
        elif len(self.lo) < len(self.hi):
            x = self.hi.pop(); self.shi -= x; self.lo.push(-x); self.slo += x
    def add(self, x):
        if len(self.lo) and x > -self.lo.top():
            self.hi.push(x); self.shi += x
        else:
            self.lo.push(-x); self.slo += x
        self._balance()
    def remove(self, x):
        if x <= -self.lo.top():          # x < max(lo) can only be in lo; ties may come from either
            self.lo.remove(-x); self.slo -= x
        else:
            self.hi.remove(x); self.shi -= x
        self._balance()
    def median(self):
        return -self.lo.top()
    def cost(self):
        m = self.median()
        return m * len(self.lo) - self.slo + self.shi - m * len(self.hi)

def window_costs(a, k):                 # CSES Sliding Window Cost
    sm, out = SlidingMedian(), []
    for i, x in enumerate(a):
        sm.add(x)
        if i >= k:
            sm.remove(a[i - k])
        if i >= k - 1:
            out.append(sm.cost())
    return out

        if j + 1 == len(lists[i]):
            return list(best)
        nxt = lists[i][j + 1]
        mx = max(mx, nxt)
        heapq.heappush(h, (nxt, i, j + 1))


def furthest_building(heights, bricks, ladders):
    h = []
    for i in range(len(heights) - 1):
        d = heights[i + 1] - heights[i]
        if d > 0:
            heapq.heappush(h, d)
            if len(h) > ladders:
                bricks -= heapq.heappop(h)  # pay bricks for the smallest laddered climb
                if bricks < 0:
                    return i
    return len(heights) - 1
What breaks
  • Lazy deletion with the wrong sizes: len(self.h) counts dead entries, so rebalancing on it is wrong. Track live sizes.
  • Removing a value that is not present: the counter goes positive forever and later deletes a live copy.
  • Comparing payloads: (val, node) crashes when values tie; put an index before the payload.
  • Median of an even window in integers: LeetCode 480 wants a float mean; values near \(2^{31}\) overflow in other languages but not in Python.
  • nlargest with \(k\) near \(n\): slower than sorting (table above).
  • Memory blow-up on long streams: dead entries accumulate; rebuild from live items when the heap exceeds twice the live size.

Definition · half-open intervals

Write intervals as \([l, r)\): \(l\) included, \(r\) excluded. Then the length is \(r - l\), \([a, b)\) and \([b, c)\) touch without overlapping, and splitting \([l, r)\) at \(m\) gives \([l, m) \cup [m, r)\) with no off-by-one. Convert a closed integer interval \([l, r]\) to \([l, r+1)\) on input and every boundary question disappears. Tie rule: with half-open intervals, at equal coordinates process ends before starts. If the statement's intervals are closed and touching counts as overlapping, starts come first (or convert to \(r+1\)). The rule depends on the question, so decide it before sorting.

A neat consequence for counting: encode a start as (l, +1) and an end as (r, -1); plain tuple sorting puts \(-1\) before \(+1\) at equal \(x\), which is exactly the half-open rule.

Merge, insert, intersect

Sorted by start, an interval overlaps the current merged block iff its start is at most the block's end, because every later interval starts even later. LeetCode's lists are closed, so [1,4] and [4,5] merge. To insert into a sorted disjoint list, copy everything ending before the new start, absorb everything starting at or before the new end, copy the rest: \(O(n)\). To intersect two sorted disjoint lists, the overlap of the current pair is [max of starts, min of ends] when non-empty, then advance whichever interval ends first: it cannot meet anything further in the other list.

import heapq

def merge(iv):                                   # LeetCode 56
    out = []
    for l, r in sorted(iv):
        if out and l <= out[-1][1]:
            out[-1][1] = max(out[-1][1], r)
        else:
            out.append([l, r])
    return out

def insert(iv, new):                             # LeetCode 57
    (l, r), out, i = new, [], 0
    while i < len(iv) and iv[i][1] < l:
        out.append(iv[i]); i += 1
    while i < len(iv) and iv[i][0] <= r:
        l, r = min(l, iv[i][0]), max(r, iv[i][1]); i += 1
    return out + [[l, r]] + iv[i:]

def intersect(A, B):                             # LeetCode 986
    i = j = 0
    out = []
    while i < len(A) and j < len(B):
        lo, hi = max(A[i][0], B[j][0]), min(A[i][1], B[j][1])
        if lo <= hi:
            out.append([lo, hi])
        if A[i][1] < B[j][1]:
            i += 1
        else:
            j += 1
    return out

Stabbing and covering: two greedy proofs

Theorem · fewest stabbing points

Sort by right end. Place a point at the first interval's right end; skip every interval containing it; repeat. Exchange argument: some optimal solution has a point in the interval \(I\) with the smallest right end \(r\); moving that point right to \(r\) keeps \(I\) stabbed, and every other interval it stabbed has right end \(\ge r\) and contains the old point, so it still contains \(r\). Remove the stabbed intervals and induct. \(O(n\log n)\) (LeetCode 452, "minimum arrows").

Theorem · fewest intervals covering \([0, T]\)

Sort by start. With everything up to reach covered, among intervals starting at or before reach take the one ending furthest; if none extends reach, it is impossible. Greedy stays ahead: by induction, after \(j\) choices the greedy reach is at least the reach of any valid choice of \(j\) intervals, since any \(j\)-th interval of another solution starts within that solution's (shorter) reach and so was a candidate for greedy. One pointer over the sorted list: \(O(n\log n)\).

def min_arrows(iv):                              # closed intervals
    arrows, last = 0, None
    for l, r in sorted(iv, key=lambda p: p[1]):
        if last is None or l > last:
            arrows, last = arrows + 1, r
    return arrows

def min_cover(iv, T):                            # -1 if [0, T] cannot be covered
    iv, i, cnt, reach = sorted(iv), 0, 0, 0
    while reach < T:
        best = reach
        while i < len(iv) and iv[i][0] <= reach:
            best = max(best, iv[i][1]); i += 1
        if best == reach:
            return -1
        reach, cnt = best, cnt + 1
    return cnt

The sweep template, with a counter or a heap

Algorithm · sweep line
  1. Turn each object into events at coordinates (start, end, query point).
  2. Sort events by coordinate, ties by the rule chosen above.
  3. Process in order, updating a structure that summarises the active set: a counter for "how many", a heap for "which ends first" or "tallest", a sorted structure for "which neighbours".
  4. Read the answer from the structure between events.

Max overlap / meeting rooms (LeetCode 253): sort meetings by start and keep a min-heap of end times of rooms in use. If the earliest-ending room is free by this start (h[0] <= start for half-open meetings), reuse it with heapreplace, else open a room. The heap size at the end is the maximum overlap. Employee free time (759): merge everyone's intervals; the gaps between consecutive merged blocks are the common free time. When coordinates are small integers, a difference array (L13) replaces the sort: add 1 at \(l\), subtract 1 at \(r\), prefix-sum. The same template returns in L35 and in geometry (L133).

def sweep(intervals, on_add, on_remove, closed=False):
    """intervals: (l, r, data). Half-open: removals first at equal x; closed=True: additions first."""
    ev = []
    for l, r, data in intervals:
        ev.append((l, 1, data))
        ev.append((r, 0, data))
    first = 1 if closed else 0
    ev.sort(key=lambda e: (e[0], e[1] != first))      # payloads are never compared
    for x, kind, data in ev:
        (on_add if kind else on_remove)(x, data)

def min_rooms(meetings):                         # LeetCode 253, [start, end)
    h = []
    for s, e in sorted(meetings):
        if h and h[0] <= s:
            heapq.heapreplace(h, e)
        else:
            heapq.heappush(h, e)
    return len(h)

The skyline problem

Buildings \((l, r, h)\) on a line; output the outline as key points where the height changes. The outline's height at \(x\) is the largest \(h\) over buildings with \(l \le x < r\), so it can change only at edges. Sweep the edges left to right with a max-heap of active (-height, right end). At each edge, first discard heap tops whose right end is \(\le x\) (lazy deletion keyed by the end coordinate: an expired building only matters once it reaches the top), then push the buildings starting here, and record \((x, \text{top height})\) if it differs from the last recorded height. Sorting starts as \((l, -h)\) before ends \((r, 0)\) processes the tallest start first at a shared \(x\), so no duplicate \(x\) is emitted. \(O(n \log n)\).

def skyline(buildings):                          # LeetCode 218
    ev = sorted([(l, -h, r) for l, r, h in buildings] + [(r, 0, 0) for _, r, _ in buildings])
    heap, out = [(0, float("inf"))], []          # (-height, right end); ground never expires
    for x, negh, r in ev:
        while heap[0][1] <= x:
            heapq.heappop(heap)
        if negh:
            heapq.heappush(heap, (negh, r))
        top = -heap[0][0]
        if not out or out[-1][1] != top:
            out.append([x, top])
    return out

P1 (monotonic stack). Previous strictly taller and next strictly taller are two scans of L28's helper; answer the nearer one. Popping on <= makes equal towers block nothing, as required. \(O(n)\).

import sys

def p1(a):
    n = len(a)
    left, right, st = [-1] * n, [n] * n, []
    for i in range(n):
        while st and a[st[-1]] <= a[i]:
            st.pop()
        if st:
            left[i] = st[-1]
        st.append(i)
    st = []
    for i in range(n - 1, -1, -1):
        while st and a[st[-1]] <= a[i]:
            st.pop()
        if st:
            right[i] = st[-1]
        st.append(i)
    out = []
    for i in range(n):
        d = min(i - left[i] if left[i] >= 0 else n, right[i] - i if right[i] < n else n)
        out.append(d if d < n else -1)
    return out

P2 (heap-greedy). Process jobs by deadline, pushing each profit into a min-heap of chosen jobs; whenever the heap holds more jobs than the current deadline, drop the cheapest. \(O(n\log n)\).

Theorem · heap greedy (proof sketch)

A set of unit jobs is feasible iff for every \(t\) at most \(t\) of them have deadline \(\le t\); earliest-deadline-first then schedules them. These feasible sets form a matroid (CLRS, 3rd ed., §16.5), so a maximum-profit feasible set exists and every maximal feasible set has the same size. Invariant: after the jobs with deadline \(\le d\) are processed, the heap is a maximum-profit feasible subset of them. Adding a job with deadline \(d\) can violate only the constraint at \(t = d\), which counts every chosen job; so if it is violated, exactly one job must leave, and in a matroid the best way to restore independence after adding one element is to drop the cheapest element of the unique circuit it created, here the whole heap plus the new job (removing any one of them restores every constraint).

import heapq

def p2(jobs):                               # [(deadline, profit)]
    h = []
    for d, p in sorted(jobs):
        heapq.heappush(h, p)
        if len(h) > d:
            heapq.heappop(h)
    return sum(h)

P3 (sliding window + counts). "Exactly \(k\)" is not monotone in the window, but "at most \(k\)" is: \(\text{exact}(k) = \text{atmost}(k) - \text{atmost}(k-1)\). For "at most", grow the right end, shrink the left while there are more than \(k\) kinds, and add the window length (the number of good subarrays ending here). A first draft with Counter is fine; the contest version compresses the raw byte tokens through a dict (randomised hashing, L26) and counts in a list. \(O(n)\).

def p3(tokens, k):                          # tokens: raw bytes from sys.stdin.buffer
    rank = {v: i for i, v in enumerate(set(tokens))}
    a = [rank[v] for v in tokens]
    def at_most(k):
        cnt, kinds, l, total = [0] * len(rank), 0, 0, 0
        for r, x in enumerate(a):
            kinds += cnt[x] == 0
            cnt[x] += 1
            while kinds > k:
                y = a[l]; cnt[y] -= 1; kinds -= cnt[y] == 0; l += 1
            total += r - l + 1
        return total
    return at_most(k) - at_most(k - 1)

P4 (sweep). Convert each closed \([l, r]\) to half-open \([l, r+1)\), emit (l, +1) and (r+1, -1), sort. At equal \(x\) the \(-1\)s come first, so the running count after each \(+1\) never exceeds the true coverage at \(x\), and the first time it beats the best we are at the smallest busiest point. A difference array would need \(10^9\) cells. \(O(n \log n)\).

def p4(iv):
    ev = sorted([(l, 1) for l, r in iv] + [(r + 1, -1) for l, r in iv])
    cur = best = 0
    where = None
    for x, d in ev:
        cur += d
        if cur > best:
            best, where = cur, x
    return best, where

P5 (linked list + simulation). Naive rounds rebuild the row each second: \(O(n)\) per round and up to \(n\) rounds. Observation: a soldier's fate depends only on its current left neighbour, which changes only when that neighbour is removed. So after the first round, the only soldiers worth re-checking are the survivors immediately right of a removed block. Keep the row as prv/nxt arrays (L30), decide all victims of a round before unlinking any (removals are simultaneous), unlink, and collect the new candidates. Each removal creates at most one candidate, so the total work is \(O(n)\). (A monotonic-stack DP also solves it in \(O(n)\), the recovery route if the simulation gets messy.)

def p5(a):
    n = len(a)
    prv, nxt, alive = list(range(-1, n - 1)), list(range(1, n + 1)), [True] * n
    cand, rounds = list(range(1, n)), 0
    while True:
        victims = [j for j in cand if alive[j] and prv[j] >= 0 and a[prv[j]] > a[j]]
        if not victims:
            return rounds
        rounds += 1
        for j in victims:
            alive[j] = False
        cand = []
        for j in victims:
            p, q = prv[j], nxt[j]
            if p >= 0:
                nxt[p] = q
            if q < n:
                prv[q] = p
                cand.append(q)              # dead ones are filtered next round

def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    print(p5(list(map(int, data[1:n + 1]))))

if __name__ == "__main__":
    main()

Mistake review, and recovering from the wrong structure

What breaks
  • P1 with < instead of <= lets an equal tower count as taller.
  • P2 without the heap: taking jobs in deadline order while a slot is free keeps (1,5), rejects (1,7), and scores 8 instead of 11 on the sample. The heap is what lets a later, better job replace an earlier one.
  • P3 with exactly-\(k\) windows directly: the left pointer is not monotone and the count is wrong. Use the subtraction.
  • P4 with starts before ends on touching closed intervals that you converted to \(r+1\): double conversion. Convert once, then use the half-open rule.
  • P5 unlinking while scanning: a soldier removed this second kills (or protects) its right neighbour in the same second. Decide first, then unlink.
  • Output: \(2\cdot10^5\) print calls cost about as much as the algorithm. One join.

Forty minutes in with the wrong structure. Stop typing and write the one-sentence invariant the inner loop needs ("I need the nearest live element to the left"; "I need the minimum of the live set"). If your structure cannot do that operation in \(O(1)\) or \(O(\log n)\), no micro-optimisation will save it. Keep the parsing, output and brute force (they are still correct), put the new structure behind the same small function, and rerun the stress test. Rewriting 30 lines is faster than debugging 100.
