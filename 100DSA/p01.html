Phase 1 covers the techniques behind most easy and medium contest problems: simulation, prefix sums and difference arrays, two pointers and sliding windows, monotonic deques, sorting, binary search on arrays and on answers, greedy algorithms with proofs, and coordinate compression with event sweeps. L11 · DAY 8

Arrays & Simulation: The Boring Skill That Wins Contests

40m video

A large share of easy contest problems only ask you to do exactly what the statement says, without an index error. The skill is discipline: one indexing convention, explicit state variables, in-place transformations you can prove, and recognising when a long simulation repeats itself.

Indexing, slicing, ranges

  • Negative indices count from the end: a[-1] is the last element. This is convenient and dangerous: a[i - 1] with \(i = 0\) silently reads the last element instead of raising.
  • Slices a[l:r] are half-open, copy \(r - l\) elements, and clamp silently: a[3:100] is fine, a[5:2] is []. a[::-1] is a reversed copy.
  • Ranges exclude the stop: count down to 0 with range(n - 1, -1, -1), not range(n - 1, 0, -1).
  • In place vs copy: a[:] = b overwrites the existing list object (every alias sees it); a = b rebinds a name. Functions that “modify in place” must use the first form.

Rotation three ways, and the reversal proof

Rotate right by \(k\) (LeetCode 189): a[-k:] + a[:-k] is one line but allocates a copy (and for \(k > n\) the slices clamp and silently return the list unrotated, so reduce \(k\) mod \(n\)); deque.rotate(k) is \(O(k)\) on a deque; the reversal algorithm is \(O(n)\) time and \(O(1)\) extra space.

Theorem · rotation by reversal

Write \(a = AB\) with \(|B| = k\). Since reversal satisfies \((XY)^R = Y^R X^R\) and \((X^R)^R = X\), we get \((A B)^R = B^R A^R\), and reversing the two blocks separately gives \((B^R)^R (A^R)^R = BA\), the right rotation by \(k\). Three reversals touch each element at most twice: \(O(n)\) time, \(O(1)\) extra space. Reduce \(k\) mod \(n\) first.

2D arrays

Build with [[0] * m for _ in range(n)] (L3). Transpose: [list(r) for r in zip(*g)]. Rotate 90° clockwise as a copy: [list(r) for r in zip(*g[::-1])]. In place (LeetCode 48): transpose, then reverse every row. Transposing sends \((i, j) \to (j, i)\) and reversing row \(j\) sends that to \((j, n-1-i)\), which is exactly where a clockwise quarter turn sends \((i, j)\). Spiral order (LeetCode 54) peels the boundary layer by layer with four limits top, bot, left, right; the guard for single rows and columns is where most solutions break.

Flattening: store cell \((i, j)\) of an \(n \times m\) grid at i * m + j. One index operation instead of two, neighbours at \(\pm1\) and \(\pm m\), and a single bytearray for visited flags. Combined with a sentinel border (pad the grid with a ring of # so it becomes \((n+2) \times (m+2)\)), BFS over a grid needs no bounds checks, since the walls stop every walk. In Python this is often noticeably faster for grid BFS; for code that mostly reads whole rows, the 2D form is simpler and fine.

Simulation discipline and cycles

Write the state as explicit variables (position, direction, time, the array) and the step as one function of the state. State the loop invariant (“after iteration \(t\), pos is the position at time \(t\)”). Then decide: if the number of steps is at most about \(10^6\), simulate; if it is \(10^{18}\), either find a formula or notice that the state space is finite, so the sequence of states must eventually repeat.

Algorithm · skip ahead through a cycle
  1. Record first_seen[state] = t and the history of states while stepping.
  2. When the current state was seen at step \(s\), the states from \(s\) on repeat with period \(L = t - s\).
  3. The state at step \(k \ge s\) is history[s + (k - s) % L].

This costs \(O(\text{tail} + L)\) steps and memory, independent of \(k\). The sequence of states of a deterministic step function is a walk in a functional graph (one out-edge per node), whose rho shape returns in L31 (Floyd's constant-memory cycle finding) and L74; the modular jump-ahead reappears in L119.

Implementation

def reverse(a, i, j):                        # reverse a[i..j] in place
    while i < j:
        a[i], a[j] = a[j], a[i]
        i += 1
        j -= 1

def rotate_right(a, k):                      # LeetCode 189
    n = len(a)
    k %= n
    reverse(a, 0, n - 1)
    reverse(a, 0, k - 1)
    reverse(a, k, n - 1)

def rotate_matrix(g):                        # LeetCode 48, clockwise, in place
    n = len(g)
    for i in range(n):
        for j in range(i + 1, n):
            g[i][j], g[j][i] = g[j][i], g[i][j]
    for row in g:
        row.reverse()

def spiral(g):                               # LeetCode 54
    out = []
    top, bot, left, right = 0, len(g) - 1, 0, len(g[0]) - 1
    while top <= bot and left <= right:
        out += g[top][left:right + 1]
        out += [g[i][right] for i in range(top + 1, bot + 1)]
        if top < bot and left < right:       # a lone row or column has no way back
            out += g[bot][left:right][::-1]
            out += [g[i][left] for i in range(bot - 1, top, -1)]
        top, bot, left, right = top + 1, bot - 1, left + 1, right - 1
    return out

def state_after(f, start, k):                # f applied k times; states hashable
    seen, history = {}, []
    state, t = start, 0
    while t < k:
        if state in seen:
            s = seen[state]
            return history[s + (k - s) % (t - s)]
        seen[state] = t
        history.append(state)
        state = f(state)
        t += 1
    return state

a = [1, 2, 3, 4, 5, 6, 7]
rotate_right(a, 3)
assert a == [5, 6, 7, 1, 2, 3, 4]
g = [[1, 2], [3, 4]]
rotate_matrix(g)
assert g == [[3, 1], [4, 2]]
assert spiral([[1, 2, 3], [4, 5, 6], [7, 8, 9]]) == [1, 2, 3, 6, 9, 8, 7, 4, 5]
print(state_after(lambda x: (x * x + 1) % 1000, 7, 10**18))   # 205, instantly

Problems

CSES — Weird Algorithm · CSES — Palindrome Reorder

Weird Algorithm (L1) is pure simulation with an explicit state. Palindrome Reorder: a rearrangement into a palindrome exists iff at most one letter has an odd count. Build half the letters, put the odd letter (if any) in the middle, and mirror. \(O(n)\).

LeetCode 66 Plus One · LeetCode 41 First Missing Positive

66: simulate carrying from the last digit; an all-9 input grows by one digit. 41 (\(O(n)\) time, \(O(1)\) extra space): the answer lies in \(1..n+1\), so place each value \(v \in [1, n]\) at index \(v - 1\) by swapping, then scan for the first index \(i\) with a[i] != i + 1. Each swap puts one value in its final place, so there are at most \(n\) swaps in total, even though the loop is nested.

from collections import Counter

def palindrome_reorder(s):
    cnt = Counter(s)
    odd = [c for c, v in cnt.items() if v % 2]
    if len(odd) > 1:
        return None                          # NO SOLUTION
    half = "".join(c * (v // 2) for c, v in sorted(cnt.items()))
    return half + (odd[0] if odd else "") + half[::-1]

def plus_one(d):
    d = d[:]
    for i in range(len(d) - 1, -1, -1):
        if d[i] < 9:
            d[i] += 1
            return d
        d[i] = 0
    return [1] + d

def first_missing_positive(a):
    n = len(a)
    for i in range(n):
        while 1 <= a[i] <= n and a[a[i] - 1] != a[i]:
            j = a[i] - 1                     # index first, then swap (see What breaks)
            a[i], a[j] = a[j], a[i]
    for i in range(n):
        if a[i] != i + 1:
            return i + 1
    return n + 1

assert palindrome_reorder("AAAACACBA") == "AAACBCAAA" and palindrome_reorder("AB") is None
assert plus_one([9, 9]) == [1, 0, 0]
assert first_missing_positive([3, 4, -1, 1]) == 2 and first_missing_positive([1, 2, 0]) == 3
What breaks
  • Tuple swap with a dependent index. a[i], a[a[i] - 1] = a[a[i] - 1], a[i] assigns a[i] first, so the second target is computed from the new a[i]. On [2, 1] it leaves the list unchanged, and LeetCode 41's while-loop spins forever. Compute j first.
  • a[i - 1] at \(i = 0\) reads the last element instead of failing. Guard or pad with sentinels.
  • k larger than n in rotations: the slicing version silently returns the input unrotated and the reversal version raises IndexError. Reduce \(k\) mod \(n\) first.
  • Mutating while iterating: removing items from the list you loop over skips elements. Build a new list.
  • Simulating \(10^{18}\) steps: detect the cycle or find the formula; don't loop.

Prefix Sums: The First Real Superpower

45m video

Precompute \(P_j = a_0 + \dots + a_{j-1}\) once, and every range sum becomes one subtraction. Better still, “the subarray \([l, r]\) has property X” turns into “two prefix values are related”, so counting subarrays becomes counting pairs of prefixes with a hash map.

Derive it, don't memorise it

Definition · half-open prefix sums

\(P_0 = 0\) and \(P_{j+1} = P_j + a_j\), so \(P_j = \sum_{i < j} a_i\) is the sum of the first \(j\) elements and the array \(P\) has length \(n + 1\). Then

$$\sum_{i=l}^{r} a_i \;=\; \sum_{i < r+1} a_i - \sum_{i < l} a_i \;=\; P_{r+1} - P_l, \qquad \sum_{i=l}^{r-1} a_i = P_r - P_l \text{ for half-open } [l, r).$$

Pick one convention for life. This course uses 0-indexed arrays and a prefix array of length \(n+1\) with \(P_0 = 0\): the half-open sum \([l, r)\) is P[r] - P[l], with no special case at \(l = 0\). With 1-indexed input, read into a[1..n] and the inclusive \([l, r]\) is P[r] - P[l-1]. Mixing the two is the classic off-by-one. Build with list(accumulate(a, initial=0)), which loops in C; write the loop by hand when you need a modulus or other work fused into it.

Which operations work

Theorem · prefix decomposition

If \(\oplus\) is associative and every element has an inverse (a group), then with \(P_j = a_0 \oplus \dots \oplus a_{j-1}\) the range value is \(a_l \oplus \dots \oplus a_{r-1} = P_l^{-1} \oplus P_r\). Associativity lets \(P_r\) split as \(P_l \oplus (a_l \oplus \dots \oplus a_{r-1})\); the inverse cancels the \(P_l\) part.

  • Sum (inverse: negation) and XOR (every element is its own inverse: \(P_l \oplus P_r\)) work directly.
  • Product works only while nothing is 0, since zero has no inverse. Keep a prefix count of zeros and a prefix product of the non-zero values; modulo a prime, divide with pow(x, p - 2, p).
  • Min and max are associative but not invertible: knowing \(\min(a_0..a_{r-1})\) and \(\min(a_0..a_{l-1})\) says nothing about \(\min(a_l..a_{r-1})\). Static range-min queries need a sparse table, \(O(1)\) per query after \(O(n \log n)\) preprocessing (L103).
  • Counts of a condition: \(P_{j+1} = P_j + [\text{condition on } a_j]\) answers “how many vowels / values \(\le x\) / odd numbers in \([l, r)\)” in \(O(1)\).

Prefix sums plus a hash map

To count subarrays with sum exactly \(k\): a subarray \([l, r)\) qualifies iff \(P_r - P_l = k\), so at each right end \(r\), add the number of earlier prefixes equal to \(P_r - k\). One pass, \(O(n)\) expected time.

Proof · divisible by \(k\), by residues

\(\sum_{i=l}^{r-1} a_i \equiv 0 \pmod k \iff P_r \equiv P_l \pmod k\). Group the \(n+1\) prefixes by residue; a class of size \(c\) contributes \(\binom{c}{2}\) pairs. Python's % returns a value in \([0, k)\) for \(k > 0\) even when \(P\) is negative, so no correction is needed (in C++ it is). Pigeonhole bonus: with \(n+1\) prefixes and \(k = n\) residues, some subarray always has a sum divisible by \(n\).

For equal numbers of 0s and 1s, map 0 to −1: the subarray is balanced iff its sum is 0, iff two prefixes are equal. For the longest such subarray, store each prefix value's first index instead of its count.

Implementation: the three variants

from collections import defaultdict

def count_sum_k(a, k):                       # LC 560, CSES Subarray Sums II
    cnt = defaultdict(int)
    cnt[0] = 1                               # the empty prefix P_0 = 0
    p = ans = 0
    for x in a:
        p += x
        ans += cnt[p - k]                    # earlier l with P_l = P_r - k
        cnt[p] += 1
    return ans

def count_div_k(a, k):                       # LC 974, CSES Subarray Divisibility
    cnt = [0] * k
    cnt[0] = 1
    p = ans = 0
    for x in a:
        p = (p + x) % k                      # non-negative in Python
        ans += cnt[p]
        cnt[p] += 1
    return ans

def longest_balanced(bits):                  # LC 525: 0 counts as -1
    first = {0: -1}                          # prefix value -> first index seen
    p = best = 0
    for i, b in enumerate(bits):
        p += 1 if b else -1
        if p in first:
            best = max(best, i - first[p])
        else:
            first[p] = i
    return best

assert count_sum_k([1, 2, 3, -3, 3], 3) == 5
assert count_div_k([4, 5, 0, -2, -3, 1], 5) == 7
assert longest_balanced([0, 1, 1, 0, 1, 1, 1, 0]) == 4
# the planted bug: drop cnt[0] = 1 and count_sum_k([3], 3) returns 0, not 1

Without the seed cnt[0] = 1, every subarray that starts at index 0 is missed, because its left boundary is the empty prefix. The samples often pass anyway; a stress test (L10) catches it within a few cases.

Problems

CSES — Subarray Sums I / II · CSES — Subarray Divisibility · CSES — Maximum Subarray Sum

Sums I (positive values, sum \(= x\)): count_sum_k works; because all values are positive, a sliding window (L15) also does, and avoids hashing. Sums II (values may be negative): only the hash-map version works. Divisibility: count_div_k(a, n). Maximum Subarray Sum (non-empty): the best subarray ending at \(r\) is \(P_{r+1} - \min_{l \le r} P_l\), so track the running minimum prefix. This is Kadane's algorithm in prefix form.

LeetCode 1524 — Number of Sub-arrays With Odd Sum

A subarray's sum is odd iff its two boundary prefixes have different parity. Count the even and odd prefixes seen so far (the empty prefix is even); each new prefix pairs with all earlier prefixes of the other parity.

def max_subarray(a):                         # CSES Maximum Subarray Sum
    best, p, low = a[0], 0, 0                # low = min prefix so far (P_0 = 0)
    for x in a:
        p += x
        best = max(best, p - low)
        low = min(low, p)
    return best

def odd_sum_subarrays(a, mod=10**9 + 7):     # LC 1524
    seen = [1, 0]                            # even / odd prefixes, empty one included
    p = ans = 0
    for x in a:
        p ^= x & 1
        ans += seen[p ^ 1]
        seen[p] += 1
    return ans % mod

assert max_subarray([-1, 3, -2, 5, 3, -5, 2, 2]) == 9 and max_subarray([-3, -1]) == -1
assert odd_sum_subarrays([1, 3, 5]) == 4

Every function here was checked against an \(O(n^3)\) brute force over all subarrays on 3,000 random small arrays.

What breaks
  • Unseeded counter: forgetting cnt[0] = 1 (or first = {0: -1}) misses every subarray starting at index 0.
  • Mixed conventions: P[r] - P[l] with an inclusive r drops the last element. Write the convention as a comment at the top of the file.
  • Updating before querying: incrementing cnt[p] before reading cnt[p - k] counts the empty subarray when \(k = 0\).
  • Window tricks on negative values: two pointers for “sum = x” need non-negative values; with negatives use the hash map.
  • Anti-hash tests: the prefix values are ints, and int hashing is not randomised. On judges with hacks this can be attacked (L26); count_div_k uses a list and is immune.

L13 · DAY 9

2D Prefix Sums & Difference Arrays

50m video

Prefix sums and difference arrays are inverse operations. A prefix array turns range queries into \(O(1)\) subtractions; a difference array turns range updates into \(O(1)\) point edits, with one prefix pass at the end. In two dimensions both follow the same four-corner inclusion–exclusion pattern.

2D prefix sums by inclusion–exclusion

Definition

For an \(n \times m\) grid \(a\), let \(P_{i,j} = \sum_{r < i,\ c < j} a_{r,c}\), an \((n+1) \times (m+1)\) table with zeros in row 0 and column 0. Then

$$P_{i+1,j+1} = a_{i,j} + P_{i,j+1} + P_{i+1,j} - P_{i,j},$$ $$\text{sum of rows } [r_1, r_2),\ \text{cols } [c_1, c_2) \;=\; P_{r_2,c_2} - P_{r_1,c_2} - P_{r_2,c_1} + P_{r_1,c_1}.$$

Maximum-sum submatrix in \(O(n^2 m)\). Fix a top row, then extend the bottom row one step at a time, maintaining each column's sum over the band. Each band collapses to a 1D array, and Kadane's algorithm (L12) finds its best contiguous column range in \(O(m)\). Replacing Kadane with the prefix-plus-hash-map count gives LeetCode 1074.

Difference arrays: \(O(1)\) range updates

Theorem · difference array

Start with \(d = 0\). For each update “add \(x\) to \(a_l..a_r\)” do \(d_l \mathrel{+}= x\), \(d_{r+1} \mathrel{-}= x\). After all updates, the prefix sum \(\sum_{j \le i} d_j\) equals the total added to position \(i\).

Proof

An update \((l, r, x)\) contributes \(+x\) to \(\sum_{j \le i} d_j\) iff \(l \le i\), and \(-x\) iff \(r + 1 \le i\). Both happen iff \(i > r\), giving 0; only the first iff \(l \le i \le r\), giving \(x\). Sum over updates. \(q\) updates plus one pass cost \(O(n + q)\), against \(O(nq)\) for adding naively.

The classic consequence: given \(n\) intervals, the maximum overlap is the maximum prefix sum of “+1 at \(l\), −1 at \(r + 1\)”. That is the seed of every sweep line; when coordinates go up to \(10^9\), sort the events instead of indexing an array (L24). In 2D, adding \(x\) to rows \(r_1..r_2\) and columns \(c_1..c_2\) touches four corners, \(+x\) at \((r_1, c_1)\) and \((r_2{+}1, c_2{+}1)\), \(-x\) at \((r_1, c_2{+}1)\) and \((r_2{+}1, c_1)\), followed by one 2D prefix pass.

The interleaving test

Do all updates happen before all queries? Then a difference array (offline) is enough. Do updates and queries interleave? Then you need prefix sums of a changing array, which is exactly what a Fenwick tree over the difference array provides: range add as two point adds, point query as a prefix sum, both \(O(\log n)\) (L104).

Implementation

from itertools import accumulate

class Prefix2D:
    """P[i][j] = sum of a[r][c] for r < i, c < j."""
    def __init__(self, a):
        P = [[0] * (len(a[0]) + 1)]
        for row in a:                        # row prefix + the row above, at C speed
            P.append([up + left for up, left in zip(P[-1], accumulate(row, initial=0))])
        self.P = P
    def rect(self, r1, c1, r2, c2):          # rows [r1, r2), cols [c1, c2)
        P = self.P
        return P[r2][c2] - P[r1][c2] - P[r2][c1] + P[r1][c1]

def range_adds(n, updates):                  # all updates first; inclusive [l, r]
    d = [0] * (n + 1)
    for l, r, x in updates:
        d[l] += x
        d[r + 1] -= x
    return list(accumulate(d[:n]))

def rect_adds(n, m, updates):                # (r1, c1, r2, c2, x), inclusive corners
    d = [[0] * (m + 1) for _ in range(n + 1)]
    for r1, c1, r2, c2, x in updates:
        d[r1][c1] += x
        d[r1][c2 + 1] -= x
        d[r2 + 1][c1] -= x
        d[r2 + 1][c2 + 1] += x
    out, prev = [], [0] * m
    for i in range(n):
        prev = [p + s for p, s in zip(prev, accumulate(d[i][:m]))]
        out.append(prev)
    return out

pf = Prefix2D([[1, 2, 3], [4, 5, 6]])
assert pf.rect(0, 1, 2, 3) == 2 + 3 + 5 + 6
assert range_adds(5, [(1, 3, 2), (0, 1, 1)]) == [1, 3, 2, 2, 0]
assert rect_adds(2, 2, [(0, 0, 1, 0, 5)]) == [[5, 0], [5, 0]]
# 10**5 random rectangles on 1000 x 1000: about 0.4 s on the test laptop

The comprehension-with-accumulate rows matter: a plain double loop over \(10^6\) cells is several times slower in CPython.

CSES — Range Update Queries (interleaved)

Updates “add \(u\) to \(x_a..x_b\)” and queries “value of \(x_k\)” arrive mixed, so the interleaving test says Fenwick. Keep a Fenwick tree over the difference array; the answer is the original \(x_k\) plus the prefix sum up to \(k\). \(O((n + q)\log n)\).

class Fenwick:                               # 1-indexed; full treatment in L104
    def __init__(self, n):
        self.t = [0] * (n + 1)
    def add(self, i, x):
        t = self.t
        while i < len(t):
            t[i] += x
            i += i & -i
    def prefix(self, i):                     # sum of positions 1..i
        s, t = 0, self.t
        while i:
            s += t[i]
            i -= i & -i
        return s

def range_update_queries(x, ops):
    bit, out = Fenwick(len(x) + 1), []
    for op in ops:
        if op[0] == 1:                       # (1, a, b, u)

Two Pointers

50m video

Two pointers replace a double loop when moving a pointer can safely discard a whole row or column of candidate pairs. That safety is a monotonicity property you must state and prove before writing the loop. Once it holds, each pointer moves at most \(n\) times and the scan is \(O(n)\).

The precondition and the amortised bound

Theorem · opposite-ends pair search

Let \(a\) be sorted ascending and maintain the invariant every pair \((p, q)\) with \(a_p + a_q = x\) has \(i \le p < q \le j\). If \(a_i + a_j < x\), index \(i\) can be dropped (\(i \mathrel{+}= 1\)); if \(a_i + a_j > x\), index \(j\) can be dropped.

Proof

If \(a_i + a_j < x\), then for every \(q \le j\), \(a_i + a_q \le a_i + a_j < x\) by sortedness, so \(i\) pairs with nothing in range and removing it keeps the invariant. The other case is symmetric. Each step moves \(i\) up or \(j\) down, so after at most \(n - 1\) steps \(i = j\): \(O(n)\) after an \(O(n \log n)\) sort.

The general shape: there is a predicate whose truth changes in only one direction as a pointer advances, so a pointer never has to move back. The amortised argument is then always the same: each pointer moves forward at most \(n\) times, so the total work is \(O(n)\) however the moves interleave. Sorting first is legitimate only when the answer does not depend on the original order (a pair of values, a matching). If the problem asks about subarrays or original positions, either keep the indices alongside the values, or you cannot sort at all.

The three patterns

  • A. Opposite ends: pair sum in a sorted array; reversing or partitioning in place; container with most water (LeetCode 11): the area is \((j - i)\min(h_i, h_j)\). Move the shorter side, because every container that keeps the shorter line and moves the other end inward is narrower and no taller.
  • B. Same direction: a slow “write” pointer and a fast “read” pointer (remove duplicates from a sorted array in place); merging two sorted arrays, which is merge sort's inner step (L17); intersecting two sorted lists; matching two sorted sequences greedily (Apartments, below).
  • C. Fast and slow: advance one pointer twice as fast to find the middle of a list or detect a cycle. Floyd's algorithm is L31.

Implementation: 3-sum and merge

3-sum (LeetCode 15): sort, fix the first element \(a_i\), and run pattern A for \(-a_i\) on the suffix. \(O(n^2)\). Uniqueness is the hard part. Skip an \(a_i\) equal to the previous one, since it would generate the same triples. After recording a hit, advance both pointers, then skip duplicate values of \(a_l\) (and by symmetry \(r\) settles itself). Skipping duplicates before checking the sum loses triples like \((-2, 1, 1)\). 4-sum adds one more outer loop with the same skip: \(O(n^3)\).

def three_sum(nums):                         # LeetCode 15
    a, n, out = sorted(nums), len(nums), []
    for i in range(n - 2):
        if a[i] > 0:
            break                            # every later sum is positive
        if i and a[i] == a[i - 1]:
            continue                         # same first value, same triples
        l, r = i + 1, n - 1
        while l < r:
            s = a[i] + a[l] + a[r]
            if s < 0:
                l += 1
            elif s > 0:
                r -= 1
            else:
                out.append([a[i], a[l], a[r]])
                l += 1
                r -= 1
                while l < r and a[l] == a[l - 1]:
                    l += 1                   # skip repeats only after a hit
    return out

def merge(a, b):                             # pattern B: two sorted lists
    i = j = 0
    out = []
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:                     # <= keeps it stable (L17)
            out.append(a[i]); i += 1
        else:
            out.append(b[j]); j += 1
    return out + a[i:] + b[j:]

        if s < x:
            i += 1
        elif s > x:
            j -= 1
        else:
            return p[i] + 1, p[j] + 1

def apartments(want, have, k):

        elif have[j] > want[i] + k:

def trap(h):                                 # LeetCode 42
    i, j, lmax, rmax, water = 0, len(h) - 1, 0, 0, 0
    while i <= j:
        if lmax <= rmax:
            lmax = max(lmax, h[i]); water += lmax - h[i]; i += 1
        else:
            rmax = max(rmax, h[j]); water += rmax - h[j]; j -= 1
    return water

Sliding Window: Fixed and Variable

55m video

A sliding window is two pointers that bound a contiguous subarray. When validity survives shrinking, the left end of the best window never moves backwards, so one template (expand right, shrink left while invalid, record) solves the whole family in \(O(n)\).

Windows versus two pointers

L14's pointers chose a pair of elements; a window's pointers bound a contiguous block \([l, r]\) and maintain an aggregate of it (sum, counts, distinct values) under two operations: add \(a_r\) on the right and remove \(a_l\) on the left. A fixed window of size \(k\) slides both ends together: compute the first window, then for each step add \(a_r\) and remove \(a_{r-k}\), so a rolling sum is s += a[r] - a[r - k]. A variable window grows and shrinks.

Three questions that identify a window problem
  1. Is the object contiguous (subarray, substring)?
  2. Is validity monotone: if \([l, r]\) is valid, is every \([l', r]\) with \(l' \ge l\) valid too? (Equivalently, extending an invalid window never makes it valid.)
  3. Can the aggregate be updated in \(O(1)\) on add and remove?

The variable-window template and its invariant

Algorithm · longest valid window
  1. l = 0. For each r: add a[r].
  2. While the window is invalid: remove a[l], l += 1.
  3. Record r - l + 1 (longest) or add it to a total (number of valid subarrays ending at r).
Theorem · the invariant

If validity is monotone (question 2), then after step 2, \([l, r]\) is the longest valid window ending at \(r\), and the total work is \(O(n)\).

Proof

Let \(L(r)\) be the smallest \(l\) with \([l, r]\) valid. If \([l, r+1]\) is valid then so is \([l, r]\) (a shrink from the right; for “at most” constraints such as counts, sums of non-negatives, or distinctness, dropping elements never hurts). So \(L(r+1) \ge L(r)\): the left end never needs to move back. Inductively, entering iteration \(r+1\) with \(l = L(r)\), the while loop advances \(l\) exactly to \(L(r+1)\). Both pointers only move forward, at most \(n\) times each, so the scan is \(O(n)\) plus the cost of the adds and removes.

For “shortest valid window” the loop flips: while the window is valid, record it and shrink (LeetCode 209, 76). For counting subarrays, sum \(r - l + 1\) over all \(r\). “Exactly \(k\)” counts are “at most \(k\)” minus “at most \(k-1\)”.

Implementation: one template, four problems

from collections import defaultdict

def longest_no_repeat(s):                    # LC 3, CSES Playlist
    cnt, l, best = defaultdict(int), 0, 0
    for r, x in enumerate(s):
        cnt[x] += 1                          # add
        while cnt[x] > 1:                    # invalid
            cnt[s[l]] -= 1                   # remove
            l += 1
        best = max(best, r - l + 1)
    return best

def max_ones_k_flips(a, k):                  # LC 1004
    zeros, l, best = 0, 0, 0
    for r, x in enumerate(a):
        zeros += x == 0
        while zeros > k:
            zeros -= a[l] == 0
            l += 1
        best = max(best, r - l + 1)
    return best

def at_most_k_distinct(s, k):                # LC 340
    cnt, l, best = defaultdict(int), 0, 0
    for r, x in enumerate(s):
        cnt[x] += 1
        while len(cnt) > k:
            cnt[s[l]] -= 1
            if cnt[s[l]] == 0:
                del cnt[s[l]]                # len(cnt) must equal #distinct
            l += 1
        best = max(best, r - l + 1)
    return best

def char_replacement(s, k):                  # LC 424: window minus its top letter <= k
    cnt, l, best = defaultdict(int), 0, 0
    for r, x in enumerate(s):
        cnt[x] += 1
        while (r - l + 1) - max(cnt.values()) > k:   # O(26) per check
            cnt[s[l]] -= 1
            l += 1
        best = max(best, r - l + 1)
    return best

from collections import Counter

def min_len_sum_at_least(a, target):         # LC 209, all a[i] > 0
    s, l, best = 0, 0, float("inf")
    for r, x in enumerate(a):
        s += x
        while s >= target:                   # valid: record, then shrink
            best = min(best, r - l + 1)
            s -= a[l]
            l += 1
    return 0 if best == float("inf") else best

def count_distinct_subarrays(a):             # CSES Distinct Values Subarrays
    last, l, total = {}, 0, 0
    for r, x in enumerate(a):
        if last.get(x, -1) >= l:
            l = last[x] + 1
        last[x] = r
        total += r - l + 1
    return total

def min_window(s, t):                        # LC 76
    need, missing, l = Counter(t), len(t), 0
    best = (float("inf"), 0, 0)
    for r, ch in enumerate(s):
        if need[ch] > 0:
            missing -= 1
        need[ch] -= 1                        # negative = surplus in window
        if missing == 0:
            while need[s[l]] < 0:
                need[s[l]] += 1
                l += 1
            if r - l + 1 < best[0]:
                best = (r - l + 1, l, r + 1)
            need[s[l]] += 1                  # release one needed char
            missing += 1
            l += 1
    return s[best[1]:best[2]]

When the window breaks: negative numbers

“Shortest subarray with sum \(\ge S\)” is a window problem only for non-negative values. With negatives, question 2 fails: removing a negative element from the left raises the sum, so a window that is invalid now may become valid after shrinking, and the template's “while invalid” logic is wrong. Restate it in prefix sums: minimise \(j - i\) subject to \(P_j - P_i \ge S\). Keep candidate left ends \(i\) in a deque with increasing \(P_i\). That is LeetCode 862, solved in L16 with a monotonic deque. For “count subarrays with sum exactly \(k\)” and negatives, use L12's hash map.

What breaks
  • Asymmetric add/remove: incrementing a counter on add but forgetting to del zero keys makes len(cnt) wrong.
  • Recording in the wrong place: “longest” records after shrinking; “shortest” records inside the shrink loop.
  • Negative values silently break monotonicity, and the template returns plausible wrong answers. Check question 2 first.
  • Comparing Counters every step in a fixed window costs \(O(\Sigma)\) per step; fine for 26 letters, slow for large alphabets. Track a “number of mismatched keys” counter instead.
  • Slicing the window (sum(a[l:r+1])) inside the loop makes it \(O(n^2)\). Maintain the aggregate.

Monotonic Deque: Sliding Window Maximum & Friends

45m video

To track the maximum of a sliding window, keep only the elements that could still become the maximum. Those form a decreasing sequence, a deque holds them, and since each index enters and leaves once, the whole scan is \(O(n)\) instead of a heap's \(O(n \log n)\).

The invariant

A heap of window elements works: push each new element, and lazily pop the top while it has expired. That costs \(O(n \log n)\). The deque does better by discarding elements that are dominated.

Theorem · domination

For indices \(j < i\) with \(a_j \le a_i\), index \(j\) is never needed again: every future window that contains \(j\) also contains \(i\) (windows move right, and \(i\) expires after \(j\)), and \(a_i\) is at least as large. Symmetrically, for window minima, a newer, smaller element dominates older, larger ones.

Invariant

The deque holds window indices \(j_1 < j_2 < \dots < j_t\) with \(a_{j_1} > a_{j_2} > \dots > a_{j_t}\): exactly the elements that are larger than everything after them in the window. The front \(j_1\) is the window maximum.

To maintain it at step \(i\): pop from the back while \(a_{\text{back}} \le a_i\) (dominated), push \(i\), then pop the front if it has left the window (\(j_1 \le i - k\)). Each index is pushed once and popped at most once, so the total is \(O(n)\) amortised, with \(O(k)\) memory.

Implementation: why indices, not values

from collections import deque

def sliding_max_values(a, k):                # BUGGY: stores values
    dq, out = deque(), []
    for i, x in enumerate(a):
        while dq and dq[-1] <= x:
            dq.pop()
        dq.append(x)
        if i >= k and dq[0] == a[i - k]:     # "is the expiring value the max?"
            dq.popleft()
        if i >= k - 1:
            out.append(dq[0])
    return out

def sliding_max(a, k):                       # correct: stores indices
    dq, out = deque(), []
    for i, x in enumerate(a):
        while dq and a[dq[-1]] <= x:
            dq.pop()                         # dominated by the newer x
        dq.append(i)
        if dq[0] <= i - k:
            dq.popleft()                     # expired
        if i >= k - 1:
            out.append(a[dq[0]])
    return out

The value version fails on duplicates: the second 3 evicted the first, so when the first 3 expires, the equality test pops the surviving copy. With indices, expiry is a comparison of positions and cannot be confused. For the minimum, flip the comparison to >=. For both at once, run two deques in the same loop. The same loop computes \(\max\) over a sliding window of any array, including a DP array that is still being filled, which is the deque optimisation of L98.

Contrast: the sliding median needs heaps

A median is not dominated by anything, so the deque idea fails. Keep the lower half in a max-heap lo and the upper half in a min-heap hi, sizes balanced so that lo holds the lower median at its top. Removing an expiring element from the middle of a heap is the problem, and lazy deletion (L4) solves it: record the deletion and discard entries only when they surface at a top. Every live value in lo is at most every live value in hi, so “\(v \le\) top of lo” tells you which heap holds \(v\). Keeping a separate pending-deletion table per heap keeps duplicates from confusing the two sides. Tracking each half's sum also gives the cost \(\sum |x - m|\) at the median \(m\), the minimum total adjustment to make all window values equal.

from heapq import heappush, heappop

class WindowMedian:
    def __init__(self):
        self.lo, self.hi = [], []            # lo stores -v (max-heap), hi stores v
        self.dlo, self.dhi = {}, {}          # pending deletions, per heap
        self.nlo = self.nhi = 0              # live sizes, nlo in {nhi, nhi + 1}
        self.slo = self.shi = 0              # live sums
    def _top_lo(self):
        lo, d = self.lo, self.dlo
        while d.get(-lo[0], 0):
            d[-lo[0]] -= 1
            heappop(lo)
        return -lo[0]
    def _top_hi(self):
        hi, d = self.hi, self.dhi
        while d.get(hi[0], 0):
            d[hi[0]] -= 1
            heappop(hi)
        return hi[0]
    def _balance(self):
        if self.nlo > self.nhi + 1:
            v = self._top_lo(); heappop(self.lo); heappush(self.hi, v)
            self.nlo -= 1; self.nhi += 1; self.slo -= v; self.shi += v
        elif self.nlo < self.nhi:
            v = self._top_hi(); heappop(self.hi); heappush(self.lo, -v)
            self.nhi -= 1; self.nlo += 1; self.shi -= v; self.slo += v
    def add(self, v):
        if self.nlo == 0 or v <= self._top_lo():
            heappush(self.lo, -v); self.nlo += 1; self.slo += v
        else:
            heappush(self.hi, v); self.nhi += 1; self.shi += v
        self._balance()
    def remove(self, v):                     # v must be in the window
        if v <= self._top_lo():
            self.dlo[v] = self.dlo.get(v, 0) + 1; self.nlo -= 1; self.slo -= v
        else:
            self.dhi[v] = self.dhi.get(v, 0) + 1; self.nhi -= 1; self.shi -= v
        self._balance()
    def median(self):                        # lower median, as CSES asks
        return self._top_lo()
    def cost(self):
        m = self._top_lo()
        return m * self.nlo - self.slo + self.shi - m * self.nhi

def medians_and_costs(a, k):                 # CSES Sliding Window Median / Cost
    w, med, cost = WindowMedian(), [], []
    for i, x in enumerate(a):
        w.add(x)
        if i >= k:
            w.remove(a[i - k])
        if i >= k - 1:
            med.append(w.median())
            cost.append(w.cost())
    return med, cost

    dp, dq = [0] * len(nums), deque()
    for i, x in enumerate(nums):
        if dq and dq[0] < i - k:
            dq.popleft()
        dp[i] = x + (dp[dq[0]] if dq else 0)
        while dq and dp[dq[-1]] <= dp[i]:
            dq.pop()
        dq.append(i)
    return dp[-1]

def shortest_sum_at_least(a, K):             # LeetCode 862
    P = [0]
    for x in a:
        P.append(P[-1] + x)
    dq, best = deque(), float("inf")
    for j, pj in enumerate(P):
        while dq and pj - P[dq[0]] >= K:
            best = min(best, j - dq.popleft())
        while dq and P[dq[-1]] >= pj:
            dq.pop()
        dq.append(j)
    return -1 if best == float("inf") else best

Sorting From Scratch I: Quadratic Sorts, Merge Sort, Inversions

55m video

You will call sorted in every contest, but the algorithms inside it are the cleanest place to practise loop invariants and divide and conquer. Merge sort also yields, almost for free, a count of inversions: the distance from an array to sorted order.

Three quadratic sorts and their invariants

A sort is stable if equal keys keep their input order. That matters when you sort records by one key after another (L18). Selection sort makes at most \(n-1\) swaps, which only matters when writes are expensive.

Theorem · insertion sort does exactly one shift per inversion

An inversion is a pair \(i < j\) with \(a_i > a_j\). Shifting \(a_j\) left past a larger neighbour swaps one adjacent out-of-order pair, which removes exactly one inversion and creates none. Insertion sort therefore runs in \(\Theta(n + I)\) for \(I\) inversions, and the minimum number of adjacent swaps that sorts the array is exactly \(I\), since no adjacent swap can remove more than one.

That is insertion sort's real use: nearly sorted data (\(I = O(n)\)) and tiny arrays, where its small constant beats everything. Timsort sorts short runs (32–64 elements) with binary insertion sort for exactly this reason (L5 measured the crossover near \(n = 60\)).

Merge sort

Split in half, sort each half recursively, merge the two sorted halves with L14's same-direction two pointers. The merge does at most \(n - 1\) comparisons.

Proof · \(O(n \log n)\), and stability

\(T(n) = 2T(n/2) + \Theta(n)\). In the recursion tree, level \(d\) has \(2^d\) subproblems of size \(n/2^d\), so each level merges \(n\) elements in total, and there are \(\lceil\log_2 n\rceil\) levels: \(\Theta(n \log n)\) in every case. (Master theorem case 2, L5.) Stability: equal elements from the left half precede those from the right in the input; the merge takes from the left on ties (l[i] <= r[j]), so their order survives every level. Writing < instead silently breaks stability.

Bottom-up merge sort skips recursion: merge runs of width 1, 2, 4, … until one run remains. It uses the same \(O(n \log n)\) work, needs no call stack, and is the natural form for linked lists, where splitting is cheap and merging needs no extra array (L31). External sorting is the same idea at disk scale: sort memory-sized chunks into runs, then \(k\)-way merge them with a heap.

Counting inversions during the merge

Every inversion either lies inside one half (counted recursively) or crosses the halves, with its larger element on the left, and is counted exactly once at the moment its smaller, right-side element is taken. Total \(O(n \log n)\), against \(O(n^2)\) for checking all pairs. In Codeforces problems the phrase to look for is “minimum number of adjacent swaps”; by the theorem above it means “count the inversions”.

def insertion_sort(a, ops):
    a = a[:]
    for i in range(1, len(a)):               # a[:i] is sorted
        x, j = a[i], i - 1
        while j >= 0 and a[j] > x:
            ops[0] += 1                      # one shift = one inversion removed
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = x
    return a

def sort_count(a):                           # (sorted copy, number of inversions)
    if len(a) <= 1:
        return a, 0
    m = len(a) // 2
    l, x = sort_count(a[:m])
    r, y = sort_count(a[m:])
    out, i, j, inv = [], 0, 0, x + y
    while i < len(l) and j < len(r):
        if l[i] <= r[j]:                     # ties from the left: stable, no inversion
            out.append(l[i]); i += 1
        else:
            out.append(r[j]); j += 1
            inv += len(l) - i
    return out + l[i:] + r[j:], inv

def merge_sort_bottom_up(a):
    a, n, w = a[:], len(a), 1
    while w < n:

        for lo in range(0, n, 2 * w):

                    b.append(l[i]); i += 1
                else:
                    b.append(r[j]); j += 1
            b += l[i:]
            b += r[j:]

    return a

CSES — Collecting Numbers II

L14 gave rounds \(= 1 + \#\{v : \text{pos}[v+1] < \text{pos}[v]\}\). A swap of values \(x\) and \(y\) changes only the pairs \((x-1, x), (x, x+1), (y-1, y), (y, y+1)\). Subtract their contributions, swap, add them back. Use a set of the affected \(v\) so that adjacent values (\(|x - y| = 1\)) are not counted twice. \(O(1)\) per swap after an \(O(n)\) start. Verified against recomputing from scratch on random swaps.

def collecting_numbers_ii(a, swaps):         # 1-indexed swap positions
    n = len(a)
    pos = [0] * (n + 2)
    for i, v in enumerate(a):
        pos[v] = i
    bad = lambda v: pos[v + 1] < pos[v]      # pair (v, v + 1) forces a new round
    rounds = 1 + sum(bad(v) for v in range(1, n))
    out = []
    for p, q in swaps:
        x, y = a[p - 1], a[q - 1]
        pairs = {v for v in (x - 1, x, y - 1, y) if 1 <= v < n}
        rounds -= sum(bad(v) for v in pairs)
        a[p - 1], a[q - 1] = y, x
        pos[x], pos[y] = q - 1, p - 1
        rounds += sum(bad(v) for v in pairs)
        out.append(rounds)
    return out

Sorting From Scratch II: Quicksort, Quickselect, Linear Sorts, Timsort

55m video

Quicksort is fast on average and quadratic against an adversary unless its pivot is random; quickselect uses the same partition to find the \(k\)-th smallest element in expected linear time. Linear-time sorts beat \(n \log n\) only under assumptions about the values. In Python, the practical lesson is to use sorted with a good key.

Partitioning: Lomuto and Hoare

Lomuto is short and easy to prove, but sends every copy of the pivot to one side, so an all-equal array costs \(\Theta(n^2)\). Hoare walks two pointers inward and swaps misplaced pairs: fewer swaps, equal keys split evenly, and a split point \(j\) with a[lo..j] <= p <= a[j+1..hi]. 3-way is the safe default with duplicates.

import random

def lomuto(a, lo, hi):                       # pivot a[hi]; returns its final index
    p, i = a[hi], lo
    for j in range(lo, hi):                  # a[lo:i] < p <= a[i:j]
        if a[j] < p:
            a[i], a[j] = a[j], a[i]
            i += 1
    a[i], a[hi] = a[hi], a[i]
    return i

def hoare(a, lo, hi):                        # returns j: a[lo..j] <= p <= a[j+1..hi]
    p = a[(lo + hi) // 2]
    i, j = lo - 1, hi + 1
    while True:
        i += 1
        while a[i] < p:
            i += 1
        j -= 1
        while a[j] > p:
            j -= 1
        if i >= j:
            return j
        a[i], a[j] = a[j], a[i]

def quicksort(a, lo=0, hi=None):             # Hoare, random pivot, small side first
    hi = len(a) - 1 if hi is None else hi
    while lo < hi:
        r, mid = random.randint(lo, hi), (lo + hi) // 2
        a[r], a[mid] = a[mid], a[r]
        j = hoare(a, lo, hi)
        if j - lo < hi - j:
            quicksort(a, lo, j); lo = j + 1  # recursion depth stays O(log n)
        else:
            quicksort(a, j + 1, hi); hi = j
    return a

Average versus worst case, and the adversary

Theorem · randomised quicksort

With a uniformly random pivot, the expected number of comparisons is \(2n H_n \approx 1.39\, n \log_2 n\). With a fixed pivot rule there are inputs that cost \(\Theta(n^2)\).

Proof sketch

Let \(z_1 < \dots < z_n\) be the sorted values. \(z_i\) and \(z_j\) are compared iff one of them is the first pivot chosen among \(z_i, \dots, z_j\); otherwise a pivot strictly between them separates them first. By symmetry that happens with probability \(\frac{2}{j - i + 1}\). Summing over pairs gives \(\sum_{i<j} \frac{2}{j-i+1} \le 2n H_n\). With “last element as pivot” on sorted input, every partition peels off one element: \((n-1) + (n-2) + \dots = \Theta(n^2)\).

Measured with a last-element pivot at \(n = 2000\): about 25,000 comparisons on a random permutation, 1,999,000 on sorted or all-equal input. Every deterministic rule has killer inputs (McIlroy's adversary builds them on the fly), and anti-quicksort tests are a well-known Codeforces hack against Java's quicksort-based Arrays.sort on primitives. Python's Timsort is \(O(n \log n)\) worst case and immune.

Quickselect and median of medians

For the \(k\)-th smallest, partition and continue only into the side containing position \(k\). Expected cost \(n + \frac34 n + \dots = O(n)\), because with probability at least \(\frac12\) the pivot lands in the middle half. Median of medians proves deterministic linear time exists. Take medians of groups of 5 and use the median of those (found recursively) as the pivot; at least \(3n/10\) elements lie on each side, so \(T(n) \le T(n/5) + T(7n/10) + O(n) = O(n)\) since \(\frac15 + \frac7{10} < 1\). Its constant is large; contests use the random pivot.

import random

def quickselect(a, k):                       # k-th smallest, 0-based; expected O(n)
    a = a[:]
    lo, hi = 0, len(a) - 1
    while True:
        p = a[random.randint(lo, hi)]
        lt, i, gt = lo, lo, hi               # a[lo:lt] < p, a[lt:i] == p, a[gt+1:] > p
        while i <= gt:
            if a[i] < p:
                a[lt], a[i] = a[i], a[lt]; lt += 1; i += 1
            elif a[i] > p:
                a[i], a[gt] = a[gt], a[i]; gt -= 1
            else:
                i += 1
        if k < lt:
            hi = lt - 1
        elif k > gt:
            lo = gt + 1
        else:
            return p                         # position k holds a copy of p

def find_kth_largest(nums, k):               # LeetCode 215
    return quickselect(nums, len(nums) - k)

Linear-time sorts, and their fine print

Any comparison sort needs \(\lceil\log_2 n!\rceil = \Theta(n \log n)\) comparisons in the worst case, since a decision tree must have \(n!\) leaves. Linear sorts escape the bound by using values as array indices:

  • Counting sort: integer keys in \([0, k)\), \(O(n + k)\) time and space, stable if written with prefix positions. Linear only when \(k = O(n)\).
  • Radix sort (LSD): \(d\) stable counting-sort passes on base-\(b\) digits, \(O(d(n + b))\). For 32-bit keys with \(b = 2^{16}\), two passes.
  • Bucket sort: \(n\) buckets over \([0, 1)\); expected \(O(n)\) only if the values are roughly uniform.
import random
import time

def radix_sort_u32(a):                       # LSD, two stable passes of 16 bits
    for shift in (0, 16):
        buckets = [[] for _ in range(1 << 16)]
        for x in a:
            buckets[(x >> shift) & 0xFFFF].append(x)
        a = [x for b in buckets for x in b]
    return a

The CP trap: a linear sort written in Python loses to an \(n \log n\) one written in C. Counting sort pays only for small \(k\) when you need the counts anyway.

Timsort and custom keys

Python's list.sort is Timsort: it finds natural runs (ascending, or strictly descending and reversed), extends short runs to 32–64 elements with binary insertion sort, and merges runs from a stack (CPython 3.11+ orders merges by the “powersort” rule). A merge where one run keeps winning switches to galloping (exponential search). Stable, \(O(n)\) on sorted or reversed data, \(O(n \log n)\) worst case.

  • Prefer key=: it runs \(n\) times and the comparisons happen in C; cmp_to_key runs Python code \(O(n \log n)\) times (2.5× slower on \(10^5\) records).
  • Three keys: key=lambda r: (-r.score, r.name, r.id), negating numbers for descending order. Strings can't be negated: sort by the secondary key, then by the primary with reverse=True, since stable sorts compose.
  • By frequency: sorted(a, key=lambda x: (-cnt[x], x)). Comparators only when no key exists (LeetCode 179, L4).

def stick_lengths(p):

            tops.append(c)                   # c >= every top: new tower
        else:

    return len(tops)

    cur = best = 0
    for _, d in events:
        cur += d
        best = max(best, cur)
    return best

Binary Search I: On Sorted Arrays

50m video

Every binary search finds the boundary of a monotone predicate: false, false, …, false, true, …, true. Write that search once, with a half-open interval and an explicit invariant, and every variant (first \(\ge x\), last \(< x\), rotated arrays, matrices) becomes a choice of predicate, not a new loop to debug.

One loop, one invariant

Definition · monotone predicate

A predicate \(p\) on \([lo, hi)\) is monotone if \(p(i) \Rightarrow p(i+1)\): its values read F…F T…T. The task is to find the first T, or \(hi\) if there is none.

Theorem · correctness and termination

With the update rules above, the loop while lo < hi maintains the invariant, terminates after at most \(\lceil\log_2(hi_0 - lo_0)\rceil + 1\) iterations, and returns the first index where \(p\) is true (or \(hi_0\)).

Proof

Initially both known regions are empty. If \(p(mid)\) holds, monotonicity makes everything from \(mid\) on true, so setting \(hi = mid\) keeps the invariant; otherwise everything up to \(mid\) is false and \(lo = mid + 1\) keeps it. Because \(lo \le mid < hi\) when \(lo < hi\) (floor division), each step shrinks \(hi - lo\) to at most \(\lfloor (hi - lo)/2 \rfloor\). At exit \(lo = hi\): every index before it is false and every index from it on is true, so it is the boundary.

Pick this convention forever: half-open \([lo, hi)\), while lo < hi, mid = (lo + hi) // 2, hi = mid or lo = mid + 1. Every other combination is a fresh chance for an off-by-one or an infinite loop. In C or Java, (lo + hi) / 2 can overflow for large indices; Python integers are unbounded, so that bug cannot happen here.

Four questions, one implementation

QuestionPredicate / formulabisect
first index with \(a_i \ge x\)a[i] >= xbisect_left(a, x)
first index with \(a_i > x\)a[i] > xbisect_right(a, x)

Counts follow too: the number of elements equal to \(x\) is bisect_right - bisect_left, and the number in \([l, r]\) is bisect_right(a, r) - bisect_left(a, l). A result of \(-1\) or \(n\) means “no such element”; check for it before indexing.

Implementation: a hand-written bisect, checked against the library

import random
from bisect import bisect_left, bisect_right

def first_true(lo, hi, pred):
    """Smallest i in [lo, hi) with pred(i) true, or hi. pred must be F..F T..T."""
    while lo < hi:
        mid = (lo + hi) // 2
        if pred(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo

def lower_bound(a, x):                       # first a[i] >= x
    return first_true(0, len(a), lambda i: a[i] >= x)

def upper_bound(a, x):                       # first a[i] > x
    return first_true(0, len(a), lambda i: a[i] > x)

  • Peak element (162): the predicate \(a_i > a_{i+1}\) need not be monotone (there can be many peaks), so use an existence invariant instead: “a peak lies in \([lo, hi]\)”. If \(a_{mid} < a_{mid+1}\), the rise guarantees a peak to the right (the array falls to \(-\infty\) at the end); otherwise one lies at \(mid\) or to its left.
  • 2D matrix (74, each row starts above the previous row's end): it is one sorted array of length \(nm\); search \(k\) and read g[k // m][k % m].
def find_min_index(a):                       # LeetCode 153
    return first_true(0, len(a), lambda i: a[i] <= a[-1])

def search_rotated(a, t):                    # LeetCode 33
    p = find_min_index(a)
    lo, hi = (p, len(a)) if t <= a[-1] else (0, p)
    i = first_true(lo, hi, lambda i: a[i] >= t)
    return i if i < hi and a[i] == t else -1

def find_peak(a):                            # LeetCode 162
    lo, hi = 0, len(a) - 1                   # a peak exists in [lo, hi]
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < a[mid + 1]:
            lo = mid + 1
        else:
            hi = mid
    return lo

def search_matrix(g, t):                     # LeetCode 74
    n, m = len(g), len(g[0])
    k = first_true(0, n * m, lambda k: g[k // m][k % m] >= t)
    return k < n * m and g[k // m][k % m] == t

LeetCode 4 — Median of Two Sorted Arrays, in \(O(\log \min(m, n))\)

Cut the shorter array \(A\) before index \(i\) and \(B\) before \(j = \lceil (m+n)/2 \rceil - i\), so the left side holds half the elements. The cut is correct iff \(A_{i-1} \le B_j\) and \(B_{j-1} \le A_i\) (out-of-range entries are \(\mp\infty\)). As \(i\) grows, \(A_i\) rises and \(B_{j-1}\) falls, so \(p(i) = [A_i \ge B_{j-1}]\) is monotone, and its first true \(i\) satisfies both conditions (minimality gives \(A_{i-1} < B_j\)). The median is the larger left-side maximum, or the average with the smaller right-side minimum when \(m + n\) is even.

INF = float("inf")

def median_two(A, B):                        # LeetCode 4
    if len(A) > len(B):
        A, B = B, A
    m, n = len(A), len(B)
    half = (m + n + 1) // 2
    a = lambda i: A[i] if 0 <= i < m else (INF if i >= m else -INF)
    b = lambda j: B[j] if 0 <= j < n else (INF if j >= n else -INF)
    i = first_true(0, m, lambda i: a(i) >= b(half - i - 1))
    j = half - i
    left = max(a(i - 1), b(j - 1))
    return left if (m + n) % 2 else (left + min(a(i), b(j))) / 2

Binary Search II: Binary Search on the Answer

55m video

When it is hard to compute the optimal value directly but easy to check whether a candidate value is achievable, binary search over the candidates. Proving that the check is monotone is the whole problem; the loop is L19's first_true, unchanged.

The recipe

Algorithm · binary search on the answer
  1. Guess a value \(X\) for the answer (capacity, speed, time, distance).
  2. Write feasible(X): can the task be done with answer \(X\)? Usually a greedy or counting pass, \(O(n)\).
  3. Prove monotonicity: if \(X\) is feasible, so is every \(X' > X\) (for “minimise”), or every \(X' < X\) (for “maximise”).
  4. Bound the range \([lo, hi)\) so that the answer is inside, then return first_true(lo, hi, feasible). For “maximise”, find the first infeasible value and subtract 1.

The cost is \(O(\log(\text{range}) \cdot \text{check})\). With \(\text{range} \le 10^{18}\) that is at most 60 checks, so an \(O(n)\) check gives \(O(n \log C)\). How to spot it: “minimise the maximum”, “maximise the minimum”, “smallest \(X\) such that at least \(k\) …”, or an answer range far larger than \(n\).

Classic 1: minimise the maximum load

Split an array into at most \(k\) contiguous parts minimising the largest part sum (CSES Array Division, LeetCode 410, and 1011 with \(k\) = days). feasible(cap) fills parts greedily left to right and opens a new part only when the next element would overflow.

Proof · greedy check is exact, and monotone

Exact: the greedy keeps each part as long as possible. By induction, after \(j\) parts it has covered at least as many elements as any valid split into \(j\) parts with cap \(\le\) cap (greedy stays ahead, L22). So if any split uses at most \(k\) parts, the greedy does too. Monotone: a split valid for cap is valid for any larger cap. So feasibility reads F…F T…T over cap, with lo = max(a) (a part must hold the largest element) and hi = sum(a) + 1.

def first_true(lo, hi, pred):                # L19, unchanged
    while lo < hi:
        mid = (lo + hi) // 2
        if pred(mid):
            hi = mid
        else:
            lo = mid + 1

def split_array(a, k):                       # CSES Array Division, LC 410, LC 1011
    def feasible(cap):
        parts, cur = 1, 0
        for x in a:
            if cur + x > cap:
                parts, cur = parts + 1, x
            else:
                cur += x
        return parts <= k
    return first_true(max(a), sum(a) + 1, feasible)

        return count >= m

Classic 3: the \(k\)-th smallest by counting

To find the \(k\)-th smallest value of a set too large to list, binary search on the value \(x\) with the count check count(≤ x) ≥ k: monotone, because counts only grow with \(x\), and its first true \(x\) is exactly the \(k\)-th smallest. The count is often a two-pointer or staircase pass:

  • LeetCode 719 (\(k\)-th smallest pair distance): sort; pairs with distance \(\le d\) by two pointers, \(O(n)\) per check, \(O(n \log n + n \log C)\) total.
  • LeetCode 378 (\(k\)-th smallest in a row- and column-sorted matrix): staircase count from the top-right corner, \(O(n)\) per check.
  • CSES Multiplication Table (median of the \(n \times n\) table, \(n\) odd): \(\text{count}(x) = \sum_{i=1}^{n} \min(n, \lfloor x/i \rfloor)\), and the median is the first \(x\) with count \(\ge (n^2+1)/2\).
def smallest_distance_pair(nums, k):         # LC 719
    a = sorted(nums)
    def enough(d):
        cnt = l = 0
        for r, x in enumerate(a):
            while x - a[l] > d:
                l += 1
            cnt += r - l                     # pairs (l..r-1, r) within distance d
        return cnt >= k
    return first_true(0, a[-1] - a[0] + 1, enough)

def factory_machines(ks, t):                 # CSES Factory Machines
    return first_true(1, min(ks) * t + 1, lambda T: sum(map(T.__floordiv__, ks)) >= t)

def multiplication_table(n):                 # CSES Multiplication Table
    need = (n * n + 1) // 2
    def enough(x):
        full = min(n, x // n)                # rows i <= x // n are entirely <= x
        return n * full + sum(map(x.__floordiv__, range(full + 1, n + 1))) >= need
    return first_true(1, n * n + 1, enough)

Problems, and the Python cost

CSES — Factory Machines · CSES — Multiplication Table

Factory Machines: in time \(T\) machine \(i\) makes \(\lfloor T/k_i \rfloor\) products, so feasible(T) is \(\sum \lfloor T/k_i \rfloor \ge t\), monotone in \(T\), and \(T = t \cdot \min k_i\) is always enough. The answer can reach \(10^{18}\), which C++ must guard against overflow and Python does not. sum(map(T.__floordiv__, ks)) runs the loop in C and was about 1.7× faster than a generator (L5). Even so, 60 checks over \(2\cdot10^5\) machines took about 2.3 s on the test laptop. Tighter bounds help: \(t/S \le T^* \le (t + n)/S\) with \(S = \sum 1/k_i\) halves the number of iterations. Multiplication Table at \(n \approx 10^6\) is about \(4\cdot10^7\) divisions, roughly 8 s in CPython here even with the C-level loop. This is a PyPy problem.

LeetCode 1482 — Minimum Number of Days to Make m Bouquets

feasible(day): scan the flowers bloomed by day and count runs of \(k\) adjacent ones; monotone, because more days only add bloomed flowers. Answer \(-1\) when \(mk > n\). Combining a binary search with a greedy or prefix-sum check like this is the common shape of medium problems.

What breaks
  • Unproven monotonicity: if feasible can flip back from T to F, the search returns garbage silently. Prove it, or stress against a linear scan over \(X\).
  • Bounds that exclude the answer: lo = 0 for Koko divides by zero; lo = 1 for Array Division is wrong when a single element exceeds the cap. Choose bounds the answer provably lies between.
  • “Maximise” off by one: first_true of ok finds the first true; for T…T F…F predicates search for not ok and subtract 1.
  • Slow checks: 60 iterations × \(O(n)\) Python loop × \(n = 2\cdot10^5\) is \(1.2\cdot10^7\) steps. Move the loop into C (map, sum), tighten bounds, or use PyPy.
  • Floats: ceiling division with math.ceil(p / s) is wrong for large integers; use (p + s - 1) // s.

Binary Search III: Real Numbers, Ternary Search, Advanced Patterns

45m video

On real numbers, loop a fixed number of times instead of testing an epsilon. To minimise a unimodal function, ternary search discards a third of the interval per step. And the halving idea reaches further than arrays: into data structures, batches of offline queries, and trees.

Binary search on doubles: iterate, don't compare with epsilon

Doubles near \(10^9\) are spaced \(2^{-23} \approx 1.2\cdot10^{-7}\) apart. Once lo and hi are adjacent doubles, mid = (lo + hi) / 2 rounds to one of them, the branch that “moves” that endpoint assigns it its own value, and while hi - lo > 1e-9 never ends. Bisecting for \(\sqrt{2\cdot10^{18}}\) with that condition ran into a 10,000-step safety cap with the gap stuck at \(2.4\cdot10^{-7}\).

Rule

Run a fixed number of iterations: each one halves the interval, so 100 iterations shrink any double range by \(2^{100}\), past the resolution of the type. It always terminates and costs at most 100 checks. If the checks are expensive, compute how many you need: \(\lceil\log_2((hi - lo)/\varepsilon)\rceil\).

Output. “Error at most \(10^{-6}\)” means print plenty of digits (f"{x:.10f}"). A tiny negative such as \(-10^{-12}\) prints as -0.000000; round to the printed precision, then add 0.0, which also turns \(-0.0\) into \(0.0\). If the answer can be exact, avoid floats: compare \(a/b < c/d\) as \(ad < cb\).

Ternary search on unimodal functions

Definition · unimodal

\(f\) is (strictly) unimodal on \([lo, hi]\) if there is \(x^*\) with \(f\) strictly decreasing on \([lo, x^*]\) and strictly increasing on \([x^*, hi]\). Convex functions with a minimum in the interval are unimodal; so is a maximum of convex functions.

Theorem · the two-probe step

Let \(lo < m_1 < m_2 < hi\). If \(f(m_1) < f(m_2)\), then \(x^* \le m_2\) (discard \((m_2, hi]\)); otherwise \(x^* \ge m_1\) (discard \([lo, m_1)\)).

Proof

If \(f(m_1) < f(m_2)\) but \(x^* > m_2\), then \(m_1 < m_2 < x^*\) lie on the strictly decreasing part, so \(f(m_1) > f(m_2)\), a contradiction. If \(f(m_1) \ge f(m_2)\) but \(x^* < m_1\), both lie on the increasing part and \(f(m_1) < f(m_2)\), a contradiction. With thirds, each step keeps \(\frac23\) of the interval: 100 iterations shrink it by \((2/3)^{100} \approx 2.5\cdot10^{-18}\).

Unimodal is not monotone. Binary search needs a monotone predicate; ternary search needs a unimodal function. They connect on integers: \(f\) strictly unimodal means the predicate \(f(i+1) - f(i) \ge 0\) is monotone (F…F T…T), and its first true \(i\) is the minimum. That binary search on the “slope” is often the simplest correct integer version. Golden-section search places the probes at ratio \(\varphi - 1 \approx 0.618\) so that one probe is reused each step: one new evaluation per step, shrinking by 0.618, which is worth it when \(f\) is expensive.

Implementation

import math
import random

def ternary_min(f, lo, hi, iters=100):       # f unimodal on [lo, hi], reals
    for _ in range(iters):
        m1 = lo + (hi - lo) / 3
        m2 = hi - (hi - lo) / 3
        if f(m1) < f(m2):
            hi = m2
        else:
            lo = m1
    return (lo + hi) / 2

def ternary_min_int(f, lo, hi):              # f strictly unimodal on integers [lo, hi]
    while hi - lo > 2:                       # d >= 1, so the interval always shrinks
        d = (hi - lo) // 3
        m1, m2 = lo + d, hi - d
        if f(m1) < f(m2):
            hi = m2
        else:
            lo = m1
    return min(range(lo, hi + 1), key=f)     # safe tail: at most 3 candidates

Advanced patterns (previews)

  • Search descent in a data structure. “Smallest prefix with sum \(\ge k\)” over a Fenwick or segment tree: binary searching prefix sums costs \(O(\log^2 n)\), but walking down the tree, choosing a child at each level, is one \(O(\log n)\) descent (L108).
  • Parallel binary search. \(q\) offline queries each ask “after which of \(T\) updates does my condition first hold?”. Run \(\log T\) rounds; in each, sort queries by their midpoint, replay the updates once, and check each query as its midpoint passes: \(O((T + q)\log T)\) operations instead of \(O(qT)\).
  • Binary lifting is binary search on a tree path: to find the highest ancestor satisfying a monotone property, try jumps of \(2^{k}, 2^{k-1}, \dots, 1\) from the largest down, taking each jump that keeps the property. It builds the answer one bit at a time (L57).

Problems

Codeforces — ternary-search problems (e.g. “Weakness and Poorness”)

Codeforces tags these “ternary search”. In Weakness and Poorness, choose a real \(x\) minimising the largest \(|\text{subarray sum}|\) of \(a_i - x\). Each subarray's term is convex in \(x\), and a maximum of convex functions is convex, so ternary-search \(x\) with an \(O(n)\) Kadane pass (max and min subarray sum) per evaluation: \(O(100\,n)\), borderline in CPython at \(n = 2\cdot10^5\).

CSES — Minimum Euclidean Distance (closest pair; full treatment in L132)

Divide and conquer: sort by \(x\), solve both halves, and let \(d\) be the better result. A closer pair must cross the dividing line, so only points within \(d\) of it (the strip) matter. Sorted by \(y\), each strip point needs comparing only with the next 7, because more points than that cannot fit, pairwise \(\ge d\) apart, in a \(d \times 2d\) box. Merging by \(y\) during the recursion gives \(O(n \log n)\), in squared integer distances. The code below matched brute force on 3,000 random point sets but took about 8 s at \(n = 2\cdot10^5\) in CPython on the test laptop: correct, not yet fast enough. L132 makes it fast.

def closest_pair_sq(points):                 # squared distance of the closest pair
    P = sorted(points)
    def rec(lo, hi):                         # returns (best, P[lo:hi] sorted by y)
        if hi - lo <= 3:
            best = min(((P[i][0] - P[j][0]) ** 2 + (P[i][1] - P[j][1]) ** 2
                        for i in range(lo, hi) for j in range(i + 1, hi)), default=float("inf"))
            return best, sorted(P[lo:hi], key=lambda p: p[1])
        mid = (lo + hi) // 2
        xm = P[mid][0]
        (d1, L), (d2, R) = rec(lo, mid), rec(mid, hi)
        best = min(d1, d2)
        ys = sorted(L + R, key=lambda p: p[1])   # Timsort merges two sorted runs in O(n)
        strip = [p for p in ys if (p[0] - xm) ** 2 < best]
        for a in range(len(strip)):
            for b in range(a + 1, min(a + 8, len(strip))):
                dy = strip[b][1] - strip[a][1]
                if dy * dy >= best:
                    break
                best = min(best, (strip[b][0] - strip[a][0]) ** 2 + dy * dy)
        return best, ys
    return rec(0, len(P))[0]

Greedy I: The Method and Its Proofs

50m video

A greedy algorithm commits to the locally best choice and never revisits it. That is only correct when a proof says so. Two proof shapes, the exchange argument and “greedy stays ahead”, cover almost every greedy you will meet, and a two-minute counterexample hunt catches the rest.

Greedy needs proof: a plausible greedy, killed

Coin change, largest coin first: with coins \(\{1, 3, 4\}\) and amount 6, greedy takes \(4 + 1 + 1\) (three coins), but \(3 + 3\) uses two. 0/1 knapsack by value density: capacity 50, items (value, weight) \((60, 10), (100, 20), (120, 30)\). Densities 6, 5, 4: greedy takes the first two for 160, and the third no longer fits; the optimum takes the last two for 220. Both rules sound right and both are wrong. The habit: before coding a greedy, spend two minutes trying to break it on tiny inputs.

Proof shape 1: the exchange argument

Activity selection (CSES Movie Festival): choose the most pairwise-disjoint intervals \([s, e)\). Greedy: sort by end time, and take each interval that starts no earlier than the last taken one ends.

Theorem · activity selection

The earliest-finish greedy returns a maximum set of pairwise-disjoint intervals.

Proof · exchange

Let \(G = (g_1, \dots, g_m)\) be the greedy picks and, among optimal solutions sorted by end time, let \(O = (o_1, \dots, o_k)\) agree with \(G\) on the longest prefix. Suppose they first differ at position \(i \le m\). Both \(g_i\) and \(o_i\) are compatible with \(g_1..g_{i-1} = o_1..o_{i-1}\), and greedy chose the compatible interval that ends first, so \(e(g_i) \le e(o_i) \le s(o_{i+1})\). Replacing \(o_i\) by \(g_i\) keeps \(O\) disjoint and the same size, and it agrees with \(G\) on a longer prefix: a contradiction. So \(O\) begins with \(g_1, \dots, g_m\). If \(k > m\), then \(o_{m+1}\) starts after \(e(g_m)\), and greedy would have taken something rather than stop. Hence \(m = k\).

The same theorem has a stays-ahead proof: by induction, \(e(g_r) \le e(o_r)\) for every \(r\). Greedy's \(r\)-th interval always ends no later than any solution's \(r\)-th, so greedy never runs out of room first.

Proof shape 2: greedy stays ahead

Fractional knapsack: items may be split. Greedy: sort by density \(v_i / w_i\) descending and pour in as much of each as fits.

Proof · stays ahead

Cut every item into infinitesimal units of weight, each worth its item's density. For a feasible load \(S\) and \(t \le W\), let \(S(t)\) be the value of the \(t\) densest units of weight in \(S\), and \(G(t)\) the value of the first \(t\) units greedy loads. Greedy loads units in globally decreasing density, so its first \(t\) units are the \(t\) densest units in the whole instance, and therefore \(G(t) \ge S(t)\) for every \(t\): greedy is ahead at every prefix. At \(t = W\) (or the total weight, if smaller) this says greedy's total is at least \(S\)'s. The cost is \(O(n \log n)\) for the sort.

The proof uses divisibility in an essential way: in 0/1 knapsack the densest units come welded to whole items, the prefix argument fails, and the counterexample above shows it.

Why some greedies are always right: matroids, briefly

A family of “independent” sets is a matroid if it is closed under subsets and, whenever \(|A| < |B|\) are independent, some \(x \in B \setminus A\) keeps \(A \cup \{x\}\) independent. On a matroid, “add the heaviest element that keeps independence” is optimal (Rado–Edmonds). Acyclic edge sets form one, which is why Kruskal works (L72). Most contest greedies are not matroids and need their own exchange argument.

def fractional_knapsack(items, W):           # (value, weight), weight > 0
    total = 0.0
    for v, w in sorted(items, key=lambda it: it[0] / it[1], reverse=True):
        take = min(w, W)
        total += v * take / w
        W -= take
        if W == 0:
            break
    return total

def knapsack_greedy(items, W):               # WRONG for 0/1, kept on purpose
    total = 0
    for v, w in sorted(items, key=lambda it: it[0] / it[1], reverse=True):
        if w <= W:
            total, W = total + v, W - w
    return total

def knapsack_dp(items, W):                   # correct 0/1 knapsack, O(nW)
    best = [0] * (W + 1)
    for v, w in items:
        for c in range(W, w - 1, -1):
            best[c] = max(best[c], best[c - w] + v)
    return best[W]

Choosing the key, and the problems

Most greedies are “sort by the right key, then sweep”, so the proof is really a proof that the key is right: end time for interval packing, duration for minimising total completion time, density for fractional loads, value difference for assignment problems.

CSES — Missing Coin Sum · Tasks and Deadlines · Stick Lengths

Missing Coin Sum (smallest sum not formable): sort the coins and keep the invariant “every sum in \([1, r]\) is formable”. A coin \(c \le r + 1\) extends the range to \([1, r + c]\); a coin \(c > r + 1\) can never help form \(r + 1\), since all later coins are larger and the earlier ones total only \(r\). Tasks and Deadlines (reward \(d_i - f_i\), where \(f_i\) is the finishing time): \(\sum d_i\) is fixed, so minimise \(\sum f_i\). Swapping adjacent tasks with durations \(a > b\) lowers the total by \(a - b\), so shortest first is optimal. Stick Lengths: the median (L18), an exchange of one unit toward the heavier side.

    return jumps

Interval problems come down to choosing the sort key: by end to pack the most intervals, by start to merge them or assign rooms. Minimum rooms, three ways

Theorem · rooms = maximum overlap

The minimum number of rooms equals the largest number of meetings in progress at any instant, and the start-sorted heap greedy achieves it.

Proof

Lower bound: meetings in progress at the same instant need distinct rooms. Upper bound: the greedy opens a new room only when every open room is still occupied at the new meeting's start time. At that moment all of those meetings, plus the new one, are in progress, so the room count never exceeds the overlap.

import heapq

def rooms_heap(meetings):                    # half-open [s, e)
    ends = []
    for s, e in sorted(meetings):
        if ends and ends[0] <= s:
            heapq.heapreplace(ends, e)       # reuse the earliest-freed room
        else:
            heapq.heappush(ends, e)
    return len(ends)

def rooms_events(meetings):                  # (t, -1) sorts before (t, +1): end first
    ev = sorted([(s, 1) for s, _ in meetings] + [(e, -1) for _, e in meetings])
    cur = best = 0
    for _, d in ev:
        cur += d
        best = max(best, cur)
    return best

def rooms_two_pointers(meetings):
    starts, ends = sorted(s for s, _ in meetings), sorted(e for _, e in meetings)
    rooms = j = 0
    for s in starts:
        if s >= ends[j]:
            j += 1                           # some meeting ended: reuse its room
        else:
            rooms += 1
    return rooms

def room_allocation(customers):              # CSES: inclusive days [a, b]
    order = sorted(range(len(customers)), key=lambda i: customers[i][0])
    free, room, k = [], [0] * len(customers), 0     # free: heap of (departure, room)
    for i in order:
        a, b = customers[i]
        if free and free[0][0] < a:          # that guest left before day a
            _, r = heapq.heappop(free)
        else:
            k += 1
            r = k
        room[i] = r
        heapq.heappush(free, (b, r))
    return k, room

When the choice set changes: heap-greedy and regret

A plain sort works when every choice is known up front. When choices become available over time (projects you can now afford, courses whose deadline has come), keep the candidates in a heap. Regret greedy goes further: take every option tentatively, and when a constraint breaks, discard the worst option taken so far.

Algorithm · Course Schedule III (LeetCode 630)
  1. Sort courses by deadline. Keep a max-heap of chosen durations and the total time \(t\).
  2. For each course: push its duration, \(t \mathrel{+}= d\).
  3. If \(t\) exceeds this course's deadline, pop the longest chosen duration and subtract it. That may be the course just added.

Invariant: after the first \(i\) courses by deadline, the heap holds a largest feasible subset of them with the least total time. A new course raises the count by at most one; if it breaks feasibility, dropping the longest restores it with minimum time, since replacing a chosen course by a shorter one never hurts. 1642 Furthest Building has the same shape: put a ladder on every climb, and when one ladder too many is in use, pay bricks for the smallest of those climbs.

import heapq

def schedule_course(courses):                # LeetCode 630: (duration, last_day)
    taken, t = [], 0                         # max-heap of durations, negated
    for d, last in sorted(courses, key=lambda c: c[1]):
        heapq.heappush(taken, -d)
        t += d
        if t > last:
            t += heapq.heappop(taken)        # regret: drop the longest
    return len(taken)

def furthest_building(h, bricks, ladders):   # LeetCode 1642
    climbs = []                              # min-heap: climbs currently on ladders
    for i in range(len(h) - 1):
        d = h[i + 1] - h[i]
        if d > 0:
            heapq.heappush(climbs, d)
            if len(climbs) > ladders:
                bricks -= heapq.heappop(climbs)
                if bricks < 0:
                    return i
    return len(h) - 1

def find_max_capital(k, w, profits, capital):   # LeetCode 502 IPO
    projects, avail, i = sorted(zip(capital, profits)), [], 0
    for _ in range(k):
        while i < len(projects) and projects[i][0] <= w:
            heapq.heappush(avail, -projects[i][1])
            i += 1
        if not avail:
            break
        w -= heapq.heappop(avail)            # best affordable project
    return w

from collections import Counter

def nested_ranges_check(r):                  # -> (contains another, inside another)
    n = len(r)
    order = sorted(range(n), key=lambda i: (r[i][0], -r[i][1]))
    contains, inside = [0] * n, [0] * n
    best = float("-inf")
    for i in order:                          # earlier: l <= l_i (ties: r >= r_i)
        inside[i] = int(best >= r[i][1])
        best = max(best, r[i][1])
    best = float("inf")
    for i in reversed(order):                # later: l >= l_i (ties: r <= r_i)
        contains[i] = int(best <= r[i][1])
        best = min(best, r[i][1])
    dup = Counter(map(tuple, r))
    for i in range(n):
        if dup[tuple(r[i])] > 1:
            contains[i] = inside[i] = 1
    return contains, inside

Choosing the sort key: a checklist

  1. Does the objective count items packed into time? Sort by end.
  2. Do you sweep and maintain a set of active items? Sort by start, keep ends in a heap.
  3. Is it about simultaneity only? Use events, with an explicit tie rule.
  4. Do items unlock over time, or can you undo? Heap of candidates, or a regret heap.
  5. Write the exchange argument for the key before coding, then try to break it with a brute force.

  • Identical intervals in nesting problems: handle duplicates explicitly.
  • Regret without the invariant: popping the newest course instead of the longest passes samples and fails tests.

Coordinate Compression, Offline Sorting & Event Sweeps

45m video

If only the order of values matters, replace them with their ranks: \(10^9\) possible values become at most \(n\) array indices. If all queries are known in advance, answer them in whatever order is convenient. Together, compression and offline sorting turn most “values up to \(10^9\)” problems into L13's arrays and sweeps.

Compression is an order-preserving bijection

Definition

Let \(v_0 < v_1 < \dots < v_{k-1}\) be the distinct values that occur. The map \(\text{rank}(v_i) = i\) is a bijection onto \([0, k)\) with \(x < y \iff \text{rank}(x) < \text{rank}(y)\). Any computation that only compares values gives the same answer on ranks.

Build it with vals = sorted(set(...)) and a dict {v: i} (\(O(n \log n)\), then \(O(1)\) per lookup). For a value that never occurred, such as a query point, bisect_left(vals, q) gives the rank of the first value \(\ge q\). Compress everything together: array values, interval endpoints and query values must go through the same map, or ranks from different maps get compared. Half-open thinking: for coverage of inclusive \([l, r]\), the event happens at \(r + 1\), so compress \(r + 1\) as well. If you compress only \(r\), the point just after \(r\) collapses onto the next coordinate.

The event sweep

Algorithm · sweep line skeleton
  1. Turn each object into events: \((l, +1)\) and \((r + 1, -1)\) for an inclusive interval; queries become events too.
  2. Sort events by coordinate, with an explicit tie rule (here \(-1\) before \(+1\), and queries after both or between, as the problem demands).
  3. Sweep in order, maintaining the state (a counter, a heap, a Fenwick tree); answer queries as you pass them.

This skeleton returns with data structures in L34, on contest day L35, and in plane geometry in L133. With compression, it can also index L13's difference array directly.

from itertools import accumulate

def compress(*seqs):                         # cplib/arrays.py
    """Sorted distinct values of all sequences, and a value -> rank dict."""
    vals = sorted(set().union(*seqs))
    return vals, {v: i for i, v in enumerate(vals)}

def stab_counts(intervals, points):          # how many inclusive [l, r] contain each point
    vals, rank = compress([l for l, _ in intervals], [r + 1 for _, r in intervals], points)
    d = [0] * (len(vals) + 1)
    for l, r in intervals:
        d[rank[l]] += 1
        d[rank[r + 1]] -= 1
    cover = list(accumulate(d))              # cover[i] = intervals containing vals[i]
    return [cover[rank[p]] for p in points]

assert stab_counts([(1, 10**9), (5, 7), (8, 8)], [0, 5, 8, 9, 10**9]) == [0, 2, 2, 1, 1]

Offline queries

“All queries are known in advance” is the trigger. You may then reorder them, for instance by right endpoint, and sweep once. The classic example is counting distinct values in \(a[l..r]\) for many queries: sort queries by \(r\), sweep \(i\) left to right, keep only the last occurrence of each value marked in a Fenwick tree (add \(+1\) at \(i\), \(-1\) at the previous occurrence), and answer every query with \(r = i\) as a range sum. That is the pattern behind L104's offline Fenwick tricks and L111's Mo's algorithm. When offline is impossible: interactive problems, “forced online” inputs where each query is XOR-ed with the previous answer, and APIs like LeetCode 731 that must answer each call immediately.

CSES — Traffic Lights (no sorted container needed)

Lights are added at distinct positions of a street \([0, x]\); after each addition, report the longest stretch without lights. Online, you would want a sorted set plus a multiset of gaps. Offline, reversed: place all lights first, and the longest gap is the last answer. Then remove lights in reverse order of arrival using a linked list over the sorted positions. A removal merges two gaps into one, so the maximum can only grow, and a single running max replaces the multiset. \(O(n \log n)\) for the sort.

def traffic_lights(x, lights):
    pos = sorted([0, x] + lights)
    idx = {p: i for i, p in enumerate(pos)}
    prev = list(range(-1, len(pos) - 1))     # doubly linked list over sorted positions
    nxt = list(range(1, len(pos) + 1))
    best = max(b - a for a, b in zip(pos, pos[1:]))
    ans = [0] * len(lights)
    for k in range(len(lights) - 1, -1, -1):
        ans[k] = best                        # answer after light k was added
        i = idx[lights[k]]
        p, q = prev[i], nxt[i]
        nxt[p], prev[q] = q, p               # unlink light k
        best = max(best, pos[q] - pos[p])
    return ans

assert traffic_lights(8, [3, 6, 2]) == [5, 3, 3]
CSES — Nested Ranges Count

For each range, count how many ranges it contains and how many contain it. Sort by \((l \uparrow, r \downarrow)\) and compress \(r\). Sweeping forward, the ranges already inserted are exactly those with \(l_j \le l_i\) (and \(r_j \ge r_i\) on ties), so “contained by” is the number of inserted \(r_j \ge r_i\): a Fenwick suffix count. Sweeping backward gives “contains” as a count of \(r_j \le r_i\). Identical ranges must count each other, so insert a whole group of identical ranges before querying it, and subtract 1 for the range itself. \(O(n \log n)\); verified against an \(O(n^2)\) count on 3,000 random sets.

from itertools import groupby

class Fenwick:                               # L13 / L104
    def __init__(self, n):
        self.t = [0] * (n + 1)
    def add(self, i, x):
        while i < len(self.t):
            self.t[i] += x
            i += i & -i
    def prefix(self, i):
        s = 0
        while i:
            s += self.t[i]
            i -= i & -i
        return s

def nested_ranges_count(r):                  # -> (contains how many, contained by how many)
    vals, rank = compress([b for _, b in r])
    m = len(vals)
    order = sorted(range(len(r)), key=lambda i: (r[i][0], -r[i][1]))
    groups = [list(g) for _, g in groupby(order, key=lambda i: tuple(r[i]))]
    contains, inside = [0] * len(r), [0] * len(r)
    bit = Fenwick(m)
    for g in groups:
        for i in g:
            bit.add(rank[r[i][1]] + 1, 1)
        for i in g:                          # inserted with r >= r_i, minus itself
            inside[i] = bit.prefix(m) - bit.prefix(rank[r[i][1]]) - 1
    bit = Fenwick(m)
    for g in reversed(groups):
        for i in g:
            bit.add(rank[r[i][1]] + 1, 1)
        for i in g:                          # inserted with r <= r_i, minus itself
            contains[i] = bit.prefix(rank[r[i][1]] + 1) - 1
    return contains, inside

import heapq

def skyline(buildings):                      # LeetCode 218: (left, right, height)
    events = sorted([(l, -h, r) for l, r, h in buildings] + [(r, 0, 0) for _, r, _ in buildings])
    live, out = [(0, float("inf"))], []      # max-heap of (-height, right end); ground
    for x, negh, r in events:
        if negh:
            heapq.heappush(live, (negh, r))
        while live[0][1] <= x:               # lazily drop buildings that have ended
            heapq.heappop(live)
        if not out or out[-1][1] != -live[0][0]:
            out.append([x, -live[0][0]])
    return out

What breaks
  • Two separate maps: compressing the array and the queries independently gives ranks that can't be compared. Compress all values in one call.
  • Forgetting \(r + 1\): inclusive intervals whose end events aren't compressed lose a gap and over-count coverage.
  • Ties in event sorts: decide whether an interval ending at \(t\) overlaps one starting at \(t\), and encode it in the tuple order.
  • Using ranks as lengths: distances are vals[j] - vals[i], not j - i.
  • bisect in a hot loop where a dict lookup works: \(O(\log n)\) instead of \(O(1)\) per value, but correct; choose by whether the value was compressed.

P1 · 313B Ilya and Queries · prefix sums

A string of . and # (\(n \le 10^5\)) and \(m \le 10^5\) queries \((l, r)\): count \(i \in [l, r)\) with \(s_i = s_{i+1}\). Observation: precompute the indicator of each equal adjacent pair and take prefix sums; each query is one subtraction. With \(P_j\) = the number of \(j' \le j\) (0-indexed) with \(s_{j'} = s_{j'-1}\), the answer is \(P_{r-1} - P_{l-1}\). \(O(n + m)\). The real risk is the off-by-one, so check it on the all-dots sample, where every answer is \(r - l\).

import sys

def main():
    data = sys.stdin.buffer.read().split()
    s, m = data[0], int(data[1])
    P = [0] * len(s)
    for i in range(1, len(s)):
        P[i] = P[i - 1] + (s[i] == s[i - 1])
    q = data[2:2 + 2 * m]
    out = [P[int(r) - 1] - P[int(l) - 1] for l, r in zip(q[::2], q[1::2])]
    sys.stdout.write("\n".join(map(str, out)) + "\n")

main()
P2 · 279B Books · sliding window

Start at any book and read consecutive books while the time \(t\) lasts; maximise the count. Observation: reading times are positive, so this is the longest subarray with sum \(\le t\), and L15's three questions all say yes (contiguous, shrinking keeps it valid, \(O(1)\) add and remove). Proof: the longest valid window ending at \(r\) is found by the template's invariant, and for positive values the longest prefix from any start is such a window. \(O(n)\).

import sys

def main():
    data = sys.stdin.buffer.read().split()
    n, t = int(data[0]), int(data[1])
    a = list(map(int, data[2:2 + n]))
    best = l = cur = 0
    for r, x in enumerate(a):
        cur += x
        while cur > t:
            cur -= a[l]
            l += 1
        best = max(best, r - l + 1)
    print(best)

main()
P3 · 1201C Maximum Median · binary search on the answer

\(n\) odd, at most \(k\) unit increments; maximise the median. Observation: after sorting, the median can reach \(m\) iff lifting every element of the upper half (indices \(\ge n/2\)) to at least \(m\) costs \(\sum_{i \ge n/2} \max(0, m - a_i) \le k\). Raising lower elements never helps, and the cost is monotone in \(m\). So binary-search the first unaffordable \(m\) in \([a_{n/2}, a_{n/2} + k + 1)\) and subtract one. \(O(n \log k)\), with an early exit once the cost exceeds \(k\). The answer can exceed \(2\cdot10^9\): no issue in Python.

import sys

def main():
    data = sys.stdin.buffer.read().split()
    n, k = int(data[0]), int(data[1])
    upper = sorted(map(int, data[2:2 + n]))[n // 2:]
    def too_costly(m):
        cost = 0
        for x in upper:
            if x < m:
                cost += m - x
                if cost > k:
                    return True
        return False
    lo, hi = upper[0], upper[0] + k + 1      # first m that is too costly lies in here
    while lo < hi:
        mid = (lo + hi) // 2
        if too_costly(mid):
            hi = mid
        else:
            lo = mid + 1
    print(lo - 1)

main()
P4 · 545C Woodcutters · greedy with proof

Trees at increasing \(x_i\) with heights \(h_i\); each may fall left onto \([x_i - h_i, x_i]\), fall right onto \([x_i, x_i + h_i]\), or stand at \(x_i\), and occupied points may not overlap. Maximise the trees felled. Greedy, left to right, tracking the rightmost occupied point: fall left if it is free; otherwise fall right if that doesn't reach the next tree; otherwise stand. Exchange argument: falling left only occupies points left of \(x_i\), which no later tree can use anyway, so it is never worse than standing. Falling right can block at most the next tree's left fall, so compared with any optimal solution that leaves tree \(i\) standing and fells \(i+1\) to the left, swapping gives the same count; greedy is never behind. \(O(n)\). Brute force over all \(3^n\) choices agreed on 1,500 random cases.

import sys

def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    xs, hs = list(map(int, data[1:2 * n + 1:2])), list(map(int, data[2:2 * n + 2:2]))
    felled, last = 0, float("-inf")          # last = rightmost occupied point
    for i in range(n):
        x, h = xs[i], hs[i]
        if x - h > last:
            felled += 1
            last = x
        elif i == n - 1 or x + h < xs[i + 1]:
            felled += 1
            last = x + h
        else:
            last = x
    print(felled)

main()
P5 · 1000C Covered Points Count · events and sweep

\(n \le 2\cdot10^5\) segments with endpoints up to \(10^{18}\); for each \(k\), count integer points covered by exactly \(k\) segments. Observation: coverage changes only at \(l_i\) (\(+1\)) and \(r_i + 1\) (\(-1\)). Sort the \(2n\) events; between consecutive event coordinates \(x < x'\) the coverage is a constant \(c\), contributing \(x' - x\) points to \(\text{cnt}[c]\). The difference array is indexed by event order, never by coordinate, which is compression done implicitly (L24). Equal coordinates give zero-length gaps and need no tie rule. \(O(n \log n)\).

import sys

def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    ev = []
    for i in range(n):
        l, r = int(data[1 + 2 * i]), int(data[2 + 2 * i])
        ev.append((l, 1))
        ev.append((r + 1, -1))
    ev.sort()
    cnt, cur = [0] * (n + 1), 0
    for (x, d), (nx, _) in zip(ev, ev[1:]):
        cur += d
        cnt[cur] += nx - x                   # coverage is cur on [x, nx)
    print(" ".join(map(str, cnt[1:])))

main()

Scoreboard analysis and common mistakes

  • P1: WA from 0- versus 1-indexing in the prefix formula; TLE from input() on \(10^5\) query lines (L2).
  • P2: forgetting that a start might fit no book at all (answer 0), or simulating from every start in \(O(n^2)\).
  • P3: lifting only the median element instead of everything at or above it; an upper bound below \(a_{n/2} + k\).
  • P4: an unproven greedy that tries right before left, or forgetting that the last tree can always fall right.
  • P5: using \(r\) instead of \(r + 1\) as the end event (it under-counts every right endpoint), or allocating an array of size \(10^{18}\).
