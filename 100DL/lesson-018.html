Pick a shape convention and never deviate

This course uses row-major batches: X has shape (N, d_in), one example per row. Weights are (d_in, d_out), so X @ W gives (N, d_out). Biases are (d_out,) and broadcast across the batch. Half of all deep learning bugs are a convention change you did not notice.

X (N, d_in)@W (d_in, d_out) +b (d_out,)=Z (N, d_out)
Pitfall

Textbooks and many papers use the column convention \(\mathbf z=W\mathbf x\) with \(W\) of shape (d_out, d_in). PyTorch stores weights that way too, then transposes internally. When porting a formula from a paper, check which convention it is in before you write a single line.

Sanity checks that catch real bugs

Run these before you trust any forward pass
  1. Shapes. Assert the output shape is exactly what you expect. Not "broadcastable to" — exactly.
  2. Initial loss. For \(K\)-class classification with random init, loss should start at \(\log K\). MNIST: \(\log 10\approx2.303\). CIFAR-10: same. If you start at 6.5, your logits are not centred and something is wrong.
  3. Zero input. Feed X = 0. Output must equal the bias exactly.
  4. Single-example vs batch. Run one example alone and inside a batch of 32. Results must match to floating-point tolerance. If they do not, you have a reduction over the wrong axis.
  5. Gradient check. Finite differences in float64, relative error \(\lt10^{-7}\). Non-negotiable before you scale up.
import numpy as np

class Neuron:
    def __init__(self, d_in, seed=0):
        rng = np.random.default_rng(seed)
        self.W = rng.normal(0, np.sqrt(1.0 / d_in), size=(d_in, 1))  # Xavier-ish
        self.b = np.zeros((1,))

    def forward(self, X):                 # X: (N, d_in)
        self.X = X                        # cached for backward
        self.z = X @ self.W + self.b      # (N, 1)
        self.p = 1 / (1 + np.exp(-self.z))
        return self.p

    def loss(self, y):                    # y: (N, 1) of 0/1
        eps = 1e-12
        return float(-(y * np.log(self.p + eps)
                       + (1 - y) * np.log(1 - self.p + eps)).mean())

    def backward(self, y):
        N = self.X.shape[0]
        dz = (self.p - y) / N             # (N, 1)  <- Lesson 17's cancellation
        self.dW = self.X.T @ dz           # (d_in, 1)
        self.db = dz.sum(axis=0)          # (1,)
        return dz @ self.W.T              # (N, d_in) grad w.r.t. input

# check 2 above:
n = Neuron(20)
X = np.random.randn(64, 20); y = (np.random.rand(64, 1) > 0.5).astype(float)
print(n.forward(X).mean(), n.loss(y))   # ~0.5 and ~0.693 = log 2

Visualising what it learned

For image input, \(\mathbf w\) has one weight per pixel — reshape it to the image size and display it. Positive weights are evidence for the class, negative against. On MNIST binary "is it a 3?", you will see a faint 3-shaped positive region and negative weights where an 8 would close its loops. The weight vector is a template. Keep this picture; on Day 41 it becomes the argument for convolution.
